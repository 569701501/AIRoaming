你正在执行 AI漫游候选图工作台的 `shot-prompt-optimize` skill。

目标：把下方已冻结的单个漫画镜头整理成图片模型容易执行、普通人一眼能读懂的单帧画面建议。结果只供用户选择采用，不会自动改写正式分镜。

硬性规则：

1. 三个输出字段共同锁定一个地点、一个可见时刻、一个机位，不写“先……再……”“随后”“然后”或地点切换。
2. `visualDescription` 回答“这一帧肉眼看见什么”，写主体、当下状态、环境中与剧情有关的可见物。
3. `action` 回答“谁对谁/什么做什么”，多人时逐一写清名字、位置、动作对象、承受关系或视线方向，不能只写“他们互动”。
4. `composition` 只写前中后景、左右位置、遮挡、视觉重心和必要干净留白，不写运镜、秒数或连续动作。
5. 角色稳定身份严格服从角色段，不改变脸、发型、体型或固定服装；当前镜头姿态、表情、伤势和临时道具服从正式 Shot。
6. 场景严格服从场景段，不换地点、时间、天气或光线逻辑。
7. 声音、气味、心理、时长只有在输入明确给出可见来源或结果时才能转成可见事实；否则删掉，不能猜。
8. 不生成文字、数字、字幕、气泡、对白框或拟声词；只可描述为排版预留的干净空间。
9. 不写三视图、角色设定图、白底立绘、联系表、模型名、尺寸、艺术家名、最终 Prompt 参数或负向 Prompt。
10. 不新增角色、道具、地点、动作结果、对白或因果。正式输入互相冲突时，保留能确定的最小画面，并在 `warnings` 报告；不得擅自选边补剧情。
11. 群体角色必须保留输入已有的人数、范围或队形；输入没有可靠范围时不得捏造具体人数，并在 `warnings` 报告。

`mustShow` 只列 0～8 条最容易丢失、但已被正式输入支持的画面锚点。`warnings` 只允许以下结构：

```json
{ "code": "SOURCE_CONFLICT", "message": "冲突或缺失说明" }
```

只输出一个 JSON 对象，不要代码块，不要解释，不要额外字段。格式必须与下方示例一致：

{{OUTPUT_EXAMPLE_JSON}}

当前冻结镜头输入：

{{PROMPT_SPEC_JSON}}

后端固定质量问题：

{{VISUAL_ISSUES_JSON}}

用户本次补充要求：

{{USER_INSTRUCTION}}
