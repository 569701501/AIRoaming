# 已有剧本导入与忠实整理

把已有完整原稿按 B1～B5 处理。原稿、分析候选、章节待确认稿和正式章节是不同产物；不得互相覆盖或冒充。

## 固定流程

1. B1 保存原稿
   - 接收 `.txt`、`.md` 或长文本粘贴。
   - 按文件和稳定文本块保存不可变原稿版本。
   - 保留文件顺序、块顺序和来源摘要。

2. B2 分析原稿
   - 只观察原稿实际内容，输出 `outlineRole=observed` 的项目级摘要。
   - 识别人物、剧情阶段、结尾状态、原稿边界和不确定项。
   - 不推测作者原计划，不用三幕式等创作公式改写原稿。

3. B3 提出拆章目录
   - 每章必须给出连续来源范围、开始/结束边界证据和置信度。
   - 每个原稿块必须且只能归入一章或明确排除范围。
   - 文件顺序、正文范围或关键边界无法确定时，输出阻断问题，不得猜测。
   - 用户可以要求重新分析；每次都输出一份完整新候选。
   - 只有用户整体确认一次拆章目录后，才进入 B4。

4. B4 生成全部章节待确认稿
   - 一次创建目录中的全部章节入口。
   - 按章顺序逐章忠实整理，单章失败不阻断其他章节。
   - 每章只使用其已确认原稿范围，输出固定章节剧本 Markdown。
   - 对每章执行独立忠实度验证；存在硬问题的章节不得成为待确认稿。

5. B5 逐章检查与确认
   - 用户可自由切换、查看任意章节，不限制顺序和次数。
   - 待确认稿全文只读。
   - 不提供手动整理、AI 重新整理、采用、丢弃或批量确认。
   - 用户点击“确认章节”后，直接创建正式 `ChapterScriptVersion`。
   - 只有正式章节版本允许进入剧情结构；其他章节待确认或失败不阻断本章。

## 分析输出规则

- 只输出严格 `import-analysis/1.0` JSON，不输出数据库 ID、Markdown 围栏或解释。
- 顶层保持：`schemaVersion`、`outlineRole`、`sourceProfile`、`observedOutline`、`chapterCandidates`、`excludedRanges`、`unresolvedItems`、`globalWarnings`。
- 来源引用只能使用系统提供的 `sourceRef`、`blockRef`。
- `chapterCandidates` 按 `order` 连续排序，来源范围不得重叠、遗漏或乱序。
- 原稿标题用 `basis=source`；保守建议标题用 `basis=suggested`。
- `unresolvedItems.impact` 为 `source_scope`、`source_order` 或 `boundary` 时视为阻断。

## 章节整理规则

- 只输出固定章节剧本 Markdown，不输出 JSON、来源引用或系统状态。
- 必须完整保留事件、对白、人物身份和顺序。
- 允许做格式标准化、场景字段归纳和保守摘要。
- 原稿未说明的辅助字段写“原稿未明确”。
- 不得新增、删除、润色、续写、压缩、重排或强化剧情。
- 不得把观察性大纲当作正文事实补进章节。
- 不输出角色卡、正式场景卡、剧情节拍、分镜、镜头或图片 Prompt。

## 忠实度验证规则

- 验证阶段只审计，不继续改写正文。
- 用 `sourceCoverage` 逐范围证明原稿块已完整映射到输出行。
- 遗漏、无来源新增、顺序改变、对白或说话人改变、实体合并拆分、越界内容均为硬问题。
- 不用模糊覆盖率数字替代来源证据。
- 格式错误最多执行一次只修格式的重试，不得借重试改剧情。

## 禁止事项

- 不从零创作或生成灵感、大纲计划、人物弧和钩子。
- 不把忠实导入和改编混在同一步。
- 不覆盖或修改不可变原稿。
- 不在拆章目录确认前创建章节。
- 不把待确认稿当作正式章节。
- 不因某章失败而回滚已成功的其他章节。
- 不直接写本地路径、数据库 ID 或时间戳；这些由系统负责。

## 阶段退出条件

- B2/B3：不存在会阻断拆章目录确认的问题。
- B4：每章分别达到“待确认”或明确失败状态，整批不能静默遗漏章节。
- B5：单章只有在用户明确确认后才成为正式章节版本。

两条上游路线只在正式 `ChapterScriptVersion` 汇合；之后复用现有 StoryStructure、分镜和出图流程。
