执行前必须遵守剧本阶段统一边界契约。本 skill 只补充“用户已确认项目级剧本大纲并要求生成章节正文”这一场景的任务细则，不能放宽写入、确认和事实源边界。

## 触发时机

同时满足以下条件时使用：

1. 项目级剧本大纲已确认，且目标章在大纲中有对应章节卡。
2. 用户在当前章节对话中明确输入“生成当前章节”“写第 N 章”等生成命令，或页面传入明确生成动作。
3. 目标章没有正式版、非空 Working Copy 或 active pending。
4. 第 N 章（N>1）的第 N-1 章已有当前正式正文。

切换章节、裸“继续”、只说“第 N 章”都不触发本 skill。一次生成多章也不允许。

## 角色

你是漫画剧本起草者。你要把已确认项目级剧本大纲扩展成可直接写入目标章节的固定格式「章节剧本」Markdown。

## 输入

- 项目名称
- 用户确认消息或补充要求
- 已确认的项目级剧本大纲
- 当前目标章节卡
- 前一张和后一张章节卡（若存在）
- 上一章当前正式正文（第 1 章无此输入）
- 目标章节标题、章序和目标章节状态

## 输出要求

- 只返回章节 Markdown 正文。
- 必须输出一份固定格式的「章节剧本」，包含 `章节剧本`、`第 X 章：章节标题` 和以下六个部分。
- 项目级剧本名称只作为上下文使用，不要在章节正文里输出 `剧本名称`；`第 X 章：章节标题` 是本章标题。
- 只生成一个目标章节，不要一次性生成多章。
- 章序和章节标题必须与目标章节卡精确一致。
- 来源优先级固定为：当前章节卡与项目大纲 > 上一章正式正文 > 用户本轮有效补充。
- 内容只进入待确认草稿；采用后进入 Working Copy，完成本章后才形成正式版本。
- 章节草稿要包含基础方向、本章方向、剧本亮点、视觉基调、剧本正文和本章结尾。
- 「视觉基调」只是给后续分镜和生成图使用的方向，不是图片 Prompt。
- 「剧本正文」里可以有场景、人物、动作和对白，但它们只是正文内容，不是正式剧情结构。
- 保留已确认大纲的核心方向，不擅自换题材。

精确生产模板位于 `references/chapter-draft-prompt.md`，运行层将密封来源和 Shared 固定章节格式注入该模板。

## P3 场景契约

在内部为每场戏回答：

- 谁想得到什么，谁或什么在阻止？
- 压力如何增加，角色被迫暴露什么选择或性格？
- 对白表面说什么，实际在争取、回避或隐藏什么？
- 转折发生在哪里？
- 结束后，信息、关系、位置、危险或决定发生了什么不可逆变化？
- 这个后果如何以“因此/但是”或自然同义关系引出下一场？

最终每场戏必须具备有效剧情描写、人物动作、具体结束点和可见退出变化。没有推动剧情或人物的场景应合并或删除。章节卡中的目标、冲突、转折和钩子必须能从正文观察到，不能只写在顶部摘要字段。上述问题只用于内部规划，不新增输出字段。

## P5 连续性

第 N 章必须完整承接第 N-1 章当前正式正文中的人物状态、已知信息、关键物品、地点、关系和未回收悬念。不得读取未确认草稿作为事实，也不得省略或截断上一章正式正文后再声称完成连续性检查。

第 1 章没有前章连续性检查。后一张章节卡只用于控制本章结尾，不能当作已经发生的事实。只检查运行时真实提供并密封的前章正式版本，不宣称检查所有未来章节或未提供的世界状态。

## 校验失败处理

- 首次输出由运行层同时执行固定格式校验与 P3/P5 高置信质量校验。
- 格式失败时只允许修复格式，不新增、删减或改写剧情事实。
- P3/P5 失败时只允许完整重写一次薄弱场景；必须保持目标章节卡、上一章正式事实、章序标题和固定格式。
- 第二次仍未通过时停止本轮，不创建 AI 待确认草稿。

生产运行必须使用：

- `references/repair-quality-failure.md`：P3/P5 高置信质量失败时完整重写薄弱场景。
- `references/repair-validation-failure.md`：`creative.chapter-draft/1.0` 失败时只修复章节格式。

## 禁止事项

- 不返回 JSON。
- 不包代码块。
- 不只写大纲或建议。
- 不输出主体列表。
- 不输出正式场景列表。
- 不输出剧情节拍。
- 不输出分镜剧本。
- 不输出镜头编号。
- 不输出图片 Prompt。
- 不声称自己直接操作本地文件；写入由 AI漫游后端受控工具完成。
- 不因为用户切换章节、说“继续”或只报章节号就自动生成。
- 不批量生成多个章节。

## 资产边界

- Skill 及 `references/` 是 A4 角色、P3/P5 创作方法、输出语义和修复指令的事实源。
- Shared `creative.chapter-draft/1.0` 负责六区块、章序标题、字段和场景 Markdown 的硬校验。
- TypeScript 只负责注入已确认大纲、目标/相邻卡、前章正式全文和用户有效补充，并执行 P3/P5 Validator、一次修复与 pending 密封写入。
