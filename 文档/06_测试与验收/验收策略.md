## 1. 验收目标

AI漫游的验收要证明系统不是“看起来生成了内容”，而是主工作流真的可用、可追溯、可导出。

## 2. 验收分层

| 层级 | 验收内容 |
| --- | --- |
| 文档验收 | 文档入口、事实源、模板、完成记录是否完整 |
| 数据验收 | 数据模型、任务输入输出、素材关系是否可追溯 |
| 功能验收 | 用户能否完成故事到导出的主流程 |
| 生成验收 | AI 输出是否结构化、可编辑、可重跑 |
| 文件验收 | 文件是否存在、路径是否正确、Asset 是否对应 |
| 导出验收 | PNG/PDF/MP4/素材包是否可打开和追溯 |

## 3. MVP 端到端验收场景

本节保留为简版入口。G0–G5 到 current `layout_publication` 的阶段性闭环，以及后置 G6/G7 的 ZIP 总验收，均以 `文档/06_测试与验收/七阶段完整链路验收基线.md` 的分层口径为准。

G0 只负责锁当前正确行为和建立最小 E2E 骨架；哪些用例当前执行、哪些留到 G1–G5，哪些长期保留给后置 G6/G7，以 `文档/06_测试与验收/G0七阶段行为用例矩阵.md` 为准。

### 场景：短篇故事生成漫画页

步骤：

1. 创建项目。
2. 输入 800 到 1500 字短篇故事。
3. 运行 `story_parse`。
4. 检查结构化剧情。
5. 运行 `shot_generate`。
6. 编辑至少 1 个分镜。
7. 为每个分镜生成至少 2 个候选图。
8. 每个分镜锁定 1 个候选。
9. 在成稿编辑器建立多格、文字和气泡并保存 LayoutRevision。
10. 预检并创建一次出版导出：页漫 PNG 页面（可选 PDF）或条漫 PNG 切片。
11. 后置 G6/G7 再导出并下载素材包；不属于当前 G0–G5 通过条件。

通过标准：

- 所有任务都有 `GenerationTask` 记录。
- 所有图片都有 `Asset` 记录。
- 每个锁定候选都能追溯到 `Shot` 和 `taskId`。
- `layout_publication` 中必需 PNG/切片存在并可打开；可选 PDF 页数/尺寸正确，manifest/sha 与 Asset 一致。
- 当前 G0–G5 到 `layout_done` 即可独立签收，不要求 ZIP/`exported`。
- 后置 G6/G7 总验收时，素材包还必须包含 `manifest.json` 并通过 ZIP 下载/摘要审计。

## 4. 任务协议验收

每个任务类型至少验收：

| 验收点 | 说明 |
| --- | --- |
| 输入合法性 | 缺必填字段时失败并给出错误 |
| 输出结构 | 返回符合任务协议的 JSON |
| 状态变化 | `queued -> running -> succeeded/failed` |
| 错误留痕 | 失败时写入 `errorJson` |
| 文件注册 | 生成文件后创建 Asset |
| 进度事件 | 前端能收到任务事件 |

## 5. 文档验收

文档类变更至少检查：

- `文档/README.md` 是否能导航到新增文档。
- 新文档是否有 frontmatter。
- 新文档是否放在正确目录。
- 功能完成后是否新增完成记录。
- 如果改变事实源，旧文档是否不再与当前事实冲突。

## 6. 完成记录验收

每份完成记录至少包含：

- 功能摘要。
- 修改文件。
- 验证命令和结果。
- 已知风险。
- 后续事项。

没有验证证据的完成记录不能视为完整。

## 7. 后续测试类型

| 类型 | 适用阶段 | 示例 |
| --- | --- | --- |
| 单元测试 | 数据模型、任务适配器 | 任务输入校验、状态转换 |
| 集成测试 | API + DB + 文件系统 | 图片任务完成后注册 Asset |
| 端到端测试 | 主工作流 | 故事到漫画页导出 |
| 视觉验收 | 漫画排版、横竖排文字、气泡与来源换图 | RenderScene/正式输出黄金对照，不以编辑器截图代替 |
| 文件验收 | 出版导出物 | PNG/PDF/条漫切片可解码、尺寸/页数/sha/manifest 正确 |
