# 自动化测试体系

## 1. 当前结论

项目当前使用四类自动化门禁：

1. **Vitest**：shared 纯函数与 Nest Service/文件系统集成测试。
2. **Playwright Test**：真实 Nest HTTP、Vite 页面、Chromium 用户路径和三个受控本地进程的生命周期。
3. **Migration Gate**：Prisma schema、正式 migration tree、fresh/migrated/legacy DB 与 file guard。
4. **Render Gate**：固定 Chromium、固定字体、LayoutDocument/RenderScene、PNG/PDF/条漫确定性输出。

G0 测试安全网已于 2026-07-11 实现；G1～G5 随后已在同一底座上完成 DB-only、版本链、版式、候选返修和正式出版覆盖。2026-07-16 A+ 剧本双流程与首组 P6 回归收口后，新鲜结果为 shared 153/153、server 单 fork 597/597、E2E 环境 34/34、prepare 3/3；AI 显式单章路径和已有剧本 B1～B5 路径分别通过 DB-only Chromium，typecheck 与 build 全绿。2026-07-15 的 G0→G5 全矩阵结果继续作为最近一次完整阶段签收；本轮 P6 只修改测试与文档，没有把非 UI 集成复核冒充为新的浏览器矩阵。默认并发 server 曾有两条 fixed 5 秒 backup/restore timeout，单 fork 全量通过，按稳定性观察保留。G6 素材包和轻量视频不属于本轮。

## 3. 测试文件约定

### 3.1 Vitest

- shared/server 测试与被测代码同目录，命名 `*.spec.ts`。
- 后端：`apps/server/src/**/*.spec.ts`。
- shared：`packages/shared/src/**/*.spec.ts`。
- G0 Service fixture：`apps/server/src/projects/test-support/seven-stage-fixture.ts`。
- G0 Service 行为链：`apps/server/src/projects/seven-stage.characterization.integration.spec.ts`。

### 3.2 E2E

```text
playwright.config.ts
tests/e2e/
  setup/                 # global setup/teardown
  api/                   # 公开 HTTP smoke
  web/                   # Chromium 用户路径
  support/               # runtime、环境守卫、fake provider、fixture 与契约自测
  tsconfig.json          # Playwright/E2E TypeScript
  tsconfig.server.json   # Nest E2E runtime TypeScript
```

Playwright 成功运行默认只保留 HTML report；失败证据写入带 runId 的 `test-results/e2e/` 和 `playwright-report/`。这些目录与 `tests/.runtime/` 均被 Git 忽略。

## 6. E2E 安全与运行时契约

### 6.1 TypeScript 与 shared 解析

- 项目验收环境为 Node 22.17.1。
- E2E TypeScript 与 provider/server/web 服务命令显式使用 `node --import tsx`；根依赖固定 `tsx@4.22.3`。
- `tests/e2e/tsconfig.json` 与 `tests/e2e/tsconfig.server.json` 把 `@airoaming/shared` 映射到 `packages/shared/src/index.ts`。
- programmatic Vite 使用同一 source alias，并排除 shared 预构建。
- `test:e2e:prepare` 禁止运行 `@airoaming/shared build`；prepare 契约会比较 shared/dist 每个文件的字节、mode 与 `mtimeNs`，防止测试准备阶段改写开发产物或触发 watcher。

### 6.2 workspace 与进程

- 每次运行生成唯一 `AIROAMING_E2E_RUN_ID`、三个独立端口和 `airoaming-e2e-<runId>` 临时根。
- 临时根必须具有内容匹配的 `.airoaming-e2e-root` marker；默认仓库 workspace、仓库根、home、文件系统根、symlink 或 marker 不匹配时拒绝启动/清理。
- provider、Nest 与 Vite 只绑定 loopback，`reuseExistingServer=false`，`workers=1`。
- 进程状态文件位于当前 run 目录；清理前复核 PID 身份，不误杀同仓库用户进程。
- `OPENCODE_AUTO_START=false`；子进程使用最小 operational allowlist，图片 key 固定为假值，不继承真实凭据。

### 6.3 浏览器网络

- UI fixture 在创建 page 前安装 HTTP 与 WebSocket 拦截。
- 只允许当前 run 的 Web/Server/fake provider loopback origin。
- 非 loopback 请求在离开浏览器前阻断，并通过 `e2e-browser-network-audit` 附件审计。
- Service Worker 被禁用，避免缓存绕过网络守卫。

## 8. 测试设计原则

1. **事故和风险驱动**：覆盖发生过的事故、状态门禁、持久化边界与外部服务隔离，不追逐覆盖率数字。
2. **测试公开行为**：断言 DTO、业务状态、错误码、用户可见文本/role/URL 与必要落盘事实，不断言私有 Map、内部调用次数或 DOM class。
3. **真实临时 fs**：Repository 与 Service 测试使用真实临时目录，只 fake 真正的外部 provider。
4. **未来行为按切片 TDD**：`red_on_slice:Gx` 到所属阶段再写 red 并最小实现到 green；不批量保留 skip/todo。
5. **失败同样可诊断**：trace、截图、DOM、网络与服务错误摘要必须足以定位问题，但不能写入 Authorization、真实 key 或图片字节。
6. **反向保护环境**：测试准备与 teardown 本身必须有契约测试；不能只检查业务 spec 是否绿色。

## 9. migration witness 的到期条件

G0 最后一条 Service 用例是文件态 `migration_witness`。G1 只有在以下条件同时满足后才能删除或替换：

1. 测试走真实迁移入口和生产 DB-only 链路。
2. 重启后通过公开 Workbench/API 读回同等 current/pending/confirmed/workflow 不变量。
3. DB-only 激活后修改旧 JSON 不影响正式读取，生产代码无 file fallback。
4. 等价 G1 测试先变绿，再移除 G0 witness，并保留相同失败定位能力。

## 10. 新增测试指引

1. 涉及状态写入或回归事故时，先补最小失败测试，再修改实现。
2. 纯函数放 shared；后端业务放 server；完整 HTTP/路由/浏览器路径放 Playwright。
3. 新浏览器路径先确定公开 role/label/text/URL 锚点，不以 CSS 结构和像素坐标作为核心契约。
4. 新外部依赖必须先进入 loopback fake/adapter 边界和网络 allowlist，不能在测试中访问真实供应商。
5. 提交前至少运行 `corepack pnpm test:all`；涉及 E2E runtime、端口、清理或网络守卫时，额外运行 `corepack pnpm test:e2e:repeat`。
