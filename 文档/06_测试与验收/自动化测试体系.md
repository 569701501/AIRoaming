## 1. 测试框架

项目使用 **Vitest** 作为单元/集成测试框架。

选型依据:
- 后端 NestJS + ESM(`"type": "module"`) + tsx,前端 Vite 5,shared 纯 TypeScript + ESM。
- Vitest 原生支持 ESM + TypeScript(零编译配置),与现有 Vite 栈同源。
- Jest 在 ESM 下需复杂 transform 配置,与 Vite 生态割裂。

## 2. 运行命令

| 命令 | 作用 | 范围 |
| --- | --- | --- |
| `corepack pnpm test` | 跑全部自动化测试(聚合) | shared + server |
| `corepack pnpm --filter @airoaming/server test` | 只跑后端测试 | server |
| `corepack pnpm --filter @airoaming/shared test` | 只跑 shared 测试 | shared |
| `corepack pnpm --filter @airoaming/server test:watch` | watch 模式 | server |
| `corepack pnpm -w typecheck` | 类型检查(三包) | shared + web + server |

## 3. 测试文件约定

- 测试文件放在被测代码同目录,命名 `*.spec.ts`。
- 后端:`apps/server/src/**/*.spec.ts`
- shared:`packages/shared/src/**/*.spec.ts`
- 配置文件:`vitest.config.ts`(各包根目录)。

## 5. 测试设计原则

1. **事故驱动,非覆盖度驱动**:测试范围由"发生过的事故 + 高风险路径"决定,不为覆盖率数字而测。
2. **测行为契约,不测实现细节**:断言"输入→输出/异常",不断言内部状态、mock 调用次数。实现重构时测试不需要改。
3. **真实临时目录测 fs**:Repository 测试用 `os.tmpdir()` 隔离目录(通过 `AIROAMING_WORKSPACE_ROOT` env 注入),测真实文件行为,不 mock fs。
4. **秒级确定性**:全部测试 < 1 秒,无网络/全局状态/时序依赖,无 flaky。
5. **反向验证**:回归测试在首次编写时验证过"去掉被测逻辑→测试变红",确保非假绿。

## 6. 回归测试与 bug 修复的关系

2026-06-24 修复了"剧本正文被空内容覆盖"的 bug。该 bug 的回归测试由 `projects.service.source-guard.spec.ts` 锁住:

- 修复涉及的 3 个写入入口(saveChapterDraft / updateProjectDraft / writeChapterDraftFromAI)都有"空 sourceText → 抛异常"的测试。
- 修复逻辑被移除时,对应测试会立即失败。

## 8. 新增测试的指引

新增功能或修复 bug 时:
1. 若涉及数据写入或状态变更,优先补回归测试(输入→异常/输出)。
2. 纯函数放 shared 测;后端业务放 server 测;Repository 用真实临时目录。
3. 回归测试命名清晰,注释说明锁住的是哪个事故或风险。
4. 提交前跑 `corepack pnpm test` + `corepack pnpm -w typecheck`。
