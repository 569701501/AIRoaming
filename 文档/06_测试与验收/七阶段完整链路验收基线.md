# 七阶段完整链路验收基线

## 1. 目标

本文件保留长期七阶段总验收：证明现有七阶段不是“页面都能打开”，而是用户最终可以从创建项目走到可下载素材包，并且：

- 每一步只消费用户已确认的 current 上游；
- 任务、数据和文件在重启后可恢复；
- 返修不覆盖旧版本；
- 导出图和 ZIP 可以打开；
- manifest 能追溯到章节、镜头、候选、修订、任务和源素材。

本基线不验证跨步骤自动调度，也不包含轻漫剧。

### 1.1 当前 G0–G5 阶段性闭环

2026-07-11 用户决定 G6 素材包 V2 与 G7 ZIP 总验收后置。当前开发和签收先使用本文件中的 G0–G5 子集：

```text
创建项目
  -> current Script/Story/Storyboard/Preflight
  -> current CandidateLockRevision[]
  -> current LayoutRevision
  -> current layout_publication
  -> Chapter 最远阶段 = layout_done
```

G0–G5 阶段性通过必须证明真实 PNG 页面或条漫切片可打开、来源/任务/Asset/manifest 可追溯、返修与重启不覆盖历史；不要求 PackageRevision、ZIP、`exported` 或第 7 步 done。第 7 步导航与长期用例继续保留。

截至 2026-07-15，G0～G5 已通过技术实现、静态复核、运行复核和用户签收，状态为 `G0_G5_COMPLETE`。G6 素材包与 G7 总验收继续后置；轻量视频不属于本基线。

## 2. 验收环境

### 2.1 自动化环境

- 临时 SQLite 数据库。
- 临时 workspace 根目录。
- 固定时钟或可注入时间。
- Fake OpenCode/LLM adapter 返回固定结构和分镜。
- Fake ImageProvider 返回固定尺寸的合法 PNG/WebP。
- 确定性字体资产和服务端渲染器。
- 每次用例结束清理临时 DB、文件和进程。

### 2.2 真实供应商冒烟

- 独立测试项目，最多 1 章、3 镜头。
- 真实文本模型和当前图片 provider 各运行一次。
- 记录 provider、model、配置指纹、任务 ID、时间、费用/用量（若可得）和输出路径。
- 真实冒烟不替代确定性自动化；供应商波动不得让 CI 变成随机失败。

## 3. 标准 fixture

使用原创短篇测试故事，避免依赖现有真实项目内容：

```text
项目：雨夜末班车
版式：竖向条漫
章节：第 1 章
角色：林夏（主角）、值班员（单次出镜）
场景：雨夜站台
剧情节拍：等待 -> 广播异常 -> 空车进站
镜头：3 个
每镜候选：2 张
```

固定要求：

- 至少包含一名缺少其既定素材的角色，用于验证 preflight 阻塞与解除；同时包含 `human + chapter`、`human + minor`、`creature`、`group`、`voice` 覆盖分类矩阵。
- 至少一张候选 A 在布局后替换为候选 B，用于验证 D3。
- 至少一个文字框使用竖排，至少一个气泡使用横排富文本。
- 至少一页使用两个以上画格，防止一镜一页骨架假通过。

## 4. 正常路径验收

| 序号 | 用户动作 | 必须产生的正式事实 | UI/门禁 | 文件/产物证据 |
| --- | --- | --- | --- | --- |
| 0 | 创建项目并选择漫画版式 | Project + 默认 Chapter；comicFormat 非空且不可改 | 创建后进入剧本；未选版式不能提交 | DB 项目/章节记录，无静默默认 |
| 1 | AI 生成或用户输入剧本，采用并完成本章 | current ScriptVersion | 结构步骤变 active；未完成稿不能生成结构 | 剧本文本可读，版本摘要一致 |
| 2 | AI 生成结构预览并确认 | current StoryVersion，绑定 ScriptVersion | pending 不能生成分镜；确认后分镜 active | 结构 Json schema/digest 正确 |
| 3 | AI 生成分镜预览，编辑并确认 | current StoryboardRevision，绑定 StoryVersion | pending 不能进 preflight | 3 镜头顺序、字段和来源一致 |
| 4 | preflight 首次因既定角色素材缺失被阻塞；回到剧情结构完成素材后重新预检并确认 | current `preflight-source-v2` PreflightRevision，绑定 StoryboardRevision 与资产版本 | 未就绪不能生成候选；出图准备无生成/修复按钮；就绪后候选 active | 问题列表从 blocked 变为 ready，且无图片 Provider 调用由 preflight 触发 |
| 5 | 每镜生成 2 张候选并逐镜定稿 | 6 Candidate + 3 current CandidateLockRevision | 未全定稿不能完成；全定稿后排版 active | 图片存在、尺寸合法、Task/Asset/sourceDigest 可追溯 |
| 6 | 创建多格布局、加入文字和气泡、保存版本并确认出版 | LayoutRevision + `layout_publication` ExportRevision | stale/预检错误阻止；warning 明确确认；通过后第 6 步完成；第 7 步可显示但不阻塞 G0–G5 签收 | 页漫 PNG/可选 PDF 或条漫切片可打开，预览与正式渲染一致，manifest 摘要匹配 |
| 7（后置 G6） | 导出素材包并下载 | PackageRevision + ZIP Asset | 成功后显示历史包和下载入口 | ZIP 可解压，manifest 完整且摘要匹配 |

当前 G0–G5 阶段性断言：

```text
Chapter 最远阶段 = layout_done
步骤 1–6 达到各自完成条件
current layout_publication 来源匹配
不存在 pending/stale 被正式出版
不要求 PackageRevision、ZIP 或 exported
```

后置 G6/G7 的长期最终断言：

```text
Chapter 最远阶段 = exported
七个 workflow step = done
所有 current 指针来源匹配
不存在 pending/stale 被正式导出
```

## 5. 门禁与负向验收

| 场景 | 预期结果 |
| --- | --- |
| 未选择漫画版式创建项目 | 400/表单不可提交，不创建项目目录或 DB 行 |
| 未完成剧本生成结构 | 拒绝，正式结构数量不变 |
| 未确认结构生成分镜 | 拒绝，pending 不能充当 current |
| 未确认分镜进入候选 | preflight/候选均拒绝 |
| `human + lead/recurring/chapter` 无定稿图确认 preflight | 返回明确 blocked issues，不写 confirmed record |
| `human + minor/extra` 重复出镜但已有预览图 | 仍可通过，不因 `appearanceCount` 升级为定稿要求 |
| `creature/group` 已有预览图、无人物四视图 | 可通过；页面不出现人物定稿动作 |
| `voice` 无图片 | 可通过且不创建图片任务 |
| 分镜引用当前剧情结构外角色 | 在分镜落库/确认前拒绝，不允许靠 preflight 临时补救 |
| 旧 `preflight-source-v1` 作为 current 使用 | 历史内容可读，但生产状态为 stale/需重新确认 |
| 候选未全部定稿完成图片阶段 | 返回未完成镜头列表，不推进状态 |
| 布局含 stale 来源正式导出 | 拒绝并列出受影响元素 |
| 缺字体、文字溢出、低分辨率或画布外对象 | 正式导出被预检阻止 |
| 缺失正式导出页生成素材包 | 任务失败，不把章节标为 exported |
| 直接访问等待阶段 URL | 页面可展示阻塞原因，但任何写操作由服务端拒绝 |

## 6. 返修路径验收

### 6.1 剧本返修

1. 完成全链路并保留 ExportRevision E1。
2. 修改剧本 Working Copy，尚未重新完成。
3. 验证 E1 仍可打开；当前 StoryVersion 不改变。
4. 重新完成剧本，产生 ScriptVersion S2。
5. 旧 StoryVersion 及下游派生为 stale/historical，不能创建新任务。

### 6.2 结构和分镜返修

- 结构剧情节拍改变后创建 StoryVersion V2；旧分镜不删除。
- 分镜重排后创建 StoryboardRevision B2；旧候选和旧布局不删除。
- 页面必须明确展示来源已更新和下一步处理动作。

### 6.3 候选 A→B

1. 镜头 1 定稿 A，创建 LayoutRevision L1 和 ExportRevision E1。
2. 更换前展示受影响元素、布局、导出和任务。
3. 提交 B，创建新的 CandidateLockRevision。
4. L1/E1 保持原内容；当前布局显示相关元素 stale。
5. 解决 stale 后创建 L2/E2；E2 使用 B，E1 仍使用 A。
6. B→A 再创建第三个修订，不能复用或覆盖第一次修订。

## 7. 任务与故障恢复验收

### 7.1 服务重启

- 在 queued、running、provider 已返回但尚未登记、文件 staged 四个时点分别终止服务。
- 重启后 queued/retrying 可继续；过期 running 按任务幂等能力重试或进入 `WORKER_INTERRUPTED/needsReview`。
- 不产生第二份 current Candidate/Asset/ExportRevision。

### 7.2 取消与迟到结果

- queued 任务取消后永不 claim。
- running 任务先写 `cancelRequestedAt`；worker 确认后才显示 cancelled。
- provider 无法取消并返回迟到结果时，可保存诊断证据，但不得更新 current 指针。

### 7.3 重试

- 仅 retryable 错误进入有限重试。
- 每次尝试有不可变 TaskAttempt。
- 超过 maxAttempts 后失败并保留全部错误，不无限重试。

### 7.4 来源变化

- 任务启动后更换 StoryboardRevision、PreflightRevision、CandidateLockRevision 或 LayoutRevision。
- 任务可结束，但 `applicability=historical`，不得成为 current。

## 8. 文件与素材追溯验收

### 8.1 Asset

每个正式文件必须满足：

- storageKey 在受控项目根内；
- 文件存在；
- sha256、bytes、mimeType 与实物一致；
- sourceTaskId/sourceRevisionId 可追溯；
- current/historical 状态与业务关系一致。

### 8.2 Manifest V2

对 ZIP 内每一项验证：

```json
{
  "path": "chapters/chapter-001/exports/page_001.png",
  "sha256": "sha256:...",
  "bytes": 123456,
  "mimeType": "image/png",
  "chapterId": "chapter_001",
  "shotId": null,
  "candidateId": null,
  "assetId": "asset_page_001",
  "sourceRevisionId": "exportrev_001",
  "sourceTaskId": "task_export_001"
}
```

- ZIP 内路径必须规范化，禁止 `../`、绝对路径和重复条目。
- manifest 自身版本、包 ID、项目 ID、章节范围和创建时间必须存在。
- 所有正式导出页、锁定图和核心 Json 都必须入包；可选诊断文件需明确标记 optional。

## 9. 自动化测试分层

| 层级 | 位置 | 最低覆盖 |
| --- | --- | --- |
| 纯函数 | shared/server Vitest | 状态投影、freshness、digest、门禁和 manifest 校验 |
| Repository/DB | server Vitest + 临时 SQLite/workspace | 版本/current 指针事务、文件 staged/ready、重启恢复 |
| Service 集成 | Nest application context | 七阶段正常路径、返修路径、任务故障注入 |
| Web E2E | 新增 Playwright 项目 | 用户点击、等待步骤、错误提示、编辑器和下载 |
| 渲染黄金样例 | renderer 测试 | 横竖排、富文本、气泡、裁切、字体和条漫/页漫输出 |
| 真实供应商冒烟 | 手工/受控任务 | 1 章 3 镜，记录供应商证据，不进入普通 CI |

当前自动化已覆盖 shared/server Vitest、环境契约、file/DB Playwright、迁移门禁和 G5 确定性渲染。G2 上游版本链清单、G3 漫画版式清单、G4 候选返修清单和 G5 成稿清单均已完成；最新运行数量和命令以 `自动化测试体系.md` 与本轮回归记录为准。

## 11. 完成判定

### 11.1 G0–G5 阶段性通过

只有同时满足以下条件，才能宣称当前开发波次通过：

1. G0–G5 各自验收清单中属于本阶段的自动化、门禁、返修和故障用例通过。
2. 用户在真实页面至少完成一次创建、上游确认、候选定稿、成稿编辑和出版路径。
3. 页漫 PNG/可选 PDF 或条漫切片实际可打开，publication manifest/sha/Asset 审计通过。
4. 服务重启、A→布局→B、迟到任务和 DB-only 读写边界符合 G1–G5 契约。
5. Scrutiny Review、Runtime/User Review 和 Handoff 齐全。

G0–G5 通过不等于七阶段 ZIP 总验收通过，也不允许把旧目录包骨架当作 G6 已完成。

### 11.2 长期七阶段通过

只有同时满足以下条件，才能宣称七阶段完整链路通过：

1. 自动化正常路径、门禁、返修和故障用例全部通过。
2. 用户在真实页面完成一次 1 章 3 镜的真实供应商路径。
3. PNG/PDF/ZIP 可打开，manifest 审计通过。
4. 服务至少在一个运行中任务场景重启，恢复结果符合 D75。
5. A→布局→B 返修不覆盖旧导出。
6. DB-only 环境中旧 JSON/Markdown 不再参与业务读写。
7. Scrutiny Review 和 Runtime/User Review 都给出通过结论。

仅满足“七个页面都能打开”“接口返回 200”“workflow 最终显示 done”中的任意一项，都不能视为完整链路通过。
