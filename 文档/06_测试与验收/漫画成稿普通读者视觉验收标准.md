# 漫画成稿普通读者视觉验收标准

## 0. 当前使用定位

本标准保留为内部视觉质量研究、后续真实素材回归和上线前抽样评测依据，不进入普通用户成稿流程，也不再作为 M4～M8 开发的强制阻塞门。

2026-07-23 用户实际复核确认：

- 当前竖向条漫的阅读顺序和主体遮挡可接受。
- 重复草图不足以让普通用户可靠判断专业“画格节奏”和关键动作完整度。
- 当前最明显的遗留问题是部分气泡外观不够自然或不够美观。
- 产品应先继续完成正式成稿、编辑器和局部视觉 AI 调整闭环；效果不满意时由用户手调，或让视觉 AI 生成可预览、可放弃的局部重排建议。

2026-07-24 对正式 Storyboard 与 Working Copy 的内容复核发现，指定测试稿缺失全部正式对白绑定；因此上述 2026-07-23 观察只保留为交互和局部视觉反馈，不构成该测试稿的内容通过结论。本文第 13 节记录的新结论优先。

因此，158 项 A/B 结果仍须保持诚实的 `pending`，不得伪造为通过；但空结果不再阻止 M4～M8 实施。

## 1. 这套标准回答什么

本标准只回答一个问题：

> 假设眼前就是准备发布的正式漫画，普通读者是否能直接阅读，创作者是否无需为了当前画格、裁切、气泡或整页节奏再打开编辑器调整？

标准编号固定为：

```text
AIR-QA-COMIC-FINAL-001-v1
```

任何人工结果都必须同时绑定标准编号、成稿清单摘要和评审轮次。标准、图片或成稿发生变化后，旧结果不得沿用。

## 2. 漫画排版的完整职责

漫画成稿不是“把文字贴到图片上”，完整链路是：

```text
分镜语义
  ↓
画格布局与节奏
  ↓
图片放置与裁切
  ↓
对白、思考、喊话、旁白等气泡布局
  ↓
音效与其他文字
  ↓
阅读顺序和说话者校验
  ↓
整页/整段节奏校验
  ↓
出版导出
```

它最终解决的是：

- 读者先看哪里、再看哪里。
- 谁先说话，气泡属于谁。
- 气泡是否利用留白且不遮挡重点。
- 人脸、手、武器、关键物品和动作是否完整。
- 小格、停顿格、强调格是否形成正确节奏。
- 对白、旁白和音效是否完整、准确、清楚可读。

## 3. “可以直接用”的唯一含义

`可以直接用` 表示：

- 不会移动、缩放或重排当前对象。
- 不会重做图片裁切。
- 不会改变气泡类型、位置、大小或尾巴。
- 不会为了看清文字而改字号或断行。
- 不会修复漏字、改写、重复或错绑说话者。
- 从整页或整段看，也不需要重新安排阅读顺序和节奏。

“大体没问题”“改一下会更好”“先这样也能看”都不算 `可以直接用`，应选择 `我会调整` 并写明原因。

## 4. 判定项目

| 对象 | 判定项 | 合格标准 | 严重可见错误 |
| --- | --- | --- | --- |
| 画格 | 大小与节奏 | 重要镜头得到足够空间，小格用于推进或停顿，大格用于强调，不抢错重点 | 否，计入直接可用率 |
| 画格 | 图片裁切 | 人脸、手、武器、关键物品和关键动作完整，构图重点明确 | 是 |
| 画格 | 阅读顺序 | 不依赖工程编号，也自然知道下一格在哪里 | 是 |
| 画格 | 主体避让 | 气泡和文字不遮挡人脸、手、武器、关键物品和关键动作 | 是 |
| 气泡 | 位置与大小 | 使用自然留白，不挤、不飘，不会远到认不出说话者 | 否，计入直接可用率 |
| 气泡 | 类型 | 普通对白、思考、喊话、旁白、系统/设备声音符合内容语义 | 否，计入直接可用率 |
| 气泡 | 对白顺序 | 气泡顺序与剧情顺序一致，不会读反 | 是 |
| 气泡 | 说话者与尾巴 | 不会认错说话者；旁白不出现对白尾巴 | 是 |
| 气泡 | 文字可读性 | 字号正常、断行自然、不溢出、不挤成一团，文字留在形状安全区内 | 是 |
| 气泡 | 原文一致性 | 不漏字、不改写、不重复，不把对白变成旁白 | 是 |
| 整页/整段 | 阅读顺序 | 从页首或段首自然读到结尾，先后关系明确 | 是 |
| 整页/整段 | 节奏与平衡 | 停顿、推进、爆发和留白符合剧情，整页视觉重心稳定 | 否，计入直接可用率 |

严重可见错误一旦出现，当前轮次直接判为 `critical_failure`。修复并生成新成稿后，必须重新评审。

## 5. 阅读方向规则

阅读方向是项目配置，不由语言自动猜测。

基础配置至少包含：

```json
{
  "readingDirection": "ltr_ttb"
}
```

支持的项目档案应明确区分：

- `ltr_ttb`：先左后右、先上后下。
- `rtl_ttb`：先右后左、先上后下。
- 条漫：整体从上到下，单个横向组合仍按项目档案决定左右顺序。

中文漫画既可能左到右，也可能右到左，因此“中文一律右到左”不是本项目规则。

## 6. 气泡位置规则

气泡不要求机械地贴近嘴边。正确优先级是：

1. 不破坏全局阅读顺序。
2. 优先使用自然留白和文字安全区。
3. 避开人脸、手、武器、关键物品和关键动作。
4. 通过尾巴或明确的空间关系绑定说话者。
5. 在满足以上条件后，再尽量缩短气泡与说话者的视觉距离。

因此，“离嘴最近”不是唯一标准；全局顺序正确、主体不被遮挡、说话者不会认错才是标准。

## 7. 图片分析与保护区域

排版引擎使用的画面保护信息应区分：

```json
{
  "protectedRegions": [
    { "type": "face", "importance": 1 },
    { "type": "hand", "importance": 0.9 },
    { "type": "weapon", "importance": 0.9 },
    { "type": "key_action", "importance": 1 },
    { "type": "key_object", "importance": 0.9 }
  ],
  "textSafeRegions": []
}
```

仅有一个笼统的“主体区域”不够。当前 M3 已具备人物、脸、视觉重点和文字安全区避让；手、武器、关键动作、关键物品的显式类型化保护属于后续引擎完善项，未完成前不得宣称全部覆盖。

## 8. 对白长度与拆分

本项目不使用“中文气泡固定最多 35 字”作为硬规则，也不允许系统静默改写或自动拆句。

处理顺序是：

1. 使用真实字体、字号、气泡形状和安全内边距测量文字。
2. 优先调整断行、气泡尺寸和可用留白。
3. 仍无法安全容纳时，生成“建议拆分”预览。
4. 保留原文、拆分建议和来源关系。
5. 用户确认后才能改变气泡数量；原文内容不得被改写。

同样字数在不同字体、字号和气泡形状中占用空间不同，因此字数只能作为提醒，不能代替真实排版测量。

## 9. 自动校验与真人复核的分工

自动校验负责确定性事实：

- 分镜、图片、对白和气泡是否一一可追溯。
- 对白是否遗漏、重复或改写。
- 文字是否溢出，是否越过气泡形状安全区。
- 气泡尾巴是否绑定了合法说话者。
- 画格、气泡、图片和导出物是否完整。
- 同一输入是否得到相同输出摘要。

真人复核负责视觉结果：

- 不看编号时是否知道先看哪里。
- 画格强调和整页节奏是否自然。
- 裁切是否破坏人物、动作或视觉重点。
- 气泡是否真的遮挡重点或让人认错说话者。
- 成稿是否达到“无需再打开编辑器”的直接可用程度。

自动满分不能代替可选的真人抽样研究；真人主观印象也不能替代内容完整性和导出契约。普通创作者不是质量研究员：产品只需要让其看到成稿、直接编辑，或对一版具体调整选择“使用这版 / 保留当前”，不能要求其逐项填写专业节奏评分。

## 10. 可选的 M3 内部复核基线

### 10.1 样本

- 12 个故事与格式变体。
- 69 个画格。
- 59 个必需气泡。
- 30 个完整页或完整条漫段。
- 共 158 个独立判断。
- 真实图片来自项目既有雨夜仓库出图，共 11 张；本轮只评排版，不把画风或角色一致性混入评分。

### 10.2 两类难度

- 普通样例：常规单人、双人、动作或无对白布局。
- 困难样例：长对白、多人、多地点、复杂页漫或密集气泡布局。

### 10.3 开展内部研究时的每轮门槛

每一类对象分别计算，不得互相抵消：

| 难度 | 画格直接可用率 | 气泡直接可用率 | 整页/整段直接可用率 |
| --- | ---: | ---: | ---: |
| 普通 | ≥ 90% | ≥ 90% | ≥ 90% |
| 困难 | ≥ 80% | ≥ 80% | ≥ 80% |

按当前样本换算，每轮至少需要：

| 难度 | 画格 | 气泡 | 整页/整段 |
| --- | ---: | ---: | ---: |
| 普通 | 40 / 44 | 26 / 28 | 18 / 19 |
| 困难 | 20 / 25 | 25 / 31 | 9 / 11 |

此外必须同时满足：

- 严重可见错误为 0。
- 内容覆盖和原文一致性自动校验为 100%。
- A、B 两轮由不同评审人独立完成。
- 两轮都先阅读正反例并确认理解标准。
- 两轮均不得查看自动评分或另一轮结果。
- 两轮都达到门槛，才可把该次内部研究记录为 `passed`；该结果不替代真实产品编辑、保存、出版和兼容验收，也不是普通用户发布前的必填闸门。

## 11. 可选内部复核页面的使用要求

复核页面必须：

- 先显示“可以直接用”的定义和真实正反例，再允许开始。
- 默认显示完整成稿，并用黄色框明确当前判断对象。
- 提供未裁切原图，供裁切判断对照。
- 每次只判断一个画格或气泡，不提供一键整批通过。
- 提供“从页首阅读”模式，暂时隐藏黄色框后再判断整页顺序和节奏。
- 使用普通中文展示气泡类型，不暴露工程枚举作为主要文案。
- 选择“我会调整”后，必须选择原因并写明如何调整。
- 只有 158 项全部完成、评审人已填写且独立性已确认时，才允许导出结果。
- A、B 使用不同本地存储键，不能串数据。

生成器只能覆盖空白模板，不能覆盖已经存在的真人结果。成稿摘要变化后，旧结果会因摘要不匹配而失效，必须人工归档后重新评审。

## 12. 状态定义

| 状态 | 含义 | 是否达到内部研究门槛 |
| --- | --- | --- |
| `pending` | 尚未完成校准、身份、独立性确认或全部 158 项判断 | 否 |
| `invalid` | 标准编号、成稿摘要、来源身份、字段或评审人独立性不合法 | 否 |
| `critical_failure` | 至少存在一个严重可见错误 | 否 |
| `below_threshold` | 无严重错误，但至少一个难度/对象桶未达到直接可用率 | 否 |
| `passed` | 两轮独立结果均合法、无严重错误且全部门槛达标 | 是 |

## 13. 当前能力边界

M3 当前已验证：

- 画格布局、图片裁切、气泡布局和尾巴的确定性生成。
- 对话、思考、喊话、旁白四类自动成稿。
- 人物、脸、视觉重点和文字安全区避让。
- 真实字体测量、形状安全、原文不改写。
- 条漫和页漫的真实渲染输出。

M5 当前已验证：

- 普通用户首次进入零配置自动成稿，成功后直接进入同一编辑器。
- 整章新排法先与当前稿对比，可保留、应用和一次撤销。
- 人工新增或修改对象继续保存为 V2 并形成保护；刷新已有稿不重复生成。
- 条漫与页漫真实浏览器路径通过，但假图片 Provider 不用于气泡审美签收。

2026-07-24 真实项目补充复核：

- 11 段条漫“雨夜点名”的图片加载、thought 气泡、SFX、预设、Undo/Redo、保存和手机只读链路可操作；此前 `8.1/10` 只评估编辑器操作性，不能作为成稿内容正确性得分。
- 对照正式 Storyboard 后确认：正式来源有 16 条 voice line 和 3 个旁白镜头，当前 Working Copy 却为 `dialogueBindings=[]`；唯一气泡没有正式来源，且文字不在分镜中。
- 多格素材还存在 AI 乱码或与分镜关键动作不一致。它们属于上游视觉素材质量问题，不能用排版编辑器或对白覆盖分数掩盖。
- 因此该 Working Copy 的内容验收结论为 `critical_failure`；旧页面只能证明渲染和交互接线，不能证明漫画成稿正确。
- ADR-0021 要求把对白/旁白闭合和未分类叙事文字检查前置到 Working Copy 打开、保存、建议应用和阅读预览，错误稿不得再显示为正常成稿。

尚需在后续阶段完成并单独验收：

- 系统/设备声音的独立语义类型和自动样式。
- 手、武器、关键动作、关键物品的类型化保护区域。
- 音效文字的智能生成、摆放和编辑。
- 真实视觉 Provider 驱动的局部调整，以及真实图片上的气泡形状、间距和节奏改善。
- 内容就绪前置、旧错误稿的可撤销内容修复 Proposal，以及极简 Facade/页面路径。
