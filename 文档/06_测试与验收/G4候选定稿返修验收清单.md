# G4 候选定稿返修验收清单

## 1. 使用规则

本清单已按 G4-A～F 的 red -> green、完整回归与总体双 Review 收口。G4 总体状态为 `G4_PASSED`；详细证据见 `g4_f_scrutiny_review.md`、`g4_f_runtime_review.md` 和代码提交 `81c922a`。NFR-01/02 是未单独执行的性能画像建议项，不属于本轮正确性/一致性退出硬门。

前置：

1. G0 临时 workspace、fake image provider、API/Chromium E2E 骨架已通过。
2. G1 DB-only、目标 Schema、persistent task、GenerationTaskSource、Asset ready 协议和幂等 importer 已完成。
3. G2 immutable version、current/pending、NewWorkGate、TaskApplicabilityGuard、ChapterProductionState 已完成。
4. G3 项目漫画版式已锁定；G4 不修改该契约。
5. 所有测试使用临时 DB/workspace 和假 key，不触碰真实项目、OpenCode auth 或图片密钥。

状态：

| 状态 | 含义 |
| --- | --- |
| `not_run` | 尚未实现或未执行 |
| `passed` | 有命令、退出码和证据 |
| `failed` | 已执行但不符合契约 |
| `blocked` | 外部前置不满足，必须记录，不得当 passed |

## 2. 测试 fixture

### 2.1 标准章节

```text
project_g4_<runId>
  chapter_001
    current confirmed storyboard: shot_001, shot_002, shot_003
    current confirmed preflight: ready/current

shot_001:
  candidate_A / asset_A ready / source current
  candidate_B / asset_B ready / source current
  candidate_C / asset_C ready / source current

shot_002:
  candidate_D / asset_D ready / source current

shot_003:
  candidate_E / asset_E ready / source current
```

### 2.2 非法候选

```text
candidate_rejected       status=rejected
candidate_superseded     status=superseded
candidate_asset_staged   Asset.status=staged
candidate_asset_missing  FK/迁移异常 fixture
candidate_other_shot     属 shot_002
candidate_other_chapter  属其他 chapter
candidate_historical     source TaskApplicability=historical
candidate_legacy_unknown source TaskApplicability=legacy_unresolved
```

### 2.3 下游 fixture

```text
layoutwc_001
  image_001 -> shot_001 / lockrev_A
  image_002 -> shot_002 / lockrev_D

layoutrev_001 (Chapter.currentLayoutRevisionId)
  binding image_001 -> shot_001 / lockrev_A
  binding image_002 -> shot_002 / lockrev_D

layoutrev_old
  binding image_old -> shot_001 / older lock revision (already stale)

exportrev_001 (Chapter.currentExportRevisionId)
  -> layoutrev_001

task_layout_active
  status=running, source layoutrev_001 + current lock set digest

task_image_active
  status=running, type=image_generate, target=shot_001, source preflight
```

### 2.4 legacy snapshot

至少包含：合法 lockedCandidateId、缺失 Candidate、跨 Shot Candidate、多个 locked status 冲突、selected、layout 匹配/不匹配、export 可识别/无法识别。

## 22. Runtime/User Review

人工用户路径至少执行：

1. 每镜生成多张候选，收藏两张，确认下游不变。
2. 定稿 A，完成本章候选图，创建布局/导出 fixture。
3. 返回候选图，查看更换 B 的准确影响，确认旧产物保留文案。
4. 提交 B，确认候选仍 done、排版 needs_update、旧导出可打开。
5. 取消定稿，确认该 Shot 阻塞新排版；再 lock A，确认产生第四条修订。
6. 已导出状态下生成新 Candidate 但不定稿，确认当前布局/导出不 stale。
7. 运行 layout export task 时 replace，确认迟到结果只能 historical。
8. 模拟两个窗口并发选 B/C，确认一个成功、一个明确冲突。

## 23. 签收闸门

| 复核 | 必须结论 | 状态 |
