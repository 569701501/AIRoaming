# G3 漫画版式入口与锁定验收清单

## 1. 使用规则

本清单最初按 red → green 编写。G3-core 已于 2026-07-12 通过 36 files/195 tests、静态复核与临时运行环境复核，权威证据见 `文档/05_执行与记录/任务记录/2026-07-12_G3核心实现/`；本表逐行的旧 `not_run` 只保留为原验收设计，不再作为 core 总状态。依赖 importer 的用例仍为 `deferred`，迁移到 `G3-M施工包_可执行验收与Luna交接.md` 继续执行。

前置条件：

1. G0 的临时 workspace、fake provider、Playwright API/Chromium 骨架已实现并通过。
2. G1 冻结 Schema 基线、Project/MigrationIssue、0001～0017 migration tree、maintenance importer、协调备份/恢复和 DB-only activate 均已完成；0017 为后续剧本来源状态 forward overlay，不改变 G3 版式契约。
3. G2 F2～F4 的 immutable version、SourceSnapshot、freshness 和 persistent task runtime 已实现，G3 必须适配真实链路。
4. 测试不访问真实 workspace、真实数据库、真实 OpenCode auth 或图片 key。

证据分类：

| 分类 | 范围 | 完成影响 |
| --- | --- | --- |
| `core_mandatory` | Shared、parser、0010、API、file compatibility、Web、G2 downstream、临时重启/故障 | 阻塞 G3-core |
| `rollout_gate` | 目标 workspace 只读 audit、脱敏 DB 副本、旧构建兼容门 | 阻塞真实发布，不阻塞临时环境开发 |
| `importer_deferred` | importer、MigrationIssue 决议、final import、备份恢复、DB-only activate | 阻塞 production-ready，不阻塞 G3-core |

未另行标注的用例均为 `core_mandatory`。精确文件、命令和新增 G2 用例见 `G3施工包_下游适配与可执行证据.md`。

状态：

| 状态 | 含义 |
| --- | --- |
| `not_run` | 尚未实现或执行 |
| `passed` | 有命令、退出码与证据 |
| `failed` | 已执行但未通过，必须记录原因 |
| `blocked` | 外部条件阻止，必须说明且不能当通过 |
| `deferred` | 依赖尚未实现的 G3-M/G1 maintenance 能力，不计入 G3-core 通过数 |

若当前 Project API output 不暴露 `rowVersion`，DB mode 的 rowVersion/updatedAt 不变证据必须在同一临时 SQLite 内用 Prisma 或 direct SQL 前后读取；禁止因为 HTTP 不返回字段而删掉该断言。file mode 只断言可见 metadata 与文件内容/mtime 不变。

## 14. Runtime/User Review

实现完成后人工执行，至少录制或截图以下路径：

1. 从原项目库点击原“创建项目”按钮。
2. 只填名称，确认创建按钮不可用。
3. 分别选择两个版式，核对说明并创建。
4. 确认创建后直接进入现有剧本步骤，没有中间页。
5. 返回项目库核对卡片标签，再进入工作台核对 TopBar 标签。
6. 检查剧本、出图准备、候选图和排版页面没有可修改版式的控件。
7. 使用 API 工具发送同值/不同值 PATCH，确认均 409 且页面数据不变。
8. 重启应用，再次核对两个项目。
9. 在临时 file fixture 上确认 page_horizontal 只读投影、原文件不变，以及 four_panel/缺失/非法 fail-closed。

maintenance snapshot 的 final import 与 four_panel 决议报告延后到 G3-M Runtime/User Review，不计入本轮 G3-core。

本轮文档阶段不执行这些步骤。

## 15. 证据包

G3 完成记录至少附：

- shared/server/web/E2E typecheck 命令与退出码。
- Vitest 和 Playwright 报告。
- 两个合法项目的脱敏 API 响应。
- 缺失/旧别名/不可变 PATCH 的 HTTP 状态与 code。
- `PRAGMA table_info`、CHECK/trigger 的规范化 sqlite_master 摘要。
- G3-core 附 file audit fixture JSON；migration report/decisionsDigest 样例只在 G3-M 完成后附。
- 项目卡、创建弹窗、TopBar 的截图。
- 重启前后 Project 值对照。
- `git diff --check` 和旧 alias allowlist 扫描结果。

任何证据不得包含真实物理 workspace 根、图片 key、OpenCode auth 或完整用户内容。

## 16. 退出标准

只有同时满足以下条件才能标记 `G3-core completed`：

1. 全部 `core_mandatory` 自动化项 `passed`，无未解释失败；`importer_deferred` 不伪装为通过。
2. 两个版式都从现有弹窗创建并在重启后保持。
3. HTTP、Service、Prisma/SQL 三层不可变测试通过。
4. 所有新 runtime 路径无静默默认、无旧 alias。
5. file page alias 只读投影且不自动改写；歧义 fixture fail-closed。
6. 项目卡和工作台有只读核对，剧本步骤无可编辑版式。
7. paged 用户语义不等于横屏；`sizePolicyVersion` 与 legacy adapter 有明确删除点。
