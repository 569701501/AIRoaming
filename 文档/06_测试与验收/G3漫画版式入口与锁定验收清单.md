# G3 漫画版式入口与锁定验收清单

## 1. 使用规则

本清单在 G3 实施开始时按 red → green 执行。当前全部为 `not_run`，不得把已采纳的验收设计当作运行证据。

前置条件：

1. G0 的临时 workspace、fake provider、Playwright API/Chromium 骨架已实现并通过。
2. G1 已完成 SQLite DB-only、migration runner、MigrationIssue、备份/恢复和数据库合同测试。
3. G2 已完成 immutable version/SourceSnapshot/freshness 基础，至少不允许 G3 通过清空历史“修复”来源。
4. 测试不访问真实 workspace、真实数据库、真实 OpenCode auth 或图片 key。

状态：

| 状态 | 含义 |
| --- | --- |
| `not_run` | 尚未实现或执行 |
| `passed` | 有命令、退出码与证据 |
| `failed` | 已执行但未通过，必须记录原因 |
| `blocked` | 外部条件阻止，必须说明且不能当通过 |

## 14. Runtime/User Review

实现完成后人工执行，至少录制或截图以下路径：

1. 从原项目库点击原“创建项目”按钮。
2. 只填名称，确认创建按钮不可用。
3. 分别选择两个版式，核对说明并创建。
4. 确认创建后直接进入现有剧本步骤，没有中间页。
5. 返回项目库核对卡片标签，再进入工作台核对 TopBar 标签。
6. 检查剧本、出图准备、候选图和排版页面没有可修改版式的控件。
7. 使用 API 工具发送同值/不同值 PATCH，确认均 409 且页面数据不变。
8. 重启应用，再次核对两个项目。
9. 在 maintenance snapshot 上查看 page_horizontal 自动映射和 four_panel 决议报告。

本轮文档阶段不执行这些步骤。

## 15. 证据包

G3 完成记录至少附：

- shared/server/web/E2E typecheck 命令与退出码。
- Vitest 和 Playwright 报告。
- 两个合法项目的脱敏 API 响应。
- 缺失/旧别名/不可变 PATCH 的 HTTP 状态与 code。
- `PRAGMA table_info`、CHECK/trigger 的规范化 sqlite_master 摘要。
- migration report/decisionsDigest 的脱敏样例。
- 项目卡、创建弹窗、TopBar 的截图。
- 重启前后 Project 值对照。
- `git diff --check` 和旧 alias allowlist 扫描结果。

任何证据不得包含真实物理 workspace 根、图片 key、OpenCode auth 或完整用户内容。

## 16. G3 退出标准

只有同时满足以下条件才能标记 G3 complete：

1. 本清单 mandatory 自动化项全部 `passed`，无未解释失败。
2. 两个版式都从现有弹窗创建并在重启后保持。
3. HTTP、Service、Prisma/SQL 三层不可变测试通过。
4. 所有新 runtime 路径无静默默认、无旧 alias。
5. 所有 legacy 歧义有 MigrationIssue/决议/报告，未决 blocker 为 0。
6. 项目卡和工作台有只读核对，剧本步骤无可编辑版式。
7. paged 用户语义不等于横屏；临时 adapter 有版本和 G5 删除点。
8. Scrutiny Review 与 Runtime/User Review 通过并留痕。
9. 上位产品、架构、模块、测试、会话与长期记忆已经同步。
