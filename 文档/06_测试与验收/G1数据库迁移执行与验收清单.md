# G1 数据库迁移执行与验收清单

## 1. 使用方式

本文是未来实施 G1 时的 go/no-go 清单。任何单项命令成功都不能替代整体验收；特别是：

- `prisma validate` 只证明 schema 语法，不证明 migration、数据、任务或切换正确。
- `migrate deploy` 不检测数据库 drift，必须另做 schema/check/trigger/index 对照。
- `integrity_check` 不检查 foreign key，必须再运行 `foreign_key_check`。
- 只打开项目列表不证明 pending、任务、素材和 DB-only 隔离正确。

状态：

| 状态 | 含义 |
| --- | --- |
| `not_run` | 尚未实施或执行 |
| `pass` | 有命令、断言和证据 |
| `fail` | 明确失败，禁止进入下一闸门 |
| `blocked` | 外部条件未满足，有责任人和解除条件 |
| `not_applicable` | 说明理由，不得空白跳过 |

## 2. 测试环境硬隔离

每个自动化 run 必须创建：

```text
tempRoot/<runId>/.airoaming-test-root
tempRoot/<runId>/workspace/
tempRoot/<runId>/data/db/
tempRoot/<runId>/data/migration-runs/
tempRoot/<runId>/fake-secret-store/
```

环境要求：

- `AIROAMING_WORKSPACE_ROOT` 和 `AIROAMING_DATA_ROOT` 均指向 runId 临时目录。
- DB URL 只指向该临时 dataRoot。
- 拒绝仓库默认 `workspace/`、用户 home、文件系统根和真实 dataRoot。
- fake OpenCode/image provider 只监听 loopback 动态端口。
- SecretStore 使用 fake adapter 和唯一 sentinel；平台 Keychain 只在隔离 E0/人工测试中使用测试 credentialId。
- Playwright `reuseExistingServer=false`。
- 清理前再次验证 marker、runId 和路径父级；任一不匹配直接失败，不执行 rm。

## 13. 正式切换检查表

### 13.1 C0 发布准备

- [ ] 同一 G1 bridge release 已以 file 模式启动，具备 maintenance/runtime bundle/SecretStore 兼容，但没有运行期 DB+JSON 双写。
- [ ] bridge 重启前，用户已处理或明确放弃旧进程内不可持久 pending/对话；报告包含 `PRE_BRIDGE_RUNTIME_UNOBSERVABLE` 说明而非伪造迁移成功。
- [ ] 代码版本、Prisma 版本、migration checksum、importerVersion 已冻结。
- [ ] G0/G1 自动化全绿。
- [ ] 最近 shadow snapshot 与即将切换源之间无未解释结构变化。
- [ ] dataRoot 与备份盘空间足够，权限正确。
- [ ] 用户再次明确授权正式迁移和停写。

### 13.2 C1 维护与清空活动运行态

- [ ] 旧 file 进程未重启；本地管理 CLI 已让同一 PID 从 open -> draining -> closed。

## 18. 最终 go/no-go

只有同时满足以下条件，G1 才可标记完成：

1. M0–M6 所属自动化与人工闸门均 pass。
2. 正式 MigrationReport blocker=0，warning 已逐项接受。
3. DB-only 运行不读写旧业务 JSON/Markdown。
4. 对话、pending、任务和素材在重启/故障后可恢复或诚实进入 needsReview。
5. 图片 key 只存在后端 SecretStore，文本 key 只归 OpenCode auth；泄密扫描为 0。
6. legacy task 保留原 taskId 且永不可执行，不伪造状态。
7. backup/restore 和开放写入前回滚实测通过。
8. Runtime/User Review 完成，真实项目逐阶段可读。
9. G0 migration witness 已逐条被 DB 等价测试接替。
10. M6 没有自动删除旧 metadata 档案或备份。

任何 blocker、secret 泄漏、foreign key 违反、旧文件 fallback、Asset 摘要冲突或 active legacy task 都是 no-go。
