# G1 数据库迁移执行与验收清单

## 1. 使用方式

本文最初是 G1 实施时的 go/no-go 清单。G1 现已完成 44 模型、0001～0016 forward-only migration、final importer、协调备份恢复、C0～C7、首笔 DB-only 写、file guard 和 R2 OBS-01～10；总体证据见 `文档/05_执行与记录/功能完成记录/2026-07-15_G0至G5阶段完成.md` 与 `文档/05_执行与记录/任务记录/2026-07-14_G0至G5剩余连续施工/`。下文逐项表格保留实施时的设计与阶段证据，旧 `not_run/blocked` 不再覆盖 G1 总体完成态。任何单项命令成功都不能替代整体验收；特别是：

- `prisma validate` 只证明 schema 语法，不证明 migration、数据、任务或切换正确。
- `migrate deploy` 不检测数据库 drift，必须另做 schema/check/trigger/index 对照。
- `integrity_check` 不检查 foreign key，必须再运行 `foreign_key_check`。
- 只打开项目列表不证明 pending、任务、素材和 DB-only 隔离正确。

状态：

| 状态 | 含义 |
| --- | --- |
| `not_run` | 尚未实施或执行 |
| `pass` | 有命令、断言和证据 |
| `fail` | 明确失败，禁止进入下一闸门 |
| `blocked` | 外部条件未满足，有责任人和解除条件 |
| `not_applicable` | 说明理由，不得空白跳过 |
| `historical` | 旧流程证据，仅留痕且不参与当前门禁 |

## 2. 测试环境硬隔离

每个自动化 run 必须创建：

```text
tempRoot/airoaming-e2e-<runId>/.airoaming-test-root
tempRoot/airoaming-e2e-<runId>/workspace/
tempRoot/airoaming-e2e-<runId>/data/db/
tempRoot/airoaming-e2e-<runId>/data/migration-runs/   # M0 migration 测试按需创建

tempRoot/airoaming-e2e-<runId>/xdg-config/
tempRoot/airoaming-e2e-<runId>/xdg-cache/

```

环境要求：

- `AIROAMING_WORKSPACE_ROOT` 和 `AIROAMING_DATA_ROOT` 均指向 runId 临时目录。
- DB URL 只指向该临时 dataRoot。
- 拒绝仓库默认 `workspace/`、用户 home、文件系统根和真实 dataRoot。
- fake OpenCode/image provider 只监听 loopback 动态端口。
- SecretStore 使用 fake adapter 和唯一 sentinel；平台 Keychain 只在隔离 E0/人工测试中使用测试 credentialId。
- Playwright `reuseExistingServer=false`。
- 清理前再次验证 marker、runId 和路径父级；任一不匹配直接失败，不执行 rm。
