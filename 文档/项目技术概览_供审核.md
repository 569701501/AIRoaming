## 0. 给审核 AI 的入口说明

请基于本文对项目进行**架构与实现合理性审核**。建议审核维度：

1. **技术选型是否匹配产品目标**（本地内部工具、生成式内容流水线）。
2. **架构分层与模块边界是否清晰**（前端 / 后端 / AI 运行时 / 文件系统）。
3. **数据持久化策略是否一致且有演进路径**（Prisma + SQLite 与 workspace 文件态并存）。
4. **AI 边界与受控写入设计是否安全**（AI 不能直接操作本地物理路径）。
5. **文档事实源与代码实现是否存在偏差**（本文第 10 节列出了已发现的疑点，请核实并补充）。
6. **MVP 主链路的完成度与风险**（第 5、11 节）。

审核输出建议：按「严重问题 / 设计建议 / 偏差确认 / 可选优化」分级给出结论。

## 1. 项目身份与定位

| 项 | 内容 |
| --- | --- |
| 项目代号 | AI漫游 |
| 前端展示品牌 | 绘界漫画 |
| 项目类型 | 内部生成式内容生产工作台（非公开 SaaS，本地单用户优先） |
| 核心目标 | 把故事创意**稳定、可控地**转化为：结构化剧情 → 分镜 → 漫画图候选 → 漫画页面 → 素材包 |

- 先把漫画主链路做扎实，轻漫剧只做基础合成。

### 4.3 AI 运行时与生成

- **对话运行时**：第一阶段采用 **OpenCode headless server**（`opencode serve`），承接消息发送、流式输出、模型选择、provider 配置。AI漫游自维护 `ConversationThread / ConversationMessage / ProjectContextFact` 作为业务事实源，OpenCode Session 仅作运行时映射。
- **OpenCode AI 资产层**：`apps/server/opencodeAI/`（agents / skills / 受控 tool 源码），如 `script-import-normalize`、`script-inspiration-seeding`、`script-chapter-drafting`、`script-chapter-editing`、`airoaming__script-collaboration-agent` 等。
- **图片生成**：OpenAI 兼容图片接口，模型固定 `gpt-image-2`；`baseUrl/apiKey` 来自后端图片专用运行时配置或设置页 `imageProvider`，不复用对话 key；进程内**串行** worker 避免 429。

## 5. 系统架构

```text
┌────────────── Web 工作台（apps/web，Vue3）──────────────┐
│ 项目库 / 7步工作区 / 对话框 / 角色库 / 设置            │
└───────────────────────┬─────────────────────────────────┘
                        │ REST + SSE
┌───────────────────────▼─────────────────────────────────┐
│                NestJS API（apps/server）                 │
│ projects / tasks / dialogue / ai-runtime / settings /   │
│ workspace / health                                      │
└───────────────────────┬─────────────────────────────────┘
                        │
        ┌───────────────┼────────────────┐
        │               │                │
┌───────▼──────┐  ┌──────▼───────┐  ┌─────▼──────────────┐
│  Prisma DB   │  │  Workspace   │  │  AI Runtime/Provider│
│  (SQLite)    │  │  本地文件系统 │  │  OpenCode / 图片   │
└──────────────┘  └──────────────┘  └────────────────────┘
```

分层职责：前端只做编辑/预览/选择/导出操作；后端做 API/校验/任务调度/路径管理；AI 层封装 provider，不直接写业务库；文件系统保存全部素材并与 `Asset` 对应。

异步任务状态机：`queued → running → succeeded/failed/cancelled/retrying`，进度推送走 SSE（`task.created/started/progress/asset.created/succeeded/failed/cancelled`）。当前队列是**内存态**，服务重启不恢复 running 任务。

## 7. 数据模型与持久化现状（⚠️ 审核重点）

### 7.1 数据建模原则（文档）

- 中间产物可追溯；AI 任务输入输出留存；图片/音频/视频/PDF 统一抽象为 `Asset`。
- **章节是项目内一等工作单元**，剧本/结构/分镜/候选/排版/导出优先挂 `chapterId`。
- 项目级角色、世界观、通用场景、共享素材挂 `projectId` 复用。
- 对话记录按步骤隔离；跨步骤只共享已确认事实。

### 7.2 Prisma 实际 model（`schema.prisma`）

当前 Prisma schema 仅包含 **6 个 model**：

```text
Project, StoryVersion, Shot, Candidate, Asset, GenerationTask
```

### 7.3 文档描述但 Prisma 未建表的实体

文档数据模型描述了 `ProjectWorkflow, Chapter, ChapterScriptVersion, StoryBeat, Character, SceneLocation, LayoutPage, PanelPlacement, ConversationThread, ConversationMessage, ProjectContextFact, VideoDraft, VideoSegment` 等实体，但**多数当前以 workspace 文件态存在**（如 `chapter.json`、`script.md`、`structure.json`、`storyboard.json`、`workflow.json`），而非 Prisma 表。

> ⚠️ 请审核者重点判断：**关系数据（Prisma）与文件态（workspace JSON/MD）的边界是否清晰、是否有双写不一致风险、演进路径是否明确**。例如 `Chapter`、`Character`、对话线程当前落盘方式与 Prisma `Project/Shot/Candidate` 的关联如何保持一致（`chapterId` 在 Prisma model 中未见字段）。

## 8. 关键设计决策与约束

| # | 决策/约束 | 要点 |
| --- | --- | --- |
| 1 | **AI 受控写入边界** | AI 不能直接操作本地物理路径、不能执行 bash；剧本/章节写入必须经 AI漫游受控工具/API（如 `update_chapter_draft`），保留来源追溯 |
| 2 | **章节工作单元** | `Chapter` 是项目内一等单元；覆盖非空章节、替换整本、低可信拆章、跨阶段产物失效必须先让用户确认 |
| 3 | **对话隔离** | 组件公共，记录按 `projectId+stepKey`（剧本再加 `chapterId`）隔离；未确认内容不跨步骤 |
| 4 | **统一任务协议** | 所有生成/导出任务走统一信封（`target`/`input`/`options`/`trace`）；章节作用域任务强制 `chapterId` |
| 5 | **待确认 → 正式** | 剧情结构/分镜等 AI 产物先「待确认预览」，用户确认后才转正式、才允许进入下一步 |
| 6 | **当前锁定与历史候选分离** | `Shot.lockedCandidateId` 指向当前锁定，历史 `Candidate` 不被覆盖 |
| 7 | **角色一致性** | 不做模型层一致性训练；靠参考图约束 + 视觉版本管理；定稿图用于候选图后旧参考图不可覆盖，只能新建版本 |
| 8 | **Web 优先、桌面壳后置** | ADR-0003；避免 MVP 陷入桌面打包复杂度 |
| 9 | **OpenCode 最小移植** | 只接对话运行时，不迁 Aurora 完整 Docker sandbox / Phaser / 计费 / 团队 |
| 10 | **密钥安全** | 全局设置密钥文件被 `.gitignore` 排除；前端只读掩码/指纹；后端服务端侧同步给 OpenCode |

## 10. 已发现的文档/代码偏差疑点（请审核核实）

1. **Tailwind / shadcn-reka-ui**：文档列为前端样式/UI 方案，但 `apps/web/package.json` 未引入。需确认前端实际样式实现。
2. **Prisma model 覆盖面**：schema 仅 6 表，大量实体（Chapter/Character/对话线程等）为文件态；`chapterId` 关联在 Prisma 层无字段，一致性靠应用层维护。
3. **`Shot` 仍挂 `storyVersionId`**：schema 中 `Shot.storyVersionId` 指向 `StoryVersion`，但文档强调章节工作单元与 `chapterId` 关联，两者模型口径需对齐。
4. **模型选择 UI**：文档记为「部分实现，下拉待恢复」，请核实当前对话面板是否已恢复可见模型选择。
5. **任务队列持久化**：内存态，重启丢失 running 任务，文档已列为已知限制。

## 11. 已知风险与待办

- **主链路未闭环**：候选图工作台 / 排版导出 / 素材包（步骤 5-7）未实现，漫画主链路尚未端到端跑通。

- **章节编辑安全网**：回到上一章编辑的「产物失效提示」未接入，存在跨阶段数据不一致风险。
- **持久化一致性**：文件态与 DB 双轨，缺乏事务/校验，长期存在漂移风险。
- **队列/数据库扩展**：内存队列、SQLite 为 MVP 取舍，需明确迁移触发条件。
