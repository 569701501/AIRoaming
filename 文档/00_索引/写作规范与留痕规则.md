## 1. 正式文档结构

正式文档应包含：

1. 标题
2. frontmatter 元数据
3. 背景或目标
4. 主体内容
5. 验收或判断标准
6. 风险、非目标或后续事项

## 2. Frontmatter 字段

```yaml
---
doc_id: AIR-XXX-001
status: active
created: 2026-05-23
updated: 2026-05-23
owner: AI漫游项目
audience: human, ai-agent
source: 来源说明
---
```

| 字段 | 说明 |
| --- | --- |
| `doc_id` | 稳定 ID，方便 AI 引用 |
| `status` | 文档状态，使用 `draft/active/in_progress/superseded/archived` |
| `created` | 创建日期 |
| `updated` | 最近更新日期 |
| `owner` | 负责维护者 |
| `audience` | 面向对象 |
| `source` | 来源、依据或参考 |

## 3. 方案文档格式

方案文档应包含：

- 背景与问题
- 目标与非目标
- 现状探索
- 方案概览
- 详细设计
- 数据与协议影响
- 风险与回滚
- 验收标准
- 里程碑与任务

### 3.1 ADR 格式

不可轻易回退的产品或技术决策必须记录决策状态、背景、不变量、被否决备选、后果、迁移、回滚和验证标准。使用 `文档/90_模板/ADR模板.md`，不要从旧 ADR 复制后遗留错误编号或过期术语。

### 3.2 验收清单格式

验收清单必须有唯一用例 ID、明确结果状态、事实源映射、证据路径、失败/恢复/安全检查和 Runtime/User Review。使用 `文档/90_模板/验收清单模板.md`；`not_run` 不能被统计为通过，静态检查不能替代真实用户路径。

## 4. 任务记录格式

复杂任务目录必须有三件套：

```text
task_plan.md
progress.md
findings.md
```

`task_plan.md` 记录：

- 目标
- 当前阶段
- 阶段列表
- 关键问题
- 已做决策
- 错误记录
- 退出标准
- 当前深思熟虑角色边界

`progress.md` 记录：

- 会话日期
- 阶段状态
- 已采取操作
- 创建或修改文件
- 验证命令与结果
- 下一步
- Handoff

`findings.md` 记录：

- 需求理解
- 研究发现
- 证据路径
- 缺口和风险
- 技术决策
- 遇到的问题
- Scrutiny Review 和 Runtime/User Review 发现

只有用户明确要求或任务确实复杂高风险时，才使用 `$deep-think` 并创建三件套。普通对话、小改、探索性讨论不创建任务记录。

如需创建正式任务记录，可使用：

```text
文档/90_模板/深思熟虑任务包模板.md
```

## 5. 功能完成记录格式

完成记录必须回答：

| 问题 | 说明 |
| --- | --- |
| 完成了什么 | 用一句话描述用户可感知结果 |
| 为什么做 | 关联需求、方案或 ADR |
| 改了哪里 | 文件、模块、数据、协议 |
| 怎么验证 | 命令、截图、样例、人工验收 |
| 风险是什么 | 已知问题、未覆盖测试、后续工作 |

## 6. AI 可读写法

推荐写法：

- 用表格列字段和状态。
- 用 JSON 描述输入输出。
- 用枚举描述状态机。
- 用 ASCII 图描述流程。
- 用清晰路径指向事实源。

避免写法：

- 只写“已完成”“待优化”，不说明证据。
- 在多个文档里重复维护同一份字段定义。
- 把历史原因写进当前契约。
- 让 AI 依赖“上文提过”的隐含信息。

## 7. 功能完成的强制留痕

有持续价值的功能完成后，新增：

```text
文档/05_执行与记录/功能完成记录/YYYY-MM-DD_<功能名>.md
```

同时检查是否需要更新：

- `01_愿景与产品`
- `02_架构与契约`
- `03_模块梳理`
- `04_方案与决策`
- `06_测试与验收`

以下情况不强制新增完成记录：

- 用户明确要求删除或推翻的试错实现。
- 未形成当前事实的页面草稿。
- 小范围文案、索引、路径修正。

## 8. 判断文档该放哪里

| 内容 | 位置 |
| --- | --- |
| 当前事实 | `01_愿景与产品`、`02_架构与契约`、`03_模块梳理` |
| 为什么这样做 | `04_方案与决策` |
| 正在怎么做 | `05_执行与记录/任务记录` |
| 做完了什么 | `05_执行与记录/功能完成记录`，仅限有持续价值的完成项 |
| 怎么证明可用 | `06_测试与验收` |
| 被推翻的试错 | `98_历史归档` |
| 旧种子和过期材料 | `99_原始种子` |

## 9. 深思熟虑留痕要求

使用 `$deep-think` 的复杂任务完成前，应具备：

- `task_plan.md`：阶段状态和退出标准。
- `progress.md`：执行过程、修改文件、命令和 Handoff。
- `findings.md`：发现、风险、证据和复核结论。
- 完成记录：最终交付、验证结果和残留风险。

复核结论必须区分：

| 复核 | 关注点 |
| --- | --- |
| Scrutiny Review | 静态检查、数据协议、文档一致性、测试证据 |
| Runtime/User Review | 真实页面、任务状态、导出物、素材追溯、人工体验 |
