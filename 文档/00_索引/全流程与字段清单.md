## 0. 文档说明

本文档用于回答三件不同的事：

1. 当前代码和 workspace 已经能做什么。
2. 已经存在但只属于早期骨架的能力是什么。
3. G1–G6 已采纳或后置的目标是什么。

这三层不得混写为一个“已完成”状态。字段的唯一类型事实源仍是 `packages/shared/src/dto.ts` 与 `packages/shared/src/domain.ts`；数据库目标以 G1 Schema 字典为准；本文件只做全链路索引和现状快照，不复制所有底层 Schema。

状态标记：

| 标记 | 含义 |
| --- | --- |
| ✅ 当前实现 | 代码、接口和持久化链路已经存在 |
| 🟡 基础骨架 | 能运行，但不满足已采纳的正式完成语义 |
| 🔵 已采纳未实现 | 用户已经确认方案，当前代码尚未迁移 |
| ⏸ 后置 | 保留产品位置，本开发波次不实施 |
| ❌ 未实现 | 当前没有对应运行能力 |

不要依赖易漂移的源码行号；文中使用稳定类型、服务和文件名定位事实。

## 1. 全局速览

### 1.1 七步主流程

```text
剧本 project_story
  → 剧情结构 story_structure
  → 分镜工作台 storyboard
  → 出图准备 image_preflight
  → 候选图工作台 image_candidates
  → 排版导出 layout_export
  → 素材包 asset_package
```

`项目角色库 /characters` 是项目级常驻资产入口，不进入七步线性序号。场景当前属于章节剧情结构，场景参考图也写在章节目录。

| 顺序 | stepKey | scope | 当前推进证据 | 当前波次口径 |
| --- | --- | --- | --- | --- |
| 1 | `project_story` | chapter | 保存/完成章节剧本 | 已实现；G2 将改为 Working Copy + 不可变正式版本 |
| 2 | `story_structure` | chapter | 生成、编辑、确认结构 | 已实现；G2 将禁止原地改 confirmed |
| 3 | `storyboard` | chapter | pending、编辑、确认分镜 | 已实现；G2 将改为不可变 StoryboardVersion |
| 4 | `image_preflight` | chapter | 检查并确认 `preflight.json` | 已实现 |
| 5 | `image_candidates` | chapter | 真实生成、登记、锁定、完成本章 | 已实现旧模型；G4 定稿修订未实现 |
| 6 | `layout_export` | chapter | 一镜一页与复制源图导出 | 基础骨架；G5 正式成稿出版未实现 |
| 7 | `asset_package` | project | 目录包 + manifest | 基础骨架；G6 ZIP/下载/正式包后置 |

### 1.2 生成任务类型：10 项

Shared `GENERATION_TASK_TYPES` 是唯一枚举事实源：

| 任务类型 | 当前真实执行方式 | 当前状态 |
| --- | --- | --- |
| `character_reference_generate` | 角色专用 API 创建受控任务；角色/场景共享串行队列调用图片 provider | ✅ 当前实现 |
| `scene_reference_generate` | 章节场景专用 API 创建 `target.type=scene` 任务；调用图片 provider | ✅ 当前实现 |
| `story_parse` | 当前主路径由对话受控工具生成/确认剧情结构；通用 TasksService 无独立真实 worker | ✅ 业务链已实现，非持久任务 worker |
| `shot_generate` | 当前主路径由对话受控工具生成 pending 分镜并确认 | ✅ 业务链已实现，非持久任务 worker |
| `shot_prompt_generate` | 枚举保留；当前候选生产路径由服务端 `CandidateGenerationSpec` 在 `image_generate` 前直接组装 Prompt | 🟡 通用任务仍走 mock，不是当前生产主路径 |
| `image_generate` | `ImageCandidateService` 注册真实 worker，串行调用当前图片 provider | ✅ 当前实现 |
| `layout_export` | 当前 Web 直接调用 `LayoutExportService`；任务枚举没有注册真实 worker | 🟡 同步服务骨架，不是正式任务实现 |
| `tts_generate` | 通用 mock | ❌ 未实现 |
| `video_export` | 通用 mock | ❌ 未实现 |
| `asset_package_export` | 当前 Web 直接调用 `AssetPackageService`；任务枚举没有注册真实 worker | 🟡 同步目录包骨架，不是正式任务实现 |

任务 runtime 状态仍为：

```text
queued / running / succeeded / failed / cancelled / retrying
```

当前 `TasksService` 仍使用进程内 Map；只有注册 worker 的类型走真实 worker，其余通用任务走 `runMockTask`。D75/G1 已采纳的 SQLite 持久任务、Attempt、lease、恢复和统一图片并发通道尚未实现。

## 2. 逐阶段字段与现状

### 2.1 Project

当前文件态主要字段：

| 字段 | 当前语义 |
| --- | --- |
| `id/name/type/status` | 项目身份、类型和旧项目级状态 |
| `currentChapterId` | 当前工作章节 |
| `storyTitle/genreTags/artStyle` | 项目创作上下文 |
| `comicFormat` | 当前 runtime 漫画版式值 |
| `createdAt/updatedAt` | 时间戳 |

`comicFormat` 必须区分当前与目标：

| 层级 | 合法值 | 状态 |
| --- | --- | --- |
| 当前 Shared/file runtime | `vertical_scroll/page_horizontal/four_panel`；缺值会默认 `vertical_scroll`，普通更新仍能修改 | 当前旧实现 |
| 当前 DB Schema | CHECK 只允许 `vertical_scroll/paged_comic`，但 repository 仍有旧 alias 转换，尚无不可变 trigger | G1 基座已存在，G3 未接线 |
| ADR-0009/G3-core 目标 | `vertical_scroll/paged_comic`；创建弹窗默认空且必选，创建后不可直接修改；file page alias 只读投影且保留原文件 | 🟦 五份施工资料已齐，业务实现未开始 |

`page_horizontal` 在 file input boundary 只读投影为 `paged_comic`，最终导入仍归 G3-M；`four_panel/缺失/非法` 在 core 中 fail-closed，未来由 importer 决议。四格意图迁移到 `LayoutPreset.four_panel`，不再作为项目级版式。分页漫画不等于横屏。

### 2.2 Chapter 与 Script

`Chapter` 当前状态：

```text
draft → script_done → structured → storyboard_done
      → images_done → layout_done → exported
```

当前主要字段为 `id/projectId/slug/order/title/status/storyboardStatus/currentScriptVersionId/currentStoryVersionId/summary/sourceTextPreview/lastScriptRevision/createdAt/updatedAt/completedAt`；详情 DTO 另含完整 `sourceText/scriptPath`。

当前 `script.md` 是生效文本，`script.versions/script-vNNN.md` 是完成本章时的快照，`script.revisions/latest.json` 保存最近一次操作来源。G2 将把 Chapter 文本明确为 Working Copy，并使正式 ScriptVersion 不可变。

### 2.3 Character

正式领域实体名为 `Character`。当前 Shared 文件态 DTO 类型叫 `ProjectCharacter`，两者表达同一角色记录，不是两套角色实体。

当前主要字段：

| 字段组 | 字段 |
| --- | --- |
| 身份 | `id/projectId/name/role/level/entityType/status/source` |
| 描述 | `appearance/personality/promptFragment` |
| 视觉 | `referenceAssetIds/previewReferenceAssetId/primaryReferenceAssetId/primaryReferenceKind/visualVersion` |
| 时间 | `previewConfirmedAt/finalizedAt/createdAt/updatedAt` |

角色层级：

```text
lead / recurring / chapter / minor / extra
```

角色视觉：

| kind | 正式含义 |
| --- | --- |
| `preview_front` | 正面半身预览图 |
| `final_reference` | 一张四要素角色定稿组合图：正面半身、正面全身、侧面全身、背面全身 |
| `none` | 特殊兼容值，新项目默认不使用 |

正式契约统一使用“角色定稿组合图”，不再用“三视图”暗示只有三个内容项。`lead/recurring` 必须有 `final_reference`；`chapter/minor/extra` 按本章出镜次数决定，出镜至少 2 次才强制。

### 2.4 章节场景与场景视觉

当前 `StoryStructureSceneCard` 字段：

```text
id / name / location / timeOfDay / atmosphere / purpose / referenceAssetId
```

`scene_reference_generate` 已真实接入图片 provider，成功后写章节级 WebP、注册 Asset，并回写 `referenceAssetId`。

旧 `核心数据模型.md` 中的项目级 `SceneLocation` 不是当前 runtime 实体。G1 已采纳目标使用 `ChapterScene + SceneVisual` 关系化当前章节场景与视觉版本；跨章节复用场景仍是后续产品能力，不能把旧 `SceneLocation` 样例当成已实现。

### 2.5 StoryStructure

`StoryStructureJson` 当前主要字段：

```text
schemaVersion / chapterId / chapterTitle / sourceScriptVersionId
synopsis / direction / characters[] / scenes[] / beats[] / notes
createdAt / updatedAt
```

`StoryStructureCharacterCard.projectCharacterId` 是兼容字段名，引用正式项目角色 `Character.id`。AI 生成 pending 时不填，由确认流程按 name 匹配/新建角色后回填。

当前剧情结构支持 pending 生成、字段编辑、确认和文件落盘；正式内容仍可能原地更新。G2 将改为 Working Copy/pending 与不可变正式版本分离。

### 2.6 Storyboard

`StoryboardShot` 当前正式结构：

| 层级 | 字段 |
| --- | --- |
| Shot 核心 | `id/order/beatId/sceneId/characterIds/coreAction/emotion/shotType/cameraAngle/promptDraft/status/lockedCandidateId` |
| `comic` | `panelDescription/composition/dialogue/caption/panelRhythm` |
| `motion` | `visualDescription/compositionDesign/cameraMovement/frameType/durationMs/durationHint/voiceLines[]` |

`shotType/cameraAngle/panelRhythm/cameraMovement/frameType` 使用 Shared 英文受控枚举；`voiceLines[]` 是唯一新写台词字段。旧 `voiceRole/line` 只允许兼容读取。

当前先写 `storyboard.pending.json`，用户确认后写 `storyboard.json`。`promptDraft` 只是中间草稿；真实候选 Prompt 由服务端 `CandidateGenerationSpec` 构建。

已登记代码 TODO：`buildStoryboardPrompt` 仍把合法 `over_shoulder` 写成 `over_the_shoulder`，会被 normalize 降级为 `eye_level`；本轮只修文档，不修改代码。

### 2.7 ImagePreflight

当前 `ChapterImagePreflight` 已实现：

- 读取正式 storyboard、角色、场景和项目风格。
- 生成 `characterChecks/sceneChecks/styleCheck/issues`。
- 用户确认后写 `preflight.json`。
- `shot_prompt_generate/image_generate` 创建前必须通过 guard。

当前 workspace 已有第 1 章 confirmed preflight，旧“示例项目尚未触发确认”的结论已经失效。G2 将把它升级为不可变 PreflightRevision 和完整来源摘要。

### 2.8 Candidate

当前不再是 DTO-only。Shared 与 runtime 已有：

```text
ProjectCandidate
ChapterCandidates
WorkbenchCandidate
CandidateGenerationSpec
```

`ProjectCandidate` 主要字段：

```text
id / projectId / chapterId / shotId / taskId / assetId / index
status / label / promptDigest
generationPurpose / generationSpecVersion / generationSpecDigest
createdAt / updatedAt
```

当前能力：

- `image_generate` 真实调用 provider。
- 每个候选写 WebP、`candidates.json` 和 `shared/assets.json`。
- 工作台展示真实图片、批次、Prompt 预览和批量生成。
- 单镜头可锁定；`Shot.lockedCandidateId` 与 Candidate 状态同步更新。
- 全部镜头锁定后可把章节推进到 `images_done`。

当前仍是 G4 前旧模型：定稿会原地改 Candidate 状态与 `lockedCandidateId`，没有 `CandidateLockRevision`、影响预览、并发摘要和下游 stale。G4 已采纳但尚未实现。

### 2.9 Layout

当前 Shared 已有 `PanelPlacement/LayoutPage/ChapterLayout`，Server/Web 已有 `LayoutExportService` 与 `LayoutExportWorkspace`，因此“完全未建模”已经失效。

当前基础骨架：

- 要求每个 Shot 已有锁定候选。
- 自动生成一镜一页，每页只有一个 placement。
- 导出时复制每页第一张候选源图到 `exports/pages/`。
- 写 `layout/layout.json`、登记导出 Asset，并推进 `layout_done`。
- Web 直接调用同步 API；`layout_export` 任务类型本身没有真实 worker。

它不等于 G5 正式成稿编辑器：没有自由画格、文字、气泡、裁切、Working Copy/LayoutRevision、来源 stale、确定性合成、PDF 或条漫切片。G5 已采纳，尚未实现。

### 2.10 AssetPackage

当前 Shared 已有 `AssetPackageManifestFile/AssetPackageManifest`，Server/Web 已有 `AssetPackageService` 与 `AssetPackageWorkspace`，因此“完全未建模”已经失效。

当前基础骨架：

- 只允许在章节 `layout_done/exported` 后执行。
- 复制章节剧本、结构、分镜、preflight、候选索引、布局、锁定候选和页面导出。
- 写项目级 `exports/packages/{packageId}/manifest.json`。
- 注册一个 `type=archive` 的文件态 Asset，并把章节推进到 `exported`。
- Web 直接调用同步 API；`asset_package_export` 任务类型本身没有真实 worker。

当前产物是本地目录，不是 ZIP；没有下载、不可变 ExportRevision 来源、摘要完整性和 G6 正式包契约。G6 已后置，现有骨架保留但不作为当前 G0–G5 完成标准。

## 4. 当前已知陷阱与开发停止线

1. `StoryboardShot.characterIds` 当前可能保存 Character ID，也可能保留角色名 token；新实现不得假设全是稳定 ID。
2. 当前 Shared/file `comicFormat` 仍是三值、可默认、可更新；DB Schema 两值不等于 G3 已实现。必须按五份施工资料完成 core，不能提前宣称 production-ready。
3. DB mode 已有 `shot_prompt_generate/image_generate` persistent worker；file mode 仍走兼容生成路径。G3 必须同时更新 Candidate V2 与 DB promptSpec V2，不能只修一条路径。
4. DB mode 已实现 claim/lease/Attempt/recovery；file `TasksService` 仍是进程内兼容状态。不得用其中一条路径的证据替代另一条。
5. 当前锁定只写 `Candidate.status + Shot.lockedCandidateId`；不得假装已有 G4 修订链或影响预览。
6. 当前排版只是复制候选源图；不得作为多格合成、文字气泡、PDF 或确定性出版证据。
7. 当前素材包只是目录；不得作为 ZIP、下载或 G6 完成证据。
8. 当前 workspace 有 4 个未登记到 `candidates.json` 的候选 WebP；迁移、清理或恢复前必须先报告，不能静默删除或导入为成功 Candidate。
9. 当前 DTO 名 `ProjectCharacter` 与正式实体 `Character` 是兼容层与领域层的命名差异，不允许据此再建立第二套角色表。
10. 场景任务当前按 `projectId + sceneId` 去重，未包含 `chapterId`；章节间重复 `scene_01` 可能错误复用任务，待开发时先加回归测试再修复。

## 6. 维护规则

- 运行代码改变任务类型、target、字段、路径或实现状态时，同一任务必须更新本文档。
- “当前实现”必须有代码或真实数据证据；方案/ADR 只能证明“已采纳目标”。
- workspace 样例只证明该样例实际走到的位置，不能单独证明代码能力不存在。
- 历史完成记录保留当时事实；本索引只维护当前事实，不复制历史过期结论。
- 每次更新后至少检查：10 个任务类型、8 个 target 类型、七步 workflow、当前规范路径、Candidate/Layout/AssetPackage 状态和 G1–G6 边界。
