## 0. 文档说明

本文档梳理 AI 漫游项目从「剧本」到「素材包」的完整生产流程,列出**每一个阶段的实体数据结构、字段含义、真实数据示例、实现现状**。

- **用途**:作为项目全流程字段的事实参考,供人/AI/AI 助手讨论架构、补全字段、判断现状时使用。
- **数据来源**:`packages/shared/src/dto.ts`(类型定义)+ `packages/shared/src/domain.ts`(枚举)+ `apps/server/src/projects/projects.service.ts`(存储与归一化逻辑)+ `workspace/projects/e3b57aeb-...`(真实项目「项目1 / 食梦诊所」的落盘数据)。
- **如何阅读**:先看第 1 节全局速览,再看第 2 节逐阶段详解。每个阶段结尾有「现状」标注(已实现 / 部分实现 / mock / 未实现)。
- **真实示例**取自「食梦诊所」第一章(凌晨门诊),是该写法在真实生成任务中的实际产出。

## 1. 全局速览

### 1.1 主流程(7 步)

```text
剧本 project_story
  → 剧情结构 story_structure
  → 分镜工作台 storyboard
  → 出图准备 image_preflight
  → 候选图工作台 image_candidates
  → 排版导出 layout_export
  → 素材包 asset_package
```

常驻资产入口(不进主流程序号):`项目角色库 /characters`(项目级),场景图当前按章节级挂在 `storyStructure.scenes`。

## 4. 已知数据陷阱(讨论时注意)

1. **`StoryboardShot.characterIds` 填的是角色名而非 char id**(如 `["林烬"]` 不是 `["char_xxx"]`)。出图准备时 service 用 `characterById` 查不到,会 fallback 到 `characterByName` 做名字匹配(`projects.service.ts:2888-2899`)。
2. **`ProjectCharacter.appearance` / `promptFragment` 真实数据被拼接了多段结构卡文本**(用 `；` 连接 role/relationship/motivation/notes),疑似结构卡→角色档案映射的拼接逻辑问题。
3. **`project.json` 不含 `sourceText` / `characters` / `assets` / `chapters`** —— 这些是 `LocalProject` 内存拼装字段,不落盘。`sourceText` 实际在章节级 `chapter.json`。
4. **`promptDraft` 是 AI 自由草稿,后端透传无组装** —— 没有任何后端方法重新组装或填充 promptDraft。直接拿去出图会效果差。
5. **候选图生成是 mock** —— `runMockTask` 直接假装成功,完全不读 Shot 画面字段,没真实出图。
6. **`SceneLocation` 项目级实体只在文档,未建模** —— 场景当前是章节级的(随章节切换),不跨章节复用。
7. **`ChapterImagePreflight.status` 只有 `"confirmed"` 一个值**(非枚举数组)。
