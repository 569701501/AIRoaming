## 1. 模块划分原则

- 模块按用户工作流和数据边界拆分。
- 每个模块都有明确输入、输出和持久化对象。
- AI 生成能力通过任务模块统一进入，不散落在业务模块里。
- 素材管理是底座模块，所有生成结果都要回到素材体系。

## 2. 模块总览

## 4. 模块边界

### 4.1 项目管理

负责：

- 创建项目。
- 删除项目。
- 维护项目状态。
- 维护默认风格和导出目标。
- 聚合项目级统计。

不负责：

- 直接生成分镜或图片。
- 直接操作物理素材文件。

### 4.2 故事与剧情结构

负责：

- 保存故事原文。
- 调用 `story_parse` 任务。
- 保存结构化剧情。
- 管理故事版本。

不负责：

- 生成最终图片。
- 决定漫画页面布局。

### 4.3 角色与场景模板

负责：

- 保存角色外观、性格、参考图、提示词片段。
- 保存场景地点、氛围、参考图。
- 为分镜和图片生成提供约束。

不负责：

- 保证高级模型层面的角色一致性训练。
- 自动判断所有候选图是否角色一致。

### 4.4 分镜工作台

负责：

- 调用 `shot_generate`。
- 展示和编辑 `Shot`。
- 管理分镜顺序和状态。
- 为图片生成准备 `shot_prompt_generate` 输入。

不负责：

- 直接调用图片 provider。
- 保存图片文件。

### 4.5 生成任务中心

负责：

- 创建、执行、重试、取消生成任务。
- 记录输入、输出、错误、耗时和 provider 元数据。
- 向前端推送任务事件。
- 任务完成后注册产物。

不负责：

- UI 展示。
- 业务模块中的人工选择逻辑。

### 4.6 漫画图候选

负责：

- 调用 `image_generate`。
- 管理候选图状态。
- 支持选择、锁定、废弃和重生成。

不负责：

- 页面排版。
- 视频时间轴。

### 4.7 漫画排版

负责：

- 基于已锁定候选建立页面布局。
- 管理格子位置、尺寸和顺序。
- 调用 `layout_export` 输出 PNG/PDF。

不负责：

- 图片生成。
- TTS 和视频导出。

### 4.8 轻漫剧基础视频

负责：

- 将已锁定漫画图组织成时间轴。
- 生成 TTS。
- 管理字幕和 BGM。
- 调用 `video_export` 输出 MP4。

不负责：

- 复杂镜头运动和自动剪辑。
- 替代漫画排版主线。

### 4.9 素材管理

负责：

- 统一注册 `Asset`。
- 维护文件路径、类型、尺寸、时长、来源任务。
- 导出素材包。
- 支持后续清理和孤儿文件检查。

不负责：

- 决定某个候选是否被选中。
- 修改业务实体状态。

### 4.10 AI 对话与上下文

负责：

- 维护项目内左侧公共“对话框”所需的数据边界。
- 以 OpenCode 作为第一阶段对话运行时，承接消息发送、流式输出、停止生成、模型选择和 provider 配置。
- 按 `projectId + stepKey` 保存步骤对话记录。
- 为当前步骤组装 AI 上下文。
- 维护项目级已确认事实。
- 记录 AI 建议的应用状态。
- 支持读取当前步骤产物和项目级已确认事实。

不负责：

- 把整个项目的原始聊天历史自动注入每个步骤。
- 把未确认聊天内容提升为项目事实。
- 提供跨步骤手动引用原始聊天消息作为默认能力。
- 自动覆盖右侧主文档。
- 让 OpenCode 直接写入项目文件、执行 bash 或绕过用户确认动作。
- 迁移 Aurora 的完整 Docker sandbox、Phaser 工具、计费或团队权限体系。
- 直接替代故事、分镜、候选图或排版模块的业务状态。

上下文注入规则：

```text
当前步骤系统提示词
  -> 项目级已确认事实
  -> 当前步骤主文档或产物
  -> 当前步骤对话记录
  -> 用户本轮输入
```

### 4.11 前端项目工作台 UI

负责：

- 展示项目库。
- 支持创建项目。
- 支持项目卡片封面 hover 删除和二次确认。
- 支持进入项目工作区。
- 在项目工作区展示 6 步流程。
- 进入项目工作区后隐藏全局左侧导航。
- 在项目工作区提供左侧公共对话框和右侧当前步骤主文档或工作内容。
- 切换步骤时只加载当前步骤对话记录，并展示项目级已确认事实可用状态。
- 根据当前步骤展示主工作面板。
- 将任务队列作为轻量入口，不默认抢占主工作区。
- 将对象检查器和下一步建议后置为抽屉、弹层或局部面板。
- 按 `文档/01_愿景与产品/功能清单与页面链路.md` 和 `文档/01_愿景与产品/当前UI信息架构.md` 实现。
- 区分真实可用能力、灰态能力和后置能力。

不负责：

- 直接执行业务生成任务。
- 伪造后端未完成能力。
- 让 AI 对话结果自动覆盖用户文档。
- 把其他步骤的原始聊天历史自动混入当前步骤。
- 把团队协作、权限、计费等后置能力放进 MVP 主路径。
- 默认展示大 hero 图或右侧常驻栏。
- 继续沿用已归档的旧六面板试错页面或输出 Tab 方案。

## 5. 模块间数据流

```text
StoryVersion.structureJson
  -> shot_generate
  -> Shot[]
  -> shot_prompt_generate
  -> image_generate
  -> Candidate + Asset(image)
  -> lockedCandidateId
  -> LayoutPage
  -> layout_export
  -> Asset(image/pdf)
```

轻漫剧分支：

```text
locked Candidate + subtitle
  -> tts_generate
  -> Asset(audio)
  -> VideoDraft
  -> video_export
  -> Asset(video)
```

## 6. 后续模块梳理规则

当某个模块开始实现后，应新增独立模块 Codemap 文档，命名：

```text
文档/03_模块梳理/<模块中文名>模块梳理.md
```

独立模块文档应包含：

- Responsibility
- Design
- Flow
- Integration
- Key Files Reference

模板见 `文档/90_模板/模块梳理模板.md`。
