## 1. 模块划分原则

- 模块按用户工作流和数据边界拆分。
- 每个模块都有明确输入、输出和持久化对象。
- AI 生成能力通过任务模块统一进入，不散落在业务模块里。
- 素材管理是底座模块，所有生成结果都要回到素材体系。

## 4. 模块边界

### 4.1 项目管理

负责：

- 创建项目。
- 删除项目，并清理项目记录、本地 workspace 项目目录、该项目生成任务和项目级对话运行态缓存。
- 维护项目状态。
- 维护默认风格和导出目标。
- 聚合项目级统计。
- 从 SQLite 读取和写入项目事实；DB-only 激活后不回落或双写 workspace，旧 workspace 只作为已封存的迁移来源和 archive 证据。

不负责：

- 直接生成分镜或图片。
- 直接操作物理素材文件。
- 直接管理章节内剧本正文和章节状态。

### 4.2 章节管理

负责：

- 创建项目默认章节。
- 展示和维护章节列表。
- 维护当前活跃章节。
- 保存当前章节剧本草稿。
- 在用户点击“完成本章，进入下一章”时，写入章节剧本版本并推进章节状态。
- 创建或切换到下一章。
- 协调章节级 workspace 路径。

不负责：

- 直接生成结构化剧情、分镜或图片。
- 把章节标题当作唯一排序依据。
- 保存项目级角色、世界观、通用场景和共享素材。
- 让前端直接写本地物理路径。

当前实现状态：

| 内容 | 状态 | 代码入口 |
| --- | --- | --- |
| 创建项目默认章节 | 已实现 | `apps/server/src/projects/projects.service.ts` |
| `story/story_draft.source.txt` 旧兼容 | 已移除 | 新项目不再创建、读取或写入旧 `story/` 目录 |
| 工作台快照当前章节 | 已实现 | `WorkbenchSnapshot.chapters/currentChapter`；编辑器和对话上下文优先消费当前章节 |
| 章节列表 API | 已实现 | `GET /api/projects/{projectId}/chapters` |
| 保存章节草稿 / 完成本章 | 已实现 | `PATCH /api/projects/{projectId}/chapters/{chapterId}/draft`、`POST /api/projects/{projectId}/chapters/{chapterId}/complete` |
| DB-only 持久化 | 已完成 G1～G5 | 项目、章节、版本、任务、候选、排版和导出均以 SQLite 为唯一业务事实源；file guard 禁止回退 |

### 4.2.1 项目工作流

负责：

- 定义项目内 7 步主流程。
- 根据当前章节状态推导下一步 `currentStepKey`。
- 维护每个步骤的 `done/active/waiting/blocked` 状态。
- 向前端流程栏、后续对话框提示和生成任务入口提供统一状态。
- 从数据库 current/pending 指针、版本摘要和任务状态派生 workflow；不把 workflow 快照写成第二套业务真值。

不负责：

- 替代 `Chapter.status` 或章节内产物状态。
- 自动创建生成任务。
- 自动把 AI 对话结果写入右侧文档。

当前实现状态：

| 内容 | 状态 | 代码入口 |
| --- | --- | --- |
| 共享 workflow 步骤定义 | 已实现 | `packages/shared/src/domain.ts` |
| `WorkbenchSnapshot.workflow` | 已实现 | `packages/shared/src/dto.ts`, `apps/server/src/projects/projects.service.ts` |
| `workflow.json` 落盘 | 已实现 | `apps/server/src/projects/projects.service.ts` |
| 流程栏按 workflow 状态点击 | 已实现 | `apps/web/src/components/workbench/WorkbenchStageRail.vue` |

### 4.3 故事与剧情结构

负责：

- 保存和读取当前章节剧本。
- 调用 `story_parse` 任务。
- 保存当前章节结构化剧情。
- 管理当前章节故事版本。
- 在剧情结构步骤按章节展示结构状态，并控制未完成剧本章节不能生成结构。
- 在用户确认剧情结构后，将当前章节推进为 `structured` 并允许进入分镜。

不负责：

- 生成最终图片。
- 决定漫画页面布局。
- 把待确认预览当作正式结构输入给分镜。

### 4.4 角色与场景模板

负责：

- 保存角色外观、性格、参考图、提示词片段。
- 保存项目级角色身份、层级、文字描述、图片生成描述 / prompt、预览图和定稿图。
- 角色名是项目内身份标识，普通角色图片生成弹窗不能修改角色名；生图弹窗只编辑用于 AI 生图的形象描述 / prompt。
- 承接剧情结构和分镜阶段发现的待处理新角色；普通用户路径以看图、改生图描述、重新生成、应用当前图和删除当前图片版本为主。
- 加入角色库、合并到已有角色、标记临时或忽略属于底层归类或高级/异常处理能力，不作为普通图卡默认主操作。
- 保存场景地点、氛围、参考图。
- 为分镜和图片生成提供约束。

不负责：

- 保证高级模型层面的角色一致性训练。
- 自动判断所有候选图是否角色一致。

### 4.5 分镜工作台

负责：

- 调用 `shot_generate`。
- 展示 AI 生成的待确认分镜预览。
- 展示和编辑当前章节 `Shot`。
- 在同一次用户分镜生成动作中，第一段产出漫画画格字段和基础漫剧镜头字段，第二段按整章一次调用自动整理详细候选图单帧说明。
- 第二段只能覆盖 `coreAction/panelDescription/composition/promptDraft`；镜头数、顺序、剧情锚点、角色/场景引用、对白和 motion 由后端冻结。
- 漫画 `panelDescription/coreAction/composition` 必须形成一个地点、一个可见时刻、一个机位的详细单帧描述；固定质量门阻断跨地点、多时刻、不可见信息、文字要求、设定图语言、绑定角色遗漏和多人总数缺失。
- 新 AI 分镜骨架与详细说明分别最多定向修复一次；任一阶段仍失败时不写入或替换待确认草稿，不保存部分镜头。
- 用户确认后保存当前章节 `storyboard.json` / `Shot[]`，并推进章节到 `storyboard_done`。
- 管理当前章节分镜顺序和状态。
- 角色引用只能来自当前已确认剧情结构；分镜不得静默引入项目角色库中的其他视觉主体。
- 为候选图工作台准备可直接使用的三段说明；`shot_prompt_generate` 只保留为用户按需单镜返修。
- 为后续轻漫剧制作准备基础镜头、配音角色、台词和画面类型输入。

不负责：

- 把未确认的分镜预览提供给候选图生成。
- 直接调用图片 provider。
- 直接生成 TTS、字幕或视频成片。
- 保存图片文件。

### 4.6 出图准备

负责：

- 读取当前章节正式 `storyboard.json` / `Shot[]`。
- 检查每个镜头出镜主体是否已绑定到当前确认剧情结构和项目角色库。
- 按共享视觉策略验证素材：`human + lead/recurring/chapter → final_reference`，`human + minor/extra` 与 `creature/group → preview_front`，`voice → none`。
- 只展示检查结果和返回上游入口；缺项阻断，但不在出图准备生成、重生、定稿或自动补齐图片。
- `appearanceCount` 仅作为检查说明，不改变必需素材类型。
- 检查当前章候选图生成所需场景、画风和漫画形式参考。
- 确认后允许进入候选图工作台。

不负责：

- 生成剧情结构或分镜。
- 生成、修复或临时升级角色素材。
- 直接批量生成候选图。
- 替代完整项目角色库管理。

### 4.7 生成任务中心

负责：

- 创建、执行、重试、取消生成任务。
- `shot_prompt_generate` 在用户明确点击“重新优化本镜头”后调用 `shot-prompt-optimize`，只把可编辑返修建议写入任务输出；不修改正式分镜或生成图片。
- 记录输入、输出、错误、耗时和 provider 元数据。
- 以数据库 `GenerationTask` 作为排队和生命周期唯一事实源，以不可变 `TaskAttempt` 保存每次尝试；内存只保留唤醒信号和当前 AbortController。
- 用短事务 claim、lease、heartbeat 和启动恢复保证单进程 worker 可在服务重启后重新发现任务。
- 统一 `idempotencyKey/sourceDigest`、已有产物检查、重复回写保护和迟到结果隔离，承诺 at-least-once 而不是虚假的 exactly-once。
- 对运行中取消写 `cancelRequestedAt`，由 worker 协作中断并确认后再进入 `cancelled`。
- 用 `concurrencyKey` 管理资源通道；V1 所有图片 provider 任务共享并发 1 的图片通道。
- 保存 `legacy_imported/legacy_stub` 历史来源；保留 Candidate/Asset 原 taskId 外键，同时保证 legacy 记录永不进入 claim、取消或重试。
- 对章节内任务记录 `chapterId`。
- 对依赖定稿图、布局和导出的任务记录来源修订与 lock set digest；旧任务结果只能回写到原始来源。
- 向前端推送任务事件。
- 任务完成后注册产物。

不负责：

- UI 展示。
- 业务模块中的人工选择逻辑。

### 4.8 漫画图候选

```text
  -> Shot.currentCandidateLockRevisionId
  -> LayoutWorkingCopy -> LayoutRevision + LayoutSourceBinding.candidateLockRevisionId
  -> layout_export
  -> ExportRevision(kind=layout_publication) + ExportArtifact + Asset(png/pdf/manifest)
```
