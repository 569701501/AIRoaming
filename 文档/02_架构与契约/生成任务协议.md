# 生成任务协议

## 1. 协议目标

生成任务协议定义所有 AI 和导出任务的统一输入、输出、状态和错误格式。无论后续接云端 API、本地模型还是 FFmpeg，都必须通过任务协议与业务系统交互。

## 2. 统一任务信封

```json
{
  "taskId": "task_001",
  "projectId": "project_001",
  "type": "image_generate",
  "target": {
    "type": "shot",
    "id": "shot_001",
    "chapterId": "chapter_001"
  },
  "input": {},
  "options": {
    "candidateCount": 4,
    "provider": "default"
  },
  "trace": {
    "requestedBy": "user_001",
    "source": "web"
  }
}
```

`target.type` 必须使用 Shared `GENERATION_TASK_TARGET_TYPES` 的 8 个值之一：`project`、`character`、`chapter`、`story`、`shot`、`asset`、`export`、`scene`。凡是处理章节内产物的任务，都必须携带 `chapterId`，避免后续生成结果只挂到项目级而无法追溯到具体章节。

`target.type` 与 `GenerationTaskSource.sourceType` 是两套不同枚举：前者描述任务的 polymorphic routing/owner 目标，后者描述不可变来源；输出真正允许写入哪里由 TaskPolicy 的独立 `writeTargetBinding` 冻结。`story_parse/shot_generate` 的 routing target 都是 Chapter，写目标分别是 Chapter active pending StoryVersion/StoryboardVersion，两个 ID 不得强行相等。`layout_export` 的 routing 与写目标恰好都是 `target.type=export`、`target.id=ExportRevision.id`；`export_revision` 只能出现在 `GenerationTaskSource.sourceType`，不得写入 Shared target 枚举或 `GenerationTask.targetType`。

当前已强制 `chapterId` 的章节作用域任务：

```text
story_parse
shot_generate
shot_prompt_generate
image_generate
layout_export
```

创建上述任务时，`target.chapterId` 必须存在。`input.chapterId` 建议同步传入；如果省略，服务端会按 `target.chapterId` 规范化写回任务输入；如果传入但与 `target.chapterId` 不一致，服务端必须拒绝创建任务。

`character_reference_generate` 是项目级任务，目标是 `Character`，不强制 `chapterId`。它可以记录来源章节或来源剧本大纲，但输出必须挂到项目级角色库和项目级 `Asset(reference image)`，不能挂到某个章节候选图目录。

`scene_reference_generate` 是章节场景参考图任务，目标类型必须是 `scene`，并携带场景所在的 `chapterId`。当前任务由章节场景专用 API 受控创建，不通过通用任务入口直接构造；输出挂到章节级场景卡和章节级 `Asset`，不能误挂为项目级共享场景。Shared 的 `CHAPTER_SCOPED_GENERATION_TASK_TYPES` 当前只约束通用任务入口的 5 类任务，因此不能据此省略场景任务自己的章节校验。

图片生成 provider 配置：

- 当前支持 `openai`、`doubao`、`grok` 三类图片 provider，对应设置页 `openaiImageProvider`、`doubaoImageProvider`、`grokImageProvider`，由 `activeImageProvider` 决定当前生效 provider。
- OpenAI 图片默认模型为 `gpt-image-2`；豆包图片默认模型为 `doubao-seedream-4-5-251128`；Grok 图片默认模型为 `grok-imagine-image-quality`。
- `baseUrl` 来自非秘密 provider 配置；图片 `apiKey` 由 NestJS 后端 `ImageCredentialStore/SecretStore` 在运行时读取，不复用 OpenCode 文本模型 key，也不返回前端。
- `baseUrl` 是最终 API 前缀；后端只移除末尾 `/`，再拼接 `/images/generations` 或 `/images/edits`，不自动追加 `/v1`。
- Grok 官方默认前缀为 `https://api.x.ai/v1`；如果用户使用 Grok 中转，设置页必须填写中转后的最终 API 前缀。
- Grok 文生图走 JSON `POST /images/generations`，使用 `aspect_ratio`、`resolution` 和 `response_format=b64_json`；Grok 图生图走 JSON `POST /images/edits`，参考图以 `data:<mime>;base64,...` 的 `image.url` 传入，不使用 OpenAI SDK 的 multipart `images.edit()`。
- 文本模型 key 的权威存储是 OpenCode 本地 auth；图片模型 key 的权威存储是后端 SecretStore。图片 key 不得写入 SQLite、普通 workspace JSON、文档、Git、任务输入输出、artifact、导出或错误日志。
- 当前实现仍使用两条本地进程内 Promise 串行队列：`ImageCandidateService.imageQueue` 生成候选图，`CharacterReferenceService.characterReferenceQueue` 生成角色/场景参考图。D75 已确认它们将被 SQLite 任务表 + 单进程持久 worker 的统一图片并发通道替代；该目标尚未实现。

暂不强制单个 `chapterId` 的任务：

| 类型 | 原因 |
| --- | --- |
| `asset_package_export` | 可按项目导出，也可携带多个 `chapterIds` 导出章节子集 |
| `tts_generate` / `video_export` | 属于 P0.5 轻漫剧链路，等视频草稿模型接入后再决定是否强制章节作用域 |

### 2.1 下游任务来源快照（D3 接受目标）

凡是读取定稿候选、布局或导出结果的长任务，创建时必须把来源修订固化到 input，不能在任务完成时重新读取“当前指针”并把旧结果冒充为新结果。

```json
{
  "source": {
    "layoutRevisionId": "layoutrev_002",
    "lockSetDigest": "sha256:...",
    "candidateLockRevisionIds": [
      "lockrev_shot001_003",
      "lockrev_shot002_001"
    ]
  }
}
```

适用任务至少包括：布局合成、正式导出、素材包导出，以及以后所有以当前定稿图为输入的视频或音频合成任务。

任务回写规则：

1. 产物永远登记到启动时的来源修订。
2. 回写前重新计算当前来源 digest；若已变化，任务仍可成功，但结果标记为 `historical`，不得更新 current 指针。
3. `cancel` 只改善用户体验；供应商请求可能已经在运行，因此来源修订校验是防止旧结果污染当前状态的最终门禁。
4. 缺少来源快照的旧任务只能迁移为 `legacy_unresolved` 历史记录，不能把原记录重试为新任务；需要重新生成时必须创建新的 runtime task，并绑定当前有效来源。

DB-only runtime 的规范化 `inputJson` 根对象统一包含 `sourceProjection: TaskSourceProjectionV1`，sources 使用 `role/order/sourceType/sourceId/sourceDigest`；sourceType 是 snake_case registry token。该数组与 append-only `GenerationTaskSource` 在同一创建事务逐项投影并 seal，`GenerationTask.sourceDigest` 是 sourceProjection 的 JCS digest。canonical token/owner/digest 映射见 `文档/04_方案与决策/2026-07-11_G1数据库Schema实施契约.md` 10.4.1；旧 PascalCase model 名不作为持久 sourceType。

### 2.2 D75 持久执行信封（接受目标，未实现）

`GenerationTask` 是任务排队、生命周期和当前执行权的唯一事实源。除第 2 节业务信封外，持久执行至少包含以下字段：

```json
{
  "status": "queued",
  "attempt": 0,
  "maxAttempts": 3,
  "nextRunAt": "2026-07-10T12:00:00.000Z",
  "leaseOwnerId": null,
  "leaseExpiresAt": null,
  "heartbeatAt": null,
  "cancelRequestedAt": null,
  "idempotencyKey": "image_generate:shot_001:sha256:...",
  "sourceDigest": "sha256:...",
  "concurrencyKey": "image-provider",
  "needsReview": false
}
```

`TaskAttempt` 每次 claim 新增一条记录；运行结束时只允许一次性写入 `finishedAt/outcome/error/artifactRefs`，终结后不可变：

```json
{
  "id": "attempt_001",
  "taskId": "task_001",
  "attemptNo": 1,
  "workerId": "worker_local_001",
  "startedAt": "2026-07-10T12:00:00.000Z",
  "finishedAt": null,
  "outcome": null,
  "error": null,
  "artifactRefs": []
}
```

正式规则：

1. 同一 NestJS 进程运行 worker；任务入库后主动唤醒，同时用数据库扫描兜底。进程内只可保存唤醒信号与当前 AbortController，不能保存权威队列。
2. worker 在短事务中原子 claim `queued/retrying` 任务并写 lease；provider 网络调用、文件写入、哈希和渲染在事务外完成。运行期间按约定刷新 `heartbeatAt/leaseExpiresAt`。
3. 执行语义为 at-least-once。每种任务必须定义稳定 `idempotencyKey`、来源 `sourceDigest`、已有产物检查和结果唯一约束；key 只能在创建事务中由已冻结 Task 字段/strict input 字段按注册表 placeholder binding 计算一次，replay 不得从可变 current/pending pointer 重算。重复执行不得产生第二份正式回写或覆盖新的 current 指针。
4. 服务启动或定时恢复扫描过期 `running` lease。只有明确可安全重放的任务才进入 `retrying`；无法确认外部副作用的任务进入 `failed`，错误码为 `WORKER_INTERRUPTED` 且 `needsReview=true`。
5. `queued/retrying` 任务可直接原子进入 `cancelled`。`running` 任务只先写 `cancelRequestedAt` 并触发协作 AbortSignal；worker 确认停止后才进入 `cancelled`，不能在外部调用仍继续时提前显示终态。
6. provider 无法真正取消或返回迟到结果时，worker 仍须检查 `cancelRequestedAt` 与 `sourceDigest`；迟到结果可以登记为诊断证据，但不能更新正式 current 关系。
7. V1 所有图片 provider 任务使用 `concurrencyKey=image-provider` 且并发上限为 1；本地轻量导出可定义独立通道，不能再由业务服务各自维护 Promise 队列。
8. 重试只适用于明确可重试错误，使用有限 `maxAttempts`、`nextRunAt` 与 backoff；每次尝试追加 `TaskAttempt`，终结后不得覆盖旧 attempt。

状态迁移：

| 当前状态 | 触发 | 下一状态 | 约束 |
| --- | --- | --- | --- |
| `queued` | claim 成功 | `running` | 同事务写 lease、attempt 与新 TaskAttempt |
| `retrying` | 到达 `nextRunAt` 且 claim 成功 | `running` | 必须未取消且未超过 maxAttempts |
| `running` | 当前 attempt 成功且来源仍匹配 | `succeeded` | 幂等登记结果并清除 lease |
| `running` | 可重试错误 | `retrying` | 结束当前 attempt，计算 backoff |
| `running` | 不可重试错误或不安全中断 | `failed` | 保留错误；不安全中断标记 needsReview |
| `queued/retrying` | 用户取消 | `cancelled` | 原子取消，不再被 claim |
| `running` | worker 确认协作中断 | `cancelled` | 必须先有 cancelRequestedAt |

首版不引入 Redis/BullMQ 或多进程 worker。多服务实例、远程 worker、持续任务积压或跨机器扩展出现时，再评估 PostgreSQL、BullMQ/Redis 与 Outbox；换队列也不取消本节的幂等和来源校验要求。

G1 持久任务子阶段（尚未实现）的开发级细化增加 `claimToken` fencing 和显式 `TaskConcurrencySlot`：task/attempt/slot 在同一短事务 claim，heartbeat 与完成都必须匹配 claimToken；旧 worker 迟到时条件更新为 0，不能写 Task、Asset 或 current 指针。当前正式 Schema/migration 已包含相关表与约束，但运行时仍使用既有内存任务链，不能把数据库基座当成持久 worker 已接线。当前 Prisma 6.19.3 不依赖 partial-index preview 来保证图片并发 1。未知中断的图片/LLM 外部调用默认进入 `WORKER_INTERRUPTED + needsReview`，只有任务策略白名单证明安全时才自动重放。详见 `文档/04_方案与决策/2026-07-11_G1数据库事实源与DB-only切换开发方案.md`。

G2 已采纳目标进一步统一上游任务：`story_parse` 的 `GenerationTask.targetId=Chapter.id`，另按 `writeTargetBinding` 将 `input.expectedTargetId` 绑定 active pending StoryVersion；`shot_generate` 同样以 Chapter 做 routing target，另绑定 active pending StoryboardVersion。两者的幂等模板都使用创建时已冻结的 `{expectedTargetId}`，不使用也不动态读取 `pendingStoryVersionId/pendingStoryboardVersionId`。前者来源是 current ScriptVersion，后者来源是 current StoryVersion；Preflight/候选任务绑定 current Storyboard、角色/场景视觉和风格的聚合 SourceSnapshot。任务创建前执行 `NewWorkGate`，完成时执行 `TaskApplicabilityGuard`，同时比较 claimToken、active pending write target、write target/pending 行自身的 `expectedTargetRowVersion`、current 来源 ID 和 sourceDigest；Chapter.rowVersion 只用于 Chapter 命令 CAS，不能冒充 pending target rowVersion。dirty/pending Working Copy 会阻止新任务；迟到结果可以 `succeeded + applicability=historical`，但不能修改 active pending/current。精确字段见 `文档/04_方案与决策/2026-07-11_G2版本来源与Freshness契约字典.md`。

### 2.3 D76 旧任务历史信封（接受目标，未实现）

旧任务来源记录与 D75 可执行状态机分层：

| `recordKind` | `provenanceStatus` | 执行语义 |
| --- | --- | --- |
| `runtime` | `complete` | 新系统正常任务，可按 D75 状态机执行 |
| `legacy_imported` | `complete/partial` | 旧 artifact 能证明完整或部分历史，只读、不可执行 |
| `legacy_stub` | `reference_only/partial` | 只能证明原 taskId 被引用，只读、不可执行 |

`legacy_stub` 示例：

```json
{
  "id": "legacy_task_001",
  "recordKind": "legacy_stub",
  "provenanceStatus": "reference_only",
  "status": null,
  "retryDisabled": true,
  "maxAttempts": 0,
  "importSource": "workspace",
  "importedAt": "2026-07-10T12:00:00.000Z",
  "observedEvidence": {
    "schemaVersion": 1,
    "artifactStatus": "missing",
    "candidateIds": ["candidate_001"],
    "assetIds": ["asset_001"],
    "sourceFiles": [
      {
        "storageKey": "projects/project_001/chapters/chapter-001/candidates.json",
        "sha256": "sha256:..."
      }
    ]
  }
}
```

强制规则：

1. Candidate/Asset 保留原 taskId 外键；不得用散落的 `legacySourceTaskId` 字符串代替统一关系。
2. worker claim 查询必须显式限定 `recordKind=runtime`；`legacy_imported/legacy_stub` 禁止 claim、取消、重试和新增 TaskAttempt。
3. `legacy_stub.status=null`。未知 input/output/error/provider/attempt/startedAt/finishedAt 保持空；文件存在、Candidate 状态和文件时间不能推断任务终态。
4. 完整旧 artifact 只导入其能证明的字段；如果原终态没有直接证据，状态仍为空。
5. `observedEvidence` 是带 schemaVersion 的审计文档，不是可执行 input/output；其中的每条路径、摘要和引用都必须来自导入扫描。
6. 导入按原 taskId 幂等；`reference_only -> partial -> complete` 只能随更强原始证据单向提升。证据冲突进入 MigrationReport，不静默覆盖。
7. 用户要重新生成旧产物时，创建新的 runtime task，并在新任务 input 中记录来源 legacy taskId；不得“重试”历史记录。

## 3. 统一任务输出

```json
{
  "taskId": "task_001",
  "status": "succeeded",
  "applicability": "current",
  "outputs": [],
  "usage": {
    "provider": "default",
    "model": "unknown",
    "inputTokens": 0,
    "outputTokens": 0,
    "cost": null
  },
  "warnings": []
}
```

`applicability` 适用于有来源修订的任务：`current` 表示仍匹配当前依赖，`historical` 表示任务成功但来源已更新，`legacy_unresolved` 表示旧任务缺少足够来源信息。它不替代 runtime 任务自身的 `queued/running/succeeded/failed/cancelled` 生命周期；legacy stub 没有可执行生命周期。

  "error": {

## 5. 任务类型总表

| 类型 | 输入 | 输出 | MVP |
| --- | --- | --- | --- |
| `character_reference_generate` | 项目角色 + 角色层级 + 外貌/风格提示词 | 角色参考图 Asset | 是 |
| `scene_reference_generate` | 已确认章节剧情结构中的场景卡 + 可选提示词 | 场景背景图 Asset + 回写后的 `scene.referenceAssetId` | 是 |
| `story_parse` | 当前章节剧本 | 结构化剧情 JSON | 是 |
| `shot_generate` | 用户已确认的当前章节结构化剧情 | 分镜数组 | 是 |
| `shot_prompt_generate` | 已确认分镜 + 已确认出图准备 + 角色/场景/风格 | 图片提示词 | 是 |
| `image_generate` | 分镜提示词 + 已确认出图准备 + 参考图 | 候选图片 Asset | 是 |
| `layout_export` | 当前且来源完整的 LayoutRevision + 规范 PublicationProfile + preflight digest | 一个 `layout_publication` ExportRevision + 页漫 PNG/可选 PDF 或条漫 PNG 切片/条件长图 Asset | 是 |
| `tts_generate` | 文本 + 声音配置 | 音频 Asset | P0.5 |
| `video_export` | 图片序列 + 字幕 + 音频 | MP4 Asset | P0.5 |
| `asset_package_export` | 项目范围和导出选项 | ZIP/文件夹 Asset | 是 |

G2 目标下，“当前章节剧本/结构化剧情”必须解释为：current 正式版本来源链为 current，且更上游没有 dirty Working Copy 或 active pending；不能退化为读取 Chapter 当前文本字段或更新时间。

### 5.1 character_reference_generate

角色库和出图准备使用的角色参考图生成任务。它用于自动生成角色图，也用于基于当前角色图生成角色定稿图。

### 输入

```json
{
  "characterId": "char_hero",
  "referenceKind": "final_reference",
  "sourceReferenceAssetId": "asset_char_preview_001",
  "model": "gpt-image-2",
  "prompt": "角色定稿图提示词",
  "image": {
    "size": "3072x1536",
    "quality": "high",
    "outputFormat": "webp"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `characterId` | string | 项目级 `Character` ID |
| `referenceKind` | enum | `preview_front/final_reference` |
| `sourceReferenceAssetId` | string | `final_reference` 必须使用已确认的 `preview_front` 资产作为图片参考输入 |
| `model` | string | 第一版固定使用 `gpt-image-2` |
| `prompt` | string | 后端根据项目类型、作品名、题材标签、漫画形式、美术风格、角色身份信息、用于 AI 生图的形象描述 / prompt 和用户要求生成的 provider prompt |
| `image.size` | string | `final_reference` 推荐 `3072x1536`；`preview_front` 推荐竖版尺寸 |
| `image.outputFormat` | enum | 推荐 `webp` |

`referenceKind` 规则：

- 所有角色进入项目角色库后，后端会为缺少预览图且没有运行中任务的角色补排 `preview_front`。
- 用户触发 `生成定稿` 时，系统内部自动使用当前可用的 `preview_front` 作为参考生成 `final_reference`；普通 UI 不要求用户先点击“确认预览”。
- 生成 `preview_front` 和 `final_reference` 时，prompt 必须明确这是漫画/条漫/漫剧制作项目，`dark_realistic`、`semi_realistic`、`japanese_realistic` 只能解释为漫画写实或半写实，禁止生成真人照片、真人演员定妆照、摄影棚肖像、电影剧照、cosplay 照片或 3D 渲染。
- 生成 `final_reference` 时，后端必须读取 `Character.previewReferenceAssetId` 对应的图片文件，并通过图片编辑/图片参考能力生成定稿图；禁止只用文字 prompt 重新文生图。
- `chapter` 默认只生成 `preview_front`，不阻塞剧情结构；如果该角色在当前章多次出镜、有台词、近景或影响剧情，出图准备阶段应补 `final_reference` 或确认可用参考图；长期复用时可提升为常驻。
- `extra` 默认只生成 `preview_front`，不自动生成 `final_reference`。
- 已有同角色同 `referenceKind` 的 `queued/running/retrying` 任务时，后端返回既有任务，不重复排队。
- 角色图任务必须出现在全局任务队列入口中，用户能看到排队、运行、完成、失败和取消状态；顶部任务队列应独立刷新任务状态，不依赖项目角色库页面整体刷新。
- 普通 UI 中“重新生成”表现为直接替换当前角色图卡片展示图；底层可以创建新的 `Asset` 或视觉版本以保留追溯，但不得要求普通用户在多个图片版本之间选择。
- 角色图片生成弹窗不能修改角色名。角色名来自项目级 `Character`，弹窗只编辑用于 AI 生图的形象描述 / prompt。

### 输出

```json
{
  "characterId": "char_hero",
  "asset": {
    "type": "image",
    "mimeType": "image/webp",
    "path": "projects/project_001/assets/characters/char_hero/visual-v001/final-reference.webp",
    "referenceKind": "final_reference",
    "generationMode": "image_edit",
    "sourceReferenceAssetId": "asset_char_preview_001"
  },
  "providerMetadata": {
    "provider": "openai_image",
    "model": "gpt-image-2"
  }
}
```

### 验收

- 生成结果必须注册为 `Asset(reference image)`，并挂到项目级 `Character.referenceAssetIds`。
- 用户确认后才可写入 `Character.primaryReferenceAssetId` 并把角色推进到 `finalized`。
- 重新生成不得覆盖旧图，只能创建新的视觉版本目录。
- 一旦参考图被漫画候选图使用，旧图进入不可覆盖状态。

### 5.2 scene_reference_generate

章节剧情结构页使用的真实场景背景图生成任务。当前实现通过：

```text
POST /api/projects/{projectId}/chapters/{chapterId}/scenes/{sceneId}/reference
```

创建受控任务；任务信封固定使用 `type = scene_reference_generate`、`target.type = scene`、`target.id = sceneId` 和目标章节 `chapterId`。

### 输入

```json
{
  "sceneId": "scene_001",
  "chapterId": "chapter_001",
  "sceneName": "雨夜街口",
  "prompt": "雨夜旧城区窄街，空镜环境底板，无人物无文字",
  "size": ""
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sceneId` | string | 当前章节已确认 `StoryStructureSceneCard.id`，必须与 `target.id` 一致 |
| `chapterId` | string | 场景所在章节，必须与路由和 `target.chapterId` 一致 |
| `sceneName` | string | 创建任务时从当前场景卡复制的可读名称 |
| `prompt` | string | 可选覆盖；为空时由后端根据场景卡构建场景环境提示词 |
| `size` | string | 当前兼容输入；现实现生成时固定使用 `2560x1440` WebP，不把调用方空值当成真实尺寸 |

### 输出

```json
{
  "sceneId": "scene_001",
  "chapterId": "chapter_001",
  "assetId": "asset_scene_001"
}
```

实际文件写入：

```text
projects/{projectId}/chapters/{chapterSlug}/scenes/{sceneId}/background.webp
```

对应章节级 Asset 必须记录 `chapterId`、`sourceTaskId`，并在 metadata 中记录 `sceneId/referenceKind=scene_background/provider/promptDigest/generationMode/createdAt`。任务成功还必须把新 Asset ID 回写到当前章节结构场景卡的 `referenceAssetId`。

### 验收

- 项目、章节、已确认剧情结构和 `sceneId` 必须存在；缺任一项不得创建伪成功任务。
- 同一项目、同一章节、同一场景已有 `queued/running/retrying` 任务时返回既有任务，不重复排队。
- 任务必须使用 `target.type = scene` 并携带 `target.chapterId`。
- 生成结果必须注册为章节级 Asset、写入规范 WebP 路径，并更新 `StoryStructureSceneCard.referenceAssetId`。
- 成功输出至少包含 `sceneId/chapterId/assetId`；失败使用 `SCENE_REFERENCE_GENERATE_FAILED` 且保持可重试语义。
- 场景参考图当前由角色/场景共享串行队列执行；D75 实施后迁入持久任务图片并发通道，不改变本节业务输入输出。

当前实现已知偏差：`CharacterReferenceService.queueSceneReference` 的运行中任务去重只比较 `projectId + sceneId`，尚未比较 `target.chapterId`。场景 ID 当前只保证章节内稳定；两章同为 `scene_01` 时可能错误复用另一章任务。该问题已登记为待开发回归测试与代码修复，本轮未修改运行代码。

## 6. story_parse

### 输入

```json
{
  "chapterId": "chapter_001",
  "sourceText": "当前章节剧本正文",
  "mode": "faithful",
  "language": "zh-CN"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chapterId` | string | 当前章节 ID；剧情结构逐章生成，不能省略或用项目级结构替代 |
| `sourceText` | string | 当前章节原始剧本文本 |
| `mode` | enum | `faithful/dramatic/comic_pacing` |
| `language` | string | 语言 |

前置条件：

- `chapterId` 对应章节必须至少处于 `script_done`，且存在非空章节剧本正文。
- `draft` 章节不能运行 `story_parse`，应提示用户先完成本章剧本。
- 对 `structured` 及后续状态章节重新运行 `story_parse` 前，必须提示会影响后续分镜、候选图和排版。

### 输出

```json
{
  "title": "故事标题",
  "summary": "一句话摘要",
  "characters": [],
  "scenes": [],
  "beats": [
    {
      "id": "beat_001",
      "order": 1,
      "summary": "剧情节拍",
      "sceneName": "场景名",
      "characterNames": [],
      "visualFocus": "轻量画面重点",
      "dialogueHints": []
    }
  ]
}
```

### 验收

- 输出必须包含 `summary`、`characters`、`scenes`、`beats`。
- 输出只描述当前 `chapterId` 对应章节，不一次性输出整本剧本的结构。
- `characters` 和 `scenes` 默认是本章结构卡，不自动写入项目级角色库或场景库。
- 生成剧情结构时必须读取项目角色库；主角和常驻角色应关联已有 `Character`，不得因为在本章出现而重复创建新角色。本章新出现的重要角色可提示用户后续提升为项目角色。
- `beats` 必须有稳定顺序。
- `beats` 表示关键剧情事件，不和最终分镜或镜头一一对应；一个 beat 后续可拆成多个 shot。
- `beats.visualFocus` 只写轻量画面重点，不写镜头编号、景别、机位、构图或完整分镜稿。
- 不允许只输出自然语言总结。
- AI 生成后必须由用户确认，确认后的结构化剧情才能作为 `shot_generate` 输入。
- 待确认结构可以在右侧预览，但不能作为 `shot_generate` 输入。
- 用户确认结构后，当前章节状态推进到 `structured`，并绑定当前 `StoryVersion`。

### Guard 后正式任务输入

```json
{
  "chapterId": "chapter_001",
  "shotId": "shot_001",

    "systemConstraints": [
      "Create exactly one clean comic illustration for one storyboard shot.",
      "Do not render text, captions, speech bubbles, sound effects or page layouts."
    ],
    "requestedSize": { "width": 1024, "height": 1536 },
    "references": [
      {
        "assetId": "asset_character_preview_001",
        "kind": "character_identity",
        "entityId": "char_hero",
        "label": "主角",
        "priority": 100
      },
      {
        "assetId": "asset_scene_001",

      }

  },

  "imagePreflightId": "chapter_001_image_preflight_v001",
  "sourceStoryboardId": "chapter_001_storyboard_v001"
}
```

`shot_clean_plate` 内容契约：

- 一个任务目标只能是一个正式 storyboard shot；每张 Candidate 是一张单幅、全出血、静态画面。
- 最终 Prompt 不得包含章节标题、对白、旁白、配音台词、动态运镜、时长、`vertical_scroll/four_panel/page_horizontal` 等页面格式名。
- 禁止生成文字、字母、数字、Logo、水印、字幕、旁白框、对白/思考气泡、拟声词、分格、边框、沟槽、拼贴、角色设定表或整页布局。
- 角色引用只使用当前 shot 的已确认单人 `previewReferenceAssetId`；不得把四分格 `final_reference` 直接作为 Candidate edit 底图，也不得注入本章全部角色。

```json
{

```

### 验收

- 生成数量等于 `candidateCount` 或在 warnings 中说明原因。
- 每个候选必须注册为 `Asset` 和 `Candidate`。
- 新 Candidate 必须写 `generationPurpose/specVersion/specDigest`；缺少这些字段的旧候选读取为 `legacy_unspecified`，不删除、不迁移、不自动解锁。
- Asset meta 必须保存 provider、generationMode、requestedSize、actualSize、实际使用的 referenceAssetIds 和 warnings。
- Provider 返回图片无法读取尺寸或宽高比相对 requestedSize 偏差超过 3% 时，必须写 `candidate_output_dimensions_unreadable` 或 `candidate_output_aspect_ratio_mismatch:*` warning。

    {
      "role": "page_png",
      "order": 1,
      "assetId": "asset_export_page_001"

## 14. 重试规则

| 错误码 | 是否可重试 | 说明 |
| --- | --- | --- |
| `PROVIDER_TIMEOUT` | 是 | provider 超时 |
| `PROVIDER_RATE_LIMIT` | 是 | 限流 |
| `INVALID_INPUT` | 否 | 输入不合法 |
| `GENERATION_TASK_CHAPTER_ID_REQUIRED` | 否 | 章节作用域任务缺少 `target.chapterId` |
| `GENERATION_TASK_CHAPTER_ID_MISMATCH` | 否 | `input.chapterId` 与 `target.chapterId` 不一致 |
| `GENERATION_TASK_INPUT_CHAPTER_ID_INVALID` | 否 | `input.chapterId` 非字符串或为空 |
| `ASSET_WRITE_FAILED` | 视情况 | 文件写入失败 |
| `WORKER_INTERRUPTED` | 否（需人工或任务类型明确判定） | lease 过期且无法确认外部副作用；标记 `needsReview=true` |
| `USER_CANCELLED` | 否 | 用户取消 |
