## 1. 架构目标

AI漫游的架构目标是支撑一条可控的生成式内容生产流水线：

- 前端负责工作台、编辑、预览、选择和导出操作。
- 后端负责 API、任务调度、数据持久化和素材路径管理。
- AI 生成层负责剧情结构化、分镜、图片、音频和视频任务。
- 文件系统负责保存所有可复用素材和导出物。

## 2. MVP 技术栈

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 应用形态 | Web 工作台核心 + 本地服务 | MVP 先跑通浏览器工作台与本地 NestJS 服务，桌面壳后置 |
| 前端 | Vue 3 + Pinia + Tailwind CSS + shadcn/reka-ui | 工作台、分镜编辑、候选图选择、漫画排版、视频预览 |
| 后端 | Node.js + NestJS | REST API、任务调度、生成服务编排 |
| 对话运行时 | OpenCode headless server | 第一阶段支撑项目对话框、流式输出、模型选择和 provider 配置 |
| 全局设置 | NestJS Settings API + workspace 文件 | 保存本地 AI 密钥状态和外观偏好；前端读取时不回传完整密钥 |
| 数据库 | Prisma + SQLite | MVP 本地开发优先；后续可切 PostgreSQL |
| 任务队列 | 本地任务表 + 进程内 worker | MVP 简化；后续可换 BullMQ/Redis |
| 文件处理 | 本地文件系统 | 统一 workspace 路径，后续可抽象对象存储 |
| 图片生成 | 云端 API 或本地模型适配器 | 通过任务协议隔离 provider |
| 音视频 | FFmpeg + TTS provider | 基础轻漫剧合成 |

## 4. 分层职责

### 4.1 前端

职责：

- 项目列表和项目工作台。
- 故事输入与结构化结果编辑。
- 分镜列表、分镜详情、批量操作。
- 角色、场景、风格模板管理。
- 漫画图候选查看、选择、锁定和废弃。
- 漫画页面排版和导出预览。
- 轻漫剧时间轴基础预览。
- 生成任务状态显示和错误反馈。

不负责：

- 直接调用 AI provider。
- 直接写数据库。
- 直接决定文件最终路径。

### 4.2 后端 API

职责：

- 提供项目、故事、分镜、角色、场景、资产、任务、导出的 API。
- 校验请求输入。
- 写入数据库事实。
- 创建生成任务。
- 推送任务进度。
- 统一管理 workspace 路径。

不负责：

- 在 controller 中写复杂生成逻辑。
- 让前端决定物理文件路径。

### 4.3 任务调度层

职责：

- 根据任务类型路由到对应生成器。
- 记录任务状态、输入、输出、错误和耗时。
- 支持重试、取消、多候选和失败留痕。
- 将任务产物注册为 Asset 或 Candidate。

MVP 可使用本地 worker；当需要并发和持久队列时再替换为 BullMQ。

### 4.4 AI 生成层

职责：

- 通过 OpenCode 对话运行时支撑项目工作区左侧对话框。
- 封装 LLM、图片生成、TTS、FFmpeg 等 provider。
- 读取全局设置中的默认 `providerId/modelId`，并在存在 API Key 时同步给 OpenCode auth 接口。
- 接收标准任务输入。
- 返回标准任务输出。
- 不直接写业务数据库，除非通过任务调度层回写。

### 4.5 文件系统

职责：

- 保存原始输入、任务输出、图片、音频、视频、页面和素材包。
- 保证文件路径与数据库 `Asset` 对应。
- 支持后续归档、清理和导出。

## 5. 异步任务状态

| 状态 | 含义 |
| --- | --- |
| `queued` | 已创建，等待执行 |
| `running` | 执行中 |
| `succeeded` | 成功完成 |
| `failed` | 失败，保留错误信息 |
| `cancelled` | 用户或系统取消 |
| `retrying` | 等待重试 |

当前本地 MVP 实现：

- 角色图生成任务 `character_reference_generate` 接入统一 `GenerationTask` 记录和顶部任务队列入口。
- 图片 provider 任务先采用进程内串行 worker，一个一个生成，避免同一时间批量调用图片接口导致 429 或代理超时。
- 前端顶部任务队列单独轮询 `GenerationTask` 列表；项目角色库页面需要资产落库状态时，再轮询项目运行态，避免刷新编辑页正文。
- 队列仍是内存态，服务重启不会恢复运行中任务；后续可迁移为 BullMQ/Redis 或数据库持久化队列。

## 6. 进度推送

MVP 推荐使用 SSE：

```text
GET /api/tasks/:taskId/events
```

事件类型：

| 事件 | 含义 |
| --- | --- |
| `task.created` | 任务创建 |
| `task.started` | 任务开始 |
| `task.progress` | 进度更新 |
| `task.asset.created` | 产生素材 |
| `task.succeeded` | 成功 |
| `task.failed` | 失败 |
| `task.cancelled` | 取消 |

## 7. 关键架构取舍

| 取舍 | 当前选择 | 原因 |
| --- | --- | --- |
| 数据库 | SQLite 起步 | 降低 MVP 启动成本 |
| 队列 | 本地任务表起步 | 任务量未知，先固化协议 |
| 视频 | FFmpeg 基础合成 | 不让视频复杂度拖慢漫画主链路 |
| 文件存储 | 本地 workspace | 内部工具优先，本地可控 |
| 全局设置 | `workspace/settings/app-settings.json` 起步 | 当前是本地单用户开发形态；密钥文件被 `.gitignore` 排除，后续可替换为系统 keychain 或数据库加密字段 |
| Provider | 适配器隔离 | 后续可替换云端或本地模型 |
| 对话运行时 | OpenCode 起步 | 用户已选择 OpenCode；只接对话运行时最小闭环，不迁移完整 Aurora 沙盒 |
| 端形态 | Web 优先，桌面壳后置 | 参考 ADR-0003，避免 MVP 前陷入桌面打包复杂度 |

## 8. 后续扩展点

- SQLite 切 PostgreSQL。
- 本地 worker 切 BullMQ/Redis。
- 本地文件切对象存储。
- 单用户切多人协作。
- 基础视频切复杂时间轴。
- Prompt 规则切可配置生成策略。
- Web 核心包装 Electron 或 Tauri 桌面壳。
