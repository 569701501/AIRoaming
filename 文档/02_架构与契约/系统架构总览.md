## 1. 架构目标

AI漫游的架构目标是支撑一条可控的生成式内容生产流水线：

- 前端负责工作台、编辑、预览、选择和导出操作。
- 后端负责 API、任务调度、数据持久化和素材路径管理。
- AI 生成层负责剧情结构化、分镜、图片、音频和视频任务。
- 文件系统负责保存所有可复用素材和导出物。

## 2. MVP 技术栈

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 应用形态 | Web 工作台核心 + 本地服务 | MVP 先跑通浏览器工作台与本地 NestJS 服务，桌面壳后置 |
| 前端 | Vue 3 + Pinia + Tailwind CSS + shadcn/reka-ui | 工作台、分镜编辑、候选图选择、漫画排版、视频预览 |
| 后端 | Node.js + NestJS | REST API、任务调度、生成服务编排 |
| 对话运行时 | OpenCode headless server | 第一阶段支撑项目对话框、流式输出、模型选择和 provider 配置 |
| 全局设置 | NestJS Settings API + 凭据分治 | 文本 key 归 OpenCode auth、图片 key 归后端 SecretStore；同地址同指纹凭据可在冷启动时安全恢复到文本运行时，前端永不读取明文 |
| 数据库 | Prisma + SQLite | ADR-0012 已完成一次性 DB-only 切换与 R2 观察；当前业务事实源为 SQLite，后续可迁 PostgreSQL |
| 任务队列 | SQLite 任务表 + 单进程持久 worker | D75 已确认目标；lease/heartbeat/启动恢复，BullMQ/Redis 后置 |
| 文件处理 | 本地文件系统 | D7 后只承载大字节、不可变产物、导入证据和显式导出，不再保存第二套当前业务事实 |
| 图片生成 | 云端 API 或本地模型适配器 | 通过任务协议隔离 provider |
| 音视频 | FFmpeg + TTS provider | 基础轻漫剧合成 |

## 4. 分层职责

### 4.1 前端

职责：

- 项目列表和项目工作台。
- 故事输入与结构化结果编辑。
- 分镜列表、分镜详情、批量操作。
- 角色、场景、风格模板管理。
- 漫画图候选查看、选择、锁定和废弃。
- 漫画成稿桌面编辑、只读 RenderScene、来源/预检提示和出版任务状态；画布库私有状态不作为事实源。
- 轻漫剧时间轴基础预览。
- 生成任务状态显示和错误反馈。

不负责：

- 直接调用 AI provider。
- 直接写数据库。
- 直接决定文件最终路径。

### 4.2 后端 API

职责：

- 提供项目、故事、分镜、角色、场景、资产、任务、导出的 API。
- 校验请求输入。
- 写入数据库事实。
- 创建生成任务。
- 推送任务进度。
- 统一管理 workspace 路径。

不负责：

- 在 controller 中写复杂生成逻辑。
- 让前端决定物理文件路径。

### 4.3 任务调度层

职责：

- 根据任务类型路由到对应生成器。
- 记录任务状态、输入、输出、错误和耗时。
- 支持重试、取消、多候选和失败留痕。
- 将任务产物注册为 Asset 或 Candidate。
- 将智能成稿规划与正式出版隔离：`layout_compose` 只产出来源密封、可校验的建议结果，应用由 Layout application 事务完成；`layout_export` 只消费不可变 LayoutRevision。

D75 已确认的目标是：`GenerationTask/TaskAttempt` 进入 SQLite，同一 NestJS 进程以数据库 claim、lease、heartbeat、有限重试和启动扫描运行持久 worker；进程内只保留唤醒信号与当前 AbortController。G2-F2～F4 已实现四类 G2 任务的 DB substrate、统一创建门禁和 worker completion；多实例、远程 worker 或持续队列压力出现后，再联合评估 PostgreSQL 与 BullMQ/Redis。

### 4.4 AI 生成层

职责：

- 通过 OpenCode 对话运行时支撑项目工作区左侧对话框。
- 封装 LLM、图片生成、TTS、FFmpeg 等 provider。
- 读取全局设置中的默认 `providerId/modelId`；D74 目标为文本 key 一次性交给本机 OpenCode auth，图片 key 只由后端 ImageCredentialStore 运行时读取。
- 对带自定义 `baseUrl` 的文本模型，把页面逻辑 Provider 映射为 `airoaming_{providerId}` 的 OpenAI-compatible 运行时 Provider；配置和 auth 分离，模型实际注册后才允许出现在模型列表。
- 接收标准任务输入。
- 返回标准任务输出。
- 不直接写业务数据库，除非通过任务调度层回写。

### 4.5 文件系统

职责：

- 保存原始输入、任务输出、图片、音频、视频、页面和素材包。
- 保证文件路径与数据库 `Asset` 对应。
- 支持后续归档、清理和导出。

## 5. 异步任务状态

| 状态 | 含义 |
| --- | --- |
| `queued` | 已创建，等待执行 |
| `running` | 执行中 |
| `succeeded` | 成功完成 |
| `failed` | 失败，保留错误信息 |
| `cancelled` | 用户或系统取消 |
| `retrying` | 等待重试 |

当前本地 MVP 实现：

- 角色图生成任务 `character_reference_generate` 接入统一 `GenerationTask` 记录和顶部任务队列入口。
- 图片 provider 任务先采用进程内串行 worker，一个一个生成，避免同一时间批量调用图片接口导致 429 或代理超时。
- 前端顶部任务队列单独轮询 `GenerationTask` 列表；项目角色库页面需要资产落库状态时，再轮询项目运行态，避免刷新编辑页正文。
- 队列仍是内存态，服务重启不会恢复运行中任务；这是当前实现事实，不是 D75 接受目标。

D75 接受目标（未实现）：

- 数据库中的 `GenerationTask` 是排队和生命周期唯一事实，`TaskAttempt` 不可变记录每次尝试；内存通知丢失后，数据库扫描仍能发现任务。
- worker 使用短事务原子 claim 与 `leaseOwnerId/leaseExpiresAt/heartbeatAt`；网络调用、文件写入和渲染在事务外执行。
- 执行语义为 at-least-once；任务必须有 `idempotencyKey/sourceDigest`、已有产物检查和重复回写保护。
- 运行中取消先写 `cancelRequestedAt`，worker 确认中断后才进入 `cancelled`；迟到结果不得覆盖已取消或来源过期的事实。
- `concurrencyKey=image-provider` 的首版并发为 1，统一替代候选图和角色/场景参考图的分散 Promise 队列。
- 服务启动扫描过期 lease：可安全重放的任务有限重试；无法确认外部副作用的任务记录 `WORKER_INTERRUPTED` 和 `needsReview=true`，不盲目重跑。
- D76 旧任务按 `runtime/legacy_imported/legacy_stub` 分层；只有 runtime 可进入队列。legacy stub 保留原 taskId 外键和可验证证据，但没有执行状态、重试或新 attempt。

## 6. 进度推送

MVP 推荐使用 SSE：

```text
GET /api/tasks/:taskId/events
```

事件类型：

| 事件 | 含义 |
| --- | --- |
| `task.created` | 任务创建 |
| `task.started` | 任务开始 |
| `task.progress` | 进度更新 |
| `task.asset.created` | 产生素材 |
| `task.succeeded` | 成功 |
| `task.failed` | 失败 |
| `task.cancelled` | 取消 |

## 7. 关键架构取舍

| 取舍 | 当前选择 | 原因 |
| --- | --- | --- |
| 数据库 | 本地 SQLite 单引擎、DB-only 唯一事实源 | ADR-0012：影子导入 + 短暂停写一次切换；关系核心 + 版本化 Json + 可重建投影 |
| 队列 | SQLite 任务表 + 单进程持久 worker | D75：先解决重启恢复、真实取消、幂等和图片并发 1，不提前引入 Redis |
| 视频 | FFmpeg 基础合成 | 不让视频复杂度拖慢漫画主链路 |
| 文件存储 | 本地 workspace | 内部工具优先，本地可控 |
| 全局设置 | 当前 workspace 起步；目标按调用运行时分治 | D74 已确认：OpenCode 保存文本 key；后端 SecretStore 保存图片 key；SQLite/workspace 只留非秘密配置与引用 |
| Provider | 逻辑 ID 与运行时适配器隔离 | 自定义中转由 AI漫游注册为专用 OpenAI-compatible Provider，避免与 OpenCode 内置 Provider 冲突 |
| 成稿渲染 | ADR-0016：Konva 10.3.0 纯交互 adapter + DOM IME + 独立 HTML RenderScene + pinned Chromium；V1/V2 正式 renderer 已接线 | 避免画布库私有 JSON、编辑器 DOM 截图和服务端另一套排版规则 |
| 智能成稿 | 规划器产出规范 `LayoutDocumentV2` 或 Editor Command Batch；视觉模型只提供结构化分析，规则规划器、硬门和评分决定是否可应用 | 保证结果可复现、可降级、可测试，并避免模型直接写画布或覆盖人工修改 |
| 对话运行时 | OpenCode 起步 | 用户已选择 OpenCode；只接对话运行时最小闭环，不迁移完整 Aurora 沙盒 |
| Prompt 资产 | `apps/server/opencodeAI/skills` 为稳定正文事实源 | 后端只读加载并填动态事实；固定校验和 provider 传输适配继续留代码，避免 Prompt/Skill 双真相 |
| 端形态 | Web 优先，桌面壳后置 | 参考 ADR-0003，避免 MVP 前陷入桌面打包复杂度 |

G1 的 DB-only 边界不只接管项目元数据，也接管对话、pending、持久任务、SecretStore metadata、迁移 provenance 和文件 Outbox；Importer 只读一致 snapshot，切换当刻内存态通过无秘密 runtime bundle 捕获。旧业务 metadata 与 Asset 字节同目录，切换时只把 JSON/Markdown/task artifact 移入独立只读档案，不能把整个项目目录设为只读。2026-07-14 已完成真实 C0～C7、首写和 R2 OBS-01～10，运行态为 `db_only`；首次 DB 写后 file-only 回退永久禁止，旧 metadata/archive/backup 只保留作证据和恢复输入。详细方案见 `文档/04_方案与决策/2026-07-11_G1数据库事实源与DB-only切换开发方案.md`。

R2 固化三条运行约束：项目 purge 只有在 Project=`deleting`、匹配 `project.delete_files` Outbox=`processed`、无 active runtime task 时才能协调拆除 Chapter reverse pointers；DB-only 协调备份必须同时保存当前 release schema identity 和历史 cutover lineage identity；DB Asset 文件读取以 `storageKey` 为物理事实源，迁移素材仅允许 `legacy-import/{projectId}/...` 受限前缀。Workbench 携带 chapterId 的读取不得修改数据库 current pointer。

标准本地入口 `pnpm dev` 通过 `local-dev.cli.ts` 连接现有 DB-only 运行实例，默认根为 `~/.airoaming/`。入口必须先验证 SQLite 文件真实存在、位于 `AIROAMING_DATA_ROOT` 内、migration ledger 与当前发布一致、`PersistenceState` 已为 `db_only` 且有 `activatedAt`，再启动 Server/Web 与持久 worker。缺库或未激活时 fail-closed；不自动创建空 SQLite，也不回退 file mode。file runtime 仅保留给带来源、授权和回滚证据的迁移/恢复过程。

2026-07-11 已形成并采纳 G2 细化：在 G1 关系底座上增加 `DocumentCodecRegistry + SourceSnapshotBuilder + ChapterProductionStateResolver + NewWorkGate + TaskApplicabilityGuard`。截至 2026-07-12，G2-E1/E2/F1～F4 已实现服务端权威 `ProductionState/Workflow`、Preflight immutable revision、无副作用 applicability guard、SQLite task runtime、四类 G2 worker、统一创建门禁和 completion transaction；legacy history importer、独立 Outbox consumer 与 capability runtime 仍后置。Script/Story/Storyboard/Preflight 的正式版本不可变；freshness 只从 current 指针和来源摘要派生，工作流不再靠清空下游或倒退 `Chapter.status`。服务端输出权威 production/workflow 投影，前端不维护另一套按时间戳猜测的状态机。详见 `文档/04_方案与决策/2026-07-11_G2上游版本链与Freshness开发方案.md`。

2026-07-12 已把尚未实现的 G3 细化为五份施工资料，并拆成 `G3-core/G3-M`。core 保持项目库和创建导航不变，只扩展现有 `CreateProjectModal`；Shared 提供 canonical 版式目录，Server 用 strict request parser/allowlist，SQLite 追加固定 `0010_g3_comic_format_immutable`、独立 overlay inspection 与 0001～0010 runtime ledger。HTTP/DB/新 artifact 只允许 canonical；file repository 的命名 legacy input adapter 可把 `page_horizontal` 只读投影为 paged 并在普通写回时保留原文件，`four_panel/缺失/非法` fail-closed。G3-M 才负责 importer、MigrationIssue 决议、备份恢复和 activate；core 完成不能称 production-ready。候选尺寸使用 `sizePolicyVersion=legacy_generation_default_v1`，与 G2 source projection 的 `policyVersion` 分离；PageProfile/LayoutPreset 仍归 G5。施工入口见 `文档/04_方案与决策/2026-07-12_G3施工包_依赖边界与阶段门禁.md`。

G4 已完成：CandidateLockRevision、两阶段影响检查、完整 lock set/source applicability 和迟到任务隔离由候选模块负责；Layout/Export 只消费来源并派生 current/stale/unresolved，旧产物不改写。

G5 M0～M8 已完成：Shared `layout/`、DB-only Working Copy、一等成稿编辑器、FontAsset、横竖排富文本、四类气泡、来源返修、不可变 LayoutRevision/SourceBinding、固定 RenderScene、`layout_publication`、手机只读、AI pending 与 legacy cutover 均已签收。2026-07-22 在该基础上接受智能成稿重构：新增 `layout_compose`、`LayoutDocumentV2.automation`、视觉规划、确定性评分/硬门以及字段级人工保护；不新建第二套编辑器，不改变 `layout_export` 的正式出版职责。M0～M6 已完成规划内核、持久任务、V2 WC、完整视觉 Pending、零设置/局部重排和人工保护；2026-07-24 已完成 M7～M8 的 V1/V2 Revision/Preflight/Publication、双摘要、来源覆盖确认、Konva 交互 adapter 与桌面/手机正式路径。付费外部视觉模型质量仍未签收，工程闭环不得冒充审美验收。详见 ADR-0019、ADR-0020、智能成稿契约与漫画成稿专业编辑能力吸收方案。

V2 正式发布固定两条身份：`revisionDocumentDigest` 是包含 automation/bindings/protections 的完整 V2 摘要，`visibleDocumentDigest` 是严格 V2→V1 可见投影摘要。Revision、preflight target、ExportRevision、task input、RenderPlan 和 manifest 必须同时冻结并在 Worker 中重算；历史 V1 继续使用原 `documentDigest` 语义，不回填、不重写。

## 8. 后续扩展点

- SQLite 切 PostgreSQL。
- 多服务实例、远程 worker 或持续队列积压时，将本地 worker 切 BullMQ/Redis，并复核 PostgreSQL 与 Outbox。
- 本地文件切对象存储。
- 单用户切多人协作。
- 基础视频切复杂时间轴。
- Prompt 规则切可配置生成策略。
- Web 核心包装 Electron 或 Tauri 桌面壳。
