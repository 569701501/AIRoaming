# 智能成稿规划与编辑保护契约

## 1. 文档目的

本文定义“智能成稿 + 正式编辑器”实施时必须共用的输入、输出、质量门、人工保护、任务、API 和兼容规则。本文只新增智能规划和人机协作语义，不重写现有 G5 的画布、来源绑定、LayoutRevision、renderer 或 publication。

优先级如下：

1. ADR-0019 决定产品和不可变边界。
2. 本文决定智能成稿与编辑保护的领域契约。
3. 既有 `2026-07-11_G5LayoutDocument与编辑命令契约字典.md` 继续决定可见元素、几何、文字、气泡、来源和保存语义。
4. 既有 `2026-07-11_G5确定性渲染与出版导出契约.md` 继续决定正式输出。

发生冲突时，智能首次流程、对白自动放置和人工保护以 ADR-0019 与本文为准；可见渲染语义仍以既有 G5 契约为准。

## 2. 当前基础与新增缺口

### 2.1 可直接复用

- `LayoutDocumentV1` 已能表达页漫/条漫、画格、画格图片、自由图片、富文本、四类气泡、尾巴和阅读顺序。
- `LayoutWorkingCopy` 已支持 800ms 自动保存、完整文档 CAS、no-op/replay、冲突恢复和来源摘要。
- Editor Command 已支持画布、对象、画格、裁切、文字、气泡、批量操作、模板和 Undo/Redo。
- `PendingEditorCommandSet` 已支持来源绑定、预览、应用、放弃和过期。
- `LayoutRevision/LayoutSourceBinding`、preflight、renderer、publication 和历史导出已完成。

### 2.2 必须新增

- 从正式分镜形成叙事分组，而不是固定一镜一段或四镜一页。
- 从 `motion.voiceLines/comic.dialogue/comic.caption` 生成无遗漏、无重复、不可改写的对白计划。
- 分析图片主体、人物和文字安全区，或在分析不可用时采用保守规则。
- 同时生成多套版式候选，经过硬门、评分和自动修复后选择最高分结果。
- 在布局文档中记录自动规划来源与字段级人工保护。
- 提供整章、场景、页面/段落和选区作用域的智能重排预览。
- 建立覆盖率、可读性、遮挡、节奏和无需手调比例的固定测试语料。

## 3. 领域词汇

| 术语 | 含义 |
| --- | --- |
| 智能成稿 | 从正式分镜、当前定稿图和版式生成完整可编辑 LayoutDocument 的过程 |
| 成稿计划 | 尚未应用的完整文档或命令批次，以及来源摘要、质量评分和问题 |
| 对白项 | 一条不可静默改写、具有稳定 ID、镜头、说话者、类型和顺序的成稿文字来源 |
| 视觉分析 | 对候选定稿图给出的主体、人脸、文字安全区和视觉重心等规范化区域 |
| 规则模式 | 不依赖视觉模型，使用图片比例、分镜元数据和保守文字区域的确定性 fallback |
| 完整模式 | 在规则模式基础上使用通过校验的视觉分析增强裁切、避让与尾巴定位 |
| 保护作用域 | 用户手调后默认不允许智能操作覆盖的字段类别 |
| 显式锁定 | 元素现有 `locked=true`；禁止任何智能变换该元素的全部字段 |
| 质量硬门 | 不满足时成稿计划不得应用的确定性条件 |
| 质量软分 | 多个有效候选之间用于选择最优结果的可重复评分 |

## 4. 总体流水线

```text
正式 StoryboardVersion + 当前 CandidateLockSet + ready Asset + FontPolicy
  -> 服务端冻结 LayoutCompositionSource
  -> 对白归一化与覆盖账本
  -> 叙事分组
  -> 图片视觉分析（可用则增强；失败走规则模式）
  -> 生成多套页/段/画格/裁切/气泡候选
  -> 硬门检查
  -> 有限自动修复
  -> 软分与稳定择优
  -> LayoutCompositionPlan
  -> 首次起稿：来源/CAS 复核后创建 Working Copy
  -> 后续重排：形成 PendingEditorCommandSet
  -> 用户编辑 / 局部智能预览 / 阅读预览
  -> 现有 LayoutRevision + layout_export + publication
```

智能模型不得越过“结构化视觉分析”直接写 LayoutWorkingCopy；最终布局几何、断行、阅读顺序、摘要和质量报告都由受控代码生成。

## 5. 权威输入

### 5.1 客户端只提交意图

客户端不得提交最终 Storyboard 文档、Candidate 来源、Asset 路径、字体清单或最终 LayoutDocument 作为智能成稿事实源。

```ts
type LayoutCompositionModeV1 =
  | "initial"
  | "full_reflow"
  | "scoped_reflow";

type LayoutCompositionIntentV1 =
  | "standard"
  | "more_compact"
  | "more_relaxed"
  | "emphasize_focus"
  | "dialogue_readability";

interface CreateLayoutCompositionRequestV1 {
  schemaVersion: 1;
  mode: LayoutCompositionModeV1;
  intent: LayoutCompositionIntentV1;
  scope: null | {
    canvasIds: string[];
    elementIds: string[];
    shotIds: string[];
  };
  expectedWorkingCopyRowVersion: number | null;
  expectedDocumentDigest: `sha256:${string}` | null;
}
```

约束：

- `initial` 要求当前章节不存在 `LayoutWorkingCopy`，`scope/expected*` 必须为空。
- `full_reflow` 要求存在 Working Copy，作用域为整章。
- `scoped_reflow` 要求至少一个 canvas、element 或 shot；服务端将其扩展为合法的完整叙事组，不能留下半个对白交换。
- `intent=standard` 是首次默认值；其他意图只在用户明确触发局部动作时使用。

### 5.2 服务端冻结来源

服务端从数据库重建并冻结：

```ts
interface LayoutCompositionSourceV1 {
  schemaVersion: 1;
  projectId: string;
  chapterId: string;
  comicFormat: "vertical_scroll" | "paged_comic";
  storyboard: {
    versionId: string;
    documentDigest: `sha256:${string}`;
    document: StoryboardDocumentV2;
  };
  candidateLockSet: {
    digest: `sha256:${string}`;
    items: Array<{
      order: number;
      shotId: string;
      candidateId: string;
      candidateLockRevisionId: string;
      assetId: string;
      assetDigest: `sha256:${string}`;
      width: number;
      height: number;
    }>;
  };
  characterCatalog: {
    digest: `sha256:${string}`;
    items: Array<{ characterId: string; name: string }>;
  };
  fontPolicy: LayoutFontPolicyV1;
  profile: LayoutProfileV1;
  visualAnalysisProvider: null | {
    providerId: string;
    modelId: string;
  };
  baseWorkingCopy: null | {
    id: string;
    rowVersion: number;
    documentDigest: `sha256:${string}`;
    document: LayoutDocumentV2;
  };
  policy: {
    composition: "layout_composition_v1";
    dialogue: "layout_dialogue_v1";
    visualAnalysis: "layout_visual_analysis_v1";
    scoring: "layout_score_v1";
    automation: "layout_automation_v1";
  };
}
```

来源建立前必须验证：

- current StoryboardVersion 存在且 freshness=`current`。
- 每个 active Shot 恰有一个 current CandidateLockRevision 和 ready 图片 Asset。
- `candidateLockSet.digest` 与 current Shot 集合完整对应。
- `characterCatalog` 至少覆盖 Storyboard/voiceLines 引用的角色 ID；名称参与旧 `comic.dialogue` 说话人前缀解析，因此必须进入来源摘要。
- `comicFormat` 与 Profile 类型匹配。
- 默认字体和所需字形可用。
- reflow 的 Working Copy rowVersion/documentDigest 与请求一致。

## 6. 对白归一化

### 6.1 归一化输出

```ts
type LayoutDialogueKindV1 = "speech" | "thought" | "shout" | "caption";

interface LayoutDialogueItemV1 {
  id: string;
  shotId: string;
  shotOrder: number;
  lineOrder: number;
  source: "voice_line" | "comic_dialogue" | "comic_caption";
  sourceIndex: number;
  speakerCharacterId: string | null;
  speakerName: string;
  kind: LayoutDialogueKindV1;
  sourceText: string;
  sourceTextDigest: `sha256:${string}`;
  text: string;
  textDigest: `sha256:${string}`;
  normalization: "identity" | "speaker_prefix_removed";
  confidence: "exact" | "inferred" | "unresolved";
}
```

`id` 必须由 `shotId + source + sourceIndex + sourceTextDigest` 确定性生成，不使用随机 UUID。`sourceText` 是经过 NFC、CRLF→LF 和首尾空白处理后的来源记录；`text` 是进入气泡的内容。两者只允许在成功识别并移除“角色名：”元数据前缀时不同。规划报告和 `LayoutDocumentV2.automation.dialogueBindings` 必须保存输入 `id` 与输出气泡元素 ID 的一一映射；首版旁白也使用 `balloonKind=caption`，不使用无来源的普通 TextElement 代替。

### 6.2 来源优先级

1. `motion.voiceLines[]` 是对白主源，保留原顺序、`characterId/name/line/voiceStyle`。
2. `comic.dialogue` 作为兼容回退时只按 CRLF/LF 拆记录，不按句号、分号或模型猜测拆句。记录开头仅在 `<名称>：`/`<名称>:` 精确匹配 `characterCatalog` 且该角色属于当前 Shot 时移除前缀并绑定角色；不匹配时保留整条原文、说话者为空、尾巴关闭并报告。
3. `comic.dialogue` 记录与 voiceLine 的气泡正文完全相同、且说话者相同或只能唯一匹配时判为重复；模糊匹配不得静默去重。
4. `comic.caption` 按显式换行形成有序 caption 项，始终独立生成 `caption`，但与完全相同的已有 caption 去重。
5. 空白或只含标点的记录不创建气泡，并在报告中说明；非空的“无/none/null”等字符串不得靠占位词猜测丢弃，必须保留并标记 `ambiguous_placeholder`，由上游质量门或用户处理。
6. 除 NFC、换行/首尾空白和已确认说话人前缀外，词句、标点内容和说话者不得由成稿阶段改写。

### 6.3 气泡类型

- `comic.caption` 固定为 `caption`。
- `voiceStyle` 明确包含内心、心声、OS、思考语义时为 `thought`。
- `voiceStyle` 明确包含喊叫、怒吼、惊呼等语义时为 `shout`。
- 其余结构化台词为 `speech`。
- 仅凭一个感叹号不得强制改为 `shout`；可以作为低权重辅助信号。
- 无法识别说话者时仍创建 `speech`，但尾巴关闭并产生 `speaker_unresolved` 非阻断问题。

### 6.4 覆盖账本

首次成稿应用前必须满足：

```text
输入对白项 ID 集合 == 输出 dialogueBindings.dialogueItemId 集合
```

任何遗漏、重复或额外生成均为硬门失败 `LAYOUT_DIALOGUE_COVERAGE_INVALID`，且每个自动气泡的可见文本摘要必须等于来源 `textDigest`。

已有 Working Copy 的后续智能调整使用“有效覆盖账本”：每条仍存在的来源对白必须处于 `placed` 或 `user_suppressed`。`placed` 且有 `text` protection 时允许可见文本与来源摘要不同，代表用户主动改过；smart 不得改回来源文字。`user_suppressed` 只允许由用户删除/隐藏已绑定气泡的确认命令产生，smart 不得重新补回。报告必须分别列出原文放置、人工改文和人工省略，不能把后两者冒充自动 100% 原文覆盖。

## 7. 叙事分组

规划器按下列优先级建立 `NarrativeGroup`：

1. 不跨 `sceneId` 合并，缺少 sceneId 时回退到连续 Shot。
2. 相同 `beatId` 的连续 Shot 优先属于同组；非连续相同 beatId 不重新拼回。
3. 连续 dialogue Shot 和人物交替对白保持同组。
4. `frameType=transition` 或 `panelRhythm=transition` 结束上一组并形成独立转场组。
5. `panelRhythm=impact` 形成重点组，可携带前一张铺垫或后一张反应，但不被普通四格模板压缩。
6. 单组默认 1～4 个 Shot；需要保持完整对话交换时可达到 6 个。

每组生成稳定 `groupId`、Shot 顺序、对白列表、节奏标签和候选模板集合。页漫分页和条漫段落都以 NarrativeGroup 为原子语义边界。

## 8. 图片视觉分析

### 8.1 标准输出

所有坐标使用相对原图的 `[0,1]` 归一化矩形；超界、NaN、负尺寸或重复 ID 必须拒绝。

```ts
interface NormalizedRectV1 {
  x: number;
  y: number;
  width: number;
  height: number;
}

interface LayoutImageAnalysisV1 {
  schemaVersion: 1;
  policyVersion: "layout_visual_analysis_v1";
  assetId: string;
  assetDigest: `sha256:${string}`;
  mode: "vision" | "rule_fallback";
  subjects: Array<{
    id: string;
    characterId: string | null;
    bodyBox: NormalizedRectV1;
    faceBox: NormalizedRectV1 | null;
    importance: number;
    confidence: number;
  }>;
  focalRegions: Array<{ box: NormalizedRectV1; weight: number }>;
  textSafeRegions: Array<{ box: NormalizedRectV1; score: number }>;
  visualCenter: { x: number; y: number };
  warnings: string[];
  analysisDigest: `sha256:${string}`;
}
```

### 8.2 适配器边界

- `LayoutVisualAnalyzer` 可以使用通过评测的多模态 Provider 或本地检测器，但只返回上述严格 JSON。
- Provider 原始自由文本不能进入 LayoutDocument、任务正式输出或 renderer。
- 分析输入绑定 Asset digest；换图后旧分析不可复用。
- 人物 ID 映射只允许使用当前 Shot.characterIds 和已确认角色事实；不得凭模型新建角色。
- 分析结果的置信度低于策略阈值时，相关主体和尾巴定位降级为 rule fallback。
- 来源投影只冻结 `providerId/modelId`；API Key、base URL、secretRef 和 Authorization 不进入任务 input/output、摘要或日志。
- 发送前必须按 DB ready Asset 记录、storageKey 安全路径、真实文件字节数、SHA-256、尺寸和 MIME 逐项复核；只接受 PNG/JPEG/WebP。
- 分析附件使用受限 data URL，最多 8 张；单镜输入先转为最大边 1536px 的 JPEG。模型只开放 `StructuredOutput`，不能调用应用工具或直接修改成稿。
- 每个 Shot 独立设置 1～60 秒超时；非法结构、越界坐标、伪造角色映射、超时或 Provider 失败只让该 Shot 回退，不让整章丢失对白或画格。
- 任务正式输出只保存重新校验并规范化的分析；同项目最近成功任务中与 `assetId + assetDigest` 完全一致的 `vision` 分析可复用，原始模型响应永不作为缓存。

### 8.3 规则 fallback

规则模式必须始终可用：

- 使用图片真实宽高和 `shotType/composition/characterIds` 选择保守裁切。
- 不可靠时保持中心裁切或调整画格比例，避免激进放大。
- 气泡优先放在画格上缘、侧边或条漫画格间留白。
- 无可靠人物锚点时关闭尾巴，而不是猜测指向。
- 报告 `visual_analysis_unavailable`，但只要内容和文字硬门通过，仍可生成基础成稿。

## 9. 布局候选生成

### 9.1 模板语义

现有 `single/two_vertical/two_horizontal/three_focus/four_panel/dialogue_two/action_focus` 继续作为低层几何模板。规划器新增上层语义模板选择，不建立第二套元素类型：

| 叙事语义 | 推荐几何策略 |
| --- | --- |
| establishing / atmosphere | 宽幅或全宽，保留环境信息 |
| dialogue exchange | 双格并列、上下交替或一主一反应，预留对白空间 |
| action / impact | 大重点格 + 小反应格；impact 可独占大区 |
| reaction / detail | 作为相邻主镜头的辅助小格 |
| transition | 独立小格或留白分隔，不与高潮挤压 |
| long dialogue | 扩大画格/留白/气泡，不以无限缩小字号解决 |

### 9.2 候选数量

- 每个 NarrativeGroup 至少生成 3 套合法候选，最多 8 套。
- 整章组合使用受控 beam search，宽度默认 6；不得对所有模板做无界笛卡尔积。
- 生成顺序和 tie-break 必须稳定；相同输入、策略和视觉分析得到相同 plan digest。

### 9.3 自动裁切

- 所有高置信度必需人物主体尽量留在 crop 内。
- 不在画格边缘切断高置信度脸部。
- 多人镜头优先保留全部必需角色；无法同时保留时先调整画格比例，再降低 zoom，最后才产生 warning。
- 图片分析不可靠时禁止激进 zoom。
- 裁切只修改现有非破坏 `CoverCropV1`，不生成派生像素文件。

## 10. 条漫规则

- 条漫使用可变高度连续段落；不得恢复固定每镜 `1080×1920`。
- 一个 strip section 可以容纳 1～4 个相关镜头，实际高度由画格、对白和留白计算。
- atmosphere/slow 增加上下留白；fast/action 减少间距；impact 使用全宽大格；transition 增加场景分隔。
- 长对白优先进入画格上缘或画格之间的留白区，避免覆盖人物脸部。
- 气泡、旁白和画格仍属于同一 LayoutCanvas；正式 renderer 继续按 section boundary 优先切片。
- 自动计划不得在气泡或文字中间建议切片边界。

## 11. 页漫规则

- 每页目标 3～6 格，但不是硬编码；重点页可 1～2 格，密集反应页可 6 格。
- 不在同一 dialogue exchange 或 NarrativeGroup 中间分页，除非该组超过单页硬容量；超过时在完整台词边界拆分。
- 页首优先 establishing/新场景，页尾优先 impact/reveal/reaction/transition。
- impact 不得被压缩为全页最小格；至少获得页面可用面积的 35%，独占页时不受该下限限制。
- 普通页保持安全区、阅读方向和 panelReadingOrder 一致；首版不新增跨页大图和印刷出血。

## 12. 气泡与文字排版

### 12.1 字号与尺寸

- 使用现有受控 FontAsset 和 Shared 字形测量，不按字符数量猜测溢出。
- 系统样式定义最小可读字号、行高、内边距和边框；规划器不得突破最小字号换取通过。
- 文字过长时按顺序尝试：增加气泡尺寸、移动到安全留白、扩大画格/段落、换候选模板、重新分页。
- 一个气泡不得跨画布或跨页拆分。

### 12.2 位置与顺序

- 同一镜头内按 `lineOrder` 排列；整页/段按 Shot order 和 profile 阅读方向生成全局顺序。
- 气泡之间不得形成无法判定的交叉阅读路径。
- 多人对话优先靠近对应人物，仍以阅读顺序和不遮挡关键主体为更高约束。
- caption 无尾巴，优先放在画格上缘或段落转场留白。

### 12.3 尾巴

- 有高置信度人物映射时，尾巴目标指向人物身体附近，不进入 faceBox 中心。
- `thought` 使用现有思考尾巴语义；`caption` 固定关闭尾巴。
- 无可靠人物位置时关闭尾巴并报告，不把随机目标当作已识别说话者。

## 13. 质量硬门、评分与修复

### 13.1 硬门

以下任一失败，计划不得应用：

- `shot_coverage`：每个 active Shot 至少有一个可见 current 图片，且默认初稿恰好放置一次。
- `dialogue_coverage`：输入对白项与输出映射集合完全一致。
- `source_current`：Storyboard、CandidateLockSet、Asset 和 Working Copy 来源在 apply 时未变化。
- `text_fit`：所有文字在最小字号以上无 overflow。
- `geometry_valid`：画布、元素、crop、阅读顺序和引用通过 LayoutDocument codec。
- `font_ready`：所需字体、许可和字形可用。
- `protected_unchanged`：智能结果未修改作用域外、受保护或锁定字段。

### 13.2 软分

有效候选按 100 分制评分：

| 维度 | 分值 | 说明 |
| --- | ---: | --- |
| 内容完整与可读性 | 30 | 字号、行长、气泡密度、阅读路径 |
| 主体与裁切保护 | 25 | 人脸/主体保留、气泡遮挡、裁切置信度 |
| 叙事节奏 | 20 | frameType、panelRhythm、重点与转场 |
| 版面平衡 | 15 | 画格面积、留白、重心与拥挤度 |
| 稳定性与人工保护 | 10 | 少改受保护邻域、少产生低置信度决定 |

相同总分按上述维度依次比较，再按规范化 plan digest 字典序稳定选择。评分明细必须进入报告，UI 只显示用户能理解的摘要，不显示内部权重。

### 13.3 自动修复顺序

每个候选最多执行 4 轮有限修复：

1. 调整气泡尺寸、断行和安全区位置。
2. 调整画格比例、段落高度和非破坏 crop。
3. 更换同一 NarrativeGroup 的候选模板。
4. 页漫重新分页或条漫增加独立留白段。

仍无法通过硬门则任务失败，不输出“基本完成”的 Working Copy。

### 13.6 2026-07-23 专业条漫安全降级与语义样式补充

#### 13.6.1 分析模式与位置硬门

1. `rule_fallback` 表示运行任务没有获得可验证的视觉分析，而不是图片中不存在人物或焦点。该模式所有自动气泡主体必须完全位于所有画格之外，尾巴固定关闭；允许在来源画格上方或画格间建立连续对白 lane，并通过邻接、无画格阻隔的走廊或同来源 stack 保持关联。
2. `vision` 允许气泡进入来源画格，但其主体必须完整落在同 Shot、同 Asset digest 的 verified `textSafeRegion` 内；仅“多数面积位于画格内”、靠近来源画格或没有检测到脸都不能替代该证明。
3. 两种模式都禁止气泡互相重叠、覆盖其他画格或越出画布。`vision` 还必须以 1px 以上即失败的方式避让投影后的人脸、人物身体和高权重焦点区。
4. fallback 的裁切、人物、脸部和焦点可见率不得获得无证据满分。质量报告必须保留 `visual_protection_unverified`；安全外置可以通过模式化位置硬门，但不能宣称已完成视觉保护。
5. 规则 section 高度按实际气泡 stack 扩展。多个 section 的候选关联必须使用各自来源画格，不能把后续镜头气泡错误绑定到第一格的留白。

#### 13.6.2 语义气泡与字体预设

冻结来源新增 `typographyPreset: layout_typography_preset_v1`，分别给出 `speech/thought/shout/caption` 的精确 `fontAssetId/fontWeight/fontStyle`。新任务把该预设纳入 policy digest、来源投影和 Asset 校验；旧任务缺少字段时按旧 `fontPolicy` 生成兼容预设，并同时接受上一版 policy digest。

默认受控字体族为 Noto Sans SC，正式项目提供 400/500/700/900 四个真实 face。语义映射为：

| 语义角色 | 形态与颜色 | 默认字面 |
| --- | --- | --- |
| `speech` | 白底深色描边椭圆 | 400 常规 |
| `thought` | 暖白底、灰蓝描边云朵 | 400 常规 |

#### 13.6.3 编辑、预览与正式渲染一致性

1. Web 编辑器、只读预览和 Server renderer 都以 Asset ID 注册独立 `FontFace`，使用字体文件真实 weight/style，并设置 `font-synthesis:none`；不得让浏览器合成不存在的粗体或斜体。

## 14. LayoutDocumentV2 与人工保护

### 14.1 V2 根结构

V2 不增加可见元素种类，只在 V1 根级增加 automation：

```ts
interface LayoutDocumentV2 extends Omit<LayoutDocumentV1, "schemaVersion" | "kind"> {
  schemaVersion: 2;
  kind: "layout_document_v2";
  automation: LayoutAutomationStateV1;
}

interface LayoutAutomationStateV1 {
  policyVersion: "layout_automation_v1";
  composition: null | {
    compositionDigest: `sha256:${string}`;
    compositionPolicyVersion: "layout_composition_v1";
    storyboardVersionId: string;
    storyboardDigest: `sha256:${string}`;
    sourceLockSetDigest: `sha256:${string}`;
    visualAnalysisSetDigest: `sha256:${string}` | null;
    mode: "vision" | "rule_fallback";
  };
  dialogueBindings: LayoutDialogueBindingV1[];
  protections: LayoutProtectionEntryV1[];
}

interface LayoutDialogueBindingV1 {
  dialogueItemId: string;
  sourceShotId: string;
  sourceTextDigest: `sha256:${string}`;
  initialTextDigest: `sha256:${string}`;
  elementId: string | null;
  disposition: "placed" | "user_suppressed";
}

type LayoutProtectionScopeV1 =
  | "existence"
  | "geometry"
  | "crop"
  | "text"
  | "style"
  | "tail"
  | "source"
  | "reading_order";

interface LayoutProtectionEntryV1 {
  targetKind: "canvas" | "element" | "panel_image";
  targetId: string;
  scopes: LayoutProtectionScopeV1[];
  reason: "user_edit" | "explicit_preserve";
}
```

`compositionDigest` 不包含 taskId、时间戳、本地路径或 URL，避免相同内容因执行时间不同产生不同文档摘要。任务和计划的追溯由 GenerationTask 关系保存。

`dialogueBindings` 按 `dialogueItemId` 规范排序，ID 不得重复。`sourceTextDigest` 绑定原来源记录，`initialTextDigest` 绑定经允许的说话人前缀处理后首次放入气泡的正文。`placed` 必须指向当前文档中唯一、可见的 BalloonElement，且它的 `sourceShotId` 与 binding 一致；`user_suppressed` 可指向一个 hidden BalloonElement 以保留原位置/样式，也可在用户显式彻底删除或所属 canvas 被移除后使用 null tombstone。普通用户手工新增的气泡可以不绑定来源；复制已绑定气泡时，binding 只保留在原元素，副本作为 unbound 自定义气泡，不能被覆盖账本重复计数。

M1 已冻结以下 strict codec 规则：

- 正式入口为 `LayoutDocumentCodecV2`；兼容只读入口为 `LayoutDocumentCodecV1OrV2`。
- V2 根、`automation`、`composition`、binding 和 protection 全部拒绝未知字段；数值、颜色、RichText、图片来源和几何继续复用 V1 strict codec。
- `dialogueBindings` 最多 20,000 条，`protections` 最多 20,000 条，且仍受整份文档 8 MiB canonical bytes 上限约束。
- protection 的 `targetId` 必须指向当前文档中的真实 canvas、顶层 element 或嵌套 panel image；同一 `targetKind + targetId + reason` 不得重复，scope 必须唯一、适用并按固定顺序规范化。
- `initialTextDigest` 使用 `layout_dialogue_text_digest_v1` 对 NFC/换行规范化后的气泡纯文本计算；用户后续改文不会重算它。`sourceTextDigest` 仍绑定 M2 归一化后的权威来源记录，不从当前气泡反推。

保护适用范围固定如下：

| target | applicable scopes |
| --- | --- |
| canvas | `existence, geometry, style, reading_order` |
| panel frame | `existence, geometry, style, reading_order` |
| panel image | `existence, crop, source` |
| free image | `existence, geometry, crop, source, reading_order` |
| text | `existence, geometry, text, style, reading_order` |
| balloon | `existence, geometry, text, style, tail, source, reading_order` |

V1 Working Copy 的保守升级使用上表为每个既有对象生成一条 `explicit_preserve`；纯用户删除对象时，同时清理已不存在或已不适用的 protection，避免留下悬空元数据。`smart` 不得借删除对象清除 protection；`system` 也不会默认清除，必须由受控迁移策略显式处理。

`compositionDigest` 由窄投影 `layout_composition_digest_v1` 计算，输入仅包含 composition policy、Storyboard ID/digest、lock set digest、可选视觉分析 digest、模式、plan digest、初始可见 V1 document digest 和初始 dialogue binding digest。helper 明确挑选这些字段，因此传入 `taskId/createdAt/path/URL` 也不会进入摘要。

### 14.2 编辑命令来源

Editor Command V2 在 V1 基础上增加：

```ts
type LayoutCommandActorV1 = "user" | "smart" | "system";
```

- `user`：命令 reducer 除修改内容外，还按命令类型更新 protection。
- `smart`：应用前检查 protection 与 locked，不能自行清除保护。
- `system`：仅用于来源替换、V1->V2 升级等受控操作；仍需显式策略和测试。

命令到保护作用域的最低映射：

| 命令 | 自动增加保护 |
| --- | --- |
| 移动/缩放/旋转 | `geometry` |
| image crop/display | `crop` |
| 修改对白/旁白文本 | `text` |
| 字体、颜色、边框、气泡类型 | `style` |
| 调整气泡尾巴 | `tail` |
| 改图层/画格阅读顺序 | `reading_order` |
| 显式锁定 | 继续使用元素 `locked=true`，阻止全部 smart 字段 |

用户仅修改文字内容时，系统仍可在后续“整理气泡”中移动该气泡；用户移动气泡后，`geometry` 被保护。字段保护不得粗暴升级为整个元素锁定。

### 14.3 清除保护

用户可对选中对象使用“允许智能再次调整”，显式清除该对象及其嵌套 panel image 当前已有的 protection scope。该动作不修改可见内容，也不解除 `locked=true`；锁定仍需用户单独解除。智能任务、模型和自动修复不能自行清除保护。

### 14.4 对白绑定的编辑规则

- 用户修改已绑定气泡文字：保留 binding，增加 `text` protection；预检显示“对白已人工修改”，但允许用户继续出版。
- 用户删除或隐藏已绑定气泡：必须显示一次语义确认；确认后删除/隐藏元素并把 binding 改为 `user_suppressed`，防止后续智能操作静默补回。
- 用户执行“恢复原对白”：重建或显示对应气泡，恢复来源文字，把 disposition 改回 `placed`，并由用户确认是否清除 `text/existence` 保护。
- Storyboard 来源对白 ID 或摘要变化：旧 binding 派生 stale，进入来源更新预览；不能按相同 `sourceShotId` 猜测为同一句并覆盖人工内容。
- publication 预检对 `user_suppressed` 和人工改文给出可定位 warning；只有未解释的遗漏、重复 binding 或悬空 elementId 才是阻断错误。

V2 command registry 必须提供原子复合命令 `balloon.suppress_bound` 与 `balloon.restore_bound`：前者同时处理元素 hidden/删除和 binding disposition，后者优先恢复 hidden 元素，否则按当前来源创建新气泡并恢复 `placed`。两个命令都必须生成完整 inverse。通用 `element.delete/element.set_hidden` 遇到已绑定气泡时不得只改元素而遗留悬空 binding；Web 必须先展示语义确认，再改用上述复合命令。

### 14.5 M1 命令精确合同

普通 V1 可见命令升级到 V2 时，根字段固定为：

```ts
interface EditorCommandV2 {
  schemaVersion: 2;
  commandId: string;
  type: EditorCommandTypeV2;
  label: string;
  actor: "user" | "smart" | "system";
  payload: unknown;
}

interface EditorCommandBatchV2 {
  schemaVersion: 2;
  batchId: string;
  label: string;
  commands: EditorCommandV2[];
}
```

新增语义命令 payload 固定为：

```ts
type ProtectionClearPayloadV2 = {
  targetKind: "canvas" | "element" | "panel_image";
  targetId: string;
  scopes: LayoutProtectionScopeV1[];
};

type SuppressBoundBalloonPayloadV2 = {
  canvasId: string;
  elementId: string;
  mode: "hide" | "delete";
};

type RestoreBoundBalloonPayloadV2 = {
  dialogueItemId: string;
  canvasId: string;
  richText: RichTextDocumentV1;
  create: null | {
    element: BalloonElementV1;
    beforeElementId: string | null;
  };
  clearProtectionScopes: Array<"existence" | "text">;
};
```

- `protection.clear`、`balloon.suppress_bound`、`balloon.restore_bound` 只允许 `actor=user`。
- hidden binding 恢复时 `create=null`，保留原几何/样式并恢复可见和原始文本；null tombstone 恢复时必须提供一个可见、`sourceShotId` 一致、纯文本摘要匹配 `initialTextDigest` 的新 BalloonElement。
- `clearProtectionScopes` 只允许 `existence/text`；未清除的两项继续以 `user_edit` 保留。
- 通用 `element.delete/element.set_hidden` 命中 bound balloon 时 fail-closed；复制 bound balloon 不复制 binding。
- 每条命令和批次都产生 V2 全文档 snapshot inverse；批次中途失败不修改输入，50 条智能微调只产生一个外层 inverse。
- protection 检查发生在 smart 可见命令执行前；任何目标 scope 被保护或对象 `locked=true` 时，整个命令失败，不进行部分应用。

## 15. layout_compose 任务协议

### 15.1 定位

新增章节作用域持久任务 `layout_compose`。它与 `shot_prompt_generate` 类似，只生成来源密封的建议结果，不直接创建 LayoutRevision 或 publication。

| 项 | 规则 |
| --- | --- |
| target | `type=chapter`, `id=chapterId`, 必须携带 `chapterId` |
| source | StoryboardVersion、CandidateLockRevision/Asset 集、字体/样式策略、可选 Working Copy digest |
| concurrencyKey | `layout-compose`，首版全局并发 1 |
| maxAttempts | 2；确定性合同错误不可重试，临时 Provider/IO 错误可重试 |
| idempotency | `chapterId + mode + sourceProjectionDigest + baseDocumentDigest + scopeDigest + policySetDigest` |
| 写入 | worker 只写 GenerationTask output；apply 由独立业务事务创建 WC 或 Pending，并同时写 ADR-0020 的不可变应用凭证 |

### 15.2 输出

```ts
interface LayoutCompositionTaskOutputV1 {
  schemaVersion: 1;
  mode: LayoutCompositionModeV1;
  sourceProjectionDigest: `sha256:${string}`;
  baseDocumentDigest: `sha256:${string}` | null;
  result: {
    kind: "initial_document" | "command_batch";
    document: LayoutDocumentV2 | null;
    commandBatch: EditorCommandBatchV2 | null;
  };
  visualAnalyses: Array<{
    shotId: string;
    sourceDigest: `sha256:${string}`;
    analysis: LayoutImageAnalysisV1;
  }>;
  report: {
    planDigest: `sha256:${string}`;
    analysisMode: "vision" | "mixed" | "rule_fallback";
    candidateCount: number;
    selectedScore: number;
    scoreBreakdown: Record<string, number>;
    shotCoverage: { expected: number; placed: number };
    dialogueCoverage: {
      expected: number;
      placedOriginal: number;
      userModified: number;
      userSuppressed: number;
    };
    issues: Array<{
      code: string;
      severity: "info" | "warning" | "error";
      canvasId: string | null;
      elementId: string | null;
      shotId: string | null;
    }>;
  };
}
```

`initial_document` 与 `command_batch` 必须二选一。任务输出不能含 API Key、Authorization、绝对路径、图片字节或 Provider 原始自由文本。

### 15.3 apply

- 初次成稿：再次验证 source projection，确认 Working Copy 仍不存在，再原子创建 V2 Working Copy。
- full/scoped reflow：再次验证 Working Copy rowVersion/documentDigest 和来源，构建 `PendingEditorCommandSet`；不得直接更新 Working Copy。
- 重复 apply 对同一 task/相同 base 状态返回 replay；已发生其他修改则返回冲突，不做部分应用。
- apply 失败不修改当前 Working Copy、LayoutRevision 或 current publication。
- 任务成功与结果已应用是两个事实。每次成功 apply 在同一事务写一条 `LayoutCompositionApplication`；同一 task 至多一条且不可更新。重复 apply 必须重验凭证所指目标仍保持创建时摘要/行版本，否则返回冲突。

### 15.4 M4 退出时实施状态（2026-07-23）

状态：`complete`。

- Shared 已注册 `layout_compose` chapter scope、initial/full/scoped 请求、权威冻结输入、strict 输出、应用响应和敏感扫描；Working Copy/Pending codec 已支持 V2。
- Server 已接持久任务 create/status/apply、权威来源投影、worker registry、claim/heartbeat/recovery 和 exactly-once application。
- initial 原子创建 V2 Working Copy；full reflow 只生成 PendingEditorCommandSet，确认前当前工作稿不变；`scoped_reflow` 在当时尚未定义真实作用域，因而 fail-closed。
- M4 退出时 persistent worker 给每个 Shot 传入 `analysis=null`，运行时报告为 `rule_fallback`。该历史缺口已由 M6 关闭。
- migration 0018 增加 V2 WC 单向升级与 `LayoutCompositionApplication`；模型理由和不变量见 ADR-0020。
- 真实数据库集成已覆盖幂等创建、初次应用/replay、用户编辑后的旧结果冲突、Server 重启恢复、整章重排预览不改原稿、确认应用和重复应用冲突。

### 15.5 M6 视觉分析与局部重排实施状态（2026-07-23）

状态：`complete`。

- `visualAnalysisProvider` 已进入权威来源投影和 policy digest，但只包含 provider/model 标识；无配置时整章稳定使用 `rule_fallback`。
- worker 对每个 Shot 消费真实或回退视觉证据，并把清洗后的 `visualAnalyses`、`vision/mixed/rule_fallback` 和问题写入 strict output；历史缺失新字段的任务仍按空数组兼容读取。
- 画布 scope 表示当前页/条漫画布段；选中 element 先映射到来源 Shot，再扩展到完整 NarrativeGroup；纯 shot scope 先扩展到同 scene，再扩展完整 NarrativeGroup。任何不存在或不含分镜对象的 ID 都直接拒绝，不静默改成整章。
- 局部计划只生成画格 geometry、panel image crop、气泡 geometry/style/tail 命令；不改台词、来源、阅读顺序，不新增或删除对象。每个字段分别检查 protection 与 `locked`，受保护字段跳过并产生 `SMART_PROTECTED_ITEMS_PRESERVED`，而不是覆盖或让其他安全修改全部失败。
- 所有 scoped 结果仍形成一个 V2 PendingEditorCommandSet。预览不修改 Working Copy；放弃不写 WC；应用后整个批次进入一次 Undo。
- full reflow 遇到手调保护时也会降为全画布的细粒度安全命令，不再用整份文档替换绕过用户修改。
- 本轮 provider 通道由本地假结构化运行时验证，未调用付费外部视觉模型；具体模型的画面理解和审美质量仍需未来在用户授权预算下单独抽样。

| 方法 | 路径 | 用途 |

## 17. 状态机

```text
no_working_copy
  -> composing
  -> composition_ready
  -> applying_initial
  -> editing

editing
  -> composing_preview
  -> preview_ready
  -> preview_applied -> editing
  -> preview_discarded -> editing

任意 composing 状态
  -> failed_rule_recoverable
  -> failed_blocking
  -> expired_source_changed
```

用户文案：

| 内部状态 | 用户文案 |
| --- | --- |
| `composing` | 正在编排镜头与对白 |
| `composition_ready` | 智能成稿已完成 |
| `rule_fallback` | 已生成基础成稿；部分图片使用保守排法 |
| `preview_ready` | 新排法已准备，可对比后应用 |
| `expired_source_changed` | 定稿图或分镜已更新，请重新生成 |
| `failed_blocking` | 有内容无法安全排入成稿，请查看问题 |

普通 UI 不显示 digest、task source、policyVersion、rowVersion 或 PendingEditorCommandSet。

## 19. 模块边界

### 19.1 Shared `packages/shared/src/layout/`

- `composition-contract.ts`：输入、输出、报告、错误和 codec。
- `dialogue-plan.ts`：对白归一化、稳定 ID 和覆盖账本。
- `narrative-groups.ts`：场景/beat/节奏分组。

Shared 不读取数据库、网络、文件路径或 Provider，不保存 Konva/DOM 状态。

### 19.2 Server Layout Application

新增建议模块：

- `LayoutCompositionService`：重建来源、创建任务、apply、CAS 和 API DTO。

- `LayoutCompositionSourceProjector`：Storyboard/lock/Asset/font/policy 投影。

- `LayoutReviewWorkspace`：左侧结构、中央正式画布、右侧上下文属性。

- `LayoutIssueDrawer`：用户可理解的问题列表和定位。
- 现有 Konva/DOM adapter、session、autosave 和 command reducer继续复用。

## 20. 并发、恢复与幂等

- 创建任务必须使用 idempotency key；刷新页面或丢响应不能产生多个等价任务。
- Worker 重启后由现有持久任务 lease/recovery 恢复，不建立内存唯一状态。
- 任务成功不等于已应用；apply 使用 task output digest、source projection、Working Copy CAS 三重校验。
- 初次任务完成前如果用户通过其他入口创建了 Working Copy，task 保留历史结果但不得覆盖。
- reflow 期间用户继续编辑导致 base digest 变化时，预览过期；系统提示重新生成，不尝试自动三方合并。
- 同一章节最多一个 active composition slot；新任务显式 supersede 旧 pending preview，不能影响已应用 Working Copy。

## 21. 安全、隐私与资源

- 视觉分析只读取当前章节已锁定候选图；不得扫描项目外文件或未登记 Asset。
- 外部视觉 Provider 使用现有 SecretStore/Provider 边界；秘密不进入 task input/output、LayoutDocument、日志或导出。
- 图片下载与解码继续使用受控 AssetResolver，拒绝未知 MIME、动画、异常 EXIF 和超限图片。
- 规划器设置最大 Shot、对白、候选、beam、修复轮次和元素数量，不能形成无界搜索。
- 条漫编辑预览使用段落虚拟化；正式 renderer 仍消费完整不可变 Revision，不按视口截图。

## 22. 兼容与切换

### 22.1 V1 读取

```text
LayoutDocumentV1
  -> 保留全部可见字段
  -> schemaVersion=2 / kind=layout_document_v2
  -> automation.composition=null
  -> automation.dialogueBindings=[]
  -> 为现有 canvas/element/panel image 按适用字段生成 reason=explicit_preserve 的保护
```

历史 LayoutRevision 仍保存原 V1 JSON 和摘要；只有恢复到 Working Copy 时才在新写入前升级。不得批量重算历史摘要。V1 Working Copy 无法证明哪些对象是人工调整，因此必须保守保护已有可见内容；用户显式选择“允许智能调整”或“生成整章新排法”并通过差异预览后，才可释放相应 scope。

### 22.2 V2 降级

V2 首版不新增可见元素类型，因此纯降级投影仅剥离 automation 并恢复 V1 根字段。它只用于 renderer/legacy adapter/golden/诊断，不得自动把 V1 JSON 覆盖写回 V2 Working Copy 或 Revision，否则会丢失 dialogue binding 和人工保护。切换前必须通过 `V1 -> V2 -> V1` 可见文档摘要等价测试。

### 22.3 功能开关

建议开关 `smart_layout_composition_v1`：

- off：继续打开现有编辑器和旧 initialize 兼容入口，不创建 `layout_compose`；已经存在的 V2 文档仍由 V2-aware codec/editor 保存为 V2，不能降级覆盖。
- shadow：后台生成计划和评分但不应用，用于固定语料比较。
- on：无 Working Copy 时自动成稿；已有 Working Copy 仅显式预览。

开关不能影响既有 LayoutRevision 的 renderer 和 publication。

一旦产生首个 V2 Working Copy，应用版本回滚到完全不认识 V2 的旧代码不再是普通 feature toggle；只能使用切换前协调备份恢复，或运行显式、审计过的迁移。不得让旧代码把 V2 当非法文档后重建空白 V1。
