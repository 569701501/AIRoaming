## 1. 建模原则

- 中间产物必须可追溯，不能只保存最终图片或视频。
- AI 任务的输入输出必须留存，便于复跑、调试和版本比较。
- 图片、音频、视频、PDF 都统一抽象为 `Asset`。
- 生成候选与分镜之间通过 `Candidate` 连接。
- 当前锁定结果与历史候选分离，避免覆盖历史。
- 章节是项目内一等工作单元，后续剧本、结构化剧情、分镜、候选图、排版和导出优先挂到 `chapterId`。
- 项目级角色、世界观、通用场景和共享素材继续挂到 `projectId`，供多个章节复用。
- 对话框组件可以公共复用，但原始对话记录必须按项目步骤隔离。
- 跨步骤 AI 上下文只共享用户已确认的事实、保存文档和锁定产物，不共享未确认聊天假设。

## 2. 实体关系图

```text
Project
  ├─ ConversationThread(step scoped)
  │    └─ ConversationMessage
  ├─ ProjectContextFact(confirmed only)
  ├─ Chapter
  │    ├─ ChapterScriptVersion
  │    ├─ StoryVersion
  │    │    ├─ StoryBeat
  │    │    └─ Shot
  │    │         ├─ Candidate
  │    │         │    └─ Asset(image)
  │    │         └─ lockedCandidateId
  │    ├─ LayoutPage
  │    │    └─ PanelPlacement
  │    └─ Asset(chapter scoped)
  ├─ Character
  │    └─ Asset(reference image)
  ├─ SceneLocation
  │    └─ Asset(background/reference)
  ├─ GenerationTask
  │    ├─ inputJson
  │    └─ outputJson
  ├─ VideoDraft
  │    └─ VideoSegment
  └─ Asset
```

## 3. Project

项目容器，承载一个作品的全部故事、分镜、素材和导出物。

```json
{
  "id": "project_001",
  "name": "月下旅人",
  "type": "comic",
  "status": "draft",
  "storyTitle": "月下旅人：第一话",
  "genreTags": ["悬疑", "都市"],
  "comicFormat": "vertical_scroll",
  "artStyle": "dark_realistic",
  "currentChapterId": "chapter_001",
  "currentStoryVersionId": "story_v001",
  "createdAt": "2026-05-23T00:00:00.000Z",
  "updatedAt": "2026-05-23T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 项目 ID |
| `name` | string | 项目名称 |
| `type` | enum | `comic/light_motion/mixed` |
| `status` | enum | `draft/story_ready/shots_ready/images_ready/layout_ready/exported` |
| `storyTitle` | string | 故事标题，用于项目内创作和故事版本默认标题；在第 1 步“剧本”保存 |
| `genreTags` | string[] | 题材标签或类型标签；在第 1 步“剧本”保存，项目库卡片当前不展示 |
| `comicFormat` | enum | `vertical_scroll/page_horizontal/four_panel` |
| `artStyle` | enum | `dark_realistic/semi_realistic/japanese_realistic/comic_style/cyberpunk/custom` |
| `currentChapterId` | string/null | 当前活跃章节 |
| `currentStoryVersionId` | string | 当前故事版本 |

当前开发阶段还没有接入数据库持久化，后端运行时仍维护进程内 `Project` 索引用于服务 API；项目创建、草稿保存和章节完成会同步写入本地 workspace。服务启动或首次访问项目接口时，会扫描 `workspace/projects/*/project.json` 和章节目录，反向恢复进程内项目索引，避免重启后项目库丢失。

创建项目只建立项目记录，前端创建弹窗只保留“项目名称”一个字段；`type` 使用默认漫画项目类型；`storyTitle`、`genreTags`、`comicFormat`、`artStyle` 和章节剧本在第 1 步“剧本”保存。

```text
workspace/projects/{projectId}/project.json
workspace/projects/{projectId}/chapters/chapter-001/chapter.json
workspace/projects/{projectId}/chapters/chapter-001/script.md
```

当前后端创建项目时已默认创建 `chapter-001` 并写入章节目录。过渡期旧剧本保存接口仍提交 `sourceText`，但后端只同步写入当前章节 `script.md`；`story/story_draft.source.txt` 旧兼容路径已废弃，新项目不再创建、读取或写入。

旧项目草稿保存接口：

```text
PATCH /api/projects/{projectId}
```

请求字段：

```json
{
  "name": "迷雾之城",
  "storyTitle": "迷雾之城：第一话",
  "genreTags": ["悬疑", "都市"],
  "comicFormat": "vertical_scroll",
  "artStyle": "dark_realistic",
  "description": "迷雾之城：第一话",
  "sourceText": "故事原文"
}
```

响应返回更新后的 `ProjectListItem` 和 `WorkbenchSnapshot`。

该接口为过渡兼容入口。剧本页当前章节保存应优先使用章节草稿保存接口。

`WorkbenchSnapshot` 中章节字段为剧本页读取当前内容的主契约：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chapters` | `ChapterListItem[]` | 当前项目章节列表，用于后续章节列表和章节切换器 |
| `currentChapter` | `ChapterDetail/null` | 当前活跃章节详情；剧本编辑器、当前章节信息面板和剧本步骤对话上下文应优先读取这里的 `sourceText`、`title` 和 `id` |
| `story` | `WorkbenchStory` | 过渡镜像，用于尚未迁移的旧消费者兜底；新增消费点不应把它当作章节事实源 |

## 4. Chapter

章节是项目内创作的基本推进单元。用户完成第 1 章后，可以创建或进入第 2 章继续创作。

```json
{
  "id": "chapter_001",
  "projectId": "project_001",
  "order": 1,
  "title": "第 1 章",
  "status": "draft",
  "currentScriptVersionId": "chapter_script_v001",
  "currentStoryVersionId": "story_v001",
  "sourceText": "当前章节剧本正文",
  "summary": "本章一句话主线",
  "createdAt": "2026-05-27T00:00:00.000Z",
  "updatedAt": "2026-05-27T00:00:00.000Z",
  "completedAt": null
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 章节 ID |
| `projectId` | string | 所属项目 |
| `order` | number | 章节顺序，不能只依赖文件夹名 |
| `title` | string | 章节标题，默认可为“第 1 章” |
| `status` | enum | 章节当前状态 |
| `currentScriptVersionId` | string/null | 当前剧本版本 |
| `currentStoryVersionId` | string/null | 当前结构化剧情版本 |
| `sourceText` | string | 当前章节剧本正文，MVP 可先冗余保存 |
| `summary` | string | 当前章节故事主线或一句话总结 |
| `completedAt` | string/null | 当前章节剧本完成时间 |

章节状态建议：

| 状态 | 含义 |
| --- | --- |
| `draft` | 章节草稿中 |
| `script_done` | 当前章节剧本已完成，可进入剧情结构 |
| `structured` | 当前章节已结构化 |
| `storyboard_done` | 当前章节分镜已完成 |
| `images_done` | 当前章节候选图或锁定图已完成 |
| `layout_done` | 当前章节排版已完成 |
| `exported` | 当前章节已导出 |

### 4.1 ChapterScriptVersion

章节剧本版本用于保存用户对章节剧本的大改和完成本章时的快照。

```json
{
  "id": "chapter_script_v001",
  "chapterId": "chapter_001",
  "projectId": "project_001",
  "version": 1,
  "sourceText": "当前章节剧本正文",
  "sourcePath": "projects/project_001/chapters/chapter-001/script.md",
  "status": "current",
  "createdAt": "2026-05-27T00:00:00.000Z"
}
```

保存草稿可以覆盖当前章节 `script.md`。点击“完成本章，进入下一章”时，必须写入当前剧本快照，并把章节状态推进到 `script_done`。

章节 API：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/projects/{projectId}/chapters` | 返回章节列表和当前章节 ID |
| `GET` | `/api/projects/{projectId}/chapters/{chapterId}` | 返回单个章节详情 |
| `PATCH` | `/api/projects/{projectId}/chapters/{chapterId}/draft` | 保存当前章节草稿，覆盖 `script.md` |
| `POST` | `/api/projects/{projectId}/chapters/{chapterId}/complete` | 完成本章，写入 `script.versions/script-vNNN.md`，并创建或进入下一章 |

保存章节草稿请求：

```json
{
  "sourceText": "当前章节剧本正文",
  "title": "第 1 章",
  "summary": "本章一句话主线"
}
```

完成本章请求：

```json
{
  "sourceText": "当前章节剧本正文",
  "title": "第 1 章",
  "summary": "本章一句话主线",
  "createNextChapter": true,
  "nextChapterTitle": "第 2 章"
}
```

完成本章响应必须返回：

| 字段 | 说明 |
| --- | --- |
| `completedChapter` | 已完成章节，状态为 `script_done` |
| `activeChapter` | 完成后进入的章节；如无下一章且 `createNextChapter` 不为 `false`，则为新建章节 |
| `chapters` | 更新后的章节列表 |
| `scriptVersion` | 本次完成动作写入的章节剧本版本 |
| `createdNextChapter` | 本次是否创建了下一章 |

## 5. StoryVersion

保存结构化剧情。章节模型接入后，`StoryVersion` 应归属于 `Chapter`，用于表示某个章节的一次结构化结果。

```json
{
  "id": "story_v001",
  "projectId": "project_001",
  "chapterId": "chapter_001",
  "version": 1,
  "sourceText": "当前章节剧本正文",
  "summary": "一句话摘要",
  "structureJson": {
    "characters": [],
    "scenes": [],
    "beats": []
  },
  "status": "structured"
}
```

| 状态 | 含义 |
| --- | --- |
| `draft` | 只有原文 |
| `structured` | 已结构化 |
| `shots_generated` | 已生成分镜 |
| `archived` | 历史版本 |

## 9. Shot

分镜单元，是图片生成和排版的核心。

```json
{
  "id": "shot_001",
  "projectId": "project_001",
  "chapterId": "chapter_001",
  "storyVersionId": "story_v001",
  "beatId": "beat_001",
  "shotNumber": 1,
  "sceneId": "scene_001",
  "characterIds": ["char_hero"],
  "action": "林舟站在雨夜街口抬头看灯",
  "dialogue": "",
  "caption": "雨越下越密。",
  "camera": "medium shot, slight low angle",
  "composition": "character left third, street depth on right",
  "emotion": "lonely",
  "promptDraft": "comic panel, rainy old street at night...",
  "lockedCandidateId": null,
  "status": "draft"
}
```

| 状态 | 含义 |
| --- | --- |
| `draft` | 初始生成或编辑中 |
| `ready_for_image` | 可用于图片生成 |
| `image_generated` | 已有候选图 |
| `locked` | 已锁定候选图 |
| `needs_revision` | 需要重改 |

所有 AI 和导出任务的统一记录。

```json
{
  "id": "task_001",
  "projectId": "project_001",
  "chapterId": "chapter_001",
  "type": "image_generate",
  "status": "running",
  "targetType": "shot",
  "targetId": "shot_001",
  "inputJson": {},
  "outputJson": null,
  "errorJson": null,
  "attempt": 1,
  "createdAt": "2026-05-23T00:00:00.000Z",
  "startedAt": "2026-05-23T00:00:01.000Z",
  "finishedAt": null
}
```

任务类型见 `文档/02_架构与契约/生成任务协议.md`。

## 11. Candidate

候选结果，通常关联一个分镜和一个图片 Asset。

```json
{
  "id": "candidate_001",
  "projectId": "project_001",
  "chapterId": "chapter_001",
  "shotId": "shot_001",
  "taskId": "task_001",
  "assetId": "asset_img_001",
  "index": 1,
  "status": "generated",
  "score": null,
  "notes": ""
}
```

| 状态 | 含义 |
| --- | --- |
| `generated` | 已生成 |
| `selected` | 当前选中 |
| `locked` | 锁定用于分镜 |
| `rejected` | 废弃 |
| `superseded` | 被替代 |

## 15. 对话框与项目上下文模型

对话框属于项目工作区公共能力，但数据上不采用“整个项目共用一条完整对话记录”。

### 14.1 ConversationThread

按项目步骤隔离的对话线程。

```json
{
  "id": "thread_001",
  "projectId": "project_001",
  "stepKey": "project_story",
  "title": "剧本对话",
  "status": "active",
  "createdAt": "2026-05-25T00:00:00.000Z",
  "updatedAt": "2026-05-25T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 对话线程 ID |
| `projectId` | string | 所属项目 |
| `stepKey` | enum | `project_story/story_structure/storyboard/image_candidates/layout_export/asset_package` |
| `title` | string | 线程显示名 |
| `status` | enum | `active/archived` |

唯一性建议：

```text
projectId + stepKey
```

MVP 阶段可以先保证每个项目步骤只有一条主线程，后续再扩展多线程或专题线程。

### 14.2 ConversationMessage

对话消息记录。

```json
{
  "id": "msg_001",
  "threadId": "thread_001",
  "projectId": "project_001",
  "stepKey": "project_story",
  "role": "assistant",
  "content": "我建议把第一幕冲突提前，让主角更早做出选择。",
  "model": {
    "providerId": "aurora",
    "modelId": "gpt-5.4"
  },
  "runtimeStatus": "completed",
  "sourceRefs": ["story_v001"],
  "proposedPatch": null,
  "applyState": "not_applied",
  "createdAt": "2026-05-25T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `threadId` | string | 所属对话线程 |
| `projectId` | string | 冗余项目 ID，便于查询 |
| `stepKey` | enum | 消息发生的项目步骤 |
| `role` | enum | `user/assistant/system/tool` |
| `content` | string | 消息内容 |
| `model` | object/null | assistant 消息使用的 `providerId/modelId` |
| `runtimeStatus` | enum | `running/completed/failed` |
| `sourceRefs` | string[] | 引用的项目文档、当前步骤产物或项目级已确认事实 |
| `proposedPatch` | object/null | AI 建议的可应用改动 |
| `applyState` | enum | `not_applied/applied/inserted/dismissed` |

规则：

- `not_applied` 消息只是聊天记录，不进入项目级事实。
- `applied` 或 `inserted` 表示用户已把内容写入当前步骤文档。
- 不提供跨步骤手动引用原始聊天消息；跨步骤来源只能来自项目级已确认事实、保存文档和锁定产物。

### 14.3 ProjectContextFact

项目级已确认事实，用于跨步骤共享上下文。

```json
{
  "id": "fact_001",
  "projectId": "project_001",
  "type": "character",
  "content": {
    "name": "林舟",
    "appearance": "黑发，短外套，神情克制"
  },
  "sourceType": "story_version",
  "sourceId": "story_v001",
  "status": "confirmed",
  "createdAt": "2026-05-25T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | enum | `story/character/world/style/structure/shot/layout/asset/custom` |
| `content` | object | 已确认事实内容 |
| `sourceType` | enum | 来源类型，如 `story_version/shot/candidate/layout_page/asset` |
| `sourceId` | string | 来源对象 ID |
| `status` | enum | `confirmed/superseded/archived` |

只有以下用户动作可以把内容提升为项目级事实：

- 应用到当前文档。
- 插入到光标处并保存。
- 保存草稿。
- 确认剧情结构。
- 锁定候选图。
- 导出或归档素材。

AI 上下文注入顺序建议：

```text
当前步骤系统提示词
  -> 项目级已确认事实
  -> 当前步骤主文档或产物
  -> 当前步骤对话记录
  -> 用户本轮输入
```

### 14.4 DialogueRuntimeSession

对话运行时映射。第一阶段采用 OpenCode 时，用于把 AI漫游业务线程映射到 OpenCode 内部 session。

```json
{
  "id": "runtime_session_001",
  "threadId": "thread_001",
  "projectId": "project_001",
  "stepKey": "project_story",
  "runtime": "opencode",
  "externalSessionId": "oc_session_001",
  "status": "active",
  "providerId": "aurora",
  "modelId": "gpt-5.5",
  "variant": "medium",
  "createdAt": "2026-05-25T00:00:00.000Z",
  "updatedAt": "2026-05-25T00:00:00.000Z"
}
```

规则：

- `DialogueRuntimeSession` 只负责运行时路由，不承载业务聊天内容。
- `ConversationThread`、`ConversationMessage` 和 `ProjectContextFact` 仍是 AI漫游对话与上下文事实源。
- OpenCode Session 不向前端直接暴露。
- OpenCode 原始事件必须由后端转换为 AI漫游标准 `dialogue.*` 事件。
- 如果未来替换运行时，只替换 `runtime/externalSessionId` 映射和 runtime adapter，不重写业务对话模型。

当前实现状态：

- 2026-05-26 已在 `packages/shared/src/dto.ts` 增加 `DialogueThread`、`DialogueMessageItem`、`SendDialogueMessageRequest`、`SendDialogueMessageResponse` 和 `AIRuntimeModelItem` DTO。
- 2026-05-26 已增加 `DialogueStreamEvent`，当前事件类型包含 `dialogue.message.created`、`dialogue.message.delta`、`dialogue.message.completed` 和 `dialogue.error`。
- 2026-05-26 后端首版使用进程内 `projectId + stepKey` 对话线程和 OpenCode session 映射，尚未落数据库。
- 2026-05-26 已支持同步发送和流式发送剧本步骤对话并记录 assistant 文本；`sourceRefs`、`proposedPatch`、`applyState` 和停止生成尚未实现。
