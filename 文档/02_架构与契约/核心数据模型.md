## 1. 建模原则

- 中间产物必须可追溯，不能只保存最终图片或视频。
- AI 任务的输入输出必须留存，便于复跑、调试和版本比较。
- 图片、音频、视频、PDF 都统一抽象为 `Asset`。
- 生成候选与分镜之间通过 `Candidate` 连接。
- 当前锁定结果与历史候选分离，避免覆盖历史。
- 对话框组件可以公共复用，但原始对话记录必须按项目步骤隔离。
- 跨步骤 AI 上下文只共享用户已确认的事实、保存文档和锁定产物，不共享未确认聊天假设。

## 2. 实体关系图

```text
Project
  ├─ ConversationThread(step scoped)
  │    └─ ConversationMessage
  ├─ ProjectContextFact(confirmed only)
  ├─ StoryVersion
  │    ├─ StoryBeat
  │    └─ Shot
  │         ├─ Candidate
  │         │    └─ Asset(image)
  │         └─ lockedCandidateId
  ├─ Character
  │    └─ Asset(reference image)
  ├─ SceneLocation
  │    └─ Asset(background/reference)
  ├─ GenerationTask
  │    ├─ inputJson
  │    └─ outputJson
  ├─ LayoutPage
  │    └─ PanelPlacement
  ├─ VideoDraft
  │    └─ VideoSegment
  └─ Asset
```

## 3. Project

项目容器，承载一个作品的全部故事、分镜、素材和导出物。

```json
{
  "id": "project_001",
  "name": "月下旅人",
  "type": "comic",
  "status": "draft",
  "storyTitle": "月下旅人：第一话",
  "genreTags": ["悬疑", "都市"],
  "comicFormat": "vertical_scroll",
  "artStyle": "dark_realistic",
  "currentStoryVersionId": "story_v001",
  "createdAt": "2026-05-23T00:00:00.000Z",
  "updatedAt": "2026-05-23T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 项目 ID |
| `name` | string | 项目名称 |
| `type` | enum | `comic/light_motion/mixed` |
| `status` | enum | `draft/story_ready/shots_ready/images_ready/layout_ready/exported` |
| `storyTitle` | string | 故事标题，用于项目内创作和故事版本默认标题；在第 1 步“剧本”保存 |
| `genreTags` | string[] | 题材标签或类型标签；在第 1 步“剧本”保存，项目库卡片当前不展示 |
| `comicFormat` | enum | `vertical_scroll/page_horizontal/four_panel` |
| `artStyle` | enum | `dark_realistic/semi_realistic/japanese_realistic/comic_style/cyberpunk/custom` |
| `currentStoryVersionId` | string | 当前故事版本 |

当前开发阶段还没有接入数据库持久化，项目创建和草稿保存先由后端维护进程内 `Project`，并同步写入本地 workspace。

创建项目只建立项目记录，前端创建弹窗只保留“项目名称”一个字段；`type` 使用默认漫画项目类型；`storyTitle`、`genreTags`、`comicFormat`、`artStyle` 和 `sourceText` 在第 1 步“剧本”保存。

```text
workspace/projects/{projectId}/project.json
workspace/projects/{projectId}/story/story_draft.source.txt
```

草稿保存接口：

```text
PATCH /api/projects/{projectId}
```

请求字段：

```json
{
  "name": "迷雾之城",
  "storyTitle": "迷雾之城：第一话",
  "genreTags": ["悬疑", "都市"],
  "comicFormat": "vertical_scroll",
  "artStyle": "dark_realistic",
  "description": "迷雾之城：第一话",
  "sourceText": "故事原文"
}
```

响应返回更新后的 `ProjectListItem` 和 `WorkbenchSnapshot`。

## 4. StoryVersion

保存故事原文和结构化剧情。

```json
{
  "id": "story_v001",
  "projectId": "project_001",
  "version": 1,
  "sourceText": "故事原文",
  "summary": "一句话摘要",
  "structureJson": {
    "characters": [],
    "scenes": [],
    "beats": []
  },
  "status": "structured"
}
```

| 状态 | 含义 |
| --- | --- |
| `draft` | 只有原文 |
| `structured` | 已结构化 |
| `shots_generated` | 已生成分镜 |
| `archived` | 历史版本 |

## 5. StoryBeat

剧情节拍，是分镜生成的上游语义单元。

```json
{
  "id": "beat_001",
  "storyVersionId": "story_v001",
  "order": 1,
  "sceneId": "scene_001",
  "summary": "主角进入雨夜街道",
  "characters": ["char_hero"],
  "emotionalTone": "lonely",
  "dialogueHints": []
}
```

## 6. Character

角色模板，约束图片生成一致性。

```json
{
  "id": "char_hero",
  "projectId": "project_001",
  "name": "林舟",
  "role": "protagonist",
  "appearance": "黑发，短外套，神情克制",
  "personality": "冷静，敏感",
  "referenceAssetIds": ["asset_char_ref_001"],
  "promptFragment": "young man, black hair, short jacket"
}
```

## 7. SceneLocation

场景或地点模板。

```json
{
  "id": "scene_001",
  "projectId": "project_001",
  "name": "雨夜街道",
  "description": "潮湿的老城区街道，路灯昏黄",
  "timeOfDay": "night",
  "mood": "quiet, melancholy",
  "referenceAssetIds": []
}
```

## 8. Shot

分镜单元，是图片生成和排版的核心。

```json
{
  "id": "shot_001",
  "projectId": "project_001",
  "storyVersionId": "story_v001",
  "beatId": "beat_001",
  "shotNumber": 1,
  "sceneId": "scene_001",
  "characterIds": ["char_hero"],
  "action": "林舟站在雨夜街口抬头看灯",
  "dialogue": "",
  "caption": "雨越下越密。",
  "camera": "medium shot, slight low angle",
  "composition": "character left third, street depth on right",
  "emotion": "lonely",
  "promptDraft": "comic panel, rainy old street at night...",
  "lockedCandidateId": null,
  "status": "draft"
}
```

| 状态 | 含义 |
| --- | --- |
| `draft` | 初始生成或编辑中 |
| `ready_for_image` | 可用于图片生成 |
| `image_generated` | 已有候选图 |
| `locked` | 已锁定候选图 |
| `needs_revision` | 需要重改 |

## 9. GenerationTask

所有 AI 和导出任务的统一记录。

```json
{
  "id": "task_001",
  "projectId": "project_001",
  "type": "image_generate",
  "status": "running",
  "targetType": "shot",
  "targetId": "shot_001",
  "inputJson": {},
  "outputJson": null,
  "errorJson": null,
  "attempt": 1,
  "createdAt": "2026-05-23T00:00:00.000Z",
  "startedAt": "2026-05-23T00:00:01.000Z",
  "finishedAt": null
}
```

任务类型见 `文档/02_架构与契约/生成任务协议.md`。

## 10. Candidate

候选结果，通常关联一个分镜和一个图片 Asset。

```json
{
  "id": "candidate_001",
  "projectId": "project_001",
  "shotId": "shot_001",
  "taskId": "task_001",
  "assetId": "asset_img_001",
  "index": 1,
  "status": "generated",
  "score": null,
  "notes": ""
}
```

| 状态 | 含义 |
| --- | --- |
| `generated` | 已生成 |
| `selected` | 当前选中 |
| `locked` | 锁定用于分镜 |
| `rejected` | 废弃 |
| `superseded` | 被替代 |

## 11. Asset

统一素材记录。

```json
{
  "id": "asset_img_001",
  "projectId": "project_001",
  "type": "image",
  "mimeType": "image/png",
  "path": "projects/project_001/assets/images/shot_001/candidate_001.png",
  "width": 1024,
  "height": 1536,
  "durationMs": null,
  "sourceTaskId": "task_001",
  "metadataJson": {}
}
```

| 类型 | 说明 |
| --- | --- |
| `image` | 漫画图、参考图、背景图 |
| `audio` | TTS、BGM、音效 |
| `video` | MP4、预览视频 |
| `document` | PDF、JSON、字幕、manifest |
| `archive` | 素材包 |

## 14. 对话框与项目上下文模型

对话框属于项目工作区公共能力，但数据上不采用“整个项目共用一条完整对话记录”。

### 14.1 ConversationThread

按项目步骤隔离的对话线程。

```json
{
  "id": "thread_001",
  "projectId": "project_001",
  "stepKey": "project_story",
  "title": "剧本对话",
  "status": "active",
  "createdAt": "2026-05-25T00:00:00.000Z",
  "updatedAt": "2026-05-25T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 对话线程 ID |
| `projectId` | string | 所属项目 |
| `stepKey` | enum | `project_story/story_structure/storyboard/image_candidates/layout_export/asset_package` |
| `title` | string | 线程显示名 |
| `status` | enum | `active/archived` |

唯一性建议：

```text
projectId + stepKey
```

MVP 阶段可以先保证每个项目步骤只有一条主线程，后续再扩展多线程或专题线程。

### 14.2 ConversationMessage

对话消息记录。

```json
{
  "id": "msg_001",
  "threadId": "thread_001",
  "projectId": "project_001",
  "stepKey": "project_story",
  "role": "assistant",
  "content": "我建议把第一幕冲突提前，让主角更早做出选择。",
  "model": {
    "providerId": "aurora",
    "modelId": "gpt-5.4"
  },
  "runtimeStatus": "completed",
  "sourceRefs": ["story_v001"],
  "proposedPatch": null,
  "applyState": "not_applied",
  "createdAt": "2026-05-25T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `threadId` | string | 所属对话线程 |
| `projectId` | string | 冗余项目 ID，便于查询 |
| `stepKey` | enum | 消息发生的项目步骤 |
| `role` | enum | `user/assistant/system/tool` |
| `content` | string | 消息内容 |
| `model` | object/null | assistant 消息使用的 `providerId/modelId` |
| `runtimeStatus` | enum | `running/completed/failed` |
| `sourceRefs` | string[] | 引用的项目文档、当前步骤产物或项目级已确认事实 |
| `proposedPatch` | object/null | AI 建议的可应用改动 |
| `applyState` | enum | `not_applied/applied/inserted/dismissed` |

规则：

- `not_applied` 消息只是聊天记录，不进入项目级事实。
- `applied` 或 `inserted` 表示用户已把内容写入当前步骤文档。
- 不提供跨步骤手动引用原始聊天消息；跨步骤来源只能来自项目级已确认事实、保存文档和锁定产物。

### 14.3 ProjectContextFact

项目级已确认事实，用于跨步骤共享上下文。

```json
{
  "id": "fact_001",
  "projectId": "project_001",
  "type": "character",
  "content": {
    "name": "林舟",
    "appearance": "黑发，短外套，神情克制"
  },
  "sourceType": "story_version",
  "sourceId": "story_v001",
  "status": "confirmed",
  "createdAt": "2026-05-25T00:00:00.000Z"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | enum | `story/character/world/style/structure/shot/layout/asset/custom` |
| `content` | object | 已确认事实内容 |
| `sourceType` | enum | 来源类型，如 `story_version/shot/candidate/layout_page/asset` |
| `sourceId` | string | 来源对象 ID |
| `status` | enum | `confirmed/superseded/archived` |

只有以下用户动作可以把内容提升为项目级事实：

- 应用到当前文档。
- 插入到光标处并保存。
- 保存草稿。
- 确认剧情结构。
- 锁定候选图。
- 导出或归档素材。

AI 上下文注入顺序建议：

```text
当前步骤系统提示词
  -> 项目级已确认事实
  -> 当前步骤主文档或产物
  -> 当前步骤对话记录
  -> 用户本轮输入
```

### 14.4 DialogueRuntimeSession

对话运行时映射。第一阶段采用 OpenCode 时，用于把 AI漫游业务线程映射到 OpenCode 内部 session。

```json
{
  "id": "runtime_session_001",
  "threadId": "thread_001",
  "projectId": "project_001",
  "stepKey": "project_story",
  "runtime": "opencode",
  "externalSessionId": "oc_session_001",
  "status": "active",
  "providerId": "aurora",
  "modelId": "gpt-5.5",
  "variant": "medium",
  "createdAt": "2026-05-25T00:00:00.000Z",
  "updatedAt": "2026-05-25T00:00:00.000Z"
}
```

规则：

- `DialogueRuntimeSession` 只负责运行时路由，不承载业务聊天内容。
- `ConversationThread`、`ConversationMessage` 和 `ProjectContextFact` 仍是 AI漫游对话与上下文事实源。
- OpenCode Session 不向前端直接暴露。
- OpenCode 原始事件必须由后端转换为 AI漫游标准 `dialogue.*` 事件。
- 如果未来替换运行时，只替换 `runtime/externalSessionId` 映射和 runtime adapter，不重写业务对话模型。

当前实现状态：

- 2026-05-26 已在 `packages/shared/src/dto.ts` 增加 `DialogueThread`、`DialogueMessageItem`、`SendDialogueMessageRequest`、`SendDialogueMessageResponse` 和 `AIRuntimeModelItem` DTO。
- 2026-05-26 已增加 `DialogueStreamEvent`，当前事件类型包含 `dialogue.message.created`、`dialogue.message.delta`、`dialogue.message.completed` 和 `dialogue.error`。
- 2026-05-26 后端首版使用进程内 `projectId + stepKey` 对话线程和 OpenCode session 映射，尚未落数据库。
- 2026-05-26 已支持同步发送和流式发送剧本步骤对话并记录 assistant 文本；`sourceRefs`、`proposedPatch`、`applyState` 和停止生成尚未实现。

## 15. 最小数据库实现建议

MVP 第一版可以先落以下表：

1. `Project`
2. `StoryVersion`
3. `Character`
4. `SceneLocation`
5. `Shot`
6. `GenerationTask`
7. `Candidate`
8. `Asset`
9. `LayoutPage`

`StoryBeat`、`PanelPlacement`、`VideoSegment` 可先以 JSON 字段嵌入，等查询需求明确后再拆表。

当对话框接入真实 AI 存储时，应增加：

1. `ConversationThread`
2. `ConversationMessage`
3. `ProjectContextFact`
4. `DialogueRuntimeSession`
