## 1. 目标

素材文件契约定义 workspace 中所有项目文件、生成素材、导出物和元数据的稳定位置。数据库保存关系，文件系统保存实体文件，两者必须能互相追溯。

## 2. Workspace 根路径

MVP 使用本地路径。当前阶段是内部使用，真实素材文件和项目元数据优先放在用户机器的本地 workspace 中；后端服务统一管理路径、写入文件和记录元数据，前端不能直接写本地物理路径。

```text
workspace/
  projects/
    {projectId}/
```

后端负责把逻辑路径解析为物理路径，前端不直接拼接本地绝对路径。后续如果需要团队共享、云同步或对象存储，只替换后端的 workspace / asset 适配层，不改变前端调用方式。

## 4. 文件路径规则

| 类型 | 路径 |
| --- | --- |
| 项目元数据 | `projects/{projectId}/project.json` |
| 项目工作流状态 | `projects/{projectId}/workflow.json` |
| 章节元数据 | `projects/{projectId}/chapters/{chapterSlug}/chapter.json` |
| 当前章节剧本 | `projects/{projectId}/chapters/{chapterSlug}/script.md` |
| 章节剧本版本 | `projects/{projectId}/chapters/{chapterSlug}/script.versions/{version}.md` |
| 结构化剧情 | `projects/{projectId}/chapters/{chapterSlug}/structure.json`，用户确认后写入；用户界面以可编辑结构表展示 |
| 待确认分镜预览 | `projects/{projectId}/chapters/{chapterSlug}/storyboard.pending.json`，AI 生成和用户确认前编辑时写入；确认后删除 |
| 分镜快照 | `projects/{projectId}/chapters/{chapterSlug}/storyboard.json` |
| 角色参考图 | `projects/{projectId}/assets/characters/{characterId}/visual-v{version}/preview.webp` 或 `final-reference.webp`；`preview.webp` 是自动生成的正面半身预览图，`final-reference.webp` 是确认预览后生成的角色定稿组合图 |
| 分镜候选图 | `projects/{projectId}/chapters/{chapterSlug}/candidates/{shotId}/{candidateId}.png` |
| 章节排版 | `projects/{projectId}/chapters/{chapterSlug}/layout/layout_page_{pageNumber}.json` |
| 章节导出 | `projects/{projectId}/chapters/{chapterSlug}/exports/` |
| 角色参考图 | `projects/{projectId}/assets/characters/{characterId}/{assetId}.png` |
| 场景参考图 | `projects/{projectId}/assets/scenes/{sceneId}/{assetId}.png` |
| TTS 音频 | `projects/{projectId}/assets/audio/tts/{shotId}_{assetId}.mp3` |
| 漫画页面 | `projects/{projectId}/exports/pages/page_{pageNumber}.png` |
| PDF 导出 | `projects/{projectId}/exports/pages/comic_{exportId}.pdf` |
| MP4 导出 | `projects/{projectId}/exports/video/{videoDraftId}.mp4` |
| 素材包 | `projects/{projectId}/exports/packages/{packageId}/` |
| 任务输入 | `projects/{projectId}/tasks/{taskId}.input.json` |
| 任务输出 | `projects/{projectId}/tasks/{taskId}.output.json` |
| 任务错误 | `projects/{projectId}/tasks/{taskId}.error.json` |

项目创建时只建立项目记录，至少写入：

```text
projects/{projectId}/project.json
projects/{projectId}/workflow.json
projects/{projectId}/chapters/chapter-001/chapter.json
projects/{projectId}/chapters/chapter-001/script.md
```

其中 `project.json` 在创建时至少保存项目名称、项目类型、当前章节和项目级元数据；`workflow.json` 保存当前章节对应的 7 步流程状态、下一步和证据路径。项目角色库是常驻资产入口，不是 workflow 线性门槛；进入候选图前的角色、场景和画风门槛由出图准备确认记录承载。故事标题、题材标签、漫画格式、画风方向和故事原文进入项目后，在第 1 步“剧本”保存。故事原文保存为独立文本文件，避免后续结构化、版本化和素材包导出时只能从内存或数据库反推。

在数据库持久化接入前，`project.json`、`workflow.json`、`chapters/{chapterSlug}/chapter.json` 和 `script.md` 同时承担本地恢复源职责。后端服务启动或首次访问项目接口时，应从 `workspace/projects/*` 恢复项目列表、当前章节、章节状态和当前章节剧本文本；`workflow.json` 可由章节状态重新推导并补写。

当前后端已在创建项目时写入默认章节目录。`projects/{projectId}/story/story_draft.source.txt` 旧路径已废弃，新项目不再创建、读取或写入；剧本文本只以章节目录下的 `script.md` 为事实源。

剧本草稿保存时，后端覆盖写入当前草稿文件：

```text
projects/{projectId}/project.json
projects/{projectId}/chapters/{chapterSlug}/chapter.json
projects/{projectId}/chapters/{chapterSlug}/script.md
```

`script.md` 是当前章节草稿入口。用户点击“完成本章”时，必须额外写入 `script.versions/{version}.md` 或等价版本记录，并把 `chapter.json` 中的状态推进到 `script_done`。

章节目录命名建议使用稳定 slug：

```text
chapter-001
chapter-002
chapter-003
```

章节显示名可以是“第 1 章”或用户自定义标题，但系统排序不能只依赖显示名。

## 5. Asset 记录与文件对应

每个可被 UI 引用、导出、复用或追溯的文件都应有 `Asset` 记录。

```json
{
  "id": "asset_img_001",
  "projectId": "project_001",
  "type": "image",
    "path": "projects/project_001/chapters/chapter-001/candidates/shot_001/candidate_001.png",
    "sourceTaskId": "task_001",
    "metadataJson": {
      "chapterId": "chapter_001",
      "shotId": "shot_001",
      "candidateId": "candidate_001"
  }
}
```

## 6. 版本策略

### 6.1 章节剧本版本

每次用户对章节剧本做大改或点击“完成本章”时，应创建章节剧本版本。

```text
chapters/chapter-001/script.versions/20260527_001.md
chapters/chapter-001/script.versions/20260527_002.md
```

### 6.2 故事版本

每次用户对章节结构化剧情做大改，应创建新的 `StoryVersion`。

```text
story_v001
story_v002
story_v003
```

### 6.3 分镜版本

MVP 当前分镜以章节目录文件为事实源：AI 生成或用户编辑待确认预览时写出 `storyboard.pending.json`；用户确认后写入正式 `storyboard.json` 并清除 pending 文件。后续如果需要保留历史版本，可在关键操作后写出快照：

```text
shots_v001.json
shots_v002.json
```

触发快照的动作：

- 首次生成分镜。
- 批量编辑分镜。
- 进入图片生成前。
- 导出漫画页前。

### 6.4 候选版本

候选不覆盖旧文件。重生成会产生新的 `Candidate` 和 `Asset`。

```text
shot_001/
  candidate_001.png
  candidate_002.png
  candidate_003.png
```

### 6.5 导出版本

每次导出产生新的 exportId。

```text
exports/pages/comic_export_20260523_001.pdf
exports/video/video_export_20260523_001.mp4
```

## 7. 锁定规则

- 一个 `Shot` 在同一时间最多有一个 `lockedCandidateId`。
- 被锁定候选不能被覆盖，只能解除锁定或用新候选替换锁定引用。
- 被废弃候选保留文件，除非用户执行清理。
- 导出默认只使用 locked 候选。

## 8. Manifest 格式

素材包必须包含 `manifest.json`。

```json
{
  "project": {
    "id": "project_001",
    "name": "月下旅人"
  },
  "export": {
    "id": "package_001",
    "createdAt": "2026-05-23T00:00:00.000Z",
    "type": "asset_package"
  },
  "stories": [],
  "shots": [],
  "assets": [
    {
      "assetId": "asset_img_001",
      "path": "assets/images/shot_001/candidate_001.png",
      "sourceTaskId": "task_001",
      "shotId": "shot_001",
      "candidateId": "candidate_001"
    }
  ]
}
```

## 9. 清理策略

MVP 不自动删除历史候选。项目删除属于用户显式确认后的破坏性操作，不归入自动清理。

| 清理类型 | 规则 |
| --- | --- |
| 项目删除 | 用户二次确认后删除 `workspace/projects/{projectId}`、项目记录和该项目关联任务记录 |
| 临时文件清理 | 删除失败任务的临时文件 |
| 废弃候选清理 | 用户确认后删除 rejected 候选 |
| 导出物清理 | 删除旧 export，但保留 manifest 记录 |
| 孤儿文件扫描 | 文件存在但无 Asset 记录时报告 |

## 10. 禁止事项

- 前端直接写物理路径。
- 覆盖已有候选图片。
- 导出物不写 manifest。
- 数据库存在 Asset 但文件缺失且无错误记录。
- 文件存在但无法追溯到项目或任务。
