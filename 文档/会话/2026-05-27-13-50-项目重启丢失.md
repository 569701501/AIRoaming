# finding

- 文档事实源说明当前尚未接数据库，项目创建和章节草稿先写本地 workspace；用户反馈的“重启后项目丢失”属于项目索引恢复缺口。
- 代码中 `ProjectsService` 原先只维护进程内 `Map<string, LocalProject>`；创建项目会写 `project.json`、`chapter.json` 和 `script.md`，但服务启动时没有从 `workspace/projects/*` 反向恢复。
- 复现结果：同一临时 workspace 中项目文件存在；重启服务后 `GET /api/projects` 返回空数组，`GET /api/projects/{projectId}/workbench` 返回 `PROJECT_NOT_FOUND`。
- 修复后，后端启动/首次访问会从 `project.json`、章节目录和 `script.versions` 恢复项目、当前章节、章节状态和章节正文。

# goal

定位并修复“创建项目后，服务重启或后续改动后再次进入项目时项目丢失”的问题。

验收标准：

- 能复现当前丢失行为，并说明根因。
- 服务重启后，项目库仍能列出已创建项目。
- 能通过项目详情或工作台接口继续进入项目。
- 修复符合当前文档事实源，不引入新的主事实源。

# approach

使用 `$grill-with-docs` 对齐“项目记录 / workspace 文件 / 持久化事实源”的边界；使用诊断流程建立接口级复现，再做最小修复和回归验证。
