# finding

- 用户反馈：第一次对话报错，第二次发送很慢；刷新页面再次进入时默认对话记录不显示，只显示初始空状态；再次发送后旧记录突然显示，并且第二次发送对应的 assistant 消息一直转圈。
- 该问题横跨前端对话线程加载、流式发送状态、后端对话线程内存状态和 abort/失败收敛，使用 `$deep-think` + diagnosis 流程处理。
- 前端原本并行读取 workbench 和 dialogueThread；无显式 `chapterId` 时会先读到项目级空线程，之后发送才进入章节线程。
- 后端原本在 SSE close 时只停止写响应，没有 abort OpenCode 请求，也没有在读取线程时收敛非活跃 `running` assistant。

# goal

修复对话框刷新后对话记录不恢复、再次发送后旧记录突然出现，以及失败/中断后的 assistant running 卡死问题。

# approach

先读对话线程加载、流式发送、后端消息状态写入代码，构造最小反馈环复现“running 消息持久存在/刷新不加载线程”的状态，再做收敛修复。优先不改业务生成能力，只修状态机和加载路径。
