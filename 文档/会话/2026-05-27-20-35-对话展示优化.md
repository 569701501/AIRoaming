# finding

- 用户反馈：AI 对话输出内容会持续撑开页面高度，希望参考 AuroraPlatformWeb 对思考、技能和工具调用的展示方式。
- 当前 `ProjectDialoguePanel.vue` 直接把 assistant `content` 放进消息气泡，`dialogueNotice` 单独显示工具结果摘要；消息列表虽有 `overflow-y: auto`，但外层工作台缺少可靠的 `min-height: 0` / viewport 高度约束时仍可能被长内容撑开。
- 当前前端没有结构化展示 `dialogue.tool_result.created`，也没有将 skill/tool/thinking 类内容折叠。
- AuroraPlatformWeb 的 `AgentChat/ChatStream.vue` 会把 reasoning 和 tools 从正文中拆出来，放进可折叠过程区；工具卡片使用紧凑行、状态图标、展开详情，消息容器使用 `min-h-0`、`overflow-auto` 和局部最大高度约束。
- 本次实现将 `DialogueThread.toolResults` 作为共享契约，后端记录工具结果，前端按 `messageId` 挂到 assistant 消息；对话正文、思考提示、技能/工具卡片分离展示。
- 用户新反馈：刷新后空态正常；发送“找灵感”后，技能卡片显示完成并输出 5 个方向，但后续 assistant 仍出现“思考 OpenCode 正在组织回复”或让用户感觉后面没反应。需要区分是 SSE 完成事件丢失、前端状态合并问题，还是“工具过程输出”和“最终回复”表达不清。
- 复现流式事件后确认第一轮技能调用事件顺序正常：`dialogue.message.created -> dialogue.tool_result.created -> dialogue.message.completed`，最终线程内 assistant 状态为 `completed`。更主要的问题是 UI 把有工具结果的 assistant 正文隐藏了，导致用户只能看到过程卡片输出，看不到最终回复。
- 用户再次反馈：最终回复虽然显示出来了，但仍和技能卡片处在同一个 assistant 气泡里，视觉上仍像“技能输出区域的一部分”。需要把过程卡片和最终回复拆成两个独立气泡。
- 用户继续反馈：独立正文气泡仍有内部滚动，像被折叠；最终回复正文应自然展开，滚动交给整个对话消息区。
