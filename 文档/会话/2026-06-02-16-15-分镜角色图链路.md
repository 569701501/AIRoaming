# finding

- 用户补充：当前已经在 `出图准备` 页面，核心疑问是出图准备里怎么生成角色图、为什么页面仍然让人找不到动作入口。
- 文档当前口径：主流程为 `剧本 -> 剧情结构 -> 分镜工作台 -> 出图准备 -> 候选图工作台 -> 排版导出 -> 素材包`；`项目角色库` 是常驻资产入口，不是线性主步骤。
- 分镜工作台只负责生成/确认当前章正式 `storyboard.json` / `Shot[]`；角色图的强门槛后移到 `出图准备`，用于阻塞候选图生成。
- 当前代码中，`ImagePreflightWorkspace` 提供 `角色库` 和 `去角色库处理` 入口，并检查待绑定角色、缺少定稿图、场景绑定和画风上下文。
- 当前代码中，`ImagePreflightWorkspace` 的 `本章角色参考` 只展示角色状态和 `缺少定稿图/生成中/参考图可用` 标签，缺少清晰的下一步处理路径。
- 当前角色库弹窗/工作区可生成角色图：缺预览时自动/手动生成 `preview_front`；用户确认预览后，`lead/recurring` 会补排 `final_reference`；用户确认定稿后才满足必需角色参考图门槛。
- 用户明确否定“把每个角色的生成/确认动作都塞进出图准备页”的方案，认为难用。需要重新设计：出图准备不应变成第二个角色库。
- 用户确认根流程：当前阶段必须继续按章节流水线走，先把人工可控的流水线跑通；后续再做调度中心，从剧本到候选图/排版全 AI 调度，人只在关键节点做决策。
- 用户认可角色库/主体库逻辑，但指出页面和样式经常让人困惑；本次调整目标不是改变底层流程，而是把出图准备改成“当前只需要做什么”的下一步导向，把角色图相关用户语言收口为“角色锁定”。
- 已改代码：`ImagePreflightWorkspace.vue` 顶部新增“当前只需要”动作卡，主按钮会根据真实阻塞项切换为处理出镜角色、锁定本章角色、查看场景问题、确认出图准备或进入候选图；指标和检查文案从“缺参考图/角色参考图”改为“待锁定角色/角色锁定”。
- 已改代码：`ProjectCharactersWorkspace.vue` 将用户文案从“角色预览图/确认预览/确认定稿”收口为“角色效果图/使用这版/角色定稿/锁定角色”，保留底层 `preview_front/final_reference` 数据契约不变。

# web_search

- 搜索主题：Seko / 商汤 Seko 的主体库、角色一致性、剧本到分镜/视频流程。
- 关键结论：Seko 的公开资料强调“主体库 / 角色锁定与复用 / 全流程故事生成”。用户先创建或选择“主体/演员”，之后通过 `@角色名` 指定角色出演；AI 自动提炼故事梗概、视觉风格、场景、音乐和分镜脚本，所有环节围绕已锁定角色展开。Seko 2.0 公开报道强调“多剧集记忆 + 全局一致性”，以及输入创意/剧本、选风格、导入角色后自动生成；角色一致性被包装为自动能力，不要求用户理解预览图/定稿图/出图准备等内部步骤。
- 重要来源：Seko 官网为 JS 应用，仅可确认其是 AI 视频生成平台；可读资料来自 AIGC 软件库、AIHub、AIbase、苏米客实测文章和新浪财经报道。
- 链接：`https://seko.sensetime.com/`、`https://seko.tchepai.com/`、`https://www.aihub.cn/tools/video/seko/`、`https://www.aibase.com/zh/news/23595`、`https://www.xmsumi.com/detail/2980`、`https://finance.sina.com.cn/roll/2025-12-15/doc-inhawpkf4079315.shtml`
