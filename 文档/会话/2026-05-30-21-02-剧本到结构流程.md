# finding

用户询问：生成第 1 章、第 2 章后，还需要用户点击切换到「剧情结构」，这个流程是否合理。

2026-05-31 后续更新：本会话中的“完成本章后进入本章剧情结构”是当时的 6 步流程结论，已被后续项目角色库决策替代。当前正式口径是：完成章节剧本后优先进入 `项目角色库`，主角和常驻角色定稿后，再进入该章剧情结构。

术语校准：这里的“生成剧情第一章第二章”按当前项目语言应称为“生成章节剧本”。「剧情结构」是下一阶段的结构表，不是章节剧本文字。

当前文档和代码一致点：

- 主流程是 `剧本 -> 剧情结构 -> 分镜工作台 -> 候选图工作台 -> 排版导出 -> 素材包`。
- `Chapter` 是主工作单元；剧本、剧情结构、分镜等后续产物都挂到 `chapterId`。
- AI 写入章节草稿的 `writeChapterDraftFromAI` 只更新 `sourceText/title/lastScriptRevision`，不会把章节推进为 `script_done`。
- 只有用户点击「完成本章」后，后端 `completeChapter` 才把章节标记为 `script_done`，并创建或切到下一章。
- workflow 当前按 `currentChapter.status` 推导：`draft -> project_story`，`script_done -> story_structure`，`structured -> storyboard`。
- 现状风险：完成第 1 章后系统会自动切到第 2 章草稿，此时当前章是 `draft`，顶部「剧情结构」会按当前章被禁用；用户需要切回已完成章节或另行进入结构页。

# web_search


# goal

判断“章节剧本生成后由用户点击切换到剧情结构”是否是合理产品流程，并识别当前实现中会造成困惑的点。

# approach

保留“AI 生成剧本后不能自动进入剧情结构”的人工确认门槛；但把“切换到剧情结构”做成完成本章后的显性下一步选择，而不是让用户自己理解顶部流程栏和当前章节状态。

# question

当时已确认：完成一章后，系统默认停留在刚完成章节，提示用户选择“进入本章剧情结构 / 继续下一章”。该主路径已被 2026-05-31 的项目角色库阶段替代，新推荐主路径是 `进入项目角色库`。

# result

用户当时确认采用推荐方案：项目按章流水线推进。完成本章后不自动跳到下一章；页面停留在刚完成章节，并展示 `进入本章剧情结构` 主动作和 `继续下一章` 次动作。

2026-05-31 覆盖结论：正式产品文档和长期记忆已改为 7 步流程。完成本章后主动作改为 `进入项目角色库`，项目角色库完成后再进入本章剧情结构；`继续下一章` 仍保留为次动作。

用户随后要求梳理刚实现/确认的剧情结构流程，用于复核产品链路是否符合预期。当前代码和文档一致：剧情结构按章节生成，`draft` 章不能生成，`script_done` 章生成待确认预览，确认后写入 `structure.json` 并推进到 `structured`。

用户指出截图里进入剧情结构后，左侧仍显示“AI 编剧助手”和“帮我找灵感/上传或粘贴剧本”的剧本阶段文案。排查结论：右侧工作区会按 `activeStepKey` 切换，但 `ProjectDialoguePanel` 标题、开场白、输入占位和附件入口是硬编码剧本语义，造成剧情结构页看起来像剧本页。

实现完成：

- 后端 `completeChapter` 仍创建下一章草稿，但 `activeChapter/currentChapterId` 保持为刚完成章节。
- 前端 `WorkbenchStore` 记录完成后的下一步行动提示，并将当前快照保留在完成章节。
- 剧本页在章节列表下方展示完成行动条；当前产品口径应为 `进入项目角色库` / `继续下一章`，角色库完成后再进入本章剧情结构。
- 左侧 `ProjectDialoguePanel` 已改为阶段感知：剧情结构页显示 `AI 剧情结构助手`、剧情结构开场白和结构调整占位文案，并隐藏上传剧本文本入口。
- 已同步核心用户流程、当前 UI 信息架构、核心数据模型、素材版本契约、剧本方案文档和 OpenCode 剧本 skill/agent 文档。
