# finding

- 相关产品口径：项目库支持项目卡片 hover 删除按钮，二次确认后调用 `DELETE /projects/{projectId}`，删除项目记录、本地 workspace 项目目录和该项目 mock 任务。
- 2026-06-02 复查确认：项目卡片原本已有封面删除按钮，底部 `MoreHorizontal` 不是删除入口；此前把底部按钮改成删除是错误 UI 改动，已撤回。
- 多出来的项目来自 Codex 临时验证项目，分别为 `preflight-guard-1780372627686`、`codex-delete-ui-check`、`codex-delete-original-button-check`，均已通过后端删除接口清理；当前 API 与 workspace 仅剩用户项目“测试 1”。
- 后端删除接口链路正常：`DELETE /api/projects/{projectId}` 会删除项目目录、项目索引和该项目任务。
- 前端薄弱点：删除成功后原先等待完整 `refresh()` 后才从项目列表消失；若刷新慢、失败或仍有旧 active project 状态，用户会感知为“点击删除没用”。现改为 DELETE 成功后先从本地项目列表移除，再刷新校准。
- 右上角封面删除按钮不弹窗的风险点：组件事件原名为泛用 `delete`，CSS 只在 `.project-cover-wrapper:hover` 时恢复 `pointer-events`。已改为明确的 `request-delete` 事件，并让右上角按钮常驻可点击，避免按钮看起来出现但点击事件没有稳定落到弹窗链路。
- 2026-06-02 继续诊断发现真正断点：`ProjectLibraryView.vue` 模板使用了 `DeleteProjectDialog`，但 `<script setup>` 未导入该组件，Vite 编译后走 `resolveComponent("DeleteProjectDialog")` 未注册组件路径；点击删除即使设置了 `projectPendingDelete`，页面也没有真实弹窗组件可渲染。
