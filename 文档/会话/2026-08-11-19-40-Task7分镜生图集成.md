```typescript
function resolveCharacterReferenceForChapter(

```

**优先级逻辑**：
1. 查找该章节对应的阶段（按 stageOrder 倒序，优先最新阶段）
   - 无 `fromChapterId` 的阶段只在 `stageOrder=1` 时适用所有章节
   - 有 `fromChapterId` 的阶段检查 `fromChapterId <= chapterId <= toChapterId`
2. 优先使用阶段图：`stage.finalAssetId > stage.previewAssetId`
3. 其次使用锚点图：`character.anchorAssetId`
4. 降级到原有逻辑：返回 `null`，由调用方处理

**返回值设计**：
- `{ assetId, useStageLogic: true }`：使用了阶段图或锚点图
- `null`：降级到原有逻辑

## 设计决策说明

### 为什么返回 `{ assetId, useStageLogic }` 而不是直接返回 `assetId`？

因为原有逻辑有 `previewConfirmedAt` 的业务检查，这是一个重要的"已确认"状态。如果直接返回 `assetId`，调用方无法区分：
- 这是阶段图/锚点图（不需要检查 `previewConfirmedAt`）
- 还是降级到原有逻辑（需要检查 `previewConfirmedAt`）

使用 `useStageLogic` 标志让调用方明确知道是否应该跳过原有检查。

### 为什么不直接使用 `primaryReferenceAssetId`？

设计文档虽然写了 `primary > preview`，但原有代码**只用** `preview`（且需要确认）。这说明：
1. `primaryReferenceAssetId` 可能是"四格定稿"之类的多人图，不适合单人分镜
2. `previewReferenceAssetId` 才是"单人预览图"，专门用于分镜生图

所以降级逻辑保持原有行为，不引入 `primaryReferenceAssetId`。
