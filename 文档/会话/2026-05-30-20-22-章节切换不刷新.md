# finding

用户反馈：切换章节时页面会整个刷新，体验不好。

代码发现：

- `apps/web/src/components/layout/AppShell.vue` 的路由 watcher 在章节路由变化时调用 `workbench.openProject(projectId, stepKey, chapterId)`。
- `apps/web/src/stores/workbench-store.ts` 的 `openProject()` 会先将 `snapshot = null`、`dialogueThread = null`，随后调用 `refresh()`。
- `AppShell.vue` 外层用 `v-if="isProjectRoute && snapshot"` 控制工作台显示；`snapshot` 被清空后会切到“正在打开项目...”加载页，因此章节切换表现为整个页面刷新。
- 该问题属于前端加载态策略问题，不需要修改后端章节状态、workspace 文件或剧情结构契约。

# goal

切换章节时保持项目工作台外壳、顶部流程栏、左右布局不卸载，只局部更新当前章节快照和对应对话线程。

# approach

保留 `openProject` 作为项目进入/路由同步入口，但增加“同项目上下文切换时保留 snapshot”的策略；章节切换期间可以显示局部 loading，但不能触发整页路由 loading。

# result

已在 `workbench-store.ts` 为 `openProject()` 增加 `preserveSnapshot` 选项，并在 `AppShell.vue` 的同项目路由同步/非剧本步骤切章中启用。这样切换章节时不会先把 `snapshot` 置空，外层 `ProjectWorkbenchView` 不会卸载，也就不会出现整页“正在打开项目...”。

验证：

- `pnpm -r typecheck` 通过。
- `pnpm -r build` 通过，保留 Vite 大 chunk 既有警告。
- 通过 Chrome 当前页面确认工作台仍保持在项目工作区；受限于 Computer Use 对当前 Chrome 的地址栏/下拉交互不稳定，本轮未完成可靠的真实点击切章录屏式验证，核心行为以代码路径和构建验证为准。
