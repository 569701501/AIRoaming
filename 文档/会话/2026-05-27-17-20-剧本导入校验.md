# finding

- 当前“用户提供剧本整理”入口在 `DialogueService.tryImportScriptToChapters` 命中后会直接调用 `ProjectsService.importScriptToChapters` 写入章节文件。
- `ProjectsService.parseProvidedScriptChapters` 目前按 Markdown 标题或 `第...章/节/回/话/幕` 拆章；Markdown 标题内容如果只是 `1`、`2`、`3` 也会被当作章节标题。
- 当前链路缺少“导入前识别/校验”：没有先判断上传内容是否真的是可整理剧本，也没有在格式不可信时阻止写入。

# web_search


# goal

评估上传剧本导入的第一步设计：避免把非剧本文档误导入章节，明确是否需要 AI 先分析内容、校验格式，再决定是否拆章写入。

# approach

建议把“分析/校验”和“写入章节”拆成两个阶段：先由 AI/规则判断内容是否像剧本、章节边界是否可信；只有通过校验后才调用写入工具。格式不对时不写文件，直接在对话框告知用户问题和可修正方式。

# question

- 是否允许 AI 在“有剧本内容但没有明确章节标记”时自动按剧情节拍拆章，还是第一版先要求用户提供 `1/2/3` 或 `第 N 章` 这类明确边界？

# result

- 已确认设计问题：当前导入链路把“切分章节”和“判断是否可导入”混在一起，导致非剧本或格式不可信内容也可能被写入章节目录。
- 建议第一步补“导入前分析/校验”：AI/规则先判断内容类型和章节边界可信度；失败时只返回对话提示，不写 `chapters/*/script.md`。
