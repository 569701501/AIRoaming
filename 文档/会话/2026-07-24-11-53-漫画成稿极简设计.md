# finding

- 当前正式链路已经具备 `LayoutDocumentV2`、Working Copy、Pending Command、Revision、Publication、来源 freshness 与确定性渲染，底层功能完整。
- `LayoutExportWorkspace.vue` 约 3972 行，同时承载编辑器、智能重排、两级对比预览、来源返修、预检、版本历史和出版任务，普通用户主路径被技术流程淹没。
- 当前 UI 暴露整章/选区/当前页段/当前场景、四种智能意图、缩略对比与完整对比、两次预检和四步发布；其中多项是同一业务意图的重复表达。
- 正式对白完整性只在 V2 Revision/Publication preflight 强制，错误 Working Copy 仍可被只读预览展示；指定测试成稿因此出现 16 条正式对白全部未绑定、唯一气泡无来源的情况。
- 需要保留的核心不是所有现有入口，而是来源事实完整、可编辑文档、人工修改保护、可追溯版本和确定性出版。
- 独立复核发现现有 reflow 无法补建 binding；最终方案增加受限 V2 内容 reconciliation 命令、自定义文字 confirm 命令、opaque draft token，并把 readiness 切换顺序改为 shadow 后分入口 fail-closed。

# goal

设计漫画成稿的最小正确闭环：保持现有关键能力，删除或合并不必要的界面、模式和中间概念，使普通用户只需“得到正确成稿 → 少量调整 → 确认发布”。

# approach

- 使用删除测试区分业务不变量、内部实现和可删除 UI。
- 并行设计三种最小接口，再按正确性、操作步数、兼容成本和可实施性比较。
- 最终选择“兼容 Facade + 内容就绪前置”：普通用户只见 `open/change/release` 对应的一条主路径；底层安全合同全部内收。
- 本轮只形成正式方案与删减清单，不修改生产代码或测试数据。

# result

已完成设计收口：

- 普通路径收敛为“打开/恢复 → 编辑或整理 → 预览并导出 → 确认 → 下载”。
- 新增内容就绪设计，正式对白/旁白和未分类叙事文字在 Working Copy 阶段即可暴露。
- 设计受限、可撤销的内容 reconciliation 与显式自定义确认，避免旧错误稿被阻断后无法修复。
- `open/change/release` 通过 opaque `draftToken` 内收 autosave、CAS、Pending、双预检、Revision 和 Publication。
- 明确删除 AI Drawer、MiniPreview、mode/intent、M6 四步及重复技术入口；手调、安全和追溯能力保留。
- 第二轮独立静态复核通过：S0=0、S1=0。
- 未修改生产代码、数据库或测试成稿。
