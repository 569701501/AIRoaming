# finding

- 文档已确认：剧本阶段 AI 可以通过 AI漫游受控工具/API 更新章节草稿，但不能直接操作本地物理路径或绕过章节契约；普通聊天内容未写入章节、保存、锁定或确认为项目事实前，不能自动进入后续步骤上下文。
- `apps/server/opencodeAI` 已存在剧本协作 agent 和 4 个 skill：`script-import-normalize`、`script-inspiration-seeding`、`script-chapter-drafting`、`script-chapter-editing`。
- `apps/server/opencodeAI/AGENTS.md.tpl` 已有基础运行时规则，但当前文档注明 OpenCode AI 资产目录“尚未接运行时模板复制”；真实普通对话主要依赖 `DialogueService.buildPrompt` 拼出的 prompt。
- `DialogueService.buildPrompt` 当前边界偏粗：只写了普通聊天给建议、导入/长剧本走受控工具、不声称直接操作本地文件、中文回复。它没有细分“可直接写入 / 必须先确认 / 只能建议 / 禁止触碰”的剧本阶段行为矩阵。
- 灵感、起草、改写三条链路已在后端通过专用 prompt 调用 OpenCode；这些 prompt 有各自硬性规则，但边界分散在多个函数和 skill 文件里。
- 代码事实显示：用户说“帮我找灵感”会触发 `generate_inspiration_seeds`，选方向后 `generate_script_from_seed` 写当前章节；用户要求改写当前章节且当前有正文时，会触发 `update_chapter_draft`。导入已有剧本则先走 `analyze_script_import`，通过或确认后再写章节。
- 用户指出“技能的格式不对”后复查：`script-chapter-drafting`、`script-chapter-editing`、`script-inspiration-seeding` 缺少 `SKILL.md` 文件头部 YAML frontmatter；历史会话记录和本地参考 skill 都显示 OpenCode skill 应以 `name`、`description` frontmatter 开头，正文再写详细流程。
