# finding

- 当前 Grok 文生图请求在 `ImageProviderService` 中把 `resolution` 硬编码为 `2k`；Grok 单图编辑和多图编辑未显式传分辨率，无法保证测试成本策略一致。
- 候选图任务冻结的 `requestedSize` 主要表达宽高比和版式，不能替代 Grok 独立的 `resolution=1k|2k` 参数。
- OpenAI 使用 `size/quality`，豆包使用像素 `size`；三家参数语义不同，不适合增加一个表面统一的数据库字段。

# web_search

- xAI 官方图片生成文档：支持 `resolution=1k|2k`；`grok-imagine-image-quality` 官方价格为 1K 每张 0.05 美元、2K 每张 0.07 美元。
- OpenAI 官方图片接口使用 `size=1024x1024|1024x1536|1536x1024|auto` 与 `quality`，不是 Grok 的 1K/2K 参数。
- 火山引擎官方文档使用 `size` 或宽高像素控制分辨率，参数语义也不同。
- 重要来源：`https://docs.x.ai/developers/model-capabilities/images/generation`、`https://docs.x.ai/developers/pricing`、OpenAI Image API Reference、火山引擎 ImageGenerations API 文档。

# goal

把 Grok 图片生成默认成本档统一降为 1K，并保留显式 2K 运行配置；不发起任何真实付费图片请求。

# approach

- 只在 Grok provider 边界实现 `1k|2k` 策略，默认 1K。
- 文生图、单图编辑、多图编辑全部显式发送同一分辨率。
- 使用环境变量 `GROK_IMAGE_RESOLUTION` 切换；非法值在联网前失败。
- 不新增数据库字段或设置页假统一开关。
