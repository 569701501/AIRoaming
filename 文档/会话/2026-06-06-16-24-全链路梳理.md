# finding

- 现有文档和代码都将主流程收口为 7 步：`剧本 -> 剧情结构 -> 分镜工作台 -> 出图准备 -> 候选图工作台 -> 排版导出 -> 素材包`。
- 代码中的 `PROJECT_WORKFLOW_STEP_KEYS` 不包含 `project_characters`，说明项目角色库已经不是顶部线性主流程步骤。
- `/projects/:projectId/characters` 路由仍存在，但文档定义为项目级常驻资产入口或深度维护入口，不应作为用户从头到尾必须点击的一步。
- 当前最容易让用户困惑的点是把“项目级资产链路”和“章节级生产流水线”混成一条线：角色库应在剧本大纲、剧情结构、分镜、出图准备中自动增量工作，而不是强制用户在某个步骤中断主线。
- 文档已明确推荐按章流水线：完成第 1 章剧本后，优先进入第 1 章剧情结构；不要求整部作品所有章节剧本都先写完。
- 现有文档定义：项目角色库优先从已确认剧本大纲的“主要角色”创建主角和常驻角色草稿，所有入库角色默认生成 `preview_front`，主角/常驻角色确认预览后必须生成 `final_reference`，这些参考图在出图准备阶段成为候选图门槛。
- 现有代码差异：`confirmScriptOutline` 当前只确认剧本大纲，未自动调用 `extractProjectCharacters`；项目角色提取主要在 `project_characters` 步骤或显式 API 中触发。这与“主角和常驻角色一开始自动准备”的产品口径存在实现缺口。
- 用户确认：主角和常驻角色需要在剧本大纲确认后自动生成角色图，但用户必须能看到角色名、角色图和角色相关信息；角色名是身份标识，普通图片生成弹窗不能修改角色名。弹窗里的描述是给 AI 生图的形象描述 / prompt，用于重生成或应用当前图。
- 当前前端角色库能展示角色列表、描述、效果图、定稿图、图片放大、确认预览和锁定定稿；但 `ProjectCharactersWorkspace.vue` 当前没有字段级编辑角色信息的入口，需要补齐。
- 新澄清：用户认可主流程不变，真正麻烦的是每章都可能出现新角色，而主角/常驻角色必须复用旧定稿图；因此需要把“角色图片生成”设计成自动资产准备线，用户只在核心角色首次定型和章节出图前处理必要角色，而不是每章被迫进入一套完整角色库流程。
- 用户进一步澄清：本章新增角色的图片生成必须先经过用户确认；当前需要重点设计的是这些新增角色在页面中如何自然展示、如何让用户确认生成、合并、临时处理或忽略，而不是改变主流程。
- 用户修正交互口径：不能让用户操作太多。角色图相关的主操作应简化为“看生成图、确认使用、不满意重新生成、需要时修改描述”。加入角色库、合并、临时、忽略等应成为系统自动判断或高级/异常处理，不应作为普通用户的主操作集合。
- 用户提供 Seko 参考流程：左侧对话推进“策划剧本大纲/细化剧情内容”，右侧是持续更新的策划文档，包含剧本内容、美术风格、主体列表/主体图、场景列表/场景图、分镜剧本。Seko 的体验重点是把角色图、场景图和分镜生成包装在同一个内容文档中，用户通过主体卡片编辑描述、重生成或转三视图，而不是跳进独立角色库流程。
- 对 AI漫游的启发：角色/场景图片可以在当前步骤右侧文档中以内嵌卡片展示，角色库仍是底层事实源，但普通用户不需要感知为单独步骤；出图准备只汇总“哪些图还没确认”，不应让用户手动处理底层归类。
- 用户提出新方向：角色库必须作为全项目所有角色的固定事实源存在；剧情结构页面已有本章角色列表，可以在角色列表下面增加角色图列表，让用户在剧情结构阶段就看到主角/常驻/本章新增角色的图状态和审核入口。
- 代码现状：`StoryStructureWorkspace.vue` 当前只展示 `structureJson.characters` 的文字角色卡（职能、动机、关系、视觉特征），没有角色图列表；项目级 `snapshot.characters/assets` 已存在，可作为角色图列表的数据来源。
- 用户提供主体图列表参考并修正口径：生成出的角色/主体图应在右侧内容区以图片列表自动展示；卡片默认只显示图片和角色名，鼠标悬停后显示删除和编辑图标。点击删除弹二次确认；点击编辑打开“角色图片生成”弹窗，弹窗左侧显示当前图，右侧角色名只读，只能编辑给 AI 生图用的形象描述 / prompt，并提供取消/应用。
- UI 决策倾向：角色图审核不做成复杂状态表，普通态就是图卡列表；用户核心操作是 hover 后编辑、删除，进入编辑弹窗后改描述并重新生成/应用。
- 用户确认：角色图卡片点击删除时，只删除当前图片版本，不删除角色/主体本身。角色仍保留在项目角色库、本章剧情结构和后续分镜引用中；删除角色本身应作为更高级的独立操作。
- 用户确认：重新生成角色图片时，界面直接替换当前卡片展示图，不在普通 UI 中展示多个图片版本供选择。
- 文档冲突审查发现并修正：旧方案文档、模块梳理、UI 信息架构和完成记录中仍有“角色库可编辑角色名”“项目角色库作为主流程门槛”“完成本章后进入项目角色库”等旧口径。当前已统一为：角色库是常驻资产入口；角色名是项目内身份标识，普通图片生成弹窗只读；图片弹窗只编辑 AI 生图描述 / prompt；出图准备是候选图前置门槛。
- 代码对照发现的实现缺口：`StoryStructureWorkspace.vue` 当前只有本章文字角色卡，没有本章角色图列表；`ProjectCharactersWorkspace.vue` 仍偏完整角色库页，不是轻量图卡列表和图片生成弹窗；`ImagePreflightWorkspace.vue` 当前仍显式展示加入/合并/临时/忽略等底层动作，后续应收敛为高级/异常处理。
- 本轮代码已补齐前两个实现缺口：新增 `CharacterImageList.vue` 统一图卡、编辑弹窗、删除确认和图片预览；`StoryStructureWorkspace.vue` 在角色结构卡后展示本章匹配到项目角色库的角色图列表；`ProjectCharactersWorkspace.vue` 已改成“角色描述 + 图片列表”的轻量角色库视图。
- 后端新增删除当前角色图版本接口，删除只移除 `Asset` 引用和对应文件，不删除 `ProjectCharacter`；如果角色定稿图已经处于 `in_use` 状态则拒绝删除/替换，避免污染后续候选图。
