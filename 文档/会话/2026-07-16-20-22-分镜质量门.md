# finding

- 当前正式用户分镜生成入口是 `StoryboardDialogueService.generateStoryboardWithAI`：第一次模型输出经 `parseStoryboardJson` 兼容归一化，再做 beat/scene/character 引用映射，随后写入 pending。
- 当前归一化会把非法或缺失枚举兜底为默认值、缺失文本兜底为空字符串、缺失 order 兜底为数组顺序；这适合读取历史数据，但会掩盖新的 AI 生产错误。
- `resolveStoryboardReferences` 已检查 beat、scene、character 引用存在性，但尚未检查全部 beat 覆盖、beat 叙事顺序、beat 与 scene 一致、空壳字段、重复镜头、comic/motion 对话一致和 `promptDraft` 污染。
- 剧情结构阶段已经有成熟的“严格解析/固定质量门失败共用一次修复预算，第二次失败不写 pending”实现，可复用同一编排模式。

# web_search

- 本轮是既有正式方案 S2 的实现，不需要新增外部资料搜索。

# goal

在不改变页面字段、数据库 Schema、Storyboard payload 和用户确认流程的前提下，为首次生成与调整 pending 分镜增加高确定性固定质量门；第一次格式、引用或质量失败时只定向修复一次，第二次仍失败则不创建或替换 pending。

# approach

- 历史读取继续使用兼容 normalize；AI 新输出在 normalize 前增加严格输出契约。
- 新建纯函数质量门，检查 coverage、order、required、duplicate、beat/scene、comic/motion 和 `promptDraft`。
- `StoryboardDialogueService` 统一执行“首次输出 → 严格解析/质量/引用 → 一次修复 → 再校验”。
- 使用固定单元样例、Service 负例和新项目 fake-runtime 浏览器路径验证。
