## 核心改动汇总

### 1. 数据模型（Prisma）
**新增表**：`character_stages`
- `id` / `projectId` / `characterId` / `stageOrder` / `name` / `fromChapterId` / `toChapterId` / `visualDelta` / `previewAssetId` / `finalAssetId`
- 唯一约束：`(characterId, stageOrder)`

**修改表**：`characters`
- 新增字段：`anchorAssetId`（定妆照/锚点图，nullable，向后兼容）

### 2. DTO 类型（`packages/shared/src/dto.ts`）
- `CharacterStage`：阶段完整类型
- `CreateCharacterStageRequest`：创建阶段请求（name? / fromChapterId? / visualDelta 必填）
- `GenerateAnchorCandidatesRequest`：生成定妆候选请求（count? 默认 3 / customPrompt?）
- `ConfirmAnchorRequest`：确认定妆请求（assetId 必填）
- `ProjectCharacter` 新增：`anchorAssetId?: string`

### 3. 核心服务（CharacterStageService）
**5 个公共方法**：
- `createCharacterStage(projectId, characterId, input)`：创建阶段 + 生成预览垫图
- `getCharacterStages(projectId, characterId)`：获取角色所有阶段
- `updateCharacterStage(projectId, characterId, stageId, input)`：更新阶段
- `deleteCharacterStage(projectId, characterId, stageId)`：删除阶段 + 回收资产
- `regenerateStagePreview(projectId, characterId, stageId)`：重新生成预览

**参考图优先级**：
- 创建阶段：上一阶段 finalAssetId > 上一阶段 previewAssetId > anchorAssetId > primaryReference > previewReference
- 重新生成：本阶段 finalAssetId > 上一阶段链

**垫图机制**：
- 使用 `ImageProviderService.editImage`
- prompt = 角色名 + visualDelta + "保持面部特征、发型和整体气质一致" + 项目画风指南
- 资产路径：`projects/{pid}/assets/characters/{cid}/stages/{sid}/preview.webp`
- 资产 role：`character_stage_preview`

### 4. 定妆接口（CharacterReferenceService）
**2 个新方法**：
- `generateAnchorCandidates(projectId, characterId, input)`：并发生成 3 张候选图（不同 seed）
- `confirmAnchor(projectId, characterId, assetId)`：保存选中的 assetId 到 `Character.anchorAssetId`

**候选资产特点**：
- meta：`kind=anchor_candidate` + `characterId` + `seed`
- **不进** `referenceAssetIds`（`normalizeCharacterReferenceKind` 归一为 none）
- 每张 seed = `Date.now() + index`，互不相同，透传给 Runware

### 5. 参考图提示词改造（reference-prompt.util.ts）
**buildCharacterReferencePrompt 新增第 6 参数**：`hasReferenceImage = false`
- `hasReferenceImage=true`：APPEARANCE = "参考所提供的角色图片，保持面部特征、发型和整体气质一致"
- `hasReferenceImage=true` 且有 `character.appearance`：ADDITIONAL_NOTES = "补充细节：" + appearance
- `hasReferenceImage=false`：保持原有行为

**6 个模板全部更新**：`{{ADDITIONAL_NOTES}}` 变量行（性格气质与 promptFragment 之间）

### 6. 分镜生图集成（candidate-generation-spec.ts）
**新增辅助函数**：`resolveCharacterReferenceForChapter(character, chapterId)`
- 查找该章节对应的阶段（按 stageOrder 倒序）
- 优先级：`stage.finalAssetId > stage.previewAssetId > character.anchorAssetId`
- 降级到原有逻辑时返回 `null`

**createCandidateGenerationSpec 修改**：
- 有阶段图/锚点图：直接使用，跳过 `previewConfirmedAt` 检查
- 无阶段图/锚点图：降级到原有逻辑（保持 `previewConfirmedAt` 检查）

### 7. API 路由（projects.controller.ts + projects.service.ts）
**5 个端点**：
- `POST /api/projects/:projectId/characters/:characterId/stages`：创建阶段
- `GET /api/projects/:projectId/characters/:characterId/stages`：列出阶段
- `PATCH /api/projects/:projectId/characters/:characterId/stages/:stageId`：更新阶段
- `DELETE /api/projects/:projectId/characters/:characterId/stages/:stageId`：删除阶段
- `POST /api/projects/:projectId/characters/:characterId/stages/:stageId/regenerate`：重新生成预览

**2 个定妆端点**：
- `POST /api/projects/:projectId/characters/:characterId/anchor-candidates`：生成定妆候选
- `POST /api/projects/:projectId/characters/:characterId/confirm-anchor`：确认定妆

## 执行过程中的问题与解决

### 1. Pi 连续失败（Task 6-7）
**问题**：Pi 在 Task 6 执行时持续失败（3 次），无输出。

**解决**：父代理接管 Task 6 和 Task 7，手动实现。

**原因分析**：
- Task 6 发现路由已存在，只需修复方法名，任务复杂度低于预期
- Task 7 涉及现有代码的精细修改（向后兼容），Pi 可能无法准确把握业务逻辑

### 2. 测试失败（candidate-generation-spec）
**问题**：初次实现 Task 7 后，测试失败，选择了 `primaryReferenceAssetId` 而不是 `previewReferenceAssetId`。

**解决**：分析原有逻辑，发现必须保持 `previewConfirmedAt` 检查，修改为"有阶段/锚点时才改变行为，否则降级到原有逻辑"。

**收获**：向后兼容不仅是数据结构，还包括业务逻辑的行为一致性。

### 3. 方法名不一致（Task 6）
**问题**：`projects.controller.ts` 调用的方法名与 `projects.service.ts` 定义的方法名不一致。

**原因**：之前的任务（可能是 Task 3-4 阶段）已经实现了路由，但没有对齐方法名。

**解决**：修正 controller 调用的方法名。

## 已知限制与后续建议

### 1. 候选资产清理
**现状**：未选中的定妆候选资产长期保留在项目中。

**建议**：
- 定时清理：创建时间超过 7 天且未被 `anchorAssetId` 引用的候选
- 或在确认定妆时删除其他候选

### 2. Seed 透传限制
**现状**：只有 Runware 透传 seed，其他 provider（OpenAI/Doubao/Grok）不透传。

**影响**：候选差异依赖 provider 随机采样，无法保证完全可控。

**建议**：后续扩展各 provider 的 seed 参数支持。

### 3. 前端 UI 未实现
**现状**：后端接口已全部就绪，但前端 UI 未接入。

**待完成**：

- 分镜生图：显示使用的参考图来源（阶段图/锚点图/角色图）

### 4. 集成测试缺失
**建议**：创建端到端测试：
