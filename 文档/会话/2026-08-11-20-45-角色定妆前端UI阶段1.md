# 角色定妆与阶段管理前端 UI（阶段1：定妆功能）

## finding

- 后端 7 个接口已实现并验证：`POST anchor-candidates` → `{ candidates: WorkbenchAsset[] }`；`POST confirm-anchor` → `{ character: ProjectCharacter }`；stages CRUD → `{ stage }` / `{ stages }` / `{ success: true }`；`regenerate` → `{ stage, previewAsset }`。
- DTO 已在 `packages/shared/src/dto.ts`（CharacterStage / GenerateAnchorCandidatesRequest / ConfirmAnchorRequest / ProjectCharacter.anchorAssetId），无需新增类型。
- 前端架构约定：workspaces 组件通过 `defineEmits` 把变更事件上抛 → `ProjectWorkbenchView` 透传 → `AppShell` 调用 `workbench-store`（store 持有 snapshot 并负责 applyProjectCharactersUpdate / dialogueNotice / error / loading）。局部生成类操作（如候选图）组件直接调用 `api` 并持有本地 loading/error（ImageCandidatesWorkspace 先例）。
- 弹窗样式基线：DeleteProjectDialog.vue（Teleport + backdrop blur + 面板渐变），z-index 层级：角色库弹窗 70、预览大图 90、新定妆弹窗 95。
- ProjectCharactersWorkspace 有 readonly 模式（ProjectCharactersModal 角色库弹窗内嵌），定妆操作按钮只在非 readonly 显示。
- 待定妆判定：`!character.anchorAssetId && !isPureVoice(character)`（纯声音角色不需要视觉素材）。

## 决策

- 定妆弹窗生成候选与确认定妆都直接调 api（本地 loading/error，错误内联显示），确认成功后通过事件链把 character 传给 store 仅做 snapshot 补丁（store confirmAnchor 第三参数 character 可缺省，缺省时兜底调 API）——避免双请求且错误提示友好。
- 候选图默认 count=3；未做 customPrompt 输入框（阶段1 按验收标准最小实现）。
- 定妆照槽位只显示 anchorAssetId 资产；anchorAssetId 有值但资产不在池中时显示「暂不可用」。
