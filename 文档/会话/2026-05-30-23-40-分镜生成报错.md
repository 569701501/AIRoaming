# finding

- 用户在分镜工作台点击“生成当前章节分镜”后，左侧对话显示 `storyboard-shot-generate` 工具失败，最终回复为 `This operation was aborted`，本次没有写入 `storyboard.json`。
- 读取对话线程确认：失败发生在 `2026-05-30T15:34:15.673Z` 到 `2026-05-30T15:38:15.743Z`，总计约 240 秒。
- 代码确认：`OpenCodeRuntimeService.postMessage` 旧默认 `OPENCODE_MESSAGE_TIMEOUT_MS` 为 120 秒，`withReadyRetry` 会对任意 OpenCode 请求失败重试一次；因此真实表现是 120 秒超时后自动重试，再 120 秒超时，最终以 `This operation was aborted` 暴露给用户。
- 分镜 prompt 旧实现同时塞入完整 `structure.json` 和完整章节剧本；用户第 3 章结构约 11KB、章节剧本约 12KB，分镜生成输出又包含漫画和漫剧两组字段，属于长生成场景。

# goal

定位并修复分镜生成被 abort 的原因；验收标准是分镜生成失败不再被误判/误报，成功时能生成待确认预览或明确给出真实失败原因。

# approach

按诊断流程先建立反馈环：读取运行日志、复现分镜对话请求、检查 `DialogueService` 分镜路径和 OpenCode abort/timeout 逻辑。已排除章节/结构缺失和 `storyboard.json` 写入失败；根因是 OpenCode 长生成超时被误报为 abort。

修复方案：

- OpenCode 普通消息默认超时从 120 秒调整为 300 秒。
- 超时和外部 Abort 不再进入 `withReadyRetry` 的自动重试，避免用户等待两轮后才失败。
- `requestJson` 区分 timeout、页面刷新/连接断开和普通请求失败，返回可读错误文案。
- 分镜 prompt 以 `structure.json` 为正式拆分事实源，章节剧本只保留 6000 字摘录作为对白/动作参考，并提示按 beat 生成约 `beatCount` 到 `beatCount * 2` 个 Shot。
