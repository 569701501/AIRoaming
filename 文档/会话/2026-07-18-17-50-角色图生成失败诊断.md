# finding

- 用户在 DB-only 项目“测试”中触发角色图生成后，系统创建了 10 个 `character_reference_generate` 任务；10 个任务均失败，共执行 30 次本地 attempt。
- 30 次 attempt 的确定性错误全部为 `TASK_PROVIDER_FAILED / IMAGE_PROVIDER_NOT_CONFIGURED`，失败发生在 `ImageProviderService.resolveProviderConfig()`，早于任何图片 Provider HTTP 请求，因此没有产生图片调用费用。
- 当前设置选择 `activeImageProvider=grok`，模型为 `grok-imagine-image-quality`，中转地址为 `https://sub.lydcloud.uk/v1`，但公开设置显示 `configured=false`。
- 当前 DB 中 3 个图片 `CredentialMetadata` 均为 `status=unconfigured`、`configured=0`、`secret_ref=NULL`、`fingerprint=NULL`；因此 `SettingsService` 不会从 Keychain 恢复运行时图片密钥。
- 迁移前备份中的 OpenAI/豆包/Grok 图片设置均有 `secretRef + keyFingerprint`。当前 macOS Keychain 中 Grok 条目仍存在，去除结尾换行后的摘要与迁移前 Grok fingerprint `sha256:084625...62ed0` 完全一致。
- 根因位于本次 file → DB-only 迁移的 provider 凭据元数据接线：`ProviderShadowImporter` 明确只导入脱敏 provider 元数据，并把所有 CredentialMetadata 建为 unconfigured；正式 cutover 虽验证了 3 个 Keychain 凭据，但没有把已验证的 `secretRef/fingerprint/configured` 绑定回目标 DB。
