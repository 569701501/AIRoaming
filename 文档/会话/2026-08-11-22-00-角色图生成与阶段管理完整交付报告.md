## 功能概述

### 核心功能
1. **交互式定妆**：生成 3 张候选图（不同 seed），用户选择 1 张作为角色定妆照
2. **阶段管理**：按章节顺序管理角色形象变化阶段（如"凡人期"→"筑基期"）
3. **分镜生图集成**：生成分镜时自动匹配章节对应阶段的预览图

### 技术亮点
- **图为王**："图锁脸、文字换装"，editImage 垫图保脸
- **visualDelta**：只存储阶段间差异（如"改穿金袍、蓄短须"），不存完整描述
- **参考图优先级链**：stage.final > stage.preview > anchorAssetId > primary > preview
- **向后兼容**：无阶段/锚点的角色分镜生图行为完全不变

## 执行过程中的问题与解决

### 1. Pi 连续失败（后端 Task 6-7）
**问题**：Pi 在 Task 6 执行时持续失败（3 次），无输出。

**解决**：父代理接管 Task 6 和 Task 7，手动实现。

**原因分析**：
- Task 6 发现路由已存在，只需修复方法名，任务复杂度低于预期
- Task 7 涉及现有代码的精细修改（向后兼容），Pi 可能无法准确把握业务逻辑

### 2. 测试失败（candidate-generation-spec）
**问题**：初次实现 Task 7 后，测试失败，选择了 `primaryReferenceAssetId` 而不是 `previewReferenceAssetId`。

**解决**：分析原有逻辑，发现必须保持 `previewConfirmedAt` 检查，修改为"有阶段/锚点时才改变行为，否则降级到原有逻辑"。

**收获**：向后兼容不仅是数据结构，还包括业务逻辑的行为一致性。

### 3. 方法名不一致（后端 Task 6）
**问题**：`projects.controller.ts` 调用的方法名与 `projects.service.ts` 定义的方法名不一致。

**原因**：之前的任务（可能是 Task 3-4 阶段）已经实现了路由，但没有对齐方法名。

**解决**：修正 controller 调用的方法名。

### 4. api.ts 类型与后端不一致（前端阶段2）
**问题**：`createCharacterStage` 声明的响应类型缺 `previewAsset`，而后端 controller/service 实际返回 `{ stage, previewAsset }`，vue-tsc 报错。

**解决**：按真实契约修正类型声明。

### 5. Vite 只绑定 IPv6 localhost（前端阶段2）
**问题**：冒烟脚本用 127.0.0.1 被拒。

**解决**：改用 localhost。

## 已知限制与后续建议

### 1. 候选资产清理
**现状**：未选中的定妆候选资产长期保留在项目中。

**建议**：
- 定时清理：创建时间超过 7 天且未被 `anchorAssetId` 引用的候选
- 或在确认定妆时删除其他候选

### 2. Seed 透传限制
**现状**：只有 Runware 透传 seed，其他 provider（OpenAI/Doubao/Grok）不透传。

**影响**：候选差异依赖 provider 随机采样，无法保证完全可控。

**建议**：后续扩展各 provider 的 seed 参数支持。

### 3. 集成测试缺失
**现状**：真实浏览器冒烟测试只覆盖了阶段管理 UI 的基本流程，定妆全链路（真实生成候选图）依赖 DB 模式 + 图像 provider，本机 e2e file 模式无法覆盖。

**建议**：创建端到端测试：
1. 创建角色 → 生成定妆候选 → 确认定妆
2. 创建阶段 → 生成阶段预览
3. 创建章节 → 生成分镜 → 验证使用了阶段图

### 4. 阶段定稿确认
**现状**：后端 `CharacterStage.finalAssetId` 字段存在，但无端点写入该字段。

**建议**：阶段3 可考虑实现定稿确认功能（类似角色定妆的三选一）。

### 5. 阶段顺序调整
**现状**：`stageOrder` 由后端自动递增，无法手动调整顺序。

**建议**：实现拖拽/上下移功能（需要后端 API 支持）。

### 6. e2e 测试矩阵不一致
**现状**：`tests/e2e/support/e2e-test-matrix.test.ts` 期望的 db 模式 spec 清单与 `e2e-test-matrix.mjs` 不一致（document-library.spec.ts 位置对不上）。

**影响**：`pnpm test:e2e:prepare` 失败（既有问题，与本次改动无关）。

**建议**：单独修复 e2e 测试矩阵，恢复 `test:e2e:prepare` 通道后补 db 模式定妆全链路 e2e 用例。
