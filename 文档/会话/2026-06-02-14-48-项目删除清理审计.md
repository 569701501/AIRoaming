# finding

- 当前任务是审计用户删除项目后是否清理干净，边界包括项目列表记录、`workspace/projects/{projectId}` 目录、章节/角色/素材文件、生成任务、对话线程和运行时缓存。
- 文档口径确认：`Project` 是项目容器，显式删除项目应删除项目记录、本地 workspace 项目目录和该项目任务；前端不能直接写本地物理路径。
- 当前 `workspace/projects` 目录只剩 `.gitkeep` 与 `.DS_Store`，未发现项目目录或项目文件。
- 删除接口现状审计：`ProjectsService.deleteProject` 原先删除 workspace 项目目录、该项目任务和项目索引；`DialogueService` 的项目对话线程、待导入、待灵感、待大纲和待剧情结构缓存原先只因项目不存在而不可访问，但仍会留在内存 Map。
- 已补齐运行时清理：`ProjectsService` 新增项目删除监听器，删除项目后通知 `DialogueService` 清理该项目线程、pending 状态和运行中消息标记；`DeleteProjectResponse` 增加 `deletedRuntimeStateCount`。
- 已补齐异步防回写：角色参考图 worker 在任务已被删除时直接退出；图片 provider 返回后、写入文件前会再次确认项目仍存在，避免删除期间的长请求回写并重新创建项目目录。
- 当前真实状态：`GET /api/projects` 返回空列表，`GET /api/tasks` 返回空列表，`workspace/projects` 只有 `.gitkeep` 与 `.DS_Store`；访问已删除项目 `b224e22c-9cdf-4195-851c-6bae207789c8` 的 workbench 和 dialogue 均返回 404。
