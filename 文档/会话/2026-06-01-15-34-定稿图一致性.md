# finding

- 用户发现 `preview_front` 与 `final_reference` 人脸和气质不一致；截图显示定稿图像是重新文生图，没有继承已确认预览图的视觉身份。
- 代码确认：`ProjectsService.generateCharacterReference` 当前对 `preview_front` 和 `final_reference` 都调用 `/images/generations`，只传文本 prompt；`final_reference` 没有读取 `previewReferenceAssetId`。
- 设计结论：`preview_front` 不是灵感图，而是角色视觉身份锚点；`final_reference` 必须通过图片参考/编辑能力基于已确认预览图生成。

# web_search

- 搜索主题：OpenAI 图片编辑接口是否支持图片参考输入。
- 关键结论：官方 Image API 的 edits endpoint 支持上传源图片作为参考；GPT Image 模型可使用 png/webp/jpg 输入，最多 16 张图片；multipart 请求使用 `image` 字段并支持 `prompt`、`quality`、`size`、`output_format` 等参数。
- 重要来源：OpenAI API Reference Images（https://platform.openai.com/docs/api-reference/images）；OpenAI Image generation guide（https://platform.openai.com/docs/guides/image-generation）。

# goal

修复项目角色库角色定稿图生成链路：`final_reference` 必须依据用户已确认的 `preview_front` 作为视觉参考生成，避免角色形象漂移。

# approach

先对照代码和契约确认当前是否只使用文本 prompt；若属实，将 `preview_front` 定义为定稿图生成的视觉锚点，并让后端在生成 `final_reference` 时读取确认预览图作为图片输入。
