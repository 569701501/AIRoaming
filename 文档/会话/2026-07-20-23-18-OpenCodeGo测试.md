# finding

- 项目文本模型由设置页逻辑 provider 映射到受控 OpenCode runtime provider；自定义 `baseUrl` 不直接占用 OpenCode 内置 provider ID。
- 当前工作区保留上一任务尚未提交的 Runware/Grok 图片改动，本任务只读测试文本配置，不覆盖这些改动。
- 用户进一步确认：这是“新增的自定义” OpenCode Go 配置，不应显示为原有的 `self/grok-4.5`。
- 设置页把“自定义 OpenAI 兼容”的 `providerId` 硬编码为 `self`；保存时将这个 ID 直接发给后端，因此 Go 配置会以 `self/grok-4.5` 出现。
- 安全设置投影只暴露一个当前 `aiKey`，界面不是真正的多文本 Provider 新增/编辑器；底层 SQLite 可保留多条 `ProviderConfig`，但页面不会按选中 Provider 读取各自配置。
- 当前 SQLite 有两条文本 Provider：旧 `xai/grok-4.5` 仍保留；新 Go 地址保存为 `self/grok-4.5`，并被设为默认。OpenCode 内部再将它注册为 `airoaming_self`，对页面回映射为 `self`。
- 最小真实文本请求已到达 `airoaming_self/grok-4.5`，但返回 `401 Missing API key`；这是与 Provider 命名问题分离的第二个配置问题。
- 用户确认 `self` 命名可接受，当前目标改为定位已订阅 OpenCode Go 套餐但真实调用返回 `401 Missing API key` 的原因。
- OpenCode 1.18.3 当前已内置 `opencode-go` Provider，且本机 OpenCode 认证库存在 `opencode-go` API 凭据；受控运行时当前请求的却是自建 `airoaming_self`，认证库中没有这个 Provider 的 Key。
- 官方 `opencode-go/grok-4.5` 差分请求在同一个本地 OpenCode 进程内成功返回 `OPENCODE_GO_OK`，证明用户订阅、API Key、模型权限和网络均正常。
- 设置页的 `configured` 只根据数据库中的 Key 指纹判定，不代表当前 OpenCode runtime provider 已有可用 Key；文本 Key 本体只在 AI漫游服务内存中暂存，重启后依赖 OpenCode auth 持久化。
- 修复阶段进一步收口剧情结构生成：官方 Go 端点复用内置 `opencode-go` 认证槽；剧情结构改用隔离的 JSON Schema 会话和 `info.structured`，不再从普通对话文本中截取 JSON。
- 章节「出场人物」新增统一括号层级解析与发布边界校验，避免把 `陈姨（电话/门外）` 拆成多个伪角色；旧正文仍兼容读取，新发布正文只允许纯角色名。

# web_search

- 主题：OpenCode Go 当前认证、Provider ID、模型与 API 端点。
- 结论：Go 订阅后需复制 API Key 并连接 `OpenCode Go`；OpenCode 配置中的模型全 ID 是 `opencode-go/<model-id>`。`grok-4.5` 当前在 Go 模型列表中，OpenAI 兼容端点为 `https://opencode.ai/zen/go/v1/chat/completions`，对应 `@ai-sdk/openai-compatible`。
- 来源：https://opencode.ai/docs/go/ 与 https://dev.opencode.ai/docs/providers。

# result

- 根因已确认：AI漫游根据自定义 Base URL 将逻辑 `self` 注册为 `airoaming_self`，但用户的有效 Go API Key 在 OpenCode 的 `opencode-go` 认证槽位；`airoaming_self` 没有 Key，因此网关返回 `401 Missing API key`。
- 官方 `opencode-go/grok-4.5` 最小真实请求成功，证明订阅本身无问题。
- 建议修复：保留页面逻辑名 `self`，但当 Base URL 是 OpenCode Go 官方端点时，运行时应绑定内置 `opencode-go`，不再创建 `airoaming_self`；同时把“已配置”改为可验证的 runtime 认证状态或明确标注仅代表已保存指纹。
- 已完成生产代码修复且未修改用户密钥：官方 Go 地址映射到内置 `opencode-go`；结构生成主流程与一次修复均使用隔离 JSON Schema 会话；正式章节发布拒绝带括号状态说明的人物名单。
- 提交前验证：服务端相关 20 个用例通过，共享协议 30 个用例通过；`@airoaming/server` 与 `@airoaming/shared` 类型检查通过。端口型测试在允许本机临时监听的环境复验 6/6 通过。
