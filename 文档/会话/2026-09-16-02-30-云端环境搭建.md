# finding

- 仓库为 pnpm 单仓（`pnpm-workspace.yaml`：`apps/*`、`packages/*`），包管理器锁定 `pnpm@9.15.4`，Node 版本 v22.14.0，均由默认云镜像通过 corepack 提供。
- 三个子包：
  - `@airoaming/shared`（TS 库，需先 `build` 产出 `dist/`，被 server、web 以 `workspace:*` 依赖并从 `dist/index.js` 解析）。
  - `@airoaming/server`（NestJS + Express，`tsx watch src/main.ts` 开发，默认端口 4310，全局前缀 `/api`）。
  - `@airoaming/web`（Vue3 + Vite，`vite --host 0.0.0.0`，端口 5173，`/api` 代理到 `localhost:4310`）。
- Prisma schema 存在（`apps/server/prisma/schema.prisma`，SQLite），但当前后端运行期不 import `@prisma/client`，数据落地在本地 `workspace/projects/` 文件系统。故开发环境无需 `prisma generate`/迁移即可跑通核心工作台。
- 环境变量均有默认值（`PORT`、`AIROAMING_WORKSPACE_ROOT`、`VITE_API_BASE_URL` 等），后端未使用 dotenv，核心工作台无需任何密钥。AI 生成类功能需外部 provider，非环境跑通必需。
- 云端环境 `environmentJson`（build/propose）schema 仅支持 `install`、`start`、`snapshot` 三个字段，不支持 `terminals`/`ports`/`name`。因此开发服务器放入 `start`（保持前台附着）。

# goal

按 env-setup「Set up a new environment」流程为本仓库搭建云端开发环境，并端到端跑通核心应用：
- install 幂等，构建/类型检查/测试通过。
- server 与 web 开发服务器可启动，健康检查与前端 UI 可用。
- 通过 UI 端到端创建项目并持久化。
- 快照 → 触发 draft build → 全新 agent 校验 → propose 环境配置。

# 决策

- 基础镜像：使用 Cursor 默认镜像（已含 Node 22 + corepack），无需自定义 Dockerfile。
- `install`：`corepack pnpm install` + 构建 `@airoaming/shared`（源生成，供 server/web 直接解析类型与产物）。
- `start`：`corepack pnpm dev`（先构建 shared，再并行启动 server 与 web，保持前台）。
- 采用 propose（DB 托管）路径交付环境配置，不提交竞争性的 `.cursor/environment.json`。
