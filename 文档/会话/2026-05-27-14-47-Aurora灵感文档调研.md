# finding

- AuroraPlatformWeb 的“灵感文档”不是对话框里的临时附件，而是工作区固定事实文件：草稿输入在 `src/task/doc/drafts/inspiration.md` 与 `src/task/doc/drafts/inspiration-mockup.webp`，正式文档在 `src/task/doc/ai_game.md`。
- `packages/shared/src/training-workflow.ts` 把 `inspiration_intake`、`training_game_spec` 与上述固定路径写进共享工作流契约；`inspiration_intake` 只检查草稿是否存在，`training_game_spec` 才生成或完善正式 `ai_game.md`。
- 编辑页是左侧 `AgentChat`，右侧 `DirectorWorkbench mode="inspiration"`；右侧工作台用 `VEditor` 展示 `ai_game.md`，并订阅工作区文件事件，文件变化后自动刷新。
- 对话框通过 workflow 状态生成阶段化 placeholder 与建议 prompt；它推动流程，但不把对话历史当唯一状态源。
- 首页创建项目后，会把首条 prompt 和上传附件暂存为 `ProjectEntryPromptPayload`；进入编辑页后 `AgentChat` 消费一次，可自动发送或还原为草稿。
- 附件上传到项目工作区 `src/upload`，发送消息时成为 `attachmentContext`：图片类按 file part 传给 OpenCode，文本类可被内联，其他附件以工作区路径提示给 agent。
- OpenCode 的 `show_file` 工具会回调前端；`AgentChat` 发出 `show-file-request`，`ProjectEditPage` 转给 `DirectorWorkbench`，工作台根据路径切到灵感文档、图片、音频、预览或源码等对应视图。
- 设计本质是三层分离：附件是临时输入上下文，工作区文档是持久事实源，workflow 是阶段状态与完成标准。

# result

本轮只做代码与文档调研，没有修改业务代码。对 AI漫游可借鉴的方向是：剧本对话也应坚持“左侧对话推动、右侧章节剧本文档承载事实”的模式；附件、用户临时描述和未保存编辑器草稿只能作为请求上下文，不能自动变成正式事实。适合迁移的是固定路径、当前阶段/章节驱动提示词、文件/状态事件同步、以及“打开/定位当前文档”的 UI 协作机制；不适合照搬的是 Aurora 的完整 Docker/OpenCode 工作流、动态多标签素材工作台，以及 agent 直接写正式文档的强自动化方式。
