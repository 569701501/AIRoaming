# goal

梳理“按章节创作”的产品、数据模型和本地文件保存方案，判断是否需要章节列表、完成本章进入下一章按钮，以及每章独立目录。

# approach

- 将“章节”提升为项目内一等工作单元，而不是只从 Markdown 标题中临时解析。
- UI 上需要章节列表和当前章节状态；右侧章节信息面板继续只展示当前章节摘要信息，不承载完整章节管理。
- 保存草稿与完成本章应区分：保存草稿只落盘当前章节；完成本章会标记章节状态、创建或切换到下一章。
- 本地文件结构建议改为 `workspace/projects/{projectId}/chapters/chapter-001/` 等章节目录；项目级角色、世界观、共享素材仍放项目级共享区域，避免章节间割裂。

# question

- “完成本章”后是否允许继续编辑上一章？初步建议允许，但要保留版本记录。
