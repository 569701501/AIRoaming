# finding

- 项目口径：OpenCode 是 AI Runtime，不是业务事实源；AI漫游自己的线程、消息、章节和项目产物才是事实源。
- 前端链路：`ProjectDialoguePanel` 收集输入/附件，`ProjectWorkbenchView.emitDialogue` 根据附件、导入意图或灵感意图决定使用项目级线程，否则使用当前章节线程，并携带编辑器最新 `sourceText`。
- Store 链路：`workbench-store.sendDialogueMessage` 只走流式 API `sendDialogueMessageStream`；SSE 事件更新消息、工具结果和章节局部状态。
- 后端链路：`DialogueController` 暴露线程读取、普通发送和流式发送；真实主路径是流式发送。
- `DialogueService` 先创建 AI漫游本地线程与消息，再按顺序尝试剧本工具：导入分析/写入、灵感种子/从种子生成、当前章节改写；命中工具时不走普通聊天回复，直接返回工具结果摘要。
- 普通聊天或未命中工具时，`DialogueService` 通过 `OpenCodeRuntimeService` 创建或复用 OpenCode session，发送拼好的 prompt，并把 OpenCode 增量事件转换为 AI漫游 SSE 事件。
- OpenCode runtime 可自动启动 `opencode serve`，默认 host/port 为 `127.0.0.1:4396`，默认模型来自环境变量，兜底为 `self/gpt-5.5`。
- 剧本导入：`analyzeScriptImport` 先判定内容类型、章节边界和覆盖风险；只有 `ready_to_import` 或用户确认后才 `importScriptToChapters` 写入章节。
- 灵感链路：用户表达找灵感时，后端调用 OpenCode 执行 `script-inspiration-seeding` prompt，解析 3 个 JSON 种子并缓存；用户“选第 N 个”后调用 `script-chapter-drafting` prompt 生成固定格式「章节剧本」并写入当前章节。
- 章节改写：用户明确要求改写/润色/扩写等，且当前章节有正文时，后端调用 `script-chapter-editing` prompt 生成完整固定格式「章节剧本」并写当前章节。
- AI 写入章节最终走 `ProjectsService.writeChapterDraftFromAI` 或 `importScriptToChapters`，写入 `chapters/{chapterSlug}/script.md`，并记录 `lastScriptRevision`。
- 生成任务中心当前是 mock worker；`story_parse`、`shot_generate`、`shot_prompt_generate`、`image_generate`、`layout_export` 强制带 `chapterId`，但还没有真实 AI provider 执行剧情结构/分镜/图片链路。
- 重要缺口：OpenCode AI 资产目录已落地，但尚未完整复制到 OpenCode session home；真实生效主路径仍是 `DialogueService` 内拼接的 prompt 和后端规则。对话历史仍是进程内 Map，不持久化；停止生成未实现；模型选择数据链路存在但 UI 下拉未展示。
