# finding

用户反馈：按照“完成第 1 章后切回第 1 章再点剧情结构”的路径仍然无法进入剧情结构。当前目标是先定位原因，不先改交互方案。

代码与运行态排查：

- 服务端 `GET /api/projects/:projectId/workbench?chapterId=chapter_001` 返回 `currentStepKey=story_structure`，`story_structure` 阶段为 `active`，说明第 1 章后端状态已满足进入剧情结构。
- 真实项目 `b224e22c-9cdf-4195-851c-6bae207789c8` 中：`chapter_001` 状态为 `script_done`，`chapter_002` 状态为 `draft`。
- Chrome 当前页面 URL 为 `/projects/b224e22c-9cdf-4195-851c-6bae207789c8/script/chapter_002`，页面顶部显示“第 2 章 草稿”；顶部流程条显示“剧情结构：需要先完成当前章节剧本”，这是因为当前章仍是草稿。
- 前端 `WorkbenchStageRail` 只允许点击 `done` 或 `active` 阶段；当当前章是 `draft` 时，`story_structure` 被置为 `waiting` 并禁用。
- `goProjectStep` 进入非剧本阶段时不带 `chapterId`，依赖项目当前章节；因此页面当前停在草稿章节时，不能直接进入该章节的剧情结构。

# web_search


# goal

找出无法进入剧情结构的真实原因，区分是章节状态、后端 workflow、前端路由/状态同步、还是 UI 禁用逻辑问题。

# approach

按 diagnose 流程建立可重复反馈环：先用本机 API 复现“完成章节 -> 切回章节 -> workflow 是否允许剧情结构”，再对照前端 `WorkbenchStageRail`、`AppShell` 和 store 的章节/步骤同步逻辑。

# result

原因不是后端没有解锁剧情结构，而是浏览器当前仍打开 `chapter_002` 草稿页。剧情结构是按当前章节解锁的，当前章为草稿时顶部“剧情结构”自然禁用。第 1 章本身已满足进入剧情结构条件。
