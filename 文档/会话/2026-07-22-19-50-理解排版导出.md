# finding

- “排版导出”是项目七步主流程的第 6 步，位于“候选图工作台”之后、“素材包”之前；正式目标是把已定稿的镜头图片编排成漫画成稿，并从不可变排版版本生成可交付文件。
- 当前事实源把该能力称为 G5 成稿编辑器/漫画排版出版，实际合并了五类职责：成稿编辑、草稿自动保存、正式版本、出版导出、历史/来源返修。
- 上游是每个 Shot 的当前候选定稿；“生成排版”只是确定性基础起稿，不是 AI 理解剧情后的智能排版：条漫为一镜一段，页漫最多四镜一页。之后用户再调整页面/段落、画格、裁切、图层、文字和气泡。
- 当前页面的关键状态分层为：`立即保存` 只保存可变草稿；`保存版本` 经预检形成不可变成稿快照；`正式出版` 再从该快照异步生成真实成品。页漫产物是逐页 PNG + 可选 PDF，条漫产物是 PNG 切片 + 能力允许时的长图。
- `手机预览` 当前默认查看最近保存的草稿；`AI 建议` 当前只是把所选对象横向微调 8px 的受控示例，不是自动设计整章版面。
- 用户认为当前页面“太难用”。代码和现状截图印证主要原因：普通编辑主路径与来源返修、两层预检、版本历史、出版任务和系统术语同时出现；“保存草稿/保存版本/当前正式/正式出版/当前成品”语义相近；顶部动作还需在展开管理区二次完成，用户很难形成单一路径心智。
- 用户进一步纠正产品定位：智能成稿和人工编辑必须同等重要、连续存在。系统生成的不是只供校对的扁平成品，而是直接进入正式编辑器的结构化可编辑初稿；现有编辑能力不应被降为隐藏的“高级模式”。

# goal

在已讲清现状的基础上，重新设计适用于 AI漫游的“漫画成稿”功能，形成正式开发依据，并按阶段实施。最终体验要求零配置、低学习成本：用户首次进入即可得到包含完整排版、画格布局、图片裁切、对白、气泡、旁白和阅读顺序的结构化可编辑成稿，普通章节的大部分内容无需手调。M0～M6 已完成或带已知视觉风险退出；下一阶段是 M7 的 V2 来源更新、阅读预览与正式出版。

# approach

1. 研究专业漫画工具、轻量漫画排版工具和 AI 漫画产品的官方工作流。
2. 区分值得吸收的共性与不适合本项目的专业复杂度。
3. 以普通用户主路径为中心重排功能、页面区域、状态和按钮。
4. 保留现有底层版本、来源追溯与确定性导出能力，但默认隐藏后台安全层。

当前推荐方案：用户可见步骤改名为“漫画成稿”，采用“一套工作台、智能起稿与人工编辑连续协作”的产品模型。首次进入用正式分镜和候选定稿生成结构化初稿，画格、图片裁切、对白、气泡、标题和留白全部直接可编辑；工作台提供编辑视图与阅读预览，不再把完整编辑器单独降为高级模式。智能能力既可整章起稿，也可按场景、页面/段落或选中对象局部优化，并必须尊重锁定项、保留人工修改、可预览和撤销。草稿自动保存，“预览并导出”继续作为最终主动作，底层版本与出版安全契约保持不变。

智能成稿细化为四段流水线：先用 `sceneId`、`beatId`、`frameType`、`panelRhythm`、`shotType` 和图片比例形成叙事分组；再把 `motion.voiceLines` 作为结构化对白主源、`comic.dialogue` 作为兼容回退、`comic.caption` 作为旁白，去重后形成不改写原文的对白计划；随后结合人物/主体区域与文字安全区生成多套布局、裁切和气泡方案；最后按镜头/文字零遗漏、文字不溢出、主体不被遮挡、阅读顺序、节奏和版面平衡评分并自动修复，选出最高分方案。条漫使用可变高度连续段落，页漫按叙事单元形成 3～6 格页面，不再固定一镜一段或四镜一页。

人工编辑保护规则：所有智能结果都是正式画格、图片、文字和气泡对象；人工调整需记录保留意图，局部智能操作默认不覆盖手调字段，显式锁定对象完全禁止智能改动；整章/场景/页面/选区重排均先预览、再应用，并进入同一撤销栈。编辑器只保留漫画成稿必需能力，不扩张为绘画软件。

M0 实施采用独立 `tests/fixtures/smart-layout/` corpus，不污染既有 G5 renderer fixture。10 个验收组中的两种格式交叉项拆为双变体，共 12 个 runnable fixture；用实尺寸合成测量图的主体白框验证中心 cover 裁切，用现有 V1 初始化生成当前文档，再由生产 Chromium renderer 输出真实成品。逐画格 rubric 和 128 行双人复核模板已经冻结，未来不得删除失败项来抬高分数。

M1 在 `packages/shared/src/layout/` 内建立与现有 V1 并存的自动化边界：V2 只增加 `automation` 元数据，不改变 renderer 可见语义；V1 历史文档可投影为相同 V1 渲染计划，Working Copy 升级时为既有对象补 `explicit_preserve`。智能命令在执行前检查字段级保护，用户编辑只保护实际受影响字段；对白绑定的删除/恢复必须走语义命令，避免智能规划把用户主动删除的气泡补回。

M2 在同一 Shared 边界内落地完整规则 fallback：来源先严格交叉校验，对白只做 NFC/换行/首尾空白归一和精确去重，不做模糊删除或改写；NarrativeGroup 保持 Shot 原序；页漫按原子组分页，条漫按可变高度 section 编排；没有视觉人物锚点时关闭尾巴并报告。真实条漫要求 section 边界为整逻辑像素，避免切片与长图量化后产生 1px 拼接差异。M3 必须补主体/人脸/关键动作/文字安全区、shape-safe 气泡、多候选评分和有限修复。

M3 在规则初稿上消费 strict、可摘要、绑定 Asset digest 的视觉区域；每次生成 `balanced/subject_first/dialogue_first` 三套完整候选，按内容硬门和五维视觉软分稳定选择。布局同时考虑主体、人脸、文字安全区、页格数/占用率、气泡 shape-safe 和尾巴路径冲突；生产 renderer 与 Shared/Web 共用实尺寸 cover 和气泡路径语义。自动评分只用于预检，A/B 人工 CSV 不由脚本或 Agent 预填。

M3 人工签收 V1 的合成测量图 HTML/CSV 已降级为工程证据。V2 统一使用 `AIR-QA-COMIC-FINAL-001-v1` 和真实漫画图：开始前先用正反例校准；复核时显示完整成稿并高亮一个画格或气泡，提供未裁切原图、原文、说话者和中文气泡类型；整页/段另行从页首阅读并隐藏高亮。每轮共 69 画格 + 59 气泡 + 30 整页/段 = 158 项，没有批量通过。普通三桶分别要求 ≥90%，困难三桶分别要求 ≥80%，严重可见错误为 0。两轮 JSON 绑定相同 manifest，但评审人必须不同；浏览器自动化只验证工具合同，不替代真人结论。

M4 采用“worker 只生成不可变建议，apply 再次校验并独立事务落地”的边界。initial 仅在无 Working Copy 时创建 V2；full reflow 只创建 Pending 预览，确认前原稿不变。每次首次成功应用与 ADR-0020 应用凭证同事务写入，重复请求只有在目标仍保持创建时状态时 replay，用户手调、预览已处理或来源变化均返回冲突。

M5 不另造编辑器：无 Working Copy 时页面自动完成 create/poll/apply，再加载现有编辑器；有稿直接加载。V2 是唯一保存事实，V1 仅作为旧画布的可见投影。整章重排避开当前可见摘要后生成新候选，先做左右可视对比；保留不改 WC，应用进入一次本地撤销历史。产品界面只显示普通中文状态，内部任务、摘要和行版本留在协议层。

M6 复用同一规划器和 Pending 边界：服务端从 DB ready Asset 安全读取并发送受限图片附件，Provider 只给结构化视觉区域，本地代码负责身份、坐标、候选和命令；任一 Shot 失败独立回退。canvas/element/shot scope 对应页段/选区/场景，并扩展完整叙事组。细粒度命令默认保留人工 protection 与锁定，用户只有显式点击“允许智能再次调整”才释放当前选中对象的 protection。外部具体模型不在产品契约中锁死，本轮没有付费视觉调用。
