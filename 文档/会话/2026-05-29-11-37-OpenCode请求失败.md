# finding

- 用户反馈 OpenCode 请求失败，要求使用 `$deep-think` 检查原因。
- `GET /api/health` 正常，`GET /api/ai-runtime/models` 正常返回模型列表，说明 AI漫游后端和 OpenCode serve 进程都在运行。
- 直接调用 OpenCode `/session` 成功，但 `/session/{id}/message` 使用默认 `aurora/gpt-5.4` 长时间不返回，诊断脚本 60 秒后 abort。
- 绕过 OpenCode 直接请求默认 provider 背后的 `timicc` OpenAI-compatible 接口，`gpt-5.5` 和 `gpt-5.4` 均返回 `503 No available accounts: no available accounts`。
- 同样方式测试 `self/gpt-5.5` 成功返回“正常”，耗时约 2.7 秒。
- 当前对话框没有可见模型切换控件，前端 store 原本会保留已选中的旧默认模型；即使后端改默认，如果 store 里已有 `aurora/gpt-5.4`，也可能继续使用坏模型。

# goal

# approach

先用 OpenCode 原生 API 和 provider 直连确认根因；再把 AI漫游默认模型兜底从 `aurora/gpt-5.4` 调整为 `self/gpt-5.5`，并让前端每次加载模型列表时采用后端当前默认。环境变量 `OPENCODE_PROVIDER_ID/OPENCODE_MODEL_ID` 仍可覆盖。
