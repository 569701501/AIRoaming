# finding

- 当前右侧 `ProjectCharactersWorkspace.vue` 展示并可编辑 `name/level/role/appearance/personality/promptFragment`，字段过多，和用户希望的“上方角色描述列表 + 下方角色图卡片”不一致。
- 当前正式文档把项目级角色称为 `Character` / 项目角色库；此前剧本阶段明确不输出“主体列表”，因此用户新提到的“主体列表”需要先和项目术语对齐。
- 当前角色参考图契约为 `single_front` 与 `turnaround_4view`；用户希望先生成一张正面照片，确认后再补一张包含“正面半身、正面全身、侧面全身、背面全身”的图。
- 已确认右侧角色库不提供字段编辑；用户要改角色名、角色描述或层级时，通过左侧 AI 对话提出要求，再由系统受控工具重新整理/更新角色列表。
- 已确认角色图生成拆成两阶段：先生成 `角色预览图`，用于判断角色长相和气质是否正确；用户确认预览后，再生成 `角色定稿图`，包含正面半身、正面全身、侧面全身、背面全身。只有角色定稿图确认后才作为后续漫画/漫剧一致性基准。
- 用户进一步确认：角色图肯定都要有，进入项目角色库后应自动异步生成；图片未生成前按角色显示“生成中”，生成完成后显示到页面。点击图片应弹窗展示当前图片。
- 代码事实：`ProjectsService.generateCharacterReference` 已保留为内部真实图片生成方法；外部 `/reference` API 改为排队 `character_reference_generate` 任务，由 `TasksService.createControlled` 控制状态并异步写入项目素材。
- 已确认自动生成触发与去重：`提取/更新角色列表成功后` 后端为缺少预览图的角色排队；`进入项目角色库页面时` 前端调用“补齐缺失预览图”接口；后端只给没有预览图、没有运行中任务的角色补排队。
- 文档事实：`核心用户流程.md`、`核心数据模型.md`、`生成任务协议.md`、素材路径和模块总览已同步到 `preview_front/final_reference`，右侧工作区为只读展示。

# question

- 已确认：不使用“主体列表”。页面展示文案改为“角色列表”，每个角色的一句话设定称为“角色描述”；底层仍沿用项目级 `Character` / 项目角色库。
- 已确认：右侧角色库只展示角色列表、角色描述和角色图，不提供表单字段编辑；修改入口回到左侧 AI 对话。
- 已确认：主角和常驻角色必须完成角色定稿图，才能进入剧情结构；普通本章角色可以只停留在角色预览图，不阻塞。
- 已确认：进入项目角色库后自动为所有角色异步生成 `角色预览图`；用户确认预览图后，再异步生成该角色的 `角色定稿图`。定稿图不在预览确认前自动生成。
- 已确认：自动生成任务的触发时机和去重规则。
- 已确认：角色图类型命名为 `preview_front` 和 `final_reference`。`preview_front` 是自动生成的正面半身/头像感预览图；`final_reference` 是用户确认预览后生成的角色定稿组合图，包含正面半身、正面全身、侧面全身、背面全身。
- 已确认：`final_reference` 生成完成后仍需用户点击“确认定稿”，角色才算完成。若定稿图不满意，可以重新生成定稿图；只有用户明确认为人设不对时，才回到预览图或重新整理角色描述。
