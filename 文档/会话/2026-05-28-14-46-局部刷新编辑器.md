# finding

- 用户反馈：AI 写入剧本文档到编辑器时，页面会像整页刷新；点击“清空剧本”时也会像整页刷新。期望改为局部刷新，或写入时慢慢追加到文件编辑器。
- 前端 `apps/web/src/stores/workbench-store.ts` 中，`refreshAfterToolResult()` 在 `import_script_to_chapters`、`generate_script_from_seed`、`update_chapter_draft` 成功后重新请求完整 `workbench` 和项目列表，并整体替换 `snapshot`。
- 同一 store 的 `resetProjectScript()` 在清空成功后也重新请求完整 `workbench` 和项目列表；这会打开全局 `loading` 并触发外层工作台组件重渲染。
- `ScriptDocumentEditor.vue` 监听整个 `props.snapshot`，快照对象被替换时会调用 `resetForm()`，把编辑器内容重置为当前章节正文。
- 后端已有章节级接口：`GET /projects/:projectId/chapters/:chapterId`；保存、完成、清空和 AI 写入相关后端结果也已经返回 `ChapterDetail` 或 `ChapterListItem[]`，具备局部合并基础。
- `DialogueToolResult` 原本只有 `currentChapterId` 和章节列表摘要，不含完整 `sourceText`；为了让 AI 写入后不额外请求完整 workbench，写入类工具结果需要带 `currentChapter`。

# web_search

# goal

修复剧本编辑器的刷新体验：AI 写入章节和清空剧本时不再触发整工作台刷新；优先改为章节级局部合并，让编辑器、章节列表和项目预览只更新必要数据。

# approach

- 建立章节级局部合并方法：用 `ChapterDetail` + `ChapterListItem[]` 更新 `snapshot.currentChapter`、`snapshot.chapters`、`snapshot.story` 和当前项目列表项预览。
- AI 工具结果成功后，用工具结果中的 `currentChapter + chapters` 局部刷新当前章节；缺少 `currentChapter` 时才兜底请求单章接口，而不是请求完整 workbench。
- 清空剧本直接使用 reset 接口返回的空白章节和章节列表局部合并，避免再次拉完整 workbench。
- 路由同步时，如果 store 已经处于目标项目/章节，AppShell watcher 跳过 `openProject()`，避免清空或完成本章后又触发一次全量加载。
- 真实“AI token 级慢慢追加到编辑器”需要后端 SSE 传正文 delta；当前先修复无全量刷新的 UX。
