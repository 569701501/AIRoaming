# finding

- 当前漫画成稿已具备内部 LayoutDocument/Editor Command、一等工作台、V2 Working Copy/Pending/人工保护和 V1 确定性出版，不是从零搭建编辑器。
- 本次需要区分“吸收专业漫画编辑能力”与“直接集成第三方完整编辑器/画布内核”。
- ADR-0016 已采纳 Konva 10.3.0 作为 Web 交互 adapter，但生产 Web 仍是绝对定位 DOM + 单对象 Pointer drag；Konva 只在归档原型。
- 当前最高优先级缺口是 V2 Preflight/Revision/Publication，以及 AI 对比缩略图、手机只读图片与权威 RenderScene 的语义偏差。
- 现有协议已经支持横竖排富文本、SFX、图层、四类气泡及 fill/stroke/padding/单尾巴；图片滤镜、文字阴影/发光、新轮廓、多尾巴、blend/mask 不存在。

# web_search

- Manga Editor Desu 是 GPL-3.0 完整 Web/PWA 应用，不是可嵌入库；GPL 允许商业使用，但复制/组合到专有前端存在显著合规义务。来源：GitHub 仓库、LICENSE、package.json。
- Comical-JS 是 MIT 库，但不处理气泡内部文字/样式 UI，并采用 Paper.js + Canvas/SVG/DOM + `data-comical`；不能视为 Konva 插件。来源：GitHub README、LICENSE、package.json、npm registry。
- Konva 是 MIT、持续维护的 TS/JS 库，适合交互 adapter；正式状态和导出仍需项目自建。来源：GitHub、Releases、npm。
- TUI Image Editor 为 MIT，依赖 Fabric 4.2.0 且长期未发布新版；主画布不宜依赖。React Komik 技术栈停更多年。Komiko 公开仓库只有 README 且无 LICENSE。
- 重要链接：
  - https://github.com/new-sankaku/manga-editor-desu
  - https://github.com/BloomBooks/comical-js
  - https://github.com/konvajs/konva
  - https://github.com/nhn/tui.image-editor

  - https://github.com/Story-Engine-Inc/Komiko

# goal

评估 Manga Editor Desu、Comical-JS、Konva.js、TUI Image Editor、React Komik 等能力是否适合放入现有“漫画成稿”，形成不破坏现有数据、任务、编辑与导出契约的推荐边界和分阶段路线。

# approach

- P0 先闭合 V2 正式出版和权威预览语义。
- P1 按现有 ADR 完成 Konva Web interaction adapter，不更换领域/撤销/导出内核。
- P2 不升级 Schema，开放已有气泡、富文本、SFX 和图层能力。
- P3 只有真实需求成立时用 LayoutDocument V3 承载新轮廓、文字效果和非破坏滤镜。
- AI 图片编辑可从成稿发起，但必须生成派生 Candidate/Asset 并走来源替换。
