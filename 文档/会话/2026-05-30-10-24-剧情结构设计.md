# finding

- 用户不确定「剧情结构」应该写成什么样，已调用 `$grill-with-docs`。
- 现有事实源定义：第 2 步「剧情结构」用于把当前章节拆成摘要、角色、场景、剧情节拍，输出 `StoryVersion.structureJson` 和 `StoryBeat[]`，为后续分镜工作台提供上游语义。
- 剧本阶段已经明确不输出主体列表、正式场景列表、剧情节拍、分镜剧本、镜头编号、图片 Prompt 或 JSON；这些内容后置到「剧情结构」「分镜工作台」「候选图」。
- 当前 `story_parse` 任务协议要求输出包含 `summary`、`characters`、`scenes`、`beats`，且 `beats` 有稳定顺序，不允许只输出自然语言总结。
- 现有 Prisma schema 仍是早期 `StoryVersion` 归属 `Project`，而文档最新口径是章节工作流下 `StoryVersion` 应归属 `Chapter`；这是后续实现时需要修正的历史模型差异。
- 用户已确认术语口径：剧情结构是“给制作看的结构表”，不是给读者看的剧本，也不是最终分镜。
- 用户已确认剧情节拍粒度：按关键剧情事件切，不和未来分镜/镜头一一对应；剧情结构阶段保持比分镜更粗的一层。
- 用户已确认角色卡/场景卡性质：剧情结构阶段先生成“本章结构卡”，不是正式项目级角色/场景资产；后续可由用户确认后提升为项目级资产。
- 用户已确认剧情结构页面形态：用户看到可编辑结构表，系统底层保存 `chapters/{chapterSlug}/structure.json`，不采用 Markdown 文档编辑器作为主形态。
- 用户已确认剧情节拍视觉边界：节拍里可以有轻量“画面重点”，但不能输出镜头编号、景别、机位、构图或分镜稿。
- 用户已确认生成分镜门槛：剧情结构生成后必须经过用户确认，才能进入“生成分镜”。
- 用户已确认页面交互：进入剧情结构步骤后，左侧仍是公共 AI 对话框，但注入剧情结构 prompt；用户说生成剧情结构后，AI 先生成结构内容，用户确认后，右侧以元素化结构表展示生成内容，不使用文本编辑器。
- 用户已确认编辑方式：结构表中可修改字段的右上角显示小笔图标；点击后当前字段变成输入框并带入当前内容；用户编辑后输入框失焦即提交并恢复为普通文本展示。
- 用户已确认待确认预览：AI 生成剧情结构后，右侧也展示“待确认预览”，顶部明确标识待确认；用户确认后才转为正式结构表。
- 代码与文档契约确认：`story_structure` 是章节级步骤，`story_parse` 输入必须带 `chapterId`，结构化剧情保存到章节目录；因此剧情结构也应按当前章节一章一章生成，不一次性生成整本结构。
- 用户已确认剧情结构步骤也需要章节下拉/章节切换器，让用户选择当前要生成或查看剧情结构的章节。
- 用户已确认每个章节都需要剧情结构生成状态；完成状态沿用章节工作流语义，`Chapter.status = structured` 表示该章剧情结构已确认完成。
- 闭环决策：剧情结构章节下拉展示所有章节；未完成剧本的章节只显示状态和“请先完成本章剧本”，不能生成剧情结构。`script_done` 章节可生成结构；`structured` 及后续状态章节可查看结构，如重新生成需提示会影响后续分镜、候选图和排版。

# result

- 已确认：剧情结构不是章节剧本，也不是最终分镜；它是当前章节进入分镜前的制作结构表。
- 已确认：剧情节拍是关键剧情事件级别，通常一章约 8-15 个节拍；分镜阶段再把节拍拆成更细镜头。
- 已确认：本章角色卡/场景卡默认只归属于当前 `StoryVersion`，用户确认复用后再进入项目级角色库/场景库。
- 已确认：剧情结构页面以可编辑结构表为主，底层保存结构化 JSON，避免像剧本页一样保存成 Markdown 正文。
- 已确认：`StoryBeat` 可包含 `visualFocus` 这类轻量画面重点，帮助后续分镜理解重点；但剧情结构阶段不得出现镜头编号、景别、机位、构图或完整分镜稿。
- 已确认：AI 生成剧情结构后，用户需要编辑/确认结构，确认后才能触发分镜生成。
- 已确认：剧情结构页右侧不使用 Markdown/文本编辑器，而是按摘要、角色卡、场景卡、节拍表渲染为元素；可编辑字段通过笔图标进入字段级编辑，失焦后保存并恢复文本态。
- 已确认：AI 生成后的结构草稿可在右侧以“待确认预览”展示，但还不是正式 `StoryVersion.status = structured`，不能触发分镜；用户确认后才成为正式结构表。
- 已确认：剧情结构与剧本、分镜一样归属于章节；用户在当前章节上生成、预览、确认和编辑结构，每个章节有自己的结构化剧情文件。
- 已确认：剧情结构页面需要章节下拉/切换器，展示章节名和结构状态；用户确认结构后，当前章节推进为 `structured`，表示该章剧情结构完成。
- 已确认：文档闭环。剧情结构链路覆盖：章节选择、生成权限、待确认预览、确认写入、状态推进、字段编辑、分镜前置门槛和过期风险提示。
