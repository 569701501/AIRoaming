# finding

- 候选图链路已存在 `storyboard-shot-generate` 与 `image-candidate-generate` 两个生产 Skill，并非完全没有 Skill。
- 根因已确认：`candidate-generation-spec.ts` 的候选图 Prompt builder 直接复制或拼接正式分镜的 `comic.panelDescription`、`coreAction`、`emotion`、`comic.composition`、景别/机位和角色/场景字段，没有“剧情语义 → 单帧视觉简报”的 AI 编译/润色阶段。OpenAI、豆包、Grok Profile 只改变标签与语言，不会消解源语义中的歧义和冲突。
- 候选图工作台展示的“画面描述”也是 `comic.panelDescription || promptDraft`，没有独立的可编辑视觉简报、冲突提示或生成前预检。
- 当前固定质量门主要检查空值、占位词、重复、对白来源和 `promptDraft` 禁词；未检查主体/受体角色、单一地点与瞬间、纯可视语言、人物站位/视线/交互、群体数量、身份特征与镜头状态分离、正负约束冲突。
- 真实 DB 项目“废土送葬人 / 杀令入棺”12 镜复现结果：12/12 画面、动作、构图均被原样复制/拼接；3 镜场景含跨地点或持续时间；3 镜含气味/声音等不可见信息；9 镜角色描述混入设定图指令或剧情状态；5 镜构图含气泡语言；3 镜要求画文字/数字，同时 12/12 Provider Prompt 又禁止文字；5 镜把 `group` 当成一个主体计数。
- 代表性冲突：小棠描述同时包含“唇边一线血、咳血溅在观察窗”和“正面半身角色设定图，不出现血液、伤口或医疗细节”；场景包含“商队圈内 → 避难舱观察窗内外”“数十秒至一两分钟”“刀出鞘的金属味、湿咳”；模型无法从这些叙事字段稳定还原一个地点、一个瞬间和清楚的空间关系。
- 实际异常图与输入一致印证：某镜要求棺盖内出现“杀令文字”，同时硬约束禁止文字，结果模型生成大幅英文；多人镜主体数量、身份、站位和父女视线关系均出现偏差。因此参考图覆盖不是本轮主因，坏语义会在所有 Provider 上继续传播。
- 上游角色 `visualTraits` 多为“守黑棺、掌心烫白印、压心口跪地”等剧情状态，不是稳定外观身份；场景字段也混合地点切换、时长、声音和气味。候选图 builder 又优先取这些字段，进一步污染身份描述。
- 用户确认市场对齐方案并授权实施后，已完成“分镜基础单帧描述 + 工作台三段可编辑草稿 + 固定问题 + 按需 AI 可见建议 + 确定性 Provider 编译”。
- `shot_prompt_generate` 已从透传 Prompt 改为真实文本优化任务；严格解析、最多修复一次，结果只进 GenerationTask.output，不写 StoryboardVersion。
- 单镜与批量图片任务都由服务端重新编译并冻结三段 override；批量发现任一视觉硬伤时图片任务数保持 0。
- Scrutiny 发现的旧模式伪可用、批量部分创建、AI 警告绕过硬伤和旧建议覆盖新草稿均已修正并回归。

# web_search

- Boords：导入剧本时会拆场景/动作/镜头并生成 image prompts；生图界面中，空 Prompt 可自动读取帧文本生成适合的图像 Prompt，并允许编辑、绑定角色/场景/前一帧参考与逐次 revision；Boords Agent 对歧义信息会先问简短问题。来源：https://boords.com/docs/creating-storyboards 、https://boords.com/docs/ai-image-generator 、https://boords.com/agent
- LTX Studio：先从剧本抽取角色、物件和地点为可复用 Elements，再提供可审阅的 Shot Breakdown，用户可在生图前拆分/合并/新增镜头，单镜可改描述或 Retake。来源：https://ltx.io/studio/platform/ai-storyboard-generator 、https://ltx.io/blog/how-to-storyboard 、https://ltx.io/blog/getting-started-with-elements
- Katalist：明确把产品定位为“创意与生成式 AI 之间的翻译层”，先拆镜头、抽取视觉信息，再让用户调整 framing、angle、pose、composition、props、scene。来源：https://www.katalist.ai/
- StoryboardHero：导入剧本后识别场景/镜头并补充细节；稳定角色外观单独保存年龄、服装、面部等身份属性，镜头另设景别、视角、焦点、光线、运动和机位。来源：https://storyboardhero.ai/features
- Adobe Firefly Boards：用户在画布中按帧使用 Prompt、风格/构图参考、角色表和背景参考，再逐帧 remix/refine。来源：https://helpx.adobe.com/ca/firefly/web/create-mood-boards/firefly-boards/about-firefly-boards.html 、https://helpx.adobe.com/dk/firefly/how-to/create-commercial-storyboard-firefly-boards.html
- Google Imagen：官方提供基于 LLM 的 Prompt rewriter，默认通过增加细节和描述性语言提高图像质量；增强结果可在生成前编辑。来源：https://cloud.google.com/vertex-ai/generative-ai/docs/image/use-prompt-rewriter
- OpenAI：生产 Prompt 建议固定按场景→主体→细节→约束组织，复杂请求用短标签；人物要明确尺度、身体范围、视线和物体交互，多参考图要逐一标注职责，避免把所有要求塞进一段长文本。来源：https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide
- Runway：建议使用描述性的完整视觉语言，并明确 subject、scene、composition、lighting、focus、angle 等；对话式或非视觉性文字可能降低结果。来源：https://help.runwayml.com/hc/en-us/articles/35694045317139-Gen-4-Image-Prompting-Guide

# goal

查明候选图工作台“画面描述生硬、不完整并导致生成结果奇怪”的真实原因，参考市场公开流程形成方案，并在用户确认后完成实现、复核和留痕。强制边界是不新增顶层步骤或数据库 Schema、不暗改正式分镜、不调用真实图片 Provider。

# approach

先按 `diagnose` 建立真实样例反馈环并做市场纠偏，再用 `$deep-think` 分角色实施：Orchestrator 定位 seam，Worker 分层接入单帧质量、AI 优化和页面草稿，Scrutiny 两轮找边界漏洞并退回修正，Runtime/User Review 用真实页面只读检查和隔离 E2E 验证。最终保持 `storyboard-shot-generate → 可编辑候选草稿/按需 shot_prompt_generate → image-candidate-generate 确定性编译`。

# question

- 无。真实图片 A/B 需要用户以后单独授权和预算，不是本任务阻塞项。

# result

- 诊断与市场结论保持有效：不是“完全没 Skill”，而是叙事字段被直接当成生图字段；成熟产品共同采用拆镜时可视描述、资产/Elements 绑定、单镜可编辑 Prompt 和按需局部重做，公开资料不能证明其内部也使用本项目形态的 Skill。
- 已完成首版生产实现：分镜产出基础单帧描述；工作台可编辑画面/动作/构图；固定问题在付费生图前可见；`shot_prompt_generate` 返回可显式采用的建议；Provider 层保持确定性。
- AI 结果不会修改正式分镜；旧建议在上游或当前草稿变化后隐藏。file/DB 最终任务都由服务端冻结覆盖后的规格，批量视觉硬伤时零图片任务创建。
- 无数据库 Schema/migration 变化。Shared 167 项通过；Server 最终全量 800 项中 799 项通过，唯一无关备份并发用例环境超时后隔离复跑通过；类型检查、Web 构建、DB 集成和 Chromium E2E 通过。
- 全程没有真实图片 Provider 请求；真实 3～5 镜新旧 Prompt A/B 仍需用户另行授权，当前不能宣称最终画质已被证明。
