# web_search

调研主题：Grok / xAI 图片生成 API 当前官方行为。

关键结论：xAI 官方文档显示 Grok Imagine 图片生成使用 `POST /v1/images/generations`，示例 base URL 为 `https://api.x.ai/v1`，模型为 `grok-imagine-image-quality`，支持 `aspect_ratio`、`resolution`、`response_format=b64_json`；图生图使用 JSON `POST /v1/images/edits`，不支持 OpenAI SDK multipart `images.edit()`。参考来源：xAI Image Generation、xAI Image Editing、xAI Images REST API。

# goal

把 Grok 生图加到设置里的图片生成模型/服务商中，支持用户配置 Grok 中转 Base URL、模型和 API Key；图片生成继续走现有串行队列，一个一个生成。

# approach

扩展图片 provider 类型为 `openai | doubao | grok`；新增 `grokImageProvider` 配置和设置 UI 表单；Grok 走 OpenAI 兼容 HTTP 分支；provider 元数据和提示文案区分 Grok。保持现有 OpenAI/豆包配置兼容。

# result

已在设置页“图片生成”新增 Grok 图片生成服务商，支持独立配置 `providerName/modelId/baseUrl/apiKey`，默认模型 `grok-imagine-image-quality`，默认 Base URL `https://api.x.ai/v1`。后端新增 `grokImageProvider` 持久化与公开状态，`activeImageProvider=grok` 时调用 Grok 文生图/图生图 JSON 接口；候选图、角色参考图和场景参考图继续走现有串行队列。验证通过：`corepack pnpm --filter @airoaming/shared build && corepack pnpm -r typecheck`、`corepack pnpm -r --parallel --filter @airoaming/shared --filter @airoaming/server test`。

2026-07-09 真实中转测试：设置已保存且当前生效 provider 为 `grok`，但用户配置的中转 `/models` 只暴露 `gpt-image-1`、`gpt-image-1.5`、`gpt-image-2`，没有 Grok/Imagine 模型；`grok-imagine-image-quality` 和 `grok-imagine-image` 请求 `/images/generations` 均返回 400：`images endpoint requires an image model`。结论：应用配置链路可读到 Grok 设置，但当前中转未提供 Grok 图片模型映射，真实出图未通过。

用户截图显示中转后台模型库里存在 `grok-imagine`、`grok-imagine-image`、`grok-imagine-image-quality`、`grok-imagine-edit` 等模型；随后逐个请求 `/images/generations` 验证，四个模型均返回 400：`images endpoint requires an image model`。判断为后台模型库存在，但当前 API Key/用户分组/图片端点路由未把这些模型作为 image model 暴露。

用户再次调整后复测：`grok-imagine-image-quality`、`grok-imagine-image`、`grok-imagine` 请求 `/images/generations` 均返回 503：`Service temporarily unavailable`；同一 API Key 请求 `/models` 返回 200，但可见模型只有 Claude 系列，没有 Grok/Image/Imagine。结论：当前 API Key/用户分组仍未暴露截图中的 Grok 图片模型，或 Grok 图片渠道上游不可用。

用户修正中转配置后再次复测成功：当前 API Key 的 `/models` 可见 Grok/Imagine 模型列表，使用设置中的 `grok-imagine-image-quality` 请求 `/images/generations` 返回 200，耗时约 9.5 秒，响应为 `b64_json`，已保存测试图片到 `workspace/grok-test/grok-generation-grok-imagine-image-quality-2026-07-09T13-31-29-376Z.png` 并人工查看确认图片正常。

队列复核：`ProjectsService.onModuleInit` 将 `image_generate` worker 注册为 `ImageCandidateService.runTaskSerialized`；`runTaskSerialized` 通过 `imageQueue` 等待上一个任务完成后才执行当前任务；同一个 `image_generate` 任务内的 `candidateCount` 循环也逐次 `await imageProvider.generateImage/editImage`，上一张返回并写入内存结果后才请求下一张。角色/场景参考图也通过 `CharacterReferenceService.characterReferenceQueue` 串行执行。
