## 1. 状态

已采纳。

## 2. 背景

用户明确提出 AI漫游需要学习 OpenCode 的“深思熟虑”能力，并指出这套能力不是单个文件，而是多个文件共同形成的工作流。

经回查 AuroraPlatformWeb，相关能力主要由以下部分组成：

- 前端“深思熟虑”高推理预设。
- OpenCode autonomous 父 Agent。
- Worker 执行 Agent。
- Scrutiny Validator。
- Runtime Validator。
- long_task 三件套。
- workflow 和 findings 单一事实源规则。
- Handoff 交接结构。

## 3. 决策

AI漫游引入“深思熟虑工作流契约”，作为复杂任务的强制流程。

新增：

- `文档/02_架构与契约/深思熟虑工作流契约.md`
- `文档/90_模板/深思熟虑任务包模板.md`
- `文档/05_执行与记录/任务记录/README.md`

并更新：

- `AGENTS.md`
- `文档/README.md`
- `文档/00_索引/AI上下文入口.md`
- `文档/00_索引/写作规范与留痕规则.md`

## 4. 理由

| 需求 | 决策理由 |
| --- | --- |
| 项目会变复杂 | 复杂任务必须有阶段计划和证据 |
| AI 需要长期接力 | 三件套能恢复上下文 |
| 生成类产品容易漂移 | 单一事实源和复核能减少跑偏 |
| 后续会有真实产物 | Runtime/User Review 能避免只停在文档或代码层 |
| 功能要有记录 | 完成记录和验收证据能支撑回溯 |

## 5. 不直接照搬的内容

| Aurora 内容 | AI漫游处理 |
| --- | --- |
| 脑训练 workflow 阶段 | 改成 AI漫游漫画/轻漫剧阶段 |
| Phaser 验证 skill | 改成网页工作台、任务状态、导出物、素材追溯验收 |
| `workflow_patch` 工具 | 当前先用 Markdown 状态记录，后续可实现 JSON workflow |
| 强制每阶段 Git 版本 | 当前先记录文件和验证，等工程成熟后再引入 |
| validation-contract.md | 当前先用验收清单，复杂阶段再升级 |

## 6. 影响

### 正向影响

- M1 开始就有规范任务目录。
- AI 不会直接从模糊需求跳到实现。
- 每个复杂功能都有计划、进度、发现、复核和完成记录。
- 后续可平滑升级为真实 agent/workflow 执行体系。

### 代价

- 文档维护量增加。
- 小任务需要判断是否适用完整流程。
- 同一个 AI 需要在当前阶段内主动切换 Worker 和 Reviewer 视角。

## 7. 验收标准

- 深思熟虑契约文档存在。
- 深思熟虑任务包模板存在。
- AGENTS 和 AI 入口明确要求复杂任务进入该流程。
- 后续 M1 任务使用该模板创建任务记录。
