## 1. 用途

本文档回答一个核心问题：

> AI漫游不是聊天产品，那么工作台里到底有哪些功能？

结论：左侧 AI 对话只是命令入口和解释层，真正的产品主体是中央的阶段工作面板。

## 2. 产品形态判断

AI漫游应是“对话驱动的生产工作台”，不是“带几个按钮的聊天窗口”。

```text
AI 对话
  -> 解析用户意图
  -> 创建或推进生成任务
  -> 把结果写入业务对象
  -> 中央工作面板展示、编辑、确认
  -> 用户选择、锁定、导出
```

## 3. 工作台三栏职责

| 区域 | 职责 | 不负责 |
| --- | --- | --- |
| 左侧命令区 | 项目上下文、AI 对话、自然语言指令、快速创建 | 不承载完整编辑器，不展示最终产物全集 |
| 中央工作区 | 当前阶段的主要功能面板、编辑、选择、确认、预览 | 不承载长聊天历史 |
| 右侧辅助区 | 任务队列、当前对象检查器、AI 下一步建议、风险提示 | 不做团队协作、商业化、复杂设置 |

## 4. 工作台功能面板

当前 MVP 应按六个功能面板组织，而不是只按“聊天输出”组织。

| 面板 Key | 名称 | 阶段 | 状态 | 目标 |
| --- | --- | --- | --- | --- |
| `project_story` | 项目与故事 | M1 | current | 创建项目、输入故事、保存原文 |
| `story_structure` | 剧情结构 | M1 | current/next | 将故事拆成摘要、角色、场景、剧情节拍 |
| `storyboard` | 分镜工作台 | M1 | next | 根据剧情节拍生成和编辑分镜 |
| `image_candidates` | 候选图工作台 | M2 | next | 为分镜生成多候选图，选择并锁定 |
| `layout_export` | 排版导出 | M3 | next | 基于锁定候选排版漫画页并导出 |
| `asset_package` | 素材包 | M3 | next | 归档故事、分镜、候选、导出物和 manifest |

## 5. 面板一：项目与故事

### 5.1 用户目标

用户进入后首先要做两件事：

- 创建或打开项目。
- 输入故事原文或章节大纲。

### 5.2 输入

| 输入 | 来源 | 必需 |
| --- | --- | --- |
| 项目名称 | 用户输入 | 是 |
| 项目类型 | 用户选择：漫画 / 轻漫剧 / 混合 | 是 |
| 简介 | 用户输入 | 否 |
| 故事原文 | 用户粘贴 | 是 |

### 5.3 主要操作

| 操作 | 结果 |
| --- | --- |
| 创建项目 | 生成 `Project` 和初始 `StoryVersion` |
| 打开项目 | 加载 `WorkbenchSnapshot` |
| 编辑故事原文 | 更新当前故事版本 |
| 保存草稿 | 保留原文和项目状态 |
| 发起剧情结构化 | 创建 `story_parse` 任务 |

### 5.4 中央区应该展示

| 区块 | 说明 |
| --- | --- |
| 项目基础信息 | 名称、类型、状态、更新时间 |
| 故事原文编辑区 | 大文本编辑器，不只是只读输出 |
| 保存/结构化动作 | 保存草稿、结构化故事 |
| 最近项目 | 未打开项目时展示 |

### 5.5 右侧区应该展示

- 当前项目状态。
- 缺失字段检查。
- 下一步建议：补故事 / 运行结构化。

## 6. 面板二：剧情结构

### 6.1 用户目标

把自然语言故事变成分镜可用的结构化数据。

### 6.2 输入

| 输入 | 来源 |
| --- | --- |
| `StoryVersion.sourceText` | 项目与故事面板 |
| 整理方式 | 忠实整理 / 强化节奏 / 漫画节奏 |
| 用户补充要求 | 左侧对话或面板表单 |

### 6.3 输出

```json
{
  "summary": "一句话摘要",
  "characters": [],
  "scenes": [],
  "beats": []
}
```

### 6.4 中央区应该展示

| 区块 | 说明 |
| --- | --- |
| 摘要卡 | 可编辑的一句话摘要和故事基调 |
| 角色表 | 角色名、身份、外观、关系、备注 |
| 场景表 | 场景名、地点、氛围、时间、备注 |
| 剧情节拍列表 | 节拍顺序、事件、角色、场景、对白线索 |
| 结构化 JSON 预览 | 面向 AI 和开发者的可复制结构 |

### 6.5 主要操作

| 操作 | 结果 |
| --- | --- |
| 运行结构化 | 创建 `story_parse` 任务 |
| 编辑角色 | 更新结构化剧情 |
| 编辑场景 | 更新结构化剧情 |
| 编辑节拍 | 作为分镜生成输入 |
| 确认可生成分镜 | 将故事状态推进到 `story_ready` |

### 6.6 右侧区应该展示

- `story_parse` 任务进度。
- 结构完整性检查：是否有摘要、角色、场景、节拍。
- AI 建议：缺角色、节拍太少、场景不清等。

## 7. 面板三：分镜工作台

### 7.1 用户目标

把剧情节拍变成连续、可编辑、可生成图片的镜头列表。

### 7.2 输入

| 输入 | 来源 |
| --- | --- |
| `StoryBeat[]` | 剧情结构面板 |
| 角色/场景模板 | 剧情结构面板 |
| 分镜生成偏好 | 镜头数量、节奏、画幅 |

### 7.3 输出

| 输出 | 说明 |
| --- | --- |
| `Shot[]` | 分镜数组 |
| `promptDraft` | 每个分镜的图片提示词草稿 |

### 7.4 中央区应该展示

| 区块 | 说明 |
| --- | --- |
| 分镜列表/卡片 | 每个镜头一张卡 |
| 分镜字段编辑 | 场景、角色、动作、对白、镜头、情绪 |
| 顺序调整 | 上移、下移、拖拽或编号 |
| 批量操作 | 生成分镜、重新生成选中、确认进入候选图 |
| 视图切换 | 卡片视图 / 表格视图 |

### 7.5 主要操作

| 操作 | 结果 |
| --- | --- |
| 生成分镜 | 创建 `shot_generate` 任务 |
| 编辑分镜 | 更新 `Shot` |
| 添加分镜 | 新增 `Shot` |
| 删除分镜 | 标记删除或移除草稿 |
| 生成提示词 | 创建 `shot_prompt_generate` |
| 确认可生图 | 分镜状态进入 `ready_for_image` |

### 7.6 右侧区应该展示

- 当前选中分镜详情。
- 分镜完整性检查：角色、动作、镜头是否缺失。
- AI 建议：节奏、镜头重复、对白过长。

## 8. 面板四：候选图工作台

### 8.1 用户目标

为一个或多个分镜生成漫画图候选，并选择锁定可进入排版的图片。

### 8.2 输入

| 输入 | 来源 |
| --- | --- |
| `Shot` | 分镜工作台 |
| `promptDraft` | 分镜或提示词任务 |
| 角色/场景约束 | 剧情结构 |
| 风格参数 | 项目设置或面板输入 |

### 8.3 输出

| 输出 | 说明 |
| --- | --- |
| `Candidate[]` | 候选图 |
| `Asset(image)` | 图片资产 |
| `lockedCandidateId` | 每个分镜最多一个锁定候选 |

### 8.4 中央区应该展示

| 区块 | 说明 |
| --- | --- |
| 分镜选择栏 | 选择要生成候选的分镜 |
| 生成参数面板 | 数量、比例、风格、参考角色 |
| 候选图网格 | 按分镜分组展示候选 |
| 候选对比 | 查看生成输入、种子、provider 元数据 |
| 锁定操作 | 选择、锁定、废弃、重生成 |

### 8.5 主要操作

| 操作 | 结果 |
| --- | --- |
| 生成候选 | 创建 `image_generate` 任务 |
| 选择候选 | 标记 `selected` |
| 锁定候选 | 标记 `locked`，进入排版输入 |
| 废弃候选 | 标记 `rejected` |
| 重生成 | 创建新 `image_generate` 任务 |

### 8.6 右侧区应该展示

- 当前候选详情。
- 生成输入和提示词。
- 角色一致性风险提示。
- 当前分镜是否已锁定。

## 9. 面板五：排版导出

### 9.1 用户目标

把已锁定候选图排成漫画页，并导出 PNG/PDF。

### 9.2 输入

| 输入 | 来源 |
| --- | --- |
| 已锁定 `Candidate` | 候选图工作台 |
| 页面模板 | 排版面板 |
| 对白/旁白 | 分镜 |

### 9.3 输出

| 输出 | 说明 |
| --- | --- |
| `LayoutPage` | 页面布局 |
| `PanelPlacement[]` | 格子布局 |
| `Asset(image/pdf)` | 导出页面 |

### 9.4 中央区应该展示

| 区块 | 说明 |
| --- | --- |
| 页面列表 | 页码、状态、导出情况 |
| 页面画布 | 漫画格子预览 |
| Panel 列表 | 每格对应分镜和候选图 |
| 基础排版操作 | 选择模板、调整顺序、生成页面 |
| 导出动作 | 导出 PNG/PDF |

### 9.5 主要操作

| 操作 | 结果 |
| --- | --- |
| 创建页面 | 生成 `LayoutPage` |
| 放置分镜 | 生成 `PanelPlacement` |
| 调整顺序 | 更新页面布局 |
| 导出页面 | 创建 `layout_export` 任务 |

### 9.6 右侧区应该展示

- 当前页面检查：是否有未锁定候选。
- 导出设置简版：格式、范围。
- 导出任务进度。

## 10. 面板六：素材包

### 10.1 用户目标

归档并导出项目素材，让后续制作或外部工具可复用。

### 10.2 输入

- 项目元数据。
- 故事结构。
- 分镜。
- 候选图和锁定图。
- 页面导出物。

### 10.3 输出

```text
manifest.json
story.json
shots.json
characters.json
scenes.json
assets/
  images/
  pages/
```

### 10.4 中央区应该展示

| 区块 | 说明 |
| --- | --- |
| 素材清单 | 按类型列出资产 |
| 追溯关系 | 资产来源任务、分镜、候选 |
| 包内容预览 | manifest 和文件树 |
| 导出素材包 | 生成 zip 或目录 |

### 10.5 右侧区应该展示

- 缺失资产检查。
- 孤儿素材提示。
- 导出包任务进度。

## 11. 对话与功能面板的关系

对话不是工作台主体，而是一个“命令和解释层”。

| 用户在左侧说 | 系统应该做 |
| --- | --- |
| “帮我把这个故事拆一下” | 触发 `story_parse`，中央切到剧情结构面板 |
| “生成 8 个分镜” | 触发 `shot_generate`，中央切到分镜工作台 |
| “第 3 个分镜换成近景” | 更新选中 `Shot.camera` |
| “给第 2 镜生成 4 张候选” | 触发 `image_generate`，中央切到候选图工作台 |
| “锁定第二张” | 更新候选状态为 `locked` |
| “导出第一页” | 触发 `layout_export` |

## 12. 下一轮前端改版原则

下一轮前端不应继续强化聊天流，而应：

1. 将中央 `OutputPane` 改为 `WorkbenchSurface`。
2. 使用面板 Tab：`项目故事 / 剧情结构 / 分镜 / 候选图 / 排版导出 / 素材包`。
3. 每个 Tab 至少有：
   - 输入区
   - 操作区
   - 结果区
   - 状态/校验区
4. 右侧 `RightRail` 根据当前面板切换：
   - 任务队列
   - 当前对象检查器
   - 下一步建议
5. 左侧对话区缩小为命令入口，不再承担主视觉。

## 13. 验收标准

前端完成工作台功能改版后，应满足：

- 用户无需通过聊天也能完成当前阶段的主要操作。
- 用户通过聊天触发任务后，中央面板能显示对应结果。
- 每个 MVP 阶段都有明确入口、状态和下一步。
- 未实现阶段只显示为 `next`，不能伪装成可用功能。
- 右侧能解释当前对象或当前任务，而不是展示无关信息。
