## 发现

- `MVP范围与路线图.md` 已经清楚定义了 M1/M2/M3 功能，但前端还没有形成对应工作面板。
- 当前 UI 的左侧对话区承担太多注意力，中央区仍偏“输出展示”，缺少编辑、选择、确认等功能动作。
- 功能矩阵解决了“不要展示什么”，但还需要补充“每个阶段具体怎么工作”。

## 决策

| Decision | Rationale |
| --- | --- |
| 把对话降级为命令入口 | 避免产品变成聊天壳 |
| 中央区改为阶段工作面板 | 每个 MVP 阶段都要有可操作表面 |
| 右侧区改为任务/检查器/建议 | 保留生产辅助，不做团队协作 |
| 下一轮前端按工作面板实现 | 先文档化，再编码 |

## 复核结论

| 检查项 | 结论 |
| --- | --- |
| 覆盖 M1 | 已覆盖项目与故事、剧情结构、分镜工作台 |
| 覆盖 M2 | 已覆盖候选图工作台 |
| 覆盖 M3 | 已覆盖排版导出和素材包 |
| 面板结构 | 每个面板均定义输入、操作、输出和右侧辅助区 |
| 范围约束 | 未引入搜索、通知、团队协作、商业化等超范围能力 |
