## 1. 当前结论

```text
应用入口：项目库
项目内部：项目工作区
项目主流程：6 步
```

当前页面位置必须由前端路由表达，业务状态由 Pinia、后端 API 和后续持久化层表达。

```text
/projects
/projects/:projectId/script
/projects/:projectId/structure
/projects/:projectId/storyboard
/projects/:projectId/candidates
/projects/:projectId/layout
/projects/:projectId/assets
```

`/projects/:projectId` 默认重定向到 `/projects/:projectId/script`。

剧本步骤后续应支持章节级定位。当前推荐路由形态为：

```text
/projects/:projectId/script
/projects/:projectId/script/:chapterId
```

其中 `/projects/:projectId/script` 默认打开当前项目的活跃章节；`:chapterId` 用于刷新、分享或返回时恢复到明确章节。

页面结构必须先服务真实工作流，而不是先做营销式欢迎页、对话页或展示型大图。

## 2. 页面一：项目库

用途：

- 查看项目。
- 创建项目。
- 打开项目。
- 删除项目。
- 看到简化创作流程。

主要内容：

- 顶部品牌：绘界漫画。
- 项目列表或项目卡片。
- 新建项目入口。
- 项目卡片封面 hover 删除入口。
- 项目状态和更新时间。
- 轻量任务队列入口。

不展示：

- 升级计划。
- 最近活动大面板。
- 团队协作。
- 常驻右侧栏。
- 常驻对象检查器。
- 常驻下一步建议。
- 顶部搜索框。
- 大面积营销 hero 文案。

## 3. 页面二：项目工作区

进入规则：

- 创建项目成功后直接进入项目工作区。
- 打开已有项目后直接进入项目工作区。
- 默认打开第 1 步“剧本”。
- 默认首屏布局必须是左侧公共“对话框”、右侧“剧本文档编辑器”。
- 不再进入旧的“项目与故事”表单页。

顶部：

- 返回项目列表按钮。
- 项目名称。
- 紧凑 6 步流程栏。

不展示：

- 顶部搜索框。
- 全局左侧导航。
- 大 hero 图。
- 常驻右侧栏。
- 下一步建议。
- 对象检查器。

主体：

- 左侧公共“对话框”。
- 右侧当前步骤主文档或工作内容。
- 第 1 步“剧本”的右侧主工作区必须是剧本文档编辑器。
- 第 1 步“剧本”需要章节列表或章节切换器，用于显示当前项目下的章节顺序、标题和状态。
- 当前剧本文档编辑器只展示剧本正文，不展示项目名称、故事标题、题材标签、漫画格式和画风方向等字段。
- 第 1 步“剧本”的最右侧辅助面板是“当前章节信息”，只展示当前章节、故事主线、出场角色和场景列表，不再展示旧的假剧本大纲。
- 章节列表负责管理章节导航和状态；当前章节信息面板只解释当前章节内容，不承担完整章节管理。

对话框定义：

- “对话框”不是弹窗，是项目内左侧常驻 AI 对话面板。
- 对话框是公共能力，剧本、剧情结构、分镜等步骤都可复用。
- 对话框组件公共，但对话记录按步骤隔离，不把整个项目的聊天历史混成一条流。
- 切换步骤时，对话框加载当前步骤的对话记录，并注入当前步骤提示词、当前步骤产物和项目级已确认事实。
- 项目级共享上下文只包含用户已确认的事实、文档和产物；未应用、未插入、未保存、未锁定或未确认的聊天内容不自动带入其他步骤。
- 对话框当前支持询问内容、给出建议、总结和改写版本，并可选择 provider/model 后发送流式消息。
- 上传剧本、停止生成、应用到剧本和插入光标是后续能力。
- AI 输出不能自动覆盖右侧文档，必须由用户点击“应用”或“插入”后才进入文档。

## 4. 六个项目内页面

| 顺序 | 页面 | 主目标 |
| --- | --- | --- |
| 1 | 剧本 | 按章节编辑和保存剧本正文；支持保存草稿、完成本章并进入下一章；上传和应用/插入后续补齐 |
| 2 | 剧情结构 | 将当前章节故事整理为摘要、角色、场景、节拍 |
| 3 | 分镜工作台 | 基于当前章节生成和编辑镜头列表 |
| 4 | 候选图工作台 | 为当前章节分镜生成、比较、选择并锁定候选图 |
| 5 | 排版导出 | 生成当前章节漫画页面并导出 |
| 6 | 素材包 | 归档项目素材、章节产物和 manifest |

章节是 6 步主流程下的工作单元。用户可以先完成第 1 章，再进入第 2 章；也可以回到已完成章节继续修改，但修改后需要提示后续结构化剧情、分镜、图片或排版可能需要重新生成。

## 5. 辅助入口

| 辅助入口 | 当前状态 | 处理 |
| --- | --- | --- |
| 搜索 | `deferred` | 项目库和项目工作区均暂不展示顶部搜索，后置实现 |
| 任务队列 | `current` | 可以作为顶部轻量入口 |
| 通知铃铛 | `deferred` | 后置，不进入主路径 |
| 用户头像 | `ui_shell` | 可以展示，但不做团队和账号系统 |
| 对象检查器 | `deferred` | 后置为抽屉、弹层或局部详情，不默认常驻 |
| 下一步建议 | `deferred` | 后置为局部辅助，不默认常驻 |
| 对话框 | `current` | 项目内公共 AI 面板，左侧常驻，不是弹窗 |
| 步骤对话记录 | `current` | 按 `projectId + stepKey` 隔离记录，避免不同步骤互相污染 |
| 项目级已确认事实 | `current` | 仅保存用户已确认的故事、角色、世界观、风格、结构、分镜和锁定结果 |
| 章节列表 | `current` | 剧本步骤内已展示章节顺序、标题、正文预览和状态，并支持切换当前章节 |
| 完成本章 | `current` | 保存当前章节，标记章节状态，并创建或进入下一章 |

## 6. 设计原则

- 主工作区优先。
- 项目库先于项目工作区。
- 项目工作区先显示流程和当前步骤。
- 项目工作区隐藏全局左侧导航，避免项目内创作被全局入口挤压。
- 顶部搜索不进入当前项目库和项目工作区，先用项目卡片、筛选、返回项目列表和流程导航保持界面清晰。
- AI 只提出建议和可应用改写，用户必须显式确认后才改动正文。
- 对话上下文默认遵循“步骤内连续、项目级事实共享”的原则，避免前一步未确认的聊天假设污染后续步骤。
- 参考图只借鉴信息密度、图标语言和工作台气质，不直接搬功能。
- 未实现能力必须灰态或后置，不能伪装成当前可用。
