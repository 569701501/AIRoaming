## 1. 当前结论

应用入口采用“项目库优先”。

用户路径：

```text
进入应用
  -> 项目库
  -> 新建项目 / 打开项目
  -> 项目工作区
  -> 默认进入第 1 步“剧本”
  -> 选择或创建当前章节
  -> 左侧对话框 + 章节列表 + 右侧剧本文档编辑器
  -> 通过 7 步流程推进项目和当前章节
```

当前不再沿用旧六面板试错页面、输出 Tab 页面或大面积 hero 工作台。下一版代码实现必须先对齐本文档和 `文档/01_愿景与产品/当前UI信息架构.md`。

## 2. 品牌与命名

| 类型 | 名称 | 用途 |
| --- | --- | --- |
| 项目内部代号 | AI漫游 | 文档、代码、仓库、内部讨论 |
| 前端展示品牌 | 绘界漫画 | 用户界面展示 |

如果代码、文档、UI 同时出现两个名称，按上表理解，不应再混用为两个产品。

## 3. 全局导航

当前全局导航只保留轻量入口：

| 入口 | 当前状态 | 说明 |
| --- | --- | --- |
| 项目库 | current | 应用默认入口 |
| 素材库 | planned | 全局素材视图，后续实现 |
| 任务队列 | current | SQLite 持久任务、重启恢复、协作取消、有限重试、资源并发槽和 legacy 历史分层均已实现；内存只保留唤醒信号和当前取消控制器 |
| 设置 | current | 文本 key 归 OpenCode，图片 key 归后端 SecretStore；页面只做单向写入/替换/清除和非秘密状态展示 |

不再同时展示“工作台”和“项目”两个并列主入口。

## 4. 项目库页面

用途：

- 查看所有项目。
- 创建项目。
- 打开项目。
- 删除项目。
- 展示简化的 7 步创作流程说明。

可以展示：

- 项目卡片。
- 项目状态。
- 新建项目入口。
- 项目筛选。
- 项目卡片封面 hover 删除按钮。
- 删除二次确认弹窗。
- 任务队列轻量入口。

创建项目只创建项目记录。项目库中的创建按钮、`CreateProjectModal.vue`、提交调用和成功后进入剧本步骤均已存在；同一弹窗包含两个必填字段：`项目名称` 和 `漫画版式`。漫画版式默认空，只提供“竖向条漫/分页漫画”，用户明确选择后才能创建，创建后不可直接修改。四格属于画布布局模板。弹窗不要求填写剧本、故事标题、题材标签、画风方向或故事原文。正式决策见 `ADR-0009`。

创建项目成功后：

```text
关闭创建弹窗
  -> 直接进入项目工作区
  -> 默认打开第 1 步“剧本”
  -> 左侧显示公共对话框
  -> 右侧显示剧本文档编辑器
```

不展示：

- 升级计划。
- 团队协作。
- 最近活动大面板。
- 大型右侧栏。
- 常驻对象检查器。
- 常驻下一步建议。
- 大面积营销 hero 文案。

## 5. 项目工作区页面

用途：

- 围绕当前项目进行创作。
- 显示返回项目列表按钮。
- 显示 7 步流程。
- 根据当前步骤展示主工作面板。

顶部可包含：

- 返回项目列表按钮。
- 项目名称。
- 7 步流程条。

主体应包含：

- 左侧公共“对话框”。
- 当前步骤需要的对象导航，例如剧本步骤的章节列表。
- 右侧当前步骤主文档或工作内容。

不默认展示：

- 全局左侧导航。
- 顶部搜索框。
- 大 hero 图。
- 常驻右侧栏。
- 剧本页最右侧“当前章节信息”面板。
- 常驻下一步建议。
- 常驻对象检查器。

主工作区优先，辅助信息不能挤压主要创作空间。

“对话框”是项目内公共 AI 面板，不是弹窗。它随当前步骤切换注入不同提示词和上下文。对话框组件公共，但对话记录按步骤隔离：剧本、剧情结构、分镜等步骤各自维护对话记录，项目级只共享用户已确认的事实、文档和产物。章节工作流下，剧本步骤还需要进一步按 `chapterId` 隔离对话。剧本阶段承担两类来源：AI 创作路线先确认大纲和轻量章节安排，再按章生成；已有剧本路线先确认整本拆章目录，再生成全部待确认章节并逐章只读确认。两条路线最终都形成正式 `ChapterScriptVersion`。AI 只能通过 AI漫游受控工具/API 处理章节，不能直接操作本地物理路径或绕过章节契约。

当前实现：

- 项目库点击 `继续创作` 进入项目工作区。
- 创建项目成功后进入项目工作区。
- 工作区顶部区域提供 `返回项目库`。
- 工作区主体展示紧凑 7 步流程栏；用户可见目标口径为 `剧本 -> 剧情结构 -> 分镜工作台 -> 出图准备 -> 候选图工作台 -> 漫画成稿 -> 素材包`。第 6 步内部 stepKey 继续使用 `layout_export`，现有路由继续使用 `/layout`。
- 项目工作区已隐藏全局左侧导航和顶部搜索。
- 当前已实现左侧“对话框”和右侧“剧本文档编辑器”，右侧只展示剧本正文，支持保存剧本草稿。
- 产品口径已废弃剧本页最右侧“当前章节信息”面板；主角和常驻角色进入项目角色库查看、调整生图描述 / prompt、生成角色图或锁定角色定稿，主线、场景和本章结构进入剧情结构步骤查看，均不在剧本页常驻展示。
- 剧本步骤对话已接入 OpenCode：支持发送消息、流式展示 assistant 回复，并按当前步骤加载对话记录；模型列表读取和 provider/model 透传链路存在，但可见模型选择控件需恢复或重做。
- 剧情结构、分镜、出图准备、候选图和漫画成稿均已有真实工作面板；现有 G5 已完成成稿编辑、版本与出版基础。2026-07-24 漫画成稿按 ADR-0022 收缩为基础版：首次无稿自动生成一次完整 V2 成稿，有稿直接恢复；之后只在同一画布逐项编辑并自动保存。页面不再提供二次智能调整、范围/intent、建议对比、撤销重做或手动保存，只保留手机预览和一个导出入口。导出对正式对白/旁白 fail-closed，用户主动文字变化以原文/当前文字弹窗确认。视觉分析不可用时继续规则回退，不宣称主体识别已通过。
- 停止生成、完整回退、手动新建/重命名/删除章节和后续产物失效提示仍未接入，不能当作已完成能力。
- 第 1～6 步已完成 G0～G5 的真实业务闭环；第 7 步素材包仅保留导航和历史骨架，G6 后置。

### 5.1 章节列表与章节推进

剧本步骤需要章节列表或章节切换器。章节列表只管理项目内章节，不恢复全局左侧导航。

章节列表当前定位：

| 功能 | 当前状态 | 说明 |
| --- | --- | --- |
| 查看章节 | `current` | 显示章节顺序、标题、状态和更新时间 |
| 切换章节 | `current` | 切换后右侧编辑器加载当前章节剧本 |
| 保存章节草稿 | `current` | 保存当前章节正文，不推进到下一章 |
| AI 创作：完成本章 | `current` | 发布当前章节正式版本；页面停留当前章。只有已确认大纲存在下一章卡时才增加下一章入口 |
| AI 创作：生成当前章 | `current` | 大纲确认、裸“继续”和切换章节都不触发生成；用户在当前章对话框明确提出后才生成，且第 N 章要求第 N-1 章已有正式版本 |
| 已有剧本：确认拆章目录 | `current` | 整本确认一次章节数量、顺序、原稿范围、排除范围和建议标题；立即创建全部章节入口并返回，后台完成整批生成尝试，结果卡自动刷新进度 |
| 已有剧本：失败章重试 | `current` | 只对一个 `generation_failed` 章节重新执行整理与忠实度验证，不修改目录、成功章节或正式版本 |
| 已有剧本：确认章节 | `current` | 完整只读查看当前导入 pending 后原子发布为正式版本；不提供采用、丢弃、手动修改、AI 重新整理或批量确认 |
| 回到上一章编辑 | `current` | 修改进入 Working Copy；再次确认后形成新版本，旧下游历史保留并派生来源已更新 |

章节是数据库一等实体，通过后端 API、不可变版本和任务来源追溯；DB-only 运行时不再以 workspace 文件作为业务事实源。

## 6. 七个项目内页面

| 顺序 | 页面 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| 1 | 剧本 | AI 创作按“大纲与章节卡—显式生成单章 pending—完整查看—采用编辑—完成本章”推进；已有剧本按“原稿分析—目录确认—整批 pending—逐章确认”推进。两条路线均已接通；页面继续展示固定格式章节剧本，不新增常驻字段面板 | current |
| 2 | 剧情结构 | 按当前章节逐章生成结构化剧情；AI 生成、字段编辑和重新分析统一进入 pending Working Copy，确认后形成不可变 StoryVersion；上游变化只派生 stale，不删除历史 | current/completed_g2 |
| 3 | 分镜工作台 | 按当前章节逐章生成和编辑 `Shot`；一次生成内部先形成分镜骨架，再整章自动整理详细候选图说明，两段都通过后才写 pending StoryboardVersion。重新生成本身不切换正式链；已有下游成果时，确认新版本前展示出图准备、候选、定稿、排版和导出影响，切换后旧产物保留为历史、出图准备变为“需更新”，章节最远里程碑不倒退 | current/completed_g2 |
| 4 | 出图准备 | 检查正式分镜、出镜角色、参考图和画风；确认不可变 PreflightRevision 并保存聚合来源摘要，来源变化显示“需更新” | current/completed_g2 |
| 5 | 候选图工作台 | 默认展示分镜生成时已自动整理的画面/动作/构图，允许本地微调并检查单帧硬问题；个别镜头可按需“重新优化本镜头”并显式采用返修建议；生成多候选图后收藏比较，定稿/更换/取消形成线性 CandidateLockRevision，更换前展示下游影响 | current/completed_g4 |
| 6 | 漫画成稿 | 普通首次进入零配置生成一次完整初稿，自动完成分页/分段、画格布局、非破坏裁切、阅读顺序、对白/旁白、气泡和尾巴；随后只在同一编辑器逐项调整并自动保存。唯一导出入口内收双重预检、不可变 Revision 与确定性 publication；系统文字错误阻断，用户文字变化对照确认 | current/basic_editor_complete；V2 正式出版已接通 |
| 7 | 素材包 | 归档项目共享素材、章节产物、manifest 和交付素材；七阶段导航与现有骨架保留 | skeleton/deferred_later；G6 开发文档与 ZIP 能力后置 |

这 7 个页面仍是项目内主流程，不改回六阶段。第 6 步的零配置初稿、人工画布、自动保存、手机预览和单一正式导出已接通；二次智能排版及其复杂控制不再属于目标产品。后续只单独优化具体编辑控件和初稿视觉质量，不另建“AI 生成页”或第二套导出服务。第 7 步 G6 保留但后置。轻漫剧基础版不进入当前 7 步 UI 主流程。

`项目角色库` 是常驻资产入口，不再作为顶部主流程步骤。顶部“角色库”默认应打开项目内弹窗/抽屉，保留当前章节步骤上下文；弹窗默认显示当前章节相关角色、当前阻塞角色和待处理新角色，并提供 `查看全部角色` 切换到全量角色库。`/projects/:projectId/characters` 可作为深度维护或路由兼容入口保留。当前代码已新增 `/projects/:projectId/preflight` 出图准备页面。

## 7. UI 元素状态

| UI 元素 | 当前状态 | 处理 |
| --- | --- | --- |
| 搜索 | `deferred` | 当前项目库和项目工作区都不展示顶部搜索 |
| 任务队列 | `current` | 轻量入口可以保留 |
| 项目删除 | `current` | 只在项目卡片封面 hover 时显示删除入口；确认后删除项目记录和本地 workspace 项目目录 |
| 通知铃铛 | `deferred` | 先不展示，或仅作为视觉占位但不进主流程 |
| 用户头像 | `ui_shell` | 可以展示，但不做团队/账号系统 |
| 对象检查器 | `deferred` | 不默认常驻右侧 |
| 下一步建议 | `deferred` | 不默认常驻右侧，可后续做抽屉或局部卡片 |
| 当前章节信息面板 | `deprecated/removed` | 剧本页不再常驻展示当前章节、故事主线、出场角色和场景列表；常驻面板代码已从剧本页移除 |
| 对话框 | `current` | 项目内公共 AI 对话面板，左侧常驻，不是弹窗 |
| 步骤对话记录 | `current` | 每个步骤独立记录对话历史，切换步骤时只加载当前步骤记录 |
| 项目级已确认事实 | `current` | 跨步骤共享已确认事实和产物，不共享未确认聊天假设 |
| 章节列表 | `current` | 剧本步骤内显示和切换章节，不作为全局导航 |
| AI 创作完成本章 | `current` | 保存当前章节、发布正式版本并标记章节状态；仅在大纲存在下一章卡时增加入口，不自动切换 |
| 已有剧本确认章节 | `current` | 当前导入 pending 原子发布为正式版本并允许进入本章剧情结构；其他章节状态不阻塞 |

## 8. 页面能力状态

| 状态 | 含义 | UI 规则 |
| --- | --- | --- |
| `current` | 当前版本要围绕它设计 | 可以进入主路径 |
| `ui_shell` | 可以有界面壳，但没有完整真实能力 | 必须弱化或明确标识 |
| `next` | 后续核心能力 | 可以在流程中展示状态，但不伪装可用 |
| `deferred` | 当前不做或后置 | 不占据主流程空间 |
| `deprecated` | 已被当前产品口径废弃 | 不再进入目标 UI；历史记录可保留但必须标明废弃 |

## 9. 禁止事项

- 不把参考图里的搜索、通知、团队、升级计划直接搬进当前产品。
- 不把对象检查器或下一步建议做成默认右侧常驻栏。
- 不用大 hero 图抢占项目工作区主内容。
- 不把轻漫剧基础版混入当前漫画 7 步主流程。
- 不把归档中的旧 UI 试错文档当作当前事实源。
- 不允许 AI 直接操作本地物理路径；剧本阶段 AI 写入章节草稿必须通过 AI漫游受控工具/API，并保留来源追溯。
- 不把整个项目的原始聊天历史自动注入每个步骤；跨步骤上下文必须来自用户已确认事实、保存文档和锁定产物。
- 不把章节只做成前端 Markdown 标题解析；章节必须能被后端、任务、文件路径和后续产物追溯。
- 不把章节内素材和项目级共享素材混在一起；角色、世界观、通用场景和共享素材优先保留项目级复用能力。
