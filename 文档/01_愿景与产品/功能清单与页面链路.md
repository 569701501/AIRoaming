## 1. 当前结论

应用入口采用“项目库优先”。

用户路径：

```text
进入应用
  -> 项目库
  -> 新建项目 / 打开项目
  -> 项目工作区
  -> 默认进入第 1 步“剧本”
  -> 选择或创建当前章节
  -> 左侧对话框 + 章节列表 + 右侧剧本文档编辑器
  -> 通过 7 步流程推进项目和当前章节
```

当前不再沿用旧六面板试错页面、输出 Tab 页面或大面积 hero 工作台。下一版代码实现必须先对齐本文档和 `文档/01_愿景与产品/当前UI信息架构.md`。

## 2. 品牌与命名

| 类型 | 名称 | 用途 |
| --- | --- | --- |
| 项目内部代号 | AI漫游 | 文档、代码、仓库、内部讨论 |
| 前端展示品牌 | 绘界漫画 | 用户界面展示 |

如果代码、文档、UI 同时出现两个名称，按上表理解，不应再混用为两个产品。

## 3. 全局导航

当前全局导航只保留轻量入口：

| 入口 | 当前状态 | 说明 |
| --- | --- | --- |
| 项目库 | current | 应用默认入口 |
| 素材库 | planned | 全局素材视图，后续实现 |
| 任务队列 | current/ui_shell | 轻量入口，可先显示任务状态壳 |
| 设置 | current | 首页全局设置入口，当前支持 AI 密钥和外观设置 |

不再同时展示“工作台”和“项目”两个并列主入口。

## 4. 项目库页面

用途：

- 查看所有项目。
- 创建项目。
- 打开项目。
- 删除项目。
- 展示简化的 7 步创作流程说明。

可以展示：

- 项目卡片。
- 项目状态。
- 新建项目入口。
- 项目筛选。
- 项目卡片封面 hover 删除按钮。
- 删除二次确认弹窗。
- 任务队列轻量入口。

创建项目只创建项目记录，创建弹窗用户可见标题为“创建项目”，只保留“项目名称”一个字段，不展示内部语义或“下一步”提示文案，不要求填写剧本、故事标题、题材标签、漫画格式、画风方向或故事原文。当前第 1 步“剧本”只在右侧编辑和保存剧本正文；故事标题、题材标签、漫画格式和画风方向等元信息后置，不在当前剧本文档页展示。

创建项目成功后：

```text
关闭创建弹窗
  -> 直接进入项目工作区
  -> 默认打开第 1 步“剧本”
  -> 左侧显示公共对话框
  -> 右侧显示剧本文档编辑器
```

不展示：

- 升级计划。
- 团队协作。
- 最近活动大面板。
- 大型右侧栏。
- 常驻对象检查器。
- 常驻下一步建议。
- 大面积营销 hero 文案。

## 5. 项目工作区页面

用途：

- 围绕当前项目进行创作。
- 显示返回项目列表按钮。
- 显示 7 步流程。
- 根据当前步骤展示主工作面板。

顶部可包含：

- 返回项目列表按钮。
- 项目名称。
- 7 步流程条。

主体应包含：

- 左侧公共“对话框”。
- 当前步骤需要的对象导航，例如剧本步骤的章节列表。
- 右侧当前步骤主文档或工作内容。

不默认展示：

- 全局左侧导航。
- 顶部搜索框。
- 大 hero 图。
- 常驻右侧栏。
- 剧本页最右侧“当前章节信息”面板。
- 常驻下一步建议。
- 常驻对象检查器。

主工作区优先，辅助信息不能挤压主要创作空间。

“对话框”是项目内公共 AI 面板，不是弹窗。它随当前步骤切换注入不同提示词和上下文。对话框组件公共，但对话记录按步骤隔离：剧本、剧情结构、分镜等步骤各自维护对话记录，项目级只共享用户已确认的事实、文档和产物。章节工作流下，剧本步骤还需要进一步按 `chapterId` 隔离对话。剧本阶段中，对话框后续承担两类来源：用户通过附件上传或输入框粘贴已有剧本并整理为章节，或在用户没有灵感时生成灵感种子并继续生成章节剧本。剧本阶段允许 AI 通过 AI漫游受控工具/API 编辑章节草稿，但不能直接操作本地物理路径或绕过章节契约。

当前实现：

- 项目库点击 `继续创作` 进入项目工作区。
- 创建项目成功后进入项目工作区。
- 工作区顶部区域提供 `返回项目库`。
- 工作区主体展示紧凑 7 步流程栏。
- 项目工作区已隐藏全局左侧导航和顶部搜索。
- 当前已实现左侧“对话框”和右侧“剧本文档编辑器”，右侧只展示剧本正文，支持保存剧本草稿。
- 产品口径已废弃剧本页最右侧“当前章节信息”面板；主角和常驻角色进入项目角色库查看和定稿，主线、场景和本章结构进入剧情结构步骤查看，均不在剧本页常驻展示。
- 剧本步骤对话已接入 OpenCode：支持发送消息、流式展示 assistant 回复，并按当前步骤加载对话记录；模型列表读取和 provider/model 透传链路存在，但可见模型选择控件需恢复或重做。
- 其他步骤切换时仍保留左侧公共对话框，右侧工作面板暂显示开发占位。
- 停止生成、完整回退、手动新建/重命名/删除章节和后续产物失效提示仍未接入，不能当作已完成能力。
- 其他步骤保留流程展示，不提供未完成的真实业务操作。

### 5.1 章节列表与章节推进

剧本步骤需要章节列表或章节切换器。章节列表只管理项目内章节，不恢复全局左侧导航。

章节列表当前定位：

| 功能 | 当前状态 | 说明 |
| --- | --- | --- |
| 查看章节 | `current` | 显示章节顺序、标题、状态和更新时间 |
| 切换章节 | `current` | 切换后右侧编辑器加载当前章节剧本 |
| 保存章节草稿 | `current` | 保存当前章节正文，不推进到下一章 |
| 完成本章 | `current` | 保存当前章节并标记剧本完成 |
| 进入下一章 | `current` | 如果下一章不存在则创建，存在则切换 |
| 回到上一章编辑 | `current/needs_warning` | 允许修改，但后续产物失效提示仍需补齐 |

章节不是前端临时状态，后续必须进入数据模型、后端 API 和本地 workspace 文件契约。

## 6. 七个项目内页面

| 顺序 | 页面 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| 1 | 剧本 | 通过对话框附件上传或输入框粘贴已有剧本、生成 3 个灵感种子、生成或编辑固定格式「章节剧本」，并在右侧保存章节正文；最终章节剧本不输出主体列表、正式场景列表、剧情节拍、分镜剧本、镜头编号、图片 Prompt 或 JSON | current |
| 2 | 项目角色库 | 从剧本大纲或导入剧本中提取主角和常驻角色，AI 自动判断层级，用户校正后生成并确认角色定稿图；主角和常驻角色未定稿前阻塞剧情结构 | next |
| 3 | 剧情结构 | 按当前章节逐章生成结构化剧情；页面提供章节下拉/切换器并展示所有章节的结构状态，未完成剧本或项目角色库未完成的章节禁用生成；左侧仍为公共对话框但注入剧情结构 prompt；AI 生成后右侧可显示待确认预览，用户确认后转为正式元素化结构表，展示摘要、本章角色卡、本章场景卡、剧情节拍，并支持字段级小笔编辑；确认后才能触发生成分镜 | current |
| 4 | 分镜工作台 | 按当前章节逐章生成和编辑 `Shot` 镜头列表；AI 生成后先展示待确认预览，用户确认后写入 `storyboard.json`；每个 `Shot` 同时包含 `comic` 漫画画格字段和 `motion` 基础漫剧镜头字段，完整轻漫剧成片仍后置 | current |
| 5 | 候选图工作台 | 为当前章节生成多候选图并选择锁定 | next |
| 6 | 排版导出 | 生成当前章节漫画页并导出 | next |
| 7 | 素材包 | 归档项目共享素材、章节产物、manifest 和交付素材 | next |

这 7 个页面是项目内主流程。轻漫剧基础版不进入当前 7 步 UI 主流程。

## 7. UI 元素状态

| UI 元素 | 当前状态 | 处理 |
| --- | --- | --- |
| 搜索 | `deferred` | 当前项目库和项目工作区都不展示顶部搜索 |
| 任务队列 | `current` | 轻量入口可以保留 |
| 项目删除 | `current` | 只在项目卡片封面 hover 时显示删除入口；确认后删除项目记录和本地 workspace 项目目录 |
| 通知铃铛 | `deferred` | 先不展示，或仅作为视觉占位但不进主流程 |
| 用户头像 | `ui_shell` | 可以展示，但不做团队/账号系统 |
| 对象检查器 | `deferred` | 不默认常驻右侧 |
| 下一步建议 | `deferred` | 不默认常驻右侧，可后续做抽屉或局部卡片 |
| 当前章节信息面板 | `deprecated/removed` | 剧本页不再常驻展示当前章节、故事主线、出场角色和场景列表；常驻面板代码已从剧本页移除 |
| 对话框 | `current` | 项目内公共 AI 对话面板，左侧常驻，不是弹窗 |
| 步骤对话记录 | `current` | 每个步骤独立记录对话历史，切换步骤时只加载当前步骤记录 |
| 项目级已确认事实 | `current` | 跨步骤共享已确认事实和产物，不共享未确认聊天假设 |
| 章节列表 | `current` | 剧本步骤内显示和切换章节，不作为全局导航 |
| 完成本章 | `current` | 保存当前章节，标记章节状态，进入下一章 |

## 8. 页面能力状态

| 状态 | 含义 | UI 规则 |
| --- | --- | --- |
| `current` | 当前版本要围绕它设计 | 可以进入主路径 |
| `ui_shell` | 可以有界面壳，但没有完整真实能力 | 必须弱化或明确标识 |
| `next` | 后续核心能力 | 可以在流程中展示状态，但不伪装可用 |
| `deferred` | 当前不做或后置 | 不占据主流程空间 |
| `deprecated` | 已被当前产品口径废弃 | 不再进入目标 UI；历史记录可保留但必须标明废弃 |

## 9. 禁止事项

- 不把参考图里的搜索、通知、团队、升级计划直接搬进当前产品。
- 不把对象检查器或下一步建议做成默认右侧常驻栏。
- 不用大 hero 图抢占项目工作区主内容。
- 不把轻漫剧基础版混入当前漫画 7 步主流程。
- 不把归档中的旧 UI 试错文档当作当前事实源。
- 不允许 AI 直接操作本地物理路径；剧本阶段 AI 写入章节草稿必须通过 AI漫游受控工具/API，并保留来源追溯。
- 不把整个项目的原始聊天历史自动注入每个步骤；跨步骤上下文必须来自用户已确认事实、保存文档和锁定产物。
- 不把章节只做成前端 Markdown 标题解析；章节必须能被后端、任务、文件路径和后续产物追溯。
- 不把章节内素材和项目级共享素材混在一起；角色、世界观、通用场景和共享素材优先保留项目级复用能力。
