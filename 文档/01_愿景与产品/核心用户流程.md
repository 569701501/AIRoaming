## 1. 文档目的

本文档定义 AI漫游当前版本的核心用户路径。

它回答以下问题：

1. 用户打开产品后先看到什么。
2. 用户如何从项目库进入某个项目。
3. 用户进入项目后，如何通过主步骤完成从故事到漫画产物的生产流程。
4. 项目库页面和项目工作区页面分别承担什么职责。
5. 哪些能力是主流程，哪些只是辅助入口或后置能力。

本文档只描述用户路径、页面层级、阶段输入输出和交互原则，不描述具体视觉样式、组件实现和代码细节。

---

## 2. 当前结论

AI漫游当前采用 **项目库优先** 的产品入口。

用户不是一打开产品就进入 AI 对话，也不是直接进入某个生成工具，而是先进入项目库，查看已有项目或创建新项目。

核心页面层级分为两层：

```text
全局层：项目库 / 素材库 / 任务队列 / 设置

项目层主流程：剧本 / 剧情结构 / 分镜工作台 / 出图准备 / 候选图工作台 / 漫画成稿 / 素材包

项目层常驻资产入口：角色库 / 后续场景库 / 后续风格库
```

当前核心路径：

```text
用户打开平台
  -> 进入项目库（/projects）
  -> 如果没有项目，创建第一个项目
  -> 如果已有项目，点击项目卡片进入项目
  -> 进入项目工作区（/projects/:projectId/script）
  -> 选择或创建当前章节
  -> 通过主流程推进项目和当前章节
  -> 导出漫画页面（当前 G0–G5）
  -> 导出素材包（后置 G6）
```

当前产品口径稳定的项目内主步骤为：

```text
1 剧本
2 剧情结构
3 分镜工作台
4 出图准备
5 候选图工作台
6 漫画成稿
7 素材包
```

这些命名应在产品文档、前端路由、UI 步骤条、数据状态和任务流中保持一致。不要在当前主流程中混用“线稿工作台”“视觉草稿”“上色与修饰”“发布与交付稿”等其他名称。`项目角色库` 不再作为顶部主流程步骤，而是项目级常驻资产入口；它仍是角色一致性的正式事实源。

当前前端路由：

| 路由 | 页面 |
| --- | --- |
| `/projects` | 项目库 |
| `/projects/:projectId/script` | 剧本 |
| `/projects/:projectId/script/:chapterId` | 剧本中的指定章节 |
| `/projects/:projectId/characters` | 项目角色库（常驻资产入口） |
| `/projects/:projectId/structure` | 剧情结构 |
| `/projects/:projectId/storyboard` | 分镜工作台 |
| `/projects/:projectId/preflight` | 出图准备 |
| `/projects/:projectId/candidates` | 候选图工作台 |
| `/projects/:projectId/layout` | 漫画成稿 |
| `/projects/:projectId/assets` | 素材包 |

规则：

- `/projects/:projectId` 默认重定向到 `/projects/:projectId/script`。
- `/projects/:projectId/script` 默认打开当前活跃章节；如果 URL 带 `chapterId`，应恢复到指定章节。
- URL 只表达当前位置，未保存草稿、对话流式状态和项目快照不写入 URL。
- 未实现步骤可以有稳定地址，但页面必须明确处于待接入状态，不能伪装成已完成能力。

## 3. 产品主流程

当前漫画主链路为：

```text
项目库
  -> 创建项目 / 打开项目
  -> 剧本
     -> 左侧对话框
     -> 章节列表
     -> 右侧剧本文档编辑器
  -> 剧情结构
  -> 分镜工作台
  -> 出图准备
  -> 候选图工作台
  -> 漫画成稿
  -> 素材包
```

| 顺序 | 步骤 | 用户目标 | 主要产物 |
| --- | --- | --- | --- |
| 1 | 剧本 | 按章节输入、确认和保存剧本正文 | `Chapter`, `ChapterScriptVersion.sourceText` |
| 2 | 剧情结构 | 把当前章节拆成摘要、角色、场景、剧情节拍，并自动发现本章角色 | `StoryVersion.structureJson`, `StoryBeat[]`, 本章角色候选 |
| 3 | 分镜工作台 | 把当前章节剧情节拍变成可编辑镜头列表，绑定出镜角色，并自动整理每镜头可直接进入候选图工作台的详细单帧说明 | `Shot[]` |
| 4 | 出图准备 | 检查本章正式分镜引用的角色、场景和风格参考是否满足剧情结构阶段已经确定的要求；缺项阻断，不在本页生成或修复素材 | 角色/场景/风格检查、不可变 `PreflightRevision` |
| 5 | 候选图工作台 | 为当前章节每个分镜生成多张候选图，收藏比较并建立正式定稿修订 | `Candidate[]`, `CandidateLockRevision` |
| 6 | 漫画成稿 | 零配置生成完整可编辑初稿，在同一编辑器手调/局部智能优化并预览导出 | `LayoutDocument`, `LayoutRevision`, `ExportRevision`, `Asset(image/pdf)` |
| 7 | 素材包 | 归档项目共享素材、章节产物、页面和 manifest；当前保留入口但后置 G6 | `Asset(archive)`, `manifest.json` |

项目内流程状态由 `ProjectWorkflow` 聚合。角色库不再阻塞剧情结构；它在剧本大纲确认后自动初始化，剧情结构确认时按 `level + entityType` 固定本章视觉主体的素材要求，分镜只能引用当前结构主体，出图准备再检查正式分镜引用是否满足同一要求。缺项阻塞候选图生成，但出图准备不生成、不修复、也不因出镜次数临时升级要求。

当前代码已经实现“AI 分步生成、用户确认后推进”的七阶段框架：AI 负责整理/生成剧本、剧情结构、分镜、角色与场景参考、候选图和排版建议；用户在每一步查看结果、必要时编辑，并通过完成、确认、锁定或导出动作建立正式事实后再进入下一步。这不要求用户手工绘图，也不是纯人工制作。该框架是现有基线，不作为 D2 新功能重复建设；D2 只保留跨步骤自动推进、整章批量编排或一键生成整部漫画的未来调度边界，等现有链路缺口补齐并完成端到端验收后再讨论。

2026-07-11 当前实施范围只到第 6 步 G5：真实 `layout_publication` 可独立完成和验收；第 7 步仍在导航中，但 G6 素材包 V2/ZIP 开发后置，不作为 G0–G5 开工或 `layout_done` 签收前置。

轻漫剧基础视频属于后续 P0.5 能力，不进入当前 7 步主流程。

## 4. 全局层流程

### 4.1 用户进入平台

用户打开应用后，首先进入：

```text
项目库
```

项目库负责展示所有漫画项目，而不是直接展示单个项目的创作工具。

### 4.2 全局导航

当前全局左侧导航应保持简洁：

```text
项目库
素材库
任务队列
设置
```

说明：

- 不再同时展示“工作台”和“项目”，避免入口层级混乱。
- `项目库` 是用户管理和打开作品的主入口。
- `素材库` 是全局素材视图，区别于某个项目内的 `素材包`。
- `任务队列` 是异步任务状态入口。
- `设置` 是产品配置入口。
- 当前设置页已进入首页全局层，先提供 `AI 密钥` 和 `外观设置`：AI 密钥用于配置 OpenCode 对话默认模型链路，外观设置用于切换深色、浅色或跟随系统。

### 4.3 项目库页面目标

项目库页面只解决三件事：

1. 查看所有项目。
2. 创建新项目。
3. 打开已有项目继续创作。

其中“创建项目”只表示建立一个项目记录。项目库创建弹窗的用户可见标题为“创建项目”，只保留两个必要输入：`项目名称` 与 `漫画版式`。漫画版式默认空，用户必须从“竖向条漫/分页漫画”中选择；创建后不可直接修改。弹窗不要求用户填写剧本、故事标题、题材标签、画风方向或故事原文。四格在后续排版画布作为布局模板选择，不在创建弹窗与条漫/页漫并列。

创建项目成功后，系统必须直接进入项目工作区，并默认打开第 1 步“剧本”。首屏布局必须是：

```text
左侧：对话框
右侧：剧本文档编辑器
```

不允许创建成功后停留在项目库，也不允许进入旧的“项目与故事”表单页。

### 4.4 项目库页面主要内容

项目库页面应包含：

- 项目列表。
- 项目卡片。
- 项目状态。
- 新建项目入口。
- 项目筛选。
- 任务队列轻量入口。
- 简化的 7 步创作流程说明。

项目库页面不默认展示：

- 升级计划。
- 团队协作。
- 最近活动大面板。
- 常驻对象检查器。
- 常驻下一步建议。
- 大面积右侧辅助栏。
- 大面积营销 hero 文案。
- 默认“导入剧本”主按钮。

如果后续需要导入剧本，应作为次级入口或新建项目流程中的导入方式，不应抢占项目库主按钮位置。

### 4.5 项目库中的创作流程说明

项目库可以展示简化版创作流程：

```text
剧本 -> 剧情结构 -> 分镜工作台 -> 出图准备 -> 候选图工作台 -> 漫画成稿 -> 素材包
```

在项目库中，这条流程的作用是：

```text
告诉新用户这个产品怎么使用。
```

它不是当前项目进度条。

### 4.6 空项目状态

如果用户没有任何项目，显示空状态：

```text
你还没有漫画项目

从一个故事开始，AI 会帮你拆剧情、生成分镜、生成候选图并形成可编辑漫画成稿。

[创建第一个项目]
```

空状态下可以展示简化版 7 步流程，帮助用户理解产品。

### 4.7 有项目状态

如果用户已有项目，展示项目卡片列表。

每个项目卡片至少包含：

| 信息 | 说明 |
| --- | --- |
| 项目名称 | 例如：迷雾之城 |
| 项目封面 | 作品视觉摘要 |
| 当前阶段 | 例如：分镜工作台 |
| 进度 | 当前项目完成比例或阶段进度 |
| 最近编辑时间 | 用于判断继续哪个项目 |
| 主按钮 | `继续创作` |

项目列表页中的 `继续创作` 表示：

```text
进入该项目工作区。
```

注意：`继续创作` 只适合出现在项目列表页，不适合出现在项目内页。

## 5. 项目工作区通用流程

### 5.1 进入项目

用户点击项目卡片后，进入项目工作区。

用户创建项目成功后，也进入同一个项目工作区，不走另一套页面。

项目工作区默认打开第 1 步“剧本”，首屏布局是左侧对话框、右侧剧本文档编辑器。

示例：

```text
项目库
  -> 点击《迷雾之城》
  -> 进入《迷雾之城》项目工作区
```

### 5.2 项目工作区顶部

项目工作区顶部应包含：

```text
返回项目列表
项目名称
7 步流程条
```

其中：

- `返回项目列表` 用于回到项目库。
- 项目工作区不展示顶部搜索框。
- 用户进入项目工作区后，全局左侧导航隐藏，避免项目内创作被全局入口挤压。
- 7 步流程条保持在顶部，帮助用户切换和理解当前阶段。

### 5.3 项目工作区主体

项目工作区主体应包含：

```text
左侧：对话框
右侧：当前步骤主文档或工作内容
```

第 1 步“剧本”中，右侧主工作区必须是剧本文档编辑器。

当前设计原则：

- 不使用大面积装饰 hero 图占据主内容高度。
- 不默认展示右侧常驻辅助栏。
- 第 1 步“剧本”不展示主线、角色、场景的最右侧信息面板；当前剧本就是写作和编辑当前章节正文的区域。
- 主工作区应占据页面主要高度和宽度。
- 用户进入项目后，应优先看到当前阶段的可操作内容。

“对话框”不是弹窗，而是项目内公共 AI 对话面板。它在剧本、剧情结构、分镜等步骤中复用，但对话记录按步骤隔离：每个步骤有自己的对话历史，切换步骤时加载当前步骤记录、当前步骤提示词、当前步骤产物和项目级已确认事实。剧本阶段中，对话框不仅提供建议，还承担用户提供剧本整理、无灵感时生成灵感种子、生成章节剧本和协助编辑当前章节草稿的职责。AI 可以通过 AI漫游受控工具/API 改动章节草稿，但不能直接操作本地物理路径或绕过章节契约。

### 5.4 章节工作单元

项目内创作按章节推进。章节不是单纯从 Markdown 标题中临时解析出来的文本片段，而是项目内一等工作单元。

一个项目可以包含多个章节：

```text
项目
  -> 第 1 章
  -> 第 2 章
  -> 第 3 章
```

每个章节都有自己的剧本、剧情结构、分镜、出图准备、候选图、排版页和导出物。角色、世界观、通用场景、统一画风和共享素材仍属于项目级，供多个章节复用。项目推进采用“按章流水线”：某一章剧本完成后，可以直接进入该章剧情结构；角色库在后台或常驻入口中承载角色档案和视觉版本，等到出图准备阶段再检查当前章节出镜角色是否具备可用参考图。不要求整部作品所有章节剧本都先写完。

剧本步骤应提供章节列表或章节切换器，至少展示：

| 信息 | 说明 |
| --- | --- |
| 章节序号 | 例如：第 1 章 |
| 章节标题 | 用户可后续自定义 |
| 章节状态 | `草稿`、`剧本已完成`、`结构化中`、`分镜中` 等 |
| 最近更新时间 | 帮助用户判断当前编辑对象 |

章节动作分为两类：

| 动作 | 含义 |
| --- | --- |
| `保存草稿` | 只保存当前章节剧本，不推进到下一章 |
| `完成本章` | 保存当前章节，标记当前章节剧本完成；如果存在下一章章节安排，则自动创建下一章入口并加入章节下拉框 |

完成本章不是不可逆关闭。完成后页面应停留在刚完成的章节，主动作只保留 `进入本章剧情结构`。如果存在下一章章节安排，系统自动把下一章加入章节下拉框，但不自动切换，也不提供 `继续下一章` 动作；用户什么时候切换到下一章，由用户自己决定。切换章节只改变当前查看章节和对话作用域，不触发生成。用户切换到尚无草稿的下一章后，必须在对话框明确输入“生成当前章节”，才触发 A4：系统读取当前章章节卡和上一章已确认的实际正文，生成当前章待确认草稿。如果系统从剧本大纲或章节中发现新的核心角色，可在行动条旁提示 `角色库有待处理角色`，但不阻塞剧情结构。用户可以回到已完成章节继续修改，但修改后需要提示：后续剧情结构、分镜、出图准备、候选图或排版可能需要重新生成或复核。

### 5.5 项目内流程条

项目内始终显示 7 步流程条：

```text
1 剧本
2 剧情结构
3 分镜工作台
4 出图准备
5 候选图工作台
6 漫画成稿
7 素材包
```

在项目内，这条流程的作用是：

```text
显示当前项目做到哪一步。
```

它同时承担两种职责：

1. 显示用户现在在哪一步。
2. 显示当前项目各步骤状态。

状态包括：

| 状态 | 含义 |
| --- | --- |
| 未开始 | 前置步骤未完成或当前步骤还没有数据 |
| 进行中 | 当前正在编辑或生成 |
| 已完成 | 当前步骤已有可进入下一步的产物 |

### 5.6 项目内页面按钮规则

项目内页不要再使用泛化按钮：

```text
继续创作
```

因为用户已经进入项目工作区，已经在创作环境里。

项目内页应使用更明确的动作按钮，例如：

| 当前阶段 | 合适主动作 |
| --- | --- |
| 剧本 | AI 创作使用 `采用草稿/丢弃` 与 `保存草稿/完成本章`；已有剧本使用 `确认章节`；正式后显示 `进入本章剧情结构`，并可提示角色库待处理项 |
| 剧情结构 | `生成剧情结构` / `确认结构` / `进入分镜工作台` |
| 分镜工作台 | `生成分镜` / `确认分镜` / `进入出图准备` |
| 出图准备 | `查看角色库` / `确认出图准备`；缺项时返回剧情结构处理 |
| 候选图工作台 | `锁定入选图` / `前往漫画成稿` |
| 漫画成稿 | `预览并导出` |
| 素材包 | `下载素材包` / `导出 manifest` |

## 6. 步骤一：剧本

### 6.1 用户目标

用户进入已创建的项目后，先通过剧本阶段确定故事来源。AI 创作路线从明确题材或 3 个灵感候选进入项目级「剧本大纲 + 轻量章节安排」，确认后按章生成、采用、编辑和完成。已有剧本路线通过对话框上传或粘贴完整原稿，先保存原稿副本、生成观察性大纲和拆章候选，用户整本确认一次拆章目录后，系统创建全部待确认章节草稿，用户再逐章只读查看和确认正式。两条路线最终都形成同一种正式 `ChapterScriptVersion`，再进入现有 StoryStructure 和后续流程。

### 6.2 用户操作

1. 选择起步来源：上传/粘贴完整原稿，输入明确题材，或让 AI 生成灵感候选。
2. AI 创作路线：需要灵感时生成 3 个候选并选择 1 个；有明确题材时直接生成项目大纲。系统在后台对灵感执行 P1 差异质量门、对大纲执行 P2 因果与结局质量门，不增加页面字段或确认步骤；首次不合格只定向重写一次，仍不合格则不交付候选。大纲包含全部轻量章节卡，用户通过对话修改并确认最新版本。
3. AI 创作路线：确认大纲本身只确认大纲，不默认生成章节；用户必须在当前目标章对话中明确输入“生成当前章节”，或点击同时明确表达“确认并生成当前章”的按钮，才生成该章 pending。裸“继续”最多确认大纲，不进入 A4。A4 在后台执行 P3 场景契约和 P5 前章连续性质量门，不新增页面字段或操作；首次不合格只重写一次，第二次仍不合格则不交付弱草稿。用户完整查看合格 pending 后可丢弃，或采用到可编辑 Working Copy。采用后，用户既可直接编辑，也可在现有对话框明确提出当前章改写；系统内部按“连续性、发展性、场景与对白、文字”四层执行 P4。第 2 章及以后同时读取上一章当前正式正文，只阻止本次改写弄丢当前稿已经承接的前章事实；缺少上一章正式版本时不会调用模型。结果仍是一个需要用户采用的 AI pending。最终只有 `完成本章` 才发布正式版本。
4. AI 创作路线：完成本章后页面停留当前章；只有大纲存在下一章卡时才增加下一章下拉入口。切换只加载章节，用户在当前章对话框明确输入“生成当前章节”才生成；第 N 章要求第 N-1 章已有正式版本。
5. 已有剧本路线：用户发送完整 `.txt/.md` 或粘贴文本的分析请求，系统保存未经改写的内部原稿副本并检查可读性、文件顺序、内容类型和空项目条件。
6. 已有剧本路线：AI 生成观察性原稿大纲、带来源范围和边界证据的拆章候选，在对话结果卡展示；用户可反馈并获取完整新候选，或一次确认最新拆章目录。
7. 已有剧本路线：确认目录后复用空白默认第 1 章并立即建立全部章节入口；目录确认操作随即返回，系统在后台按确认范围逐章整理和验证，结果卡自动更新等待、处理中、待确认或失败状态。
8. 已有剧本路线：所有章节至少完成一次生成尝试后，用户自由切换、完整只读查看；不提供手动修改、AI 重新整理、采用后编辑、丢弃或批量确认。失败章可在结果卡单独点 `重试本章`；点击 `确认章节` 后当前 pending 直接发布为正式 `ChapterScriptVersion`。
9. 任一路线形成正式版本后，页面停留当前章并可点击 `进入本章剧情结构`；其他章节未生成、待确认或失败不阻塞当前正式章节。

### 6.3 页面主要内容

剧本页面应展示：

- 左侧公共对话框。
- 对话框附件上传入口。
- 灵感种子生成入口。
- 对话框消息列表。
- 对话框输入框。
- 章节列表或章节切换器。
- AI 创作候选、项目大纲、原稿分析大纲、拆章目录预览、章节生成、总结、改写和受控编辑结果。
- 右侧剧本文档编辑器。
- 来源相关的待确认动作：AI 创作 pending 使用 `采用草稿/丢弃`，导入 pending 使用 `确认章节`；正式正文继续使用 `保存草稿/完成本章`。

剧本页面不常驻展示“当前章节 / 故事主线 / 出场角色 / 场景列表”信息面板。主角和常驻角色可进入项目角色库查看、调整生图描述 / prompt、生成角色图或锁定角色定稿；主线、场景和本章结构应在进入剧情结构步骤，或打开局部结果时查看；AI 对话框不提供“分析剧情”快捷入口。

### 6.4 输入

- 已有剧本文本或文件。
- 用户选择的灵感种子。
- 已确认的 AI 项目大纲或导入拆章目录。
- 当前章节剧本正文。

### 6.5 输出

- `Chapter`
- 每章待确认正文（非正式事实）
- `ChapterScriptVersion`
- `Chapter.sourceText`
- AI 写入来源记录或修订记录

### 6.6 下一步

当前章节剧本完成后，用户可以进入：

```text
剧情结构
```

AI 创作章节完成后，如果已确认大纲存在下一章卡，下一章会自动出现在章节下拉框中；用户可以在任意时间自行切换，但切换不触发生成。已有剧本路线的全部章节入口已经由 B4 一次创建，不在逐章确认时继续新增。

默认推荐路径是按章流水线：第 1 章获得正式剧本后，优先进入第 1 章剧情结构。角色库会在剧本大纲确认和剧情结构确认时自动增量更新；视觉素材要求也在剧情结构确认时固定，出图准备只检查。AI 创作路线中，如果已确认大纲有第 2 章卡，第 2 章入口会自动加入章节下拉框；系统不自动跳转，也不要求用户执行“继续下一章”确认。用户切换到第 2 章时只打开该章；在第 2 章对话框明确输入“生成当前章节”后，A4 才根据第 2 章章节卡和第 1 章已确认正文生成待确认草稿。已有剧本路线不走该逻辑，其全部章节入口已经在 B4 创建。

## 7. 项目角色库（常驻资产入口）

### 7.1 用户目标

用户在项目中维护可复用角色档案和视觉版本，作为后续漫画候选图和漫剧镜头生成的一致性基准。角色库不再是顶部主流程步骤，也不再阻塞剧情结构；它是常驻资产入口，并被剧情结构、分镜、出图准备和候选图阶段共同读取。

项目角色库不绑定单一章节。它优先读取已确认的项目级剧本大纲中的 `主要角色`，也可以读取用户导入剧本后由 AI 提取出的主要人物。剧情结构阶段会展示当前章节出现的角色；用户确认剧情结构时，系统按角色名和项目角色库匹配，已有角色直接复用已有角色档案和角色图，不重复生成；未匹配到的新角色自动创建为项目级 `Character(source=story_structure)`，并异步生成第一张角色图。普通用户路径不应把“加入角色库、合并、临时、忽略”做成一排主按钮；系统应先自动判断角色是否需要生成参考图，并以“角色图片卡”的形式让用户看图、改生图描述 / prompt、重生成或删除当前图片。只有识别冲突、疑似重复角色或用户主动展开高级处理时，才展示合并、临时或忽略等动作。

主角和常驻角色一开始就应生成项目级 `Character` 草稿。用户确认项目级剧本大纲后，系统应自动提取主角、常驻角色和主要反派，创建角色草稿并异步生成第一张角色图；自动生成不等于自动定稿。用户必须能看到角色名、角色图、角色描述、层级和相关信息。角色名是结构阶段确定的身份标识，普通图片生成弹窗里不能修改角色名；这里的“角色描述”主要是给图片模型使用的形象描述 / prompt。定稿前用户可以修改图片生成描述并重新生成图片。用户满意当前角色图后，可以直接生成 `角色定稿图`；系统内部自动把当前角色图作为定稿参考，不向用户暴露“确认预览”按钮。当角色定稿图已经被漫画候选图使用后，不允许覆盖旧图，只能创建新的视觉版本并用于后续新生成内容。

### 7.2 用户操作

1. 查看 AI 从剧本大纲或导入剧本中提取的角色列表。
2. 在右侧查看每个角色的角色名、角色描述、层级和备注；角色名只读，图片生成弹窗只编辑生图描述 / prompt。
3. 等待系统为需要视觉素材的角色自动生成第一张角色图；`voice` 不生成图片。
4. 点击角色图查看大图；不满意时通过编辑弹窗修改生图描述并重新生成。
5. 为 `human + lead/recurring/chapter` 生成角色定稿图，并在满意后锁定定稿；其他可视主体采用单张参考。
6. 对本章新增角色，不需要用户先确认入库；系统自动入库和自动生成第一张角色图。用户只在图不满意时编辑生图描述 / prompt、重新生成或删除当前图片；合并、临时或忽略只作为异常或高级处理。

角色图生成范围：

- `human + lead/recurring/chapter`：必须有 `final_reference`；生成时内部使用当前第一张角色图作为参考。定稿图是一张包含正面半身、正面全身、侧面全身、背面全身的组合图。
- `human + minor/extra`：只需 `preview_front` 单张身份参考，不因分镜重复出镜升级为定稿图。
- `creature/group`：任意层级只需类型适配的 `preview_front` 单张视觉参考，不生成人物四视图；同一群体的保守别名只对应一份素材身份。
- `voice`：不要求图片，也不排图片任务。
- `appearanceCount` 只用于展示实际出镜信息，不参与素材类型判定。

角色预览图和定稿图的默认审美必须是漫画/条漫角色设定图。写实题材可以有写实气质，但不能默认生成真人照片、摄影棚肖像或 3D 渲染。

### 7.3 页面主要内容

- 角色库入口默认以项目内弹窗/抽屉打开，保留用户当前所在章节步骤作为背景上下文；AI 对话负责生成、解释、合并建议和批量调整。深度维护入口可以保留路由，但不作为顶部“角色库”按钮的默认体验。
- 弹窗默认显示与当前章节、当前步骤或当前阻塞项相关的角色和待处理问题。
- 弹窗提供 `查看全部角色` 切换入口，进入全量项目角色库视图；全量视图作为 `Character[]` 和角色定稿图的正式事实源。
- 角色列表。
- 角色层级标签。
- 展示只读角色名、角色描述、层级和备注；普通图片生成弹窗只允许编辑用于 AI 生图的形象描述 / prompt。角色定稿图被候选图使用后进入锁定或新版本流程。
- 角色图、角色定稿图和异步生成状态。
- 普通卡片主按钮只保留 `生成角色图`、`生成定稿`、`锁定定稿` 等用户能理解的动作；不展示 `确认预览`、`重新生成预览` 这类中间状态按钮。
- 角色图列表：生成后的角色图以图片卡片自动展示，卡片默认只显示图片和角色名；鼠标悬停后显示编辑和删除图标。点击编辑打开角色图片生成弹窗，角色名只读，不允许在这里改名；用户只修改用于 AI 生图的形象描述 / prompt，并重新生成或应用当前图。重新生成后直接替换当前卡片展示图，不在普通 UI 中展示多版本选择。点击删除只删除当前图片版本，不删除角色本身，且必须二次确认。合并、临时或忽略仅在系统发现疑似重复或用户展开高级处理时出现。
- 角色定稿状态和是否已被漫画候选图使用的锁定提示。

项目角色库弹窗可以沿用项目工作区的两栏结构：左侧 AI 对话负责生成、解释、重生成和按用户要求调整角色；右侧工作区负责展示、编辑、确认和保存项目级角色资产。弹窗打开时优先呈现当前章节相关角色、当前出图准备阻塞角色和待处理新角色，避免用户一进入就被全量资产列表淹没；需要长期维护时，再切换到 `查看全部角色`。左侧普通聊天内容不自动进入项目角色库，只有用户确认、右侧编辑保存或受控工具写入后，才成为正式 `Character` 或角色定稿图。关闭弹窗后，用户应回到打开前的章节步骤、章节选择和局部工作状态。

### 7.4 输入

- 项目级剧本大纲。
- 已导入剧本中提取的主要角色。
- 项目题材、风格和漫画形式。

### 7.5 输出

- `Character[]`
- 角色层级：`lead / recurring / chapter / minor / extra`
- 角色预览图 `Asset(reference image, referenceKind=preview_front)`
- 按 `level + entityType` 固定的视觉素材：`preview_front / final_reference / none`
- 角色主参考图或视觉版本引用

### 7.6 下一步

角色库不是线性下一步。用户可以随时返回当前章节主流程。角色文字档案、素材要求和角色匹配在剧情结构确认后成为分镜与出图准备共同读取的上游合同；出图准备只验证是否满足，不改变要求。

## 8. 步骤二：剧情结构

### 8.1 用户目标

用户确认 AI 是否理解了故事，并把故事变成后续分镜可用的结构化数据。

剧情结构不是给读者阅读的剧本文字，也不是最终分镜；它是给后续制作使用的结构表，用于把当前章节拆成摘要、角色、场景和剧情节拍。

剧情结构按章节生成和确认。一个项目可以有多章剧本，但进入剧情结构步骤时，系统只对当前章节生成结构化剧情；每个章节都有自己的剧情结构、分镜、候选图、排版和导出产物。

剧情结构步骤也需要章节下拉或章节切换器，显示当前项目下各章节以及每章的剧情结构状态。用户选择某一章后，只查看、生成、预览、确认和编辑该章的剧情结构。

剧情结构章节下拉展示所有章节，避免用户误以为未完成章节丢失。但只有剧本已完成的章节才能生成剧情结构：`draft` 章节显示“请先完成本章剧本”，不可点击 `生成剧情结构`；`script_done` 章节可以生成待确认预览；`structured` 及后续状态章节可以查看和编辑已确认结构，重新生成时必须提示会影响后续分镜、候选图和排版。

剧情节拍按关键剧情事件切分，不和最终分镜或镜头一一对应。剧情结构阶段应保持比分镜更粗的一层，后续由分镜工作台把一个剧情节拍拆成多个镜头。

剧情结构里的角色卡和场景卡默认是“本章结构卡”，只用于当前章节理解和分镜准备；剧情结构确认时必须优先读取项目角色库，遇到主角、常驻角色或已存在角色应关联已有 `Character`，不能新建重复角色。未匹配到的新角色自动进入项目角色库并自动排队生成第一张角色图；普通用户只需要查看角色图，不满意时重新生成、删除当前图或编辑用于 AI 生图的形象描述 / prompt。合并到已有角色、标记临时或忽略属于系统自动匹配、冲突提示或高级处理，不应成为默认主操作。

剧情结构页面的主形态是可编辑结构表，而不是 Markdown 文档编辑器。用户在表单、卡片和节拍表里编辑结构内容；系统底层保存为当前章节的 `structure.json`，供后续分镜任务读取。

剧情节拍可以包含轻量“画面重点”，用于提示后续分镜应突出什么视觉信息；但剧情结构阶段不能写镜头编号、景别、机位、构图或完整分镜稿，这些属于下一步“分镜工作台”。

AI 生成剧情结构后，不能自动继续生成分镜。用户必须先编辑或确认剧情结构，再点击 `生成分镜` 进入下一步，避免结构误读连带污染分镜、候选图和排版。

剧情结构步骤仍保留左侧公共 AI 对话框，但注入的是剧情结构 prompt。用户在左侧请求生成剧情结构，AI 生成结构内容并等待用户确认；确认后的结构在右侧以元素化结构表展示，不使用文本编辑器。

AI 生成剧情结构后，右侧可以同步展示“待确认预览”，顶部必须明确标识待确认状态。待确认预览方便用户在主工作区检查结构，但还不是正式结构，不允许触发 `生成分镜`。用户确认后，预览转为正式结构表。

### 8.2 用户操作

1. 查看故事摘要。
2. 查看角色卡片。
3. 查看场景列表。
4. 查看剧情节拍。
5. 编辑角色、场景和节拍。
6. 点击 `生成分镜`。

### 8.3 页面主要内容

剧情结构页面应展示：

- 章节下拉或章节切换器。
- 故事摘要。
- 本章角色卡片。
- 本章场景列表。
- 剧情节拍。
- 结构化剧情状态。
- 待确认预览状态。
- `重新分析`。
- `编辑角色`。
- `编辑场景`。
- `生成分镜`。

可编辑字段采用字段级编辑：可修改内容块右上角显示小笔图标；点击后该字段切换为输入框并带入当前内容；输入框失焦时提交修改并恢复为普通文本展示。

每章剧情结构状态建议展示为：

| 状态 | 含义 |
| --- | --- |
| `未生成` | 当前章节剧本未结构化，尚未生成待确认预览 |

| `已完成` | 用户已确认剧情结构，章节推进到 `structured`，可以生成分镜 |
| `需更新` | 当前章节剧本被修改，已有剧情结构可能过期，后续需要重新生成或确认 |

当前代码仍会混用更新时间判断。G2 已采纳目标改为比较 `currentScriptVersionId + SourceSnapshot digest`：未确认的剧本 Working Copy 显示“有未确认修改”，发布新 ScriptVersion 后旧结构才显示“来源已更新”。不得再用章节或结构 `updatedAt` 推断正式来源，详细规则见 `文档/04_方案与决策/2026-07-11_G2上游版本链与Freshness开发方案.md`。

## 9. 步骤三：分镜工作台

### 9.1 用户目标

用户把剧情节拍变成可编辑、可生成图片的镜头列表。

分镜工作台按章节生成和确认。只有当前章节已经完成剧情结构，即 `Chapter.status = structured` 或后续状态时，才能生成分镜。一个项目可以有多章剧本和多章剧情结构，但分镜工作台每次只处理当前章节。

分镜工作台复用“AI 对话框 + 右侧工作区”的阶段形态，但产物粒度不同：剧情结构里的 `StoryBeat` 是关键剧情事件，分镜工作台里的 `Shot` 是最终用于出图、排版和后续轻漫剧制作的镜头/画格。一个 `StoryBeat` 可以拆成多个 `Shot`。

分镜阶段不只生成漫画用画格，也要同步生成基础漫剧镜头字段。漫画和漫剧共用同一组 `Shot` 核心，包括顺序、剧情节拍、角色、场景和主要动作；但在 `Shot` 内区分 `comic` 漫画画格表达和 `motion` 漫剧镜头表达。

两者差异必须保留：漫画画格关注阅读顺序、画格构图、对白气泡/旁白和页面/条漫节奏；漫剧镜头关注时间轴、画面持续、运镜、配音角色、台词、字幕/声音和画面类型。完整轻漫剧成片、TTS、字幕、剪辑和视频导出仍属于后续阶段。

M1 正式采用一个 `Shot` 同时带一个 `comic` 表达和一个 `motion` 表达，便于同批生成和编辑。但产品语义上不能把“漫画一格 = 漫剧一镜”写死；后续允许一个漫画画格拆成多个漫剧镜头，或多个静态画格组合成一个连续漫剧片段。

AI 生成分镜后，右侧先展示“待确认预览”。待确认分镜可以给用户检查、编辑、排序、新增和删除，但还不是正式分镜，不允许触发候选图生成。用户确认后，系统才切换当前正式 StoryboardVersion，并把章节至少推进到 `storyboard_done`；若章节已经达到 `images_done`、`layout_done` 或 `exported`，最远里程碑保持不变。

新生成分镜采用“一次用户动作、两段内部处理、一次待确认结果”：第一段拆剧情节拍并形成漫画/漫剧骨架；骨架通过严格字段、剧情质量和引用检查后，第二段按整章一次调用自动整理候选图所需的详细单帧说明。第二段只能覆盖 `coreAction`、`comic.panelDescription`、`comic.composition` 和 `promptDraft`，不能改镜头数量、顺序、beat、scene、characterIds、对白、剧情结果或 motion。任一阶段及其一次自动返修仍失败时，整份结果不写入、也不替换已有待确认分镜。

已进入出图准备、候选图或排版后再次生成分镜，生成动作仍只建立 pending，旧正式分镜与下游成果继续可用。用户点击“确认分镜”时，页面展示已确认出图准备、候选图、当前定稿图、排版和导出数量；取消只关闭切换提示并保留 pending，确认才切换 current。切换成功后旧候选、排版和导出不删除，按来源保留为历史，出图准备显示“来源已更新”并要求重新确认。若 pending 所依据的剧情结构已经不再是 current，系统必须拒绝确认并要求基于最新结构重新生成，不能让用户盲目刷新重试。

整理后的 `comic.panelDescription + coreAction + comic.composition` 必须共同锁定一个地点、一个可见时刻和一个机位，并用自然完整句写清主体、动作关系和构图。两个及以上人类角色同镜时要显式写出总人数并逐一写出角色名、位置、动作对象、承受或视线关系；群体只有范围事实时使用“一群”“一队”等中性范围，不虚构精确人数。声音、气味、心理、时长、地点切换、连续动作、气泡文字和角色设定图语言不得混入静态画格。

## 10. 步骤四：出图准备

### 10.1 用户目标

用户在真正生成候选图前，确认当前章节所有出图依赖已经准备好，避免候选图阶段才发现角色缺图、角色未绑定、场景缺参考或画风不一致。

出图准备是章节级检查点，不是完整资产库。它读取当前章节已确认的 `storyboard.json` / `Shot[]`，聚合每个镜头的出镜角色、场景和风格需求，再和项目角色库及后续场景/风格资产做匹配。

角色视觉定稿的硬门槛放在本阶段：主角、常驻角色，以及当前章重要出镜角色，如果在镜头中多次出现、有台词、近景或影响剧情，必须有可用参考图后才能进入候选图生成。临时/背景角色可以只保留文字描述，不强制生成定稿图。

### 10.2 用户操作

1. 查看本章出镜角色清单。
2. 查看本章新增角色确认卡，确认生成图是否可用。
3. 不满意时重新生成，或先编辑用于 AI 生图的形象描述 / prompt 再重新生成。
4. 确认本章场景和画风参考。
5. 点击 `确认可出图`。

### 10.3 页面主要内容

- 待处理新角色列表。

- 场景参考和画风参考检查。
- 图片生成任务队列状态。
- 本章角色图列表：角色图自动展示为图片卡片，hover 后显示编辑和删除；图片生成弹窗内角色名只读，只支持修改用于 AI 生图的形象描述 / prompt、重生成和应用。
- `确认可出图`；高级处理仅在疑似重复、系统无法判断或用户主动展开时展示。

## 11. 步骤五：候选图工作台

## 12. 步骤六：漫画成稿

> 用户可见名称目标为“漫画成稿”；内部步骤键继续使用 `layout_export`，路由继续使用 `/projects/:projectId/layout`。

### 12.1 用户目标

用户不配置模板、画布或气泡参数，系统根据当前正式分镜、候选定稿图和项目版式自动生成包含画格布局、图片裁切、对白、气泡、旁白、留白和阅读顺序的完整可编辑成稿。用户在同一正式编辑器内修正少量例外、进行局部智能优化、阅读预览并导出不可变漫画成品。

底层已实现首次自动成稿、已有稿恢复、同一编辑器手调、局部智能调整、权威视觉对比、来源返修、V2 正式版本与 publication。普通用户路径按 ADR-0021 收敛为“打开/恢复 → 编辑或整理 → 预览并导出”；当前暴露 mode、intent、双预览和四步版本/出版的页面属于待删除过渡实现，不再作为目标信息架构。

### 12.2 用户操作

1. 前置定稿完整且没有 Working Copy 时，页面自动生成标准智能成稿，不显示 Profile、模板、尺寸和初始化模式。
2. 页面加载即核对正式镜头、对白、旁白和所有可见叙事文字；缺失、重复、悬空、无保护改文或未分类文字进入“成稿不完整”修复态，不能当成正常阅读稿或进入版本/出版。旧错误稿先生成可撤销的内容修复预览，补齐正式内容；无来源文字仍须用户明确删除或“保留为自定义”。
3. 系统按 scene/beat/frameType/panelRhythm 分组，自动选择页漫页面或条漫段落、画格比例、重点、留白和阅读顺序。
4. 系统读取 `motion.voiceLines`、兼容 `comic.dialogue` 和 `comic.caption`，自动生成普通/思考/喊叫/旁白气泡；只允许断行，不得静默改写台词。
5. 用户直接拖动画格、裁切图片、移动气泡、修改对白、调整样式和顺序；完整编辑器是主工作区，不是隐藏高级模式。
6. 智能范围由当前选择自动推断；动作使用“整理选中画格、避让人物、排紧一点”等具体文案，不要求用户选择 initial/full/scoped、场景/页段或底层 intent。结果在中央唯一权威视觉面预览后应用或放弃，并可整批撤销。
7. 人工修改按 geometry/crop/text/style/tail 等字段保护，显式锁定对象完全禁止智能改动；用户可以明确“允许智能调整”后再清除保护。
8. Working Copy 持续自动保存；来源更新、文字溢出、低分辨率和阅读问题以可定位的问题列表显示。
9. 用户点击唯一主动作“预览并导出”；系统内部等待保存、运行 Working Copy 检查、创建或复用不可变 Revision、再次运行出版检查并提交 Publication。普通用户只看一份问题清单和一次确认，服务端的两次校验仍然保留。
10. 候选定稿发生变化时只显示一个“更新到最新定稿”入口；系统生成同一种调整预览，确认后把同一 Shot 的全部出现位置作为一个可撤销命令批更新，并建立 `source/crop` 人工保护。

### 12.3 页面主要内容

漫画成稿页面应展示：

- 顶部章节、自动保存、撤销/重做、上下文“整理成稿”、“预览并导出”和“更多”。
- 左侧场景/页面/条漫段落与镜头顺序；未放置、来源更新或内容错误时才展开异常素材。
- 中央唯一正式视觉面，在编辑、调整预览和阅读预览之间互斥切换。
- 随选中画格、图片、文字或气泡变化的 3～5 个常用属性和具体动作。
- 按需出现的问题、来源更新、图层、历史、恢复和高级属性。
- 页漫 PNG/可选 PDF，或条漫 PNG 切片/条件长图的简化导出选项。

普通主界面不展示 raw digest、rowVersion、内部 task/source ID、Pending、Working Copy、Revision、Publication 或数据库术语。服务端安全边界不能绕过，自动保存草稿也不能被误当成正式版本。

### 12.4 输入

- 当前正式 `StoryboardVersion` 及其 scene/beat/shot/comic/motion 字段。
- 当前完整 `CandidateLockRevision` 集与 ready 图片 Asset。
- 项目 `comicFormat`、系统默认 LayoutProfile、受控字体和成稿策略版本。
- 已存在时的 LayoutWorkingCopy 及人工保护。

- 按需保存的不可变 `LayoutRevision`。
- `ExportRevision(kind=layout_publication)`
- `Asset(image)`
- `Asset(document/pdf)`

## 14. 对话框与辅助能力定位

以下能力服务 7 个主流程步骤，但不替代右侧主文档或工作内容。

### 14.1 对话框

对话框是项目内公共 AI 对话面板，不是弹窗。

它位于项目工作区左侧，随当前步骤注入不同提示词和上下文。

对话记录规则：

- 对话框组件在项目内公共复用。
- 对话历史按步骤隔离，不把整个项目聊天混成一条记录；剧本等章节内步骤下一阶段应按 `projectId + stepKey + chapterId` 隔离。
- 切换步骤时，只自动加载当前步骤的对话记录。
- 跨步骤共享的上下文只来自用户已确认事实、保存文档和锁定产物。
- 未被写入章节、保存、锁定或确认为项目事实的聊天内容，不能自动进入其他步骤上下文。

它可以帮助用户：

- 上传剧本或参考文本。
- 生成灵感种子。
- 生成或整理章节剧本。
- 询问当前步骤内容。
- 总结当前文档。
- 给出改写版本。
- 生成分镜。
- 重写镜头。
- 生成候选图。
- 调整排版。

对话框产生的结果必须落回主流程步骤、项目资产入口、文档或受控任务。

剧本阶段允许 AI 通过 AI漫游受控工具/API 更新章节草稿；其他阶段是否允许 AI 写入，需要按各自文档和任务契约单独确认。AI 不允许直接操作本地物理路径或绕过后端业务接口。

### 14.2 任务队列

任务队列用于展示异步任务状态。

包括：

- 排队中。
- 运行中。
- 已完成。
- 失败。
- 已取消。

项目角色库中的角色预览图和角色定稿图生成必须进入任务队列。MVP 阶段图片生成按队列一个一个执行，避免同时生成多个角色图导致限流或超时。

顶部任务队列应展示真实任务记录并独立刷新，不应为了更新队列而刷新剧本、剧情结构或分镜编辑内容。

D75 已接受的目标是：任务排队和生命周期由 SQLite `GenerationTask/TaskAttempt` 持久化；服务重启后可重新发现任务，运行中取消由 worker 协作确认，明确可重试错误有限重试，所有图片 provider 任务统一并发 1。当前代码仍以内存 Map 与 Promise 队列执行，以上目标尚未实现。

D76 已确认：旧完整任务和仅有引用的 taskId 作为只读 `legacy_imported/legacy_stub` 保留，Candidate/Asset 继续指向原 taskId；legacy 记录不进入活动队列、不显示成排队/执行/失败可重试，也不能从已有图片推断成功状态。重新生成必须创建新的正常任务。

任务队列可以作为顶部入口或独立页面，不默认占据项目工作区主内容高度。

### 14.3 对象检查器与下一步建议

对象检查器和下一步建议属于上下文辅助能力。

当前版本不默认作为右侧常驻栏展示。

后续可作为：

- 抽屉。
- 弹层。
- 当前对象详情面板。
- 局部辅助卡片。

它们不应压缩主工作区。

| `project_story` | 剧本 |
| `story_structure` | 剧情结构 |

| `image_candidates` | 候选图工作台 |

`project_characters` 已迁出顶部主流程，仅作为 `/characters` 项目级资产入口保留；`image_preflight` 是分镜工作台和候选图工作台之间的正式主流程步骤。

### 16.2 阶段完成条件

| 阶段 | 完成条件 |
| --- | --- |
| 剧本 | 已保存项目和故事原文 |
| 剧情结构 | 已生成并确认摘要、角色、场景和剧情节拍 |
| 分镜工作台 | 已生成并确认可用于出图的分镜列表 |
| 出图准备 | 当前章节出镜角色、场景和画风参考已绑定；必需角色已有可用参考图 |
| 候选图工作台 | 每个需要排版的分镜都有当前 `CandidateLockRevision` |
| 漫画成稿 | 当前 LayoutRevision 来源/字体/预检通过，且已有对应的 ready/current `layout_publication` ExportRevision |
| 素材包 | 已导出素材包和 manifest |

### 16.3 项目状态建议

| 项目状态 | 含义 |
| --- | --- |
| `draft` | 项目草稿中 |
| `story_ready` | 故事已保存，准备生成剧情结构；角色库可自动初始化或提示待处理角色 |
| `characters_ready` | 兼容旧状态，表示项目核心角色参考已完成；后续不应作为剧情结构门槛 |
| `structure_ready` | 剧情结构已确认 |
| `shots_ready` | 分镜已确认 |
| `images_ready` | 所需分镜都有当前定稿修订；这是兼容聚合状态，不取代修订历史 |
| `layout_ready` | 漫画页已排版且来源新鲜；上游返修后由 workflow 派生 `needs_update`，不粗暴回退该枚举 |
| `exported` | 已有导出页面或素材包；旧导出保留，是否代表当前版本由 ExportRevision 新鲜度判断 |

## 18. 验收标准

更新后的用户流程应满足：

- 用户打开应用后，先进入项目库。
- 用户可以从项目库创建或打开项目。
- 用户进入项目后，可以看到返回项目列表按钮、当前项目名称和 7 步创作流程。
- 用户进入项目后，全局左侧导航隐藏，左侧显示公共对话框，右侧显示当前步骤主文档或工作内容。
- 用户创建项目成功后，默认看到第 1 步“剧本”的左侧对话框和右侧剧本文档编辑器。
- 用户进入项目后，可以看到 7 步创作流程。
- 用户切换步骤时，对话框记录按步骤隔离，但可读取项目级已确认事实。
- 用户能明确知道当前处于哪一步。
- 每一步都有清晰输入、操作、输出和下一步。
- 项目列表页和项目工作区职责不混淆。
- 项目列表页中的 `继续创作` 只用于进入项目。
- 项目内页不再使用泛化的 `继续创作` 按钮，而使用当前阶段的具体动作。
- 剧本阶段支持 AI 受控生成、整理和编辑章节草稿；写入必须经过 AI漫游后端工具/API，并可追溯来源。
- 轻漫剧不抢占漫画主链路。
