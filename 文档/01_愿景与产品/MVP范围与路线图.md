## 1. MVP 一句话

长期 MVP 要证明一件事：用户能从章节剧本出发，经过结构化剧情、分镜编辑、出图准备、漫画图多候选生成和修订式定稿，最终导出可追溯的漫画页面和素材包；项目角色库作为常驻资产入口保障角色一致性，但不阻塞剧情结构。当前开发波次先完成 G0–G5 到真实漫画出版成品，素材包 V2/ZIP 作为后置 G6，不阻塞前一波次开工或签收。

## 2. MVP 主线

```text
创建项目
  -> 创建或进入当前章节
  -> 输入当前章节剧本
  -> AI 整理当前章节剧情结构
  -> AI 生成当前章节分镜和基础漫剧镜头字段
  -> 人工编辑分镜
  -> 出图准备检查角色、场景和画风参考
  -> 为分镜生成漫画图候选
  -> 人工收藏比较并建立当前定稿修订
  -> 排版漫画页面
  -> 导出 PNG/PDF/条漫切片（当前 G0–G5）
  -> 导出素材包（后置 G6）
```

## 3. MVP 功能范围

| 模块 | MVP 范围 | 不进入 MVP 的内容 |
| --- | --- | --- |
| 项目管理 | 新建项目、项目状态、基础版本号；创建时必选且锁定“漫画版式”（竖向条漫/分页漫画） | 团队权限、多工作区、原地切换项目版式 |
| 章节管理 | 默认章节、章节列表、保存草稿、正式章节进入本章剧情结构；AI 创作仅在大纲存在下一章卡时增加入口并停留当前章，已有剧本在目录确认后一次创建全部入口并逐章确认；角色库待处理项只提示不阻塞结构化 | 自动长篇拆卷、多人章节协作 |
| 上游版本与返修 | Script/Story/Storyboard Working Copy 与不可变正式版本、current/pending 指针、Preflight 来源快照、派生 freshness；旧产物保留，新任务只读 current 且已确认来源 | 多分支合并、三方 diff、多人版本审批 |
| 故事输入 | 粘贴当前章节文本、保存章节原文；后续由剧情结构和角色库增量匹配继续推进 | 复杂设定库 |
| 项目角色库 | 从剧本大纲、导入剧本和剧情结构中提取项目角色；支持角色描述、层级、预览图、定稿图和视觉版本管理；作为常驻资产入口，不作为主流程步骤 | 完整角色 LoRA 训练、自动角色一致性闭环训练 |
| 剧情结构化 | 提取当前章节场景、角色、事件、对白线索 | 世界观知识图谱 |
| 分镜生成 | 根据剧情生成可编辑分镜数组；同一分镜同时包含漫画画格字段和基础漫剧镜头字段 | 专业电影级镜头语言优化 |
| 分镜编辑 | 修改角色、场景、动作、对白、镜头、情绪和基础漫剧镜头字段 | 多人同时编辑 |
| 出图准备 | 检查本章出镜角色绑定、待处理角色、角色参考图、场景和画风参考；必需角色准备好后才能候选图生成 | 完整场景库、自动角色一致性评分闭环 |
| 漫画图生成 | 单分镜生成多候选图，读取出图准备确认的角色和参考素材 | 完整角色 LoRA 训练 |
| 候选定稿 | 查看、收藏、定稿、影响预览、更换/取消定稿、废弃非当前候选；每次正式选择形成不可变修订 | 高级 A/B 数据统计、团队审批 |
| 漫画排版 | 在条漫/页漫有限成稿容器内高自由编排画格、图片、横竖排富文本和受控气泡；Working Copy 自动保存、显式保存不可变 LayoutRevision，定稿变化后预览并解决来源；桌面完整编辑、手机只读；AI 建议经预览和确认后应用；一次出版形成页漫 PNG+可选 PDF 或条漫切片+条件长图 | 任意矢量画格/气泡、通用持久 Group、手机完整编辑、绘画/滤镜/无限白板、复杂印刷规范、素材 ZIP（归 G6） |
| 素材管理 | 图片、PDF、manifest、任务输入输出归档 | 对象存储、CDN、多端同步 |
| 任务可靠性 | SQLite 持久任务与不可变 attempt、单进程 worker/lease、重启恢复、协作取消、有限重试、at-least-once 幂等、图片并发 1；旧任务引用以不可执行 legacy stub 保留 | Redis/BullMQ、多进程/多机器 worker、首版 exactly-once 承诺、伪造旧任务成功历史 |
| 轻漫剧基础版 | P0.5 / M4 后续扩展，不进入当前 7 步 UI 主流程；M1 分镜阶段只提前保存基础漫剧镜头字段 | 复杂运镜、自动剪辑策略 |

## 4. 里程碑

### M0：文档与契约成型

目标：让后续实现有清晰事实源。

交付物：

- 文档体系
- 产品总览
- MVP 范围
- 架构总览
- 数据模型
- 生成任务协议
- 素材路径契约

退出标准：

- AI 能通过 `文档/README.md` 找到所有核心事实源。
- 每个 P0 模块都有明确输入输出。
- 每个功能完成后有固定记录位置。

### M1：章节剧本到分镜

目标：验证故事结构化和分镜编辑闭环。

交付物：

- 项目创建
- 章节列表和当前章节剧本输入
- 剧情结构化任务
- 分镜生成任务
- 分镜列表和编辑
- 基础漫剧镜头字段随分镜一起生成和编辑

退出标准：

- 输入当前章节剧本后能得到结构化剧情 JSON。
- 结构化剧情能生成分镜数组。
- 用户能修改分镜字段并保存。
- 每个分镜能保存基础漫剧镜头字段，供后续轻漫剧制作复用。

### M2：分镜到漫画图候选

目标：验证单分镜多候选生成和人工选择。

交付物：

- 角色模板
- 场景模板
- 图片生成任务
- 候选图列表
- 候选收藏、定稿修订和返修影响检查

退出标准：

- 每个分镜可生成至少 2 个候选图。
- 候选图能追溯到生成任务输入。
- 用户能把一个候选定稿为该分镜当前图片；更换时创建新修订，不覆盖旧决定。
- 已有排版或导出时更换定稿图，系统能指出受影响格子并保留历史导出。

### M3：漫画排版与导出

目标：验证选定素材能形成可交付漫画页。

交付物：

- 页面排版模型
- 条漫/页漫共同 `LayoutDocument` 与模板初稿
- 画格、非破坏裁切图片、横竖排字符范围富文本和四类受控气泡
- 桌面成稿编辑、手机只读预览、预检与修订保存
- PNG/PDF 导出
- 后置增量：素材包 V2、真实 ZIP 和下载（G6；当前不写开发文档）

退出标准：

- 当前定稿修订对应的分镜图可生成漫画页面。
- 浏览器预览与正式渲染对画格、裁切、字体、横竖排、富文本和气泡保持一致。
- AI 布局/文字/气泡建议在用户应用前可预览、可放弃，并能作为一个编辑命令撤销。
- 导出物包含图片文件和元数据。
- 当前 G0–G5 退出标准到 current `layout_publication` 与 `layout_done`，不要求 ZIP 或 `exported`。
- 后置 G6 完成后，素材包还必须能追溯项目、章节、分镜和候选关系。

### M4：轻漫剧基础版

目标：



交付物：

- 图片序列时间轴
- TTS 音频
- 字幕文件
- BGM 引用
- MP4 导出

退出标准：

- 当前定稿修订对应的漫画图序列能导出基础 MP4。
- 字幕与 TTS 有对应关系。
- MP4 与源素材关系可追溯。

## 5. 优先级表

| 优先级 | 功能 | 原因 |
| --- | --- | --- |
| P0 | 项目、章节、剧情结构化、分镜、图片候选、漫画排版出版、持久任务底座 | 构成当前 G0–G5 漫画创作、可靠执行和成品闭环 |
| P0 后置 | 素材包 V2、真实 ZIP、下载与 `exported` 总验收 | 保留长期 MVP 位置，但不作为当前波次前置 |
| P0.5 | 基础轻漫剧、TTS、字幕、BGM | 基于漫画产物的后续扩展 |
| P1 | 局部重生成、角色一致性增强、批量操作 | 提升生产效率 |
| P2 | 多人协作、云端扩容、商业化、复杂视频 | 等主链路稳定后再做 |

## 6. MVP 非目标

- 不要求 AI 完全自动理解所有文学隐喻。
- 不要求漫画图一次生成即最终可用。
- 不要求轻漫剧达到专业动画剪辑质量。
- 不要求第一版支持云端多用户并发。
- 不要求第一版具备商业权限体系。
- 不在七步主链路跑通前建设跨步骤自动推进、整章批量调度或“一键生成整部漫画”。
- 轻漫剧基础版：P0.5 / M4，不进入当前 7 步 UI 主流程。

## 7. 验收样例

MVP 应至少用一份短篇故事做端到端验收：

1. 创建项目并进入第 1 章。
2. 输入 800 到 1500 字当前章节剧本。
3. 生成至少 3 个剧情场景。
4. 生成至少 8 个分镜。
5. 每个分镜生成 2 个漫画图候选。
6. 锁定每个分镜的候选图。
7. 导出至少 1 页漫画 PNG。
8. 当前 G0–G5 验收出版 manifest、来源摘要和 Asset；后置 G6 再验收含 JSON 元数据的 ZIP 素材包。
