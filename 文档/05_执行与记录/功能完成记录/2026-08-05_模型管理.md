# 模型管理功能完成记录

## 功能摘要

设置页新增「模型管理」独立 tab：用户可以自己添加对话/图片模型，列表卡片展示（名称 + provider/model + 配置状态），点击行即选中，行尾删除按钮；首次进入预置常用模型。选中状态持久化，删除当前选中被禁止。

对话运行时已接通：对话面板 header 新增模型选择器（列表=模型管理对话模型），点击即切换——持久化选中 + 后续消息立即使用新模型；消息气泡显示所用模型；「AI 密钥」tab 保存与模型管理选中双向同步。

图片生成运行时已接通：候选图工作区工具栏新增图片模型快捷切换；图片生成默认模型跟随模型管理选中的 image 模型（协议按 providerId 推断，凭证同源复用）；「图片生成」tab 切换与模型管理选中双向同步。

## 为什么做

用户反馈：对话模型/图片生成模型可能有多个，期望"选中哪个就用哪个、随时切换"；现状对话模型只有设置页单一 AI 密钥槽位，前端 `selectedDialogueModel` 启动取一次默认后无法切换（"选 a 后想换 b 没办法"）。

## 影响范围

- 设置页：新增「模型管理」tab（对话模型/图片生成模型两个区块），现有「AI 密钥」「图片生成」「外观设置」功能保留。
- 数据契约：`AppSettings` 新增 `models: ManagedModelItem[]`；存储结构 `StoredAppSettings` v1→v2（增量兼容）。
- 对话运行时：默认模型跟随 `activeTextModelId`；对话面板快捷切换；`syncActiveTextModelWithAIKey` 双向同步。
- 图片生成运行时：默认模型跟随 `activeImageModelId`；候选图工作区快捷切换；`syncActiveImageModelWithProvider` 双向同步。

## 数据或协议变化

- 新增接口：`POST /api/settings/models`、`PATCH /api/settings/models/:id`、`DELETE /api/settings/models/:id`、`PUT /api/settings/models/:id/activate`。
- 文件存储：`app-settings.json` version 1→2，新增 `models[]`、`activeTextModelId`、`activeImageModelId`；旧文件读取时自动补预置并写回；aiKey 已配置凭证时镜像同源模型为默认选中。
- DB 模式：模型列表映射 providerConfig 行（text→owner `opencode`、image→owner `image_secret_store`）；active 指针不落库。
- 对话运行时：默认模型跟随 `activeTextModelId`；「AI 密钥」保存双向同步。
- 图片生成运行时：默认模型跟随 `activeImageModelId`；协议按 providerId 推断（doubao/grok/runware 关键字，默认 openai）；「图片生成」tab 切换双向同步。

## 已知风险

1. DB 模式下不支持为模型配置密钥（`MANAGED_MODEL_SECRET_UNSUPPORTED_IN_DB`）：G1 credential_metadata trigger 只允许固定 owner 组合，凭证轮换/清除/删除需 Outbox 流程，本期未实现。
2. DB 模式下「AI 密钥/图片生成」固定槽位对应的模型行不可在模型管理删除（`MANAGED_MODEL_FIXED_SLOT_DELETE_FORBIDDEN`）。
3. DB 模式下 active 指针不持久化，重启后回到默认预置选中（文件模式完整持久化）。
4. 切换无凭证模型后对话/生成调用可能失败（选择器带"无密钥"标记，错误透传）；带 baseUrl 的跨 provider 切换会触发 OpenCode serve 重启（数秒，既有行为）。
5. 无凭证/无 baseUrl 的图片模型生成时报 `IMAGE_PROVIDER_NOT_CONFIGURED`（既有检查）。

## 后续建议

- DB 模式凭证：设计 Outbox 化的凭证生命周期，或把模型凭证并入既有 image_secret_store/opencode 语义。
- DB 模式 active 指针持久化（当前重启回默认）。
- 可选：模型编辑表单已留 PATCH 接口，前端可补"编辑"入口。
