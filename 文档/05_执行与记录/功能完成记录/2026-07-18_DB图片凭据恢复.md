# DB-only 图片凭据恢复完成记录

## 功能摘要

修复 file → DB-only final import 已验证 Keychain 图片凭据、但没有把配置状态绑定到目标数据库的问题。新迁移会自动完成安全绑定；既有成功迁移可通过显式 replay 修复。当前正式实例的 OpenAI、豆包、Grok 均已恢复配置。

## 影响范围

- final import 编排和显式 repair CLI。
- 新增 verified image credential binder。
- 迁移集成与完整 cutover 演练夹具。
- 当前 `~/.airoaming` DB-only 实例的 Provider/CredentialMetadata 元数据。

## 修改文件

- `apps/server/src/migration/verified-image-credential-binder.ts`
- `apps/server/src/migration/final-importer.ts`
- `apps/server/src/migration/db-import.cli.ts`
- `apps/server/src/migration/project-chapter-shadow-importer.integration.spec.ts`
- `apps/server/src/migration/cutover-runner.service.spec.ts`

## 数据或协议变化

- 无数据库 Schema 变化。
- 新 final import 在 credential verification 与 16-slice verification 都通过后绑定图片凭据元数据。
- 新增内部 CLI 参数 `--rebind-verified-image-credentials true`，仅用于对同一成功 final run 做显式修复。
- 数据库仍不保存明文 API Key；SecretStore 查找继续使用稳定 credentialId。

## 验证结果

- 服务端 typecheck/build 通过。
- 迁移集成 81/81 通过。
- 首次绑定、既有 run replay、幂等和缺失目标 fail-closed 回归通过。
- 当前 DB `integrity_check=ok`，三家 configured，Grok active 且运行时 Keychain Secret 可加载。
- 修复前后任务、attempt、candidate、asset、migration run 计数不变。
- 真实图片调用为 0。

## 已知风险

- 默认并行服务端测试的重型 SQLite/CLI 用例存在既有固定 5 秒超时抖动；本次相关逻辑用例和超时用例隔离复跑通过。
- 历史失败任务不会自动重试，需用户未来显式再次生成。
