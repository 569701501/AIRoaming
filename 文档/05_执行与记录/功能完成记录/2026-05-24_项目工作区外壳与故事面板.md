## 1. 功能摘要

项目库后的项目工作区已落地：用户创建或打开项目后进入工作区，看到项目标题、6 步流程和“项目与故事”面板，并能保存故事草稿到本地 workspace。

## 2. 背景

- 关联需求：继续做下一个功能，并显式调用 `$deep-think`。
- 关联任务记录：`文档/05_执行与记录/任务记录/2026-05-24_项目工作区外壳与故事面板/`
- 关联事实源：`文档/01_愿景与产品/当前UI信息架构.md`、`文档/01_愿景与产品/核心用户流程.md`

## 3. 完成内容

- 创建 / 打开项目后切换到项目工作区。
- 项目工作区显示返回项目库、项目名称、故事标题、当前阶段和 6 步流程。
- 新增“项目与故事”面板。
- 支持编辑和保存项目名称、故事标题、题材标签、漫画格式、画风方向和故事原文。
- 新增 `PATCH /api/projects/{projectId}` 保存草稿接口。
- 草稿保存后写回 `workspace/projects/{projectId}/project.json` 和 `story/story_draft.source.txt`。
- `AI 分析剧情` 当前创建 `story_parse` mock 任务，用于任务链路占位。

## 6. 数据或协议变化

新增接口：

```text
PATCH /api/projects/{projectId}
```

请求：

```json
{
  "name": "迷雾之城",
  "storyTitle": "雨夜天台",
  "genreTags": ["悬疑", "都市"],
  "comicFormat": "vertical_scroll",
  "artStyle": "dark_realistic",
  "description": "雨夜天台",
  "sourceText": "故事原文"
}
```

响应：

```json
{
  "project": {},
  "snapshot": {
    "stages": []
  }
}
```

## 8. 已知风险

- 当前项目仍是进程内记录，服务重启后不会从 workspace 自动回读。
- `AI 分析剧情` 只创建 mock 任务，暂不生成结构化剧情 JSON。
- 还没有真正的项目路由，刷新页面后不会恢复某个项目工作区状态。

## 9. 后续建议

- 下一步实现“剧情结构”页面，展示和编辑 `story_parse` 输出。
- 接入 SQLite/Prisma 后，将项目草稿保存改为数据库事务加文件写入。
- 后续引入项目路由或本地恢复机制，让刷新后能回到当前项目。
