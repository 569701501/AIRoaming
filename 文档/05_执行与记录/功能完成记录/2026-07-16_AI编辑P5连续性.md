# AI 编辑 P5 连续性完成记录

## 1. 功能摘要

在不改变页面、章节 Markdown、数据库 Schema 和 A5 用户步骤的前提下，AI 章节改写已接入上一章当前正式全文。系统会保护当前稿已经建立的跨章承接，并在模型运行期间上一章正式版本变化时拒绝写入过期结果。

## 2. 影响范围

- 编辑专用连续性上下文和事务写入围栏。
- 章节编辑 Prompt、Skill 与 P5 固定校验。
- 对话线程非流式活动消息保护。
- 服务、数据库集成和 DB-only Chromium 用户路径回归。
- 产品流程、来源状态契约和自动化测试文档。

## 3. 数据与协议变化

- 内部章节写入输入可携带上一章 ID、正式版本 ID 和正文摘要，供同一事务复核。
- 没有数据库迁移、公开页面字段或章节 Markdown 变化。
- revision pending 仍为 `kind=legacy`；本轮没有伪造持久 base draft / previous script provenance。

## 4. 用户行为

- 完成第 1 章后，切换到第 2 章仍不会自动生成。
- 用户在对话框明确生成、采用，再明确要求改写。
- 改写结果继续以待确认完整草稿展示，用户仍需采用；系统只在后台增加连续性保护。

## 6. 已知风险

- P5 当前是高置信语义锚点的不退化检查，不是人物知识、伤势、道具和时间线的完整世界状态账本。
- revision pending 没有持久保存本次输入草稿和上一章来源；未来若需要历史审计，应单独设计来源协议和迁移。
- 完整 Server 套件中的备份恢复固定 5 秒超时仍是测试稳定性债，虽然隔离复跑通过。

## 7. 后续建议

先按当前 A+ 流程继续完善其他 Prompt 细节。只有当产品确实需要“查看某次改写基于哪一版当前稿与前章”时，再单独建设 revision provenance，避免为暂未展示的能力扩张页面或数据库。
