# 分镜生成契约 S1 完成记录

## 功能摘要

分镜阶段已形成两个明确的生产动作：首次生成当前章节分镜，以及调整当前待确认分镜。两种动作共用已确认剧情结构和其绑定的正式章节剧本，最终都写入同一套待确认 Storyboard Working Copy；AI 创作和已有剧本导入不再复制下游 Prompt。

页面现有分镜字段、用户查看方式、确认按钮和正式版本流程均未改变。

## 影响范围

- Server Prompt：生成/调整双模式、正式枚举、结构引用和分镜质量边界。
- Server 对话编排：DB 正式 ScriptVersion 读取、pending 修订、Working Copy 保存与确认。
- Server 引用映射：StoryStructure 角色卡引用转 Project Character ID，beat/scene 范围校验。
- Web 版本适配：页面手动编辑和新增镜头使用相同角色映射、稳定 Shot ID 分配和最新并发版本。
- Shared：新增 `revise_pending_storyboard` 对话意图，不增加页面字段或数据库字段。

## 数据与协议变化

- 无数据库 migration、Schema、页面字段、StoryStructure payload 或用户确认节点变化。
- AI 输出使用 StoryStructure 的 character card / beat / scene 本地 ID；新 Shot 不生成数据库 ID。
- 后台把角色引用映射为正式 Project Character ID，通过 `createPendingShot` 分配稳定 Shot ID，再保存严格 Storyboard V2 文档。
- 调整动作只读取并替换当前 pending 的完整草稿；没有 pending 时不修改正式分镜。
- DB 模式只读取 StoryStructure 绑定的正式 ScriptVersion；正文存在未发布修改或来源过期时失败关闭。

## 已知风险

- S1 尚未实现固定质量 Validator 和一次定向修复；当前质量规则先由 Prompt 执行，S2 负责把高确定性错误变成后端门禁。
- 尚未进行双来源真实模型和浏览器验收；该项属于 S3，需在 S2 完成后验证，避免重复跑不稳定模型链路。
- OpenCode `skills/` 资产目录尚未接入生产运行时复制，因此本阶段没有创建孤立的 `storyboard-shot-generate/SKILL.md`；当前生产事实是动态 Prompt。
- Server 全量中的备份恢复用例存在既有固定 5 秒 timeout 稳定性债，与本次分镜改动无关。
