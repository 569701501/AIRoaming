# G5-M2 共享排版领域内核

## 功能摘要

完成平台无关的 Shared Layout Domain Kernel。LayoutDocument、Profile、Element、RichText、Publication 与 39 类编辑命令现在有统一类型、strict codec、规范化、摘要、来源投影、几何和 Undo 语义，Web 与 Server 不再需要各写一套规则。

实现提交：`e93d70f`。

## 影响范围

- 新增 `packages/shared/src/layout/`，并从 Shared 根入口导出。
- 新增固定 Unicode 17.0 / UAX #29 rev47 grapheme 实现 `unicode-segmenter@0.17.0`。
- M0 的 8 份 fixture 现在同时经过生产 LayoutDocument codec 验证。
- 未改数据库、API、Web 页面、用户数据或正式 renderer。

## 数据与协议变化

- LayoutDocument/Profile/Element/RichText/Publication 未知字段 fail-closed，数值与文本统一规范化。
- `sourceDigest` 可结合受控 Asset sha 重算；crop 可结合受控源图尺寸复核空洞。
- 39 类命令具备编译期 payload 映射和 runtime codec；batch 原子执行，inverse 使用受 200 batch / 50 MiB 上限约束的规范文档快照。
- Konva/DOM/viewport/dpr/selection/时间戳/URL 不进入正式文档。

## 验证

- M2 定向：4 files / 29 tests。
- Shared 全量：14 files / 83 tests。
- G5 fixture：3/3；8 份文档 round-trip，100 次 serialize/parse digest 不变。
- 命令：100 次 apply/Undo 恢复原 digest；batch 失败保持输入不变。
- 全仓：typecheck、E2E typecheck、build、Server 80 files / 536 tests 通过。
- `test:render` 仍按设计报告 M5/M7 的生产红灯。

## 已知边界与后续

- M3/M4 Server 保存必须注入真实 Asset sha/尺寸上下文，才能把 source/crop 校验升级为真实通过。
- 编辑器外壳、Working Copy/CAS/autosave、多标签恢复属于 M3。
- Font provision/embedding 属于 M5，正式 PNG/PDF/条漫 renderer 属于 M7。
- backup/archive 保留；未执行 down migration、file-only 回退、G6 或视频链路。
