# 已有剧本长稿、后台与单章重试完成记录

## 功能摘要

已有剧本 B1～B5 的三个剩余增强已完成：超长原稿不再依赖一次模型上下文；拆章目录确认不再等待全部章节生成；失败章节可以在结果卡单独重试。既有产品语义保持不变：目录只整体确认一次、导入草稿全文只读、章节仍逐章确认、两条路线只在正式 `ChapterScriptVersion` 汇合。

## 影响范围

- Shared：超长单段确定性切块；导入批次查询和重试 DTO。
- Server：长稿叶子分析/相邻分层合并、专用导入 Worker、启动恢复、批次查询和单章重试 API。
- Web：批次状态轮询、章节状态更新和失败章 `重试本章`。
- Skill/Prompt：明确技术分段不是章节边界，重试不得借机改写剧情。
- 测试：长稿中段覆盖、Worker 恢复/领取/重试，以及 DB-only 浏览器失败后重试路径。

## 数据与协议变化

- 未新增数据库 migration，继续使用 `0017_script_dual_flow_source_state` 的 batch/item/attempt/error/CAS。
- `ScriptImportBatch/Item` 是唯一进度事实源；没有复制到通用 `GenerationTask`。
- 新增只读批次查询和单章失败重试接口；重试只允许 `generation_failed → materializing`。
- 服务重启时，中断中的 `materializing/verifying` 先形成 `IMPORT_WORKER_INTERRUPTED` 证据，未超过 3 次自动尝试上限时从本章起点恢复。
- StoryStructure、章节剧本和页面内容字段均未变化。

## 已知风险

- 当前 Worker 目标是本地单服务进程；没有 lease owner/token/expiry，不能宣称多实例分布式并发安全。
- 分层分析能避免中段静默截断，但最终完整分析 JSON 仍受模型输出上限约束；超限时会明确失败，不降低覆盖要求。
- Worker 重启后使用当前默认模型恢复；目录确认时临时选择的模型没有新增数据库字段持久化。

## 后续建议

- 只有部署形态升级为多实例时，才增加正式 lease 契约。
- 后续 P6 优先增加多文件跨边界、最终 JSON 极限和真实进程崩溃恢复用例，不再扩充页面字段或另建 ChapterPlan。
