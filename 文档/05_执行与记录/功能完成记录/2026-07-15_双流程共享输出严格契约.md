# 双流程共享输出严格契约完成记录

## 功能摘要

完成 AI 创作与已有剧本导入的第一实施包：在 Shared 建立七个模型阶段共用的可执行输出 Schema、严格解析/校验、canonical Markdown round-trip 和固定正反 fixture。该基线让后续动态 Prompt 与服务端写入门可以 fail-closed，不再依赖“包含几个标签就算合法”或“格式错误自动包装”。

## 影响范围

- 新增 Shared 严格契约，不改变现有页面内容字段。
- 不修改生产动态 Prompt、五个公开 Skill、数据库、pending、正式化或 StoryStructure。
- 旧运行时继续保持兼容；后续实施包显式接线后才改变生产行为。

## 数据或协议变化

- `creative.ideation`：JSON 必须恰好 3 个候选，不再允许多余候选静默截取。
- `creative.outline`：Markdown 固定四区块，`剧集章数`是正整数，章节卡数量与连续序号完全一致。
- `creative.chapter-draft`、`creative.chapter-edit`、`import.materialize`：共用现有六区块页面字段，但严格要求单章、字段顺序、连续场景和无模板/系统/下游产物。
- `import.analyze`：新增 `import-analysis/1.0` 可执行契约。
- `import.verify`：新增 `import-fidelity/1.0` 可执行契约，模型不能输出 verdict 或 ready 状态。
- 原稿标题未提供时，新契约使用 `sourceTitle={value:null,basis:"not_provided"}`。

本轮没有数据库 Schema 或正式 API DTO 变化。
