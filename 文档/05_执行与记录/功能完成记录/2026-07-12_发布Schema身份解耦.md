# 发布 Schema 身份解耦完成记录

## 功能摘要

发布数据库结构身份已从 G1 大生成器的 source manifest digest 中分离。新 identity 只绑定 SQLite、当前 Prisma Schema 与全部有序 migration SQL，因此无关 package script/importer/CLI 改动不会再使发布身份失效；未来新增 migration 也不会被 identity 忽略。

同时整合并纠正 Luna 的 M4 verifier 草稿，修复 G3-M 执行文档落后和 commit 错误，但不把 M4、full importer 或 cutover 宣称为完成。

## 影响范围

- 新增 release Schema identity 模块与特征测试。
- `db:verify` 报告改用 release identity。
- G1 source closure 从 19 份收窄为 18 份并重新生成 manifest。
- 更新 ADR、核心模型事实、AI 上下文入口、G3-M Luna handoff 和任务留痕。

## 数据或协议变化

- 无表、字段、CHECK、trigger 或 migration SQL 变化。
- `effectiveSchemaManifestDigest` 的语义改为 release artifact identity，不再是 G1 source provenance digest。
- G1 manifest 新 digest：`sha256:ad3b0e1ba884e20718e6e81994cbb8beaedbb9e6777e471ac2a21e4c94c2b1ea`。

## 已知风险

- M4 目前只验证复合来源的主追溯锚点存在；完整摘要重算仍需 entityType 证据注册表。
- Layout/Export、Dialogue/provider、full importer、backup/restore 与 activate 未完成。
- release identity 自动纳入 migration 不代表 runtime 自动放行；新 migration 仍必须同步 runtime catalog。

## 后续建议

- 按 handoff 继续完成 full importer 和 M4，不再扩展 G1 大生成器。
- trigger/投影优化继续遵循既定里程碑，不在当前迁移切换中途批量删除。
