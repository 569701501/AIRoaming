## 1. 功能摘要

## 2. 影响范围

- 共享包 `packages/shared`:新增 vitest 依赖 + 配置 + 1 个 spec(15 tests)。

## 6. 已知风险

- **前端 canSave 无测试**:前端判空逻辑未被自动化测试覆盖。后端校验是兜底防线(已测),前端按钮在切章竞态时仍可能亮起,但后端会拒绝。
- **无 e2e**:全链路(前端→后端→fs)无自动化测试,本批是单元/集成层。
- **Dialogue/OpenCode 链路无测试**:AI 写入走 writeChapterDraftFromAI(校验已测),但 DialogueService 工具分流逻辑未测。
- **Service 编排逻辑无测试**:角色图生成 queue/run/confirm 全流程未测(依赖 4 注入 + 跨模块副作用,本批明确不做)。

## 7. 后续建议

- 补 e2e:前端→后端→fs 全链路(Playwright),覆盖切章保存的真实场景。
- 补 DialogueService 工具分流测试(用户/AI 写入路径分流)。
- 给 Repository 更多边界场景补测试(并发写入、大章节、损坏文件恢复)。
- 考虑给 ProjectsService 编排逻辑(角色图生成)抽独立 service 后再补测试(见任务 2026-06-21_ProjectsService拆分 遗留)。
- CI 接入:`pnpm test` + `pnpm typecheck` 作为 PR 必过门禁。

## 8. 关键设计决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 框架 | Vitest | ESM 原生 + Vite 同源 + 零编译配置 |
| Repository 隔离 | 真实临时目录(env 注入) | Repository 职责即 fs,mock 失真 |
| Service 校验测试 | 轻量 mock | 校验在方法首行,throw 早于依赖调用 |
| 测什么 | 行为契约,不测实现 | 降低维护负担 |
| 范围驱动 | 事故 + 拆分遗留高风险 | 锁住会复发的风险,非覆盖度 |
