# Grok 文本模型接入

## 功能摘要

- 设置页保留逻辑模型 `xai/grok-4.5`，支持用户填写官方地址或 OpenAI-compatible 中转地址。
- AI漫游把自定义中转注册为 OpenCode 专用运行时 Provider `airoaming_xai`，避免与 OpenCode 内置 `xai` 适配器冲突。
- 配置只保存 Provider、模型和 Base URL；API Key 单独同步到 OpenCode auth，不进入运行时配置、日志或文档。
- 模型列表只展示 OpenCode 实际注册的模型，不再把设置默认值伪装成可运行 fallback。
- 已完成真实 OpenCode、项目对话和删除 auth 后的冷启动恢复回归；未调用图片生成。

## 影响范围

| 范围 | 变化 |
| --- | --- |
| Web 设置页 | 新增 xAI 选项和 Grok 4.5 预填配置 |
| 设置服务 | 增加 `xai` 展示名；修正切换 provider 时旧密钥指纹残留；同地址同指纹的图片凭据可在冷启动时恢复文本运行时 Key |
| OpenCode Runtime | 逻辑 `xai` 映射为 `airoaming_xai`；使用 `@ai-sdk/openai-compatible` 和用户 Base URL；密钥走独立 auth |
| 模型列表 | 只返回运行时实际注册模型，移除不可运行 fallback |
| 图片生成 | 图片调用协议无变化；本轮只在凭据完全相同时复用已有安全秘密，不调用图片服务 |

## 数据或协议变化

没有新增数据库字段或公开 API 字段。新增内部运行时约定：

```text
页面/业务 providerId = xai
OpenCode runtime providerId = airoaming_xai
modelId = grok-4.5
npm = @ai-sdk/openai-compatible
options.baseURL = 设置页保存的最终 API 前缀
```

## 已知风险

- 文本与图片凭据不相同时，冷启动不会跨用途复用秘密；如果旧逻辑 Provider auth 尚未迁移，用户需要重新保存一次文本 Key。
- 显式设置 `OPENCODE_BASE_URL` 连接外部 OpenCode 时，外部实例必须自行注册相同运行时 Provider；AI漫游不会停止或重写外部进程。
- 全仓并行测试仍存在与本次无关的固定 5 秒集成测试资源竞争；失败用例已隔离复跑通过，本轮未修改其超时策略。
- Web 构建仍有既有的大 chunk 警告。

## 后续建议

1. 后续若支持同一时间保存多套文本 Provider Key，应升级为正式多 Provider 凭证目录，不继续扩展单默认模型设置。
2. 可增加受控运行时健康状态字段，让页面区分“已配置、已注册、已鉴权、可调用”。
3. 保留 `Grok文本回归-0718` 项目供用户查看；确认无需保留后可在项目库删除。
