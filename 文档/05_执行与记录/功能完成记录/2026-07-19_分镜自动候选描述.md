# 分镜自动候选描述完成记录

## 功能摘要

完成“生成分镜时自动产出详细候选图描述”的主流程。用户仍只执行一次“生成分镜”，系统内部先生成分镜骨架，再按整章一次调用自动整理每个镜头的画面、动作、构图和静态摘要；两段全部通过后才形成待确认分镜。

候选图工作台不再依赖用户逐镜点击 AI 优化才能得到完整说明。原单镜优化能力保留为“重新优化本镜头”，只处理少数不满意的镜头，并且仍需用户显式采用返修建议。

## 用户可见变化

- 新生成的待确认分镜默认带有自然、具体、可直接入画的详细单帧说明。
- 多人镜头要求写明总人数，逐一写出绑定角色及其位置、动作对象、承受或视线关系。
- 群体镜头会按绑定名显式写出数量或中性范围；裸写“商队众人”仍会被拦截，但“一群商队众人”可正确识别和编译。
- 候选图工作台显示“生成分镜时已自动整理，可继续微调”。
- 原“AI 优化描述 / 采用优化结果”改为“重新优化本镜头 / 采用返修结果”，明确它是可选返修，不是正常出图前的必点步骤。
- 手工修改和采用返修结果仍只影响本次候选图草稿，不修改正式 StoryboardVersion。

## 实现边界

1. `storyboard-shot-generate` 负责同一用户动作内的两个模型阶段：
   - 第一段生成 `Shot + comic + motion` 骨架。
   - 第二段只整理 `coreAction`、`comic.panelDescription`、`comic.composition` 和 `promptDraft`。
2. 第二段按镜头 `order` 严格一一对应，不得增加、删除、合并、拆分或换序，也不得修改 beat、scene、characterIds、对白、剧情结果或 motion。
3. 骨架和详细说明分别最多自动返修一次；任一阶段仍失败时，整份分镜不写入，也不替换已有 pending。
4. Dialogue 直连生成与持久 `shot_generate` 共用同一章节级整理器和固定校验。
5. 分镜阶段不调用图片 Provider，不绑定参考图槽位、尺寸或 Provider 参数；这些仍由候选图阶段确定性编译。

## 静态复核结论

- 第二段只通过后端构造覆盖四个静态字段，冻结字段没有采用模型回传值。
- 两条生产路径使用同一整理器、同一 Skill 资产和同一质量检查。
- pending 保存发生在两段全部成功之后，失败用例证明不会部分写入。
- Prompt 示例已与多人总数硬规则对齐，双人示例明确写出“两人”。
- 无 Schema、migration 或图片 Provider 调用变化；未跟踪的本地 `apps/server/config.json` 未纳入本次修改。

## 已知风险

- 每次生成分镜增加一次章节级文本调用，失败返修时再增加一次，因此会增加等待时间和文本 token 成本。
- 首版整章一次整理；异常超长章节未来可能需要内部安全分组，但对用户仍应保持一次动作、整体提交。
- 固定校验只能拦截人数、绑定角色、文字、跨地点、多时刻、不可见信息等高确定性问题，不能替代人工审美判断。
- 历史正式分镜不会自动变详细；需要用户重新生成分镜后才进入新流程。
- 已完成一个真实章节的文本模型用户路径验收，但没有运行多章节重复 A/B 或真实图片生成，不能把单章语义链路通过表述为最终成图质量已经证明。
- 多人镜头为满足数量硬门会出现“几人与一队”的规则化句式；当前清楚可读，但自然度仍需用更多真实章节继续观察。

## 后续建议

1. 用另外 2～3 个题材章节重复新流程，重点观察事实增写、角色漏写和多人数量句式是否过于机械。
2. 收集真实章节长度与第二段耗时；只有出现上下文或稳定性证据后，再设计内部批次上限。
3. 保持“重新优化本镜头”是例外返修，不要重新变成每镜必点流程。
