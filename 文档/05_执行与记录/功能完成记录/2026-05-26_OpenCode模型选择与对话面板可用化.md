## 1. 功能摘要

在已有 OpenCode 对话和流式输出基础上，补齐前端模型选择入口：用户可在项目工作区左侧对话框顶部查看和切换 provider/model，发送消息时会把当前选择透传给后端 OpenCode runtime。

## 2. 背景

- 关联需求：用户要求“实现下对话的功能”。
- 关联方案：`文档/04_方案与决策/2026-05-25_OpenCode对话运行时移植方案.md`
- 现状核对：代码已经具备对话线程、OpenCode runtime 和流式输出，但对话框缺少模型选择 UI，且产品文档仍有“真实 OpenCode 对话未接入”的旧表述。

## 3. 完成内容

- 前端 store 增加 runtime model 列表、当前对话模型和模型加载错误状态。
- 进入项目工作区后异步读取 `GET /api/ai-runtime/models`。
- `ProjectDialoguePanel` 顶部新增当前步骤标签和模型下拉。
- 项目工作区所有步骤都保留左侧公共对话框；非剧本步骤右侧暂显示开发占位，不伪装真实业务操作。
- 发送消息时把所选 `providerId/modelId` 放入 `SendDialogueMessageRequest.model`。
- “分析剧情”按钮改为直接发送预设对话 prompt，不再走旧 mock 任务。
- 附件按钮置灰，避免暗示上传剧本已完成。
- 同步修正对话相关事实源。

## 6. 数据或协议变化

无新增接口。前端开始实际使用既有请求字段：

```json
{
  "content": "只回复：对话功能可用",
  "stepKey": "project_story",
  "model": {
    "providerId": "aurora",
    "modelId": "gpt-5.4"
  }
}
```

## 8. 已知风险
