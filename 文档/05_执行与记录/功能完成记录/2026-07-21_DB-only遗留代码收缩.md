# DB-only 遗留代码收缩完成记录

## 功能摘要

在不改数据库、不删除恢复能力的前提下，移除迁移完成后仍留在仓库中的生成器、旧整本导入/重置写链和重复 cutover 协调器，并完成生产入口、CLI、Nest 装配、Web API、迁移恢复与测试责任的收尾审计。累计完整删除 31 个代码文件；当前工作树代码路径 `+848/-14,358`，净减 13,510 行。工作树还包含用户既有 OpenCode 改动，因此行数是工作树级统计，不作为单一清理提交归因。

## 影响范围

- G1 Schema/迁移计划生成器及其测试退役。
- 旧 file-mode 整本剧本分析/覆写、项目级 reset 和 impact preview 退役。

- 旧候选锁 facade、同步参考图 facade、测试专用 service 方法、失效 readiness wrapper 和 no-op applicability guard 退役。
- 删除 `legacy-layout-format.ts`、旧 versioning repository contract、`ProjectStats.vue`、`WorkflowStrip.vue` 四个孤儿文件。
- 清理无调用 Web API/状态事件链和 Shared 旧 DTO/解析器/别名；Server/Web/Shared 启用 unused 编译门禁。
- 当前架构、模块、历史完成记录与长期记忆同步。

## 数据或协议变化

- 删除两个无标准用户入口的旧 HTTP API、旧 file candidate lock facade 和无调用共享 DTO/别名；正式 G4 CandidateDecision 两阶段 API 不变。

## 已知风险

- file runtime 的部分 Story/Storyboard/Preflight fallback 仍存在；它们仍有测试/对话调用，不是本轮可证明的死代码。
- trigger 数量较高，但当前覆盖不可变历史、关系同域、状态迁移、任务租约、Outbox 和激活防回退；直接删除会降低数据库自保护能力。
- `ProjectDeleteOutboxService.purgeDeletedProject` 是必要的最终物理清理，但标准启动未发现通用 Outbox 消费和 purge 调度；这是功能接线风险，不能靠删除代码处理。
- Web AppShell 构建 chunk 约 1.0 MB（gzip 约 328 KB），仍有前端拆包空间。

## 后续建议

- 产品有真实用户前，不再新增迁移 DSL、第二套 coordinator 或 file/DB 双实现。
- 若继续瘦身，优先做“file runtime 整体退役”或按 trigger 约束族做一份带性能基准的新 ADR，避免零散拆除。
- 项目删除 Outbox worker/purge 调度已由用户明确决定暂不修复，作为已接受风险保留。
