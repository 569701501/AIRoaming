# G3-M3-A11C 候选锁定证据导入完成记录

## 功能摘要

恢复旧 storyboard 中有直接 `lockedCandidateId` 证据的候选锁定历史。只有 Candidate、Shot 和项目/章节作用域均可验证时才写入锁定 revision；仅旧 Candidate 状态不会伪造当前锁。

## 影响范围

- 新增 `CandidateLockShadowImporter`，导入 `CandidateLockRevision` 并更新 Shot current pointer。
- CLI 新增 `--slice candidate-locks`。
- 集成 fixture 与 A11C replay 测试覆盖直接证据和幂等。

## 数据与协议变化

- `action=lock`、`origin=legacy_import`、`decidedAt=null`、稳定 revision/source key。
- scope 缺失或指针冲突返回 blocker，不写断链锁定。

## 验证命令与结果

- A11C 定向集成：1 项通过。
- typecheck：通过。
- server 全量回归：44 个测试文件、252 项测试通过；首轮一次 SQLite `database is locked` 锁竞争，复跑通过。
- G1 manifest/schema/migration 三项门禁与 `git diff --check`：通过。

## 已知风险

- verifier、backup、activate、Layout/Export、final import 尚未实现。
- 旧数据的决定时间不可证明，因此保持 `decidedAt=null`。
