# 分镜与图片 Prompt 技能归位完成记录

## 功能摘要

分镜、角色/场景参考图和单镜头候选图的稳定创作提示词，已从后端代码归位到 `apps/server/opencodeAI/skills/`。生产运行时通过统一只读加载器真实读取 Skill 资产；后端继续负责动态项目事实、固定校验、版本写入和 provider 传输适配。

## 影响范围

- 新增三个生产 Skill：`storyboard-shot-generate`、`image-reference-generate`、`image-candidate-generate`。
- 分镜漫画/漫剧双轨规则、参考图 V1/V2、候选图合同和 provider profile 均可在 Skill 目录直接查看和维护。
- 页面字段、数据库 Schema、七阶段流程、待确认/正式确认边界保持不变。
- OpenAI、豆包和 Grok 继续作为交付 profile，不拆分三套创作 Skill。

## 数据或协议变化

- 无数据库 Schema 变化。
- 无页面 DTO 或用户可见字段变化。
- 新增内部 Skill 资产读取约定：Skill 名称、引用路径和模板变量均严格校验；缺失或非法时失败，不回退到代码内第二份 Prompt。

- 服务端定向测试：28/28 通过。
- 迁移测试隔离复跑：12/12 通过。

- 服务端完整测试：121 个测试文件、726/726 通过。

- 编译后加载器读取 Skill 资产检查通过。

## 已知风险

- 当前是“Skill 资产 + 应用内只读加载器”的生产接线方式，还不是由 OpenCode 原生自动发现 Skill；未来切换原生加载时必须继续复用同一事实源，不能复制正文。
- 本轮遵守用户预算约束，未调用真实图片 provider；因此只验证 Prompt 组装与系统回归，不宣称真实视觉质量重新通过。

## 2026-07-18 后续复核纠偏

本记录的“稳定创作提示词已全部归位”表述过强。后续静态复核确认主模板和加载器已完成，但唯一事实源仍未闭合：生产代码还保留 `shot_generate` 旁路、provider 参考图职责、分镜示例语义和参考图画风/版式词汇。修复前应将状态理解为“主路径已迁移，残留待清理”，证据见 `文档/05_执行与记录/任务记录/2026-07-18_后端Prompt残留复核/`。

## 后续建议

- 后续修改创作提示词，只编辑对应 Skill 的 `SKILL.md` 或 `references/`。
- 若未来恢复付费视觉 A/B，先重新确认 provider、模型、单价、请求上限和总预算，再使用已有隔离测试入口执行。
