# Grok 图片默认 1K 完成记录

## 功能摘要

Grok 图片生成不再固定使用 2K。文生图、单图编辑和多图编辑统一显式发送分辨率，默认使用 1K；正式高分辨率需求可通过 `GROK_IMAGE_RESOLUTION=2k` 显式切换。

## 影响范围

- Grok 图片 Provider 请求编译。
- 本地运行环境示例。
- 图片生成任务协议和模块说明。

OpenAI、豆包、候选任务 `requestedSize`、数据库 Schema、任务来源摘要和页面流程不变。

## 修改文件

- `.env.example`
- `apps/server/src/projects/image-provider.service.ts`
- `apps/server/src/projects/image-provider.service.spec.ts`
- `文档/02_架构与契约/生成任务协议.md`
- `文档/03_模块梳理/模块总览与依赖.md`

## 数据或协议变化

- 新增可选运行配置 `GROK_IMAGE_RESOLUTION=1k|2k`。
- 未配置时默认 `1k`。
- 非法值抛出 `IMAGE_PROVIDER_GROK_RESOLUTION_INVALID`，且不发起网络请求。
- 无数据库迁移；既有任务和素材不重写。

## 验证

- 图片 Provider、候选合同与持久 Worker：4 files / 17 tests 通过。
- E2E 环境安全回归：35/35 通过。
- `image-provider.service.spec.ts`：Grok 默认 1K、显式 2K、非法值、单图编辑、多图编辑请求体回归通过。
- Server typecheck、`git diff --check` 通过。
- 全程使用模拟响应，没有真实图片 Provider 调用。

## 已知风险

- 该配置当前是服务运行参数，不在设置页面展示；修改后需重启服务。
- 1K 可能降低小字、远景细节和复杂人脸质量，正式成稿可显式切回 2K。

## 后续建议

只有在确实需要非技术用户频繁切换时，才为 Provider 配置增加受版本管理的 options 模型；不要把 Grok `resolution`、OpenAI `quality/size` 和豆包像素尺寸强行合并成同一个含义不清的字段。
