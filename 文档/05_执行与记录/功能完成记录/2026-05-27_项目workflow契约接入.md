## 功能摘要

项目工作台已接入轻量 `ProjectWorkflow`，把当时的 6 步主流程、当前章节下一步、完成标准和证据路径统一到共享契约和工作台快照中。

2026-05-31 后续口径：产品主流程已调整为 7 步，并在 `剧本` 与 `剧情结构` 之间新增 `项目角色库`。本完成记录保留 2026-05-27 的历史实现事实；当前实现还需要迁移 workflow key、路由、状态门槛和 `workflow.json` 到包含 `project_characters` 的 7 步契约。

## 背景

AI漫游当时已经拆出项目 6 步和章节工作单元，但流程状态此前散落在前端硬编码 `snapshot.stages` 和 `Chapter.status` 中。参考 AuroraPlatformWeb 的 workflow 思路后，本次将 workflow 作为项目级流程视图接入，后续对话框和任务入口可以读取同一份状态。

## 影响范围

- 共享契约新增 `ProjectWorkflow`、`ProjectWorkflowStep`、当时的 6 步 workflow 常量和状态枚举。
- `WorkbenchSnapshot` 新增 `workflow`，`stages` 作为 `workflow.steps` 的兼容镜像。
- 后端根据当前章节 `Chapter.status` 推导 `workflow.currentStepKey` 和每个步骤状态。
- 后端写入 `workspace/projects/{projectId}/workflow.json`。
- 前端流程栏读取步骤状态，显示已完成、当前、等待，并只开放已完成步骤和当前 active 步骤点击。

## 数据或协议变化

新增本地文件：

```text
workspace/projects/{projectId}/workflow.json
```

新增快照字段：

```json
{
  "workflow": {
    "schemaVersion": 1,
    "projectId": "project_001",
    "currentChapterId": "chapter_001",
    "currentStepKey": "story_structure",
    "steps": []
  }
}
```

当时的步骤推导规则：

| `Chapter.status` | `workflow.currentStepKey` |
| --- | --- |
| `draft` | `project_story` |
| `script_done` | `story_structure` |
| `structured` | `storyboard` |
| `storyboard_done` | `image_candidates` |
| `images_done` | `layout_export` |
| `layout_done/exported` | `asset_package` |

当前目标契约需要在 `script_done` 后优先进入 `project_characters`；主角和常驻角色完成定稿后，再允许进入章节级 `story_structure`。

## 风险

- 当前 workflow 由章节状态推导，真实结构化剧情、分镜、候选图、排版等产物完成后，还需要在对应模块落地时推进 `Chapter.status`。
- `blocked` 状态已预留，但当前没有自动阻塞判定。
- 对话框本轮未改；后续再让对话框读取 workflow 生成阶段提示。

## 后续建议

下一步先实现剧情结构步骤的真实工作台或任务入口，让 `story_parse` 成功后推进章节状态到 `structured`，再继续接分镜步骤。
