# 功能摘要

修复剧情结构页场景参考图重生成会覆盖旧文件、DB 保存失败后又误删旧文件的问题，并修复缺失图点击“重新生成”被旧失败任务幂等复用、页面无反馈的问题。场景视觉版本现在使用独立物理路径；缺失文件返回明确 404、Asset 自动校正为 `missing`，页面显示“场景图文件缺失”，每次明确重生成都能创建新的可观察任务。

# 根因

旧 DB worker 固定写入 `scenes/{sceneKey}/background.webp`。场景已有 Asset 后再次生成时，新内容先覆盖该文件，随后 `assets.storage_key` 唯一约束拒绝第二条 Asset；异常清理再删除同一路径，最终形成“DB 旧资产仍为 ready、物理文件已丢失”的不一致状态。

后续无反馈问题由两点叠加造成：场景生成请求没有一次操作级 `requestId`，所以相同输入会复用旧终态失败任务；同时任务 `target.id` 使用 `ChapterScene.id`，页面却拿结构中的 `sceneKey` 比较，无法可靠显示该场景正在生成。

# 影响范围

- DB `scene_reference_generate` worker 的物理路径与失败清理边界。
- Asset 文件读取时的缺失状态校正与 HTTP 错误。
- 剧情结构页场景图加载失败提示。
- Preflight 场景检查的 `referenceAssetId` 从 `SceneVisual.id` 修正为 `Asset.id`。
- 场景生成请求增加操作级 `requestId`，活动任务仍按项目、章节和 `ChapterScene.id` 去重。
- 页面按 `task.input.sceneKey` 匹配剧情结构场景并显示“生成中”。

# 数据或协议变化

- 无数据库 Schema 变化。
- DB-only 新场景图路径改为 `projects/{projectId}/chapters/{chapterId}/scenes/{sceneKey}/visuals/{assetId}/background.webp`。
- 历史路径保持只读兼容，不迁移、不覆盖。
- 物理文件缺失时，`Asset.status` 由 `ready` 校正为 `missing`，接口返回 `404 PROJECT_ASSET_FILE_NOT_FOUND`。
- 同一 `requestId` 幂等重放；不同用户点击使用不同 `requestId`。旧任务终态后再次点击会创建新任务，但同一场景已有活动任务时仍只返回该活动任务。
