# 出图准备视觉来源失效门禁完成记录

## 功能摘要

修复“场景图或角色图在确认出图准备后发生变化，但页面仍允许生成候选图”的 freshness 缺口。正式页面和新图片任务现在都会基于当前 DB 视觉来源实时判断旧 Preflight 是否失效。

## 影响范围

- Preflight 派生 freshness。
- 七阶段 DB workflow 第 4/5 步状态。
- `shot_prompt_generate` / `image_generate` 的 NewWorkGate。
- 不影响页面字段、StoryStructure、Storyboard、数据库 Schema、历史确认版本或图片 Prompt。

- `packages/shared/src/versioning/production-state.ts`

- `apps/server/src/projects/versioning/script-version.repository.ts`
- `apps/server/src/projects/project-db-persistence.integration.spec.ts`
- 本完成记录、任务记录、验收清单、会话记忆和长期记忆。

## 数据与协议变化

- 无 migration、无表字段变化、无 HTTP DTO 新字段。
- `ChapterVersionGraphInput` 增加内部可选 `livePreflightSourceSnapshot`。
- 复用既有 freshness reason code：Storyboard、Character、Scene、Style、Unresolved。
- 已确认 PreflightRevision 继续不可变；重新确认会创建新 revision。

## 已知风险

- 部分仓储 mutation 返回的内嵌 productionState 没有 live reader，可能在响应瞬间仍是旧投影；正式 Workbench 查询与所有新图片任务门禁均已使用 live 路径。
- 本次真实页面只做门禁复核，没有替用户点击“确认出图准备”，也没有创建真实候选图任务。

## 后续建议

- 用户自行确认当前出图准备后，再进入候选图工作台。
- 若未来要求所有 mutation 响应也实时反映视觉 freshness，应把 live snapshot 注入统一 mutation response projector，不要在各仓储重复实现比较规则。
