# 候选图画面描述优化完成记录

## 功能摘要

完成“分镜基础单帧描述 → 候选图工作台可编辑草稿 → 固定质量检查 → 按需 AI 优化建议 → 确定性 Provider 编译”的镜头视觉编译链路。

没有新增第八个顶层步骤，也没有把润色塞进出图准备。AI 结果不会暗中覆盖正式分镜；用户只有点击“采用优化结果”后，建议才进入当前候选图草稿。

## 用户可见变化

- 候选图工作台新增“画面 / 动作 / 构图”三个编辑区，明确说明只影响本次候选图。
- 生成前显示人话问题；确定性硬伤会禁用单镜生成，批量生成会先检查整章且零任务落库。
- 可对当前镜头点击“AI 优化描述”，单独查看建议并决定是否采用。
- 用户在 AI 请求后又修改草稿，旧建议自动隐藏，避免覆盖新编辑。
- 旧 file-mode 明确禁用尚未真实接通的 AI 优化入口。

## 影响范围

- 分镜生成 Skill 与固定质量门。
- CandidateGenerationSpec、三家 Provider Prompt Profile 与多人/群体镜头合同。
- file/DB 图片任务创建门禁、`shot_prompt_generate` worker 和错误映射。
- 候选图预览 API、页面编辑区、批量预检和任务轮询。
- E2E fake provider、候选图 fixture 与 DB 浏览器验收。

## 数据与协议变化

- 无数据库 Schema 或 migration 变化。
- 新增后向兼容 `CandidatePromptOverrides`：`visualDescription/action/composition`，每项非空且最多 1200 字。
- `CandidateGenerationSpec` 可选返回 `visualIssues`；旧规格仍可读取。
- DB 创建门禁只信任三段语义草稿，仍由服务端冻结正式来源、Prompt、引用、尺寸、Provider 和 digest。
- `shot_prompt_generate` 输出新增可见建议字段、`mustShow`、固定质量问题和来源冲突警告；任务来源继续绑定 StoryboardVersion、PreflightRevision、角色/场景视觉。

## 验证结果

- Shared 全量 27 files / 167 tests 通过。
- Server 最终全量 800 项中 799 项通过；唯一失败是无关备份并发用例的 5 秒环境超时，立即隔离复跑通过。复核修正前 798 项曾全量通过，修正后 9 项聚焦测试通过。
- Shared、Server、Web、E2E 类型检查通过；Web 生产构建通过。
- DB 目标集成、42 项 DB 全量集成和候选图 Chromium E2E 通过。
- `git diff --check` 通过；无 Schema/migration diff。
- fake provider 审计确认没有图片接口请求，真实图片费用为 0。

完整证据见 `文档/06_测试与验收/候选图画面描述优化验收清单.md`。

## 已知风险

- 中文固定检查仍需用更多真实镜头迭代，不能取代人工审美判断。
- 页面草稿刷新后不持久化，这是首版无新表方案的取舍。
- 批量创建在预检后逐任务提交，网络中断仍可能留下部分批次。
- 没有运行真实图片 A/B，因此不能把输入链路修复表述为成图质量已被证明。

## 后续建议

1. 用户授权后，从真实 12 镜中选 3～5 个典型坏例，在相同资产和参数下做新旧 Prompt 小规模 A/B。
2. 根据 A/B 与人工反馈扩充固定语料，优先处理误报/漏报，不把主观文风做成阻断。
3. 若用户需要跨刷新保留未生成草稿，再评估独立草稿版本或浏览器本地恢复；不要直接改不可变 StoryboardVersion。
