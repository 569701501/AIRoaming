## 1. 功能摘要

修复剧本对话刷新恢复和流式中断状态收敛问题：进入剧本页时先解析当前章节再加载章节对话线程；浏览器刷新、页面离开或流式请求 abort 后，后端会把不再活跃的 assistant `running` 消息收敛为失败，不再永久转圈。

## 2. 影响范围

| 类型 | 内容 |
| --- | --- |
| 前端 | `workbench-store.refresh` 改为先读取 workbench，再按解析后的当前章节加载对话线程 |
| 前端 | `AppShell` 在 snapshot 已存在但 dialogueThread 缺失时不跳过打开项目流程 |
| 后端 | `DialogueController` 在 SSE 客户端 close 时 abort 当前请求 |
| 后端 | `DialogueService` 跟踪活跃流式 assistant 消息，读取线程或创建新 turn 时收敛不活跃的旧 `running` |
| 后端 | `OpenCodeRuntimeService` 支持把 AbortSignal 传入 session 创建、消息发送和事件监听 |
| 文档 | 更新对话线程加载和 running 状态收敛契约 |

## 3. 验收口径

- 刷新/重新进入剧本页时，默认加载当前章节线程，不误读空的项目级线程。
- 浏览器刷新或请求 abort 后，后端不保留永久 `running` assistant 消息。
- 再次发送同线程消息前，旧的非活跃 `running` 消息会被标记为失败。
- `analyze_script_import`、灵感、剧本大纲和章节写入的业务工具结果展示不受影响。

## 5. 已知风险

- 当前对话线程仍是进程内 Map，服务重启后不会恢复历史对话；本次只修前端刷新、页面重进和同进程流式中断状态。
