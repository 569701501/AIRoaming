## 1. 功能摘要

后端 DialogueService 拆分完成后，全仓最大文件转到前端。本批次做低风险高收益的纯函数外移 + 通用组件抽取，不动业务行为。

关键发现：前端大 `.vue` 文件的"大"主要是 CSS(StoryboardWorkspace 60% 是 CSS，逻辑只 ~430 行)，所以拆分价值在提升可维护性，不是单纯减行数。

## 2. 影响范围

- `workbench-store.ts`：17 个纯函数外移到 utils
- `StoryboardWorkspace.vue`/`StoryStructureWorkspace.vue`：选项字典外移 + 3 个内联组件合并为通用 EditableField
- 调用面零变更：store 仍导出相同 action，组件 props/emit 不变

## 4. 关键设计

- **沿用 `utils/*.ts` 纯函数模式**（项目无 composable 约定），不引入 `composables/` 目录。
- **通用 EditableField**：合并 3 个逻辑实质相同的内联 defineComponent+h 组件（EditableShotField/EditableShotSelect/EditableBlock），统一为 SFC，用 `options` prop 区分 textarea/select 模式。
- **CSS 选择器适配**：StoryboardWorkspace 的 `:deep(.editable-shot-*)` 规则同时命中旧类名(原生 HTML duration/voice 输入)和新 `.editable-field .editable-*`(EditableField 组件)，保留列主题色(purple/teal)。

## 6. 已知风险

- 运行时行内编辑功能尚未人工验证。建议验证：分镜页面的文本编辑(Enter 提交)、下拉选择(景别/机位/运镜)、剧情结构页面的可编辑字段(canEdit 门控)。
- CSS 选择器复制导致样式表略增(148→151 kB)，可接受。

## 7. 后续建议(不做，高耦合/高风险)

- workbench-store 的 chapter-applyer 簇(applyChapterUpdate 等 5 方法 + 8 调用方)——不可分割核心，不拆。
- dialogue→chapter 桥(applyDialogueStreamEvent/applyToolResultChapterUpdate)——跨域耦合，不拆。
- usePendingResource composable——pending-edit 策略分叉(Storyboard 允许 pending 编辑，Structure 不允许)，需先对齐策略。
- 大 .vue 文件的 CSS 拆分(60% 行数是 CSS，ROI 低)。
