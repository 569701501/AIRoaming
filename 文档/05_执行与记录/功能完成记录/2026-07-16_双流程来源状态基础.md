# 双流程来源状态基础完成记录

## 功能摘要

完成 A+ 双流程实施包 2：AI 创作与已有剧本导入现在具备可追溯的内部来源和状态基础。两条路线仍在正式 `ChapterScriptVersion` 汇合，现有页面内容字段和 StoryStructure payload 未改变。

## 影响范围

- Shared：原稿快照、确认拆章目录、pending 来源投影和摘要。
- Database：0017 新增 9 张来源/状态表，并扩展 `ChapterScriptPending`。
- Server：双流程来源仓储、导入状态机、AI/import pending 来源密封、导入直接确认。
- 下游门禁：任意 pending 阻断 StoryStructure，导入 pending 使用独立原因码。
- 运维：运行时 migration ledger、发布 Schema 身份、G1 post-overlay 和项目协调删除。
- 文档：新增正式来源与状态契约、任务 Reviews 和 Handoff。

## 关键规则

- 不新增 `ChapterPlan`。
- 拆章目录整体确认一次，只批准边界；正式正文仍逐章确认。
- Import pending 不允许采用、丢弃、手动修改或 AI 重新整理。
- AI pending 不允许覆盖已有正式章或非空正文，并密封绑定大纲、章节卡和必要的前章正式版本。
- 只有正式 `ChapterScriptVersion` 可以进入现有 StoryStructure。

## 数据与协议变化

- 原稿使用 Version/Document/Block 三层不可变结构和稳定 block 引用。
- 导入使用 AnalysisCandidate → confirmed ChapterMap → ImportBatch/Item → FidelityReport → import pending。
- `ChapterScriptPending.kind` 新增 `legacy/ai/import` 语义；新 AI/import pending 必须有密封来源投影。
- 0017 前的 pending 保持 legacy，不回填虚假来源。
