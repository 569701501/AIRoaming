# 候选图必需引用编译功能完成记录

## 功能摘要

候选图的角色和场景引用已从“尽量传入”升级为必需引用合同。容量足够时独立直传；容量不足时只把全部角色合成确定性身份板，场景保持独立；任何必需来源缺失、损坏、无效或无法覆盖时，都在调用外部图片 Provider 前失败，不再静默丢第 3 个角色或场景。

## 影响范围

- 文件兼容候选生成与 DB-only `image_generate` worker。
- OpenAI、Doubao/Seedream、Grok 候选图 Provider 适配。
- DB 出图准备 final 证据、单人 preview 身份输入和任务来源投影。
- Candidate Asset metadata、任务输出、Prompt 引用指引及视觉 A/B 口径。

## 主要修改

- 新增 `candidate_reference_plan_v1` 和 `cast_identity_board_v1`，使用 `sharp@0.35.3` 解码 PNG/JPEG/WebP、检测损坏输入并确定性合成角色板。
- Grok 单参考改为官方单图编辑；三角色加场景改为“全员身份板 + 原始场景”，成功计划强制 `omittedRequired=[]`。
- OpenAI/Doubao 容量内保留独立引用，超限时打包全部角色，不再按优先级删除必需来源。
- DB final 继续作为出图批准证据，Candidate 物理输入使用单人 preview；新 final 保存 preview `sourceVisualId`，旧空来源资产只在存在唯一可验证的更早 preview 时兼容。
- 引用缺失、文件不可读、图片损坏、final-only 旧任务、来源关系无效和技术容量超限均失败关闭。
- 文件候选与 DB Candidate Asset metadata v2 保存原始来源、物理槽位、覆盖关系、派生摘要、生成模式及请求/实际尺寸。

## 数据与协议变化

- 无数据库 migration、无页面字段变化、无候选图用户流程变化。
- `CharacterVisual.sourceVisualId` 对新生成 final 开始保存实际 preview 来源；旧数据允许为空并按受控兼容规则读取。
- DB Candidate Asset 使用 metadata schema v2；任务输出增加同一 `referencePlan` 证据。
- 身份板是内存派生输入，不注册新的项目 Asset，也不替换现有角色资产。

## 已知风险

- 引用完整送达不等于模型成图必然一致；多人漏人、串脸、动作绑定、远景服装和场景地标仍需真实视觉 A/B。
- 当前构图仅 `prompt_only`，没有结构化站位或场景构图板。
- 12 人和 640×896 单元是技术止损值，不是质量阈值。
- 当前没有按角色 mask 的局部修复和身份板跨任务缓存。

## 后续建议

先在用户授权预算后用固定三人镜头做小规模跨 Provider A/B，再决定真实质量阈值。关键镜头若仍不稳定，优先补结构化站位和局部角色修复；长期高频核心 IP 才评估专用身份模型或 LoRA。
