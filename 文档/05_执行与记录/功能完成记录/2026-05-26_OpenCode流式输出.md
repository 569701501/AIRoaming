## 1. 功能摘要

完成剧本步骤对话框的流式输出：assistant 回复会通过 `dialogue.message.delta` 增量展示，不再等完整回复结束后一次性出现。

## 2. 背景

- 关联需求：用户要求“流式输出做一下”。
- 关联方案：`文档/04_方案与决策/2026-05-25_OpenCode对话运行时移植方案.md`
- 关联任务记录：`文档/05_执行与记录/任务记录/2026-05-26_OpenCode流式输出/`

## 3. 完成内容

- 后端 OpenCode runtime 新增 `/event` SSE 监听，读取 `message.part.delta` 的文本增量。
- 新增 AI漫游标准流式事件 `DialogueStreamEvent`。
- 新增 `POST /api/projects/{projectId}/dialogue/threads/{stepKey}/messages/stream`。
- 前端 API 使用 `fetch + ReadableStream` 解析 SSE。
- Pinia store 根据 `dialogue.message.created`、`dialogue.message.delta`、`dialogue.message.completed` 增量更新对话消息。
- 对话框消息区在流式更新时自动滚动到底部。

## 6. 数据或协议变化

新增接口：

```text
POST /api/projects/{projectId}/dialogue/threads/{stepKey}/messages/stream
```

事件类型：

```text
dialogue.message.created
dialogue.message.delta
dialogue.message.completed
dialogue.error
```

规则：

- 前端只消费 AI漫游 `dialogue.*` 事件，不消费 OpenCode 原始事件。
- 最终 completed 内容仍以 OpenCode `/message` 完整响应校准。
- AI 输出仍不会自动修改右侧剧本文档。

## 8. 已知风险

- 暂未支持停止生成，客户端断开后 OpenCode 可能继续完成当前请求。
- 对话记录仍为进程内存储，服务重启后丢失。
- 还没有模型选择 UI 和 variant。
- 流式输出只处理文本 delta，工具调用、建议动作和 usage 事件尚未标准化。

## 9. 后续建议

- 下一步做停止生成，配合客户端断开或用户手动停止。
- 增加 suggestion 事件，承接“应用到剧本 / 插入光标处”。
- 将对话线程和运行时映射持久化。
