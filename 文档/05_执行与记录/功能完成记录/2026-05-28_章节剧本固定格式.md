## 1. 功能摘要

剧本阶段输出格式收口为固定「章节剧本」：用户上传/粘贴剧本或选择 AI 灵感种子后，右侧章节编辑器只写入章节剧本正文，不把主体列表、正式场景列表、剧情节拍、分镜剧本、镜头编号、图片 Prompt 或 JSON 作为最终章节剧本输出。

## 2. 背景

剧本阶段已有两条入口：用户提供剧本整理，以及 AI 先生成灵感种子、用户选择后生成章节草稿。此前灵感数量仍是 5 个，章节起草只要求普通 Markdown，容易和后续「剧情结构」「分镜工作台」「候选图」阶段产物混在一起。

## 3. 影响范围

- 灵感生成：`generate_inspiration_seeds` 固定每次生成 3 个种子；用户可选择其一，或要求重新生成 3 个。
- 章节起草：`script-chapter-drafting` 必须生成固定格式「章节剧本」。
- 章节编辑：`script-chapter-editing` 必须返回完整固定格式「章节剧本」。
- 用户提供剧本导入：非标准文本写入章节时，后端用同一格式做兜底包装，避免直接落成松散 Markdown。
- 剧本阶段边界：显式禁止输出主体列表、正式场景列表、剧情节拍、分镜剧本、镜头编号、图片 Prompt 和 JSON。

## 5. 数据或协议变化

无 DTO 或 API 字段变化。共享包新增格式工具函数和 `SCRIPT_INSPIRATION_SEED_COUNT = 3` 常量；后端对话服务和项目服务消费该常量与格式工具。

## 6. 验证结果

静态复核：

- 当前代码与事实源中不再保留“生成 5 个灵感”的当前口径。
- 章节起草、章节编辑、导入兜底和 OpenCode AI 资产均同步固定「章节剧本」格式。
- 灵感技能内部仍允许返回 JSON 供后端解析；禁令收口为“不把 JSON 作为最终章节剧本输出”，避免与工具解析契约冲突。

命令验证：

```text
corepack pnpm --filter @airoaming/shared typecheck
corepack pnpm --filter @airoaming/shared build
corepack pnpm --filter @airoaming/server typecheck
corepack pnpm --filter @airoaming/web typecheck
git diff --check
```

结果：均通过。第一次直接跑 server typecheck 时因共享包 `dist` 尚未构建而找不到新增导出；执行 shared build 后重跑通过。

运行/用户路径复核：

本次未启动真实 OpenCode 模型做端到端生成，因为输出质量依赖本机 OpenCode 服务和模型配置；已通过 prompt、后端解析和类型检查验证链路契约。

## 7. 已知风险

- 上传/粘贴已有剧本的第一版导入仍以服务端规则做格式兜底；它能统一结构，但不能像完整 AI 整理那样精确提炼每一章的基础方向、亮点和视觉基调。
- OpenCode AI 资产目录仍未完整接入运行时模板复制，真实生效主路径仍依赖 `DialogueService` 注入的 prompt。
- 目前只保存最近一次 AI 写入来源，完整修订历史和一键回退仍待实现。
- 未做真实模型端到端验收，仍需在可用 OpenCode runtime 下确认模型稳定遵守固定格式。

## 8. 后续建议

- 将导入剧本的格式整理升级为真正逐章 AI normalize，再由后端受控写入。
- 为「章节剧本」增加轻量格式检查，提示缺少的固定模块。
- 后续进入「剧情结构」阶段时，再从章节剧本中生成正式角色卡、场景卡和剧情节拍。
