## 1. 功能摘要

按 Cursor Cloud Agent「env-setup / Set up a new environment」流程，为本仓库搭建可复用的云端开发环境：默认镜像 + `install`（依赖安装与 shared 构建）+ `start`（并行启动 server 与 web 开发服务器），并端到端验证核心工作台可用。

## 2. 影响范围

- 云端开发环境配置：以仓库文件 `.cursor/environment.json` 提交（repo 托管，随分支/PR 版本化、代码可见），为最高优先级配置源。
- 同时已通过 propose 记录了一份等价的面板提案（DB 托管，附已校验 build）；因提交了仓库文件，仓库配置优先，面板 Save 变为可选/冗余。
- 不改动任何应用代码。

## 3. 环境配置

| 阶段 | 命令 | 说明 |
| --- | --- | --- |
| 基础镜像 | Cursor 默认镜像 | 已含 Node v22.14.0 + corepack（pnpm 9.15.4），无需自定义 Dockerfile |
| `install` | `corepack pnpm install && corepack pnpm --filter @airoaming/shared build` | 幂等；安装依赖并构建 shared 产物，供 server/web 解析 |
| `start` | `corepack pnpm dev` | 构建 shared 后并行启动 server（4310）与 web（5173），保持前台附着 |
| `ports` | `4310`（server）、`5173`（web） | 端口转发 |

配置文件：`.cursor/environment.json`。默认端口：Web `5173`、Server `4310/api`。核心工作台无需任何密钥。

## 4. 数据或协议变化

无。后端运行期仍以本地 `workspace/projects/` 文件系统持久化，未启用 Prisma 运行期依赖。

## 6. 已知风险

- AI 生成类功能（opencode / 图像生成）依赖外部 provider 凭据，本次未纳入环境跑通范围；如需使用需在环境 Secrets 中补充。
- `@prisma/client` 为依赖但运行期未使用，安装时 postinstall 会提示找不到默认 schema，属预期无害告警。
- 交付形态为仓库文件 `.cursor/environment.json`（repo 托管，最高优先级）；同时存在一份等价的面板提案（DB 托管）。仓库文件优先，二者内容一致，不冲突；若未来只想用面板配置，需删除该仓库文件。
- draft build 被独立 agent 直接启动时出现「stale build → 跳过 install」现象（node_modules/shared dist 未预置、start 未自动拉起），属 draft build 直接启动的固有行为；用户在环境面板 Save 后，Portal 会服务端复核并复用该 build 已校验的快照，正式环境将带依赖启动并执行 `start`。

## 7. 后续建议

- 若引入 Prisma 运行期依赖，需在 `install` 增加 `prisma generate --schema apps/server/prisma/schema.prisma` 与迁移步骤。
- 如需在环境面板中直接看到并重启两个开发服务器日志，可在支持 `terminals` 的配置形态下拆分为独立终端。
