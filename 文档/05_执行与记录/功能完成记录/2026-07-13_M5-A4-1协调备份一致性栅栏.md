# M5-A4-1 协调备份一致性栅栏

## 功能摘要

完成 coordinated backup 的 SQLite 写入栅栏和 backup/restore CLI 精确参数门禁。DB 派生事实、数据库副本、ready Asset 复制和 settings 元数据读取现在处于同一个稳定区间；active writer、栅栏内第二 writer 和额外 positional 参数均 fail-closed。

## 影响范围

- 不改变 Prisma schema、migration、trigger、release identity 或 restore 的 A4-2 账本规则。
- 不实现 SecretStore、final importer、pre-cutover 成功路径、activate、D2 或 M6。
- M5 总状态继续为 `hardening_required`。

## 修改文件

- `apps/server/src/backup/app-backup.service.ts`
- `apps/server/src/backup/app-backup.cli.ts`
- `apps/server/src/backup/app-restore.cli.ts`
- `apps/server/src/backup/app-backup-restore.integration.spec.ts`

## 数据与协议变化

- 新增内部 `withDatabaseWriteFence`：执行 `wal_checkpoint(TRUNCATE)`、`BEGIN IMMEDIATE`、WAL 收敛检查，并在 operation 完成后回滚释放栅栏。
- `copyDatabaseWhileLocked` 在 fence 内复制数据库，复制后重新读取源摘要并执行 integrity/FK/ledger 表检查。
- ready Asset 在复制前后校验 regular file、bytes、sha256；源文件变化返回 `BACKUP_ASSET_MISMATCH`。
- backup/restore CLI 只接受严格 `flag value` 和唯一 `--format json`，非法参数返回对应 `*_ARGS_INVALID`。
