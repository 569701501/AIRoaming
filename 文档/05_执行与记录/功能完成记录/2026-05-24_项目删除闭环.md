## 1. 功能摘要

项目库已支持删除项目：鼠标 hover 到项目卡片封面时显示删除按钮，点击后弹出二次确认，确认后删除项目记录、本地 workspace 项目目录和该项目 mock 任务。

## 2. 背景

- 关联需求：用户要求项目列表卡片图片 hover 后显示删除按钮，并在二次确认后删除当前项目。
- 关联方案：当前项目数据由后端写入本地 `workspace/projects/{projectId}`，删除必须由后端统一执行，前端不能直接操作物理路径。
- 关联任务记录：本次为单功能闭环，未创建复杂任务三件套。

## 3. 完成内容

- 新增 `DELETE /projects/{projectId}` 接口。
- 删除时移除进程内项目记录、本地 `workspace/projects/{projectId}` 目录和该项目关联 mock 任务。
- 项目卡片封面 hover 显示右上角删除按钮；触屏设备默认显示删除按钮。
- 新增删除确认弹窗，用户确认后才执行删除。
- 删除成功后项目库刷新；如果删除的是当前选中项目，同步清空当前项目快照。

## 6. 数据或协议变化

新增接口：

```text
DELETE /api/projects/{projectId}
```

响应：

```json
{
  "deletedProjectId": "project_id",
  "deletedTaskCount": 0
}
```

删除行为：

```text
用户确认删除
  -> 前端调用 DELETE /projects/{projectId}
  -> 后端删除 workspace/projects/{projectId}
  -> 后端删除进程内 Project
  -> 后端删除该 projectId 下的 mock GenerationTask
  -> 前端刷新项目库
```

## 8. 已知风险

- 当前项目和任务仍为进程内记录，服务重启后不会从 workspace 回读；接入 SQLite/Prisma 后需要把删除行为改为数据库事务加文件删除。
- 当前删除为硬删除，尚未提供回收站、撤销或归档恢复能力。

## 9. 后续建议

- 接入数据库后增加项目删除事务和失败补偿记录。
- 增加“归档项目”作为更安全的非破坏性操作。
- 后续如果支持真实素材生成，删除前可展示项目占用空间和素材数量。
