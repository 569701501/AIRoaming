# 功能摘要

剧情结构生成规则已迁入 `structure-story-parse` Skill。对话生成和持久 `story_parse` 不再维护两套方法，模型输出与现有页面字段一致，系统字段继续由后端负责。

# 影响范围

- OpenCodeAI Skill 资产。
- 对话 Prompt 动态装配。
- 持久 `story_parse` Provider 路径。
- StoryStructure 语义输出到 `StoryDocumentV2` 的后端转换。
- Prompt 来源与任务协议文档。

# 数据与协议变化

- Prisma Schema：无变化。
- 外部 API / 任务类型：无变化。
- 页面字段与确认流程：无变化。
- 模型输出职责：不再要求生成数据库/版本 ID；后端补齐。

# 验证结果

- 新 Skill 和其余三个已迁移生产 Skill 校验通过。
- 针对性回归 26/26，通过类型检查和构建。
- 服务端全量 731/733；两个固定 5 秒慢测并发超时，隔离复跑 2/2 通过。
- 构建产物读取新 Skill 成功。
- 未产生任何付费媒体调用。

# 已知风险

- 持久 `story_parse` 当前只冻结 ScriptVersion，未冻结 OutlineVersion；因此后台 Prompt 有意不注入运行时 current outline。
- 全量默认并发测试的两个历史 5 秒慢测仍是测试稳定性债，与本功能无关。

# 后续建议

按同样原则逐步审查剧本创作/导入阶段 Prompt，但每次只迁移真实生产调用的阶段，不新增孤立 Skill，也不改变用户已经认可的页面字段。
