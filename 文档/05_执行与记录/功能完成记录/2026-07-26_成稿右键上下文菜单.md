# 漫画成稿元素/图层右键上下文菜单

## 功能摘要

在漫画成稿编辑器中,右键点击画布元素(Konva 命中层)或右侧「图层」Tab 的图层行,在指针处弹出上下文菜单,点击菜单项直接执行操作。右键未选中的元素会先把它选中再弹出菜单。

## 菜单项(按元素类型动态显示)

- 通用:复制对象、上移一层/下移一层(按图层序边界禁用)、锁定/解锁、隐藏/显示、删除对象(走统一 `deleteElementsWithConfirm` 确认)。
- 含图元素:`在画布上拖调裁切`(进入裁切工具)。
- 有图画格:`分离为自由图`。
- 自由图且存在空画格:`自由图放回画格`。

只读模式(<1024px)不弹出。点击菜单外、Escape 或执行动作后关闭;位置做视口边界钳制。

## 影响范围

- `apps/web/src/components/workbench/LayoutKonvaInteractionLayer.vue`:命中矩形新增 `contextmenu` 监听,emit `contextMenu { elementId, clientX, clientY }` 并 preventDefault。
- `apps/web/src/components/workbench/LayoutExportWorkspace.vue`:`contextMenu` 状态、`openElementContextMenu`/`closeContextMenu`/`runContextMenuAction`、图层行 `@contextmenu.prevent`、菜单模板与样式、Escape 优先关菜单。
- 复用既有动作函数,无新命令类型、无协议变化。

## 关键缺陷与修复

首版 `runContextMenuAction` 先 `closeContextMenu()` 再执行动作,而菜单项闭包内引用 `contextMenuElement`(menu 关闭后为 null),导致 `Cannot read properties of null (reading 'id')` 静默失败(菜单不执行也不关闭)。修复为先执行动作再关闭;e2e(m4)锁定/解锁断言语义复现并验证。

## 验证命令与结果

- `pnpm --filter @airoaming/web typecheck`、`typecheck:e2e` 全绿。
- 契约测试:`LayoutExportWorkspace.contract.test.mjs` / `LayoutKonvaInteractionLayer.contract.test.mjs` 新增菜单接线断言,web 55/55。
- e2e:`layout-editor-m4` 新增画布右键锁定 → API 验证 locked=true → 图层行右键解锁 → locked=false;db 套件 18/18 全绿。

## 已知风险

- 菜单项目前是固定集合,多选状态下动作只作用于右键的单个元素(复制/删除实际作用于 primaryElement/该元素),多选批量操作菜单未做。
- 菜单高度按 340px 钳制估算,极端小窗口可能仍有少量溢出。

## 后续建议

- 多选右键时提供批量锁定/隐藏/删除/对齐入口。
- 画布空白处右键可提供「添加画格/添加文字/添加气泡/页面设置」入口(本次未做,用户未要求)。
