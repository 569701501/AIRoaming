# 图片 Prompt 真实 A/B 完成记录

## 功能摘要

使用 S4.1 固定语料和生产 Prompt/Provider 边界执行真实图片 A/B。严格预算 runner 为 30 个槽位建立先写账本、失败占位、无自动重试的保护，并保存 6 张共用参考、20 张真实输出、Provider 追溯、尺寸/引用 warning 和人工视觉复核。

## 影响范围

- 新增只读、隔离的真实图片 A/B CLI 和安全计划测试。
- 不修改生产 Prompt、页面、数据库、正式项目、当前 active provider 或现有项目资产。
- 未改变 `ImageProviderService` 生产行为；本轮只暴露其现状差异。

## 验证结果

- 固定预算测试：4/4 通过。
- Server 全量 119 files / 715 tests、typecheck、build 通过。
- 对终态账本重复执行 runner 后，历史请求计数仍为 21，未重复调用 provider。
- 真实运行：21 次请求；20 成功、1 失败、9 跳过、0 待执行、0 不确定重试槽位。
- Doubao：10/10 成功；人工契约分 14/30，强制水印与比例策略不通过。
- Grok：10/10 成功；人工契约分 24/30，当前表现最佳，但有单参考舍弃、三参考上限和 1 次分格污染。
- OpenAI：首个请求 503，停止剩余 9 槽位；画质不评分。
- 证据 secret scan：未发现 API Key 字段、secretRef、fingerprint 或 Bearer 内容。

## 已知风险

- 样本只有 5 类、每类 2 张，结论适用于当前 Prompt、模型、端点和参考图，不是永久排名。
- 内置生成的 6 张参考图只服务公平对比，不是项目正式角色/场景资产。
- OpenAI 未形成图片样本，必须在端点恢复后用相同案例补做单独授权复测。

## 后续建议

先设计 provider 适配修复：Doubao 水印开关与尺寸策略、Grok 单参考和多人身份边界、OpenAI 503 诊断；再以同一固定语料进行小规模复测。不要先继续堆 Prompt 规则。
