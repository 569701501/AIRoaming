# G0 七阶段测试安全网完成记录

## 1. 功能摘要

已建立 G0 七阶段自动化安全网：Vitest/Nest Service 锁住当前正确的阶段推进与门禁，Playwright 启动独立 fake provider、Nest、Vite 和 Chromium，覆盖真实 HTTP、项目库、工作区与七阶段流程栏。

G0 只证明安全网可重复、可隔离、可诊断；不代表 G1～G5 或最终漫画出版链路已经实现。

## 2. 完成内容

- 新增 8 条七阶段 Service characterization，覆盖显式版式创建、剧本/结构/分镜推进、pending/confirmed、preflight、候选锁定、下游门禁和重开语义。
- 新增 15 条 E2E 环境契约和 3 条 prepare 契约，保护路径、marker、凭据、loopback、PID、teardown、shared/dist 与 source alias。
- 新增 Playwright 基础设施、API-01～API-04 与 UI-01～UI-05；API 删除测试含独立控制项目，UI 在 page 创建前拦截 HTTP/WebSocket。
- 新增 `typecheck:e2e`、`test:e2e:env`、`test:e2e:prepare`、`test:e2e`、`test:e2e:repeat`、`test:e2e:ui` 与 `test:all` 命令。
- Node 22.17.1 下统一显式使用 `node --import tsx`；根依赖固定 `tsx@4.22.3`，Playwright 固定 `1.61.1`。
- Nest/TSX 与 Vite E2E runtime 均从 `packages/shared/src/index.ts` 解析 shared，不在 prepare 中构建 shared。

## 5. 数据或协议变化

没有业务数据或生产协议变化。新增的是测试运行协议：

- 每次 E2E 使用唯一 runId、独立端口、带 marker 的临时 workspace。

- 子进程使用最小 operational allowlist、假 key 与 `OPENCODE_AUTO_START=false`。
- 浏览器只放行当前 run 的 loopback HTTP/WebSocket origin。
- prepare 必须真实运行 env suite、拒绝零测试假绿，且不能改写 shared/dist。
