## 1. 功能摘要

用户上传或粘贴剧本文本后，系统会先执行 `analyze_script_import` 导入前分析；只有内容像剧本且章节边界可信，才继续调用 `import_script_to_chapters` 写入章节。

## 2. 背景

此前导入链路命中“整理成章节”后会直接写章节，导致非剧本、提纲或普通编号文档可能因为 `1`、`2`、`3` 或 Markdown 标题被误拆成章节。用户确认了新规则：上传剧本后必须先正式检查，通过才写入；不通过绝不写文件。

## 3. 影响范围

- 共享 DTO 增加 `ScriptImportAnalysis`、章节边界计划和 `analyze_script_import` 工具结果。
- 后端导入链路改为：分析 -> 通过才写入；失败或待确认不写文件。
- 对需要确认的导入，后端在当前剧本线程内临时缓存待导入文本；用户回复“确认导入/确认覆盖”后再写入。
- 前端收到 `analyze_script_import` 时只展示提示，不刷新章节；收到写入成功结果时才刷新工作台。

## 5. 数据或协议变化

`DialogueToolResult.tool` 新增：

```text
analyze_script_import
```

`DialogueToolResult.status` 新增：

```text
needs_user_confirmation
```

`DialogueToolResult.analysis` 用于承载导入前分析结果：

```json
{
  "decision": "needs_user_confirmation",
  "contentType": "story_prose",
  "reason": "这份内容像故事或剧本，但没有识别到明确章节边界。",
  "chapters": [
    {
      "order": 1,
      "title": "第 1 章",
      "boundary": "single_chapter",
      "summary": "雨夜里，主角第一次发现异常。"
    }
  ],
  "risk": "继续导入会先写成单个章节。",
  "nextTool": null
}
```

## 6. 验证结果

已执行：

```text
corepack pnpm --filter @airoaming/shared build
corepack pnpm --filter @airoaming/server typecheck
corepack pnpm --filter @airoaming/web typecheck
git diff --check
```

结果：均通过。

临时后端运行验证：

```text
PORT=4312 AIROAMING_WORKSPACE_ROOT=$(mktemp -d) OPENCODE_AUTO_START=false corepack pnpm --filter @airoaming/server dev
```

验证路径：

- 非剧本/大纲附件：返回 `analyze_script_import` + `failed/reject`，当前章节正文长度仍为 0。
- 明确 `# 第 1 章`、`# 第 2 章` 剧本：先返回 `analyze_script_import/succeeded`，再返回 `import_script_to_chapters/succeeded`，写入 2 个章节。
- 无章节故事正文：先返回 `analyze_script_import/needs_user_confirmation` 且不写入；回复“确认导入”后返回 `import_script_to_chapters/succeeded`，写入单章。

## 7. 已知风险

- 当前导入前分析是后端规则分析，还不是完整 LLM 结构化判断；后续可把 `script-import-normalize` 接到 OpenCode tool bridge。
- 待确认导入目前存于进程内线程，服务重启会丢失；与当前对话线程未持久化状态一致。
- 第一版不自动按剧情节拍拆无章节文本；没有明确章节边界时先要求用户确认按单章导入。

## 8. 后续建议

1. 增加真实 `analyze_script_import` OpenCode 工具桥，让 LLM 能在规则基础上输出更精细的章节计划。
2. 补 `update_chapter_draft`，让 AI 在章节内编辑当前草稿。
3. 持久化对话线程和待确认工具动作。
