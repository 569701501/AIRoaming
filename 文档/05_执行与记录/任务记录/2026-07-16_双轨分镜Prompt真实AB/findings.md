# 漫画 / 漫剧双轨分镜 Prompt V1/V2 真实 A/B 发现

## 已确认事实

- V1 的精确生产基线是 `c3fe684`；V2 首个生产提交是 `5551271`。
- 两个版本之间没有 Schema 或数据库 migration 差异，可以从同一正式结构基线安全复制 SQLite 与 workspace。
- 当前默认文本模型为 `self/gpt-5.5`；真实文本生成不需要调用图片 provider。
- `AIROAMING_TASK_WORKER_ENABLED=false` 可关闭图片等持久任务 worker；完整剧本拆章仍需要暂时启用 Script Import Worker。
- 上次 S3 使用隔离环境并在结束后关闭，导致用户无法查看；本次必须保留 V1/V2 可访问页面并交付地址。

## 风险

- 模型生成存在随机性；每个版本每条路线只跑一次时，结论只能是两样例证据。
- 两个版本的 Conversation Session 必须独立，否则模型上下文会污染比较。
- 同一数据库不能同时让 V1/V2 写入；必须在正式结构后复制并分别运行。
- V2 仍受 M1 共用镜头数量、景别和机位限制，不能用本次结果直接证明独立序列 Schema 的必要性。

## AB1 真实基线发现

1. 短于 1200 字的粘贴原稿即使用户写了“已有剧本导入路线”，只要没有命中“导入/整理/拆分 + 剧本/章节”的确定性正则，就会落入 AI 创作大纲；这是可复现的入口误路由风险。
2. 自然格式原稿第 1 章正文覆盖、对白、顺序和实体验证全部通过，但 verifier 把模型生成的“保护许岚”和“形成悬疑开场”摘要元数据列为 `UNSUPPORTED_METADATA` 并令整章 `IMPORT_FIDELITY_FAILED`。说明当前 P6 对摘要性元数据过严，会让正文忠实的章节无法进入用户确认。
3. 标准章节剧本原稿可以稳定通过两章 materialize + verify；因此最终分镜 A/B 使用标准稿，避免把导入 formatter 的失败混入分镜 Prompt 差异。
4. 导入后的正式章节标题存在重复章节前缀；StoryStructure 又把同一人“老周/远处的老周”拆成两个角色。A/B 两侧从同一 StoryVersion 复制，所以不会影响版本间公平性，但会影响导入路线绝对质量评分。
5. AI 创作基线：竖向条漫，4 角色 / 7 场景 / 13 beats。导入基线：分页漫画，7 角色 / 3 场景 / 8 beats。两个样例能同时覆盖长节拍密度与来源忠实型短章。

## AB3 / AB4 真实分镜发现

1. V2 的双轨规则在两条来源路线都产生了可观察改善，不依赖导入或创作的某一特定上游：漫画继续选择静态决定性瞬间，漫剧更常表达开始、变化和结束状态。
2. V2 的“主镜 + 必要辅助镜”使 AI 和导入样本的 Shot 数都比 V1 少约 29%，beat 覆盖仍为 100%。这减少了机械拆镜，但也减少了漫画细分画格，后续需要更多题材确认漫画节奏没有退化。
3. AI V2 的动态总时长由 95.4 秒增至 127 秒，voice line 由 24 增至 45；它更完整地保留了正式对白和表演空间。导入 V2 的原稿六句对白仍全部逐字命中。
4. AI V2 首次生成出现一次 comic/motion 对白不一致，定向修复成功。说明现有一次修复链有效，但 V2 首次稳定性尚不能判为优于 V1。
5. V2 的下一项 Prompt 风险不是“双轨仍未分开”，而是少数动态镜头过载：一个共享 Shot 可能承载多个动作变化和多轮对白。V2.1 应以动作/状态变化/对白负载为条件拆镜，不按固定秒数拆镜。
6. 基于结构本地角色 ID 直接检查生成后的 `characterIds` 会产生假阳性；服务端已将其映射为项目角色 UUID。A/B 必须对照项目角色库验证，四组实际未知角色引用均为 0。
7. 本轮正式判定 `MIXED / V2_DIRECTIONALLY_BETTER`：继续保留 V2 方向，不回退 V1；补 V2.1 与多题材重复样例后再决定 `V2_ACCEPTED`。
