# 目标

明确“长篇拆章”如何成为项目外的大文件入口，并结合当前代码判断以下修正方案能否落地：

```text
导入并预览拆章
→ 直接创建漫画项目
→ 项目内立即可见全部章节目录
→ 默认打开第 1 章
→ 原文、制作数据和 AI 仅按当前章处理
```

# 非目标

- 本阶段不修改产品代码、数据库或页面。
- 不把整本小说交给 AI，也不决定所有后续小说分析能力。
- 不立即导入桌面《凡人修仙传》数据。
- 本阶段不修改产品功能代码、数据库 Schema 或正式产品事实源。

# 验收标准

- 核对现有全局导航、创建项目流程和资产边界。
- 调研成熟产品对“大文档导入、切分、复用、按需处理”的做法。
- 核对修正方案与当前 `Project/Chapter`、B1～B5 导入、工作台快照、章节控件、路由、备份和删除链路的兼容性。
- 给出可直接复用、必须改造、不能沿用和建议实施顺序。
- 明确推荐方案、首版范围和不应包含的功能。

# 当前角色边界

- Orchestrator：只读核对事实源和代码，形成适配方案。
- Worker：本阶段只更新任务与会话记录，不改功能代码。
- Scrutiny Review：复核数据语义、全量加载风险、Token 边界和现有下游复用点。
- Runtime/User Review：本阶段无运行功能可验，待用户确认进入实施后执行真实页面路径。

# 退出标准

用户能够基于当前代码事实决定是否进入实施；在用户确认前不修改正式产品事实源与功能代码。
