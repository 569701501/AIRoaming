# 图片生成 Prompt 离线基线任务计划

## 1. 目标

在不调用真实图片服务的前提下，为以下正式生产 Prompt 建立同源、可重复、可审计的固定样例和质量基线：

1. 角色参考图：单角色正面预览、四视图定稿。
2. 场景参考图：可复用、无人、无字的空间资产。
3. 候选图：单镜头干净底图，覆盖单人、多人、无角色及不同 provider profile。

## 2. 非目标

- 不调用付费图片服务。
- 不评价真实成图美术质量。
- 不修改页面展示字段、数据库 Schema、任务状态或用户确认流程。
- 证据不足时不修改生产 Prompt。
- 不把漫画分镜 Prompt 与图片生成 Prompt 合并。

## 3. 验收标准

- 固定样例直接调用生产 Prompt 构造器，不复制另一套 Prompt 逻辑。
- 样例覆盖角色 preview/final、场景、候选图单人/多人/无角色以及现有 provider profile。
- 可自动检查单镜头、单静态瞬间、无文字/气泡/分格、角色与场景引用边界、尺寸和 provider 投递策略。
- 能输出稳定的机器可读快照或报告，后续真实图片 A/B 可复用同一案例 ID。
- 相关单元测试、Server 类型检查和构建通过。
- 完成静态复核、运行复核说明、Handoff 和完成记录。

## 4. 阶段

### P0：事实源与调用链盘点

状态：`completed`

- 读取图片 Prompt、任务协议、素材路径和既有验收文档。
- 核对 `reference-prompt.util.ts`、`candidate-generation-spec.ts`、provider profile、页面预览和 worker 的实际调用关系。

退出标准：形成明确的事实源矩阵和未覆盖风险。

### P1：固定样例与质量口径

状态：`completed`

- 定义最小但有区分度的角色、场景、候选图样例。
- 定义机器可检查的必须包含、禁止包含、引用数量、尺寸和 provider 投递规则。

退出标准：样例能覆盖现有生产契约，且不依赖真实图片生成。

### P2：离线基线实现

状态：`completed`

- 复用生产 builder 生成快照或机器报告。
- 增加针对固定样例的自动化检查。

退出标准：测试能捕获 Prompt 漂移和媒介边界回归。

### P3：验证与结论

状态：`completed`

- 执行定向测试、全量 Server 测试、类型检查、构建和变更检查。
- 只读完成 Scrutiny Review。
- 说明本阶段 Runtime/User Review 为什么不调用图片 provider，以及下一阶段真实视觉 A/B 的进入条件。

退出标准：所有证据可追溯，明确是否需要修改生产 Prompt。

## 5. 当前决策

- 生产 Prompt 暂时冻结，以 2026-07-16 已确认实现为基线。
- 本阶段评测对象是“实际发送给 provider 的 Prompt 和参数”，不是页面摘要 `promptDraft`。
- 候选图必须继续保持单镜头、单幅、无文字、无气泡、无分格/边框的干净底图边界。
- 真实成图视觉 A/B 是下一阶段，必须在本基线完成后再单独授权执行。

## 6. 最终结论

- 当前生产图片 Prompt 无需修改，继续冻结 2026-07-16 已确认版本。
- 固定语料和离线报告已经可以作为真实图片 A/B 的唯一输入清单。
- 下一阶段固定为 5 类候选镜头 × 3 个 provider × 每项 2 张，共 30 张；未经用户明确授权保持 `not_run`。
