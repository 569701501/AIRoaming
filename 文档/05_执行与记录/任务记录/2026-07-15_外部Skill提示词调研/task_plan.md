# 外部 Skill 提示词调研任务

## 目标

重新核验公开来源中的创作类 Skill、提示词和工作流，提取适合 AI漫游剧本链路的可复用方法，形成供用户拍板的适配矩阵。

## 非目标

- 本轮不修改生产 `SKILL.md`、动态 prompt、工具或业务代码。
- 本轮不编写 Luna 施工计划或 Handoff。
- 不整段复制外部提示词，不引入第三方故事、角色、版权 IP 或艺术家风格。
- 不以“热门程度”替代来源质量、许可边界和可验证性。

## 调研对象

| 项目 Skill | 调研重点 |
| --- | --- |
| `script-inspiration-seeding` | 钩子、欲望、冲突、反差、视觉承诺、方向差异化 |
| `script-outline-drafting` | premise 到 outline、因果链、角色弧、冲突升级、章节承诺 |
| `script-chapter-drafting` | 场景目标、阻碍、转折、对白潜台词、视觉可画性、结尾钩子 |
| `script-chapter-editing` | 诊断维度、修订顺序、约束保持、完整稿输出和自检 |

## 阶段

- [x] R0：核对现有计划、4 个生产 Skill、动态 prompt 和项目边界。
- [x] R1：重新搜索并核验外部一手来源、原始文件和许可证。
- [x] R2：提取方法部件，区分可吸收、需改造、禁止引入。
- [x] R3：形成逐 Skill 适配矩阵、候选方案和风险说明。
- [x] R4：静态复核来源、证据、项目边界和结论一致性。
- [x] R5：交付用户审阅；等待用户拍板后另行编写无排期施工计划。

## 判断标准

每项候选方法必须说明：来源、原始用途、适配的项目 Skill、预期收益、不能照搬的部分、建议验证样例和许可风险。

## 当前角色边界

- Orchestrator：约束调研范围、维护证据与用户决策项。
- Worker：只读外部来源并整理方法，不修改生产资产。
- Scrutiny Review：复核来源可信度、许可证与项目边界。
- Runtime/User Review：本轮不适用；用户负责审阅调研结论并拍板候选方法。

## 退出标准

1. 外部来源可追溯到原始页面或原始仓库文件。
2. 4 个生产 Skill 均有明确的“保留 / 吸收 / 拒绝”结论。
3. 用户能据此逐项拍板，不需要先阅读外部仓库。
4. 未修改任何生产 Skill 或功能代码。
