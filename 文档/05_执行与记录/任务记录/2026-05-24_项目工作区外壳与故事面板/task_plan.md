## 1. 目标

把项目库后的下一段主链路补上：用户创建或打开项目后进入项目工作区，看到项目标题、6 步流程和“项目与故事”工作面板，并可以保存故事草稿。

## 2. 非目标

- 不实现真实剧情结构化结果。
- 不实现分镜、候选图、排版导出和素材包真实业务。
- 不新增账号、团队、通知、全局素材库。
- 不引入路由系统，当前仍用 Pinia 的 `activeProjectId` 控制项目库 / 项目工作区切换。

## 3. 当前事实

| 事实 | 证据 |
| --- | --- |
| 应用入口为项目库 | `文档/01_愿景与产品/当前UI信息架构.md` |
| 项目工作区是下一阶段 | `文档/00_索引/AI上下文入口.md` |
| 项目内主流程为 6 步 | `文档/01_愿景与产品/核心用户流程.md` |
| 项目创建已写入本地 workspace | `文档/02_架构与契约/素材文件与版本契约.md` |

## 4. 风险级别

中等。

原因：

- 涉及共享 DTO、后端 API、前端 store 和 UI。
- 会改变创建项目后的用户路径。
- 仍处于进程内数据阶段，不能宣称持久化完整可靠。

## 5. 阶段计划

| 阶段 | 状态 | 退出标准 |
| --- | --- | --- |
| 1. 任务记录与边界 | completed | 三件套任务记录建立，目标和非目标明确 |
| 2. 后端草稿保存接口 | completed | 支持更新项目名、故事标题、题材、格式、画风和故事原文，并写回 workspace 文件 |
| 3. 前端工作区外壳 | completed | 创建 / 打开项目后进入工作区，可返回项目库，显示 6 步流程 |
| 4. 项目与故事面板 | completed | 可编辑并保存故事草稿，可触发当前 mock 分析任务 |
| 5. 验证与留痕 | completed | 构建、接口、用户路径验证通过，完成记录和事实源同步 |

## 6. 当前角色边界

| 角色 | 本轮职责 |
| --- | --- |
| Orchestrator | 对齐事实源、控制范围、维护任务记录 |
| Worker | 实现接口、store、组件和样式 |
| Scrutiny Review | 检查合同、状态、文档是否矛盾 |
| Runtime/User Review | 验证真实创建 / 打开 / 保存 / 返回路径 |

## 7. 退出标准

- 项目库点击 `继续创作` 能进入项目工作区。
- 创建项目成功后能进入项目工作区。
- 项目工作区能返回项目库。
- 项目与故事面板保存后刷新快照，workspace 中 `project.json` 和 `story/story_draft.source.txt` 更新。
- 文档和完成记录同步。
