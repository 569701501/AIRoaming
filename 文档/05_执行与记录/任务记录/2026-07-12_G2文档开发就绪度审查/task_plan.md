# G2 文档开发就绪度审查计划

## 目标

判断现有 G2 文档是否达到“另一个开发模型无需补关键决策即可分阶段实现并按证据验收”的标准。

## 非目标

- 不实现 G2 功能，不修改 Schema、migration 或业务代码。
- 不假设完整 G1 已完成。
- 不以文档篇幅、测试数量或旧 Scrutiny 结论代替当前代码对照。

## 审查维度

1. 产品语义与范围是否唯一。
2. 数据模型、migration overlay 和事务是否可直接落地。
3. API/DTO/错误码是否闭合。
4. 当前模块 seam 与文件级改动范围是否明确。
5. 持久任务、迟到结果、importer 等前置依赖是否真实存在。
6. 验收命令、fixture、故障注入和退出闸门是否可执行。

## 退出标准

- 给出明确的“可直接开发 / 可分切片开发 / 不可直接开发”结论。
- 每个阻断项都引用当前文档或代码证据，并说明需要补哪类契约。
- 区分可由实现者自行决定的工程细节与必须由项目先冻结的语义决策。

## 完成判定

- [x] 已给出“可分切片开发、不可整包无监督开发”的明确结论。
- [x] 已对照当前 Schema、Repository、Task runtime、共享 DTO、Controller 和测试脚本。
- [x] 已区分 G2 设计质量与当前工程施工包的闭合程度。
- [x] 已形成交给外部开发模型前必须补齐的五项实施资料。
