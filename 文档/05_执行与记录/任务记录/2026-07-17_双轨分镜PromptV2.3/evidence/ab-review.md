# 漫画 / 漫剧双轨分镜 Prompt V2.3 真实 A/B

## 结论

V2.3 通过，作为当前生产 Prompt 基线。

它保留了 V2.1 的镜头克制，并解决 V2.2 因全量对白回填造成的单镜对白拥挤；同时新增了正式正文逐字来源硬门。导入路线没有明显退化，AI 创作路线的长镜和对白负载显著收敛。

## 固定条件

| 条件 | 值 |
| --- | --- |
| 模型 | `self/gpt-5.5` |
| 用户输入 | `请生成当前章节完整分镜，漫画和漫剧都要完整。` |
| AI 创作项目 | `AB-AI-零点回声`，第 1 章 `无编号列车` |
| 导入项目 | `AB-导入-雨夜证词`，第 1 章 `最后一班渡轮` |
| 输出边界 | 只生成待确认分镜，不点击确认，不进入出图准备 |
| 安全边界 | 图片、视频、TTS、字幕任务 worker 关闭 |

两处 4 条台词镜头均为 10 秒内的完整交流：一处是“姐姐承诺—程野追问—站务中心回答”，另一处是“疑似真实姐姐出现—苏弥制止—程野确认—警告落点”。它们属于 Prompt 允许的软例外，不是把不同动作链挤回单镜。

人工逐镜检查发现一个非阻断弱化点：`beat_01` 的结构结果包含“旧机器刹车声把程野引向站台尽头”，V2.3 镜头只写程野看向废弃轨道，下一镜直接揭示旧列车，没有明确保留刹车声。因主因果仍可读、后续揭示正确，本轮不回滚；该问题进入后续“Beat summary/outcome 语义覆盖”软评测样例。

## 最终判定

`accepted_with_non_blocking_observation`

V2.3 进入当前生产基线。下一轮不继续堆 Prompt 文案；优先补独立的语义软评测，专门检查每个 Beat 的 `summary + outcome` 是否真正进入镜头内容，而不是只检查 `beatId` 是否出现。
