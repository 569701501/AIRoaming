# 任务计划：漫画成稿专业编辑能力评估

## 目标

结合现有漫画成稿事实源与实现，判断应吸收哪些专业编辑能力、是否应引入第三方库，并给出可执行且兼容现有契约的分阶段路线。

## 非目标

- 本轮不直接替换画布内核。
- 本轮不实现完整图片编辑器或新增 AI 生图后端。
- 本轮不复制 GPL 项目代码或视觉资产。

## 验收标准

1. 结论建立在现有产品、契约和代码事实上。
2. 对候选项目给出采用、参考或拒绝的清晰边界。
3. 方案覆盖数据模型、编辑命令、渲染导出、许可证与迁移风险。
4. 给出分阶段优先级与首批用户价值。
5. 完成静态复核；运行复核如不适用需说明原因。

## 关键问题

1. 现有 SVG/DOM 编辑与确定性渲染能否承载新增专业能力，还是确有必要引入 Konva。
2. 气泡系统应扩展内部协议，还是运行时依赖 Comical-JS。
3. 图片滤镜应存参数化编辑状态，还是烘焙为新素材版本。
4. 哪些能力属于漫画成稿，哪些仍应留在候选图或素材生成阶段。

## 已做决策

| Decision | Rationale |
| --- | --- |
| 把“吸收能力”与“直接集成项目”分开评估 | 现有成稿已有稳定契约，第三方完整编辑器并非天然可嵌入模块 |
| 本轮只做评估和正式方案，不直接更换内核 | 更换内核涉及编辑、导出、测试和历史文档兼容，回滚成本高 |
| Konva 只作为 Web 交互 adapter | ADR-0016 已采纳该边界；内部文档、命令和 Server renderer 继续作为事实源 |
| V2 publication parity 先于高级效果 | 自动成稿 V2 当前只能 Working Copy/Pending，尚不能形成正式 Revision 和 publication |
| 先释放现有协议能力，再评估 V3 | 气泡基础样式、横竖排、SFX 和图层已有数据/命令；滤镜、阴影和新轮廓会破坏 V2→V1 可见内容投影 |
| Comical-JS 不作为默认气泡内核 | 它的 Canvas/SVG/DOM 与 JSON 会形成第二套坐标、撤销和导出语义；仅在新轮廓需求成立时做限时 PoC |
