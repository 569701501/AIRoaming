# 后端规模与 Trigger 审计计划

## 目标

- 复算前后端代码量、数据库表和 trigger 数量，澄清统计口径。
- 解释后端规模的组成，而不是只用总行数判断复杂度。
- 核实 SQLite DB-only 迁移与 Schema 代码生成器是否已落地、当前承担什么职责。
- 对 trigger 分组并给出保留、替代、删除候选及其证据。

## 非目标

- 本次不删除表、trigger、迁移记录或后端代码。
- 本次不改变数据库契约、产品流程或 UI。
- 本次不把测试、生成文件和业务代码混为同一统计口径。

## 验收标准

1. 统计命令可复现，并分别披露生产代码、测试、迁移/生成代码与文档。
2. 表和 trigger 同时核对定义源、生成产物与标准运行 SQLite。
3. 每类 trigger 都说明写入方、约束目标、应用层是否已有等价保护及移除风险。
4. 最终给出工程先行风险判断和按收益/风险排序的收缩建议。

## 阶段

1. 事实源与统计口径。
2. SQLite 迁移和 Schema 生成链追踪。
3. Trigger 分类、调用链与必要性审查。
4. 静态复核、结论与留痕。

## 退出标准

- 完成静态证据复核并明确通过/不通过。
- 本次是只读架构审计，无产品运行路径变更；运行复核以 SQLite 元数据和现有测试证据替代，并注明边界。
- `progress.md`、`findings.md`、会话记忆和长期记忆同步完成。

## 完成状态

- [x] 事实源、历史决策和代码路径完成交叉核对。
- [x] 代码、表、trigger、文档规模完成复算。
- [x] 标准 SQLite、生成器产物和 trigger 契约测试完成验证。
- [x] 静态复核与运行复核完成，审计通过。
