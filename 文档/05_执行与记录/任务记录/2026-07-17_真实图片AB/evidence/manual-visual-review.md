## 4. 问题归因

### 4.1 主要不是 Prompt 文案的问题

1. Doubao 请求层固定 `watermark: true`，与 Prompt 的“无水印”硬约束直接冲突；单纯重复提示词无法解决。
2. Doubao 的 provider size 映射固定为 16:9/9:16，而候选规格是 3:2/2:3；属于尺寸策略冲突。
3. Grok 单参考为保比例主动放弃参考、多人最多使用 3 张；属于 provider 能力与适配策略边界。
4. OpenAI 503 是当前端点/中转可用性问题，不是图片质量结论。

### 4.2 Prompt 可继续优化的点

1. 单人近景中“终端编号区域”会对数字产生正向词汇诱导；可改为“被遮蔽的终端面板区域”，继续保留不得出现可读编号的禁令。
2. 双人镜头需要更明确锁定动作主客体，例如“许澄的手放在林舟肩上；林舟不能把手放在许澄肩上”。
3. Grok 出现一次斜切分格，说明通用的“不要分格”仍可能失效；可在 provider profile 中把“单张无边框全幅画面”前置，但不能据此保证 10/10。

## 5. 当前建议

1. 当前候选图默认优先级暂定为 `Grok > Doubao`；OpenAI 保持未判定，先修复或验证 503。
2. Doubao 在关闭强制水印、统一目标比例之前，不应作为正式干净候选底图的默认 provider。
3. Grok 可作为当前默认，但单参考场景镜头不能声称使用了场景参考；四人及以上身份锁定也不能只靠现有三参考入口。
4. 下一步先做 provider 适配修复方案，不立即改生产 Prompt；修复后使用同一 5 类语料做小规模复测，不能换题证明通过。
