## 研究发现

- 已知真实臃肿点包括：开发状态条、对话内部 ID、英文技能名、候选页重复解释、项目卡封面与状态重叠、摘要原始 Markdown 符号。
- 现有 `prototypes/ui-redesign-v2/` 已有剧本工作区与项目库方向稿，可作为统一视觉基线，但仍需覆盖全部页面。
- 真实截图共 12 张：项目库、创建项目、设置、剧本、角色库、剧情结构、分镜、出图准备、候选图、排版导出、素材包、排版只读预览。
- 工作区现状共性问题：顶部与流程轨较高；左侧 AI 面板过程卡与正文抢焦点；右侧不同页面缺少统一 StepHeader；结构/分镜泄露 `DB Working Copy` 和英文 skill；候选图解释与表单密度过高；排版工具横向拥挤；素材包直接展示内部文件名，用户交付语义弱。
- 项目库现状问题：单项目时大面积空白，封面状态与缺图提示重叠，摘要暴露 Markdown 标记，卡片阶段仍显示旧“角色库第 2 步”口径。
- 排版只读预览在带正确 `chapterId` 查询参数后可显示真实成稿，路由裸地址会提示缺少参数，因此概念稿应以真实带参预览为准。

## 缺口与风险

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 图像模型可能写错密集中文 | 视觉稿文字局部失真 | 以层级与布局评审为主；生成后逐张检查，必要时迭代或用浏览器原型承载精确文字 |
| 某些页面依赖特定项目状态 | 无法从单一项目获得所有页面 | 使用现有真实项目、只读路由切换和既有原型组合，不触发业务生成 |
| “每个页面”可能包含大量弹窗与状态变体 | 交付规模失控 | 以用户可达主页面为一级覆盖，关键弹窗单列；不把每个错误态都当独立页面 |

## 技术决策

| 决策 | 依据 |
| --- | --- |
| 视觉稿归类为 `ui-mockup` | 用户需要高保真产品 UI 图片，而非生产代码 |
| 现状截图与新版稿全部保存到 `output/ui-redesign/` | 项目绑定资产必须落在工作区内 |
| 不用网络搜索 | 本轮只依赖项目事实与真实本地页面，不需要最新外部资料 |
| 使用统一 1440×900 桌面视口 | 主要工作台是桌面生产工具，固定尺寸便于逐页横向评审 |
| 不使用浏览器 `fullPage` 作为内部滚动工作台截图 | 实测会出现渲染缺片；视口截图稳定并代表用户首屏体验 |
