# 任务计划：AI 质量与提示词工程

## 状态

`proposed / backlog`。已作为独立大功能登记，本轮不展开开发；它不是推荐路线 R5，也不因 R5 后置而取消。

## 目标

把当前分散的 agent 指令、结构化输出契约、图像/视频 prompt 和供应商参数，升级为可登记、可版本化、可复现、可评测、可比较、可回滚的 AI 质量系统。

## 非目标

- 不建立“万能 prompt 文案库”。
- 不把所有供应商强制成同一提示词模板。
- 不只做一个模板管理后台而缺少真实样例和评测运行。
- 本任务未正式启动前，不修改当前生产 prompt。

## 核心能力

| 编号 | 能力 | 最小产物 |
| --- | --- | --- |
| Q0 | 代表样例与失败样例集 | 固定项目/章节/镜头、输入夹具、期望、失败标签、人工评分表 |
| Q1 | Prompt/生成规格注册与版本审计 | template、version、digest、model、reference、parameters、输出关联 |
| Q2 | 供应商能力注册与 profile | 尺寸、多参考图、mask、negative prompt、输出格式、模型快照和限制 |
| Q3 | 评测运行与质量门 | schema 校验、规则评分、视觉人工复核、成本/耗时、基线对比 |
| Q4 | 剧本/结构/分镜 prompt 治理 | agent 目标、工具边界、输出 schema、样例和回归测试 |
| Q5 | 版本发布与回滚 | 草稿、候选、已发布、已废弃、回滚和变更说明 |

## 推荐阶段

### 阶段 0：资产盘点与正式分类
- [ ] 建立四类正式资产：Agent/System、Skill/Workflow、结构化输出契约、生成模型 prompt。
- [ ] 为现有资产分配稳定 ID、owner、调用点和状态。

### 阶段 1：评测夹具与失败分类
- [ ] 从真实项目提取不含敏感数据的代表夹具。
- [ ] 覆盖剧本、结构、分镜、角色图、场景图和候选图。
- [ ] 形成结构错误、身份漂移、场景污染、伪文字、构图、成本和耗时等失败标签。

### 阶段 2：版本与追溯
- [ ] 统一记录模板版本、实际 prompt、模型快照、参考素材版本和参数 digest。
- [ ] 输出能追溯到评测运行和生产任务。

### 阶段 3：供应商能力与编译
- [ ] 建立 provider/model capability registry。
- [ ] 从领域生成规格编译出供应商专用请求，避免共享不受支持的 negative prompt 或参考图规则。

### 阶段 4：评测执行与对比
- [ ] 文本输出执行 schema、规则和语义评分。
- [ ] 图片输出执行基础自动检查与人工视觉复核。
- [ ] 同屏比较 prompt/model/provider 的质量、成本和耗时。

### 阶段 5：发布质量门
- [ ] 模板或模型升级必须跑选定基线。
- [ ] 明显回退阻断发布；允许带理由豁免。
- [ ] 支持回滚到上一已发布版本。

### 阶段 6：产品化工作台
- [ ] 提供资产、版本、评测集、运行结果和差异查看。
- [ ] 权限和多人审批等 SaaS 能力后置。

## 依赖

- D7 全量数据库化：用于 PromptVersion、EvalCase、EvalRun、EvalResult 和 ProviderProfile 的正式存储。
- 现有服务端权威 `CandidateGenerationSpec`：作为图像生成规格追溯的首个接入点。
- 真实供应商样例验收：用于建立首批视觉失败标签和质量基线。

## 进入正式规划的条件

1. D1 和 D7 的领域/数据边界已确认。
2. 用户指定首批优先治理对象：文本链路、角色/场景图或候选图。
3. 现有 prompt 资产盘点完成时效复核。
4. 明确首版是否只提供内部工程页面，还是进入普通创作者界面。

## Epic 验收方向

- 任一生产输出可反查实际使用的模板版本、模型、参考素材和参数。
- 同一夹具可跨版本/模型重复运行并形成结构化对比。
- 不支持 negative prompt 的模型不会收到全局 negative prompt。
- Prompt 或模型升级有基线、结果、审核与回滚记录。
- 热门外部 prompt 只能作为案例输入，不能绕过测试直接发布。

## 退出标准

本任务当前只完成“独立大功能登记”。正式启动时必须重新使用 `$deep-think` 细化数据模型、任务协议、页面、迁移、评测方法和成本边界。
