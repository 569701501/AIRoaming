# 任务计划：项目完成度复核

## 目标

以文档事实源、当前代码和可执行证据为准，给出项目已完成、部分完成、未开始、被阻塞的全量盘点，并提供可信的剩余量区间和下一步优先顺序。

## 非目标

- 不实现新功能或修复现有功能。
- 不执行真实数据库切换、Keychain/provider 操作或真实 workspace 写入。
- 不覆盖、回退或提交工作树里的既有改动。

## 验收标准

1. 覆盖产品七阶段、数据库切换、测试门禁与真实用户路径。
2. 文档声明与代码、测试、真实运行证据分开判定。
3. 给出完成度估算口径、主要缺口、阻塞关系和推荐顺序。
4. 完成 Scrutiny Review；Runtime/User Review 未执行真实环境步骤时，明确说明原因和待验收项。

## 最终状态

项目级复核已完成。完成度按“工作量 × 交付成熟度”估算，不按文件数、页面数或测试数简单平均：

| 口径 | 已完成 | 仍未完成 |
| --- | ---: | ---: |
| 当前静态漫画 G0～G5 波次 | 55%～65% | 35%～45% |
| 长期漫画 MVP，包含 G6 ZIP/下载 | 50%～55% | 45%～50% |
| 完整产品愿景，包含基础视频链路 | 40%～45% | 55%～60% |

## 已做决策

| Decision | Rationale |
| --- | --- |
| 使用 `$deep-think` 的项目级复核流程 | 盘点跨产品、架构、数据库、测试和真实用户路径 |
| 本次只读检查，不修改功能代码 | 用户请求检查而非实现；工作树已有用户既有改动 |
| 不以完成记录数量直接计算完成度 | 完成文档、自动化证据和真实运行证据的成熟度不同 |
| 把 G2 Web DB-only 适配加入真实 C7 前门禁 | Web 第 2～4 步仍调用 DB 模式已禁用的旧写接口，直接切换会产生用户路径回归 |
| 默认 `pnpm test` 超时视为工程门禁缺口 | 60 秒 single-fork 配置下 462 个测试全绿，但仓库默认入口仍有 4 个慢测在 5 秒超时 |

## 注意事项

- 估算区间用于排期和决策，不是精确工时承诺。
