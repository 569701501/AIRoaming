# 漫画成稿基础版收缩任务计划

## 目标

把漫画成稿从“自动排版 + 二次智能调整 + 专业编辑 + 版本中心 + 出版中心”收缩为普通用户可直接理解的基础闭环：

```text
首次无感自动排版
→ 人工画布调整
→ 自动保存
→ 单一导出
→ 有人工文字变化时确认
→ 下载成品
```

## 已确认产品规则

1. AI 只在本章没有 Working Copy 时自动排版一次。
2. 首次排版必须逐条、原样放入正式对白和旁白；不能遗漏、重复或改写。
3. AI 尽量避开人脸、人物、关键动作和视觉焦点；无可靠安全区时使用保守位置。
4. 保留现有画布底层，具体编辑控件与交互后续另定。
5. 保留自动保存；普通用户不再看到立即保存、撤销、重做。
6. 删除整章/局部/场景/选区智能调整、intent、建议预览和应用/放弃。
7. 普通用户只看到一个“导出”入口。
8. 系统遗漏、重复、错绑或无来源系统文字直接阻止导出。
9. 用户主动改字、删除正式文字或添加自定义文字时，导出弹窗展示差异；用户可“返回修改”或“按当前文字导出”。
10. 没有文字差异且没有其他警告时直接进入导出。

## 非目标

- 不重新设计具体编辑工具、属性栏或画布交互。
- 不新增 `LayoutDocumentV3`、数据库表或第二套编辑器。
- 不删除 Working Copy CAS、自动保存、来源密封、不可变 Revision、Publication 和 renderer。
- 不让 AI 二次修改用户已经编辑的成稿。
- 不自动修复或覆盖历史错误 Working Copy；错误稿在导出时必须阻断。
- 不新增滤镜、修图、OCR、网点或漫画特效。

## 实施阶段

### P0 文字导出判定

- 在 Shared V2 preflight 上增加用户可读的原文/当前文字证据。
- 识别用户自定义文字与无合法用户所有权的未分类文字。
- 固定“系统错误阻断、用户变化确认”的公共行为测试。

### P1 页面能力收缩

- 移除立即保存、撤销、重做及其快捷键入口。
- 移除 AI Drawer、full/scoped reflow、范围与 intent、双预览、应用/放弃入口。
- 初次自动排版仍由现有 missing Working Copy watcher 无感触发。

### P2 单一导出

- 用一个导出按钮编排 autosave、Working Copy preflight、文字确认、Revision、publication preflight 和 Publication。
- 阻断弹窗不提供强行导出。
- 用户变化弹窗只确认一次；确认身份随文档或 preflight 摘要变化失效。
- 发布任务完成后提供产物链接。

### P3 清理与回归

- 删除前端无人使用的状态、方法、导入、文案与样式。
- 更新原有合同测试，使其保护新的基础用户路径。
- 运行 Shared/Web/Server 定向测试、类型检查和全量测试。

### P4 真实页面验收

- 使用真实 DB 项目验证首次自动排版、人工改字、自动保存、导出弹窗、阻断和产物。
- 保留截图、任务状态、Revision、Publication 和 Artifact 证据。

### P5 复核与留痕

- Scrutiny Review 只读复核代码、协议、测试与文档。
- Runtime/User Review 记录真实页面结论。
- 更新产品、模块、ADR、验收、完成记录和长期记忆。

## 强制验收标准

| 项目 | 标准 |
| --- | --- |
| 首次自动排版 | 无 Working Copy 时自动执行一次，不展示模式或参数 |
| 正式文字覆盖 | 100%，无遗漏、重复、错镜头和 AI 改写 |
| 主体避让 | 有视觉证据时使用安全区；无证据时保守放置且不宣称视觉识别通过 |
| 后续 AI 调整 | 普通页面入口为 0 |
| 保存 | 自动保存保留；立即保存入口为 0 |
| 撤销/重做 | 按钮和键盘入口为 0 |
| 导出入口 | 1 个 |
| 系统文字错误 | 阻止导出，无强行继续按钮 |
| 用户文字变化 | 展示镜头、说话者、原文和当前文字；允许一次确认 |
| 自定义文字 | 弹窗提示后允许导出 |
| 无差异 | 不出现文字确认弹窗 |
| 正式产物 | 保留不可变 Revision、Publication 和确定性产物 |

## 回滚

- 页面收缩通过单一提交回滚，不需要数据库迁移。
- Shared 新 preflight code 为向后兼容扩展；旧 V1 历史读取不变。
- 回滚不得放宽现有 Revision/Publication 的正式文字阻断。

## 角色边界

- Orchestrator：冻结范围、维护计划与阶段门。
- Worker：按 P0→P3 顺序测试先行实施。
- Scrutiny Review：只读检查，不修改代码。
- Runtime/User Review：只验证真实页面和产物，不用静态测试代替。

## 退出标准

- 所有强制验收通过。
- Scrutiny Review 无 S0/S1。
- Runtime/User Review 完成；若环境阻断，必须记录准确阻断证据。
- 产品、模块、ADR、验收和完成记录同步。
