# 文稿库方案（全局文稿导入 → 拆章阅读器 → 创建项目导入）

## 1. 定位与目标

- 新增**全局「文稿库」菜单节点**（项目库同层入口），不区分剧本/小说，统一承接大文件文本。
- 用户上传 .txt/.md → 系统**确定性拆章（零 token）** → 左侧章节列表 + 右侧只读原文阅读器 → 用户检查拆分正确。
- 创建项目时可选文稿库中的文稿，**直接引用原文**建立全部章节（不复制、不改原文、不触发 AI）。

## 2. 用户流程（用户 2026-08-04 确认）

```text
项目库
 └─ 文稿库（新菜单节点）
     ├─ 上传剧本/小说 .txt/.md
     ├─ 确定性拆章：第X章/卷/空行规则 → 零 token
     ├─ 阅读器：左侧章节名列表，右侧原文内容（只读）
     ├─ 用户检查拆分（章节标题/顺序/范围），只读不改
     └─ 存为全局文稿资产（可复用）
创建项目时
 └─ 选择该文稿 → 自动建好全部章节壳（直接引用原文）
     ├─ 不复制原文（项目引用文稿库章节）
     ├─ 不生成正文、不调 AI、不建 pending/对话
     └─ 之后按现有「章节 → 剧情结构 → …」逐章推进
```

## 3.1 页面流程（用户确认）

```text
文稿库首页 = 文稿列表（卡片/表格，可重命名、删除）
 └─ 「新增文稿」按钮 → 弹窗
     ├─ 用户点击上传（.txt/.md）
     ├─ 点击「确定」→ 自动拆分（零 token，异步可进度）
     └─ 拆分成功 → 自动跳转到文稿详情页
         ├─ 左侧：章节分组列表（一级=分卷/分桶，默认展开第一组，组内章节可点）
         ├─ 右侧：只读原文（默认选中第 1 章，正文按章节范围加载）
         └─ 顶部：文稿名（可重命名）、章数、字数、来源文件
```

## 4. 拆章引擎设计（对齐小说阅读器成熟方案）

### 4.1 设计原则

- **零 token**：纯确定性规则，不调用任何 AI。
- **对齐小说阅读器**（微信读书/番茄/静读天下等验证过的成熟做法）：核心规则相同，标准网文/剧本格式成功率 99%+。
- **三层规则 + 可见兜底**：不静默吞内容；非标文本进「未分章」区可见，而不是悄悄错分。

### 4.2 拆章规则（三层）

| 层 | 规则 | 说明 |
| --- | --- | --- |
| 第一层 | `第X章/第X回/第X节/第X话` 识别（全角/半角/前导零/中文数字都处理）；`卷` 标题识别为卷组 | 主流网文/剧本格式，成功率极高 |
| 第二层 | 空行分段兜底：无章节号时按连续空行切分 | 没章节号的手稿也能分 |
| 第三层 | 整篇无任何结构 → 视为单章 | 保底可用，不报错 |

- 特例标题（序章/楔子/尾声/番外）独立识别，归入对应组。
- 卷识别到 → 卷为一级分组节点；无卷 → 每 100 章分桶（如「1-100 章」）。

### 4.3 可见兜底（非标文本，不阻断）

- 无法匹配任何规则的块 → 「未分章」区，详情页可见。
- 序号断裂（第 15 章后直接第 17 章）→ warning 标记，不中断。
- 拆章成功/失败结果都有明确提示；失败可重新上传。

### 4.4 拆分输出契约（每章）

```json
{
  "chapterId": "dc_xxx",
  "order": 1,
  "title": "第一章 初入宗门",
  "sourceRange": { "startOffset": 1234, "endOffset": 89012 },
  "charCount": 87778,
  "group": "卷一 风起" | "1-100 章" | "未分章",
  "anomalies": []
}
```

### 4.5 验证

- 拆章引擎单测覆盖：章节号全角/半角/前导零/中文数字、卷标题、序章/番外、空行切分、无结构单章、异常块 ≥15 个 fixture。
- 真实样例：《凡人修仙传》前 N 章真实文本跑通，人工核对边界。
- 确定性幂等：同文件重复拆分结果一致（按文件 sha256 缓存）。

## 4. 范围边界

### 4.1 做（首版）

- 全局文稿库入口（项目库同层菜单）。
- 上传 .txt/.md（编码识别，UTF-8 为主）。
- 确定性拆章引擎：按「第 X 章 / 第 X 卷 / 卷名 / 连续空行」规则切分，**不调用 AI、不消耗 token**。
- 拆章阅读器：左侧章节名列表 + 右侧只读原文，支持查看每章范围与字数。
- 文稿资产持久化：全局存储（非项目 Asset）+ 元数据（章节列表、顺序、来源范围、摘要）。
- 创建项目弹窗/流程中可选文稿，自动建立全部章节壳并引用原文。
- 拆章异常处理：无法识别的段落进「未分章」区，不静默吞掉。

### 4.2 不做（首版）

- 向量库、全书摘要、多文稿混编、跨项目素材复用（角色/场景等）。
- 文稿库内编辑/修订（只读）。
- 自动同步项目章节与文稿库变化。
- 超大规模（>500 章）的流式体验与虚拟滚动（先用普通列表，量大再评估）。

### 4.3 与既有链路的关系

- 创建项目导入文稿后，章节进入现有 `Chapter` 体系；`ChapterScriptVersion` 及下游（剧情结构/分镜/候选/成稿）完全复用。
- 现有 B1～B5 对话框附件导入**保持不变**，作为轻量/临时入口。
- 07-25 长篇原著资产库方案中「轻量章节目录、统一章节路由、流式上传、单章 AI 门禁」等 8 项规模改造**本方案不引入**——首版只做「全局文稿 + 拆章 + 创建导入」，不做全书级持续管理。

## 5. 数据与存储（初稿）

- 全局存储：`workspace/documents/`（或等价目录），按文稿 UUID 分目录，原文文件 + 章节 manifest。
- 新表（初稿，待架构评审细化）：
  - `DocumentWork`（文稿：名称、格式、状态、来源文件路径、文件 sha256、字节数、章数）
  - `DocumentChapter`（章节：workId、序号、标题、原文文件偏移/范围、字符数）
- 项目引用：`Chapter` 增加来源字段（documentChapterId 或等价），正文读取时从文稿原文按范围投影。
- 备份/恢复/删除：文稿库需纳入现有 backup/restore 与删除契约（全局资产，不属于单项目）。

## 6. 验收标准（初稿）

- 上传《凡人修仙传》类大文件不报错（body 限制已放宽），拆章零 token 完成。
- 拆章结果可预览：左侧分组列表（卷/百章桶，默认展开第一组）与右侧原文一一对应，未分章内容可见，默认选中第 1 章。
- 新增文稿弹窗：点击上传 → 确定 → 自动拆分 → 成功自动跳转详情页。
- 文稿可重命名、可删除（删除确认后项目引用一并处理）。
- 创建项目选择文稿后，章节壳全部建立（标题/顺序/来源引用正确），不触发任何 AI 调用与 pending。
- 项目内章节正文按需从文稿原文加载，可进入剧本页编辑并形成 `ChapterScriptVersion`。
- 拆章引擎单测 ≥15 个 fixture 全绿；真实长篇小说样例人工核对边界准确率达标。
- 文稿库删除/备份符合全局资产契约。

## 7. 待确认问题（进入实施前）

- 拆章是否允许手动调整边界：**已确认首版只读**（拆错重新上传），手动合并/拆分后置。
- 其余决策见 §3（1-8 全部确认）。
