# 漫画成稿现状设计评审

## 1. 评审范围与方法

- 阅读事实源：ADR-0022、ADR-0023、2026-07-26 体验评估与 P0 修复任务计划、2026-07-30 极简重构任务三件套（task_plan/findings/progress/scrutiny_review）。
- 阅读代码：`LayoutExportWorkspace.vue`（3755 行）、`layout-editor-session.ts`（825 行）、`LayoutKonvaInteractionLayer.vue`（685 行）、`LayoutExportDialog.vue`（438 行）。
- 目标：梳理当前设计的完整形态（产品流程 / 数据流 / 交互 / 边界），找出设计问题与机会，不写代码。

## 2. 当前设计形态

### 2.1 产品流程（ADR-0022 基础版）

```text
首次自动排版（无 WC 时一次） → 人工画布编辑 → 自动保存（CAS） → 单次导出
```

- 无二次 AI 调整、无手动保存、无版本历史 UI、无出版控制中心。
- ADR-0023 增加：画布优先布局、浮动上下文工具条、拖拽实时预览、双击就地改字、有限本地撤销（内存 50 步、无 redo、服务端重载即清空）。

### 2.2 数据流（session 层）

```text
load() → Working Copy（V1/V2 双栈） → execute()/executeBatch() 命令应用
       → markDirty → scheduleAutosave（idle 800ms / max 5s）
       → flush() → saveLayoutWorkingCopy（expectedRowVersion + documentDigest CAS）
       → 409 → conflict 三选一（下载恢复 / 重载服务端 / 保留本地）
       → runPreflight → createRevision（不可变） → createPublication（异步渲染）
```

- 关键机制：V1/V2 文档双栈、`toV2UserCommand` JSON 序列化克隆、undo 快照栈（全文档 structuredClone）、saveFlight 防并发、loadGeneration 防过期响应。

### 2.3 交互层（Konva 与 DOM 双轨）

- DOM 投影：`elementStyle()` 渲染真实视觉（图片、文字、边框、气泡）。
- Konva 层：命中检测、拖拽、Transformer 缩放旋转、框选、裁切手势、尾巴拖点、右键菜单、吸附参考线。
- 预览变换：dragmove/transform 期间 emit `previewTransform` → 合并进 DOM 投影，松手才提交正式命令。

### 2.4 导出链路

`startSimpleExport` → flush → 双 preflight（revision + publication profile）→ blocked（硬阻断）/ review（文字差异确认）/ 直接 createRevision → publication 异步渲染 → ready 提供产物链接。

## 3. 设计强项（保留）

| 维度 | 强项 |
| --- | --- |
| 数据完整性 | 对白 binding + tombstone、CAS 并发控制、双 preflight、不可变 Revision/Publication、系统文字错误无法强行导出 |
| 编辑可追溯 | 全命令化（`EditorCommandV1/V2`），payload 严格 JSON 契约，V2 支持 suppress/restore bound 对白 |
| 冲突处理 | 409 三选一 + 恢复副本下载，saveFlight 防并发飞丢 |
| 交互收敛 | 极简重构方向正确：三栏 → 画布优先，常驻面板 → 按需浮层，拖拽实时预览 |
| 导出门禁 | 文字差异只弹一次并展示原文/当前；视觉检查维度完整（图片、字体、色彩空间、分辨率、安全区、对白台账） |

## 4. 设计问题与机会（按影响排序）

### 4.1 组件规模与职责边界（P0 架构债）

- `LayoutExportWorkspace.vue` 3755 行单文件承载：导出编排、元素操作、画布投影、属性面板、右键菜单、来源同步、composition、移动预览、发布历史。边界不清，后续任何改动都高风险。
- 建议：按职责拆模块（导出编排 / 元素操作 / inspector / 画布投影 / 来源素材栏 / 选择工具条），保持 testid 稳定。

### 4.2 Undo 快照粒度与成本（P1）

- undo 是「全文档 structuredClone」入栈，上限 50。文档含全部 canvas + 富文本，大文档下内存与 CPU 成本高；跨画布撤销会连带无关内容。
- 建议：按受影响 canvas 粒度做增量快照，或引入命令逆操作（需评估成本），至少先统计真实文档体积。

### 4.3 就地文字编辑丢失混排（P1，已知取舍）

- 双击就地编辑按首段样式重建段落，段内混排（局部加粗/变色）会丢失。ADR-0023 接受此代价（IME 安全优先）。
- 建议：保留当前实现，但属性面板富文本编辑器仍是完整编辑入口，需在 UX 上让用户能发现「双击改字会简化样式」。

### 4.4 多选变换能力不完整（P1）

- 多选支持对齐/分布/删除，但 Transformer 多节点缩放/旋转是否可用需验证；框选 + Shift 加选在 Konva 层曾未触发（m2 冒烟备注）。
- 建议：验证多选批量缩放/旋转，补齐 shift+click 加选。

### 4.5 长条漫导航与总览缺失（P2）

- 条漫长画布（多段拼接）只能滚轮/平移漫游，无全局缩略图或鹰眼视图，多页结构靠左栏页面导航。
- 建议：增加缩略图导航（mini-map）或段快速跳转，评估优先级。

### 4.6 导出「完成」后的引导断裂（P2）

- 导出完成后仅提供产物链接 + 「完成」，无「再次编辑」或素材包入口；遮罩拦截画布点击是已知 e2e 教训。
- 建议：完成后增加返回编辑的显式出口。

### 4.7 视觉主题一致性残留（P2）

- 导出对话框独立配色（`#111a2b` 背景、`#8f9db8` 小字），与全局 `#0b1020` 深夜蓝黑不完全一致；选中态已统一为紫 `#8b5cf6`。
- 建议：导出对话框并入全局 tokens，做一次全编辑器视觉对齐。

### 4.8 文本预检性能（P2）

- `collectLayoutTextIssuesV1` 每次 computed 全量重算所有文字溢出与字体缺字，大文档高频操作（拖拽）时开销不可忽略。
- 建议：按需计算（仅选中元素/画布）或缓存依赖 digest。

## 5. 评审结论

- 数据链路与导出门禁设计已达产品级，是核心资产，不应动摇。
- 主要设计债在「编辑器 UI 复杂度与规模」（4.1）与「撤销/性能细节」（4.2、4.8），以及几个体验断点（4.3～4.6）。
- 建议下一步：与用户确认优先级后，将选中的改进项拆为独立设计任务（涉及交互变化需先出方案，涉及 ADR 口径需新增 ADR 或修订 ADR-0023）。

## 6. 深层设计思考（2026-08-03 追加）

第 4 节是表层优化项。更本质的三个产品级设计问题：

### 6.1 用户能力错配：产品没选边，两不像

- 自动排版质量足够好 → 编辑器只是「微调工具」，应保持极简（ADR-0022/0023 口径）。
- 自动排版不够好 → 编辑器是「主战场」，需要专业能力（当前实际保留了裁切、尾巴、富文本、安全区预检等专业工具级功能）。
- 现状：实际是后者，口径却是前者。**两者不可兼得**：
  - 要么投入自动排版质量（含用户偏好回流），让编辑器真的只是微调；
  - 要么承认编辑器是专业工作台，按专业工具设计（图层重排、批量变换、鹰眼导航、键盘工作流）。
- 当前两头各做一半，用户被迫在"本应极简"的编辑器里做专业操作。

### 6.2 用户修改没有回流：自动排版学不到东西

- 用户每次成稿的挪气泡、改字、调裁切是最宝贵的真实反馈信号，目前全部丢弃；下一次自动排版重复犯错，用户重复劳动。
- 低成本版本：项目级「排版偏好账本」，记录 override 统计（某镜头总被挪、某气泡总被改位置），下次排版优先尊重。
- 高成本版本：用户修改作为 visual analysis 的 ground truth 训练信号。
- 这是「自动排版质量持续提升」的唯一现实路径，目前为零。

### 6.3 章节级 vs 整本成品：范围断裂

- 编辑器按章工作，用户要的是整本漫画；跨章一致性（字体、气泡风格、画格模板、页边距）无统一设计。
- 素材包（G6）本应是「整本交付」载体却被后置；跨章复制素材、统一模板、批量应用无入口。

### 6.4 再设计方向（候选）

| 方向 | 含义 | 押注 |
| --- | --- | --- |
| A. 自动排版为尊 | 投入排版质量 + 用户偏好回流，编辑器保持极简 | 普通创作者，少动手 |
| B. 专业编辑为尊 | 按专业漫画工具设计编辑器（图层、批量、导航、键盘流） | 专业漫画家，精细化 |
| C. 成品交付为尊 | 以导出物/素材包为中心，编辑器只是过程工具，G6 提前 | 出成品、要交付 |
| D. 用户分级 | 基础/高级双轨模式，两种用户都服务 | 都要，复杂度最高 |

### 6.5 判断

必须先回答「用户是谁」，其他设计才成立。在目标用户复杂度分级未定之前，4.1～4.8 的优化都是对着空气优化。建议下一步与用户确认产品定位方向，再决定编辑器是「极简化」还是「专业化」。
