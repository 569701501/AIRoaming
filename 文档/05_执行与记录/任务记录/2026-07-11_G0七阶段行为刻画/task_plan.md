# G0 七阶段行为刻画与 E2E 测试骨架任务计划

## 目标

1. 找出 D7 切换前必须锁住的现有正确行为，并按公开接口形成可重复的 characterization 用例。
2. 确定 Service 集成、HTTP 契约、Web E2E 三层边界、fixture、进程启动、端口和临时 workspace 隔离方式。
3. 设计最小但可继续扩展的浏览器 E2E 骨架，先证明项目库、工作区外壳和七阶段门禁，而不是假装当前后半段已经达到最终成品标准。
4. 把已知错误与未来目标行为放入验收矩阵，但不在 G0 批量创建默认 CI 必然失败的测试，也不把错误现状固化成绿色回归标准。
5. 本轮只写开发级方案和行为用例矩阵，不安装依赖、不新增测试、不改业务代码、不写真实 workspace。

## 非目标

- 不重建七阶段 workflow，不实现 D2 自动调度。
- 不在 G0 修复剧本/结构/分镜 freshness、D1、D3、D4/D5、D7 或素材包 V2。
- 不调用真实 OpenCode、文本模型或图片供应商作为普通 CI 前提。
- 不使用现有用户项目作为自动化 fixture。
- 不以 DOM 结构、私有 Map、内部方法调用次数或具体文件写入顺序作为长期契约。

## 强制退出标准

1. 每个 G0 用例都有：层级、公开入口、前置 fixture、用户动作、业务断言、文件断言、归属切片和是否当前可绿。
2. 明确哪些正确行为现在锁住，哪些缺口只登记、待对应功能切片以 red → green 方式实现。
3. 测试环境不会连接真实供应商，不会读取或污染默认 `workspace/`；首版串行，多个 E2E 进程并发时必须显式隔离 runId、端口和目录。
4. Web E2E 工具选择有官方能力依据，启动方式、失败产物、CI/本地命令和清理策略明确。
5. 方案能按垂直切片逐条实施；首个实现切片不要求一次写完全部测试。
6. Scrutiny Review 完成；Runtime/User Review 明确为实现阶段验收项。

## 当前深思熟虑角色边界

- **Orchestrator：** 核对事实、拆分测试层、管理文档一致性。
- **Worker：** 本轮只编写方案、矩阵和记录，不执行实现。
- **Scrutiny Review：** 静态核对用例是否锁公开行为、是否误固化错误、是否具备环境隔离。
- **Runtime/User Review：** 本轮不运行浏览器测试；未来获得开发授权并实施 G0 后，再验证真实启动、截图、trace 和用户点击路径。
