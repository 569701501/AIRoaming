# 任务计划：分镜自动候选描述设计

## 目标

让用户只点击一次“生成分镜”，系统就自动产出可直接进入候选图工作台的详细画面、动作和构图；“AI 优化描述”降级为返修能力，不再是正常出图前的必点步骤。

## 非目标

- 不新增第八个顶层步骤。
- 不把创作或修复能力放进“出图准备”；该步骤继续是纯检查门。
- 不在分镜阶段提前绑定图片 Provider、参考图槽位、尺寸或负向 Prompt。
- 不迁移或静默重写历史正式分镜；旧分镜只有在用户重新生成时才进入新流程。

## 推荐设计

采用“一次用户动作、两段内部处理、一次待确认结果”：

1. 第一段仍由 `storyboard-shot-generate` 完成剧情拆镜、镜头数量、角色/场景引用和漫画/漫剧骨架。
2. 第一段通过严格结构与高确定性质量门后，系统自动对本章全部漫画镜头做一次章节级视觉描述整理。
3. 第二段只允许改写 `coreAction`、`comic.panelDescription`、`comic.composition` 和派生摘要，不得改镜头数量、顺序、beat、scene、characterIds、剧情结果、对白或 motion。
4. 第二段输出再次经过来源忠实、单地点/单时刻/单机位和多人关系检查；失败最多自动修复一次。
5. 两段都通过后才写入待确认 Storyboard；任一失败时不部分覆盖既有待确认分镜。
6. 候选图工作台直接用正式分镜的三段详细描述初始化本次草稿。
7. 原“AI 优化描述”改为“重新优化本镜头”，只处理例外镜头或用户手工修改后的返修。

## 初步决策

| 决策 | 原因 |
| --- | --- |
| 不新增 `candidateBrief` 平行字段 | 现有 `coreAction + panelDescription + composition` 就是同一语义，新增一套会产生漂移和失效问题 |
| 不自动创建每镜一个 `shot_prompt_generate` | 会产生 N 个任务、N 次文本调用和部分成功状态，而且当前任务必须等 Preflight 确认后才能创建 |
| 在同一 `shot_generate` 内增加章节级第二段 | 用户只操作一次；专门模型步骤负责详细度；结果在进入待确认分镜前保持原子性 |
| 第二段不读取 Provider 和参考图槽位 | 分镜阶段只生成语义视觉描述，实际图片 Prompt 与引用仍在候选图阶段确定性编译 |
| 两条生产路径共用一个整理器 | Dialogue 直连生成和持久 `shot_generate` 不能形成两套画质行为 |

## 验收标准

1. 新生成分镜中的每个漫画镜头默认已有可读的画面、动作、构图，正常出图不需要点击 AI 优化。
2. 多人镜头逐人写清位置、动作对象、承受关系或视线；群体不凭空编具体人数。
3. 第二段不能改变镜头数、镜头顺序、剧情事实、对白、角色/场景引用或 motion。
4. 失败最多自动修复一次，仍失败时不保存部分结果，也不覆盖已有待确认分镜。
5. 候选图工作台仍允许本地编辑；编辑不修改正式 StoryboardVersion。
6. “重新优化本镜头”是可选返修，不再是默认流程依赖。
7. 不调用图片 Provider，不新增数据库表或顶层流程步骤。
