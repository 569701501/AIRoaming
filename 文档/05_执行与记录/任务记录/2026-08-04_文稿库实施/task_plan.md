# 文稿库实施任务

## 目标

实现全局「文稿库」：上传剧本/小说 → 确定性拆章（零 token）→ 分卷/分桶折叠章节阅读器（只读）→ 创建项目时可选文稿自动建章节壳（直接引用原文）。

## 非目标

- 不做全书级资产管理（轻量目录/统一路由/流式上传/单章 AI 门禁，见 07-25 方案）。
- 不做文稿编辑、向量库、跨项目素材复用。
- 不改现有 B1-B5 对话框导入。

## 阶段划分

| 阶段 | 内容 | 产物 |
| --- | --- | --- |
| M1 数据与存储 | 全局文稿存储目录 + `DocumentWork`/`DocumentChapter` 表（Prisma migration）+ 读写 Repository + 备份/删除契约接入 | migration、repository、契约测试 |
| M2 拆章引擎 | 三层规则拆章引擎（章节号/空行/单章）+ 卷组/百章桶分组 + 输出契约 + ≥15 fixture 单测 + 幂等缓存 | shared 拆章模块、单测 |
| M3 后端 API | 文稿 CRUD（列表/详情/新增上传/重命名/删除）+ 拆章任务（异步）+ 创建项目导入文稿接口 | controller/service、API 契约测试 |
| M4 前端页面 | 文稿库列表页（与项目库并列）+ 新增文稿弹窗（上传→确定→自动拆分→跳转详情）+ 详情页（左侧折叠章节列表 + 右侧只读原文）+ 重命名/删除 | Vue 组件、web 契约测试 |
| M5 创建项目接入 | 创建项目弹窗可选文稿 → 自动建章节壳（直接引用原文，零 AI） | 创建流程改造、e2e |
| M6 验证与留痕 | 全量门禁 + 真实《凡人修仙传》样例拆章人工核对 + 完成记录 | 证据、完成记录 |

## 关键决策（用户确认）

1. 入口：文稿库与项目库并列（项目库页面上方同层）。
2. 创建项目弹窗内可选文稿，不选保持空白。
3. 文稿可重命名、删除；删除确认后项目引用一并处理。
4. 详情页左侧章节分组折叠：有卷按卷，无卷每 100 章一桶，默认展开第一组；右侧只读原文，默认第 1 章。
5. 新增文稿：弹窗上传 → 确定 → 自动拆分 → 成功跳详情。
6. 拆章对齐小说阅读器成熟规则（章节号+空行+单章兜底），零 token；非标块进「未分章」可见，不阻断。
7. 首版拆章结果只读，不做手动调整边界；拆错重新上传。
8. 创建项目直接引用文稿原文，不复制、不改原文、不触发 AI。

## 验收标准（汇总）

- 上传大文件（≥2MB）不报错；拆章零 token 完成且幂等。
- 拆章结果可预览：分组列表（默认展开第一组）+ 右侧原文 + 默认第 1 章 + 未分章可见。
- 新增弹窗流程闭环；重命名/删除可用。
- 创建项目选文稿 → 章节壳全建（标题/顺序/来源引用正确），零 AI 调用。
- 项目内章节正文按需从文稿加载，可进剧本页形成 `ChapterScriptVersion`。
- 拆章单测 ≥15 fixture 全绿；真实样例人工核对。
- 文稿库备份/删除符合全局资产契约。

## 退出标准

- 全部门禁绿：typecheck、shared/server/web 单测、web 契约、e2e db/file。
- 真实浏览器路径走通：文稿库 → 上传 → 拆章 → 详情阅读 → 创建项目 → 剧本页可见章节。
- Scrutiny Review 静态复核通过；完成记录已写入。
