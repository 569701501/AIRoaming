# AI 创作 P1/P2 质量门发现

## 当前事实

- P1 对外 JSON 固定为 `title/genreTags/logline/keyConflict/visualHook/firstChapterDirection`，调研明确第一版不增加质量字段。
- 当前严格 parser 只保证恰好三项、字段完整、标签数量和标题唯一；三个候选只换标题仍可通过。
- P2 对外 Markdown 已含主要角色、情节概要、结局方向和轻量章节卡；调研明确不新增区块。
- 当前大纲 parser 只保证四区块、章数、卡片数量和字段格式，不判断因果推进、结局空泛或卡片伪重复。
- 当前灵感和大纲都只允许一次修复，但修复文案只处理格式；若直接把质量错误塞进同一 catch，会出现“要求不改语义却要修质量”的矛盾。

## 决策

- 质量门放在 Server 编排层，严格输出 parser 继续只负责格式/Schema，避免把艺术启发式伪装成稳定数据协议。
- 使用独立错误类型区分格式错误与质量错误，保持一次修订总上限。
- P1/P2 的确定性规则只覆盖高置信反例；更细的新鲜度、情感力度仍由 Prompt 内部自检和用户选择负责。

## 风险

- 中文因果表达很多，连接词检查必须接受一组自然同义表达，不能只认字面“因此/但是”。
- 终章衔接规则可能误杀含蓄表达，因此 Prompt 应要求显式写明“终章/收束/结束”等标记。
- 质量重做不能改变用户题材或选中种子的核心承诺。

## 实现与复核结论

- P1 只对四个现有语义字段的规范化完全重复做固定触发，不尝试计算抽象“创意分数”。
- P2 只检查转折/结果连接、空泛结局标签、章节卡核心字段完全重复和终章显式收束；自然同义连接词被接受。
- `ScriptCreativeQualityError` 只在 Server 内部使用，不进入 Shared、数据库或页面 Schema。
- 首轮格式失败后只做格式修复；修复结果若再暴露质量问题也会停止，不开启第二次模型调用，符合一次修订总上限。
- 当前 fake provider 的大纲含自然因果连接和“故事结束”终章标记，真实 DB A3～A5 路径无需修改即通过。
- 静态复核未发现 P0/P1 问题；剩余风险是启发式规则不覆盖近义改写型伪差异，也不应继续扩张成完整艺术评分器。
