## 1. 目标

修复项目对话框在失败、重发、刷新和重新进入页面后的线程状态问题：

- 刷新/重新进入剧本页时，应主动加载当前步骤和当前章节的对话记录。
- 请求失败、abort 或连接中断后，不应留下永久 `running` 的 assistant 消息。
- 再次发送消息时，不应因为旧 running 状态导致 UI 突然恢复但继续转圈。

## 2. 非目标

- 不优化 OpenCode 或模型本身的生成速度。
- 不改剧本灵感、剧本大纲、章节写入的业务能力。
- 不引入数据库持久化；当前仍基于进程内线程状态。

## 3. 阶段

| 阶段 | 状态 | 退出标准 |
| --- | --- | --- |
| 事实探索 | completed | 找到线程加载、发送、状态写入和 abort 处理入口 |
| 复现与假设 | completed | 有最小反馈环能观察到 running 卡死或刷新不加载 |
| 修复实现 | completed | 状态机和加载路径改动完成 |
| 验证复核 | completed | typecheck、最小反馈环、diff 检查和文档更新完成 |

## 4. 关键风险

- 真实 OpenCode 调用慢或失败，不能把运行时慢误判成 UI 状态机 bug。
- 当前对话线程在进程内存中，刷新前端能恢复，重启后不能恢复；本任务只处理前端刷新/页面重新进入，不承诺服务重启恢复。
- 流式 SSE 中断路径较多，需确保所有异常都把消息状态收敛到 `failed` 或可重试状态。

## 5. 退出标准

- 静态复核确认没有新的永久 running 分支。
- 至少有 API 或前端 store 级反馈环验证：失败/中断后再次读取线程不会出现未完成 running 卡死。
- 文档/记忆同步记录对话状态收敛规则。
