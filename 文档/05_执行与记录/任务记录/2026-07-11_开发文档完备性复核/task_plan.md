# G0–G5 开发文档完备性复核任务计划

## 目标

1. 判断现有 G0–G5 文档是否足以支持后续开发，而不是只检查篇幅和文件数量。
2. 交叉核对产品范围、数据与任务契约、文件/秘密边界、迁移回滚、UI 路径和验收证据是否闭环。
3. 按用户最新决定，将 G6 素材包 V2 与 G7 七阶段总验收从当前开发波次后置，但保留七阶段导航和长期产品位置。
4. 明确区分“文档内容完整”“文档已确认冻结”“功能已实现并验收”三种状态。

## 非目标

- 不编写 G6 素材包 V2 开发方案。
- 不删除第七步素材包的现有页面、路由、数据骨架或长期路线。
- 不修改代码、Schema、migration、依赖、数据库或真实 workspace。
- 不把 G1/G5 实施期 E0 原型结果伪装成已知结论。

## 复核维度

- 范围、目标与非目标。
- 前置依赖、阶段所有权和跨阶段边界。
- 数据模型、API/错误码、并发、幂等和任务来源。
- 文件、Asset、SecretStore、迁移和回滚。
- Web 用户路径、移动端边界和可访问性。
- 自动化、故障注入、真实用户路径和证据目录。
- 文档状态、Handoff、索引、路线图和长期/阶段性验收口径。

## 阶段

| 阶段 | 内容 | 状态 | 退出标准 |
| --- | --- | --- | --- |
| R0 | 读取事实源并盘点 G0–G5 | completed | 文件、状态、任务记录和关键边界有清单 |
| R1 | 交叉复核开发契约 | completed | 识别真实阻塞、实施期探针和纯留痕问题 |
| R2 | 同步 G6/G7 后置决策 | completed | 路线图、验收和“下一步”不再要求先写 G6 |
| R3 | 补齐 Handoff 与完备性报告 | completed | 有开发就绪矩阵、剩余批准项和交接记录 |
| R4 | 静态复核与记忆同步 | completed | 格式、链接、doc_id、一致性检查通过 |
| R5 | 用户补充九项事实源冲突复核 | completed | 逐项核对代码/ADR，统一字段、枚举、路由、路径和章节编号 |
| R6 | 用户补充六项协议、现状、术语与模板缺口复核 | completed | 任务枚举与 target 对齐代码；全流程索引重建当前态；角色术语统一；补齐 ADR/验收模板 |

## 强制退出标准

1. G0–G5 每阶段均能找到主方案、实施契约或数据字典、验收清单和阶段退出标准；不适用项须解释。
2. 当前开发波次的终点明确为 G5 `layout_publication`，不以 G6 ZIP 或 `exported` 为完成前提。
3. G6/G7 后置不会被误解为删除第七步、放弃历史素材包或允许 G5 越权生成 ZIP。
4. proposed/accepted/implemented 的差异明确，未经用户确认不得自动把 proposed 改为 accepted。
5. 形成 Scrutiny Review、Runtime/User Review 适用性说明和 Handoff。
