# 模型凭证统一重构 - 执行计划

## 背景

当前模型管理存在以下问题：
1. 双轨制混乱：固定槽位（aiKey + 4个image provider）和模型管理列表并存
2. 凭证解析复杂：5层回退逻辑，容易出bug
3. DB/文件模式不统一：存储方式不同，代码要区分处理
4. 同步逻辑复杂：`syncActiveTextModelWithAIKey` 等方法逻辑复杂

**参考**：Aurora项目的 `ProviderCredentialService` + `AgentModelSettingService` 设计

---

## 总体目标

1. 统一凭证存储：所有凭证加密存储到DB（或SecretStore），不区分模式
2. 简化数据模型：废弃固定槽位，只保留 `models[]` + `ProviderCredential`
3. 简化运行时解析：从5层回退简化为2层
4. 删除同步逻辑：不再需要固定槽位与模型管理的同步
5. 简化UI：只保留"模型管理"tab

---

### 阶段3：简化运行时解析

**3.1 重写 getRuntimeAIKeySettings()**
- 文件：`apps/server/src/settings/settings.service.ts` 177-205行
- 改为：
  ```typescript
  async getRuntimeAIKeySettings(): Promise<RuntimeAIKeySettings> {
    const model = this.resolveActiveTextManagedModel();
    if (!model) throw new Error('No active text model');
    
    const apiKey = await this.credentialService.resolve({
      modelId: model.id,
      providerId: model.providerId,
      fallbackToGlobal: true,
    });
    
    return { ...model, apiKey };
  }
  ```
