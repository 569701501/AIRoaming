## 2. R4 问题修正

### 2.1 动态镜头合同完成 Provider 语言编译

- 领域层不再依赖 `人物数量：`、`动作主客体：` 等中文字符串前缀作为内部协议。
- 候选图规格保存一个带版本的 `AIROAMING_SHOT_CONTRACT_V2` 结构化合同，包含：
  - 环境 / 单人 / 双人 / 多人调度类型；
  - 准确人数与角色名；
  - 动作；
  - 构图；
  - 单一决定性瞬间；
  - 条件式特效因果。
- OpenAI 和 Grok 将合同编译为英文；Doubao 将同一合同编译为中文。
- 15 份 V2 固定 Prompt 均未再出现旧中文合同前缀；内容字段中的中文角色名和剧情描述继续保留，这是正式业务事实，不是协议混用。

### 2.2 真实 A/B 强制显式选择 V1 或 V2

- `image:prompt:visual-ab` 现在必须传入 `--prompt-version v1` 或 `--prompt-version v2`。
- 不传版本会在读取凭据和调用 Provider 之前失败：

```text
VISUAL_AB_PROMPT_VERSION_REQUIRED:v1|v2
```

- V1、V2 使用不同输出目录、不同 ledger、不同 slot id 和不同 plan digest。
- ledger 升级为 schema v2，并直接记录 `promptVersion`。
- dry-run 报告记录每个案例和 Provider 的 `profileId`、最终 Prompt SHA-256 和字符长度，不保存密钥。

### 2.3 Grok 能力例外评分冻结

运行报告固定记录两条 Provider 能力例外：

1. Grok 无人场景只有一张场景参考时，为保持比例会省略该参考图；跨 Provider 总分排除 `environment`，仍评 `clean_plate` 和 `empty_scene`。
2. Grok 四人群像请求五张参考图时最多使用两名角色加场景；跨 Provider 总分排除完整 `identity`，仍评 `clean_plate` 和 `staging`。

对应 warning 必须实际出现，否则不能套用例外规则。Prompt 质量和 Provider 参考图能力不再混为同一项。

## 5. 仍然存在但不阻断付费 A/B 的边界

1. 角色预览、角色四视图和场景参考图 V2 仍是共享英文模板；本轮真实 A/B 只比较漫画候选图，不把该问题伪装成已经完成 Provider 专属参考资产模板。
2. Grok 单参考图与目标比例不能同时保证的问题仍未从 Provider 层消失，只是已经从评分中隔离。
3. 真实成图仍可能出现漏人、串脸、文字污染和比例偏差；这些正是 R5 要验证的内容，离线测试不能替代。
