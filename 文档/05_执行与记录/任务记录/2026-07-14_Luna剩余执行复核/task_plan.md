# Luna 剩余执行复核计划

## 目标

- 识别当前交给 Luna 的计划中已完成、部分完成、未执行和等待人工授权的阶段。
- 用代码、测试、提交和运行证据校正文档状态。
- 估算当前 G0～G5 目标的剩余工作量。
- 评估交接文档能否让 Luna 安全、连续执行，并指出必须修正的歧义或漂移。

## 非目标

- 不执行 C5/C6/C7 或任何真实数据、Keychain、Provider、激活操作。
- 不代替人类生成 AUTH 或签署 SH-10。
- 不实现 G4/G5 功能代码。

## 阶段

1. 读取事实源和 Luna 主交接。
2. 对账 S0/W1/R0B/R1/R2/G4/G5 的静态与运行证据。
3. 评估工作量和文档可执行性。
4. 输出 Scrutiny Review、运行复核适用性说明和最终结论。

## 验收标准

- 每个剩余阶段都有状态、证据、前置门和工作量区间。
- 明确区分 Luna 可自动执行、需要人工授权、当前后置三类工作。
- 文档审查给出通过/不通过结论和可操作风险清单。
- 会话记忆和长期记忆完成同步。

## 退出标准

- 计划、进度、发现和静态复核记录齐全。
- 文档路径和状态引用完成自检。
- 明确本次只读复核不适用真实 Runtime/User Review 的原因。

## 完成状态

- [x] Luna 主计划与 R0-R2 最新证据完成对账。
- [x] 剩余阶段、人工门和工作量区间已明确。
- [x] 交接文档静态复核已给出 `changes_required`。
- [x] 本次不执行真实运行复核的边界已留痕。
