# 任务计划：全项目功能补全规划

## 目标

在不进入功能开发的前提下，基于项目事实源、真实代码、现有调研和最新一手资料，形成全项目能力缺口与取舍方案；先通过可交互 HTML 与用户逐项决策，确认后再编写详细开发文档。

## 非目标

- 本轮不实现或修改业务功能代码。
- 不以“竞品有多少功能”替代项目用户价值判断。
- 不未经用户确认就改写长期产品范围、数据模型或开发排期。
- 不把无法核验的营销表述写成事实。

## 验收标准

1. 已具备、部分具备、缺失、暂缓和明确不做的能力有真实证据。
2. 竞品结论优先引用官方产品页、官方文档、官方仓库或可复现页面，并标注核验日期与置信度。
3. 提示词借鉴区分业务工作流指令、结构化输出契约、生成模型提示词和工具边界，避免混为一体。
4. 决策 HTML 能按用户任务、价值、依赖、风险、阶段和候选方案筛选或阅读。
5. 每个进入候选路线图的能力都有“为什么、先做什么、依赖什么、如何验收”；开发文档只在用户确认后编写。
6. 完成静态复核，并明确仍需用户验证或决策的事项。

## 当前阶段

阶段 5 已完成：D1、D3、D4/D5、D7 已收口；复核确认 D2 的“AI 分步生成、用户确认后推进”已经是现有七阶段实现，不再列为待开发功能，只有跨步骤自动调度细节后置。下一阶段围绕现有链路的真实能力缺口与端到端验收编写详细开发文档。

## 关键问题

1. AI漫游首个明确交付渠道与核心用户任务是什么，它将决定排版、导出和发布能力的优先级。
2. 已确认沿用当前已经实现的“AI 分步生成、用户确认后推进”；跨步骤一键自动调度细节等现有链路缺口补齐并完成端到端验收后再讨论。
3. 提示词优化优先解决输出质量、可控性、可追溯性还是成本与速度；不同目标对应不同契约。
4. 轻漫剧应继续后置，还是作为漫画主链路完成后的下一条主线。

## 角色边界

- Orchestrator：恢复事实源、规划研究与决策顺序，不写功能代码。
- Worker：仅执行资料核验、矩阵整理和 HTML 文档制作。
- Scrutiny Review：只读检查证据、口径、链接和方案一致性。
- Runtime/User Review：由用户阅读 HTML、验证理解并逐项拍板。

## 退出标准

- 决策 HTML、研究证据和能力矩阵完整且通过静态复核。
- 关键产品分叉得到用户确认。
- 详细开发文档在确认后完成，并明确后续开发的进入条件。
- 本轮没有越界修改功能代码。
