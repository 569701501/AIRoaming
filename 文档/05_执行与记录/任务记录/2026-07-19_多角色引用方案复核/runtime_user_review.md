# Runtime / User Review

## 1. 本轮状态

`not_run`

原因：本轮用户要求继续思考方案，没有授权修改生产链或发起新的付费图片 A/B。当前也尚未实现多人身份板、场景构图板和区域修复，不能通过旧输出代替新方案验收。

## 2. 已有但不能替代本轮验证的证据

- 2026-07-17 真实 A/B 已证明：Grok 单场景参考被舍弃会造成场景漂移；四人镜头省略两名角色参考时，人数和站位可以生成，但被省略角色没有图像级身份锁定。
- 该证据只证明现状缺口，不证明“身份板 + 场景”或“焦点单图 + 其余角色板 + 场景构图板”一定更好。

## 3. 未来最小 A/B

继续使用同一批已固化角色和场景资产，避免换素材证明通过；至少包含：

1. 三人同等重要群像。
2. 一名焦点角色 + 两名支持角色。
3. 四人群像。
4. 双人复杂动作主客体镜头，作为“不应合板”的对照。

对比策略：

| Provider | 对照 | 新方案 |
| --- | --- | --- |
| Grok | 当前独立引用裁剪基线 | 全员身份板+场景；全员身份板+场景+构图板；焦点单图+其余角色板+场景构图板 |
| OpenAI / Seedream | 独立角色图+场景 | 全员身份板+场景；焦点单图+其余角色板+场景/构图 |

逐图固定检查：

- 目标人物数量、每个角色身份、服装和关键配饰。
- 动作发起者/承受者、左右与前后站位、遮挡关系。
- 场景地标、出入口、空间深度和主光方向。
- 是否复制身份板排队布局、构图标记、拼贴、格线、文字或编号。
- Provider 实际使用/省略的来源、输入像素、usage/成本、延迟和警告。

## 4. 运行门禁

- 必须由用户重新确认 Provider、模型、每策略重复数和最大请求预算。
- 失败请求占预算，不自动重试或换 Provider 补位。
- 运行前先固化身份板/构图板字节、来源摘要和 Prompt；运行中不得动态换布局。
- 结果必须分别给出 Provider 结论，不能把某一家成功外推到其他模型。
