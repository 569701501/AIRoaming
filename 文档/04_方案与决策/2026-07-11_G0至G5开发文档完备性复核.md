# G0–G5 开发文档完备性复核

## 1. 复核结论

现有 G0–G5 文档在**内容层面已经达到可实施级**：每个阶段都有明确范围、依赖、所有权、数据或行为契约、实施切片、失败/回滚边界和验收入口，没有发现必须先编写 G6 素材包方案才能解释的 G0–G5 核心问题。

但“可实施级”不等于“已全部冻结”，更不等于“功能已实现”：

| 判断 | 结论 | 含义 |
| --- | --- | --- |
| 文档内容是否足够 | 通过 | 开发者可以按 G0→G5 逐阶段实施，不需要临场补产品规则 |
| 跨文档是否形成当前闭环 | 通过 | 当前波次到 G5 `layout_publication`，不依赖 G6 ZIP |
| 正式方案是否全部获用户确认 | 通过 | G0–G5 均为 `accepted`；用户以逐阶段“继续”确认前一阶段，并于本轮澄清确认意图 |
| 功能是否已经实现 | 否 | 现有代码仍保留文件/内存事实源、一镜一页和复制源图等旧骨架 |
| 是否可以宣称运行验收通过 | 否 | G0–G5 的实现、迁移、E0 原型和真实用户路径尚未执行 |

因此，当前最准确的状态是：

```text
G0–G5 内容完备
  + G0–G5 均已确认冻结
  + 全部功能尚未实施
  + G6/G7 明确后置
```

## 2. 当前范围决定

### 2.1 当前开发波次

```text
G0 行为刻画与 E2E 安全网
  -> G1 SQLite DB-only、SecretStore、持久任务与迁移
  -> G2 上游版本链与派生 Freshness
  -> G3 现有创建弹窗补“漫画版式”并锁定
  -> G4 候选定稿修订、影响预览与返修
  -> G5 高自由成稿编辑器与确定性出版导出
```

当前波次的用户可见终点是：用户能把 current 候选定稿编排成真实漫画成品，并得到 current `layout_publication`：

- 分页漫画：必需 PNG 页面，可选 PDF；
- 竖向条漫：必需 PNG 切片，能力允许时可附长图；
- 出版版本、任务、Asset、来源摘要和 manifest 可追溯；
- 章节达到 `layout_done`，不要求进入 G6 才会使用的 `exported`。

### 2.2 明确后置

- G6 素材包 V2、真实 ZIP、下载和 PackageRevision。
- G7 从创建项目到 ZIP/`exported` 的七阶段总验收。
- D2 跨步骤自动推进、整章批量调度和一键生产。
- D6 轻漫剧、R5，以及已单独登记的 AI 质量与提示词工程大功能。

后置 G6 不改变以下长期事实：

- 顶部仍保留七阶段导航，不改回六阶段；
- 现有素材包页面和旧目录包骨架不在本轮删除；
- G5 不越权生成 ZIP，`layout_publication` 仍是未来 G6 的唯一 current 输入；
- 完整 `draft -> exported`/ZIP 验收继续保留为长期基线，但不阻塞 G0–G5 开发和阶段签收。

## 5. 不属于“文档缺失”的实施期问题

以下问题必须在开发中以真实证据回答，但不应为了让文档看起来“全确定”而提前猜测：

### 5.1 G0 运行骨架

- Playwright 浏览器安装、多个本地进程的可靠关闭、trace 演练和连续三次无随机失败。
- 这些证据在 G0 实施时产生；当前文档已给出环境守卫和失败标准。

### 5.2 G1 M0 E0

- 当前 Prisma 6.19.3/SQLite 对 Json、DateTime、复合约束、定制 trigger 和离线备份的真实行为。
- macOS Keychain adapter 的读写、替换、删除、权限/锁屏失败与脱敏日志。
- runtime bundle、journal/synchronous 和异常退出恢复。

探针失败时可以换实现方式，但不能退回明文文件、file/DB 双写或静默 fallback。

### 5.3 G5 E0

- 交互 adapter、富文本/IME、专用 HTML/SVG RenderScene、固定 Chromium 和 SVG/resvg 对照的量化结果。
- 字体包和许可证、渲染能力上限、golden diff 与性能预算。

原型通过后再用技术 ADR 锁定画布/renderer 依赖；原型失败时更换路线，不进入正式编辑器实现。

## 8. 最终判定

如果问题是“还要不要继续写 G6 才能开始前面的开发”，答案是：**不需要**。

如果问题是“现在能不能把全部文档视为已经确认”，答案是：**可以，G0–G5 均已 accepted**。

如果问题是“现在能不能直接改代码”，答案是：**还不可以，仍需用户单独明确授权开始开发**。

本复核未发现 G0–G5 必须新增的产品决策文档，但用户在首轮结论后补充发现 9 项既有事实源同步问题；这些不是新产品决策，已在 R5 逐项校正。后续仍应停止扩写同层方案，把精力转入按阶段实现、E0 实测、测试证据和真实用户路径复核。
