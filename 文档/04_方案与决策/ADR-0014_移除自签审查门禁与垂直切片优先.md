# ADR-0014 移除自签审查门禁与垂直切片优先

## 1. 状态

已采纳，正在执行。该决策替代 G1 当前实现中“同一 Codex 在同一工作区模拟两名独立 Reviewer，并以 2/2 attestation/CAS bundle 授权 Schema 与 migration 写入”的做法。

## 2. 背景

G1 为了让 Schema 派生可审计、可回滚，引入了 review-attestation、review-bundle、review-check、sealed CAS 和多轮 review evidence。机械复算显示，这部分约包含 2696 行生产代码、2699 行测试以及 3051 行审查证据；与此同时，正式 migration tree 尚未生成，生产运行时也没有接入 `PrismaClient`。

现有 Reviewer 的 `reviewerId` 与 `independentFromWorker: true` 都是工作区文件内的自声明，没有外部账号、密钥、权限域或人工身份验证。它可以证明文件未被意外改动，但不能证明审查者真正独立，因此不应作为写入授权或业务交付门禁。

r5 还发生了顺序倒置：先完成 2/2 签收，之后首次运行真实 Prisma validate，随即暴露 106 个 Schema 错误并触发后续重审。这说明关键反馈应首先来自可运行 artifact，而不是自建证明流程。

## 3. 决策

### 3.1 自签审查退出关键路径

- 删除生产入口对 review-attestation、review-bundle、review-check 的依赖。
- 删除对应 publish/recover/check CLI 与 package scripts；相关历史 review 文档只作为历史记录保留。
- 同一 Agent 可以进行静态复核，但不得再表述为具有独立信任边界的“双签”。

### 3.2 写入授权改为直接、确定性校验

Schema 与 migration materializer 只依赖下列事实：

1. manifest 的自摘要有效，且由当前源文件重新生成后逐字一致；
2. 生成的 Prisma Schema 与 manifest 精确一致并通过 `prisma validate`；
3. migration plan 与当前 manifest/Schema 精确匹配；
4. 正式目标 tree 在首次 materialize 前不存在；
5. staging tree 与最终 tree 的路径、字节、文件类型和链接约束精确一致；
6. fresh SQLite 能完整 replay，二次 deploy 无 pending，并通过 integrity、FK 与约束验证。

这些校验只证明 artifact 正确性和可重放性，不伪造组织级审批含义。

### 3.3 先跑 artifact，再做复核

每个派生产物必须先通过真实工具链和运行验证，再进入静态复核。任何 review 文档都不能替代 `prisma validate`、fresh deploy、数据库约束测试或业务集成测试。

### 3.4 采用业务垂直切片推进

- 先生成正式 migration tree。
- 随后实现 Project/Chapter/Script 的最小 DB-only 路径：创建项目、保存草稿、完成章节、重建应用上下文并从同一 SQLite 读回。
- G2 的开始条件改为“最小 DB substrate 与当前/版本事务已通过”，不再等待 G1-10 的完整 importer/witness。
- 其余 G1 模块继续按垂直切片迁移；正式 DB-only 切换、真实数据迁移和删除 file runtime 仍需要独立授权。

### 3.5 设置复杂度与反馈时间盒

- 非领域流程代码不得超过当前阶段生产改动的 10%。
- 连续 90 分钟没有新增可运行的业务行为时，必须停止扩展基础设施，回到当前最小垂直切片。
- 摘要、CAS、证明性 DSL 只有在直接保护真实数据或可执行 artifact 时才允许新增。

## 4. 被否决的备选

### 4.1 否决：继续完成 r7 双 Reviewer 门禁

没有外部身份和权限隔离时，继续补协议只能强化自我证明，不能增加真实独立性，并会继续阻塞 migration 和业务路径。

### 4.2 否决：删除全部 Schema/migration 校验

manifest freshness、Schema exact、Prisma validate、fresh replay、integrity/FK 和原子 materialize 直接降低数据库事故风险，应当保留。

### 4.3 否决：先完成全部 G1 再进入 G2

Dialogue、SecretStore、持久任务、Asset、Layout、Importer 与 G2 的 Script/Story 版本事务并非全部存在严格前置关系。全串行会放大批量设计错误，也推迟真实业务反馈。

### 4.4 否决：立即切换真实 workspace 到 DB-only

当前任务只建立隔离数据库基座。真实停写、snapshot、Secret 迁移、激活与回滚演练仍属于高风险动作，必须另行授权。

## 5. 影响范围

- `apps/server/src/persistence/` 的 manifest、Schema 与 migration 生成链。
- `apps/server/package.json` 中 G1 review 相关脚本。
- `apps/server/prisma/migrations/` 正式 migration artifact。
- Project/Chapter/Script 的 Repository、Service 与应用生命周期接线。
- G1/G2 总控计划、QA 清单和后续 Handoff。

## 6. 回滚边界

- C1/C2 只修改源码和仓库内 migration artifact，不连接真实用户数据库。
- DB 垂直切片通过 `AIROAMING_PERSISTENCE_MODE=db` 显式启用；完整切换前默认 file 模式不变。
- 若直接校验链出现问题，可以回退 materializer 改动，但不得恢复“同一 Agent 自签即授权”的语义。

## 7. 验证标准

- 生产代码和 package scripts 不再引用 G1 review gate。
- manifest、Schema、migration 由当前源文件可确定性重建并精确校验。
- 正式 migration tree 通过 Prisma validate、fresh deploy、二次 no-pending、SQLite integrity/FK/约束与 artifact exact 检查。
- Project/Chapter/Script DB-only 垂直切片通过应用上下文重建后的持久化回读。
- 根级聚合测试稳定通过，真实 workspace/settings/secret 未被读写或迁移。
