## 1. 背景与问题

7 步主流程前 4 步（剧本、剧情结构、分镜、出图准备）已落地，第 5 步候选图工作台未实现，漫画主链路尚未端到端闭环。本方案定义第 5 步的 MVP 范围：让用户在已确认分镜和出图准备的前提下，为每个分镜生成候选图、选择锁定，并把章节推进到 `images_done`。

设计原则：**第一版只打「链路闭环」一场仗**。多角色一致性、prompt 智能优化、批量效率优化全部排到链路跑通之后。

## 2. 目标与非目标

### 2.1 目标

- 每个分镜可生成候选图（默认 2 张/次），候选可追溯到任务输入。
- 用户可查看、锁定、废弃候选；可将分镜标记「跳过」。
- 全部分镜锁定或跳过后，用户点「完成候选图」，章节状态推进到 `images_done`。
- 提示词由程序确定性拼装（系统级模板 + 章节画风 + 分镜用户级内容），用户可编辑用户级部分。
- 候选记录落章节级 `candidates.json` 文件态，与 storyboard/preflight 模式一致。

### 2.2 非目标（明确不做）

| 项 | 说明 |
| --- | --- |
| 多参考图/拼图参考 | `referenceAssetIds[]` 协议字段保留数组形态，MVP worker 只取第 1 张 |
| LLM 生成 prompt | `shot_prompt_generate` 任务类型保留但 MVP 不使用，降级为后续增强 |
| 多角色一致性 | 单参考图下配角形象漂移是已知接受的代价 |
| 角色一致性评分 | 不做自动评分闭环 |
| Prisma 启用 | `schema.prisma` 6 表继续闲置勿用；候选数据不入库 |
| shot 级细粒度失效 | 分镜变更后旧候选只打「基于旧分镜」标记，不自动删除 |
| 停止生成/任务取消增强 | 沿用现有任务能力 |
| 对话框受控工具 | 第 5 步对话框仅做阶段提示与答疑，不新增写入工具 |

## 4. 方案概览（已收敛决策）

| # | 决策 |
| --- | --- |
| Q1 | 候选记录存 `chapters/{chapterSlug}/candidates.json`；Prisma 继续闲置 |
| Q2 | prompt = 系统级模板（可编辑配置，不写死代码）+ preflight 画风 + 分镜用户级内容；分开存储，生成时拼接 |
| Q3 | 单参考图：出场角色按 `lead > recurring > chapter` 取首个的定稿图；空镜纯文生图 |
| Q4 | 默认 `candidateCount: 2`；主操作为单 shot 生成；整章批量 = 循环建任务；共用一条串行图片队列 |
| Q5 | 每格「锁定」或「跳过」后，「完成候选图」按钮可点 → `images_done` |
| Q6 | 旧候选标「基于旧分镜」，不删除 |
| Q7 | 对话框仅阶段提示 |

## 5. 详细设计

### 5.1 数据契约：candidates.json

路径：`workspace/projects/{projectId}/chapters/{chapterSlug}/candidates.json`

```json
{
  "schemaVersion": 1,
  "chapterId": "chapter_001",
  "sourceStoryboardId": "chapter_001_storyboard_v001",
  "sourceStoryboardUpdatedAt": "2026-07-06T10:00:00.000Z",
  "status": "in_progress",
  "shots": [
    {
      "shotId": "shot_001",
      "decision": "pending",
      "lockedCandidateId": null,
      "skipNote": "",
      "userPromptOverride": null,
      "candidates": [
        {
          "id": "candidate_001",
          "taskId": "task_xxx",
          "assetPath": "projects/{projectId}/chapters/chapter-001/candidates/shot_001/candidate_001.png",
          "status": "generated",
          "promptSnapshot": {
            "systemPart": "...",
            "stylePart": "...",
            "userPart": "...",
            "finalPrompt": "..."
          },
          "referenceAssetIds": ["asset_char_hero_final"],
          "sourceStoryboardUpdatedAt": "2026-07-06T10:00:00.000Z",
          "createdAt": "2026-07-06T10:05:00.000Z"
        }
      ]
    }
  ],
  "confirmedAt": null,
  "createdAt": "...",
  "updatedAt": "..."
}
```

字段口径：

| 字段 | 说明 |
| --- | --- |
| `shots[].decision` | `pending / locked / skipped`；`locked` 必须携带 `lockedCandidateId` |
| `shots[].userPromptOverride` | 用户手改的用户级 prompt；`null` 表示用自动拼装 |
| `candidates[].status` | `generated / discarded`；废弃不删文件，只改状态 |
| `candidates[].promptSnapshot` | 生成时三段快照 + 最终拼接结果，保证可复现追溯 |
| `candidates[].sourceStoryboardUpdatedAt` | 与当前正式分镜 `updatedAt` 不一致时 UI 标「基于旧分镜」 |
| `status` | `in_progress / confirmed`；确认时写 `confirmedAt` 并推进章节状态 |

候选图文件路径（正典，实现时同步修正素材契约 248 行）：

```text
projects/{projectId}/chapters/{chapterSlug}/candidates/{shotId}/{candidateId}.png
```

候选图注册进 `shared/assets.json`（现有文件态资产登记），`metadataJson` 带 `chapterId/shotId/candidateId`。

### 5.2 边界：storyboard.json 在第 5 步只读

- 候选工作台**不写** `storyboard.json`；锁定/跳过/候选清单全部落 `candidates.json`。
- DTO 层 `StoryboardShot.lockedCandidateId` 保留为聚合视图字段：快照组装时从 `candidates.json` join 合成，不落盘回分镜文件。
- workflow 推导 `images_done` 时 join 两个文件判断。

### 5.3 prompt 拼装

```text
finalPrompt = [系统级模板] + [画风段: preflight.styleCheck 的 comicFormat/artStyle] + [用户级段]
用户级段默认 = 拼装(shot.coreAction, emotion, shotType, cameraAngle, comic.panelDescription,
                comic.composition, 出场角色 promptFragment, 场景名)
```

- **系统级模板**存全局设置（settings 新增 `imagePromptTemplate` 文本字段，设置页可编辑），代码只提供默认值。打磨措辞不改代码、即时生效。
- **用户级段**：`userPromptOverride` 为 `null` 时每次生成实时自动拼装（分镜改了自动跟上）；用户手改后存 override，后续生成用 override。提供「重置为自动拼装」。
- 拼装为纯函数 `buildShotImagePrompt(...)`，放 `packages/shared` 或 server util，**必须有单元测试**。
- UI 每格显示最终 prompt 预览，可编辑区仅用户级段。

### 5.4 参考图选择规则

1. 取 `shot.characterIds` 对应项目角色，按 `lead > recurring > chapter` 排序取首个。
2. 该角色须有可用 `final_reference` 定稿图（preflight 已确认保证了必需角色就绪）→ `editImage` 图生图。
3. 无出场角色（空镜）→ `generateImage` 纯文生图。
4. `referenceAssetIds` 数组完整记录进任务输入与候选快照，MVP worker 只消费第 1 张。

### 5.5 任务流与队列

- 复用 `image_generate` 任务类型与现有 `guardGenerationTaskCreate` 闸门（preflight 确认 + storyboard 匹配 + shot target 校验）。
- 把 `CharacterReferenceService` 的 Promise 链串行队列抽成通用 `ImageTaskQueue`（进程内单并发），角色参考图任务与候选图任务共用，统一吃 provider 429 预算。
- 单 shot 生成：一个任务生成 `candidateCount`（默认 2）张，逐张写盘、注册资产、追加进 `candidates.json`，SSE 报进度。
- 整章批量：前端循环对未锁定/未跳过的 shot 建任务入队，无新协议。
- 失败处理：沿用任务协议，`error` 保留 provider 错误与输入；部分成功时已产出候选保留并在 warnings 说明。

### 5.6 API 草案

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/projects/:pid/chapters/:cid/candidates` | 读取候选状态（无文件时返回空骨架） |
| PUT | `/projects/:pid/chapters/:cid/candidates/shots/:shotId/prompt` | 保存/清除 `userPromptOverride` |
| POST | `/projects/:pid/chapters/:cid/candidates/shots/:shotId/generate` | 建 `image_generate` 任务（body: candidateCount?） |
| POST | `/projects/:pid/chapters/:cid/candidates/shots/:shotId/lock` | 锁定候选（body: candidateId） |
| POST | `/projects/:pid/chapters/:cid/candidates/shots/:shotId/skip` | 标记跳过（body: note?） |
| POST | `/projects/:pid/chapters/:cid/candidates/shots/:shotId/discard` | 废弃候选（body: candidateId） |
| POST | `/projects/:pid/chapters/:cid/candidates/confirm` | 完成候选图 → `images_done` |

确认前置校验：所有 shot `decision != pending`，且 `sourceStoryboardId` 与当前正式分镜匹配。

### 5.7 前端

- 新增 `ImageCandidatesWorkspace.vue`，路由挂 `image_candidates` 步骤（`/projects/:projectId/candidates/:chapterId`，与现有步骤路由模式对齐）。
- 每 shot 一行/卡：分镜信息（只读）、prompt 预览（用户级可编辑）、「生成候选」、候选缩略图网格（锁定/废弃/放大）、「跳过本格」。
- 顶部：整章批量生成、进度统计（已锁定 x / 跳过 y / 待定 z）、「完成候选图」按钮（全部非 pending 才可点）。
- 旧分镜候选打「基于旧分镜」角标。
- 任务进度走现有 SSE 通道。

## 7. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 单参考图下多角色画面配角漂移 | MVP 明确接受；后续迭代多参考图/拼图（非目标已列） |
| gpt-image-2 成本（约 ¥1-1.5/张） | 默认 2 候选；单 shot 生成为主操作；批量前 UI 显示预估张数 |
| 串行队列整章批量耗时（20 shot × 2 ≈ 40 张 ≈ 20-40 分钟） | SSE 进度可见；允许边生成边锁定已完成的 shot |
| 内存任务队列重启丢失 | 已知限制沿用；candidates.json 落盘的候选不丢，仅未完成任务需重发 |
| 分镜返工导致候选与分镜错位 | `sourceStoryboardUpdatedAt` 标记 + 确认时校验 storyboardId 匹配 |
| 回滚 | 全部新增物为独立文件/新端点/新组件，删除即回滚，不触碰前 4 步产物 |

## 8. 验收标准

对齐 MVP 路线图 M2 退出标准：

1. 每个分镜可生成至少 2 张候选图，候选可追溯到任务输入（promptSnapshot + referenceAssetIds + taskId）。
2. 用户能锁定一张候选作为分镜当前图片；能废弃候选；能跳过分镜。
3. 全部分镜锁定/跳过后「完成候选图」可点，章节状态变为 `images_done`，workflow 第 6 步解锁。
4. 空镜（无角色）分镜走纯文生图成功出图。
5. 修改用户级 prompt 后重新生成，使用用户版本（快照可证）。
6. 修改系统级模板后新生成的候选使用新模板（无需重启）。
7. 分镜修改后旧候选显示「基于旧分镜」且不被删除。
8. `buildShotImagePrompt` 与 candidates.json 读写有单元测试。
