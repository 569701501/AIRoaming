开源 AI 漫画平台调研：出图准备要保留，但边界要更轻

基于 GitHub 热门开源项目与 AI漫游当前链路，对“分镜工作台之后、候选工作台之前”的出图准备做判断：它不是多余步骤，而是生产级漫画链路里少见但很关键的版本门禁和生成上下文快照。

调研日期：2026-07-09 范围：漫画垂直项目 · 通用生图工作台 · 漫画处理管线 目标：判断出图准备是否保留，并指导候选工作台
总判断
保留出图准备

只做“能不能出图”的检查与版本放行，不承载复杂创作编辑。

市场启发
强在生成，弱在门禁

ComfyUI、A1111、InvokeAI 等生图能力强，但缺漫画章节级业务检查。

下一步重心
强化候选工作台

补 prompt 可见、单镜重画、批量生成、候选批次和生成历史。

1一句话结论

把出图准备从“功能页”理解成“生产放行口”，它的价值就清楚了。

AI漫游现在的方向是对的

开源生态里，大多数工具直接从 prompt 或 workflow 进入生成；它们擅长参数、节点、inpaint、variation，但很少处理“正式分镜版本、角色是否定稿、场景是否绑定、生成任务能否追溯到资产来源”。AI漫游的出图准备正好补的是这个生产风险。

出图准备 = 出门检查单 + 生成上下文快照
候选工作台 = 单镜生成 / 批量生成 / 多候选比较 / prompt 可编辑 / 锁定与废弃 / 生成历史

边界要收住

出图准备不应该变成一个新的创作工作台。角色图、场景图、风格板可以在这里提示缺口和提供跳转，但真正的生成、重画、候选比较、参数调整都应该留给候选工作台。

2调研项目全景

热度以 2026-07-09 查询到的 GitHub 数据为参考，重点看它们有没有类似“出图准备”的能力。

StoryDiffusion

约 6.4k stars

强项是长序列角色一致性，支持 comics generation demo，说明“角色一致性”确实是漫画生成核心问题。

启发：AI漫游的角色定稿硬门槛应该保留。

PrintFilm

约 2.8k stars

采用 Script-to-Asset-to-Keyframe 路线：先剧情分镜，再角色/场景资产，再关键帧/视频，再导出。

启发：出图前资产准备不是臆造，长链路工具也会先做资产阶段。

AI Comic Factory

已归档

LLM + SDXL 生成 comic panels，demo 价值高，但缺完整章节生产、正式分镜门禁和资产准备检查。

启发：一把梭适合 demo，不适合可返修的漫画生产。

AI-Comic-Generator

低星但贴近

JSON 驱动，包含角色一致性检查、三视图、单格重画、批量生成和后台任务。

启发：候选工作台要把“单镜重画”和“批量队列”做成一等能力。

MangaGen

本地优先

强调项目素材桶、生成历史、批量队列、provider route、项目导入导出。

启发：生成历史和 provider 参数追溯应进入候选工作台。

Komiko

产品入口

强调角色库、AI canvas 和 comic studio，但仓库更像商业产品展示入口。

启发：角色库与画布能力有价值，但不能替代生成前版本门禁。

ComfyUI

约 120k stars

节点图和 workflow 复用很强，可组合复杂生图链路，但没有漫画章节级状态、分镜和角色定稿检查。

启发：可以学 workflow 可追溯，暂时不学完整节点编辑器。

AUTOMATIC1111 WebUI

约 164k stars

txt2img、img2img、inpaint、prompt matrix 和参数试验强，是通用生成工作台代表。

启发：prompt 透明、参数可见、重跑历史值得吸收。

Fooocus

约 50.8k stars

降低参数心智，支持 image prompt、variation、inpaint，面向轻量用户。

启发：候选工作台应先给简单主路径，再把高级参数收起来。

InvokeAI

约 27.6k stars

canvas、workflow、gallery、图像元数据召回更成熟，适合专业创作工作流。

启发：生成结果要能召回当时的 prompt、模型、seed 和参考图。

Krita AI Diffusion

约 10.3k stars

在 Krita 内做 inpaint、outpaint、ControlNet、IP-Adapter，适合锁图后的精修。

启发：局部修图很重要，但应放在候选锁定后的精修阶段。

漫画翻译管线

约 10k stars

manga-image-translator 与 comic-translate 都把 OCR、inpainting、translation、text rendering 做成阶段管线。

启发：漫画工具天然需要阶段化，不应该把所有事情压进一个按钮。

4产品取舍

留下好的，先补最影响真实生产体验的能力。

继续保留

  • 出图准备独立步骤，作为候选图前的放行口。
  • 只读正式分镜，待确认分镜不能污染候选图。
  • preflight 绑定分镜版本，分镜变更后自动失效。
  • 角色定稿硬门槛，尤其 lead / recurring。
  • 场景参考图 warning，提醒但不拖死主线。
  • 任务注入参考图资产，保证候选图可追溯。
  • 一镜多候选 + 显式锁定，优于整页一把梭。

优先增强

  • prompt 预览与可编辑，每个镜头生成前可看可改。
  • 重画此镜作为一等操作，旧候选保留。
  • 候选批次 candidateBatch，支持第 1 轮 / 第 2 轮比较。
  • 批量生成未锁镜头，降低长章节点击成本。
  • 候选状态可见，显示 generated / locked / rejected / superseded。
  • 生成历史面板，保存 prompt、参考图、provider、模型、尺寸、seed、任务 ID。

暂时后置

  • ComfyUI 式节点图编辑器，能力强但心智太重。
  • 完整自由 canvas 排版，先稳定主线，再做复杂排版。
  • 局部 inpaint / mask 编辑，适合锁图后的精修阶段。
  • 视频关键帧 / 漫剧生成，PrintFilm 方向值得参考，但不抢当前候选工作台主线。

5建议路线

先把“可生成、可重画、可追溯”的闭环做扎实，再扩展高级编辑。

P0

候选工作台主体验

补 prompt 预览/编辑、单镜重画、候选批次、批量生成、候选状态和锁定。这个阶段直接决定用户是否愿意在工作台里反复打磨。

P1

出图准备轻增强

确认 preflight 时产出只读镜头出图包，包含 shot、角色参考、场景参考、风格片段、默认 prompt 和版本信息。

P2

锁图后的精修工具

再考虑 inpaint、mask、局部重绘、画布排版和视频关键帧。它们有价值，但不应阻塞当前漫画生成主链路。
