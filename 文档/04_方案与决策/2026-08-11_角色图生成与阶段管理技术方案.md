## 1. 方案概述

### 1.1 目标

解决角色图生成的两个核心问题：
1. **提示词信息源单薄**：只读单章内容，first-write-wins 导致后续描写无法补充
2. **缺乏阶段管理**：角色有阶段性变化（年龄、衣着、气质），但系统无阶段机制

### 1.2 方案定位

**选择稳妥路线**：跟 Midjourney、LlamaGen 等市面产品对齐，做"图为王"

**核心理念**：
- 图片是角色的核心，文字描述只是辅助
- 用户先定妆（3 选 1），后续生成全部参考定妆照
- 阶段变化 = 定妆照 + 差异描述（"改穿金袍"）+ 垫图生成

### 1.3 不做什么（与创新路线的区别）

- ❌ 不做"全书扫描自动提炼设定"
- ❌ 不做"AI 自动检测阶段冲突"
- ❌ 不做"槽位结构化解析"

## 2. 数据模型设计

### 2.1 CharacterStage 表

```prisma
model CharacterStage {
  id            String   @id @default(uuid())
  projectId     String
  characterId   String
  stageOrder    Int      // 1, 2, 3...（阶段顺序）
  name          String?  // 可选：阶段名称，如"练气期""金丹期"
  fromChapterId String?  // 可选：从第几章开始
  toChapterId   String?  // 可选：到第几章结束（null = 直到下一阶段）
  visualDelta   String   // 差异描述："改穿金色道袍、蓄短须、气质沉稳"
  previewAssetId String? // 阶段预览图
  finalAssetId   String? // 阶段定稿图（可选）
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  
  character Character @relation(fields: [characterId], references: [id], onDelete: Cascade)
  project   Project   @relation(fields: [projectId], references: [id], onDelete: Cascade)
  
  @@unique([characterId, stageOrder])
  @@index([projectId])
  @@index([characterId])
}
```

**字段说明**：
- `stageOrder`：阶段顺序，自动递增（1, 2, 3...）
- `name`：阶段名称，可选，用户可以填"筑基期""金丹期"等
- `fromChapterId/toChapterId`：章节范围，可选，用于分镜生图时自动选择阶段
- `visualDelta`：差异描述，只存变化的部分，不存全量描述
- `previewAssetId`：阶段预览图，创建阶段时自动生成
- `finalAssetId`：阶段定稿图，可选，用户可以确认预览图或重新生成

### 2.2 Character 表新增字段

```prisma
model Character {
  // ... 现有字段
  anchorAssetId String?           // 定妆照/锚点图
  stages        CharacterStage[]  // 角色的所有阶段
}
```

**字段说明**：
- `anchorAssetId`：定妆照，用户 3 选 1 后保存的图片 ID
- `stages`：关联的所有阶段

### 2.3 迁移策略

**0021 migration**（原方案编号 0018，因仓库最新 migration 实为 0020_document_library，序号顺延）：
- 新增 `CharacterStage` 表
- 在 `Character` 表增加 `anchorAssetId` 字段（nullable）
- 旧数据无需迁移，`anchorAssetId` 默认为 null
- 旧数据兼容：读取时如果 `anchorAssetId` 为 null，降级使用现有的 `previewReferenceAssetId`

## 3. 核心功能设计

### 3.1 交互式定妆

**目标**：lead/recurring 角色支持定妆流程，生成 3 张候选供用户选择

#### 3.1.1 前端交互

**角色库状态显示**：
- lead/recurring 角色且 `anchorAssetId` 为 null → 显示"待定妆"标签
- 已定妆的角色 → 显示定妆照缩略图

**定妆弹窗**：
1. 用户点击"定妆"按钮
2. 弹窗显示 loading → 调用后端生成 3 张候选
3. 展示 3 张候选图（grid 布局）
4. 用户点击选择其中一张
5. 调用后端确认接口 → 关闭弹窗 → "待定妆"标签消失

**可选功能**：
- "重新生成 3 张"按钮（如果 3 张都不满意）
- "调整描述"输入框（用户可以提供更详细的要求）

#### 3.1.2 后端接口

**生成定妆候选**：
```typescript
POST /api/projects/{projectId}/characters/{characterId}/anchor-candidates

Request:
{
  count: 3,           // 生成数量（默认 3）
  customPrompt?: string  // 可选：用户自定义提示词
}

Response:
{
  candidates: WorkbenchAsset[]  // 3 张候选图
}
```

**实现逻辑**：
```typescript
async generateAnchorCandidates(
  projectId: string,
  characterId: string,
  count: number = 3,
  customPrompt?: string,
): Promise<WorkbenchAsset[]> {
  const project = await this.projectStore.getReadyProject(projectId);
  const character = this.projectStore.findCharacter(project, characterId);
  
  // 1. 构建提示词
  const prompt = customPrompt 
    ?? character.appearance 
    ?? `${character.name}，${character.role}`;
  
  // 2. 并发生成 count 张候选
  const candidates = await Promise.all(
    Array.from({ length: count }, (_, i) => 
      this.generateCharacterReference(project, character, {
        prompt,
        seed: Date.now() + i,  // 不同的 seed 保证图片不同
        referenceKind: 'preview_front',
      })
    )
  );
  
  return candidates;
}
```

async confirmAnchor(
  projectId: string,
  characterId: string,
  assetId: string,
): Promise<ProjectCharacter> {
  // 1. 更新 Character.anchorAssetId
  await this.prisma.character.update({
    where: { id: characterId },
    data: { anchorAssetId: assetId },

async queueCharacterReference(...) {

  // 检查是否需要提醒定妆

      characterId: character.id,
      canSkip: true,  // 可以跳过
    });
  }
  
  // 正常生成逻辑
  // ...
}

### 3.2 阶段管理

**目标**：支持手动创建阶段，新阶段基于上一阶段图垫图生成

#### 3.2.1 前端交互

**角色详情页**：
- 显示当前角色的所有阶段（列表或时间轴形式）
- 每个阶段显示：阶段名、章节范围、预览图
- "新增阶段"按钮

**新增阶段弹窗**：
1. 表单字段：
   - 阶段名称（可选，如"筑基期"）
   - 从第几章开始（可选，章节选择器）
   - 差异描述（必填，如"20 岁青年，改穿青色道袍，蓄短须，气质沉稳"）
2. 点击"生成"→ loading → 调用后端
3. 生成成功 → 显示预览图 → 关闭弹窗 → 阶段列表刷新

**阶段图操作**：
- 查看大图
- 重新生成（如果不满意）
- 删除阶段

#### 3.2.2 后端接口

**创建阶段**：

{
  name?: string,           // 可选：阶段名称
  fromChapterId?: string,  // 可选：从第几章开始

**实现逻辑**：
```typescript
async createCharacterStage(
  projectId: string,
  characterId: string,
  input: CreateCharacterStageRequest,
): Promise<{ stage: CharacterStage; previewAsset: WorkbenchAsset | null }> {
  const project = await this.projectStore.getReadyProject(projectId);
  const character = this.projectStore.findCharacter(project, characterId);
  
  // 1. 获取上一阶段（stageOrder 最大的）
  const previousStage = await this.prisma.characterStage.findFirst({
    where: { characterId },
    orderBy: { stageOrder: 'desc' },
  });
  
  // 2. 确定参考图（优先级：上一阶段图 > 锚点图 > primary/preview）
  const referenceAssetId = previousStage?.finalAssetId 
    ?? previousStage?.previewAssetId 
    ?? character.anchorAssetId
    ?? character.primaryReferenceAssetId
    ?? character.previewReferenceAssetId;
  
  // 3. 创建阶段记录
  const stage = await this.prisma.characterStage.create({
    data: {
      projectId,
      characterId,
      stageOrder: (previousStage?.stageOrder ?? 0) + 1,
      name: input.name,
      fromChapterId: input.fromChapterId,
      visualDelta: input.visualDelta,
    },
  });
  
  // 4. 如果有参考图，生成新阶段预览图（editImage 垫图）
  if (referenceAssetId) {
    const previewAsset = await this.generateStagePreview(
      project,
      character,
      stage,
      referenceAssetId,
    );
    return { stage, previewAsset };
  }
  
  return { stage, previewAsset: null };
}
```

**垫图生成核心逻辑**：
```typescript
private async generateStagePreview(
  project: LocalProject,
  character: ProjectCharacter,
  stage: CharacterStage,
  referenceAssetId: string,
): Promise<WorkbenchAsset> {
  // 1. 加载参考图
  const referenceAsset = await this.loadAsset(project, referenceAssetId);
  
  // 2. 使用 editImage（垫图生成）
  const result = await this.imageProvider.editImage({
    referenceImage: referenceAsset.buffer,
    prompt: `${character.name}，${stage.visualDelta}`,
    style: project.artStyle,
    size: { width: 512, height: 768 },  // 根据项目版式调整
  });
  
  // 3. 保存为阶段预览图
  const asset = await this.saveStageAsset(
    project,
    character,
    stage,
    result,
    'preview',
  );
  
  // 4. 更新阶段记录
  await this.prisma.characterStage.update({
    where: { id: stage.id },
    data: { previewAssetId: asset.id },
  });
  
  return asset;
}
```

### 3.3 生图提示词改造

**目标**：有参考图时，提示词以图为主，文字降级为辅助

#### 3.3.1 当前问题

```typescript
// reference-prompt.util.ts:131
APPEARANCE: character.appearance || REFERENCE_PROMPT_DEFAULTS.appearance
```

**问题**：提示词全靠文字，信息量有限，AI 会瞎猜

#### 3.3.2 改造方案

```typescript
export function buildCharacterReferencePrompt(
  project: LocalProject,
  character: ProjectCharacter,
  referenceKind: ProjectCharacterReferenceKind,
  version: ImagePromptVersion = "v2",
  hasReferenceImage: boolean = false,  // 新增参数
): string {
  // 有参考图时，提示词简化
  const appearance = hasReferenceImage
    ? "参考所提供的角色图片，保持面部特征、发型和整体气质一致"
    : (character.appearance || REFERENCE_PROMPT_DEFAULTS.appearance);
  
  // 有参考图且有文字描述时，文字作为补充
  const additionalNotes = hasReferenceImage && character.appearance
    ? `补充细节：${character.appearance}`
    : "";
  
  return renderOpenCodePromptTemplate(
    readOpenCodeSkillReference(IMAGE_REFERENCE_SKILL, templateName),
    {
      APPEARANCE: appearance,
      ADDITIONAL_NOTES: additionalNotes,
      // ... 其他字段
    },
  );
}
```

### 3.4 分镜生图集成阶段图

**目标**：分镜生成候选图时，根据章节自动选择对应阶段的参考图

#### 3.4.1 阶段选择逻辑

```typescript
function resolveCharacterReferenceForChapter(
  character: ProjectCharacter,
  chapterId: string,
): string | null {
  // 1. 查询该章节对应的阶段（按 stageOrder 倒序，优先最新阶段）
  const stage = character.stages
    ?.sort((a, b) => b.stageOrder - a.stageOrder)
    .find(s => {
      // 如果没有设置 fromChapterId，则只有第一个阶段（stageOrder=1）适用所有章节
      if (!s.fromChapterId) return s.stageOrder === 1;
      
      // 如果设置了 fromChapterId，检查章节是否在范围内
      const fromMatch = s.fromChapterId <= chapterId;
      const toMatch = !s.toChapterId || s.toChapterId >= chapterId;
      return fromMatch && toMatch;
    });
  
  // 2. 优先使用阶段图
  if (stage?.finalAssetId) return stage.finalAssetId;
  if (stage?.previewAssetId) return stage.previewAssetId;
  
  // 3. 其次使用锚点图
  if (character.anchorAssetId) return character.anchorAssetId;
  
  // 4. 最后使用现有的 primary/preview
  if (character.primaryReferenceAssetId) return character.primaryReferenceAssetId;
  if (character.previewReferenceAssetId) return character.previewReferenceAssetId;
  
  return null;
}
```

## 4. 兼容性设计

### 4.1 旧数据兼容

**场景 1：旧角色没有 anchorAssetId**
- 读取时检查 `anchorAssetId` 是否为 null
- 如果为 null，降级使用 `previewReferenceAssetId` 或 `primaryReferenceAssetId`
- 不影响现有功能

**场景 2：旧角色没有阶段**
- `character.stages` 为空数组
- 阶段选择逻辑自动跳过，直接使用锚点图或 primary/preview 图
- 不影响现有功能

**场景 3：旧项目升级**
- migration 0018 只增加表和字段，不修改现有数据
- 旧项目加载后，角色库显示"待定妆"（如果是 lead/recurring）
- 用户可以选择性定妆，不强制

### 4.2 降级策略

**降级 1：editImage 失败**
- 阶段图生成失败 → 返回错误，不创建阶段记录
- 用户可以重试或使用上一阶段图

**降级 2：没有参考图**
- `resolveCharacterReferenceForChapter` 返回 null
- 生图时完全依赖文字描述（现有逻辑）

**降级 3：定妆失败**
- 生成候选失败 → 返回错误，用户可以重试
- 用户跳过定妆 → 系统使用文字描述生成（现有逻辑）

## 8. 风险与对策

### 8.1 技术风险

**风险 1：editImage 质量不稳定**
- **现象**：垫图换装可能导致脸部变形
- **对策**：提供"重新生成"按钮，支持多次抽卡

**风险 2：定妆候选相似度高**
- **现象**：生成的 3 张图可能很相似
- **对策**：使用不同的 seed 确保多样性

### 8.2 产品风险

**风险 1：用户跳过定妆**
- **现象**：用户不定妆就直接生图，质量还是不好
- **对策**：首次生成时智能提醒（可跳过但会提示）

**风险 2：阶段管理复杂**
- **现象**：2574 章项目可能有几十个阶段
- **对策**：阶段列表分页显示，提供搜索/筛选功能
