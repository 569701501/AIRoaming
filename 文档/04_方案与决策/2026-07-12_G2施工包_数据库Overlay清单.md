# G2 施工包：数据库 Overlay 清单

## 1. 唯一目标

在 G1 0001～0008 基线上追加一个向前兼容 migration，补齐 G2 的 active pending、CAS、V2 runtime、current source、Shot retire 和任务 gate 数据库防线。B1 实现前同步收紧了一处已有 Working Copy 本地 CHECK：允许“已有 current Script、Working Copy 被清空、状态 dirty”的合法组合；这不是新增列或新增 G2 CHECK，但会更新 0008 的正式 checksum 与 manifest。

本文冻结数据库施工对象。实现者不得自行增删对象；发现本文无法表达的约束时，先更新本文，不得在 migration 中暗加规则。

## 2. Migration 身份

```text
apps/server/prisma/migrations/0009_g2_version_freshness_overlay/migration.sql
```

固定属性：

| 项 | 值 |
| --- | --- |
| migration name | `0009_g2_version_freshness_overlay` |
| 前置 | 0001～0008 全部成功且 checksum 正确 |
| 新表 | 0 |
| 删除表 | 0 |
| 新列/删除列 | 0 |
| table rebuild | 0 |
| 新 G2 CHECK | 0（仅同步既有 `ck_chapters_working_consistency` 的合法形状） |
| 新 index | 2 个 partial unique index |
| 新 trigger | 14 |
| 数据回填 | 仅 preflight 扫描断言，不改业务行 |

Freshness 是查询派生状态，不新增 `stale/freshness` 列，也不通过 CHECK 存储派生结果。原 `g1-schema-constraint-source.ts` 的 G2 `addChecks` 概念占位在实施时改为空数组；语义约束由本文 index/trigger 和应用 Resolver 共同承担。唯一的 G1 兼容调整是允许 current Script 存在时的空 Working Copy dirty 形状，以满足 clear/revert 契约。

## 3. Migration 前置扫描

DDL 前创建迁移内 guard table `_g2_overlay_preflight_guard`，并为下表六个 code 创建只在 migration transaction 内存在的 guard trigger。每个 `INSERT ... SELECT '<code>' WHERE EXISTS(...)` 命中时，由对应 guard trigger 执行静态 `RAISE(ABORT, 'AIR_G2:preflight_<code>')`。六项均通过后 DROP guard trigger/table，再创建正式对象。guard 对象不是最终 Schema 对象，不计入 14 个正式 trigger；任一失败时整个 migration transaction 回滚。

| code | 查询条件 |
| --- | --- |
| `story_multiple_active_pending` | 同 chapter 的 `story_versions.status='pending_confirmation'` 数量 > 1 |
| `board_multiple_active_pending` | 同 chapter 的 `storyboard_versions.status='pending_confirmation'` 数量 > 1 |
| `story_pending_pointer_mismatch` | pending Story 行未被同章 `Chapter.pending_story_version_id` 唯一指向 |
| `board_pending_pointer_mismatch` | pending Board 行未被同章 `Chapter.pending_storyboard_version_id` 唯一指向 |
| `script_working_shape_invalid` | Chapter working state 不满足第 5.1 节形状 |
| `nonlegacy_v1_pending` | active pending 的 origin 不是 `legacy_import` 且 schemaVersion 不是 2 |

`nonlegacy_v1_pending` 不自动重编码。上线 0009 前必须运行应用层 dry-run codec；能无损转换的先显式转换，不能转换的创建 MigrationIssue 并停止 migration。

## 4. 新 Index

### 4.1 Story active pending

```sql
CREATE UNIQUE INDEX "uq_g2_story_versions_active_pending_chapter"
ON "story_versions" ("chapter_id")
WHERE "status" = 'pending_confirmation';
```

### 4.2 Storyboard active pending

```sql
CREATE UNIQUE INDEX "uq_g2_storyboard_versions_active_pending_chapter"
ON "storyboard_versions" ("chapter_id")
WHERE "status" = 'pending_confirmation';
```

两个 index 表达“每章每层最多一个 active pending”。版本历史仍由现有 `(chapter_id, version)` 唯一约束保证。

## 5. 新 Trigger Manifest

所有 trigger 的错误格式固定：

```text
AIR_G2:<trigger_name>
```

机械 manifest 固定如下；`updateColumns=[]` 表示普通 `UPDATE`，不是省略定义：

| name | table | timing/event | updateColumns | WHEN |
| --- | --- | --- | --- | --- |
| `trg_g2_chapters_script_working_shape_insert` | chapters | BEFORE INSERT | — | `1` |
| `trg_g2_chapters_script_working_shape_update` | chapters | BEFORE UPDATE | `script_working_text,script_working_digest,script_working_state,current_script_version_id` | 任一列 `IS NOT OLD` |
| `trg_g2_chapters_command_row_version_update` | chapters | BEFORE UPDATE | 本节 5.2 的 12 个字段 | 任一字段 `IS NOT OLD` |
| `trg_g2_chapters_current_source_update` | chapters | BEFORE UPDATE | `current_story_version_id,current_storyboard_version_id,current_preflight_revision_id` | 任一指针 `IS NOT OLD` |
| `trg_g2_story_versions_pending_v2_insert` | story_versions | BEFORE INSERT | — | `NEW.status='pending_confirmation'` |
| `trg_g2_story_versions_pending_update` | story_versions | BEFORE UPDATE | `[]` | `OLD.status='pending_confirmation'` |
| `trg_g2_story_versions_confirm_source_update` | story_versions | BEFORE UPDATE | `status` | `OLD.status='pending_confirmation' AND NEW.status='confirmed'` |
| `trg_g2_storyboard_versions_pending_v2_insert` | storyboard_versions | BEFORE INSERT | — | `NEW.status='pending_confirmation'` |
| `trg_g2_storyboard_versions_pending_update` | storyboard_versions | BEFORE UPDATE | `[]` | `OLD.status='pending_confirmation'` |
| `trg_g2_storyboard_versions_confirm_source_update` | storyboard_versions | BEFORE UPDATE | `status` | `OLD.status='pending_confirmation' AND NEW.status='confirmed'` |
| `trg_g2_shots_retired_monotonic_update` | shots | BEFORE UPDATE | `lifecycle_status,retired_at` | 任一列 `IS NOT OLD` |
| `trg_g2_preflight_revisions_v2_current_insert` | preflight_revisions | BEFORE INSERT | — | `1` |
| `trg_g2_generation_tasks_new_work_gate_seal` | generation_tasks | BEFORE UPDATE | `source_set_sealed_at` | `OLD.source_set_sealed_at IS NULL AND NEW.source_set_sealed_at IS NOT NULL AND NEW.record_kind='runtime' AND NEW.type IN (...)` |
| `trg_g2_generation_tasks_applicability_terminal` | generation_tasks | BEFORE UPDATE | `status,applicability` | `OLD.status='running' AND NEW.status='succeeded' AND NEW.type IN (...)` |

每个 trigger body 只能包含本节对应小节列出的拒绝谓词和 `SELECT RAISE(ABORT, ...)`；不得在 BEFORE trigger 中静默修正 NEW 值，也不得由 trigger 自动切 current 指针。

### 5.1 Chapter Working Copy 形状

新增：

```text
trg_g2_chapters_script_working_shape_insert
trg_g2_chapters_script_working_shape_update
```

两者使用同一谓词：

```text
digest matches ^sha256:[0-9a-f]{64}$
AND exactly one branch is true:

empty:
  script_working_state = 'empty'
  script_working_text = ''
  current_script_version_id IS NULL

clean:
  script_working_state = 'clean'
  current_script_version_id IS NOT NULL
  script_working_text <> ''
  script_working_digest = current ChapterScriptVersion.source_digest

dirty:
  script_working_state = 'dirty'
  AND (
    (current_script_version_id IS NULL AND script_working_text <> '')
    OR
    (current_script_version_id IS NOT NULL
      AND script_working_digest <> current ChapterScriptVersion.source_digest)
  )
```

已有正式版本时清空 Working Copy 属于 `dirty`，不属于 `empty`。

### 5.2 Chapter G2 command rowVersion

新增：

```text
trg_g2_chapters_command_row_version_update
```

`BEFORE UPDATE ON chapters`，当下列任一字段变化时，强制 `NEW.row_version = OLD.row_version + 1`：

```text
title, summary, milestone_status,
script_working_text, script_working_digest, script_working_state,
current_script_version_id,
current_story_version_id, pending_story_version_id,
current_storyboard_version_id, pending_storyboard_version_id,
current_preflight_revision_id
```

仅更新 `updated_at` 不触发；G2 command 不得一次跳过多个 rowVersion。应用写入仍必须使用 `WHERE id=? AND row_version=?`，trigger 只是最后防线，不能替代 CAS。

### 5.3 Chapter current source 指针

新增：

```text
trg_g2_chapters_current_source_update
```

仅校验发生变化的 current 指针，允许新上游发布后未变化的旧下游自然变 stale：

| 变化字段 | 必须满足 |
| --- | --- |
| `current_story_version_id` | 新 Story confirmed；`source_script_version_id = NEW.current_script_version_id`；Script working=`clean` |
| `current_storyboard_version_id` | 新 Board confirmed；`source_story_version_id = NEW.current_story_version_id`；当前 Story 来源等于当前 Script；Script working=`clean`；`pending_story_version_id IS NULL` |
| `current_preflight_revision_id` | 新 Preflight confirmed+ready；source Board 等于 current Board；Board/Story/Script 链 current；Script working=`clean`；Story/Board pending 均为空 |

### 5.4 Story V2 pending 插入

新增：

```text
trg_g2_story_versions_pending_v2_insert
```

`BEFORE INSERT`：

- `origin <> 'legacy_import'` 时强制 `schema_version=2` 且 `document_json.schemaVersion=2`。
- `origin='legacy_import'` 可保留 V1，但只能由 maintenance importer 调用，普通 runtime codec 不暴露该 origin。
- source ID/policy/digest 在 pending 创建时冻结，不允许空。

### 5.5 Story pending 更新与 formalize

新增：

```text
trg_g2_story_versions_pending_update
```

`BEFORE UPDATE WHEN OLD.status='pending_confirmation'`：

1. 必须存在同章 Chapter 且 `pending_story_version_id=OLD.id`。
2. `NEW.row_version=OLD.row_version+1`。
3. 永久不可变：`id/project_id/chapter_id/version/source_script_version_id/source_policy_version/source_digest/origin/created_at`。
4. `status` 只能保持 pending，或变为 `confirmed/archived`。
5. 保持 pending 时，只允许 `document_json/schema_version/document_digest/updated_at/row_version` 变化，且 runtime 仍为 V2。
6. formalize 时 document/source 不得与 OLD 同时变化；confirmed/archived 时间形状继续由 G1 trigger 校验。
7. 非 legacy 的 V1 pending 不允许 confirmed，返回 `VERSION_CODEC_UPGRADE_REQUIRED` 映射。

### 5.6 Story confirm current source

新增：

```text
trg_g2_story_versions_confirm_source_update
```

`BEFORE UPDATE WHEN OLD.status='pending_confirmation' AND NEW.status='confirmed'`，要求：

```text
Chapter.pending_story_version_id = OLD.id
Chapter.current_script_version_id = NEW.source_script_version_id
Chapter.script_working_state = 'clean'
NOT EXISTS ChapterScriptPending for this Chapter
NEW.source_digest = SourceSnapshotBuilder(story-v1) 的已冻结 digest
```

SQLite 不重新计算 JCS；最后一项由应用 transaction 重新构建并逐值比较，trigger 负责可由关系证明的 current ID/shape。

### 5.7 Storyboard V2 pending 插入

新增：

```text
trg_g2_storyboard_versions_pending_v2_insert
```

规则与 Story 对称：非 `legacy_import` 必须 V2；source Story ID/policy/digest 创建时冻结且非空。

### 5.8 Storyboard pending 更新与 formalize

新增：

```text
trg_g2_storyboard_versions_pending_update
```

规则与 Story 对称，active pointer 为 `Chapter.pending_storyboard_version_id`，source 字段为 Story source。projection 必须在 parent 仍 pending 时重建；G1 parent-formal trigger 继续阻止 confirmed 后修改 projection。

### 5.9 Storyboard confirm current source

新增：

```text
trg_g2_storyboard_versions_confirm_source_update
```

要求：

```text
Chapter.pending_storyboard_version_id = OLD.id
Chapter.pending_story_version_id IS NULL
Chapter.script_working_state = 'clean'
NOT EXISTS ChapterScriptPending for this Chapter
Chapter.current_story_version_id = NEW.source_story_version_id
current Story.source_script_version_id = Chapter.current_script_version_id
```

### 5.10 Shot retire 单向性

新增：

```text
trg_g2_shots_retired_monotonic_update
```

规则：

- `retired -> active` 永远拒绝。
- OLD 为 retired 后，`retired_at` 不可修改或清空。
- active Shot 仅可在 Storyboard confirm 事务中变 retired；应用必须基于新 current projection 的差集执行。
- 重新出现的镜头必须创建新 stable Shot ID，不能复活旧 ID。

### 5.11 Preflight V2/current source 插入

新增：

```text
trg_g2_preflight_revisions_v2_current_insert
```

`BEFORE INSERT` 要求：

```text
schema_version = 2
status = 'confirmed'
ready = 1
source_storyboard_version_id = Chapter.current_storyboard_version_id
Chapter.pending_story_version_id IS NULL
Chapter.pending_storyboard_version_id IS NULL
Chapter.script_working_state = 'clean'
NOT EXISTS ChapterScriptPending for this Chapter
current Board.source_story_version_id = current Story.id
current Story.source_script_version_id = current Script.id
document_json.sourceSnapshot 与 source_policy_version/source_digest 同 codec
```

完整角色/场景/风格 Asset 摘要由应用事务内逐项复核；G1 scope trigger 继续验证 JSON 基础形状。

### 5.12 Task NewWorkGate seal

新增：

```text
trg_g2_generation_tasks_new_work_gate_seal
```

`BEFORE UPDATE OF source_set_sealed_at`，仅在 `NULL -> non-NULL`、`record_kind='runtime'` 且任务属于下表时运行：

| type | DB 可机械证明的条件 |
| --- | --- |
| `story_parse` | routing target=Chapter；active pending Story=`input.expectedTargetId`；pending rowVersion=`expectedTargetRowVersion`；Script clean/current；无 `ChapterScriptPending`；唯一 script source 指向 current Script |
| `shot_generate` | routing target=Chapter；active pending Board 与 rowVersion 匹配；无 Script pending/Story pending；Script clean；current Story 来源 current Script；唯一 story source指向 current Story |
| `shot_prompt_generate` | target Shot active 且属于 current Board projection；无 Script/Story/Board pending；Script→Story→Board→Preflight current；source set 含精确 Board/Shot/Preflight |
| `image_generate` | 与 shot_prompt 相同；另外 `generationSpecDigest/requestId` strict input 已冻结 |

G1 `trg_generation_tasks_source_set_seal` 继续负责 sourceProjection 与 `GenerationTaskSource` 逐项相等、source row digest 和排序；G2 不复制该长 trigger。

### 5.13 Task terminal applicability

新增：

```text
trg_g2_generation_tasks_applicability_terminal
```

`BEFORE UPDATE`，当 G2 任务 `running -> succeeded`：

- `applicability` 必须为 `current` 或 `historical`。
- `current` 时 claimToken 对应未结束 Attempt，active pending target 仍等于冻结 expectedTargetId，写目标已从 `expectedTargetRowVersion` 恰好递增 1，current source ID/sourceDigest 仍相等。
- `historical` 时不得更新 current/pending 的业务保证由同一 Repository transaction、条件 UPDATE 行数和集成测试证明；SQLite 无 session context，不能用 trigger 准确判断某行更新由哪个 task 发起，因此本文不伪造一个不可靠的 SQL 证明。

## 6. 版本分配算法

Story/Storyboard/Preflight/Script 统一：

1. 在事务内读取 `MAX(version)`，分配 `next=max+1`。
2. INSERT 依赖现有 `(chapter_id,version)` unique。
3. 遇到 `SQLITE_BUSY` 或该 unique 冲突，整个事务回滚并最多重试 3 次，退避 `[10ms,30ms,90ms]`。
4. 每次重试必须重新校验 expected current/rowVersion；expected 已失效立即返回 409，不继续分配。
5. 已分配但事务回滚的数字可以再次使用；已提交的版本号永不复用。

不得在内存保存 nextVersion，不新增 version counter 表。

## 7. 错误映射

| SQLite/Prisma 证据 | HTTP/code |
| --- | --- |
| 两个 partial unique index 冲突 | `409 ACTIVE_PENDING_EXISTS` |
| `trg_g2_*_pending_update` 或条件 UPDATE=0 | `409 PENDING_VERSION_CONFLICT` |
| Chapter 条件 UPDATE=0 | `409 CHAPTER_VERSION_CONFLICT` |
| V2 trigger | `409 VERSION_CODEC_UPGRADE_REQUIRED` 或新 payload `400 VERSION_DOCUMENT_INVALID` |
| current source/confirm trigger | `409 UPSTREAM_SOURCE_STALE` |
| NewWorkGate seal trigger | `409 UPSTREAM_WORK_NOT_CONFIRMED`，details 带 Resolver reasonCodes |
| Shot retired trigger | `409 SHOT_ID_RETIRED` |
| preflight trigger | `409 PREFLIGHT_SOURCE_CHANGED` 或 `422 SOURCE_UNRESOLVED` |
| 未识别 `AIR_G2:*` | `500 G2_DATABASE_CONTRACT_VIOLATION`，不得原样返回 SQL |

## 8. Runtime Ledger 与直接验证

实施时新增：

```text
G2_RUNTIME_MIGRATION_NAMES = [...G1_RUNTIME_MIGRATION_NAMES, '0009_g2_version_freshness_overlay']
```

DB mode 在 G2 capability 开启时必须验证 9 段 migration；只存在 0001～0008 时返回：

```text
DB_PERSISTENCE_MIGRATION_LEDGER_MISSING:0009_g2_version_freshness_overlay
```

G1 仍保持“8 migrations/195 CHECK/194 triggers”的结构计数；0008 的 Working Copy CHECK 语义变更必须同步 `g1-schema-check-dsl.ts`、manifest 和 migration artifact checksum，不能只手改 SQL。另建轻量 `g2-overlay-contract`，只校验本文 2 index、14 trigger、normalized SQL 与 migration checksum；不新增 reviewer、签名、bundle 或 CLI 流水线。

## 9. 回滚

- 0009 上线前：恢复协调备份即可。
- 0009 已上线但无 G2 业务写：可恢复 0009 前完整 DB 备份；不写 down migration。
- 已有 G2 业务写：只能运行理解多版本/pending 的兼容应用，或恢复完整 DB+Asset 协调备份。
- 禁止 DROP trigger/index 后继续用旧客户端写库。
