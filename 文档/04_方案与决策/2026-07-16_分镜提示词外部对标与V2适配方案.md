# 分镜提示词外部对标与 V2 适配方案

## 1. 结论先行

不建议导入或替换成任何一个网上热门分镜 Prompt。

AI漫游当前分镜 Prompt 的核心优势已经成立：它不是从一句故事简介直接生成“漂亮镜头”，而是把已确认 `StoryStructure` 拆成有 `beatId / sceneId / characterIds` 引用、可编辑、可确认、可追溯的 `Shot[]`。现有字段、页面和“生成 pending → 用户确认 → 正式 StoryboardVersion”流程都应保持不变。

外部来源最值得吸收的不是固定 15 秒、黄金三秒、九宫格或电影术语堆叠，而是五种方法：

1. 每个镜头先有明确叙事用途，再决定景别和机位。
2. 按 beat 复杂度分配镜头，不再只用“每个 beat 1～2 镜”泛化处理。
3. 相邻镜头使用进入状态、可见变化、退出状态检查动作、站位、视线和道具连续性。
4. 把角色、场景、画风和版式作为稳定锚点，不在每一镜自由改写。
5. 确定性质量门先拦截格式和引用错误，软评测再判断镜头必要性、连续性、揭示顺序和阅读体验。

推荐形成 `storyboard-shot-generate V2`，但第一版仍然只改 Prompt、定向修复和测试，不新增页面字段、数据库字段、公开 Skill 或用户确认步骤。

## 2. 当前基线不是“提示词太弱”，而是“镜头决策规则不够具体”

### 2.1 已经做对的部分

当前生产 Prompt 已经具备：

- 已确认 `StoryStructure` 是正式拆分事实源，章节正文只作对白和动作参考。
- beat、scene、character 使用结构本地引用，AI 不生成数据库 UUID。
- 一个 Shot 同时有共同核心、`comic` 和 `motion`，两种表达不得改写同一剧情事实。
- 单帧可画、漫画阅读、气泡安全区、视觉变化、结尾钩子强调和 `promptDraft` 污染限制。
- 新生成先成为待确认分镜，用户确认后才形成正式版本。
- 格式错误和固定质量门问题共用一次定向修复，第二次失败不写入 pending。
- 固定门已覆盖 Schema、枚举、顺序、beat 覆盖、beat/scene 一致、空壳、完全重复、对白双表达一致和 `promptDraft` 禁止项。

真实模型证据也说明基线可用：AI 创作样例 12 beats 生成 24 shots 首次通过；导入样例 7 beats 生成 12 shots，在命中空对白画格后经一次定向修复通过。

### 2.2 当前真正的缺口

| 缺口 | 当前表现 | 可能后果 |
| --- | --- | --- |
| 镜头数量规则过宽 | 只给出每个 beat 1～2 镜和总数范围 | 模型容易把所有 beat 都拆到上限，产生重复反应镜头 |
| 镜头用途没有决策顺序 | 只列建立、动作、反应、细节、转场 | 模型知道有哪些类型，但不知道何时必须用、何时不该用 |
| 连续性仍是一句总要求 | 人物、道具、空间、视线和动作结果一起描述 | 模型容易漏掉手持道具、朝向、位置或动作完成状态 |
| 漫画与 motion 的分工还可收紧 | motion 可以补充时间和运镜 | 容易为每一镜都安排运镜，或把多个动作塞进一个动态镜头 |
| 项目版式和画风未明确注入当前 Prompt | 当前只注入项目名、剧集名、结构和正文摘录 | `vertical_scroll / paged_comic` 与项目画风不能参与镜头决策 |
| “黄金钩子”容易被误用 | 外部短视频模板常要求黄金三秒、每段留钩 | 分镜阶段可能擅自创造正文没有的冲突、反转或悬念 |

因此，V2 的主任务不是扩字段，而是把“模型输出前的镜头规划过程”写清楚。

## 4. 热门方法逐项适配

### 4.1 黄金钩子、黄金三秒

结论：不作为分镜阶段的剧情生成规则；只作为已有钩子的视觉强调规则。

适配方式：

- 如果 `StoryStructure.direction.endingHook` 和末尾 beat 已经存在钩子，最后 1～2 个 Shot 应突出“视觉问题、代价、揭示或人物反应”。
- 如果正式结构没有钩子，分镜不得自行添加人物、线索、反转或新对白。
- 开篇是否需要强画面，取决于第一个 beat 的功能；不能为了“黄金三秒”跳过必要的因果和空间信息。

### 4.2 Hook → Build → Payoff、三幕式、CTA

结论：保留“镜头有用途”的思想，拒绝固定营销顺序。

AI漫游已经有项目大纲、章节正文和 StoryStructure。分镜只需要识别当前 beat 是建立、动作、对白、揭示、选择、后果、转场或钩子，再用合适镜头承接；不能重写章节结构，更不应生成 CTA。

### 4.3 固定秒数、时间轴分段

结论：漫画分镜拒绝；motion 只借鉴“一个时间段完成一个清楚动作”。

- `comic` 不按 3 秒、5 秒或 15 秒分格。
- `motion.durationMs` 根据这一镜可见变化、台词和停顿决定，不按外部平台固定 cadence。
- 一个 motion 默认只有一个主体动作和一个主要运镜；静态或 `none` 是合法选择。

### 4.4 角色、场景、道具参考锚点

结论：采用，但使用项目现有结构引用，不新建素材槽字段。

- 角色继续使用 `characterIds`，视觉描述以角色卡 `visualTraits` 和正式角色资产为准。
- 场景继续使用 `sceneId`，地点、时间和氛围以场景卡为准。
- 道具没有正式 ID 时，只能保留正文和 beat 中已出现的可见事实，不能由 Prompt 自造资产编号。
- `promptDraft` 不重复粘贴整份角色设定，只保留当前镜头识别所需的稳定特征。

### 4.5 尾帧到首帧、相邻关键帧连续

结论：重点采用，并从视频“尾帧”改写为适合漫画的“状态接力”。

每个 Shot 在模型内部检查：

```text
进入状态
→ 本镜可见变化
→ 退出状态
→ 下一镜从该退出状态继续
```

连续性账本至少包含：人物位置和朝向、视线、手持道具、道具状态、服装/伤势、时间/天气/光线、上一动作是否已经完成。账本只用于内部规划和自检，不新增输出字段。

### 4.6 全局视觉主题

结论：采用已有项目事实，不复制营销视频里的色板、镜头和胶片字段。

- 把现有 `project.comicFormat` 和 `project.artStyle` 注入 Prompt。
- `comicFormat` 只影响阅读节奏和构图倾向，不在分镜阶段决定最终格子尺寸和整页排版。
- `artStyle` 只约束镜头描述不要偏离项目画风；最终 provider 风格词仍由下游图片 Prompt 编译器负责。

## 5. V2 Prompt 模块设计

### 模块 1：角色与事实源契约——保留

保留当前 Skill 名、正式结构来源、版本边界、本地引用、禁止新增剧情和只输出完整 JSON 的规则。

### 模块 2：项目视觉上下文——增强

新增注入现有事实：

```text
漫画版式：vertical_scroll / paged_comic
项目画风：现有 project.artStyle
```

不新增页面字段，也不把版式改成固定视频宽高比。

### 模块 3：beat 覆盖计划——新增内部步骤

模型先在内部为每个 beat 确定：

1. 叙事功能：建立 / 动作 / 对白 / 揭示 / 选择 / 后果 / 转场 / 钩子。
2. 必须被看到的事实：人物、动作、物件、信息或状态变化。
3. 一个主镜是否足够。
4. 是否满足增加辅助镜头的条件。

该过程不输出、不新增字段，也不要求模型展示思维链。

### 模块 4：复杂度镜头预算——替换泛化数量规则

每个 beat 先分配一个主镜。只有满足以下任一条件时，才增加第二镜：

- 同一画格无法同时表现原因和结果。
- 揭示需要“关键物/事实”与“人物反应”分开才能读懂。
- 选择需要“做出选择”与“立即代价/后果”分开。
- 对白改变关系或信息，听者反应会改变台词含义。
- 动作跨越明确空间，缺少一镜会造成位置或方向断裂。

不得只为了景别变化、平均分配枚举或增加画面数量而拆第二镜。总量仍不得超过每个 beat 两镜，但建议值改成：

```text
beat 数量 + 真正复杂 beat 数量
```

### 模块 5：漫画镜头模式——增强

| beat 功能 | 推荐处理 | 禁止机械处理 |
| --- | --- | --- |
| 建立 | 只有理解空间、人物关系或危险来源需要时才用建立镜头 | 每个场景都先来一个空全景 |
| 动作 | 选择预备、撞击、决定性瞬间或余波中最有叙事价值的一刻 | 一个画格塞连续三四个动作 |
| 对白 | 优先表现说话者目的、听者压力和两人空间关系 | 只做轮流说话头像；长台词完整塞进一格 |
| 揭示 | 关键细节和人物反应按理解需要拆分 | 为制造悬念添加正文没有的线索 |
| 选择 | 让姿态、手势、视线或行动体现选择 | 只写“他意识到/他决定了” |
| 后果 | 显示状态真正改变，供下一镜接力 | 下一镜把人物、道具或伤势重置 |
| 转场 | 使用地点、时间、光线、物件或行动桥接 | 每次都淡入淡出或强制空镜 |
| 钩子 | 末尾保留视觉问题、代价、揭示或反应 | 自造反派、秘密、爆炸或新对白 |

### 模块 6：连续性账本——新增内部步骤

在生成下一 Shot 前，逐项核对：

- 主体位置、朝向与视线。
- 手里或身边的关键道具及其状态。
- 服装、伤势、污渍和情绪余波。
- 同场景的时间、天气、光线和空间关系。
- 上一镜动作完成到哪一步，下一镜不能从更早状态重新开始。

### 模块 7：comic 与 motion 分工——增强

`comic` 先确定静态决定性瞬间和阅读构图；`motion` 再从同一事实投影动态表达：

- 一个主要主体动作。
- 最多一个主要镜头运动；如果运镜没有叙事价值，用 `static / none`。
- 不通过 motion 增加漫画画格里没有的剧情结果。
- 对白、说话人和句意在两种表达中一致。

### 模块 8：promptDraft 编译顺序——增强

继续保持它不是最终图片 Prompt，建议固定为一句简短事实摘要：

```text
主体身份 + 决定性瞬间 + 场景锚点 + 光线/情绪 + 构图重点
```

不加入模型名、艺术家名、画质词、负面 Prompt、版式参数、对白原文、字幕或气泡。

### 模块 9：输出前删除检查——新增

模型在内部逐镜检查：

> 删除这一镜后，如果 beat 事实、因果、情绪转折、空间连续或钩子仍完整，这一镜可能是冗余镜头，应合并或删除。

该规则比“景别必须多样”更重要。视觉变化是手段，不是增加镜头的理由。

## 6. 当前 Prompt 的保留／增强／拒绝矩阵

| 当前模块 | 结论 | V2 动作 |
| --- | --- | --- |
| Skill、动作和 pending/confirm 边界 | 保留 | 不改 |
| StoryStructure 正式事实源 | 保留 | 不改 |
| beat/scene/character 本地引用 | 保留 | 不改 |
| comic + motion 双表达 | 保留并增强 | 先 comic 决定静态瞬间，再投影 motion |
| 每 beat 1～2 Shot | 拆分重写 | 改为一个主镜 + 有条件辅助镜 |
| 单帧可画 | 增强 | 加决定性瞬间和抽象心理外化规则 |
| 连续性 | 增强 | 改成状态接力和连续性账本 |
| 漫画阅读与气泡安全 | 保留并增强 | 对话按说话目的、听者反应和气泡负载决定是否拆镜 |
| 镜头语法 | 增强 | 使用 beat 功能→镜头模式的决策表 |
| 视觉变化 | 降级为软规则 | 不为枚举多样而拆镜 |
| 结尾钩子 | 增强并限权 | 只放大正式结构已有钩子，不创造新钩子 |
| promptDraft | 保留并增强 | 固定事实顺序，继续留给下游编译 |

| 黄金三秒、固定三幕、CTA | 不采用 | 留在特定上游题材或营销视频，不进入通用漫画分镜 |
| 固定 9:16 / 16:9、固定秒数 | 不采用 | 使用现有 comicFormat；motion 时长按内容决定 |
| 8K、胶片、镜头焦段、负面词 | 不采用 | 归下游 provider Prompt，不污染 Storyboard |

## 7. 定向修复 V2

当前一次修复上限正确，建议只增强问题到修复动作的映射：

| 问题组 | 修复范围 |
| --- | --- |
| JSON、字段、枚举、引用 | 只修格式、引用和非法值，不重写镜头内容 |
| beat 缺失或顺序倒退 | 只补缺失 beat 或调整顺序，保留其他镜头含义 |
| 完全重复或空壳 | 合并/改写对应镜头，重新检查是否真的需要辅助镜 |
| 空对白画格或 comic/motion 不一致 | 从正式正文恢复对应对白和说话人，不新写台词 |
| promptDraft 污染 | 只重写 `promptDraft`，不改正式镜头事实 |
| 连续性软问题 | 只调整受影响相邻镜头的动作、位置或状态描述 |

仍然返回完整 `shots`，不返回 patch；第二次失败仍不写 pending。

## 8. 质量门分层

### 8.1 后端确定性硬门——继续保留

- JSON 和必填字段。
- 固定枚举。
- order 连续。
- beat 全覆盖和叙事顺序。
- beat/scene 匹配。
- 合法角色和说话人引用。
- 必填文本非空壳。
- 完全重复镜头。
- 对白在 comic 与 motion 中一致。
- `promptDraft` 禁止项和对白泄漏。

第一版不建议增加“镜头必须多样”“对话最多多少字”“必须有建立镜头”等主观硬门。

### 8.2 模型软评测——新增 P6 测试，不立即阻断生产

建议使用独立 rubric 评价：

1. 每个 Shot 是否提供新的可见信息、动作结果或情绪变化。
2. 关键揭示、选择、代价和钩子是否得到适当视觉强调。
3. 相邻镜头位置、朝向、视线、道具和动作状态是否连续。
4. 对白是否过载，听者反应是否只在有叙事价值时出现。
5. 是否存在无理由的全景、特写、空镜或重复构图。
6. comic 和 motion 是否仍表达同一瞬间。
7. 是否引入正式结构和正文中不存在的事实。
8. 是否适合项目版式和画风，而不是固定视频模板。

模型评分只用于版本 A/B 和回归观察，不写入 Storyboard 核心数据，也不替代用户确认。

### 8.3 用户判断——继续保留

用户最终判断情绪力度、画面审美、阅读节奏和是否符合创作意图。系统不能把审美偏好伪装成确定性事实。

## 9. 固定评测样例

V2 至少使用以下样例与现有 Prompt 做同模型 A/B：

| 样例 | 重点失败模式 |
| --- | --- |
| 双人长对白 | 轮流说话头像、气泡过载、无意义反应镜 |
| 关键道具揭示 | 线索和反应顺序错误、擅自补新线索 |
| 连续动作 | 一格多动作、动作重复开始、朝向跳变 |
| 新场景进入 | 每场强制全景，或缺少必要空间定位 |
| 情绪选择 | 只写抽象心理，不展示可见选择 |
| 章节结尾钩子 | 钩子未强调，或为了强刺激擅自新增剧情 |
| 原稿导入章节 | 为套热门结构而改写或强化原稿 |
| 竖向条漫 / 分页漫画同结构 | 仍机械套 16:9 视频构图，忽略项目版式 |

每次记录：

- 首次硬门通过率。
- 一次修复触发率和修复成功率。
- 平均 Shot/beat 与冗余镜头率。
- 无来源事实或对白数量。
- 连续性问题数量。
- 盲评偏好和主要理由。

## 10. 实施顺序

用户确认本方案后，建议按以下顺序改造：

1. 在现有 Prompt 中注入 `comicFormat` 和 `artStyle`。
2. 用“主镜 + 有条件辅助镜”替换当前泛化数量规则。
3. 增加内部 beat 覆盖计划、镜头用途和漫画镜头模式。
4. 增加连续性账本与结尾钩子限权。
5. 收紧 motion 为单动作、单主要运镜，并明确静态合法。
6. 按问题代码增强一次定向修复。
7. 增加固定样例和独立软 rubric，运行旧版/V2 A/B。
8. 只有 A/B 证明持续改善后，才把 V2 设为生产默认。

## 11. 最终推荐

采用“保留现有骨架、补镜头决策层”的 V2：

- 不导入外部完整 Skill。
- 不新增 Storyboard 字段。
- 不改页面展示和确认流程。
- 不把黄金三秒、固定时长、9:16、CTA 或九宫格变成通用规则。
- 重点补 beat 复杂度、镜头用途、状态接力、角色/场景锚点和软评测。
- 先做 Prompt 与测试改造，再用同模型 A/B 决定是否上线。

这比继续堆电影术语更能解决真实问题，也不会破坏已经验证通过的双路线、版本链和下游图片 Prompt 编译。
