# 分镜提示词外部对标与 V2 适配方案

## 1. 结论先行

不建议导入或替换成任何一个网上热门分镜 Prompt。

AI漫游当前分镜 Prompt 的核心优势已经成立：它不是从一句故事简介直接生成“漂亮镜头”，而是把已确认 `StoryStructure` 拆成有 `beatId / sceneId / characterIds` 引用、可编辑、可确认、可追溯的 `Shot[]`。现有字段、页面和“生成 pending → 用户确认 → 正式 StoryboardVersion”流程都应保持不变。

外部来源最值得吸收的不是固定 15 秒、黄金三秒、九宫格或电影术语堆叠，而是六种方法：

1. 每个镜头先有明确叙事用途，再决定景别和机位。
2. 按 beat 复杂度分配镜头，不再只用“每个 beat 1～2 镜”泛化处理。
3. 相邻镜头使用进入状态、可见变化、退出状态检查动作、站位、视线和道具连续性。
4. 把角色、场景、画风和版式作为稳定锚点，不在每一镜自由改写。
5. 确定性质量门先拦截格式和引用错误，软评测再判断镜头必要性、连续性、揭示顺序和阅读体验。
6. 漫画分镜和漫剧分镜分别使用适合自身媒介的创作规则，只共享正式剧情事实，不能把漫剧当成漫画画格的动态附属层。

推荐形成 `storyboard-shot-generate V2`，但第一版仍然只改 Prompt、定向修复和测试，不新增页面字段、数据库字段、公开 Skill 或用户确认步骤。

### 1.2 生产实施状态（2026-07-16）

V2 已进入当前服务端生产 Prompt，实施范围严格限定为：

- `buildStoryboardPrompt` 按共享剧情事实、漫画分镜、漫剧分镜、双轨边界依次组合。
- `buildStoryboardRepairPrompt` 分别修复漫画静态画格与漫剧时间过程。
- 注入现有 `comicFormat` 和 `artStyle`，不新增页面或存储字段。
- 保留现有 `Shot[]`、`comic / motion`、正式枚举、待确认与用户确认流程。
- 固定测试允许两条轨道使用不同画面文案和媒介表达，只要求正式剧情事实不冲突。

本次自动化、类型检查和构建已通过。2026-07-16 又完成了 AI 创作与已有剧本导入各一个新项目的 V1/V2 真实文本模型 A/B，正式判定为 `MIXED`，方向性结论为 `V2_DIRECTIONALLY_BETTER`：

- 两条路线的 V2 都明显改善了漫剧镜头的开始、变化、结束状态和内容时长，漫画画格仍保持静态可画，正式事实和导入原稿对白没有退化。
- AI 创作 V2 首次输出触发一次对白双轨不一致，定向修复后通过；V1 首次通过。
- V2 共享镜头数约减少 29%，漫画未丢 beat，但少数 7～10 秒动态镜头承载的动作和对白偏多。

因此当前不回退 V1，继续保留 V2 方向；但也不把两样例表述成“V2 已全面验收”。下一轮应先增加动态镜头负载上限与必要拆镜规则，再补多题材重复样例。完整证据见 `../05_执行与记录/任务记录/2026-07-16_双轨分镜Prompt真实AB/evidence/ab-review.md`。

### 1.1 本方案冻结的双轨边界

本项目中的“漫画分镜”和“漫剧分镜”是两种并列的媒介表达，不是“先生成漫画，再把漫画动起来”的上下级关系。

| 层级 | 两条轨道共同遵守 | 漫画分镜独立决定 | 漫剧分镜独立决定 |
| --- | --- | --- | --- |
| 剧情事实 | beat、scene、characters、核心事件、因果结果、对白来源、不得新增剧情 | — | — |
| 镜头设计 | 不能互相矛盾，必须能追溯到同一正式结构 | 静态决定性瞬间、画格构图、阅读顺序、气泡/旁白、格间节奏 | 时间过程、人物表演、镜头运动、时长、配音、动态镜头衔接 |
| 当前 M1 存储 | 一个 `Shot` 共同携带 `comic` 和 `motion` | 填写 `comic` 字段 | 填写 `motion` 字段 |
| 当前限制 | order、beat/scene/character、shotType、cameraAngle 和镜头数量仍共用 | 不能独立增加漫画画格 | 不能独立增加漫剧镜头 |

因此，当前实现是“**内容字段双轨、镜头骨架共用**”。V2 先把两套 Prompt 规则真正分开，为以后独立的漫画分镜序列和漫剧分镜序列留出边界；本轮不为了长期形态提前改页面或 Schema。

## 2. 当前基线不是“提示词太弱”，而是“镜头决策规则不够具体”

### 2.1 已经做对的部分

当前生产 Prompt 已经具备：

- 已确认 `StoryStructure` 是正式拆分事实源，章节正文只作对白和动作参考。
- beat、scene、character 使用结构本地引用，AI 不生成数据库 UUID。
- 一个 Shot 同时有共同核心、`comic` 和 `motion`；内容字段已经分开，但顺序、结构引用、景别、机位和镜头数量仍共用。
- 单帧可画、漫画阅读、气泡安全区、视觉变化、结尾钩子强调和 `promptDraft` 污染限制。
- 新生成先成为待确认分镜，用户确认后才形成正式版本。
- 格式错误和固定质量门问题共用一次定向修复，第二次失败不写入 pending。
- 固定门已覆盖 Schema、枚举、顺序、beat 覆盖、beat/scene 一致、空壳、完全重复、对白双表达一致和 `promptDraft` 禁止项。

真实模型证据也说明基线可用：AI 创作样例 12 beats 生成 24 shots 首次通过；导入样例 7 beats 生成 12 shots，在命中空对白画格后经一次定向修复通过。

### 2.2 当前真正的缺口

| 缺口 | 当前表现 | 可能后果 |
| --- | --- | --- |
| 镜头数量规则过宽 | 只给出每个 beat 1～2 镜和总数范围 | 模型容易把所有 beat 都拆到上限，产生重复反应镜头 |
| 镜头用途没有决策顺序 | 只列建立、动作、反应、细节、转场 | 模型知道有哪些类型，但不知道何时必须用、何时不该用 |
| 连续性仍是一句总要求 | 人物、道具、空间、视线和动作结果一起描述 | 模型容易漏掉手持道具、朝向、位置或动作完成状态 |
| 漫画和漫剧仍被写成主从关系 | 当前规则要求 `motion` 只补充漫画画格的时间和运镜 | 漫剧会退化成漫画的动态说明，无法形成独立的表演、时间和镜头衔接设计 |
| 项目版式和画风未明确注入当前 Prompt | 当前只注入项目名、剧集名、结构和正文摘录 | `vertical_scroll / paged_comic` 与项目画风不能参与镜头决策 |
| “黄金钩子”容易被误用 | 外部短视频模板常要求黄金三秒、每段留钩 | 分镜阶段可能擅自创造正文没有的冲突、反转或悬念 |

因此，V2 的主任务不是扩字段，而是把“模型输出前的镜头规划过程”写清楚。

## 4. 热门方法逐项适配

### 4.1 黄金钩子、黄金三秒

结论：不作为分镜阶段的剧情生成规则；只作为已有钩子的视觉强调规则。

适配方式：

- 如果 `StoryStructure.direction.endingHook` 和末尾 beat 已经存在钩子，最后 1～2 个 Shot 应突出“视觉问题、代价、揭示或人物反应”。
- 如果正式结构没有钩子，分镜不得自行添加人物、线索、反转或新对白。
- 开篇是否需要强画面，取决于第一个 beat 的功能；不能为了“黄金三秒”跳过必要的因果和空间信息。

### 4.2 Hook → Build → Payoff、三幕式、CTA

结论：保留“镜头有用途”的思想，拒绝固定营销顺序。

AI漫游已经有项目大纲、章节正文和 StoryStructure。分镜只需要识别当前 beat 是建立、动作、对白、揭示、选择、后果、转场或钩子，再用合适镜头承接；不能重写章节结构，更不应生成 CTA。

### 4.3 固定秒数、时间轴分段

结论：漫画分镜不使用秒级切镜；漫剧分镜独立使用时间轴规则，但不照搬外部平台的固定总时长和等距分段。

- `comic` 不按 3 秒、5 秒或 15 秒分格。
- `motion.durationMs` 根据动作展开、人物表演、台词、反应和停顿决定，不按外部平台固定 cadence。
- 一个漫剧镜头默认聚焦一个主要动作或一次清楚的情绪/信息变化；需要复合调度时应明确开始、发展和结束状态。
- 运镜必须服务揭示、关系、空间或情绪，静态或 `none` 仍是合法选择。

### 4.4 角色、场景、道具参考锚点

结论：采用，但使用项目现有结构引用，不新建素材槽字段。

- 角色继续使用 `characterIds`，视觉描述以角色卡 `visualTraits` 和正式角色资产为准。
- 场景继续使用 `sceneId`，地点、时间和氛围以场景卡为准。
- 道具没有正式 ID 时，只能保留正文和 beat 中已出现的可见事实，不能由 Prompt 自造资产编号。
- `promptDraft` 不重复粘贴整份角色设定，只保留当前镜头识别所需的稳定特征。

### 4.5 尾帧到首帧、相邻关键帧连续

结论：两条轨道都采用连续性，但使用不同检查方法。

漫画分镜检查相邻画格的阅读接力：

```text
进入状态
→ 本镜可见变化
→ 退出状态
→ 下一镜从该退出状态继续
```

漫剧分镜检查相邻动态镜头的尾帧到首帧接力：上一镜动作结束到哪里、人物朝向和运动方向、关键道具状态、下一镜从哪个状态开始、运镜是否造成空间跳变。

两套账本都至少包含人物位置和朝向、视线、手持道具、道具状态、服装/伤势、时间/天气/光线，但不能用同一条笼统规则代替各自的媒介检查。账本只用于内部规划和自检，不新增输出字段。

### 4.6 全局视觉主题

结论：采用已有项目事实，不复制营销视频里的色板、镜头和胶片字段。

- 把现有 `project.comicFormat` 和 `project.artStyle` 注入 Prompt。
- `comicFormat` 只影响阅读节奏和构图倾向，不在分镜阶段决定最终格子尺寸和整页排版。
- `artStyle` 只约束镜头描述不要偏离项目画风；最终 provider 风格词仍由下游图片 Prompt 编译器负责。

## 5. V2 Prompt 模块设计

### 模块 1：角色与事实源契约——保留

保留当前 Skill 名、正式结构来源、版本边界、本地引用、禁止新增剧情和只输出完整 JSON 的规则。

### 模块 2：项目视觉上下文——增强

新增注入现有事实：

```text
漫画版式：vertical_scroll / paged_comic
项目画风：现有 project.artStyle
```

不新增页面字段，也不把版式改成固定视频宽高比。

### 模块 3：共享剧情锚点计划——新增内部步骤

模型先在内部为每个 beat 确定共同的剧情锚点：

1. 叙事功能：建立 / 动作 / 对白 / 揭示 / 选择 / 后果 / 转场 / 钩子。
2. 必须被看到的事实：人物、动作、物件、信息或状态变化。
3. 进入状态、关键变化和退出状态。
4. 漫画分镜和漫剧分镜分别要解决什么媒介问题。

该过程只统一事实，不统一两种媒介的具体构图、时间处理和节奏。它不输出、不新增字段，也不要求模型展示思维链。

### 模块 4：M1 共享骨架预算——替换泛化数量规则

每个 beat 先分配一个主镜。只有满足以下任一条件时，才增加第二镜：

- 同一画格无法同时表现原因和结果。
- 揭示需要“关键物/事实”与“人物反应”分开才能读懂。
- 选择需要“做出选择”与“立即代价/后果”分开。
- 对白改变关系或信息，听者反应会改变台词含义。
- 动作跨越明确空间，缺少一镜会造成位置或方向断裂。

不得只为了景别变化、平均分配枚举或增加画面数量而拆第二镜。总量仍不得超过每个 beat 两镜，但建议值改成：

```text
beat 数量 + 真正复杂 beat 数量
```

这里的数量是当前 `Shot[]` 共享骨架的兼容预算，不代表漫画与漫剧长期应使用相同镜头数。未来若漫剧需要把一个漫画画格展开为多个动态镜头，或多个漫画画格合并成一个动态镜头，应升级数据契约，不能继续靠 Prompt 假装一一对应。

### 模块 5：漫画分镜 Prompt——独立增强

漫画轨道只设计静态画格和阅读体验，不读取或模仿 `motion` 的运镜与秒数。重点规则为：

| beat 功能 | 推荐处理 | 禁止机械处理 |
| --- | --- | --- |
| 建立 | 只有理解空间、人物关系或危险来源需要时才用建立镜头 | 每个场景都先来一个空全景 |
| 动作 | 选择预备、撞击、决定性瞬间或余波中最有叙事价值的一刻 | 一个画格塞连续三四个动作 |
| 对白 | 优先表现说话者目的、听者压力和两人空间关系 | 只做轮流说话头像；长台词完整塞进一格 |
| 揭示 | 关键细节和人物反应按理解需要拆分 | 为制造悬念添加正文没有的线索 |
| 选择 | 让姿态、手势、视线或行动体现选择 | 只写“他意识到/他决定了” |
| 后果 | 显示状态真正改变，供下一镜接力 | 下一镜把人物、道具或伤势重置 |
| 转场 | 使用地点、时间、光线、物件或行动桥接 | 每次都淡入淡出或强制空镜 |
| 钩子 | 末尾保留视觉问题、代价、揭示或反应 | 自造反派、秘密、爆炸或新对白 |

### 模块 6：漫剧分镜 Prompt——独立新增

漫剧轨道基于同一剧情锚点，独立设计可随时间展开的镜头，不从 `comic.panelDescription` 或 `comic.composition` 逐句改写。重点规则为：

1. 写清镜头开始状态、主要动作或表演变化、镜头结束状态。
2. 每个镜头优先聚焦一个主要动作、一次明确反应或一次信息揭示；复合动作必须保持时间顺序可执行。
3. `cameraMovement` 只在帮助揭示空间、关系、危险或情绪时使用，`static / none` 是正常选择。
4. `durationMs` 同时考虑动作完成、台词可说完、表演停顿和观众理解时间，不套固定 3 秒或 5 秒。
5. `compositionDesign` 服务运动路径、演员调度和镜头结束位置，不机械复制漫画画格构图。
6. `voiceLines` 只能来自正式正文中的对应对白，不能为了成片节奏擅自改词或补词。
7. 相邻动态镜头必须检查人物运动方向、视线、道具、动作完成状态和尾帧到首帧衔接。

外部参考主要来自 Seedance2 Storyboard Generator 的时间顺序与尾首帧连续、story-shot-agent 的拆镜/审计分层、Runway 的单镜主要动作原则，以及 AI Storyboard Generator 的相邻状态过渡。固定总时长、固定画幅和营销钩子不进入通用漫剧分镜 Prompt。

### 模块 7：双轨连续性账本——新增内部步骤

两条 Prompt 分别在生成下一单元前核对：

- 主体位置、朝向与视线。
- 手里或身边的关键道具及其状态。
- 服装、伤势、污渍和情绪余波。
- 同场景的时间、天气、光线和空间关系。
- 漫画轨道：上一画格留下的可读状态，下一画格是否自然承接。
- 漫剧轨道：上一镜尾部动作完成到哪一步，下一镜首部不能从更早状态重新开始。

### 模块 8：漫画与漫剧的一致性边界——纠正

两条轨道共享同一剧情锚点，但各自完成镜头设计：

- 必须共享或不冲突：beat、scene、characters、核心事件、因果结果、关键道具状态、正式对白来源。
- 不要求相同：决定性瞬间、描述文案、构图重点、阅读节奏、时间展开、镜头运动和表演节奏。
- 漫剧可以表现同一剧情单元从进入状态到退出状态的过程，不必冻结在漫画选中的那一帧。
- 漫画也不能为了迁就漫剧时间轴，把一个画格写成连续动作说明。
- 当前 `shotType`、`cameraAngle` 和数量仍因 M1 Schema 共用，这是兼容约束，不是长期领域定义。

### 模块 9：promptDraft 编译顺序——明确归属

当前单一 `promptDraft` 是后续静态候选图的草稿输入，归漫画轨道使用；它不是漫剧生成 Prompt，也不是最终图片 Prompt。建议固定为一句简短事实摘要：

```text
主体身份 + 决定性瞬间 + 场景锚点 + 光线/情绪 + 构图重点
```

不加入模型名、艺术家名、画质词、负面 Prompt、版式参数、对白原文、字幕或气泡。

漫剧轨道现阶段由 `motion.visualDescription / compositionDesign / cameraMovement / frameType / durationMs / voiceLines` 为未来动态 Prompt 编译器提供结构化输入，不在本轮新增 `motionPromptDraft` 死字段。等真实漫剧生成链路落地时，再单独设计 provider 无关的 Motion Prompt 编译器。

### 模块 10：双轨输出前删除检查——新增

漫画和漫剧分别逐镜检查：

> 删除这一画格或动态镜头后，如果该轨道的事实表达、因果、情绪转折、阅读/时间连续或钩子仍完整，它可能是冗余内容，应合并或删除。

该规则比“景别必须多样”更重要。视觉变化是手段，不是增加镜头的理由。

## 6. 当前 Prompt 的保留／增强／拒绝矩阵

| 当前模块 | 结论 | V2 动作 |
| --- | --- | --- |
| Skill、动作和 pending/confirm 边界 | 保留 | 不改 |
| StoryStructure 正式事实源 | 保留 | 不改 |
| beat/scene/character 本地引用 | 保留 | 不改 |
| comic + motion 双表达 | 保留并纠正 | 两套 Prompt 规则并列生成，只共享剧情事实；不再把 motion 写成 comic 投影 |
| 每 beat 1～2 Shot | 拆分重写 | 改为一个主镜 + 有条件辅助镜 |
| 单帧可画 | 增强 | 加决定性瞬间和抽象心理外化规则 |
| 连续性 | 增强并拆轨 | 漫画检查画格阅读接力；漫剧检查动作时间和尾帧到首帧 |
| 漫画阅读与气泡安全 | 保留并增强 | 对话按说话目的、听者反应和气泡负载决定是否拆镜 |

| 固定 9:16 / 16:9、固定秒数 | 不作为通用默认 | 漫画使用现有 comicFormat；漫剧时长按内容决定，未来画幅由成片配置决定 |
| 8K、胶片、镜头焦段、负面词 | 不采用 | 归下游 provider Prompt，不污染 Storyboard |

## 7. 定向修复 V2

当前一次修复上限正确，建议只增强问题到修复动作的映射：

| 问题组 | 修复范围 |
| --- | --- |
| JSON、字段、枚举、引用 | 只修格式、引用和非法值，不重写镜头内容 |
| beat 缺失或顺序倒退 | 只补缺失 beat 或调整顺序，保留其他镜头含义 |
| 完全重复或空壳 | 合并/改写对应镜头，重新检查是否真的需要辅助镜 |
| 空对白画格或双轨剧情事实冲突 | 从正式正文和 StoryStructure 恢复对应事件、对白和说话人，不要求两轨描述文案相同 |
| promptDraft 污染 | 只重写 `promptDraft`，不改正式镜头事实 |
| 连续性软问题 | 只调整受影响相邻镜头的动作、位置或状态描述 |

仍然返回完整 `shots`，不返回 patch；第二次失败仍不写 pending。

## 8. 质量门分层

### 8.1 后端确定性硬门——继续保留

- JSON 和必填字段。
- 固定枚举。
- order 连续。
- beat 全覆盖和叙事顺序。
- beat/scene 匹配。
- 合法角色和说话人引用。
- 必填文本非空壳。
- 完全重复镜头。
- comic 与 motion 的正式对白来源和剧情结果不冲突。
- `promptDraft` 禁止项和对白泄漏。

第一版不建议增加“镜头必须多样”“对话最多多少字”“必须有建立镜头”等主观硬门。

### 8.2 模型软评测——新增 P6 测试，不立即阻断生产

建议使用独立 rubric 评价：

1. 每个 Shot 是否提供新的可见信息、动作结果或情绪变化。
2. 关键揭示、选择、代价和钩子是否得到适当视觉强调。
3. 相邻镜头位置、朝向、视线、道具和动作状态是否连续。
4. 对白是否过载，听者反应是否只在有叙事价值时出现。
5. 是否存在无理由的全景、特写、空镜或重复构图。
6. 漫画轨道是否形成清楚的静态决定性瞬间、阅读顺序、气泡空间和格间节奏。
7. 漫剧轨道是否形成可执行的时间过程、人物表演、运镜、时长和尾首帧衔接。
8. comic 和 motion 是否来自同一剧情锚点且不互相矛盾，而不是是否描述同一瞬间。
9. 是否引入正式结构和正文中不存在的事实。
10. 是否分别适合漫画版式和漫剧时间表达，而不是套同一个模板。

模型评分只用于版本 A/B 和回归观察，不写入 Storyboard 核心数据，也不替代用户确认。

### 8.3 用户判断——继续保留

用户最终判断情绪力度、画面审美、阅读节奏和是否符合创作意图。系统不能把审美偏好伪装成确定性事实。

## 9. 固定评测样例

V2 至少使用以下样例与现有 Prompt 做同模型 A/B：

| 样例 | 重点失败模式 |
| --- | --- |
| 双人长对白 | 轮流说话头像、气泡过载、无意义反应镜 |
| 关键道具揭示 | 线索和反应顺序错误、擅自补新线索 |
| 连续动作 | 一格多动作、动作重复开始、朝向跳变 |
| 新场景进入 | 每场强制全景，或缺少必要空间定位 |
| 情绪选择 | 只写抽象心理，不展示可见选择 |
| 章节结尾钩子 | 钩子未强调，或为了强刺激擅自新增剧情 |
| 原稿导入章节 | 为套热门结构而改写或强化原稿 |
| 竖向条漫 / 分页漫画同结构 | 仍机械套 16:9 视频构图，忽略项目版式 |
| 同一 beat 的漫画与漫剧双轨输出 | motion 只是复述 comic；或两轨出现不同事件、对白和结果 |
| 漫剧动作与对白镜头 | 动作没有开始/结束状态、时长不足以说完台词、无意义运镜、尾首帧跳变 |

每次记录：

- 首次硬门通过率。
- 一次修复触发率和修复成功率。
- 平均 Shot/beat 与冗余镜头率。
- 无来源事实或对白数量。
- 连续性问题数量。
- 盲评偏好和主要理由。

## 10. 实施顺序

用户确认本方案后，建议按以下顺序改造：

1. 在现有 Prompt 中注入 `comicFormat` 和 `artStyle`。
2. 把当前混合规则拆成“共享剧情事实契约 + 漫画分镜 Prompt + 漫剧分镜 Prompt”三个明确模块。
3. 用“主镜 + 有条件辅助镜”替换当前 M1 共享骨架的泛化数量规则。
4. 漫画 Prompt 增加决定性瞬间、画格功能、阅读节奏、气泡负载和画格连续性规则。
5. 漫剧 Prompt 吸收外部动态分镜方法，增加开始/发展/结束状态、动作表演、运镜用途、内容时长和尾首帧连续规则。
6. 增加双轨剧情锚点一致性检查，但删除“motion 只能补充 comic 时间和运镜”“两轨必须描述同一瞬间”等主从表述。
7. 按问题代码增强一次定向修复，并为漫画、漫剧和共享事实分别设置软 rubric。
8. 使用 AI 创作/import 样例运行旧版/V2 同模型 A/B，验证当前生产切换是否持续改善；若质量退化，按本次独立提交回退 Prompt，不涉及数据迁移。

第一轮实现仍返回现有 `Shot[]`，不改变页面。若真实漫剧 A/B 证明一条漫画画格经常需要多个漫剧镜头，或两条轨道需要不同景别/机位，再单独立项升级为独立序列；不能在本轮凭空扩字段。

## 11. 最终推荐

采用“保留现有骨架、补镜头决策层”的 V2：

- 不导入外部完整 Skill。
- 保留一个公开 `storyboard-shot-generate` 入口，但内部明确编排共享事实、漫画分镜和漫剧分镜三套 Prompt 契约。
- 漫画和漫剧均在本阶段生成；任何一条都不是另一条的附属结果。
- 当前继续写入同一个 `Shot` 下的 `comic` / `motion`，因此页面字段和用户流程不变。
- 共享的是正式剧情事实；媒介镜头规则、描述、节奏和连续性评测分开。
- 明确记录 M1 的共用镜头数量、景别和机位只是兼容限制，为后续独立序列铺路。
- 不新增 Storyboard 字段。
- 不改页面展示和确认流程。
- 不把黄金三秒、固定时长、9:16、CTA 或九宫格变成通用规则。
- 重点补 beat 复杂度、镜头用途、状态接力、角色/场景锚点和软评测。
- Prompt 与测试改造已进入生产代码；下一步用同模型 A/B 决定是否继续保持该默认版本。

这比继续堆电影术语更能解决真实问题，也不会破坏已经验证通过的双路线、版本链和下游图片 Prompt 编译。
