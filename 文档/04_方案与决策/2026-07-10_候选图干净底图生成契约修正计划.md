# 候选图干净底图生成契约修正计划

## 1. 决策摘要

候选图阶段的正式产物收口为：

> 一个 `Shot` 对应一张单幅、单场景、单机位、无文字、无气泡、无分格/边框、可供后续裁切和排版的漫画干净底图。

修复不能只删掉 dialogue/caption。需要同时完成四项：

1. **后端生成规格成为事实源**：前端不再自行拼完整 Prompt 和全章参考图。
2. **Prompt 建立不可覆盖的干净底图约束**：排除章节名、对白、旁白、动态镜头过程和页面格式词。
3. **参考图按 shot 解析并按 provider 能力执行**：不再把全章参考传给每个 shot，也不再静默只取第一张。
4. **任务与资产记录生成规则版本**：旧候选不删除，新候选能追溯到确切规格、参考图和 provider 请求计划。

后续“一键生成整页漫画”如果保留，应作为排版成稿阶段的可选扁平草稿，不复用 `Candidate.shotId` 语义。

## 2. 已确认根因

### 2.1 Prompt 泄漏成稿信息

问题样本的真实 Prompt 包含：

- 章节标题。
- 三句对白。
- 整段旁白。
- `comic panel`。
- `format: vertical_scroll`。
- 含“镜头从……推到……”的动态过程描述。

这些信息共同鼓励模型把一个 shot 扩写成有标题、气泡、旁白和多个时间切片的完整漫画页。

### 2.2 参考图作用域错误

- 前端为每个 shot 传入整章所有角色参考图。
- 后端 guard 再注入一份整章角色参考图。
- worker 最终只读取第一张可用参考图。
- 第一张参考恰好是四分格角色定稿图，模型继承其横版和多格布局。

### 2.3 Provider 尺寸契约错误

- 当前 Grok 单图 edit 请求不带 `aspect_ratio`。
- xAI 官方说明：单参考图 edit 的输出比例继承输入图；多图 edit 才能显式覆盖 `aspect_ratio`。
- 当前第一张角色定稿图是横版 16:9，因此竖滑项目最终得到 1280×720 横图。

### 2.4 追溯缺口

- Candidate/Asset 只保存 `promptDigest`，没有稳定保存生成规格正文和实际参考绑定。
- 文档规定的 `tasks/{taskId}.input.json/output.json/error.json` 当前没有在内存 TasksService 中落地。
- 本次只能通过 Git 历史、正式 storyboard 和摘要重建真实输入，说明审计链仍不完整。

## 3. Candidate 产物契约

### 3.1 必须满足

- 一个连续场景。
- 一个静态叙事瞬间。
- 一个主要机位。
- 画面可包含当前 shot 需要的一个或多个人物。
- 允许构图中留出后续气泡安全区，但不得绘制气泡。
- 输出宽高比符合当前生成规格。
- 素材能追溯到 storyboard、preflight、shot、参考资产、provider 和 Prompt 模板版本。

### 3.2 明确禁止

- 章节名、页码、标题和任何排印文字。
- 对白、旁白、字幕、拟声词、标签和水印。
- 对话气泡、旁白框及其尾巴。
- 漫画页面、分格线、边框、沟槽、拼贴、三联画、分屏和 storyboard sheet。
- 在同一张图中连续展示多个时间点或多个镜头。
- 复制角色设定图的多视图排列、白底格子和参考图边框。

### 3.3 不承诺

生成模型仍可能偶发产生乱码或边框。V1 通过强约束 Prompt、正确引用和人工锁定把概率降到可接受范围；自动 OCR/分格检测作为后续质量门，不伪装成已解决。

## 4. 后端权威 GenerationSpec

新增共享契约，示意如下：

```ts
interface CandidateGenerationSpec {
  schemaVersion: 1;
  purpose: "shot_clean_plate";
  templateVersion: "candidate-clean-plate-v1";
  projectId: string;
  chapterId: string;
  shotId: string;
  sourceStoryboardId: string;
  sourceStoryboardUpdatedAt: string;
  imagePreflightId: string;
  imagePreflightVersion: number;
  prompt: {
    systemConstraints: string;
    scene: string;
    subjects: string;
    action: string;
    composition: string;
    camera: string;
    emotionAndLighting: string;
    style: string;
    userOverride: string | null;
    positive: string;
    negative: string;
    digest: string;
  };
  output: {
    requestedWidth: number;
    requestedHeight: number;
    aspectRatio: string;
    format: "webp" | "png";
    candidateCount: number;
  };
  references: CandidateReferenceBinding[];
  providerPlan: CandidateProviderPlan;
  warnings: string[];
}
```

### 4.1 事实源规则

- 后端从正式 `storyboard.json`、已确认 `preflight.json`、ProjectCharacter、Scene 和项目风格构建规格。
- 前端只提交 `shotId`、`candidateCount` 和以后允许的 `userPromptOverride`。
- 客户端提交的原始 `positivePrompt/referenceAssetIds` 不再成为执行事实；兼容期可忽略并记录 warning，稳定后拒绝。
- worker 只读取 `CandidateGenerationSpec`，不再自行 fallback 拼 Prompt 或拼接两组 reference ID。
- Prompt 预览调用后端 preview API，看到的就是任务真正执行的规格。

### 4.2 Prompt 可编辑的未来边界

Prompt 分为两层：

- 锁定系统层：单镜头、无文字、无分格等约束，用户不可删除。
- 可编辑描述层：人物动作、环境、情绪、构图补充。

用户修改描述后生成新任务/新批次，保存新的 GenerationSpec，不覆盖历史任务。

## 5. Prompt 模板修正

### 5.1 保留字段

- `shot.comic.panelDescription`
- `shot.comic.composition`
- `shot.coreAction`
- `shot.emotion`
- `shot.shotType`
- `shot.cameraAngle`
- 当前 scene 的地点、时间与氛围
- 当前 shot 相关角色的外貌/服装/气质描述
- 项目美术风格

### 5.2 排除字段

- `chapter.title/storyTitle`
- `shot.comic.dialogue`
- `shot.comic.caption`
- `shot.motion.visualDescription`
- `shot.motion.cameraMovement/voiceLines/duration`
- `vertical_scroll/page_horizontal/four_panel` 等页面格式名称

漫画格式只转换为 provider 输出比例和“portrait/landscape/square composition”描述，不直接告诉模型生成 webcomic/page/four-panel。

### 5.3 系统约束示意

```text
Create one clean production-ready comic shot illustration.
Show one continuous scene, one static narrative moment, and one camera view.
This is source artwork for later page composition, not a finished comic page.
Do not draw any text, title, caption, subtitle, dialogue, speech bubble,
sound effect, panel border, gutter, split screen, collage, or multiple panels.
Reference images are identity/environment references only; do not copy their
layout, background, borders, labels, or multi-view arrangement.
```

negative 部分同步包含 `text/typography/title/caption/dialogue/speech bubble/comic page/multiple panels/panel border/gutter/collage/storyboard/watermark/logo` 等禁止项。

## 6. Shot 级参考图解析

新增 `CandidateReferenceResolver`，只负责从正式事实源生成带角色语义的引用列表：

```ts
interface CandidateReferenceBinding {
  assetId: string;
  role: "character_identity" | "scene_environment" | "style";
  sourceEntityId: string;
  sourceEntityName: string;
  priority: number;
  required: boolean;
  referenceKind: string;
}
```

规则：

1. 用 `shot.characterIds` 匹配项目角色 ID/名称，只选择当前 shot 角色。
2. 用 `shot.sceneId` 只选择当前 scene 的 referenceAssetId。
3. 不使用全章 `characterChecks` 顺序决定当前镜头参考图。
4. 角色引用 V1 优先使用已确认的单人 `previewReferenceAssetId`；四分格 `final_reference` 只作身份事实和人工查看，不作为单图 edit 底图。
5. 若缺少安全的单人参考图，则用角色 appearance/promptFragment 文本降级并记录 warning，不把不相关或多格图片强塞给 provider。
6. 超过 provider 上限时，按角色层级、构图主体和 shot 中出现顺序选取，未使用角色转成文本描述并记录 omittedReferences。

后续可增加专用 `generationReferenceAssetId`，从最终定稿派生单人、无边框、适合 provider 引用的身份图；不把该能力塞进第一阶段热修复。

## 7. Provider 能力与降级计划

### 7.1 统一内部接口

将当前单数 `referenceImage` 改为 canonical 请求：

```ts
interface ImageGenerationRequest {
  prompt: string;
  negativePrompt: string;
  width: number;
  height: number;
  aspectRatio: string;
  references: Array<{ role: string; buffer: Buffer; mimeType: string; fileName: string }>;
  quality: "auto" | "low" | "medium" | "high";
  outputFormat: "webp" | "png" | "jpeg";
}
```

adapter 必须返回实际执行信息：mode、usedReferenceAssetIds、omittedReferenceAssetIds、requested/actual size、provider/model 和 warnings。

### 7.2 能力矩阵

| Provider | 官方能力 | 第一版计划 |
| --- | --- | --- |
| Grok Imagine | 多图 edit 最多 3 张，可显式设 aspect ratio；单图 edit 继承输入比例 | 2-3 张安全引用时使用 `images[] + aspect_ratio`；只有 1 张且比例不匹配时暂退纯文生图，不再静默继承横图 |
| OpenAI GPT Image | edit 支持多张输入，GPT Image 最多 16 张；支持 1024×1024、1024×1536、1536×1024 | multipart 重复 image 字段并传 size；按 model capability 限制引用数 |
| 豆包 Seedream | 官方支持单/多参考图和 size；不同接入面参数形态不同 | provider adapter 使用当前模型对应官方参数；先做 payload 合约测试和一次真实 integration 验证，失败则纯文生图降级 |

未知模型、中转服务或不确定能力的安全默认值是：

```text
不传参考图 + 保留完整文本身份描述 + 按支持尺寸文生图 + 显示一致性降级 warning
```

禁止的 fallback：把多张引用缩成第一张继续 image edit。

### 7.3 输出比例

V1 继续使用可预测的项目格式 profile：

| 项目格式 | Candidate profile |
| --- | --- |
| `vertical_scroll` | 2:3 portrait，OpenAI 1024×1536，Grok `2:3` |
| `page_horizontal` | 3:2 landscape，OpenAI 1536×1024，Grok `3:2` |
| `four_panel` | 1:1，OpenAI 1024×1024，Grok `1:1` |

实际像素尺寸写入资产元数据；输出比例明显不符时任务标记 warning，不能假装已满足。

## 8. 数据、任务与资产变化

### 8.1 Candidate

建议为 `ProjectCandidate/WorkbenchCandidate` 增加：

```ts
generationPurpose: "shot_clean_plate" | "legacy_unspecified";
generationSpecVersion: number | null;
generationSpecDigest: string | null;
```

字段表示生成意图和规则版本，不宣称模型视觉结果一定合格；最终仍由用户锁定确认。

### 8.2 GenerationTask

- `image_generate.input` 写入完整 `generationSpec`。
- `output` 写入 providerPlan 实际结果、candidateIds、assetIds、实际尺寸和 warnings。
- 按现有素材契约先为 image_generate 落：
  - `projects/{projectId}/tasks/{taskId}.input.json`
  - `projects/{projectId}/tasks/{taskId}.output.json`
  - `projects/{projectId}/tasks/{taskId}.error.json`
- 通过可复用 `TaskArtifactService` 实现，后续其他 worker 逐步接入，不在 ImageCandidateService 内散落三套写文件逻辑。

### 8.3 Asset meta

至少记录：

- `generationPurpose`
- `generationSpecVersion/digest`
- `promptTemplateVersion`
- `provider/model/mode`
- `usedReferenceAssetIds`
- `omittedReferenceAssetIds`
- `requestedWidth/Height`
- `actualWidth/Height`
- `sourceStoryboardId/imagePreflightId`

不在每个 Candidate meta 重复完整 Prompt；完整规格只存 task input。

## 9. 旧候选兼容

- 不删除、不改写、不自动重生成现有文件。
- 没有 `generationSpecVersion` 的候选读取为 `legacy_unspecified`。
- UI 增加“旧规则候选”标识，说明可能含文字、分格或错误引用。
- 已锁定的旧候选不自动解锁，避免破坏用户选择。
- 新锁定旧候选时给一次明确提示；用户仍可选择使用。
- 排版成稿导出检查把旧规则锁定候选列为 warning，不在兼容期硬阻塞。
- 新批次只使用 V1 干净底图规格；批次列表可明确区分新旧规则。

## 10. 分阶段实施计划

### 阶段 0：回归夹具与红灯测试

目标：先锁住本次真实失败模式。

- 用 `shot_015` 的结构化字段建立匿名化/最小 JSON fixture，不提交大图片和 API Key。
- 测试旧输入会包含 chapter/dialogue/caption/motion/page format，作为失败证据。
- 建立 Prompt 禁止项断言、shot 参考作用域断言和 provider payload snapshot。

退出标准：测试能在当前错误链路上失败，且失败原因指向真正调用边界。

### 阶段 1：后端权威干净底图规格

目标：不带参考图也能稳定生成语义正确的单镜头底图。

- 新增 CandidateGenerationSpec DTO、builder/service 和模板版本。
- guard 根据正式 storyboard/preflight 重写 image_generate input。
- worker 只读 generationSpec。
- 新增 preview API；前端 Prompt 预览切换到后端结果。
- 前端单镜/批量生成只提交 shotId、candidateCount。
- 暂时以 `references=[]` 验证 Prompt 和尺寸，隔离参考图变量。

退出标准：fake provider 捕获的 15 个 shot 请求均无章节名、对白、旁白、motion 动态过程和页面格式词，且 profile 尺寸正确。

### 阶段 2：Shot 级参考解析

目标：不再出现无关角色和四分格设定图污染。

- 实现 CandidateReferenceResolver。
- 只解析当前 shot 角色与 scene。
- 使用安全的单人 preview 参考；不直接使用四分格 final sheet。
- 在预览 UI 展示“将使用/将省略”的参考资产和 warning。

退出标准：fixture 中 shot_002 只得到年轻船员、老船员和 scene_01；不能出现酷拉皮卡或其他章节角色。

### 阶段 3：Provider 多参考 adapter

目标：按官方能力恢复一致性，不牺牲尺寸和单镜头契约。

- Grok：实现 `images[]`、最多 3 张和多图 `aspect_ratio`；单图比例不匹配走安全降级。
- OpenAI：实现多 image multipart 和模型 size/capability 校验。
- 豆包：实现当前模型对应的多图参数与 size；用 mock payload + 一次真实调用验证。
- 未知中转/模型走保守 capability，不猜参数。

退出标准：三类 adapter 的请求 payload 快照测试通过；不再存在 `resolveReferenceImage(...)[0]` 语义。

### 阶段 4：版本、旧候选与任务追溯

目标：用户能区分规则版本，问题可复盘。

- Candidate 增加 generation purpose/spec version。
- Asset meta 保存实际 provider plan 和尺寸。
- image_generate 落 task input/output/error 文件。
- UI 标识旧规则候选和新规则批次。
- 旧候选锁定提示与兼容导出 warning。

退出标准：重启服务后仍能从 workspace 定位新候选的完整 GenerationSpec 和实际引用。

### 阶段 5：真实运行验收与放行

目标：验证模型真实行为，不用“测试通过”代替视觉结果。

- 每个启用 provider 选择 5 类镜头：无角色远景、单人近景、双人对话、多人群像、场景/特效镜头。
- 每类生成 2 张，共 10 张/provider。
- 保存样本、任务 JSON、provider plan 和人工判定表。
- 验收通过后再默认开启对应 provider 的 reference mode。

退出标准见第 11 节。

## 11. 验证矩阵

### 11.1 自动化测试

| 测试 | 强制结果 |
| --- | --- |
| Prompt fixture | 不含 chapter/dialogue/caption/motion/page-format；包含 clean-plate 约束 |
| Reference resolver | 结果是当前 shot 角色 + 当前 scene 的子集 |
| Provider cap | 超上限产生 omitted + warning，不静默丢弃 |
| Grok payload | 多图使用 `images[] + aspect_ratio`；单图比例冲突不走危险 edit |
| OpenAI payload | 多图 multipart 与 size 正确 |
| 豆包 payload | 当前模型参数、size、单图输出开关正确 |
| Worker persistence | input/output/error、Candidate、Asset 追溯一致 |
| Legacy normalize | 旧 candidates.json 可读且不改原文件 |
| 前端单镜/批量 | 不再传 raw positivePrompt 和全章 reference IDs |

### 11.2 真实视觉验收

每个已启用 provider 的 10 张样本必须满足：

- 10/10 不复制章节标题、对白和旁白原文。
- 10/10 输出比例符合 provider 支持的目标 profile。
- 10/10 不出现其他 shot 的无关参考角色。
- 至少 9/10 没有任何文字、气泡、分格、边框或拼贴；出现的单个异常必须可被用户废弃，且不能形成系统性同类错误。
- 多人镜头中，省略的参考角色与 warning 和 task 记录一致。
- 任务、Candidate、Asset、文件路径可互相追溯。

若某 provider 达不到门槛：关闭该 provider 的 reference mode，保留纯文生图，不能整体宣称修复完成。

## 12. 回滚与安全开关

- 以 provider 为粒度提供 `reference mode on/off`，出错时退回纯文生图。
- 不提供“退回全章第一张参考图”的旧逻辑。
- GenerationSpec 版本化，新模板只影响新任务；旧候选不重写。
- provider adapter 失败时任务保留明确 warning/error，不自动换另一 provider 产生不可解释结果。
- 实现期间保持现有用户未提交 Grok 设置改动，不覆盖无关工作树内容。

## 14. 静态复核结论

### 一致性

- 与产品主链路一致：候选图负责单镜图片，排版负责多格页面和气泡。
- 与 `Candidate.shotId` 一致：不再让一个候选包含多个镜头/页面。
- 与 preflight 一致：角色/场景参考仍来自已确认出图准备，但作用域收窄到当前 shot。
- 与任务中心一致：继续使用 `image_generate` 和通用任务状态，只升级 input 契约。
- 与素材追溯一致：GenerationSpec、Task、Candidate 和 Asset 形成完整链路。

### 残留风险

- 多参考图不能保证多人身份完全一致，需要真实样本验证。
- `previewReferenceAssetId` 与最终定稿可能存在细微差异；专用 generation reference 仍是后续方向。
- 用户自定义中转可能不完全兼容官方 API，需要保守 capability 和清晰 warning。
- Prompt 无法百分百阻止模型生成乱码/气泡，最终锁定仍需人工视觉判断。
- 任务持久化如果只先接 image_generate，其他任务仍保留原有内存态缺口，应单独追踪后续收口。

## 15. 决策状态

本文是待用户确认的实施计划，不是已生效 ADR。用户确认后，应按阶段 0 开始测试先行；阶段 1-2 完成前不建议继续批量生成正式候选，阶段 5 运行验收通过前不宣称问题解决。
