# 图片 Prompt 专业化调研与 V2 设计依据

## 1. 本文定位

本文先回答三个问题：

1. 网上官方资料和热门开源项目，实际采用了哪些有效方法；
2. 哪些方法适合 AI 漫游，哪些不应照搬；
3. 下一阶段应重写哪些 Prompt，以及怎样按 OpenAI、Doubao、Grok 分别编译。

本文是 V2 Prompt 的设计依据，不是最终 Prompt 文案，也不代表已经完成真实图片测试。

本轮范围只覆盖：

- 角色参考图；
- 场景参考图；
- 漫画静态候选图；
- 参考图职责描述；
- 三个图片 Provider 的 Prompt 与参数适配。

漫剧起始帧、结束帧和图生视频 Prompt 继续保留为独立包，后续单独研究和测试，不与漫画静态图共用一条 Prompt。

## 2. 结论先行

### 2.1 不存在值得直接导入的“万能漫画 Prompt”

官方资料和成熟开源项目的共同规律不是堆砌“杰作、获奖、8K、超细节”等词，而是：

1. 明确这次要生成的产物用途；
2. 用稳定顺序描述场景、主体、动作、构图、光线和限制；
3. 多参考图时逐张说明用途；
4. 明确必须保持什么、允许改变什么；
5. 将人物数量、位置、动作主体和动作对象写清楚；
6. 将比例、水印、参考图上限等能力问题放在 Provider 参数层处理；
7. 使用固定样例反复评测，而不是凭一次“看起来不错”判断 Prompt 质量。

### 2.2 AI 漫游应采用“语义规格 + 任务模块 + Provider 编译器”

下一版不应继续维护一条越来越长的公共字符串，而应分为三层：

```text
现有页面与领域字段
→ 语义规格：人物、场景、动作、构图、镜头、画风、成图合同
→ 任务模块：角色参考 / 场景参考 / 无人 / 单人 / 双人 / 多人 / 特效
→ Provider 编译器：OpenAI / Doubao / Grok
→ Prompt 文案 + 请求参数 + 参考图清单
```

页面字段保持不变。专业化方法在内部编译层完成，不要求用户填写更多技术字段。

### 2.3 Prompt 只能解决一部分问题

| 问题 | 主要解决层 |
| --- | --- |
| 人物身份、动作、位置说不清 | Prompt 语义规格 |
| 每张参考图用途不清 | 参考图清单与 Provider 编译 |
| 多人物串脸、串色、位置漂移 | Prompt + 参考图能力 + 布局/结构控制 |
| 水印 | Provider 请求参数优先，Prompt 仅作补充 |
| 输出比例错误 | Provider 请求参数与编辑模式 |
| 单参考图被静默丢弃 | Provider 适配策略 |
| 连续多格人物一致性 | 稳定身份锚点 + 参考图 + 连续性评测；不能只靠长 Prompt |
| 对话框、字幕和分格污染 | 单格成图合同 + 后续排版职责分离 |

## 3. 当前生产实现对照

### 3.1 当前已有的正确基础

- 角色预览、角色定稿、场景参考图已经分开生成；
- 候选图已经能接收视觉描述、动作情绪、构图、镜头、人物、场景和画风；
- 当前候选图已有“单张、单场景、单时刻、无文字、无水印、无拼贴”的基础合同；
- 漫画静态分镜与漫剧动态分镜已经是不同业务产物，方向正确。

### 3.2 当前需要修正的地方

| 现状 | 问题 | V2 方向 |
| --- | --- | --- |
| 三个 Provider 最终使用相同正文，只更换 `profileId` | 没有真正利用不同模型的提示习惯和参考图能力 | 分别编译三套最终文案与参数 |
| 参考图只写“身份参考”或“场景参考” | 缺少逐图保持项、允许变化项、位置和动作归属 | 生成结构化 Reference Manifest |
| 通用候选图 Prompt 不区分人数与任务类型 | 无人、单人、双人、多人需要的约束不同 | 增加五类镜头模块 |
| Doubao 请求固定 `watermark: true` | 与“干净画面、无水印”合同直接冲突 | 请求层改为无水印；不能靠 Prompt 抹掉 |
| Grok 单参考图时当前适配器改走纯文本生成 | 目标比例得到保留，但身份或场景参考被静默舍弃 | 明确预处理、接受参考比例或显式降级，禁止静默丢图 |
| 双人镜头只写自然语言动作 | 容易出现动作主体与对象反转 | 明确 A 做什么、B 被怎样影响、B 不做什么 |
| 多人镜头没有完整位置合同 | 容易漏人、合并人物或身份错位 | 精确数量、逐人位置、逐人动作、缺图时显式警告或阻断 |

## 4. 官方资料与热门开源项目对照

### 4.1 OpenAI 官方 GPT Image 指南

来源：

- [GPT Image 提示词指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)
- [OpenAI Image API 指南](https://developers.openai.com/api/docs/guides/image-generation)

可吸收方法：

1. 生产 Prompt 使用稳定顺序：场景/背景 → 主体 → 关键细节 → 限制；
2. 复杂任务使用短小的分段标签，不使用难以调试的超长散文；
3. 明确构图、机位、人物尺度、身体取景、视线、手部动作和道具交互；
4. 编辑或多图合成时，明确“哪些内容改变、哪些内容必须保持”；
5. 多张输入图逐张编号，并说明每张图提供的人物、场景或风格；
6. 漫画叙事应拆成清晰、可见、可执行的视觉节拍，而不是把整段剧情一次塞进一张图；
7. 复杂结果通过迭代和固定评测改善，不依赖一次超长 Prompt。

对 AI 漫游的直接影响：

- OpenAI Profile 使用清晰分段的制作简报；
- 多参考图必须逐图编号；
- 双人和多人镜头必须写明位置与交互；
- “保持身份、允许改变姿势和表情”要成为明确字段，而不是隐含期望。

### 4.2 火山引擎 Seedream 官方指南

来源：

- [Seedream 提示词指南](https://www.volcengine.com/docs/82379/1829186)
- [Ark ImageGenerations API](https://api.volcengine.com/api-docs/view?action=ImageGenerations&serviceCode=ark&version=2024-01-01)

可吸收方法：

1. 使用简洁、连贯的自然语言描述“主体 + 行为 + 环境”；
2. 再补充风格、色彩、光影和构图，不以形容词堆砌代替主体关系；
3. 明确图片应用目的；
4. 多图输入中逐张说明贡献对象和要执行的操作；
5. 编辑任务写清目标和不应改变的部分；
6. 准确、较短的表达通常比重复修饰更容易维护。

对 AI 漫游的直接影响：

- Doubao Profile 优先使用中文连贯制作描述；
- 不直接复制 OpenAI 的长英文合同；
- 参考图采用“图 1 提供谁、图 2 提供什么空间”的清晰关系；
- `watermark`、`size` 等能力由请求参数控制。

### 4.3 xAI 官方图像生成与编辑文档

来源：

- [xAI Image Generation](https://docs.x.ai/developers/model-capabilities/images/generation)
- [xAI Image Editing](https://docs.x.ai/developers/model-capabilities/images/editing)
- [xAI Multi-Image Editing](https://docs.x.ai/developers/model-capabilities/images/multi-image-editing)

可吸收方法与能力边界：

1. 比例和分辨率是 API 参数，不应只写进 Prompt；
2. 多图编辑最多使用三张来源图；
3. 多图任务应明确所有主体都要出现，并明确禁止额外人物；
4. 单图编辑、多图编辑和纯文本生成的比例行为不同，需要适配器显式选择；
5. 当参考图预算不足时，系统必须按优先级选择或阻断，不能默默删掉关键人物。

对 AI 漫游的直接影响：

- Grok Profile 使用更短、更直接的英文指令；
- 开头明确“只生成一张无边框完整画面”；
- 明确准确人物数量和动作主体/对象；
- 参考图上限固定按三张预算设计；
- 单参考图目标比例冲突由适配策略解决，不伪装成 Prompt 问题。

### 4.4 Midjourney Character / Omni Reference

来源：

- [Character Reference](https://docs.midjourney.com/hc/en-us/articles/32162917505293-Character-Reference)
- [Omni Reference](https://docs.midjourney.com/hc/en-us/articles/36285124473997-Omni-Reference)

可吸收方法：

1. 有参考图仍需要在正文中强化关键外貌和服装特征；
2. 身份参考与画风参考可能相互竞争；
3. 复杂细节不会因为“给了参考图”就自动精确复现；
4. 身份锚点应短、稳定、可重复使用。

不采用：

- 不把 Midjourney 的专有参数写进 OpenAI、Doubao 或 Grok；
- 不把某个权重参数误认为跨模型通用规律。

### 4.5 StoryDiffusion

来源：

- [StoryDiffusion 官方仓库](https://github.com/HVision-NKU/StoryDiffusion)

可吸收方法：

1. 连续画面应反复使用稳定的角色身份描述；
2. 连续性需要按多格序列评测，而不是只评单张美观；
3. 每一格场景描述可以简洁，但身份锚点必须稳定；
4. 长序列人物一致性是专门的模型/工作流问题。

重要边界：

StoryDiffusion 的主要一致性能力来自专用注意力机制和工作流，不是其示例 Prompt 本身。AI 漫游可以采用“稳定身份锚点 + 连续性测试”，但不能宣称仅靠提示词就能达到相同一致性。

### 4.6 ComfyUI Area Composition / ControlNet 工作流

来源：

- [Area Composition](https://comfyanonymous.github.io/ComfyUI_examples/area_composition/)
- [Noisy Latent Composition](https://comfyanonymous.github.io/ComfyUI_examples/noisy_latent_composition/)
- [ControlNet](https://comfyanonymous.github.io/ComfyUI_examples/controlnet/)

可吸收方法：

1. 多人物应有区域位置与身份分配；
2. 不做区域控制时，人物颜色和特征可能互相污染；
3. 人物交互可以由文字定义，但姿势和空间稳定性还需要结构控制；
4. 文本、身份参考、布局参考和姿势参考是不同职责。

对 AI 漫游的影响：

- 当前托管 API 没有直接暴露区域条件时，Prompt 仍要明确左/右、前/后和人物数量；
- 若固定评测长期显示多人污染，应将其标为 Provider/工作流能力缺口，而不是无限加长 Prompt。

### 4.7 IP-Adapter 与 InstantID

来源：

- [IP-Adapter 官方仓库](https://github.com/tencent-ailab/IP-Adapter)
- [InstantID 官方仓库](https://github.com/instantX-research/InstantID)

可吸收方法：

1. 身份参考和文本场景描述是两种不同条件；
2. 身份保真与画面自由度存在权衡；
3. 人脸或人物一致性通常需要专门的身份保持机制；
4. 单张身份图可以作为稳定身份来源，但不能指望文字完整重建所有细节。

使用边界：

当前三家托管 API 并未直接暴露这些开源适配器的完整控制能力，因此只吸收职责分离原则，不假装当前系统已经具备相同底层能力。

### 4.8 AI Comic Factory

来源：

- [AI Comic Factory 仓库](https://github.com/jbilcke-hf/ai-comic-factory)
- [面板结构生成 Prompt](https://github.com/jbilcke-hf/ai-comic-factory/blob/main/src/app/queries/getSystemPrompt.ts)
- [画风与图像 Prompt 预设](https://github.com/jbilcke-hf/ai-comic-factory/blob/main/src/app/engine/presets.ts)
- [图像渲染调用](https://github.com/jbilcke-hf/ai-comic-factory/blob/main/src/app/engine/render.ts)

值得吸收：

1. 每个面板重复稳定的人物年龄、外貌、服装和颜色描述；
2. 面板画面指令与对白、说明文字分开；
3. 图像生成阶段明确排除 speech bubble、caption、subtitle；
4. 结构模型先输出面板，再由图像模型逐格生成。

不应照搬：

1. 泛化的“beautiful、award winning、high resolution”等质量词堆砌；
2. 依赖重复文本解决人物一致性；
3. 直接借用艺术家姓名作为长期生产画风合同；
4. 在同一张候选图里同时完成分格、对白框和成图；
5. 把“single comic panel”等文字机械叠加到所有模型，导致字面元素污染画面。

AI 漫游当前“干净单格图 → 后续排版文字”的职责分离，比一次生成完整漫画页更适合稳定生产，应继续保留。

## 5. 采用与拒绝清单

### 5.1 V2 必须采用

| 方法 | 落点 |
| --- | --- |
| 稳定描述顺序 | 所有 Provider 编译器 |
| 明确产物用途 | 角色、场景、候选图开头 |
| 逐图编号与职责 | Reference Manifest |
| 必须保持 / 允许变化 | 角色和场景参考模块 |
| 精确人数 | 所有包含人物的候选图模块 |
| 左右/前后/景别 | 双人、多人模块 |
| 动作主体与对象 | 单人、双人、动作特效模块 |
| 一格一时刻 | 漫画静态成图合同 |
| 无对白框、字幕、水印、UI、拼贴 | 漫画静态成图合同 + 参数层 |
| 稳定身份锚点 | 角色资产与连续格上下文 |
| 按 Provider 区分语言、长度和参考图策略 | 三个 Provider Profile |
| 固定样例 A/B | V2 验收 |

### 5.2 明确拒绝

- 网络流传的“泄露系统 Prompt”；
- 一整段不可维护的万能长 Prompt；
- 通用 Stable Diffusion 负面词串直接塞给所有 Provider；
- 仅靠“masterpiece、8K、best quality”判断专业；
- 把漫画静态分镜和漫剧视频运镜写在同一条 Prompt；
- 让图像模型直接画对白框、字幕和排版；
- 静默丢弃超出 Provider 预算的关键参考图；
- 用 Prompt 掩盖水印、比例、参数和编辑模式错误；
- 把计划中的人物、动作或场景自动补入原分镜没有的内容。

## 6. V2 Prompt 包清单

### 6.1 参考资产包

| Prompt | 核心职责 | 必要约束 |
| --- | --- | --- |
| 角色预览 | 建立可选择的身份设计 | 单角色、清楚面部发型服装、无复杂背景、无文字 |
| 角色定稿组合图 | 固定后续可复用的身份资产 | 同一人同一服装、四个指定视角、不重复人物、不加标签 |
| 场景参考图 | 固定空间和光线资产 | 稳定地标、出入口、前中后景、主光方向、无人抢主体、无文字 |

### 6.2 漫画静态候选图包

| 模块 | 额外必须写清的内容 |
| --- | --- |
| 共享单格合同 | 一张无边框完整画面、一个时刻、无拼贴、无字幕和对话框 |
| 无角色环境镜头 | 明确零人物、零人影；空间地标和主光源 |
| 单人镜头 | 准确一人；姿态、表情、视线、手部和道具关系 |
| 双人镜头 | 准确两人；A/B 位置、动作主体、对象、反应和视线轴 |
| 多人镜头 | 准确人数；逐人位置与动作；主次层级；禁止合并或新增人物 |
| 动作/光效/环境特效 | 单一可见瞬间；原因、爆发点、影响对象、主要光源、仍需可见的主体 |

### 6.3 参考图职责包

每一张图至少编译以下语义：

```json
{
  "inputIndex": 1,
  "role": "character_identity",
  "subject": "林舟",
  "mustPreserve": ["脸型", "发型", "年龄感", "服装主色", "关键配饰"],
  "mayChange": ["姿势", "表情", "镜头角度", "画面裁切"],
  "placement": "画面左侧中景",
  "actionOwnership": "林舟伸手抓住许澄的手腕",
  "ignoreFromReference": ["白色参考图背景", "组合图排版", "标签文字"]
}
```

这是 AI 语义输出示意，不包含数据库 ID；正式引用、文件路径和 Provider 入参数组仍由后端补充。

## 7. 三个 Provider 的 V2 差异

### 7.1 OpenAI Profile

- 语言：清晰英文制作简报；领域内容可先由内部字段组装再翻译；
- 结构：短标签分段；
- 顺序：output purpose → scene → subjects → action → composition/camera → light/style → references → preserve/change → exclusions；
- 多图：逐图编号，明确移植对象、位置与保持项；
- 重点：人物身体取景、视线、手部、道具交互和身份保真；
- 不采用：通用负面词串和冗长修辞。

### 7.2 Doubao / Seedream Profile

- 语言：简洁连贯中文；
- 结构：主体、动作、环境先形成完整句，再补构图、光色、风格和限制；
- 多图：使用“图 1 / 图 2 / 图 3”逐图说明；
- 重点：图片用途、对象关系、必须保留项和编辑目标；
- 参数：明确目标尺寸，关闭水印；
- 不采用：照搬 OpenAI 的长英文合同、重复同义形容词。

### 7.3 Grok Profile

- 语言：短而直接的英文指令；
- 开头：one borderless full-frame image, not a collage or comic page；
- 重点：准确人物数量、A/B 动作关系、禁止额外人物、明确比例；
- 多图：最多三张，优先保留当前镜头中的关键人物身份，其次场景；
- 单图：遇到目标比例冲突必须走明确适配策略；
- 不采用：在参考图不足时静默退化为纯文本生成。

## 8. 参考图预算规则

### 8.1 通用优先级

参考图不是“越多越好”，而是按当前镜头目标排序：

1. 身份关键的画面内人物；
2. 当前镜头的核心场景空间；
3. 次要人物；
4. 独立画风参考。

### 8.2 不允许的降级

- 双人镜头只保留一人的参考图，却不产生警告；
- 场景空间是剧情关键，却静默删除场景参考；
- 多人镜头超过预算后随机选择人物；
- 参考图组合图的白底、排版和标签被当成成图内容复制。

### 8.3 建议状态

| 状态 | 含义 |
| --- | --- |
| `ready` | 所有身份关键参考与场景参考均在预算内 |
| `degraded` | 可以生成，但有明确缺失项和预期风险 |
| `blocked` | 缺少会改变人物身份或场景事实的关键参考，不应静默生成 |

这些状态供内部任务与测试使用，当前不增加页面字段。

## 9. 固定评测设计

### 9.1 参考资产固定样例

1. 单角色预览：辨识度、服装、脸部清晰、无多余人物；
2. 四视图定稿：同一身份、同一服装、四个准确视角、无文字；
3. 场景参考：空间地标、出入口、光线方向、无人和无文字。

### 9.2 漫画候选图固定样例

1. 无人环境建立镜头；
2. 单人近景情绪镜头；
3. 双人对抗且容易出现主客体反转的镜头；
4. 三人调度且人物外观差异明显的镜头；
5. 强光效或环境特效镜头。

### 9.3 连续性固定样例

1. 同一角色连续三格：角度、表情和动作改变，身份与服装不变；
2. 同一场景连续三格：机位改变，地标、出入口和主光方向不漂移。

### 9.4 评分维度

| 维度 | 核心问题 |
| --- | --- |
| 规格遵守 | 是否为一张单格图，人数、时刻和内容是否正确 |
| 身份一致 | 人脸、发型、服装、关键配饰是否保持 |
| 动作准确 | 动作主体、对象、反应、手部与道具是否正确 |
| 空间一致 | 地标、出入口、前后关系和光源是否稳定 |
| 构图可用 | 景别、机位、主体层级和留白是否符合分镜 |
| 污染控制 | 是否出现文字、水印、UI、拼贴、边框或额外人物 |
| 视觉质量 | 画面是否清晰、有层次、符合项目画风 |

不得只用一个总分掩盖硬性失败。文字、水印、人数错误、身份错误和动作反转应单独记录。

## 10. V2 编写边界

### 10.1 不影响当前页面字段

当前页面展示已经足够用户理解，不新增“Prompt 工程字段”。现有字段继续作为输入：

- 分镜视觉描述；
- 动作与情绪；
- 构图；
- 镜头；
- 人物；
- 场景；
- 画风；
- 输出比例。

内部编译器根据这些字段推导任务模块、人物数量、参考图职责和 Provider 文案。

### 10.2 漫画与漫剧继续分开

漫画静态图强调：

- 一格；
- 一个决定性时刻；
- 静态构图和动作结果；
- 干净画面；
- 后续排版。

漫剧后续 Prompt 强调：

- 起始状态与结束状态；
- 角色连续表演；
- 时间变化；
- 运镜；
- 图生视频可实现的动作幅度。

两者共享角色和场景事实，但不共享最终 Prompt 模板。
