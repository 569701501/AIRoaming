## 1. 背景

当前实现中，一个项目只有一份项目级剧本文本。随着产品进入真实漫画创作流程，用户会自然按“第 1 章、第 2 章、第 3 章”推进内容。

如果继续只保存项目级单份剧本文本，会出现以下问题：

- 用户无法清楚看到当前写到第几章。
- 完成当前章节后，缺少进入下一章的明确动作。
- 剧情结构、分镜、候选图和排版无法稳定追溯到具体章节。
- 本地文件只有项目级草稿，后续素材包和导出物容易混乱。

## 2. 决策

将 `Chapter` 作为项目内一等工作单元。

```text
Project
  -> Chapter
     -> ChapterScriptVersion
     -> StoryVersion
     -> StoryBeat
     -> Shot
     -> Candidate
     -> LayoutPage
     -> chapter scoped Asset
```

项目级继续承载：

- 项目名称、类型、默认风格。
- 角色模板。
- 世界观和项目级已确认事实。
- 通用场景。
- 共享素材。

章节级承载：

- 当前章节剧本。
- 当前章节结构化剧情。
- 当前章节分镜。
- 当前章节候选图和锁定图。
- 当前章节排版和导出。

## 3. UI 决策

剧本步骤需要章节列表或章节切换器。

章节列表展示：

| 信息 | 说明 |
| --- | --- |
| 章节序号 | 例如 `第 1 章` |
| 章节标题 | 后续允许用户自定义 |
| 章节状态 | 草稿、剧本已完成、结构化中、分镜中等 |
| 更新时间 | 帮助用户判断最近编辑章节 |

剧本步骤主动作分为：

| 动作 | 说明 |
| --- | --- |
| 保存草稿 | 保存当前章节剧本，不推进流程 |
| 完成本章 | 保存当前章节，写入正式版本并标记章节完成。完成后仍停留在当前章，只展示“进入本章剧情结构”；若已确认项目大纲存在下一张章节卡，则仅在章节切换器中增加下一章入口，不创建下一章草稿、不自动切换，也不提供“继续下一章”动作。角色库待处理项只提示，不阻塞剧情结构。此处已按 2026-07-16 双流程来源与状态契约修正 |
| AI 分析当前章节 | 对当前章节执行结构化剧情任务 |

“完成本章”不是不可逆关闭。用户可以回到已完成章节继续修改，但修改后应提示后续结构化剧情、分镜、候选图或排版可能需要重新生成。

章节切换只改变当前工作上下文，不触发 AI 生成。用户进入下一章后，仍需在该章对话中明确要求生成当前章节，才会产生待确认草稿。

## 4. 本地文件决策

目标 workspace 结构：

```text
workspace/projects/{projectId}/
  project.json
  chapters/
    chapter-001/
      chapter.json
      script.md
      script.versions/
      structure.json
      storyboard.json
      candidates/
      layout/
      exports/
  shared/
    characters.json
    scenes.json
    project_facts.json
  assets/
  tasks/
```

文件夹只是落盘方式，不能替代数据模型。章节排序必须依赖 `Chapter.order`，不能只依赖文件夹名或显示标题。

## 5. 迁移原则

当前代码仍使用项目级单份剧本文本和过渡路径：

```text
projects/{projectId}/story/story_draft.source.txt
```

接入章节模型时：

1. 新项目默认创建 `chapter-001`。
2. 已有开发期项目如果存在 `story/story_draft.source.txt`，迁移或兼容读取到 `chapters/chapter-001/script.md`。
3. 后续所有章节内生成任务携带 `chapterId`。
4. 前端不直接写本地物理路径，仍通过后端 API 保存章节。

## 6. 后续实现顺序

1. 增加 `Chapter` 和章节 DTO。
2. 后端项目服务创建默认章节，并提供章节列表、保存草稿、完成本章接口。
3. 前端剧本页增加章节列表或章节切换器。
4. 将剧本文档编辑器绑定到当前章节。
5. 移除剧本页常驻的右侧“当前章节信息”面板；当前剧本区域只负责写作、编辑、保存和完成当前章节正文。
6. 将主线、角色、场景等结构化整理放到用户主动触发的 `AI 分析当前章节`、剧情结构步骤或局部详情中。
7. 后续结构化剧情、分镜、候选图和排版任务逐步改为章节级。

## 7. 不做

- 不把章节只做成 Markdown 标题解析。
- 不把章节列表做成全局左侧导航。
- 不在剧本页常驻展示“当前章节 / 故事主线 / 出场角色 / 场景列表”最右侧信息面板。
- 不把项目级角色、世界观和共享素材复制到每个章节目录。
- 不让前端直接操作本地物理路径。
