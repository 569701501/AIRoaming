# 图片 Prompt 专业 V2 模板与编译规则

## 1. 当前结论

专业 V2 已完成代码编写、第一轮独立静态复核和 R4.1 返工。由于用户明确停止图片生成，真实图片 A/B 因预算延期并禁止执行。

R4 发现的测试版本混用已经修正：A/B 命令必须显式选择 V1 或 V2，两个版本使用独立账本和摘要。动态镜头合同已改为结构化语义，再由 OpenAI/Grok 编译成英文、Doubao 编译成中文。Grok 单参考图和群像参考上限继续存在，但评测例外已明确冻结。详细证据见任务记录 `evidence/r4.1-remediation-evidence.md`。

本次保持不变：

- 页面字段；
- 数据库 Schema；
- 用户确认节点；
- 分镜字段；
- 漫画静态图与漫剧动态 Prompt 的职责边界。

生产新任务默认使用 V2；冻结的 V1 编译器继续保留，供同语料真实 A/B 和历史兼容。

## 2. 版本标识

| 类型 | V1 | V2 |
| --- | --- | --- |
| OpenAI 候选图 | `openai-image-instruction-v1` | `openai-comic-clean-plate-v2` |
| Doubao 候选图 | `doubao-image-instruction-v1` | `doubao-seedream-comic-clean-plate-v2` |
| Grok 候选图 | `grok-image-instruction-v1` | `grok-comic-clean-plate-v2` |
| 角色/场景参考图 | 旧模板可显式调用 | 默认使用 V2 模板 |

V1 的行为是：把领域 `positivePrompt` 原样投递。

V2 的行为是：读取同一组领域分段和镜头合同，分别编译成适合三家 Provider 的最终制作简报。

## 3. 角色预览图 V2

### 3.1 目标

建立一个后续可重复使用的角色身份种子，不追求戏剧海报效果。

### 3.2 模板结构

```text
INTENDED USE
Create one clean front preview portrait that will become the stable identity seed for a comic/manhua character library.

IDENTITY SEED
- 建立稳定脸型、五官、发型轮廓、年龄感、体型、服装结构、固定配色和关键配饰。
- 身份可重复性优先于特效、复杂背景和戏剧动作。

CHARACTER FACTS
- 项目类型
- 作品名
- 题材标签
- 漫画形式
- 美术风格
- 角色名
- 角色身份
- 外貌设定
- 性格气质
- 固定视觉特征

COMPOSITION
- 准确一个角色、正面、半身、中性可读表情、均匀光线、浅色纯背景。
- 脸、双肩、发型轮廓和主要服装结构完整可见。

OUTPUT CONTRACT
- 只能是绘制感漫画角色设计，不是真人照片、演员定妆照、电影剧照、Cosplay 或 3D。
- 无文字、标志、水印、额外人物、场景背景、裁脸、动作姿势、联系表或拼贴。
```

## 4. 角色四视图定稿 V2

### 4.1 目标

使用已经确认的角色预览图作为严格身份来源，生成可供后续候选图引用的定稿组合图。

### 4.2 模板结构

```text
INTENDED USE
Create one clean final character reference sheet for a comic/manhua production pipeline.
Use the supplied preview image only as the strict identity source.

IDENTITY LOCK
- 必须保持：脸型、五官、发型轮廓、年龄感、身体比例、服装结构、固定配色、关键配饰和气质。
- 只允许为了四视图改变：姿势、裁切和观察方向。
- 忽略参考图中的：背景、标签、边框、裁切、联系表排版和灯光设置。

CHARACTER FACTS
- 项目和角色正式事实

LAYOUT
- 单张图准确包含四个分离视图，固定顺序：正面半身、正面全身、侧面全身、背面全身。
- 四个视图必须是同一角色、同一套服装。
- 三个全身视图使用相同比例和基线，清楚展示手、鞋、服装层次和固定配饰。

OUTPUT CONTRACT
- 绘制感漫画角色设定图。
- 无文字标签、尺寸标注、颜色名、标志、水印、额外角色、重复视图、遮挡身体的道具、裁肢、戏剧动作或场景背景。
```

## 5. 场景参考图 V2

### 5.1 目标

生成可供不同机位和镜头裁切重复使用的空间身份资产，不生成带人物的剧情插图。

### 5.2 模板结构

```text
INTENDED USE
Create one reusable environment reference image for a comic/manhua production pipeline.
This is a clean background identity asset, not a story panel or concept-art poster.

ENVIRONMENT IDENTITY
- 场景名
- 地点
- 剧情用途

SPATIAL CONTRACT
- 中性广角建立机位。
- 前景、中景、背景清楚。
- 建筑关系、地平线、透视、稳定地标、入口和出口明确。
- 保留后续放置人物以及远、中、近景裁切的空间。

LIGHTING AND ATMOSPHERE
- 时间
- 氛围
- 固定一个主光方向、色温、天气线索和可见层级。

STYLE
- 项目画风与漫画版式提示。
- 绘制感漫画背景，不是真人摄影、Cosplay 或 3D。

OUTPUT CONTRACT
- 准确一个环境、零人物；无人群、路人、剪影、人形倒影、人物肖像或作为主体的车辆。
- 无戏剧动作、可读招牌、文字、数字、UI、标志、水印、气泡、边框、网格、拼贴或联系表。
```

## 6. 漫画静态候选图共享输入

V2 不读取对白、旁白、漫剧动态描述或旧 `promptDraft`。继续只读取：

| 领域输入 | 用途 |
| --- | --- |
| `scene` | 场景身份、地点、时间、氛围 |
| `characters` | 当前镜头角色名和稳定外观 |
| `comic.panelDescription` | 一个可画的静态决定性瞬间 |
| `coreAction + emotion` | 动作归属和情绪 |
| `comic.composition` | 人物位置、视觉重心和负空间 |
| `shotType + cameraAngle` | 景别和机位 |
| `artStyle` | 项目漫画画风 |

## 7. 五类镜头合同

### 7.1 无角色环境镜头

```text
人物数量：画面中必须是零人物，不出现人群、路人、剪影、倒影中的人或以人物为主体的车辆驾驶者。
环境建立：场景地标、出入口、前中后景和主光方向必须清楚，保留后续放置人物和裁切镜头的空间。
```

### 7.2 单人镜头

```text
人物数量：画面中只能出现一个指定角色；不得复制角色或添加路人。
动作归属：只有该角色执行分镜动作，手部、视线和道具关系必须对应正式 coreAction。
单人调度：姿态、表情和身体取景遵循镜头描述；站位与留白遵循正式 composition。
```

### 7.3 双人镜头

```text
人物数量：准确出现两个指定角色，每人只出现一次，不得合并身份或添加第三人。
动作主客体：保持 coreAction 中的发起者、承受者和反应者，不得交换谁在行动、谁在被影响。
双人调度：左右、前后、视线轴、接触点与负空间遵循正式 composition。
```

### 7.4 多人镜头

```text
人物数量：准确出现 N 个指定角色；不得漏人、复制、合并身份或添加路人。
群像调度：逐人保持身份、服装、相对站位和叙事职责。
动作关系：保护、阻拦、对抗或协作关系不得互换角色职责。
```

### 7.5 动作、光效与环境特效

所有镜头均附加：

```text
可视事件：只呈现动作最清晰的一个决定性瞬间，不在一张图中并列动作前、动作中和动作后的多个时间状态。
特效因果：如果包含光线、电力、天气、烟雾、爆炸或环境变化，只呈现一个明确来源、可见影响和受影响对象；主光方向必须与事件一致。
```

这是条件合同，不要求普通对话镜头凭空增加特效。

## 8. OpenAI V2 编译顺序

```text
INTENDED USE
SCENE AND BACKGROUND
SUBJECTS AND IDENTITY
KEY VISUAL MOMENT
ACTION AND EMOTION
COMPOSITION AND PLACEMENT
CAMERA
STYLE
SHOT-SPECIFIC CONTRACT
OUTPUT REQUIREMENTS
```

主要特点：

- 标签化制作简报；
- 先场景，再主体，再关键动作和细节；
- 人物身体取景、视线、手部、道具和位置由正式分镜字段提供；
- 输出合同明确单图、单场景、单时刻、无文字和无分格。

## 9. Doubao / Seedream V2 编译顺序

```text
用途
场景环境
人物主体
关键画面瞬间
动作与情绪
构图与人物位置
景别与机位
漫画画风
当前镜头合同
硬性成图要求
```

主要特点：

- 使用简洁中文自然语言；
- 主体、动作和环境优先；
- 不复制 OpenAI 的长英文制作合同；
- 不堆砌通用质量形容词；
- 候选图使用正式 `1536×1024` 或 `1024×1536`，不再改成 16:9 或 9:16；
- 请求参数固定 `watermark=false`。

## 10. Grok V2 编译顺序

```text
TASK
SCENE
SUBJECTS
VISIBLE MOMENT
ACTION
PLACEMENT
CAMERA
STYLE
SHOT RULES
HARD CONSTRAINTS
```

主要特点：

- 开头直接要求一张无边框完整漫画图，不是拼贴或漫画页；
- 明确准确人物数量、动作主客体和禁止额外人物；
- 多参考图最多三张；
- 参考图超限时按人物身份和场景优先级确定性选择并产生 warning；
- 单参考图与目标比例冲突仍保留显式降级 warning，尚未伪装为已彻底解决。

## 11. 参考图职责 V2

参考图选择完成后，Provider 网关按实际使用顺序追加职责说明。

### 11.1 角色身份参考

```text
图 N / Image N 只提供指定角色身份。

必须保持：
- 脸型与五官
- 发型轮廓
- 年龄感与身体比例
- 服装结构和固定配色
- 关键配饰

允许变化：
- 姿势
- 表情
- 机位
- 裁切

必须忽略：
- 参考图白底
- 标签和文字
- 边框
- 联系表或四视图排版
```

### 11.2 场景空间参考

```text
图 N / Image N 只提供场景空间身份。

必须保持：
- 稳定地标
- 入口和出口
- 前后空间关系
- 材质
- 主光方向

允许变化：
- 当前分镜机位
- 当前分镜裁切

必须忽略：
- 参考图人物
- 文字
- 边框
- 排版
```

参考图不能覆盖主 Prompt 中的人物数量、动作主客体、站位和决定性瞬间。

## 12. 成图硬合同

三家 Provider 使用不同措辞，但必须表达同一组生产要求：

1. 只生成一张完整画面；
2. 一个场景、一个静态瞬间、一个机位；
3. 保持人物、服装、道具、场景地标、空间关系和光向一致；
4. 主体层级和前中后景清楚；
5. 保留后续排版负空间；
6. 无文字、字母、数字、标志、水印、UI、字幕、说明框、气泡或拟声词；
7. 无多格、分屏、边框、网格、拼贴、联系表或角色设定表；
8. 绘制感漫画插画，不是真人摄影、Cosplay 或 3D。

## 13. V1 / V2 与历史任务

- V1 编译器没有删除；
- 新任务默认编译 V2；
- DB 任务继续冻结 `providerType`、`profileId` 和实际 `providerPrompt`；
- 已创建任务继续使用自己冻结的旧 Prompt，不会在运行时被 V2 悄悄替换；
- `positivePrompt` 继续保留为领域审计和页面预览；
- V2 实际投递 Prompt 由相同 `sections + systemConstraints` 编译；
- `systemConstraints` 中的镜头任务使用版本化结构合同，不再依赖中文自然语言前缀解析；
- 领域规格摘要加入 sections 和镜头合同，避免语义变化后摘要不变。

## 14. 当前验证结果

已完成：

- V1 / V2 双版本可独立编译；
- 3 个参考资产模板；
- 5 类固定候选镜头；
- 15 个 V2 Provider Profile；
- 三家最终 Prompt 互不相同；
- Prompt 长度在离线门槛内；
- 参考图职责按 Provider 语言编译；
- Doubao 关闭水印；
- Doubao 候选图保持 3:2 / 2:3 目标尺寸；
- DB Prompt 冻结链和候选图合同集成回归通过。
- V1、V2 真实测试入口、账本、slot id 和 Prompt manifest 已完全隔离；双版本 dry-run 均为 0 次真实请求。

尚未完成：

- 真实 V1/V2 图片质量比较；
- OpenAI 当前端点 503 是否恢复；
- Grok 单参考图目标比例与参考保真的两全策略；
- 多人物在三家 Provider 中的真实漏人、串脸和串色结果；
- 连续三格角色与场景一致性的真实视觉评测。

因此当前只能判断“V2 Prompt 已写好并通过离线合同”，不能判断“V2 成图质量已经通过”。

完整 V1/V2 计划各 30 次、合计最多 60 次 Provider 图片请求；必须在用户明确同意请求上限后才能执行。

2026-07-17 用户已明确当前无图片生成预算，因此上述计划仅保留为未执行证据。在用户未来重新给出明确预算授权前，不得调用任何图片 Provider；当前结论限于“V2 代码和离线合同通过，真实成图质量未验证”。
