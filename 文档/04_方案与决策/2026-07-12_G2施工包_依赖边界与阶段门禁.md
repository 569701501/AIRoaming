# G2 施工包：依赖边界与阶段门禁

## 1. 文档定位

本文冻结 G2 每个施工切片的真实前置、允许范围、阻塞条件和完成口径。开发模型必须先按本文判断能否开工，不能因 Prisma Schema 中存在表就把对应 runtime 视为已实现。

本文优先级：

1. ADR-0012/ADR-0013 决定长期方向。
2. 本文决定 G2 实施期依赖和切片门禁。
3. G2 主方案决定领域行为。
4. 当前代码只说明现状，不覆盖已采纳契约。

## 2. 状态词

| 状态 | 含义 |
| --- | --- |
| `ready` | 当前代码已提供该能力，可直接依赖并必须复用 |
| `slice_owned` | 当前 G2 切片负责实现，退出时必须完成 |
| `integration_blocked` | 可先开发纯逻辑或手工命令，但涉及该依赖的集成验收不得宣称通过 |
| `release_blocked` | 不阻止本地切片开发，但阻止 DB-only 生产发布 |
| `deferred` | 不属于 G2，本阶段不得顺手实现 |

## 3. 当前基线

### 3.1 已存在且必须复用

| 能力 | 状态 | G2 使用方式 |
| --- | --- | --- |
| Prisma 6.19.3、44 模型、0001～0008 migration | `ready` | G2 只追加 `0009_g2_version_freshness_overlay`，不重建 G1 基线 |
| Chapter/Script/Story/Storyboard/Preflight/Task/Source 等表和基础字段 | `ready` | 不重复 ADD COLUMN，不新增同义表 |
| current 指针作用域、formal history immutable、projection seal 等 G1 trigger | `ready` | G2 overlay 只补 active pending、CAS、V2、current source 与 gate |
| Project/Chapter/Script DB 最小写入与重启读回 | `ready` | G2-B 从此垂直切片扩展，不重新设计项目持久层 |
| G0 临时根、Nest Service fixture、Playwright 进程隔离、loopback fake provider | `ready` | 扩展而不是另建第二套 harness |
| `GenerationTaskSource` sourceProjection seal 及 G1 task SQL 状态机 | `ready_schema_only` | 可写合同测试；运行时 claim/worker 尚不能作为通过证据 |

`ready_schema_only` 不是可执行 runtime 状态。它仅表示表和 trigger 已物化。

### 3.2 尚未接线

| 能力 | 当前状态 | 对 G2 的影响 |
| --- | --- | --- |
| SQLite 持久 Task/Attempt worker、claim、lease、heartbeat、recovery | 未实现 | 阻塞 G2-C/D 的真实 AI 任务回写验收和 G2-F worker 故障验收 |
| G1 maintenance importer/cutover | 未实现 | 阻塞 G2 migration/importer 用例与生产切换 |
| CharacterVisual/SceneVisual/Asset 的完整 DB runtime | 未实现 | 阻塞 Preflight 聚合来源的完整 DB 集成验收 |
| SecretStore、Outbox、协调备份与真实 DB-only 切换 | 未实现 | 阻塞生产发布，不阻塞纯 G2 文档/逻辑/临时库切片 |
| Story/Storyboard/Preflight DB Repository | 未实现 | 属于 G2-C/D/E 的 `slice_owned` 范围 |

## 4. 切片依赖矩阵

| 切片 | 可立即开始 | 本切片负责 | 明确不负责 | 退出状态 |
| --- | --- | --- | --- | --- |
| `G2-A0` Codec/JCS/Resolver | 是 | Shared strict codec、JCS、SourceSnapshot 类型、Freshness/production state 纯函数 | DB 写入、worker、UI | 可独立完成 |
| `G2-A1` DB overlay/Repository substrate | 是 | 0009 overlay、错误映射、版本事务重试器、查询 Repository | importer、持久 worker | 可独立完成 |
| `G2-B` Script Working Copy/publish | 是 | Script API、Chapter CAS、版本分配、发布/还原/清空、重启读回 | AI task runtime | 可独立完成 |
| `G2-C1` Story 手工 Working Copy/confirm | G2-A/B 后 | pending CRUD、projection、confirm、历史、freshness | `story_parse` worker 执行 | 可完成手工路径 |
| `G2-C2` `story_parse` 任务集成 | 否 | Task 创建与 applicability 写回 | 实现通用持久 worker | `integration_blocked`，等待 G1 persistent task runtime |
| `G2-D1` Storyboard 手工 Working Copy/confirm | G2-C1 后 | pending CRUD、stable Shot ID、retire、projection、历史 | `shot_generate` worker 执行 | 可完成手工路径 |
| `G2-D2` `shot_generate` 任务集成 | 否 | Task policy 与目标写回 adapter | 实现通用持久 worker | `integration_blocked` |
| `G2-E1` ProductionState/Workflow/NewWorkGate | G2-C1/D1 后 | 服务端派生、API、前端只展示 | Preflight 完整视觉聚合 | 可完成版本链路径 |
| `G2-E2` Preflight confirm | 部分 | preview/confirm、事务复核、history | CharacterVisual/SceneVisual/Asset DB 接管 | 纯 codec/query 可做，完整 DB 集成被阻塞 |
| `G2-F1` 并发/重启/浏览器路径 | 对已完成手工路径可做 | CAS、响应丢失、双页面、重启读回、Playwright | lease/worker/importer | 可部分完成，证据必须标明覆盖范围 |
| `G2-F2` worker/importer 故障矩阵 | 否 | G2 特有 applicability/barrier 用例 | G1 worker/importer 本体 | `integration_blocked` |

## 5. 允许的并行开发边界

以下可并行：

- Shared codec/Resolver 与 0009 overlay 合同测试。
- API DTO 定义与 Server Repository 接口定义。
- 前端 production state 展示与后端只读 DTO，在 DTO 已冻结后并行。

以下必须串行：

```text
G2-A0/A1
  -> G2-B
  -> G2-C1
  -> G2-D1
  -> G2-E1/E2
  -> G2-F1
```

理由：每层正式来源必须引用上一层 current；不能用 mock current 指针冒充上一切片已经完成。

## 6. G1 与 G2 的所有权边界

### 6.1 G1 所有

- 44 模型与基础字段。
- 通用 Task/Attempt/Slot/Source SQL 状态机。
- 通用 PersistentTaskWorker、claim/lease/heartbeat/recovery/cancel。
- importer、MigrationRun/Issue、cutover 和 production activation。
- Asset/Outbox/SecretStore 的通用 DB runtime。

### 6.2 G2 所有

- Script/Story/Storyboard/Preflight 的 runtime codec 与摘要。
- active pending 生命周期、pending CAS 和版本发布事务。
- current/source/freshness/production state。
- Story/Storyboard write target binding 的业务 adapter。
- `story_parse/shot_generate/shot_prompt_generate/image_generate` 的 NewWorkGate 和 applicability 规则。
- V1 active pending 到 V2 的显式重编码命令。

### 6.3 禁止跨界

- G2 不得复制一套 Task 表、内存持久队列或第二个 lease 实现。
- G2 不得自建 importer 替代 G1 maintenance importer。
- G2 不得为通过测试创建假 Asset/Visual 权威表。
- G1 persistent worker 不得内置 Story/Storyboard 领域判断；它只能调用 G2 的 policy/gate/adapter。

## 7. 开发与发布的两套门禁

### 7.1 本地开发门禁

开发 G2-A0～D1 只要求：

1. 正式 0001～0008 fresh deploy 通过。
2. 临时 SQLite、临时 workspace/data root、无真实 key。
3. DB mode 显式开启。
4. 每个写切片提供 CAS、回滚和进程重启读回证据。

### 7.2 生产发布门禁

G2 上线真实项目之前必须同时满足：

- G1 persistent worker 已接线并完成 lease/recovery/cancel 证据。
- G1 Asset/Outbox/SecretStore 与 importer/cutover 已完成。
- 0009 migration 在真实数据副本 dry-run。
- G2-F 全量 worker/importer/用户路径验收通过。
- `PersistenceState` 达到允许 activation 的状态；不得仅修改环境变量强开。

## 8. 开发模型任务书规则

交给开发模型的每个任务必须只包含一个切片，并写明：

```text
目标切片
允许修改文件
必读施工资料
明确前置状态
禁止实现的相邻能力
退出测试命令
残留 integration_blocked 项
```

禁止使用以下任务书：

```text
按照 G2 文档完成全部功能。
把所有测试跑绿。
缺什么自己补什么。
```

## 9. 完成判定

G2 总体只能在所有 `integration_blocked` 项转为真实通过后标记完成。部分切片完成时，完成记录必须使用 `G2-B completed`、`G2-C1 completed` 等精确名称，不能写“G2 已完成”。
