# G3 施工包：数据库 Overlay 与迁移账本

## 1. 唯一目标

在不修改 G1 0001～0008、不修改 G2 0009、不重建 `projects` 表的前提下，为 `Project.comicFormat` 增加“任何 UPDATE 语句只要包含该列就拒绝”的 SQLite 硬约束，并让 DB runtime 精确验证 0001～0010 的 artifact 与 `_prisma_migrations` ledger。

G1 0008 已提供：

- `comic_format TEXT NOT NULL`；
- 无数据库默认值；
- `ck_projects_comic_format` 两值 CHECK。

G3 只补不可变 trigger，不重复已有约束。

## 2. Migration 身份

```text
directory: apps/server/prisma/migrations/0010_g3_comic_format_immutable/
file:      migration.sql
name:      0010_g3_comic_format_immutable
provider:  sqlite
owner:     G3-A1
```

固定对象：

```text
trigger: trg_g3_projects_comic_format_immutable
error:   AIR_G3:COMIC_FORMAT_IMMUTABLE
```

不得使用时间戳目录，不得改名为通用 `project_update_guard`，不得把 SQL 合并回 0008 或 0009。

## 3. SQL 合同

`migration.sql` 固定为一个 trigger 语义：

```sql
CREATE TRIGGER "trg_g3_projects_comic_format_immutable"
BEFORE UPDATE OF "comic_format" ON "projects"
BEGIN
  SELECT RAISE(ABORT, 'AIR_G3:COMIC_FORMAT_IMMUTABLE');
END;
```

使用 `BEFORE UPDATE OF comic_format`，不加 `WHEN NEW... IS NOT OLD...`。因此以下两种语句都失败：

```sql
UPDATE projects SET comic_format = 'paged_comic' WHERE id = ?;
UPDATE projects SET comic_format = comic_format WHERE id = ?;
```

目的：API 同值 PATCH 也要暴露旧客户端；底层脚本若把不可变字段无差别放入 SET，即使值相同也必须修正调用方，而不是被数据库静默接受。

以下更新不触发 G3 trigger：

```sql
UPDATE projects SET current_chapter_id = ? WHERE id = ?;
UPDATE projects SET name = ?, row_version = row_version + 1 WHERE id = ?;
```

所以现有 create transaction 在插入默认 Chapter 后只更新 `current_chapter_id`，仍可继续工作。

## 4. 精确对象计数

```text
new tables   = 0
new columns  = 0
new indexes  = 0
new checks   = 0
new triggers = 1
rebuilds     = 0
temp objects = 0
```

禁止为一个 trigger 建新的 manifest generator、review bundle、签名、CAS 或写入 CLI。只使用轻量常量、SQL shape 检查、SQLite inspection 与 ledger checksum。

新增：

```text
apps/server/src/persistence/g3-overlay-contract.ts
apps/server/src/persistence/g3-overlay-contract.spec.ts
```

导出固定接口：

```ts
export const G3_OVERLAY_MIGRATION_NAME =
  "0010_g3_comic_format_immutable" as const;

export const G3_OVERLAY_TRIGGER_NAMES = [
  "trg_g3_projects_comic_format_immutable",

  migrationRoot?: string,

```

`assertG3OverlaySqlShapeV1` 至少断言：

1. `CREATE TRIGGER` 恰好 1 个。
2. 不含 `CREATE/ALTER/DROP TABLE`、`CREATE INDEX`、`ADD COLUMN`、`PRAGMA writable_schema`。
3. trigger 名、table、`BEFORE UPDATE OF "comic_format"` 和 error token 精确匹配。
4. 不含 `WHEN NEW."comic_format" IS NOT OLD...`，确保同值 SET 也拒绝。

`inspectG3OverlayV1` 只查询 `sqlite_master` 中 `trg_g3_%`；结果必须恰好等于固定 trigger 集合。测试同时比较 migration 前后的 table/column/index/check 集合完全相等。

## 6. Runtime migration chain

### 6.1 固定链

```ts
export const G3_RUNTIME_MIGRATION_NAME =
  "0010_g3_comic_format_immutable" as const;

export const G3_RUNTIME_MIGRATION_NAMES = [
  ...G2_RUNTIME_MIGRATION_NAMES,
  G3_RUNTIME_MIGRATION_NAME,
] as const;
```

新增：

```text
apps/server/src/persistence/g3-runtime-migration-ledger.ts
apps/server/src/persistence/g3-runtime-migration-ledger.spec.ts
```

职责：

- 复用 `loadG2RuntimeMigrationExpectationsV1()` 读取 0001～0009 checksum。
- 对 0010 做单链接普通文件检查并计算 SHA-256。
- `_prisma_migrations` 必须恰好 10 行且名称、checksum、成功状态精确匹配。
- 缺失 0010 返回 `DB_PERSISTENCE_G3_MIGRATION_LEDGER_MISSING:0010_g3_comic_format_immutable`。
- 任意额外行返回 `DB_PERSISTENCE_G3_MIGRATION_LEDGER_UNEXPECTED:<name>`。

必须新增可运行入口：

```ts
export async function assertG3RuntimeMigrationReadyV1(
  client: MigrationLedgerClient,
): Promise<void>;
```

它读取 `_prisma_migrations` 后调用 exact ledger assertion；不能只写 unit helper 而不接 runtime。

### 6.2 G1 exact check 的最小适配

当前 G1 artifact/ledger 只识别 0009 为 post-G1 overlay。实施 0010 时以下两处必须把已知 overlay allowlist 固定为：

```ts
const KNOWN_POST_G1_MIGRATION_NAMES = [
  "0009_g2_version_freshness_overlay",
  "0010_g3_comic_format_immutable",
] as const;
```

改动文件：

```text
apps/server/src/persistence/g1-runtime-migration-ledger.ts
apps/server/src/persistence/g1-runtime-migration-ledger.spec.ts
apps/server/src/persistence/g1-migration-plan.ts
apps/server/src/persistence/g1-migration-plan.spec.ts
```

规则：

- G1 base 检查在比较根目录时只过滤上述两个固定名字。
- G1 base ledger 在统计八段时只忽略上述两个固定名字。
- 任意 `0011_*` 或未知目录仍然失败，不能改成“过滤所有大于 0008”。
- G1 八段 checksum、Schema manifest、195 CHECK/194 trigger 计数不变。

G2 独立 ledger 测试仍验证精确九段 fixture；G3 runtime 使用新十段 guard，不把 G2 helper 改成可接受任意后续行。

### 6.3 PrismaService 激活

修改：

```text

```

G3-core 合并时：


映射表：

| 未识别的 `AIR_G3:*` | `500 G3_DATABASE_CONTRACT_VIOLATION` |
| 其他 Prisma/SQLite 错误 | 交给现有通用错误链，不伪装成 immutable |

响应不得包含 SQL、数据库 URL、物理路径、Prisma stack 或整个 request body。

## 8. Repository 约束

- `ProjectRepository.toDatabaseComicFormat/fromDatabaseComicFormat` 不再做 `page_horizontal <-> paged_comic` 转换；DB 读写都调用 strict canonical parser。
- Create 的第一条 `project.create` 显式写入 canonical 值。
- create transaction 后续 `project.update` 只能更新 `currentChapterId`，不得重复带 `comicFormat`。
- 未来 metadata update 的 data object 必须省略 `comicFormat`，不能传当前值。
- trigger 失败时整个 transaction 回滚；Project rowVersion/updatedAt、Chapter 和 G2 来源均不变化。

## 9. 最小测试矩阵

### 9.1 SQL shape/inspection

```text
DB-001: SQL 只有 1 trigger、无其他 DDL
DB-002: fresh 0001～0009 后应用 0010 成功
DB-003: sqlite_master 只有固定 G3 trigger
DB-004: projects table/column/index/check 集合前后相等
DB-005: migration 不留 temp object
```

### 9.2 不可变行为

```text
DB-010: vertical -> paged 失败
DB-011: paged -> vertical 失败
DB-012: vertical -> vertical 的显式 SET 失败
DB-013: paged -> paged 的显式 SET 失败
DB-014: name/currentChapterId 的 UPDATE 成功
DB-015: 失败前后 comicFormat/rowVersion/updatedAt 相等
DB-016: Project + default Chapter create transaction 成功
```

`rowVersion` 由测试直接查询 SQLite，不要求扩展公开 Project DTO。

### 9.3 Ledger/startup

```text
LED-001: exact 0001～0010 通过
LED-002: 缺 0010 失败
LED-003: 0010 checksum 漂移失败

LED-005: 额外 0011 行失败
```

## 11. 回滚

- 0010 尚未部署：可回滚代码和 migration 文件。
- 0010 已部署但没有 G3 新项目：恢复 0010 前完整临时/协调备份，或运行理解 0010 的兼容构建；不手写 down migration 后继续运行旧应用。
- 已有 `paged_comic` Project：禁止回到会把未知值默认成 vertical 的旧构建。
- DROP trigger 只允许离线诊断副本；不得成为生产回滚方案。

## 12. 完成判定

G3-A1 只有在以下全部满足时完成：

- 0010 SQL 与对象计数精确。
- overlay shape/inspection 通过。
- G1/G2/G3 artifact 与 ledger 测试通过。
- `PrismaService` 使用 G3 十段 guard。
- direct SQL 同值/异值 SET 均失败，非 comicFormat 更新与 Create transaction 成功。
- 无 G1 manifest 重写、无新 reviewer/CAS 流程、无真实数据库写入。
