# 模型管理重构方案

## 1. 问题诊断

### 1.1 当前架构的混乱点

```
┌─ 旧系统（固定槽位） ──────────────────┐
│ aiKey: {providerId, modelId, ...}    │
│ openaiImageProvider                  │
│ doubaoImageProvider                  │
│ grokImageProvider                    │
│ runwareImageProvider                 │
│ activeImageProvider                  │
└──────────────────────────────────────┘
         ↓ 同步逻辑 ↓
┌─ 新系统（模型管理） ──────────────────┐
│ models: ManagedModelItem[]           │
│ activeTextModelId                    │
│ activeImageModelId                   │
└──────────────────────────────────────┘
```

**核心问题**：
1. 双轨并行导致同步逻辑复杂（`syncActiveTextModelWithAIKey` 592行，`syncActiveImageModelWithProvider` 588行）
2. 凭证解析有5层回退逻辑，难以追踪
3. DB模式与文件模式存储方式不同，运行时要区分处理
4. 用户在"AI密钥"tab配置后，要自动同步到"模型管理"tab，概念重叠

### 1.2 典型Bug场景

**场景1：用户在"AI密钥"配置了gpt，但对话提示"未配置密钥"**
- 原因：`getRuntimeAIKeySettings()` 优先读 `activeTextModelId` 对应的model
- 如果model列表为空，activeTextModelId=null，但aiKey有配置
- 解决：现在有回退逻辑（195行），但初次使用时models=[]，需要触发一次同步

**场景2：在"模型管理"添加了新模型，但运行时用不了**
- 原因：模型自己的 `secretRef/keyFingerprint` 为空
- 同providerId的固定槽位也没配置
- 解决：需要在UI明确提示"未配置密钥，切换前请先编辑补充"

**场景3：DB模式下模型凭证无法保存**
- 原因：DB模式下不支持 `ManagedModel` 的独立凭证（只能共享 ProviderConfig 行）
- 抛出 `MANAGED_MODEL_SECRET_UNSUPPORTED_IN_DB`
- 用户体验差：不理解为什么有时候能保存密钥，有时候不行

## 2. 重构目标

### 2.1 原则

1. **单一职责**：模型管理只管模型列表，凭证管理独立抽取
2. **统一入口**：废弃"AI密钥"/"图片生成"tab，只保留"模型管理"（或保留但改为只读）
3. **透明映射**：DB模式与文件模式的差异封装在 `CredentialStore` 层，上层无感
4. **明确回退**：凭证解析回退链路简化为2层：模型自己的凭证 → 全局默认凭证

### 2.2 非目标（本期）

- 不破坏现有对话/图片生成功能
- 不改变数据库schema（凭证仍用 `ProviderConfig` + `CredentialMetadata`）
- 不要求用户重新配置（兼容升级）

## 3. 重构方案

### 3.1 阶段1：抽取 CredentialService（本周完成）

**目标**：把凭证存取逻辑从 `SettingsService` 中抽离

```typescript
// apps/server/src/settings/credential.service.ts

export interface CredentialDescriptor {
  owner: 'model' | 'legacy_slot';  // 凭证归属
  scopeId: string;                 // modelId 或 固定槽位key
  providerId: string;
  kind: 'text' | 'image';
}

@Injectable()
export class CredentialService {
  /**
   * 统一凭证存储入口
   * - 文件模式：写 SecretStore，返回 secretRef
   * - DB模式：写 ProviderConfig.CredentialMetadata，返回 keyFingerprint
   */
  async storeCredential(
    descriptor: CredentialDescriptor,
    apiKey: string,
  ): Promise<{ secretRef: string | null; keyFingerprint: string }> {
    const fingerprint = fingerprintSecret(apiKey);
    
    if (this.prismaService?.isDatabaseMode()) {
      // DB模式：写到 ProviderConfig 行
      const providerConfig = await this.ensureProviderConfig(descriptor);
      await this.updateCredentialMetadata(providerConfig.id, apiKey, fingerprint);
      return { secretRef: null, keyFingerprint: fingerprint };
    } else {
      // 文件模式：写 SecretStore
      const credentialId = this.buildCredentialId(descriptor);
      const secretRef = await this.secretStore.set(credentialId, apiKey);
      return { secretRef, keyFingerprint: fingerprint };
    }
  }

  /**
   * 统一凭证读取入口
   * - 文件模式：从 SecretStore 读
   * - DB模式：从 ProviderConfig 读
   */
  async retrieveCredential(
    descriptor: CredentialDescriptor,
    storedRef: { secretRef: string | null; keyFingerprint: string | null },
  ): Promise<string | null> {
    if (this.prismaService?.isDatabaseMode()) {
      if (!storedRef.keyFingerprint) return null;
      const providerConfig = await this.findProviderConfig(descriptor.providerId, descriptor.kind);
      if (!providerConfig) return null;
      const metadata = await this.prismaService.database().credentialMetadata.findUnique({
        where: { providerConfigId: providerConfig.id },
      });
      if (!metadata?.configured) return null;
      // DB模式凭证存在 SecretStore，用 providerConfigId 索引
      const secret = await this.secretStore.get(`provider_${providerConfig.id}`).catch(() => null);
      return secret?.reveal() ?? null;
    } else {
      if (!storedRef.secretRef) return null;
      const secret = await this.secretStore.get(storedRef.secretRef).catch(() => null);
      return secret?.reveal() ?? null;
    }
  }

  /**
   * 删除凭证
   */
  async deleteCredential(descriptor: CredentialDescriptor): Promise<void> {
    if (this.prismaService?.isDatabaseMode()) {
      const providerConfig = await this.findProviderConfig(descriptor.providerId, descriptor.kind);
      if (providerConfig) {
        await this.prismaService.database().credentialMetadata.deleteMany({
          where: { providerConfigId: providerConfig.id },
        });
      }
    } else {
      const credentialId = this.buildCredentialId(descriptor);
      await this.secretStore.delete(credentialId).catch(() => undefined);
    }
  }

  private buildCredentialId(descriptor: CredentialDescriptor): string {
    return `${descriptor.owner}:${descriptor.kind}:${descriptor.scopeId}:${descriptor.providerId}`;
  }
}
```

**改造点**：
- `SettingsService.persistManagedModelSecret` → `CredentialService.storeCredential`
- `SettingsService.getRuntimeAIKeySettings` → 调用 `CredentialService.retrieveCredential`
- 删除内存缓存 `runtimeManagedModelSecrets`，凭证按需读取（或在 CredentialService 内部缓存）

### 3.2 阶段2：简化凭证解析链路（下周）

**目标**：把5层回退简化为2层

**当前逻辑**（177-204行）：
```typescript
getRuntimeAIKeySettings(): RuntimeAIKeySettings {
  const activeModel = this.resolveActiveTextManagedModel();
  if (activeModel) {
    // 1. 模型自己的凭证
    const managedKey = (activeModel.secretRef || activeModel.keyFingerprint)
      ? this.runtimeManagedModelSecrets.get(activeModel.id)?.reveal() ?? null
      : null;
    // 2. 同provider复用aiKey凭证
    const sharedKey = activeModel.providerId === this.settings.aiKey.providerId
      ? this.runtimeAIKey ?? this.findMatchingImageCredentialForTextRuntime()
      : null;
    return { ...activeModel, apiKey: managedKey ?? sharedKey };
  }
  // 3. 回退到 aiKey
  const recoveredSharedKey = this.runtimeAIKey ?? this.findMatchingImageCredentialForTextRuntime();
  return { ...this.settings.aiKey, apiKey: recoveredSharedKey };
}
```

**重构后**：
```typescript
async getRuntimeAIKeySettings(): Promise<RuntimeAIKeySettings> {
  const activeModel = this.resolveActiveTextManagedModel();
  const baseConfig = activeModel ?? this.settings.aiKey;
  
  const apiKey = await this.credentialService.resolveRuntimeCredential({
    providerId: baseConfig.providerId,
    kind: 'text',
    modelRef: activeModel ? { secretRef: activeModel.secretRef, keyFingerprint: activeModel.keyFingerprint } : null,
    fallbackRef: this.settings.aiKey.keyFingerprint ? { secretRef: this.settings.aiKey.secretRef, keyFingerprint: this.settings.aiKey.keyFingerprint } : null,
  });
  
  return {
    providerId: baseConfig.providerId,
    modelId: baseConfig.modelId,
    baseUrl: baseConfig.baseUrl,
    apiKey,
  };
}
```

**CredentialService 新增方法**：
```typescript
async resolveRuntimeCredential(params: {
  providerId: string;
  kind: 'text' | 'image';
  modelRef: { secretRef: string | null; keyFingerprint: string | null } | null;
  fallbackRef: { secretRef: string | null; keyFingerprint: string | null } | null;
}): Promise<string | null> {
  // 1. 优先用模型自己的凭证
  if (params.modelRef) {
    const key = await this.retrieveCredential(
      { owner: 'model', scopeId: 'active', providerId: params.providerId, kind: params.kind },
      params.modelRef,
    );
    if (key) return key;
  }
  
  // 2. 回退到全局默认凭证（aiKey 或固定槽位）
  if (params.fallbackRef) {
    const key = await this.retrieveCredential(
      { owner: 'legacy_slot', scopeId: params.providerId, providerId: params.providerId, kind: params.kind },
      params.fallbackRef,
    );
    if (key) return key;
  }
  
  return null;
}
```

### 3.3 阶段3：废弃固定槽位UI（可选，需产品确认）

**选项A：彻底废弃**
- 移除"AI密钥"/"图片生成"tab
- 只保留"模型管理"tab
- 旧数据迁移：首次打开时，自动把 `aiKey` + 4个固定槽位转为 `models[]` 条目

**选项B：改为只读**
- "AI密钥"/"图片生成"tab 改为只读预览
- 引导用户去"模型管理"编辑
- 保留同步逻辑，但标记为 deprecated

**推荐**：选项A，减少维护负担

### 3.4 阶段4：统一DB模式与文件模式（长期）

**目标**：让上层代码完全无感知存储模式

**当前问题**：
- DB模式不支持 `ManagedModel` 独立凭证（抛出 `MANAGED_MODEL_SECRET_UNSUPPORTED_IN_DB`）
- 固定槽位模型不可在模型管理中删除

**方案**：
1. DB模式下，允许每个 `ManagedModel` 独立创建 `ProviderConfig` 行（放宽 providerId 唯一约束，改为 providerId+runtimeKind 复合唯一）
2. 或者：引入 `ModelCredential` 表，与 `ProviderConfig` 解耦

```prisma
model ModelCredential {
  id               String   @id @default(uuid())
  modelId          String   @unique  // 关联 settings.models[].id
  kind             String   // 'text' | 'image'
  providerId       String
  secretRef        String?  // 文件模式用
  keyFingerprint   String?  // DB模式用
  configured       Boolean  @default(false)
  createdAt        DateTime @default(now())
  updatedAt        DateTime @updatedAt
}
```

## 6. 风险与缓解

### 风险1：凭证丢失
- **场景**：重构过程中，现有凭证无法读取
- **缓解**：
  1. 实施前完整备份 SecretStore 和 DB
  2. 先上阶段1（CredentialService），观察1周无问题再继续
  3. 提供回滚脚本

### 风险2：用户习惯变更
- **场景**：用户已习惯"AI密钥"tab，突然消失会困惑
- **缓解**：
  1. 阶段3先改为只读+引导，观察1周反馈
  2. 提供迁移说明文档

### 风险3：性能下降
- **场景**：凭证按需读取，可能增加延迟
- **缓解**：
  1. CredentialService 内部维护内存缓存（TTL 5分钟）
  2. 对话开始时预热缓存
