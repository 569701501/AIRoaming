# ADR-0010 候选定稿修订与下游返修

## 1. 状态

已采纳，尚未实现。

## 2. 背景

当前系统通过 `Shot.lockedCandidateId` 和 Candidate `status=locked` 表达当前图片。用户在已有排版草稿后更换锁定候选时，Shot 会指向新图，但 `PanelPlacement.candidateId` 仍指向旧图；导出后章节进入 `layout_done`，锁定接口又不允许返修。

简单地禁止返修不符合创作工具需求，自动把所有旧图替换为新图又会破坏手工裁切、布局和历史导出。

## 3. 决策

### 3.1 草选不驱动下游

`selected` 不作为正式工作流状态。用户可以收藏多张候选，但排版、导出和素材包只读取当前定稿修订。

### 3.2 定稿使用不可变修订

新增 `CandidateLockRevision`。第一次定稿、每次更换和取消定稿都创建新修订，动作使用 `lock/replace/clear`；`clear` 修订的候选为空。Shot 保存最近一次正式决定的修订指针，旧修订、候选和素材永久保留。

### 3.3 布局绑定来源修订

`PanelPlacement` 记录 `sourceCandidateLockRevisionId`。当它与 Shot 当前修订不同，派生为 stale；不批量改写旧布局。

### 3.4 更换前必须影响预览

更换或取消定稿先计算受影响的格子、布局、导出和运行任务，返回 impact digest。提交时使用当前修订 ID 和 digest 做乐观锁，防止预览后状态变化；digest 使用排序后的规范 JSON 计算，不依赖数据库行顺序或时间戳。

### 3.5 旧导出不可变

导出使用 `ExportRevision` 绑定布局修订和 lock set digest。更换定稿不会修改或删除旧文件；解决 stale 后创建新布局和新导出修订。

### 3.6 长任务绑定输入快照

布局、合成、导出和素材包任务保存来源布局修订与 lock set digest。任务完成时只登记到原始修订；若当前状态已变化，结果作为历史产物，不能自动成为 current。

### 3.7 新鲜度独立于章节单调状态

更换定稿后，候选步骤仍然完成，排版步骤显示 `needs_update`。不通过把 `Chapter.status` 从 `layout_done` 粗暴回退到 `images_done` 表达依赖失效。

## 4. 被否决的备选

### 4.1 否决：只修改 lockedCandidateId

会造成当前锁定和既有 layout placement 来源分叉，且无法追溯返修历史。

### 4.2 否决：自动替换所有下游格子

会静默破坏手工裁切、缩放和自由画布布局，用户无法比较旧版。

### 4.3 否决：一旦进入排版就永久禁止换图

不符合漫画返修路径，迫使用户删除项目或复制整章。

### 4.4 否决：把 selected 当成下游输入

普通预览点击或草选会触发大范围失效，用户无法安全比较候选。

### 4.5 否决：覆盖旧导出

破坏交付物可追溯性，无法证明某次发布使用了哪张候选图。

## 5. 影响范围

- Candidate 状态、收藏和当前定稿语义拆分。
- Shot 从候选 ID 指针升级为当前定稿修订指针。
- LayoutRevision、PanelPlacement 和 ExportRevision 增加来源关系。
- GenerationTask 增加依赖快照和旧结果隔离。
- 工作流增加下游 freshness / needs_update。
- 候选页增加收藏、定稿、更换影响提示。
- 画布增加 stale 格子、逐格/批量替换和历史布局。
- 数据库迁移现有 `selected/locked/lockedCandidateId/layout/export`。

## 6. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 修订表和关系增加实现复杂度 | D7 数据库事务承载；按 D3-A 至 D3-F 分阶段落地 |
| stale 派生计算成本 | 用 lock set digest 快速比较，必要时缓存但不改变事实源 |
| 用户被版本概念困扰 | UI 只用收藏、定稿、来源已更新、历史导出等结果语言 |
| 旧任务仍写回 | 任务来源 digest 校验作为最终防线，不只依赖取消 |

实现后的回滚不能恢复“只改指针”模型，否则会丢失历史关系。可暂时隐藏收藏或历史 UI，但数据库修订记录和旧导出引用必须保留。

## 7. 验证标准

- A→布局→B 不自动改旧格子，相关 placement 显示 stale。
- A→导出→B 保留旧导出，新导出使用 B 的新布局修订。
- B→A 创建第三个定稿修订，不复用或覆盖 v1。
- 并发更换和过期 impact digest 返回 409。
- 运行中的旧导出任务不能覆盖新 current。
- 收藏操作不改变任何下游状态。
- 迁移后现有锁定和布局关系可追溯，无 silent fallback。
