# 竞品设计吸收与轻画布建议

> 状态说明（2026-07-10）：用户已在全项目功能补全决策中选择 D4=B、D5=B，方向调整为“漫画成品形态有边界，但画布编辑高自由；首期只做基础核心能力”。本文关于结构化轻画布和不做自由画布的结论已被替代，不能继续作为开发范围依据；其中竞品证据、追溯和确定性导出原则仍可供后续 D4/D5 方案参考。当前事实源见 `2026-07-10_全项目功能补全研究与决策基线.md`。

## 1. 结论

AI漫游最应该吸收的不是某个竞品的完整页面，而是三套机制：

1. **可回退的生成迭代**：prompt 可编辑、生成形成新批次、旧结果保留、候选可比较和锁定。
2. **漫画成稿编辑**：模板排版、格子调整、裁切、对白与旁白文字层、确定性导出。
3. **跨阶段追溯**：每个成稿元素仍能追溯到章节、分镜、候选图、素材与生成任务。

画布需要做，但建议做成**有限边界、结构化、分页或条漫式的成稿轻画布**，不做无限自由画布，也不把局部修图、绘画和节点工作流塞进同一画布。

这不是额外扩张产品范围。现有产品事实源已经要求“在画布中查看漫画页、调整格子布局、编辑气泡并导出 PNG/PDF”；当前实现只完成了一镜一页预览和原图复制，尚未形成真正可读的漫画成稿。

## 2. 最值得吸收的设计模式

### 2.1 第一优先：LlamaGen + Midjourney 的受控迭代

吸收：

- 编辑 prompt 后生成新批次，不覆盖旧结果。
- 当前批和历史批清晰分开，可恢复、复用和对比。
- 候选具备明确的选择、淘汰、锁定和替换动作。
- 单镜重画、变体和批量重画共享同一套版本语义。
- 后续局部修改采用单图遮罩编辑，不依赖完整排版画布。

AI漫游已有按 `taskId` 分批、旧批保留、重新生成和锁定的骨架，最值得继续补的是 prompt 版本、候选状态命令和替换关系，而不是重新设计整套候选页。

不照搬：

- 不采用只围绕图片图库组织产品的方式。
- 不让“变体按钮”绕过章节、分镜、preflight 和任务追溯。

### 2.2 第一优先：Anifusion + AI Comic Factory 的漫画成稿编辑

吸收：

- 页面或条漫模板先行，用户从可用布局开始，而不是面对空白画布。
- 图片格子与文字/气泡是独立、可序列化的图层。
- 对白和旁白默认从 `Shot.comic.dialogue/caption` 带入，用户可直接修改。
- 页面列表、当前页面画布和属性面板形成清楚的编辑结构。
- “重画此格 / 编辑文字 / 更换布局 / 导出”都是就地操作，减少在多个页面间往返。

不照搬：

- 不在第一版建设无限画布。
- 不追求专业桌面排版软件的全部文字、印刷和图层能力。
- 不把浏览器打印当成唯一导出实现；预览与最终导出应共享同一布局数据和渲染口径。

### 2.3 第二优先：Dashtoon 的成稿到发布闭环

吸收：

- 围绕真实发布渠道提供尺寸、格式和完整性检查。
- 把缺图、溢出文字、低分辨率、未确认页面等问题在导出前集中提示。
- 后续可沉淀渠道预设，而不是让用户每次手填尺寸。

不照搬：

- 当前不做完整无限画布和重型图片编辑器。
- 当前不把内容发布、社区和变现入口并入核心生产链路。

### 2.4 第二优先：Katalist / LTX / Runway 的镜头控制与引用复用

吸收：

- 分镜是可编辑生产单元，不是一次性 AI 输出。
- 角色、场景和风格引用使用稳定名称与版本，可跨镜头复用。
- 上游改变时明确提示会影响哪些候选图、排版页和导出物。

这套思路主要进入分镜、出图准备和素材追溯，不应被误做成漫画排版画布功能。

### 2.5 暂不作为产品界面参考：ComfyUI

可以吸收“底层工作流与用户界面分离”的架构思路，但不建议默认暴露节点画布。AI漫游的核心价值是把复杂工作流压缩成受控章节链路，而不是要求创作者自己接节点。

## 3. 三条画布路线比较

| 路线 | 能解决的问题 | 主要代价 | 判断 |
| --- | --- | --- | --- |
| 无画布 | 一镜一页预览、简单导出 | 无法拼版、处理气泡和阅读节奏，难以形成真实漫画成稿 | 不采用 |
| 结构化轻画布 | 模板拼版、格子调整、裁切、气泡、页面设置、稳定导出 | 需要扩展布局数据和建设统一渲染器，但边界可控 | **采用** |
| 完整自由/无限画布 | 任意图层、自由排版、绘制、复杂修图和大型创作板 | 产品与工程规模接近独立编辑器，移动端、导出一致性和版本恢复成本高 | 当前不采用 |

## 4. 建议的轻画布边界

### 4.1 V1 必须有

1. **页面/条漫列表**：新增、删除、复制、重排；选择模板生成初始布局。
2. **格子编辑**：交换图片、拖动和缩放格子、调整格间距；在格子内移动/缩放源图，支持基础裁切焦点。
3. **文字与气泡层**：对白、旁白、气泡形状、位置、尺寸、字号、对齐和基础尾巴指向；文字可脱离气泡作为标题或音效文本。
4. **结构化属性面板**：选中页面、格子或气泡时只显示对应参数，避免工具堆叠。
5. **撤销、重做、自动保存**：画布操作写入持久化布局草稿，而不是只存在前端内存。
6. **导出前检查**：缺失素材、文字溢出、图片分辨率、页面尺寸和未保存状态。
7. **确定性导出**：预览与导出读取同一布局 JSON；至少完成首个渠道需要的 PNG 产物与 manifest。

### 4.2 V1 不做

- 无限画布和多作品自由拼贴。
- 画笔、橡皮、套索、滤镜、混合模式和 Photoshop 式图层系统。
- AI 工作流节点编辑器。
- 多人实时协作。
- 自动智能气泡避让、自动读序和专业印刷色彩管理。
- 在排版画布内直接 inpaint。
- 视频时间线和动效编辑。

### 4.3 局部重绘的正确位置

局部重绘应放在候选图工作台，作为**单张图片的遮罩编辑弹窗**：

```text
选择候选图 -> 涂抹遮罩 -> 描述修改 -> 生成新候选 -> 对比 -> 锁定/替换
```

结果必须生成新候选和新素材，不原地改写已锁定图片，并记录：

- `sourceCandidateId`
- `sourceAssetId`
- `maskAssetId`
- `taskId`
- 修改 prompt 与 provider 参数

当前 `ImageProviderService.editImage` 只统一支持“参考图 + prompt”，没有统一的 mask 输入契约，因此 inpaint 不能假设已经具备跨 provider 的稳定能力。

## 5. 与现有数据模型的衔接

现有 `LayoutPage.placements: PanelPlacement[]` 已允许一页多个格子，适合向轻画布演进，不需要另建一套互不相干的前端状态。但正式实现前至少需要补齐：

| 对象 | 建议补充 | 原因 |
| --- | --- | --- |
| `PanelPlacement` | 稳定 `id`、裁切/源图变换、层级、可选模板槽位 | 支持稳定选中、撤销和非破坏裁切 |
| `LayoutPage` | `templateId`、页边距/格间距、背景、文字层/气泡层 | 让成稿元素可持久化和复现 |
| 文字/气泡层 | 来源 `shotId`、类型、文本、位置尺寸、样式、尾巴、读序 | 把分镜对白变成可编辑成稿元素 |
| `ChapterLayout` | 修订号、草稿/确认状态、导出快照关系 | 区分持续编辑的布局和已交付版本 |

坐标应基于页面或条漫的固定逻辑尺寸存储，界面缩放只是视图行为，不能反写成不同语义的布局数据。

当前还存在 `Project.comicFormat = vertical_scroll` 与 `LayoutPage.format = vertical_comic` 的命名映射，进入实现前应明确它是有意的表现层映射还是需要统一的领域枚举。

## 6. 推荐落地顺序

### 阶段 A：先让排版产物可编辑、可保存

- 只支持一个首发格式。
- 模板生成多格页面/条漫。
- 格子换图、裁切、顺序、撤销重做和自动保存。
- 建立真实的合成渲染与 PNG 导出，不再复制原图充当页面。

### 阶段 B：补齐漫画成稿语义

- 从分镜带入对白与旁白。
- 增加可编辑气泡/文字层、基础尾巴和字体样式。
- 增加溢出、缺图和分辨率检查。

### 阶段 C：补交付和返修效率

- 按目标渠道增加长图、PNG 序列、ZIP 或 PDF。
- 候选图增加单图遮罩修改和非破坏版本链。
- 根据真实返修数据再决定是否做自动气泡布局、更多模板和高级印刷选项。

## 7. 首个产品决策

实现前只需先确认一个会显著改变布局模型的选择：**首个交付格式是什么**。

- 若目标是线上连载，建议先做 `vertical_scroll`：固定宽度、可变高度的条漫段落，先交付长图或分段 PNG/ZIP。
- 若目标是页漫、审阅或印刷，建议先做固定页尺寸的 `page_horizontal`，并更早处理分页、字体嵌入和 PDF。
- `four_panel` 可建立在固定页模板能力之上，不建议与前两者同时首发。

按当前项目默认格式和降低首版复杂度的原则，建议首版先选 `vertical_scroll`；若实际首发渠道明确要求页漫，再切换为固定页方案。

## 8. 静态复核

### 与产品目标一致性

- 一致：现有核心用户流程明确要求页面画布、格子布局、气泡、页面设置和 PNG/PDF 导出。
- 一致：M3 的退出标准要求已锁定分镜图形成可交付漫画页面，并保留素材追溯。
- 不扩大：本建议把完整自由画布、复杂修图和视频编辑排除在 V1 外。

### 与当前实现一致性

- 可演进：`LayoutPage` 已有多 `placements` 容器，章节布局也已落盘。
- 有缺口：当前构建逻辑固定一镜一页，当前导出仅复制第一张 placement 的源文件。
- 有缺口：`Shot.comic.dialogue/caption` 已存在，但布局层没有文字/气泡实体。
- 有缺口：图片 provider 的 edit 能力未统一 mask 契约，不适合把 inpaint 纳入轻画布 V1。

### 主要风险

- 首发格式不确认，会让固定页和可变高条漫的布局规则相互牵制。
- 若预览和导出使用两套渲染逻辑，字体、换行、裁切和气泡位置会漂移。
- 中文字体授权、字体嵌入、竖排和多语言排版应按交付渠道分阶段处理。
- 布局变更与导出快照如果不分离，用户重新编辑后可能无法复现已交付版本。
