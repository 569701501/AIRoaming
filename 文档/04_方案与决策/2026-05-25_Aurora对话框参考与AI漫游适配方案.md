## 3. 与 AI漫游相同的地方

| 相同点 | AI漫游适配 |
| --- | --- |
| 都是左侧 AI 对话，右侧主工作区 | AI漫游项目工作区可采用左对话框、右步骤文档或工作面板 |
| 都需要按当前阶段注入不同提示词 | AI漫游可为当前 7 步分别定义 `stepKey`、placeholder 和 suggested prompts；2026-06-02 后顶部主流程使用 `image_preflight` 作为候选图前检查阶段，`project_characters` 仅保留为项目资产入口 |
| 都需要附件或素材输入 | 剧本阶段优先支持上传文本文件，后续步骤再扩展图片和素材 |
| 都需要流式输出 | AI漫游可保留 `message.updated`、`message.part.updated`、`session.status`、`session.idle` 这类最小事件 |
| 都需要把 AI 输出落回业务对象 | AI漫游必须通过受控业务工具/API、保存动作或生成任务落库；剧本阶段可由 AI 受控写入章节草稿 |
| 都要避免组件猜协议 | AI漫游应建立 `chatStream.contract.ts` 或同等共享契约 |

## 4. 不能直接搬的地方

| Aurora 能力 | AI漫游处理 | 原因 |
| --- | --- | --- |
| OpenCode 对话运行时 | 迁移最小闭环 | AI漫游第一阶段选择 OpenCode 作为项目对话框 AI Runtime，但只迁移会话、流式输出、模型选择和 provider 配置经验 |
| OpenCode 完整沙盒与代码执行体系 | 暂不迁移 | AI漫游当前不需要让模型直接操作代码仓库、沙盒命令或业务文件 |
| Docker sandbox session | 暂不迁移 | AI漫游当前主链路是漫画创作，不运行用户代码 |
| Phaser 工具回调 | 不迁移 | AI漫游没有 Phaser 画布和游戏场景对象 |
| 子会话 / 子 agent 展示 | 不迁移 | AI漫游已经决定步骤对话隔离，不做完整项目聊天树 |
| 历史会话恢复 | 当前不迁移 | 会增加上下文污染和状态恢复复杂度；AI漫游先做当前步骤主线程 |
| 计费 ledger / provider credential UI | 暂不迁移 | 当前是内部工具，先用本地配置或环境变量 |
| ask_user / show_file / phaser_call ToolBridge | 不直接迁移 | AI漫游更需要剧本导入、灵感生成、章节草稿编辑和生成任务等业务工具 |
| StreamEvent 长期归档 | 不直接迁移 | AI漫游可先保留数据库消息记录和短时 SSE，不需要事件日志体系 |

## 5. Aurora 文档与代码差异

本次回查发现 Aurora 的部分“极简化”结论尚未完全反映在当前代码里，AI漫游不能盲目照搬。

| 差异 | 文档结论 | 当前代码观察 | AI漫游判断 |
| --- | --- | --- | --- |
| 历史恢复 | `聊天链路极简化重构/findings.md` 写到删除历史读取和恢复 | `ChatController` 仍有 `history`、`resume`、`messages` 接口，`AgentChat` 仍有“继续上次”入口 | 当前不迁移历史恢复 |
| 子会话 | 文档写到子 agent / 子会话能力废弃 | `ChatSession` 仍有 `parentSessionId/rootSessionId`，`AgentChat` 仍有子会话视图逻辑 | AI漫游不迁移子会话树 |
| 事件归档 | 文档写到删除 `stream_events` 和事件日志 | schema 中仍有 `StreamEvent`、`StreamEventCounter` | AI漫游先不做长期事件归档 |

## 6. 推荐迁移模型

AI漫游应迁移 Aurora 的“前端组件拆分思想”，而不是迁移完整运行时。

```text
ProjectWorkbenchView
  -> ProjectDialoguePanel
    -> DialogueHeader
    -> DialogueMessageList
    -> DialogueInput
    -> StepPromptShortcuts
  -> CurrentStepWorkspace
    -> ScriptEditor / StructurePanel / StoryboardPanel / CandidatePanel / LayoutPanel / AssetPackagePanel
```

前端状态建议拆分：

```text
useProjectDialogue.ts            # 组合入口
dialogue-stream/
  dialogueStream.contract.ts     # 前端可消费事件与 payload 类型
  useDialogueSessionLifecycle.ts # 获取或创建当前步骤线程、发送消息、停止
  useDialogueEventStream.ts      # SSE 订阅和事件过滤
  useDialogueMessageProjection.ts# 消息流投影
  useDialogueToolActions.ts      # 剧本导入、灵感生成、章节草稿编辑、生成结构等动作
```

后端模型建议沿用 AI漫游当前文档：

```text
ConversationThread(projectId + stepKey)
ConversationMessage(threadId)
ProjectContextFact(confirmed only)
GenerationTask
```

## 7. AI漫游对话事件最小白名单

当前阶段建议只支持最小事件集合：

| 事件 | 作用 |
| --- | --- |
| `dialogue.message.created` | 新增用户或 assistant 消息 |
| `dialogue.message.delta` | assistant 流式文本增量 |
| `dialogue.message.completed` | assistant 消息完成 |
| `dialogue.status` | 当前步骤对话运行状态 |
| `dialogue.tool_result.created` | AI 受控工具产生业务结果 |
| `task.created` | AI 触发结构化、分镜、候选图等生成任务 |
| `task.updated` | 任务进度变化 |
| `task.completed` | 任务完成并产出业务对象 |
| `task.failed` | 任务失败 |

不进入当前白名单：

- `permission.updated`
- `permission.replied`
- `tool.ask_user.pending`
- `tool.show_file.pending`
- `tool.phaser_call.pending`
- `closed_loop.updated`
- 子会话镜像事件

## 8. 适配结论

| 结论 | 状态 |
| --- | --- |
| 采用 Aurora 的左对话、右工作区布局骨架 | adopt |
| 采用 Aurora 的组件拆分方向 | adopt |
| 采用 Aurora 的事件白名单思想 | adopt |
| 采用 workflow step -> prompt guidance 的思想 | adopt |
| 迁移 OpenCode 对话运行时最小闭环 | adopt |
| 不迁移 Docker sandbox / Phaser / Aurora 专用工具 | reject |
| 不迁移历史恢复和子会话树 | reject |
| AI漫游保留步骤对话隔离、项目级确认事实共享 | keep |
| AI 输出必须通过受控工具/API、保存、锁定或生成任务后才落入主事实；剧本阶段可由 AI 受控编辑章节草稿 | keep |

## 9. 待确认问题

OpenCode 对话运行时的正式移植方案见：

```text
文档/04_方案与决策/2026-05-25_OpenCode对话运行时移植方案.md
```

当前只剩一个产品问题需要确认：

```text
AI漫游的“对话框”首版是否只做剧本步骤的真实发送和受控文档编辑，
其他 5 个步骤先只显示同一组件骨架与步骤提示词？
```

建议答案：

```text
是。
```

原因：

- 剧本步骤最需要对话辅助，且已明确需要“已有剧本导入 / 灵感种子生成 / AI 受控编辑章节草稿”。
- 其他步骤的真实 AI 能力依赖结构化剧情、分镜、候选图和任务协议，过早做容易伪功能。
- 先把公共组件和步骤线程模型立住，再逐步接入后续步骤。
