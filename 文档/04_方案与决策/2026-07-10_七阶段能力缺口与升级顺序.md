# 七阶段能力缺口与升级顺序

## 1. 结论

现有七阶段框架保留，不重新设计：

```text
剧本 -> 剧情结构 -> 分镜工作台 -> 出图准备 -> 候选图工作台 -> 排版导出 -> 素材包
```

共享契约、前后端 workflow、页面路由、步骤门禁以及完成/确认/锁定/导出动作已经存在。D2 A“AI 分步生成、用户确认后推进”属于 `accepted_existing`，不是待开发模块。

下一阶段真正需要解决的是四类问题：

1. **事实一致性：** 上游修改后，下游旧版本、旧候选、旧布局和旧导出如何保留并明确失效。
2. **持久可靠性：** D7 的数据库唯一事实源、持久任务、重启恢复、取消、幂等和秘密分治。
3. **真实成品能力：** D3 候选修订、D4/D5 高自由成稿编辑器、确定性渲染和不可变导出。
4. **交付证据：** 当前先完成 G5 出版成品、来源 manifest 和正常/返修/故障证据；真正可下载的素材包与 ZIP 总验收按用户决定后置到 G6/G7。

当前真实样例已完成前四步，停在候选图：15 个镜头已有 27 张候选，尚未锁定，因此还没有真实排版与素材包产物。这是“样例未走完”，不是“阶段框架未实现”。

## 2. 判断口径

本方案不以页面、类型或接口是否存在作为完成证据，统一使用四级成熟度：

| 等级 | 含义 | 是否可列为已完成 |
| --- | --- | --- |
| L0 契约存在 | 有类型、枚举、路由或页面壳 | 否 |
| L1 业务可执行 | 前后端动作能改变正式状态或产物 | 部分 |
| L2 自动验证 | 关键规则有单元/集成测试 | 是，但不等于用户可用 |
| L3 真实路径 | 用户在真实页面完成，产物可打开且可追溯 | 是 |

待开发项分为：

- `repair`：已有行为会造成错误事实、状态漂移或历史覆盖，必须先修。
- `upgrade`：已有基础能力，但未达到已采纳方案或真实交付标准。
- `deferred`：不阻塞当前静态漫画主链路，明确后置。
- `keep`：已经存在且方向正确，禁止重复建设。

## 4. 逐阶段详细缺口

### 4.0 创建项目前置：漫画版式

#### 保留

- 创建成功后进入剧本步骤。
- `comicFormat` 继续作为领域字段，不新建重叠的项目类型字段。

#### 必须升级

1. 创建弹窗增加默认空、必选的“漫画版式”。
2. 顶层枚举只保留 `vertical_scroll/paged_comic`。
3. `CreateProjectRequest.comicFormat` 改为必填；服务端不得静默默认。
4. 普通更新 DTO 和服务移除修改入口；四格进入 `LayoutPreset`。
5. D7 导入器按 ADR-0009 处理旧值并输出异常报告。

#### 阶段验收

- 条漫、页漫各创建一个项目，重启后保持值。
- 缺失/非法值创建失败。
- 创建后任何普通页面和普通 API 都不能原地修改版式。

### 4.1 剧本

#### 保留

- 章节列表、章节路由、Markdown 编辑、保存草稿和完成本章。
- AI 写入先进入 `pendingSourceText`，由用户采用或丢弃。
- 对话 key 已能使用 `projectId + stepKey + chapterId`，不重复建设章节隔离。

#### 必须修正

当前 `saveChapterDraft`、`confirmChapterPendingSource` 和旧项目更新入口在章节已进入后续阶段时，只改 `sourceText/updatedAt`，不会同步处理：

- `currentScriptVersionId`；
- 已确认 `StoryVersion.sourceScriptVersionId`；
- `Chapter.status`；
- 下游 freshness。

结果是正文已变，但 workflow 仍可能停在候选、排版或导出，旧结构仍被视为当前事实。

目标规则：

1. `draft` 阶段允许保存 Working Copy，不推进版本。
2. 已完成章节再次修改正文时，先保存 Working Copy，并把“当前正式剧本仍是旧版”明确展示。
3. 用户再次点击“完成本章”才创建新的不可变 `ScriptVersion` 并更新 current 指针。
4. 新 ScriptVersion 生效后，旧 StoryVersion 及其下游派生为 `stale/historical`，不删除旧产物。
5. 未完成 Working Copy 不能进入结构生成上下文。

#### 后置

- 手动新建、重命名、删除章节属于编辑便利性，不阻塞一章完整链路。
- 跨章批量自动生成不进入本方案。

#### 阶段验收

- 已导出章节修改正文但未重新完成时，旧导出仍可查看，当前 workflow 显示“剧本有未完成修改”。
- 重新完成后产生新 ScriptVersion，旧结构不再是 current，且不能静默生成新分镜。

### 4.2 剧情结构

#### 保留

- AI 生成待确认预览；确认前不能生成分镜。
- 正式结构包含摘要、角色、场景和剧情节拍。
- 确认后同步本章角色到项目角色库。

#### 必须修正

1. `pendingStoryStructures` 仍是进程内 Map，服务重启后预览消失。
2. 重新确认结构时只把章节状态设为 `structured`，但旧正式 storyboard/candidates/layout 仍可能保留在对象、快照和文件中。
3. 字段编辑会原地更新同一 StoryVersion，且可能保留 `images_done/layout_done/exported` 状态。
4. 旧 StoryVersion 与当前 ScriptVersion 的来源匹配没有进入 workflow 门禁。

#### 目标规则

- PendingStructure、Structure Working Copy 和 StoryVersion 全部进入 D7 数据库。
- 结构字段编辑只改 Working Copy；“确认本次修改”创建新 StoryVersion。
- StoryVersion 使用 `sourceScriptVersionId + sourceDigest`。
- 新 StoryVersion 生效后，旧 StoryboardVersion 及下游派生为 stale，不物理删除。
- 场景参考图、角色映射等非剧情结构字段要区分“改变分镜语义”和“只补资产引用”，避免无意义地使所有分镜失效。

#### 阶段验收

- 服务重启后待确认结构仍存在。
- 修改剧情节拍并确认后，旧分镜显示来源已更新，不能作为新候选输入。
- 只补场景参考图时，是否使分镜失效由明确字段级规则决定，不依赖模糊更新时间。

### 4.3 分镜工作台

#### 保留

- PendingStoryboard 已持久化为独立文件，确认前不进入出图准备。
- 镜头字段编辑、新增、删除和拖拽重排已经实现。
- 正式分镜更新后会使出图准备、候选和布局失效，方向正确。

#### 必须升级

1. 正式分镜字段编辑仍原地修改同一 `ChapterStoryboard.id/version`。
2. 候选和布局使用清空方式处理，而不是保存旧版并标记历史。
3. 分镜没有统一 Working Copy / StoryboardRevision / current 指针。
4. 所有候选任务必须绑定 `sourceStoryboardRevisionId/sourceDigest`，迟到结果不能写入新版本。

#### 后置

- 单镜头 AI 重写、镜头缩略图增强和复杂批量重编号属于效率优化，不阻塞静态漫画首版。
- 基础漫剧 motion 字段保留，但不扩张视频链路。

#### 阶段验收

- 重排正式分镜后创建新修订，旧候选和旧布局仍可查但标记历史。
- 基于旧分镜运行中的图片任务完成时，不得进入新分镜 current 候选集。

### 4.4 出图准备

#### 保留

- 只读取正式分镜。
- 必需角色参考图、镜头角色绑定、场景和画风检查。
- `sourceStoryboardId/sourceStoryboardUpdatedAt` 已能避免明显的旧确认复用。
- 场景参考图缺失目前只 warning、不阻塞，保持当前产品口径。

#### 必须升级

1. ConfirmedPreflight 进入数据库，绑定明确 `sourceStoryboardRevisionId/sourceDigest`。
2. `ready` 继续作为派生结果，不允许客户端直接写成 true。
3. 角色/场景生成任务迁入统一持久 worker，不再由业务服务 Promise 队列承载。
4. 角色参考图、场景参考图和画风输入要保存资产版本/摘要，生成候选时固化来源集合。

#### 阶段验收

- 修改正式分镜或必需角色定稿后，旧 preflight 自动失效。
- 服务重启不会丢失已确认记录或运行中的参考图任务。
- 旧 preflight 不能创建候选任务。

### 4.5 候选图工作台

#### 保留

- 真实图片 provider、服务端权威生成规格、生成前预览、参考图解析和多批次历史。
- 用户逐镜头锁定；未全部锁定时不能完成本章候选图。
- 批量生成未锁定镜头已经存在，不重复建设。

#### 必须升级

按 ADR-0010：

1. 收藏/草选与正式定稿分离。
2. 新增不可变 `CandidateLockRevision`，lock/replace/clear 都创建修订。
3. 更换或取消前返回下游影响和 digest；提交使用乐观锁。
4. Shot 只保存当前修订指针，不直接覆盖历史候选关系。
5. 图片任务绑定 storyboard/preflight/reference source digest。
6. D75 持久任务提供重启恢复、有限重试、协作取消、幂等和图片并发 1。

#### 不在本方案展开

- Prompt 评测、供应商 profile 和视觉质量门属于“AI 质量与提示词工程”独立任务；本链路只定义引用接口和验收挂点。

#### 阶段验收

- A 定稿后建立布局，再换 B：旧布局不改写，受影响格子显示 stale。
- 旧图片任务迟到时只登记到旧来源，不污染当前候选集。
- 服务重启后 queued/running 任务按 D75 恢复或进入 needsReview。

### 4.6 排版导出

#### 保留

- 该步骤继续读取正式定稿候选，不改变七阶段位置。
- “生成工作稿”和“确认正式导出”保持为两个用户动作。

#### 必须升级

按 ADR-0011：

1. 引入规范化 `LayoutDocument`、Working Copy、不可变 `LayoutRevision`。
2. 条漫/页漫有限容器内支持矩形/圆角矩形画格、图片非破坏裁切、层级、移动、缩放、旋转和重叠。
3. 支持横排/竖排字符范围富文本，以及普通/思考/喊叫/旁白四类气泡和单尾巴。
4. 一般多选只保存到会话 SelectionSet，不保存通用 Group。
5. 编辑器桌面完整、手机只读；AI 助手默认收起，建议先预览再应用。
6. `PanelPlacement/ImageElement` 绑定 `sourceCandidateLockRevisionId`。
7. 建立导出前预检和确定性服务端合成，不允许复制源图或 DOM 截图冒充成稿。
8. 新增不可变 `ExportRevision + ExportProfile`，条漫切片、页漫序列和 PDF 由 profile 决定。

#### 当前必须删除的错误语义

- 一镜一页不再作为正式漫画排版。
- 重复导出不能覆盖同一路径并追加新的 Asset ID。
- 导出不能只读取 `placements[0]`。

#### 阶段验收

- 同一 LayoutDocument 的浏览器预览和服务端 PNG 结果在画格、裁切、字体、富文本、气泡和层级上确定一致。
- 旧 LayoutRevision/ExportRevision 永久可打开；来源更新后只生成新修订。
- 缺字体、文字溢出、低分辨率、stale 来源和未保存修改会阻止正式导出。

### 4.7 素材包

#### 保留

- 继续汇总章节剧本、结构、分镜、preflight、候选、布局、导出页、共享角色和 manifest。
- 继续作为第七阶段，不拆成新的发布中心。

#### 必须修正

当前 `archive` Asset 指向目录，不是文件；页面只显示路径，没有下载按钮；通用 Asset 文件接口会对目录执行 `readFile`。因此当前“导出素材包”不构成用户可交付下载。

#### 必须升级

1. 生成真实 ZIP 文件；可选保留同名展开目录作为调试证据，但 Asset 指向 ZIP。
2. 素材包通过 `asset_package_export` 持久任务执行，绑定 ExportRevision 和 lock set digest。
3. Manifest V2 至少包含：`storageKey/sha256/bytes/mimeType/chapterId/shotId/candidateId/assetId/sourceRevisionId/sourceTaskId`。
4. 页面提供下载、重新生成和历史包列表；下载响应使用 attachment。
5. 缺失必需文件时任务失败并保留报告，不能像当前逻辑一样静默跳过后仍标记章节 `exported`。
6. ZIP 和 manifest 均登记不可变 Asset；重复生成创建新 PackageRevision，不覆盖旧包。

#### 阶段验收

- 用户点击下载得到可解压 ZIP，而不是本地目录路径。
- 解压后所有 manifest 条目存在且 sha256/bytes 匹配。
- 任一必需正式导出页缺失时，素材包任务失败，章节不进入成功终态。

## 5. 跨阶段强制契约

### 5.1 线性进度与新鲜度分离

`Chapter.status` 只表达该章达到过的最远线性阶段，不能单独表达依赖是否仍然有效。每个正式版本需要独立 freshness：

```text
current     来源仍匹配当前上游，可用于新任务
stale       上游已更新，保留历史但不能用于新的正式下游
historical  从未是当前或已被新修订替代，只读追溯
pending     尚未由用户确认，不进入下游
```

强制规则：

- 未确认内容永远不能成为下游正式输入。
- 上游 current 指针改变后，旧下游不删除、不覆盖，只改变派生 freshness。
- 只有 `current` 来源可以创建新候选、布局、导出和素材包任务。
- 运行中的任务使用启动时来源；来源变化后结果只能成为 historical。

### 5.2 版本链

```text
ScriptVersion
  -> StoryVersion
  -> StoryboardRevision
  -> PreflightRevision
  -> CandidateLockRevision[]
  -> LayoutRevision
  -> ExportRevision
  -> PackageRevision
```

每一层必须具备：

- 稳定 ID 与 schemaVersion；
- 上游 revision ID 或集合；
- 规范化 sourceDigest；
- createdAt/createdBy；
- current 指针；
- 不可变历史；
- 下游任务的幂等键和适用性判断。

### 5.3 项目库状态投影

当前项目列表只可能返回 `draft/story_ready/characters_ready`，即使章节已进入候选、排版或导出。D7 后改为从章节 current/freshness 派生项目投影：

- 项目卡显示当前活跃章节和最远有效阶段。
- 多章项目不能仅用一个全局单调状态覆盖所有章节。
- 投影可重建，不作为独立可写事实。

### 5.4 文件与数据库

- 数据库保存业务关系和版本；文件只保存大字节与不可变导出物。
- Asset 必须有稳定 storageKey、sha256、bytes、mimeType、status 和来源关系。
- 数据库提交与文件采用 staged → rename → ready；失败恢复不能留下“DB 成功但文件不存在”的 current Asset。
- DB-only 后禁止回退读取旧 JSON 作为业务兜底。

## 6. 实施依赖顺序

本顺序不是自动调度路线，而是开发依赖顺序：

| 阶段 | 内容 | 为什么先后如此 | 退出闸门 |
| --- | --- | --- | --- |
| G0 | 现有行为 characterization + 最小 E2E 骨架 | D7 切换前先锁住已有正确行为和已知错误 | 当前七阶段状态映射、文件读写和真实断点有可重复证据 |
| G1 | D7 M0–M6：SQLite DB-only、仓储、导入、SecretStore、持久任务 | D1/D3/D4/D5 都依赖事务、修订和任务来源 | DB-only 冒烟通过，旧文件只读封存，任务可重启恢复 |
| G2 | 上游版本与 freshness 修复 | 不先修会让后续编辑器继续建立在漂移状态上 | Script/Story/Storyboard/Preflight 版本链和失效测试通过 |
