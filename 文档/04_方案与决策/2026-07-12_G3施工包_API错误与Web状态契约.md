# G3 施工包：API 错误与 Web 状态契约

## 1. 通用规则

- 复用 `POST /api/projects`、`PATCH /api/projects/{projectId}` 和现有成功导航。
- Create 的 `comicFormat` 编译期必填、运行时严格必填。
- Update DTO 不含该字段；原始 body 只要出现该自有属性，无论值为何均 409。
- G3 输入错误统一返回 `ApiErrorEnvelope`，Web 按 `error.code` 判断，不解析 message。
- create 错误、项目列表加载错误和删除错误分开，不共用一个全局 `error`。
- G3 不新增通用创建幂等 key，也不扩大 DB Project metadata PATCH。

## 3. 原始 body parser

新增：

```text
apps/server/src/projects/project-input.contract.ts
apps/server/src/projects/project-input.contract.spec.ts
```

固定接口：

```ts
export function parseCreateProjectRequestV1(value: unknown): CreateProjectRequest;
export function parseUpdateProjectDraftRequestV1(value: unknown): UpdateProjectDraftRequest;
```

Service 公共入口必须调用 parser；Controller 不能只依赖 TypeScript annotation。为避免内部直接调用绕过，建议把 `ProjectsService.createProject/updateProjectDraft` 参数改为 `unknown`，解析后再进入现有业务逻辑。

### 3.1 Create allowlist

```text
name
type
comicFormat
storyTitle
genreTags
artStyle
description
sourceText
```

校验顺序固定：

1. body 必须是非数组 object，否则 `400 PROJECT_BODY_INVALID`。
2. 出现 allowlist 外自有属性，返回 `400 PROJECT_INPUT_FIELD_UNSUPPORTED`。
3. `name` 非字符串、空或纯空格，返回 `400 PROJECT_NAME_REQUIRED`。
4. `comicFormat` 缺失、undefined、null、空或纯空格，返回 `400 COMIC_FORMAT_REQUIRED`。
5. 其他非 canonical 值返回 `400 COMIC_FORMAT_INVALID`；不 trim 后接受。
6. 其余字段沿用现有类型/长度规则；不得因 G3 新增宽松 coercion。

unknown field 的 details 只返回排序后的字段名，最多 20 个；不回显值。

### 3.2 Update allowlist

```text
name
storyTitle
genreTags
artStyle
description
sourceText
```

校验顺序固定：

1. body 必须是非数组 object。
2. **先**执行 `Object.prototype.hasOwnProperty.call(body, "comicFormat")`。
3. 命中即 `409 COMIC_FORMAT_IMMUTABLE`，即使值是 undefined/null/同值/非法值。
4. 再检查其余 unknown field，返回 `400 PROJECT_INPUT_FIELD_UNSUPPORTED`。
5. 再执行现有 name/sourceText 等规则。

混合 body `{name:new, comicFormat:current}` 整体 409，name 不写入。

## 4. persistence mode 行为矩阵

| 请求 | file mode | db mode |
| --- | --- | --- |
| POST canonical | 创建 Project + Chapter | 创建 Project + Chapter，同事务 |
| POST 缺失/非法/旧值 | 400，无文件 | 400，无行 |
| PATCH 含 comicFormat | 409，无写 | 409，在 DB unsupported 门前返回 |
| PATCH 不含 comicFormat | 保持现有 file update | 保持 `DB_PERSISTENCE_OPERATION_UNSUPPORTED:update_project_draft` |

G3 不为满足 name-only DB PATCH 测试而新增通用 metadata repository。DB 不可变由 0010 direct-SQL/Prisma contract test 证明。

## 5. 稳定错误 envelope

G3 Server 错误统一形状：

```json
{
  "success": false,
  "error": {
    "code": "COMIC_FORMAT_REQUIRED",
    "message": "请选择漫画版式"
  }
}
```

可用 `HttpException({ success:false, error:{...} }, status)`，或一个仅 G3 Project command 使用的窄 helper；本阶段不要求重写全局 Nest exception filter。

| HTTP | code | 用户 message | details |
| --- | --- | --- | --- |
| 400 | `PROJECT_BODY_INVALID` | 请求内容无效 | 无 |
| 400 | `PROJECT_INPUT_FIELD_UNSUPPORTED` | 请求包含不支持的字段 | `{fields}` |
| 400 | `PROJECT_NAME_REQUIRED` | 请输入项目名称 | 无 |
| 400 | `COMIC_FORMAT_REQUIRED` | 请选择漫画版式 | 无 |
| 400 | `COMIC_FORMAT_INVALID` | 漫画版式无效，请重新选择 | 无 |
| 409 | `COMIC_FORMAT_IMMUTABLE` | 漫画版式创建后不可直接修改 | 无 |
| 409 | `LEGACY_COMIC_FORMAT_DECISION_REQUIRED` | 旧项目的漫画版式需要迁移决议 | 脱敏 issue summary |
| 500 | `G3_DATABASE_CONTRACT_VIOLATION` | 数据库约束校验失败 | 无 |

日志只能写 code、requestId、projectId 和安全分类；禁止完整 body、DB URL、workspace 根、SQL 或 secret。

## 6. Web API error type

当前 `apps/web/src/services/api.ts` 把错误 envelope 压成普通 `Error(message)`，导致 store 看不到 code。G3 修改为：

```ts
export class ApiClientError extends Error {
  constructor(
    message: string,
    readonly status: number,
    readonly code: string,
    readonly details?: unknown,
  ) {
    super(message);
    this.name = "ApiClientError";
  }
}
```

`request()` 行为：

- `ApiErrorEnvelope`：抛 `ApiClientError(message,status,code,details)`。
- 旧 Nest 默认错误：抛 code=`API_REQUEST_FAILED`，保留安全 message。
- 成功 envelope 行为不变。
- 不在 API client 中翻译漫画版式文案；翻译归项目创建 UI。

增加 unit-testable 纯函数或导出：

```ts
parseApiClientError(payload: unknown, status: number, fallback: string): ApiClientError;
```

## 7. Pinia 专用状态

修改 `apps/web/src/stores/workbench-store.ts`：

```ts
export type CreateProjectErrorCode =
  | "PROJECT_BODY_INVALID"
  | "PROJECT_INPUT_FIELD_UNSUPPORTED"
  | "PROJECT_NAME_REQUIRED"
  | "COMIC_FORMAT_REQUIRED"
  | "COMIC_FORMAT_INVALID"
  | "PROJECT_CREATE_FAILED";

interface WorkbenchState {
  // existing state...
  creatingProject: boolean;
  createProjectErrorCode: CreateProjectErrorCode | null;
}
```

固定状态转移：

| 事件 | creatingProject | createProjectErrorCode | 全局 error |
| --- | --- | --- | --- |
| 打开弹窗 | false | null | 不改 |
| 提交开始 | true | null | 不改 |
| 字段/API 失败 | false | 映射后的 code | 不改 |
| 未识别失败 | false | `PROJECT_CREATE_FAILED` | 不改 |
| 成功 | false | null | 不改 |
| 用户关闭 | false | null | 不改 |

增加 `clearCreateProjectError()` action。`createProject()` 不再把字段错误写入 `this.error`，也不使用通用 `loading` 驱动创建按钮。

成功路径：

```text
POST success
-> upsert result.project 到 projects
-> 设置 activeProjectId/currentChapterId/activeStepKey
-> 返回 ProjectListItem
-> ProjectLibraryView 关闭弹窗并沿用 projectRoute 导航
```

不要把 `refresh()` 放在成功判定的关键路径中；若创建成功后 refresh 失败，不能把已创建项目伪装成创建失败并诱导重复提交。工作台路由会按现有流程加载 snapshot。

## 8. CreateProjectModal 精确契约

props：

```ts
defineProps<{
  open: boolean;
  loading: boolean; // 绑定 creatingProject
  errorCode: CreateProjectErrorCode | null;
}>();
```

内部状态：

```ts
const form = reactive<{
  name: string;
  type: "comic";
  comicFormat: ComicFormat | "";
}>({
  name: "",
  type: "comic",
  comicFormat: "",
});

const canSubmit = computed(() =>
  form.name.trim().length > 0 && isComicFormat(form.comicFormat),
);
```

规则：

- 每次从 closed→open 重置 name、type、comicFormat；默认聚焦项目名称。
- 失败时 modal 保持 open，两个输入值保持不变。
- 关闭后由父级清空 error；下一次打开仍为空。
- submit 再次调用 `isComicFormat`，不使用 `as ComicFormat` 绕过空值。
- loading 时关闭按钮、取消、select 和提交按钮均 disabled；不得只禁提交按钮。

选项必须从 Shared `COMIC_FORMAT_DEFINITIONS` 生成：

```text
placeholder: 请选择漫画版式
vertical:    竖向条漫
paged:       分页漫画
```

不得出现“横版页漫”“四格漫画”。

## 9. 无障碍与错误归属

固定节点：

- `<form aria-busy="true|false">`。
- select 有可见 label“漫画版式”。
- `aria-invalid` 只在 comicFormat 相关错误时为 true。
- `aria-describedby="comic-format-help comic-format-error"`。
- 字段错误容器 `id="comic-format-error" role="alert" aria-live="polite"`。
- 项目名称错误显示在名称字段，不显示在版式字段。
- 通用创建失败显示在 modal footer 上方的 `role=alert`，不显示为“项目服务连接失败”。
- Tab 顺序固定：名称→版式→取消→创建；关闭按钮仍可在标准 dialog 顺序访问。

错误映射：

```ts
const CREATE_PROJECT_ERROR_MESSAGES: Record<CreateProjectErrorCode, string> = {
  PROJECT_BODY_INVALID: "请求内容无效，请重试",
  PROJECT_INPUT_FIELD_UNSUPPORTED: "创建信息包含不支持的字段",
  PROJECT_NAME_REQUIRED: "请输入项目名称",
  COMIC_FORMAT_REQUIRED: "请选择漫画版式",
  COMIC_FORMAT_INVALID: "漫画版式无效，请重新选择",
  PROJECT_CREATE_FAILED: "项目创建失败，请重试",
};
```

## 10. ProjectLibraryView 接线

禁止 `@create="isCreateOpen = true"` 和 `@close="isCreateOpen = false"` 的裸赋值，改为显式函数：

```ts
function openCreateProject() {
  workbench.clearCreateProjectError();
  isCreateOpen.value = true;
}

function closeCreateProject() {
  if (workbench.creatingProject) return;
  workbench.clearCreateProjectError();
  isCreateOpen.value = false;
}
```

Modal 绑定：

```vue
<CreateProjectModal
  :open="isCreateOpen"
  :loading="creatingProject"
  :error-code="createProjectErrorCode"
  @close="closeCreateProject"
  @create="createProject"
/>
```

`ProjectLibraryView` 的项目列表 `error` 区域继续只表示 refresh/list 失败。

## 13. 完成判定

G3-B0/C0/C1 只有在以下满足时完成：

- Shared DTO 与 raw parser 同时生效。
- G3 错误 envelope 可被 `ApiClientError.code` 读取。
- create 专用状态与全局 list error 分离。
- modal 默认空、失败保留、成功导航、无障碍断言通过。
- file/db PATCH 矩阵与本文一致。
- 没有新增入口、向导、DB metadata PATCH 或版式编辑控件。
