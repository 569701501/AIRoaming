> 本规范是项目「从头重做交互/视觉层」的产物，也是以后每个页面都套用的尺子。
> **边界：只约束交互/视觉层，不改字段定义、数据模型、任务协议、后端。**
> 状态：草案，待用户确认方向后再落代码。

## 1. 为什么需要这份规范

现有工作台的核心问题不是审美，是**信息密度失控**，根因有三：

1. **卡片把所有字段常驻可编辑**：一张分镜卡 14 个 `EditableShotField` 平铺，视线无落点。
2. **一屏多块平级面板抢焦点**：出图准备页同时有 hero / next-action / metrics / checklist / issue-panel 五块同级。
3. **待确认态与正式态视觉差异不足**：用户分不清「AI 草案」和「我已确认内容」，不敢放心让 AI 干活。

过去反复改不好，是因为在 UI 层面解决信息架构层面的问题。本规范把**信息架构的规则**先定死，UI 在规则内自由发挥。

---

## 2. 五条核心原则（尺子）

### 原则 1：默认只读，点按编辑（渐进披露）

- 卡片默认是**只读摘要**：标题 + 1~2 行关键信息 + 缩略（若有）。
- 字段编辑**收进抽屉/弹窗**，点卡片或「编辑」按钮才进入。
- 禁止「一张卡片把 N 个字段全部常驻 inline 可编辑」。

> 心智参考：Notion 卡片、Figma 属性面板、剪映片段 inspector。都是「默认信息少，编辑才展开」。

### 原则 2：一屏一焦点

- 每个屏幕**只有 1 个主信息区**（当前状态/进度，一句话）。
- 每个屏幕**只有 1 个主操作**（下一步该做什么，唯一高亮按钮）。
- 其余内容（指标、checklist、辅助说明）**降级**：小字、次级色、折叠、底部。

> 判定标准：用户打开页面 3 秒内，眼睛落在唯一一个高亮元素上。如果有两个元素同时「喊」用户，就是错的。

### 原则 3：状态先行（强对比）

四种核心状态必须有**一眼可辨的视觉差异**：

| 状态 | 含义 | 视觉规范 |
| --- | --- | --- |
| `empty` | 前置步骤未完成/无数据 | 灰色占位 + 锁图标 + 一句「先去 X」 |
| `draft` | 已有草稿，未提交生成 | 中性色，普通卡片 |
| `pending_confirmation` | AI 刚生成，待用户确认 | **强提示**：顶部琥珀色横条 + 虚线边框 + 巨大「确认」按钮 + 背景微暖色 |
| `confirmed` | 用户已确认 | 干净只读态，去掉所有「待确认」装饰，左上角小绿点 |

> 关键：`pending_confirmation` → `confirmed` 的视觉跃迁必须强烈。这是用户「放心让 AI 干活」的信任基础。

### 原则 4：视觉优先

- 凡涉及**视觉产物**（分镜、候选图、角色图、排版页），卡片左侧必须是**图/缩略**，文字是辅助。
- 用户靠眼睛扫缩略图判断内容，不是读 14 个字段。
- 文字字段用于「定位改哪张」，不用于「看懂这张」。

> 候选图工作台、角色库尤其适用。分镜卡在候选图就绪前，用「画面描述」首句作为伪缩略。

### 原则 5：列表是卡片，不是表单

- 列表页（分镜列表、候选图列表、角色列表）一律用**卡片网格/纵向列表**，不是字段堆叠的长表单。
- 卡片信息层级：`主标题（1行） > 副信息（1行） > 状态徽标`。更多细节折叠。

## 3. 信息密度上限（硬约束）

| 单位 | 上限 | 超过怎么办 |
| --- | --- | --- |
| 一张卡片默认显示字段 | **≤ 3 个** | 其余收进编辑抽屉 |
| 一屏平级面板数 | **≤ 2 块**（主信息 + 主操作外） | 其余折叠/降级/底部 |
| 一屏高亮按钮数 | **1 个**主操作 | 次级操作用文字链/灰按钮 |
| 一个编辑抽屉分组数 | **≤ 3 组**（用 tab 或折叠） | 参考 storyboard 的 comic/motion 分组 |

> 这张表是「尺子」。以后每改一个页面，先数这几项是否超标。超标先收，再谈美观。

## 4. 布局骨架

### 4.1 项目工作台外壳（保留现状，微调）

现有三宫格是对的，保留：

```
┌──────────────────────────────────────────────────────────┐
│  ← 项目库            ① 剧本 → ② 结构 → ③ 分镜 → ...      │  顶部：返回 + 流程轨
├────────────────┬─────────────────────────────────────────┤
│                │                                         │
│   AI 对话框    │            当前步骤工作区               │
│   (按步骤隔离) │       (本规范主要约束的区域)            │
│   固定宽度     │                                         │
│                │                                         │
├────────────────┴─────────────────────────────────────────┤
│  对话框独立，工作区独立，两者不抢焦点                     │
└──────────────────────────────────────────────────────────┘
```

微调点：

- 流程轨里**当前步骤**高亮，已完成步骤显示状态徽标，未达步骤灰禁。
- 工作区内部严格遵循「一屏一焦点」，不再出现 5 块平级面板。

### 4.2 右侧工作区内部统一结构

所有步骤的右侧工作区用**同一个三段式骨架**，消除各页结构不一致：

```
┌─────────────────────────────────────────┐
│ A. 步骤头（StepHeader）                 │  章节选择 + 步骤状态一句话 + 主操作按钮
│    只有 1 个主操作                      │
├─────────────────────────────────────────┤
│ B. 主内容（StepBody）                   │
│    - 列表卡片 / 编辑区                  │
│    - pending_confirmation 时这里显示    │
│      强对比待确认横条                   │
├─────────────────────────────────────────┤
│ C. 辅助区（StepAside，可折叠）          │  指标/checklist/辅助说明，默认折叠
└─────────────────────────────────────────┘
```

> 对比现状：出图准备页现在是 `toolbar + hero + next-action + metrics + checklist + issue-panel` 六块平级。新骨架下，hero/next-action 并入 A，metrics/checklist 折叠进 C，issue-panel 升级为 B 的主内容（因为「处理未识别角色」就是该步主任务）。

## 6. 卡片 → 编辑抽屉模式（核心交互）

这是解决「14 字段平铺」的关键模式。以分镜卡为例：

### 默认列表态（只读摘要）

```
┌─────────────────────────────────────────┐
│ #3  林晓走进废弃实验室                   │  主标题：核心动作
│     实验室外景 · 紧张                     │  副信息：场景·情绪
│                              [编辑] ▸    │  点卡片或编辑进抽屉
└─────────────────────────────────────────┘
```

### 点开后（编辑抽屉，字段分组）

```
┌──── 编辑镜头 #3 ────────────────────────┐
│ [核心] [漫画画格] [漫剧镜头]   ← ≤3 分组  │  tab 切换
├─────────────────────────────────────────┤
│  ▸ 核心动作    林晓走进废弃实验室        │
│  ▸ 情绪        紧张                       │
│  ▸ 场景        实验室外景                 │
│                                         │
│  ─ 漫画画格（折叠/展开）─                │
│  ─ 漫剧镜头（折叠/展开）─                │
│                          [取消] [保存]   │
└─────────────────────────────────────────┘
```

> 对比现状：14 个 `EditableShotField` 常驻平铺 → 新设计默认 3 个字段，其余 tab/折叠。
> 字段一个不少，只是**默认收起来**。信息密度从 14 降到 3。

## 7. 组件库（需新增/重构）

| 组件 | 职责 | 对应原则 |
| --- | --- | --- |
| `StepHeader` | 章节选择 + 状态一句话 + 唯一主操作 | 原则2 |
| `StatusBand` | empty/draft/pending/confirmed 四态渲染 | 原则3 |
| `SummaryCard` | 列表卡（标题+副信息+状态点+编辑入口） | 原则1,4,5 |
| `EditDrawer` | 字段编辑抽屉（分组 tab + 折叠） | 原则1 |
| `MetricsRail` | 辅助指标/checklist，默认折叠 | 原则2 |
| `PrimaryAction` | 唯一高亮主按钮封装 | 原则2 |

> 这些组件是「尺子」的物化。用它们重组现有页面，字段不变，只改呈现。

## 8. 样板页 ASCII：分镜工作台（新设计）

> 分镜是字段最多、最典型的页面。先改它做样板，通过后横向推。

### 空态（剧本未完成）

```
┌─ #3 分镜 ──────────────────── [本章：第二章] ─┐
│                                              │
│              🔒 请先确认本章剧情结构          │
│         分镜会读取已确认的 structure.json     │
│                                              │
└──────────────────────────────────────────────┘
```

### 待确认态（AI 刚生成）—— 强对比

```
┌─ #3 分镜 ─ 第二章 · 8 镜 ─ [重新生成] ──────┐
╠══════════════════════════════════════════════╣
║ ⚠ 待确认预览 · 共 8 镜 · 看不顺眼可重新生成  ║  琥珀横条
╠══════════════════════════════════════════════╣
║ ┊ #1  开场：林晓收到神秘邮件   ┊ 编辑 ▸ ┊    ║
║ ┊ #2  潜入实验室               ┊ 编辑 ▸ ┊    ║  虚线边框
║ ┊ #3  发现异常数据             ┊ 编辑 ▸ ┊    ║  卡片只读
║ ┊ #4  被发现                   ┊ 编辑 ▸ ┊    ║
║ ┊ ...                                     ┊    ║
║                                            ║
║          [  ✓ 确认这 8 个分镜  ]            ║  唯一高亮
╚══════════════════════════════════════════════╝
```

### 已确认态（干净列表）

```
┌─ #3 分镜 ─ 第二章 · 8 镜 ── [编辑分镜] ────┐
│  本章分镜已确认，进入下一步「出图准备」     │  一句话状态
├──────────────────────────────────────────────┤
│ 🟢 #1  开场：林晓收到神秘邮件      [编辑▸]  │
│ 🟢 #2  潜入实验室                  [编辑▸]  │  干净只读
│ 🟢 #3  发现异常数据                [编辑▸]  │

├──────────────────────────────────────────────┤
│ ▾ 辅助（指标/检查）                          │  默认折叠
└──────────────────────────────────────────────┘
```

### 点「编辑」后（抽屉）

```
┌──── 编辑镜头 #3 ─────────────────[ × ]────┐
│ [核心] [漫画画格] [漫剧镜头]               │
```

> **对比现状**：14 字段常驻平铺 → 默认 3 字段 + 折叠。字段一个没少，密度从 14 降到 3。

## 9. 推广顺序

| 顺序 | 页面 | 为什么是它 |
| --- | --- | --- |
| 1 | 分镜工作台 | 字段最多（14），最典型，样板价值最大 |
| 2 | 剧情结构 | 同类问题（EditableBlock 平铺），组件可复用 |
| 3 | 出图准备 | 多面板抢焦点问题最严重，验证 MetricsRail 折叠 |
| 4 | 角色库 | 验证「视觉优先」（角色图缩略） |
| 5 | 候选图工作台（新） | 直接按本规范新建，不用返工 |

## 10. 待用户确认的方向问题

在动代码前，请确认：

1. **「默认只读 + 编辑抽屉」方向**是否接受？（这是最大的改动，从「全部 inline 可编辑」转向「点按编辑」）
2. **pending_confirmation 强对比**（琥珀横条+虚线+巨大确认键）是否符合你想要的感觉？
3. **辅助信息默认折叠**（metrics/checklist 收起来）是否接受？还是你希望某些指标常驻可见？
4. **分镜卡作为第一个样板**是否认可？

确认后，我再出分镜工作台的 Vue 组件拆分 + 具体 diff，再落代码。
