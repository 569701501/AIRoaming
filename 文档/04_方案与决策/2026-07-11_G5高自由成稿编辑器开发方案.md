# G5 高自由成稿编辑器开发方案

## 1. 本方案的结果

G5 不新增第八个制作阶段，也不重做已有项目入口。它只升级现有第 6 步“排版导出”：

```text
当前：选择章节 → 一镜一页卡片 → “导出”时复制候选原图

目标：进入成稿编辑器
  → 页漫页面 / 条漫段落
  → 画格、非破坏裁切、自由图片、横竖排富文本、四类气泡
  → Working Copy 自动保存
  → 用户保存不可变 LayoutRevision
  → 来源/字体/溢出/分辨率预检
  → 持久任务生成真实 PNG、页漫可选 PDF、条漫切片
  → 不可变 layout_publication ExportRevision
```

本轮只完成开发级方案，不修改代码、Schema、数据库、依赖或真实 workspace。文档已获用户确认；实际开发仍应按总顺序先实施 G0–G4，不能直接跳到 G5。

## 2. 已确认产品决策

本文直接消费 ADR-0011，不再重复询问：

| 决策 | 已确认结果 |
| --- | --- |
| 产品身份 | 条漫/页漫有限成稿容器内的高自由对象编排，不是无限白板或绘画软件 |
| 画格 | 矩形/圆角矩形；对象可移动、缩放、旋转、重叠和排序 |
| 文字 | 页漫/条漫均支持 `horizontal-tb/vertical-rl` 和字符范围富文本 |
| 气泡 | speech/thought/shout/caption + 最多一条可调尾巴 |
| 分组 | 会话级多选和批量命令；不保存通用 Group |
| 端能力 | 桌面完整编辑；手机只读真实预览和预检 |
| AI | 成稿步骤默认收起 AI 抽屉；建议经预览/用户应用后才改 Working Copy |
| 来源 | 候选图片绑定 G4 CandidateLockRevision；旧布局/导出不覆盖 |

## 3. 本方案新增的实施级推荐

以下不是改变 D4/D5，而是把已确认方向变成可开发契约；建议作为一个整体确认：

1. `paged_comic` 首次进入默认 `1800×2400` 竖页，仍可在成稿初始化/页面设置中选择横页、方页或受限自定义；项目漫画版式本身不变。
2. `vertical_scroll` 默认宽 1080、逻辑段落高 1920；段落可调高，正式导出按 Profile 切片。
3. 画格与它内部的候选图是受控复合对象；自由图片才是独立顶层图层，避免边框和图片层被误拆。
4. 自动保存只更新 Working Copy；离开页面不自动生成正式版本。用户点“保存版本”、恢复历史后确认或导出前保存时才创建 LayoutRevision。
5. 每个 active Shot 在新正式版本中至少有一个可见的当前候选图；若确实不需要该 Shot，应回分镜正式删除/调整，而不是在成稿阶段无痕丢弃。
6. 一次出版导出形成一个 `layout_publication`：页漫必含 PNG 页面、可选 PDF；条漫必含 PNG 切片、能力允许时可含长图。它是 G6 素材包的唯一当前成品输入。
7. E0 优先验证“交互 adapter + 专用 HTML/SVG RenderScene + 固定 Chromium”，同时以 SVG/resvg 做对照；原型通过前不锁库。

## 4. 现状证据

### 4.1 Web

`apps/web/src/components/workbench/LayoutExportWorkspace.vue` 当前只有：

- 章节选择。
- “生成排版”。
- “导出 PNG 序列”。
- 一页一张的卡片预览。
- 从 `shot.lockedCandidateId` 读取来源。

没有页面/段落列表、工具栏、图层、属性、文字、气泡、裁切、Undo、Working Copy 状态、版本历史或预检。

`ProjectWorkbenchView` 当前固定左侧 `ProjectDialoguePanel` + 右侧业务工作区；成稿步骤没有全宽特例。

### 4.2 Shared

当前 `PanelPlacement/LayoutPage/ChapterLayout` 只能表达：

```text
shotId, candidateId, assetId, order, x, y, w, h
```

没有稳定 element ID、CandidateLockRevision、crop、层级、隐藏/锁定、富文本、FontAsset、气泡、Working Copy 或正式修订。

### 4.3 Server

`apps/server/src/projects/layout-export.service.ts`：

- 近似按每个 locked Shot 建一页。
- 每页一个 placement 填满页面。
- 保存时覆盖旧 layout JSON/章节状态。
- 导出只取第一页/placement 对应源文件并 `copyFile`，不是合成 PNG。
- 没有 LayoutRevision/SourceBinding/preflight/renderer/task source。

当前“导出成功”只能作为已知错误的 characterization，不能成为 G5 green 语义。

### 4.4 依赖

- Web 未安装 Konva/Fabric/Pixi 或富文本编辑内核。
- Server 未安装 Chromium renderer、resvg、Sharp/Skia 或 PDF 合成链。
- 项目无受控 FontAsset。

因此本方案不能假装已有技术栈已经选定，E0 是硬门禁。

## 7. 用户主路径

### 7.1 首次进入成稿步骤

1. 用户沿用现有项目工作台进入第 6 步，不新增项目入口或向导。
2. 系统读取 Project.comicFormat、当前章节、G4 lock set、旧 Layout/Working Copy 和 FontAsset。
3. lock set 不完整时显示具体未定稿 Shot，并提供返回候选图工作台的入口；历史成稿仍只读可见。
4. 没有 Working Copy 时打开一次性“创建成稿草稿”设置：
   - 项目漫画版式只读。
   - 页漫默认竖页 3:4，可选横页/方页/自定义。
   - 条漫默认 1080 宽和 1920 段高。
   - 默认“按分镜建立基础排版”，也允许空白草稿。
5. 系统用确定性模板把当前定稿图放入同一 LayoutDocument，创建 Working Copy，不自动创建正式修订或导出。

这里与 G3 不冲突：创建项目时锁的是“条漫还是页漫”；页面横竖、具体宽高和四格模板本来就属于 G5 容器内部设置。

### 7.2 编辑

1. 用户在页面/段落导航中选择 canvas。
2. 从工具栏添加画格、图片、文字、气泡，或从 Shot tray 拖入未放置定稿。
3. 选择对象后在右侧修改属性；图层列表负责顺序、隐藏和锁定。
4. pointerup、输入法 compositionend 或属性提交形成一个 Editor Command；Undo/Redo 以 batch 为单位。
5. 800ms idle 自动保存 Working Copy，顶部明确显示未保存/保存中/已保存/冲突。
6. 用户点击“真实预览”切换到无控制柄 RenderScene；条漫显示手机视窗和切片线，页漫按页翻看。

### 7.3 保存版本

- “已自动保存”只表示草稿安全，不表示可导出正式版本。
- 用户点击“保存版本”后，Server 核对 Working Copy rowVersion、当前 LayoutRevision、完整可见 Shot、来源、Asset/字体和 revision gate。
- 成功创建不可变 LayoutRevision、LayoutSourceBinding 并移动 Chapter.currentLayoutRevisionId。
- 文字溢出/低分辨率等可作为检查点 warning；来源、字体/图缺失和结构错误阻止正式保存。

### 7.4 出版导出

1. 先 flush 本地自动保存。
2. Working Copy 比 current LayoutRevision 新时：
   - 推荐“保存新版本并导出”；
   - 也可明确选择“导出当前已保存版本”，保留草稿不变。
3. 对目标 LayoutRevision + ExportProfile 运行预检。
4. error 必须修复；warning 每次导出明确确认。
5. 创建 queued layout_publication + persistent task。
6. ready 后查看/下载真实 PNG、PDF/切片；旧出版版本保留历史。

### 7.5 候选 A 改成 B

1. G4 replace 只创建新 CandidateLockRevision，旧 Layout/Export 不改写。
2. 编辑器刷新后，对所有使用旧 A revision 的图片显示 stale 标识；当前历史成品仍可查看。
3. 用户对单张或全部 stale 图片打开替换预览。
4. 每张明确选“保留归一化裁切”或“重置 cover”；前后对照显示构图变化。
5. commit 只更新 Working Copy，作为一个可撤销 batch。
6. 用户解决所有来源后保存新 LayoutRevision，再出版新 ExportRevision。

如果当前 lock 已 clear，编辑器不猜目标图，用户必须先回候选阶段重新定稿。

## 9. 手机只读预览

路由建议：

```text
/projects/:projectId/layout/preview?chapterId=...&source=working_copy|revision|publication&id=...
```

- 在通用 `/layout` 路由之前注册并 lazy load 只读 bundle。
- 条漫按真实宽度连续滚动，显示手机视窗/切片边界；页漫按 page 顺序翻页。
- 可查看 stale/unresolved、字体、溢出、低分辨率和画布外问题。
- Working Copy 只显示最近成功 autosave snapshot 并标注草稿；Revision/Publication 标注版本号。

## 11. 状态与职责

| 状态 | 可变 | Undo | 下游可引用 | 用途 |
| --- | --- | --- | --- | --- |
| Editor local document | 是 | 是 | 否 | 当前未 autosave 交互 |
| LayoutWorkingCopy | 是，rowVersion | 会话内 | 否 | 自动保存/崩溃恢复 |
| LayoutRevision | 否 | 通过恢复生成新草稿 | 是 | 正式成稿快照 |
| layout_publication ExportRevision | ready 后否 | 否 | 是，供 G6 | PNG/PDF/切片批次 |
| Editor Command History | 会话内 | 本体 | 否 | Undo/Redo |
| PendingEditorCommandSet | pending 可决议 | 应用后作为 batch | 否 | AI 建议预览 |

关键规则：

- Autosave 不等于正式保存。
- LayoutRevision 不等于 ExportRevision。
- 创建新 LayoutRevision 不删除旧 publication；旧 current pointer 的查询位置变为 historical。
- Export task 从不引用 Working Copy。

## 12. 数据库细化

G5 不新增领域模型，但细化 G1 现有表：

### 12.1 LayoutWorkingCopy

保留：

```text
documentKind=layout_document_v1
documentJson/schemaVersion/documentDigest
sourceLockSetDigest
basedOnRevisionId
rowVersion
```

无需 command log、selection、viewport 或 autosave history 表。

### 12.2 LayoutRevision

G1 base 已预建，G5 开始使用：

```text
previousRevisionId
contentBasedOnRevisionId
saveReason
bindingSetSealedAt
```

用 previous + current expected 保证线性历史和丢响应重放；contentBasedOn 记录从哪个历史内容恢复。Binding 集合在同一事务写完后单向 seal，seal 后禁止晚插入/改写/删除。

### 12.3 LayoutSourceBinding

沿用 element/role/order/Shot/Candidate/LockRevision/Asset/sourceDigest；由文档投影同事务写，不独立修改。

### 12.4 Asset

扩展 `type=font/role=layout_font` 和 `layout_font_asset_v1` metadata；不新增 FontAsset model。

### 12.5 PendingDialogueArtifact

扩展 `kind=layout_editor_command_set`；同章同逻辑槽最多一个 active pending。

### 12.6 ExportRevision

- runtime kind 收口为 `layout_publication`。
- G1 base 已预建 `scopeKey/taskId/profileJson/profileDigest/preflightDigest/rendererVersion`；G5 开始正式使用。
- status=`queued/rendering/ready/failed/cancelled`。
- 一次出版的 PNG/PDF/切片用 ExportArtifact roles 表达。

上述列属 G1 base，不在 G5 重复 ADD COLUMN。G5 migration 只通过 G5 overlay manifest 添加 previous 线性、autosave replay、publication 状态机/current finalize 等约束，并进入 Prisma migration/trigger/contract-test 体系，不能 `db push`。

## 14. 自动保存、并发和崩溃恢复

### 14.1 自动保存

- 命令完成后 dirty；800ms idle 保存，最长 5s。
- 发送完整规范文档 + expected rowVersion/base digest，避免 V1 持久化命令日志和复杂 server merge。
- Server normalize/digest/source validate 后原子更新。
- 丢响应重试只在 current rowVersion=expected+1 且 digest 等于请求结果时 replay。

### 14.2 冲突

- 多标签或旧页面写入返回 409；自动保存暂停。
- 不 last-write-wins、不对象级猜合并。
- 用户可先下载本地恢复 JSON，再选择服务端版本或明确基于最新 rowVersion 保留本地。
- 恢复历史、章节切换或冲突解决后 Undo history 清空。

### 14.3 浏览器崩溃

- 成功 autosave 的 Working Copy 是唯一恢复事实。
- 内存中小于 800ms/失败未保存的最后操作可能丢失，UI 用 save state 和 beforeunload 降低风险。
- V1 不把 IndexedDB/LocalStorage 建成第二权威副本；可下载的 recovery JSON 只由用户手工处理。

## 15. 富文本实现边界

- 不使用普通 textarea 伪装字符范围富文本。
- 输入层可使用成熟 rich-text/DOM selection adapter，但持久化必须转成 paragraphs/runs。
- IME composition 期间不产生中间 command/auto-save；compositionend 产生一个可撤销命令。
- 外部粘贴清洗为纯文本和段落；内部富文本 MIME 仍经 codec。
- 范围按固定 Unicode grapheme policy，避免切开 emoji/组合字符。
- 改框尺寸只重排；显式“整体缩放页面内容”命令才改变字号。
- 缺字体、缺 glyph、overflow 必须可定位到 canvas/element/range。

## 16. FontAsset 策略

### 16.1 V1 产品边界

- V1 提供受控内置字体选择，不先做任意字体上传/字体市场。
- 至少一套字体组合覆盖常用中日韩文字和 normal/bold/italic 用户动作。
- 每种正式 face 有明确 Asset sha、weight/style、cmap digest 和可嵌入许可证。
- 字体选择 UI 只展示项目已 ready 的受控字体；不列客户端系统字体。

### 16.2 Provision

- 首次初始化成稿时由 Server 通过 Asset/Outbox 为项目 provision 字体 Asset。
- 不把字体复制逻辑塞入 Web，也不把 base64 写文档/任务。
- 字体包最终选择属于 E0 + 许可证复核的实施证据；没有证据前不在本文点名生产字体文件。

## 17. 预检分层

### 17.1 Working Copy/Revision gate

阻止正式版本：

- schema/尺寸/crop 非法。
- active Shot 缺少可见当前候选图。
- source stale/unresolved/lock set incomplete。
- 图片/字体 Asset 缺失、未 ready、sha/作用域错误。
- 字体不可嵌入或缺 glyph。

允许保存版本但给 warning：

- 文字溢出。
- 低分辨率。
- 对象画布外、超 safe area、空页面。

### 17.2 Export gate

- 上述 source/integrity error 全阻止。
- 文字溢出和有效分辨率 <0.5 阻止。
- 0.5–1 分辨率、画布外、safe area、空页面、切片穿内容须逐次确认。
- Working Copy 比目标 revision 新时明确提醒，用户选择保存新版本或导出已保存版本。
- renderer 能力/页数/像素超限阻止。

## 18. AI 助手

### 18.1 抽屉

- 进入成稿步骤默认收起；只在用户打开时加载该 step 的 ConversationThread。
- 可读当前项目/章节、最近已保存 Working Copy、选择摘要、Shot tray 和预检结果。
- 未确认聊天内容不写 ProjectContextFact。

### 18.2 权限

AI 可建议：

- 使用哪个模板或如何重排。
- 修改文字/气泡内容和样式。
- 对齐、分布、层级或修复某些预检问题。
- 对 stale 替换给出 crop 方案，但来源目标必须由 Server 当前 lock 决定。

AI 不可：

- 直接保存任意 JSON Patch/脚本。
- 在来源 digest 变化后应用旧建议。
- 自动创建 LayoutRevision/ExportRevision。
- 自动确认 warnings、替用户导出或覆盖历史。
- 执行 inpaint/扩图；这些回候选图阶段产生新 Candidate。

Pending command apply 在 Server 事务中用 Shared reducer 重放，成功后在浏览器作为一次可撤销 batch。

## 21. 迁移与切换

### 21.1 Feature gate

建议内部 gate：

```text
layoutDocumentV1Read
layoutDocumentV1Write
layoutPublicationV1
```

不是长期双写开关：

- read 先支持 legacy 只读和 v1。
- write 开启后只写 DB `layout_document_v1`。
- publication green 后删除旧“复制源图”写入口。
- 禁止同时写新 DB 文档和旧 workspace layout.json。

### 21.2 旧数据

- 可解析：转换成 Working Copy，保留尺寸/顺序/来源，用户预览后保存正式版本。
- unresolved：旧内容只读，用户明确用当前定稿重建；不伪造 current。
- G1 metadata 档案和 migration provenance 保留原证据。

### 21.3 Rollback

- E0 原型可直接删除，不影响生产数据。
- V1 首次业务写前可关闭 gate 回到旧读页面。
- 首次 `layout_document_v1`/新 Revision/Publication 写入后，旧应用不能作为完整回滚目标；只能部署能读新 Schema 的修复版本或恢复 G1 协调 backup。
- 绝不能以重新启用复制源图导出“修复”正式 renderer 故障；可暂时禁用新导出并保留编辑/历史读取。

## 22. 安全、隐私与资源

- RenderScene 全部用户文字转义，不执行 HTML/脚本。
- Server renderer 无外网/file scheme；Asset 仅经 manifest/path guard/sha resolver。
- 禁止把图片模型 key、OpenCode auth、prompt、对话全文或绝对路径写入 document/task/manifest/log。
- 字体许可证/embeddingAllowed 是预检硬门禁。
- 文档、元素、文本、canvas、输出像素、PDF 页数和 renderer 时间/内存均有硬上限。
- 条漫分段虚拟化；Server 单 layout-render 并发槽，避免 Chromium/大 raster 并发耗尽内存。

## 23. 可访问性

- 工具按钮、图层和属性字段提供明确 label/快捷键提示和焦点顺序。
- 所有核心对象操作除自由拖拽外提供数字输入/键盘替代。
- 锁定/隐藏/stale/error 不只靠颜色，使用图标和文本。
- true preview 支持页面/画格阅读顺序描述；panelReadingOrder 是事实源。
- 属性输入错误就地说明，不只 toast。
- `prefers-reduced-motion` 下关闭非必要过渡；zoom/pan 不触发眩晕动画。

## 24. 可观测性

建议指标：

```text
layout_working_copy_save_duration_ms / conflict_total / payload_bytes
layout_command_apply_duration_ms / undo_depth
layout_preflight_duration_ms / issue_total{code,severity}
layout_render_duration_ms{phase,format}
layout_render_output_bytes / output_pixels / pdf_pages / slice_count
layout_render_failure_total{code,rendererVersion}
layout_source_replacement_total{cropMode}
```

日志只记录 project/chapter/layout/export/task/asset ID 与 digest、phase、尺寸和清洗后的 code；不打印全文文档/文字、storage 绝对路径、字体字节或秘密。

## 25. 主要风险与应对

| 风险 | 后果 | 应对 |
| --- | --- | --- |
| 先选热门画布库再补 renderer | 预览/导出两套语义 | E0 先做完整薄切片，adapter 私有状态不落盘 |
| 竖排字符范围富文本低估 | IME、标点、换列、PDF 漂移 | 固定 grapheme/text policy、受控字体和黄金样例 |

| 自动保存生成大量正式版本 | 历史噪声、下游误引用 | Working Copy/显式 LayoutRevision 分离 |

| 系统字体/字体许可证不受控 | 换机器漂移或不能嵌入 PDF | FontAsset sha/cmap/license/embedding gate |
| 条漫单个超高 DOM/raster | 卡顿、OOM、无法恢复 | logical sections、虚拟化、切片、能力上限 |

| 迟到 renderer 覆盖 current | 新成稿被旧任务替换 | immutable task input + completion applicability + current recheck |
| legacy fallback 长期保留 | 两套事实源和错误导出后门 | publication green 后删除旧写/复制导出路径 |
