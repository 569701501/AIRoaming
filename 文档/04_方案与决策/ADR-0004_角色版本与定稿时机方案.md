## 1. 状态

已采纳。

## 2. 背景

角色库已是项目级常驻资产，`/characters` 作为常驻资产入口保留（见 `2026-06-02_角色库与出图准备流程调整方案.md`）。但在落地过程中，角色图生成的时机、定稿规则、老角色带入、版本管理等关键交互一直没有正式定稿。

本文档记录 2026-06-18 经多轮讨论对齐后的最终规则，作为后续所有改动的唯一事实源。本规则聚焦「剧情结构页」的角色区域交互与角色生命周期，不改主流程结构。

## 3. 规则正文

### 3.1 流程定位

1. 主流程不变：剧本 → 剧情结构 → 分镜 → 出图准备 → 候选图 → 排版 → 素材包。
2. 角色库 `/characters` 作为常驻资产入口保留，不取消。
3. 角色图的生成、定稿、版本管理，全部发生在「剧情结构」页。

### 3.2 剧情结构页角色区域：显示规则

4. 角色区域显示两类角色：
   - 主角色/常驻角色（项目库已有）→ 自动带入显示。
   - 本章新角色（AI 识别）→ 列出待处理。
5. 两类角色在同一区域，用分组区分（主角色 / 本章新角色）。

### 3.3 新角色：图生成与定稿状态机

新角色从被识别到定稿，经历以下状态：

| 状态 | 页面显示 | 可操作 |
| --- | --- | --- |
| A 无图 | 灰占位 | `生成角色图` |
| B 有图未定稿 | 角色图 + 左上角 🔄 刷新 icon | 🔄 重新生成 / `定稿` |
| C 定稿中 | 角色图 🔒 | 无（等三视图生成） |
| D 定稿完成 | 角色图 🔒 + 三视图 | 点三视图 → 编辑弹窗重生 |

规则：

6. 点 `生成角色图` → 进入状态 B，得到预览图。
7. 状态 B 可以反复点 🔄 刷新重新生成，直到满意。
8. 必须先有角色图（状态 B）才能定稿。
9. 点 `定稿` → 角色图 🔒 锁死 → 自动触发生成三视图。
10. 角色图定稿后（状态 C/D）永不能重生，🔄 icon 消失。
11. 三视图生成中不显示；生成完成才显示（状态 D）。
12. 状态 D，用户觉得三视图不行 → 点击三视图 → 弹出编辑弹窗（现有功能）→ 改 prompt → 重新生成三视图，角色图不动。
13. 三视图重生不改角色图。

### 3.4 老角色（主角色/常驻，自动带入）规则

14. 老角色进剧情结构页 → 直接显示 `角色图 🔒 + 三视图`。
15. 老角色完全锁死：
    - 角色图不能改。
    - 三视图也不能改（连编辑弹窗都不给）。
    - 没有任何「重新生成」入口。
16. 老角色唯一能做的事：创建新版本（入口在 `⋯ 更多`）。

### 3.5 新版本规则

17. 创建新版本时，必须把老版本的角色图喂给 AI 作为参考。
18. AI 基于老版本图 + 用户修改意图 → 生成新版本的角色图。
19. 新版本生成后，走和「新角色」一样的流程：预览图 → 🔄 刷新 → 定稿 → 三视图。
20. 老版本图永远不变，新版本从创建章起往后生效。
21. 版本区间模型：第 1-4 章用 v1，第 5 章起用 v2；查询「第 N 章用哪个版本」= 找 `effectiveFromChapterId ≤ N` 的最新版本。
22. 老版本永不删除。

### 3.6 关键边界

23. 「定稿」这个动作只做一件事：锁定角色图 + 触发生成三视图。不做别的。
24. 角色图和三视图是两个独立资产：角色图（预览图）决定「角色长啥样」，三视图（设定图）是「正面/侧面/背面组合图」用于出图参考。
25. 三视图依赖角色图：没角色图不能定稿；三视图基于角色图生成；重生三视图基于同一个已锁定角色图。
26. 新版本依赖老版本图：新版本不是凭空生成，是「老图 + 调整」。
27. 角色图生成不阻塞主流程：生成分镜按钮永远可点，图在后台异步出，出图准备阶段做硬门槛兜底。

## 4. 数据结构示例

角色版本以数组承载，每个版本独立持有预览图与三视图，并记录生效章节：

```json
{
  "id": "char_linxia",
  "name": "林夏",
  "globalLevel": "lead",
  "sourceStep": "outline",
  "description": "齐耳短发，米色风衣，眼神锐利，身形清瘦",
  "versions": [
    {
      "version": 1,
      "effectiveFromChapterId": "chapter_001",
      "previewReferenceAssetId": "asset://char_linxia_v1_preview",
      "primaryReferenceAssetId": "asset://char_linxia_v1_final",
      "primaryReferenceKind": "final_reference",
      "promptFragment": "齐耳短发，米色风衣...",
      "finalizedAt": "2026-06-18T10:00:00Z",
      "createdAt": "2026-06-18T09:00:00Z"
    },
    {
      "version": 2,
      "effectiveFromChapterId": "chapter_005",
      "previewReferenceAssetId": "asset://char_linxia_v2_preview",
      "primaryReferenceAssetId": "asset://char_linxia_v2_final",
      "primaryReferenceKind": "final_reference",
      "promptFragment": "齐耳短发，左眉角有疤...",
```

查询规则：
- 第 3 章林夏用哪个版本：`effectiveFromChapterId ≤ chapter_003` 的最新版本 → v1。
- 第 7 章林夏用哪个版本：`effectiveFromChapterId ≤ chapter_007` 的最新版本 → v2。

## 5. 影响范围

### 5.1 数据模型

- `ProjectCharacter` 的角色图从「单值覆盖」改为「versions 数组」承载，每个版本含 `effectiveFromChapterId`、`previewReferenceAssetId`、`primaryReferenceAssetId`。
- 旧的单值字段（`previewReferenceAssetId`、`primaryReferenceAssetId`、`primaryReferenceKind`、`visualVersion` 等）需迁移到 `versions[0]`。
- 已有项目数据需提供幂等迁移逻辑，把现有单值转成 `versions: [{version:1, effectiveFromChapterId: 当前章节, ...}]`。

### 5.2 任务触发点

| 触发点 | 动作 | 阻塞性 |
| --- | --- | --- |
| 大纲确认 | 提取主角/常驻，建档案（无图） | 不阻塞 |
| 章节剧情结构确认 | 匹配角色库 + 新角色建档案 + 排预览图任务 | 不阻塞 |
| 用户点「定稿」 | 锁定角色图 + 生成三视图 | 不阻塞 |
| 用户点 🔄 刷新 | 重新生成角色图（仅未定稿状态） | 不阻塞 |
| 用户点三视图 → 编辑弹窗 → 重生 | 重新生成三视图（角色图不动） | 不阻塞 |
| 用户点 `⋯ 更多 → 创建新版本` | 以老版本图为参考，生成新版本预览图 | 不阻塞 |
| 出图准备 | 读取本章出场角色的有效版本，检查必需角色是否有三视图 | 硬门槛 |

### 5.3 页面交互

- 剧情结构页「本章角色」区域改为分组展示（主角色 / 本章新角色），按状态机渲染卡片。
- 新角色卡片支持 4 状态流转（A 无图 / B 有图未定稿 / C 定稿中 / D 定稿完成）。
- 状态 B 的角色图左上角显示 🔄 刷新 icon；定稿后消失。
- 状态 D 的三视图点击进入现有编辑弹窗重生。
- 老角色卡片完全锁死，`⋯ 更多` 内提供「创建新版本」。
- 角色库全量视图展示版本历史，旧版本只读且不可删除。

### 5.4 关联文档

- 细化并扩展 `2026-06-02_角色库与出图准备流程调整方案.md` 中「角色库职责」和「新角色增量机制」两节，不冲突。
- `01_愿景与产品/核心用户流程.md` 第 7 节（项目角色库）和第 8 节（剧情结构）与本方案一致，无需改动。

## 6. 风险与后续

| 风险 | 应对 |
| --- | --- |
| 版本模型与现有「单值覆盖」结构冲突 | 必须写迁移逻辑，把现有单值字段迁入 `versions[0]`，迁移需幂等 |
| 角色识别准确度 | 大纲建档案时可给用户可编辑角色清单确认层级 |
| 版本累积过多 | 「创建新版本」入口隐藏在 `⋯ 更多`，不鼓励频繁升版本 |
| 新版本必须依赖老版本图 | 生成新版本时强制传入老版本角色图作为参考，AI 不得凭空生成 |
| 旧版本存储成本 | 旧版本三视图与预览图均保留，不清理 |

后续实现任务应在 `05_执行与记录/任务记录/` 建立对应任务目录，并在完成后补充功能完成记录。
