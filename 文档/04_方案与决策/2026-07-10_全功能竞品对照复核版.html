竞品对照
从“谁更强”回到“下一步做什么”

本页修正旧版中的现状过期、竞品误判与无证据排名。目标不是给平台排一个虚假的总分， 而是明确 AI漫游已经有什么、真正缺什么、每一类产品值得借鉴哪一段，以及后续功能讨论必须先决定什么。

定位保留 章节级漫画生产工作台

项目 / 章节 / 正式分镜 / preflight / 候选 / 排版 / 素材包的状态链与追溯骨架是差异化，不再宣称“市场独家”。

事实更新 旧版 P0 多数已经完成

prompt 预览、候选批次、分镜缩略图、拖拽重排和全章批量生成已落地，不能继续列成缺口。

下一矛盾 从图片批次走向漫画成稿

真正需要讨论的是状态闭环、prompt 版本、气泡文字层、多镜排版和渠道化导出，而不是继续堆生图入口。

00

怎么读这份对照

商业产品公开页大多带营销口径。本页把证据强度单独标记；没有登录付费产品实测的能力，不再写成“无”或“最强”。

A

可直接确认

官方帮助文档、官方源码或当前项目代码。可写“已支持 / 已实现”。

B

官方自述

官方发布说明或营销页。可写“官方宣称支持”，不能替代稳定性与体验实测。

C

待登录实测

公开资料不足、套餐差异或仅能从截图推断。矩阵统一标“未见公开证据 / 待实测”。

01

总判断：哪些保留，哪些改写

旧版的分类方法仍有用，但结论必须从“绝对排名”改成“证据化能力事实 + 面向 AI漫游的产品启示”。

Keep · 保留

生产链路比单点生图更重要

AI漫游的价值不是一次生成几张图，而是把正式输入、人工确认、任务结果和最终资产绑定起来。这个方向应继续守住。

Correct · 修正

“完整链路”只能叫 MVP 骨架

当前排版仍是一镜一页 PNG，尚无多镜拼版、气泡、长图/ZIP/PDF。应写“状态链已打通”，不能写成“已交付完整漫画”。

Decide · 先决策

先定首个交付格式，再做排版

竖滑条漫、横版页漫、四格和印刷 PDF 的页面模型完全不同。没有首发渠道，气泡和排版需求就无法收口。

Avoid · 删除

删除“独家、最强、80%”

没有统一实测、用户数据或市场样本时，不做强弱总排名。对手公开资料中没有出现某能力，也只能写“未见公开证据”。

02

AI漫游当前真实状态

以 2026-07-10 当前代码为准。重点区分“已经能操作”“只有结构或视觉”“完全缺失”。

候选批次

已实现

按生成任务 `taskId` 分批，最新批展开、旧批折叠；“重新生成”保留旧批。

下一步：批次命名、成本信息、清理和归档策略。

prompt 透明

部分

已展示画面、构图、角色、场景、风格与完整 provider prompt，生成前可检查。

缺口：不可编辑；修改后没有 prompt 版本与新批次的正式关联。

候选 5 态

部分

枚举与视觉覆盖 generated / selected / locked / rejected / superseded。

缺口：业务只稳定驱动 generated / locked，其余状态缺命令、API 和转换规则。

批量生成

已实现

可一次为本章全部未锁镜头创建候选任务，后端按本地队列串行生成。

下一步：失败汇总、重试、成本预估和全章批次视图。

分镜预览与重排

已实现

镜头卡显示锁定图或最新候选缩略图；支持拖拽重排、重新编号和下游失效确认。

缺口：单镜 AI 重写、没有候选时的视觉草图。

漫画成稿

核心缺口

已有 layout 数据与 PNG 序列导出，但当前每个镜头独占一页，只是交付骨架。

缺口：气泡/旁白、多镜拼版、长图、ZIP、PDF 和渠道规格。
03

直接竞品：漫画生产工具

这四个产品与 AI漫游共享“多画格叙事 / 漫画编辑 / 成稿输出”问题，适合进入同一张能力矩阵。

Dashtoon Studio

故事到漫画 + 专业画布 + 发布

B
  • Story Mode 把故事转为逐格 screenplay，每格可编辑并可通过文字新增。
  • 官方发布说明包含无限画布、Storyboard-to-Comic、inpainting、image-to-image 与气泡工具。
  • 官网提供发布和变现入口；发布侧接受 JPEG / PNG，偏竖滑 Webtoon。
值得学画布内图像编辑、气泡尾巴、创作到发布闭环。
不要推断未公开确认 PDF、候选版本历史和 manifest。

LlamaGen

候选迭代 + 故事板 + 多格式导出

B
  • 官方发布记录确认单 panel redraw、批量重画和 Comic History。
  • Version History / Generation History 支持恢复旧版本与复用旧资产。
  • 公开支持 PDF，并在故事板工作流中导出 Word / Excel / PDF / MP4。
值得学版本与生成历史分层、批量重画、多格式生产交接。
不要推断“最优/最成熟”需要同任务实测后才能成立。

Anifusion

漫画页编辑 + 角色资产 + 视频延展

B
  • 官方当前页面覆盖 layouts/templates、可编辑气泡和文字层、无限画布与 inpaint。
  • Character Sheet、LoRA、批量生成与保存角色是长期连载能力基础。
  • 公开支持 PNG / PDF 与图生视频；漫画和视频工具处于同一产品套件。
值得学文字层、角色 sheet、多页项目、漫画到视频延展。
不要推断“manga 最强”没有统一评分和付费实测支撑。

AI Comic Factory

开源整页生成 + 轻量编辑

A
  • 当前官方源码包含单格 Redraw、单格 Edit Prompt，而不是“只能重做整页”。
  • Caption 是可编辑覆盖层；仓库包含多种页面布局。
  • 通过浏览器 Print to PDF 导出，但源码未保证固定 300 DPI。
值得学低门槛整页体验、轻量单格 prompt 编辑、零复杂工程导出。
真实短板章节状态、候选版本、素材追溯与专业排版深度有限。

05

局部能力参考：不要再混进漫画总分

这些产品不是 AI漫游的完整直接竞品，但某个环节值得借鉴。每张卡只回答“学什么”和“不能由此推断什么”。

Midjourney / Niji

生图与局部编辑

官方文档确认默认四图、reroll/rerun、参考图权重和 Editor mask/inpainting。

学：一次多候选、变体、遮罩编辑心智。
不推断：不具备漫画章节业务链。

Katalist

脚本到故事板

脚本自动拆镜、角色一致性、镜头的 framing / angle / pose / composition 控制。

学：分镜视觉化和镜头控制。
不推断：故事板输出不等于漫画成稿。

LTX Studio

故事板到视频时间线

从 script 生成 scenes/storyboards，提供 Dynamic Storyboard、Timeline/Video Editor 与一致性 Elements。

学：阶段衔接、Retake、时间线。
不推断：视频 workflow 不等于漫画排版。

Runway Gen-4

参考图一致性

官方帮助中心确认单张或多张 References 可保持人物、物体、地点与风格。

学：参考资产命名、复用和多场景一致性。
不推断：模型一致性不能替代角色版本契约。

即梦

中文画布与图像编辑

公开官网可确认智能画布、局部重绘、扩图、消除和抠图；具体九宫格/故事板能力需按账号实测。

学：中文指令与局部编辑入口。
不推断：不要与可灵合成一个能力列。

可灵

图片编辑与视频生成

快手官方公开资料确认图片局部重绘/扩图与视频生成体系；它更接近动态内容平台。

学：静态画格到视频延展。
不推断：不因视频强就判定漫画生产强。

ComfyUI App Mode

底层工作流产品化

官方 App Mode 可把节点 workflow 的选定输入输出包装成简化应用界面，并保存、分享、运行。

学：内部 workflow 与用户界面分离。
不推断：AI漫游默认 UI 不应变成节点编辑器。
06

修正后的优先级

不按竞品功能数量排期。先关闭当前状态语义，再定义首个交付渠道，最后由真实失败类型决定 inpaint 和视频的投入。

NOW · 先收口

候选迭代闭环

把“看得到”升级为“语义完整、可恢复”。

  • 候选状态命令/API明确 selected、locked、rejected、superseded 的用户动作和状态转换。
  • prompt 编辑与版本编辑后创建新批次，记录完整 prompt 与来源，不覆盖旧依据。
  • 真实路径复核验证多批重画、批量失败、锁定、排版和素材包的完整用户路径。
NEXT · 做成稿

首个可交付漫画格式

从图片序列跨到真正可读的一章漫画。

  • 先选竖滑 / 页漫 / 四格第一版只服务一个主格式，避免同时建设三套布局模型。
  • 可序列化气泡文字层dialogue/caption、位置、尺寸、样式、tail、读序；先人工可编辑。
  • 多镜模板与渠道导出线上优先长图/PNG/ZIP；印刷或审阅场景再补 PDF。
CONDITIONAL · 条件式

局部修图与视频延展

由用户失败数据和项目路线共同决定。

  • inpaint 不必先做无限画布可从单图 mask 弹窗开始，但必须先统一 provider edit/mask 契约与追溯。
  • 基础轻漫剧仍是 P0.5如要降为 P2，必须同步修改产品路线和正式决策，不能由竞品报告静默改变。
  • 专家模式不排默认路线ComfyUI 只保留底层兼容思路，等明确专家用户需求再决定界面。
排期原则：如果一个功能不能缩短“正式分镜 → 可交付一章漫画”的真实路径，或不能提高生成失败后的可恢复性，就不应仅因为竞品有而进入近期主线。
07

后续功能讨论清单

下一轮讨论不需要重新从竞品开始。按下面六个决策题逐项收口，就能形成气泡、排版、prompt 和 inpaint 的正式方案。

第一版交付的是哪种漫画？

竖滑条漫、横版页漫、四格还是印刷 PDF？这决定页面尺寸、画格模板、读序和导出物。

建议默认：如果面向中文线上连载，优先竖滑条漫 + 长图/PNG/ZIP；PDF 作为后续审阅或印刷出口。

气泡 V1 做到什么程度？

只需人工移动与改字，还是必须自动放置、自动尾巴指向、碰撞避让和竖排？

建议默认：先做人工可编辑文字层 + 基础样式；自动布局只提供建议，不作为首版阻塞条件。

selected 和 locked 有什么差别？

selected 是临时候选、locked 是下游正式输入，还是二者对普通用户只保留一个？

建议默认：selected 可多选/暂存，locked 每镜唯一且触发下游；rejected 可恢复，superseded 由系统派生。

prompt 编辑放在哪一层？

改镜头字段、改组合后的 provider prompt，还是建立“高级 prompt 覆盖值”？不同选择影响事实源和可追溯性。

建议默认：保留结构化镜头事实，允许候选阶段设置本次生成覆盖值；每次覆盖都随新批次落盘。

inpaint 首先解决哪类失败？

脸崩、手指、服装、道具、背景、文字残留的技术路径不同，不能用一个“局部重绘”按钮概括。

建议默认：先记录整镜重画失败原因；若脸/局部物体问题占比高，再做 mask 弹窗和 provider 适配。

视频 P0.5 与漫画成稿如何并行？

先完成静态漫画交付，再做基础漫剧；还是两条小队并行？需要明确同一 Shot 的素材与状态如何共享。

建议默认：静态成稿为主线，视频只消费锁定图和 motion 字段，不反向阻塞漫画排版。
