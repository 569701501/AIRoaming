# G3-M 施工包：备份、恢复与 DB-only 激活

M5 原始实现细节在 `文档/05_执行与记录/任务记录/2026-07-13_G3-M5协调备份恢复/`；2026-07-13 独立复核后的当前入口为相邻 `2026-07-13_G3-M5A4验收收口/`。本文继续提供 M5/M6 总边界。

## 1. 首版边界

首版只做 offline coordinated backup：进入 maintenance closed、完成 SQLite checkpoint、停止业务进程后备份。不得把直接复制运行中的 db/wal/shm 宣称为一致备份。

备份是目录 bundle，不要求 ZIP；实际 SecretStore 内容不进入 bundle。

## 2. DB capability gate

新增 db-capability-registry.ts 与命令：

```text
db:capabilities --format json
db:capabilities --check
```

registry 每项：id、ownerModule、readStatus、writeStatus、restartCovered、requiredForActivate、evidenceTestIds、blocker。

required 范围至少覆盖：Project/Chapter/Script、Outline、Story、Storyboard/Shot、Preflight、Character/Scene/Asset/Candidate/Lock、Layout/Export、Dialogue/Pending、Task create/claim/complete/cancel/recover、Settings/Credential、Project delete/Outbox。

只要任一 `requiredForActivate=true` 的项未同时满足读写 `implemented`、`restartCovered=true` 且 `evidenceTestIds` 非空，`db:import --kind final`、`app:backup --kind pre-cutover` 和 `db:activate` 都返回 `MIGRATION_CAPABILITY_BLOCKED`。

当前 ProjectRepository 的 create_project/save_chapter_draft/complete_chapter 只能证明局部能力，不能把 registry 总门标绿。

## 3. 备份 bundle

### 3.1 命令

```text
app:backup
  --database-url <explicit sqlite url>
  --workspace-root <explicit path>
  --data-root <explicit path>
  --release-root <explicit current release root>
  --app-commit <explicit commit sha>
  --maintenance-bundle <explicit closed runtime bundle file>
  --full-import-report <explicit full shadow report>  # coordinated
  --decisions <explicit decisions artifact>           # coordinated
  --run-id <verified final run id>                     # pre-cutover 保留
  --output <explicit empty directory>
  --kind pre-cutover|coordinated
  --format json
```

`coordinated` 允许 M5 在临时根绑定 succeeded full-shadow 证据集做恢复演练；不接受单条 shadow run 代表全量成功。`pre-cutover` 必须绑定 succeeded final run、ready PersistenceState 且 capability 全绿。D2-A7 前后者保持 fail-closed；D2 全绿后可在带 marker 的临时根开发和演练，真实根成功路径仍需单独授权。

### 3.2 内容

```text
backup-<bundleDigest>/
  backup-manifest.json
  database/app.db
  assets/<storageKey>
  config/settings.redacted.json
  migration/run-summary.json
  legacy-metadata/          可选，仅已脱敏档案
  SEALED
```

manifest schemaVersion=1，包含 kind、appCommit、migration ledger/checksum、有序 runIds、fullImportReportDigest、runSummaryDigest、source/snapshot/decisions/effective manifest digest、PersistenceState 摘要、DB sha256/bytes、每个 ready Asset storageKey/sha256/bytes、缺失资产清单、secretHandling、bundleDigest。`coordinated` 必须验证 `airoaming_full_shadow_import_v1` 正好包含 `FULL_SHADOW_SLICE_ORDER` 的 16 个 succeeded slice，聚合摘要可重算，每个 nested report/run/ledger 匹配，且 16 条 run 共享同一 source/snapshot/decisions 身份；显式 decisions artifact 必须与 run 摘要绑定。`coordinated` 可记录 `cutoverRunId=null`；只有 `pre-cutover` 才要求 final cutover identity。

任一 ready Asset 缺失或摘要不符时 backup 失败；missing 状态资产只进报告，不伪装为 ready。物理孤儿不自动纳入。

### 3.3 一致性顺序

1. coordinator=closed，active/queued=0，并验证显式 maintenance bundle。
2. 停止业务 Server；backup 进程执行并验证 WAL checkpoint，取得复制期间的排他写阻断。
3. 无法 checkpoint、WAL 未收敛、存在 writer 或无法取得排他锁时返回 `BACKUP_NOT_OFFLINE`。
4. 在锁保护下复制 DB 到临时 bundle；对副本执行 integrity_check/foreign_key_check/ledger。
5. 按 DB ready Asset 清单复制字节并逐项校验。
6. 写无秘密配置和 run summary。
7. secret sentinel 扫描为 0。
8. 写 manifest、fsync、原子 rename、写 SEALED。

任何失败都不产生 SEALED；临时目录可由清理命令按 marker/runId 精确删除。

## 4. Restore

### 4.1 命令

```text
app:restore
  --backup <sealed bundle>
  --target-data-root <explicit absent path>
  --target-workspace-root <explicit absent path>
  --mode verify-only|materialize
  --format json
```

materialize 只接受不存在的目标根，以保证 staging rename 语义；不提供覆盖活动根的 flag。先完整校验 bundleDigest、每项文件摘要、DB integrity/FK/ledger，再复制到带同一 restore marker 的 staging，最后按 data/workspace 两根分别原子发布。两根之间不声称跨文件系统事务原子；第二根失败时只补偿清理本 run marker 且未被外部修改的第一根。

restore 后默认保持 maintenance closed；必须执行 DB read-only/API smoke，SecretStore 引用可读或明确进入 credential_reconfiguration_required，才允许开放。

同一机器可复用系统 SecretStore；跨机器不得把 secretRef 可见误判成秘密可用。

## 5. PersistenceState 与激活

### 5.1 ready_for_activation

final succeeded 后由 cutover coordinator 单事务写：activationState=ready_for_activation、cutoverRunId、sourceManifestDigest、effectiveSchemaManifestDigest、lastVerifiedAt；activatedAt/firstBusinessWriteAt 必须 null。

身份必须分别匹配 final MigrationRun.sourceManifestDigest 与 verificationJson.effectiveSchemaManifestDigest，不能互换。

### 5.2 activate CLI

```text
db:activate
  --database-url <explicit sqlite url>
  --run-id <final run id>
  --source-manifest-digest <sha256>
  --effective-manifest-digest <sha256>
  --backup <sealed backup>
  --gate ACT-08
  --dry-run|--execute
```

execute 只在用户已单独授权正式切换时运行。dry-run 不写数据库。

原子 UPDATE：ready_for_activation→db_only 并首次写 activatedAt；不得同时写 firstBusinessWriteAt。更新后立即读回 PersistenceState、final run、当前 release effective manifest。

### 5.3 第一笔业务写

所有 DB 业务 UnitOfWork 在事务内先检查 PersistenceState。若 db_only 且 firstBusinessWriteAt=null，在同一业务事务写入首次时间；事务回滚则时间也回滚。maintenance smoke 的测试写必须整体 rollback。

firstBusinessWriteAt 非空后只能运行兼容当前 DB 的应用或恢复协调 backup，禁止 file-only。

bridge file 模式在 C3 后必须保留显式 DATABASE_URL 并在启动时读取 PersistenceState：已激活或无法核对 cutover identity 时拒绝启动；开放写入前回滚只能使用同一 bridge release。

## 6. 正式切换顺序

2026-07-13 M6-A1 复核纠正：pre-cutover DB backup 要求 final succeeded + `ready_for_activation`，因此不可能在 C2 生成。C2 只生成最终旧源 snapshot；pre-cutover backup、verify-only 和 materialize rehearsal 固定在 C4 ready 之后、C5 smoke 之前。

```text
C0 bridge release/file mode + 全门禁
C1 同进程 drain/close/runtime bundle
C2 final source snapshot + source rollback evidence
C3 fresh DB + SecretStore 预暂存
C4 final import/verify + settings 明文清除 + ready_for_activation
   + pre-cutover backup + verify-only/materialize rehearsal
C5 DB maintenance start + read/API/rollback smoke
C6 metadata-only archive，Asset 原路径保留
C7 db:activate execute + reopen DB writes
```

C0～C7 任一步不得并行。C4 前失败可清理目标并 reopen 旧进程；明文清除后回滚仍使用 SecretStore，不恢复 plaintext。

## 7. 回滚矩阵

| 时点 | 允许 | 禁止 |
| --- | --- | --- |
| shadow/final 失败 | 丢弃目标 DB，旧 closed 进程 reopen | 双边开放写 |
| ready_for_activation、first write=null | restore snapshot/runtime bundle，同 bridge file mode | 更旧二进制/明文 secret |
| db_only、first write=null | 先停 DB，按授权恢复 pre-cutover bundle | 无证据直接改状态 |
| first write 非空 | 兼容 DB 应用或 coordinated backup restore | file-only、down migration、改回 legacy enum |

恢复动作必须新建 kind=rollback_restore 的 MigrationRun 或 run-summary，保留原 cutover identity，不删除旧 final run。

## 8. 稳定错误

| code | 含义 |
| --- | --- |
| BACKUP_NOT_OFFLINE | 仍有 writer/进程未停 |
| BACKUP_ARGS_INVALID | 参数缺失、重复或路径不符合显式契约 |
| BACKUP_PATH_UNSAFE | 根重叠、symlink、越界或 DB 不在 dataRoot |
| BACKUP_RUN_INVALID | run 与 backup kind/status/identity 不匹配 |
| BACKUP_ASSET_MISMATCH | ready Asset 缺失或摘要不符 |
| BACKUP_SECRET_DETECTED | bundle 命中秘密 |
| BACKUP_NOT_SEALED | restore 输入不完整 |
| RESTORE_ARGS_INVALID | restore 参数缺失、重复或非法 |
| RESTORE_TARGET_NOT_EMPTY | 目标根非空 |
| RESTORE_VERIFICATION_FAILED | digest/DB/Asset 任一失败 |
| ACTIVATE_NOT_READY | PersistenceState 或 final run 不满足 |
| ACTIVATE_IDENTITY_MISMATCH | source/effective/release identity 不同 |
| ACTIVATE_BACKUP_UNVERIFIED | 没有已演练 sealed backup |
| FILE_MODE_FORBIDDEN_AFTER_FIRST_WRITE | 不可逆边界已越过 |
