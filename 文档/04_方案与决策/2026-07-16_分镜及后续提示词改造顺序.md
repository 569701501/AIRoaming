# 分镜及后续提示词改造顺序

## 1. 正式结论

剧本与剧情结构之后，下一项先完善**分镜 Prompt / Skill**。

本轮不调整页面已经展示的分镜字段，不新增下游流程，也不为“AI 创作”和“已有剧本导入”复制两套分镜能力。两条上游路线都在用户确认本章剧情结构后汇合：

```text
已确认 StoryVersion / StoryStructure
→ 用户明确要求生成当前章分镜
→ AI 生成待确认分镜草稿
→ 用户查看、编辑或要求 AI 调整
→ 用户确认
→ 正式 StoryboardVersion
→ 出图准备及候选图
```

AI 创作和已有剧本导入只在上游方法、Prompt 和质量标准上不同。进入分镜阶段后，事实源都是已确认的本章剧情结构，因此共用同一套分镜生成与检查规则。

## 2. 当前分镜流程保持不变

| 节点 | 当前规则 |
| --- | --- |
| 进入条件 | 当前章节已有用户确认的剧情结构 |
| 触发方式 | 用户在分镜阶段明确要求“生成当前章分镜”，不能由剧情结构确认自动触发 |
| AI 产物 | 当前章节的待确认 `Shot[]` 草稿 |
| 用户检查 | 在现有分镜工作台查看镜头卡、顺序、角色、场景、动作、对白和漫画/漫剧字段 |
| 草稿调整 | 当前页面继续支持直接编辑、排序、新增和删除；后续补齐“让 AI 调整待确认草稿”能力 |
| 正式确认 | 用户确认后才形成正式 `StoryboardVersion` |
| 下游门禁 | 待确认草稿不能进入出图准备或候选图生成 |

## 3. 页面字段不改

现有页面字段已经足够用户查看和调整，继续保持：

### 3.1 共同镜头核心

```text
order
beatId
sceneId
characterIds
coreAction
emotion
shotType
cameraAngle
```

### 3.2 漫画表达

```text
comic.panelDescription
comic.composition
comic.dialogue
comic.caption
comic.panelRhythm
```

### 3.3 基础漫剧表达

```text
motion.visualDescription
motion.compositionDesign
motion.cameraMovement
motion.frameType
motion.durationMs
motion.durationHint
motion.voiceLines[]
```

`promptDraft` 继续只是供后续候选图阶段使用的简短画面摘要，不承担最终图片 Prompt 的职责。

## 5. 当前实现发现的四个缺口

### 5.1 Prompt 偏“填表”，缺少固定分镜质量门

当前 Prompt 对 JSON 字段和枚举规定较多，但没有稳定检查以下质量：

- 每个剧情节拍是否被镜头覆盖；
- 场景、人物和节拍引用是否都来自已确认剧情结构；
- 动作前后、人物位置和视线是否连续；
- 景别、机位和镜头类型是否根据剧情功能变化；
- 情绪峰值、信息揭示和结尾钩子是否获得足够画面强调；
- 漫画阅读顺序、对白气泡承载量和画格节奏是否合理；
- comic 与 motion 是否在表达同一个剧情瞬间；
- 是否存在重复、空泛或一镜塞入多个不可同时呈现动作的镜头。

### 5.2 一个枚举值不一致

当前 Prompt 要求：

```text
over_the_shoulder
```

正式共享契约和数据库使用：

```text
over_shoulder
```

旧兼容层会把前者静默降级为 `eye_level`，导致模型明明选择了过肩镜头，正式数据却被改成平视。下一轮必须先修正。

### 5.3 AI 输出引用与数据库 ID 边界不清

当前 Prompt 让 AI 在 `characterIds` 中填写角色名，而正式数据库要求项目角色 ID。合理边界应为：

| 层级 | 职责 |
| --- | --- |
| AI 输出 | 使用剧情结构中已有的本地引用或角色名，不生成数据库 UUID |
| 工作台 DTO / 后端 | 把 AI 本地引用映射为正式角色、场景和节拍 ID，并报告未解析引用 |
| 数据库 | 只保存已经通过映射和范围校验的正式 ID |

页面字段不需要因此变化，但确认前必须完成映射，不能依赖容错层静默猜测。

### 5.4 没有“固定校验 + 定向修复”

当前分镜生成只调用模型一次，然后使用宽松兼容逻辑补默认值。它可以把非法枚举、缺字段和空数组变成“可保存的数据”，却不能判断分镜是否忠实、完整、连贯。

下一轮应沿用剧情结构阶段已经验证的方式：

```text
模型生成
→ JSON / 引用 / 固定质量门校验
→ 通过：保存待确认草稿
→ 未通过：携带明确问题定向修复一次
→ 再失败：不保存坏草稿，向用户报告
```

固定校验只判断高确定性的错误，不使用主观总分，也不要求所有章节机械地拥有相同景别比例。

## 6. 分镜能力拆成两个动作

分镜仍是一项逻辑能力，但内部包含两个明确动作，不能用一条模糊 Prompt 同时承担。

当前 OpenCode `skills/` 资产目录尚未接入生产运行时复制，因此 S1 的真实生产入口是服务端动态 Prompt。现阶段不创建无法被调用的孤立 `SKILL.md`；等运行时真正加载 Skill 资产后，再把同一能力暴露为 `storyboard-shot-generate`，不改变下面的动作契约。

### 6.1 首次生成

```text
generate
```

输入是已确认剧情结构、正式章节正文中的必要对白/动作和用户本次要求；输出完整的待确认 `Shot[]`。

### 6.2 调整待确认草稿

```text
revise_pending
```

输入是当前待确认分镜、已确认剧情结构和用户的具体调整要求；输出一份新的完整待确认分镜，替换旧的待确认草稿，但不覆盖正式分镜。

允许的要求例如：

- “把打斗节奏加快”；
- “结尾钩子多给一个特写”；
- “对白太密，拆成两个画格”；
- “不要改变剧情，只调整景别和机位”。

若章节已经存在正式分镜，仍沿用当前覆盖警告；用户确认重新生成后才创建新的待确认草稿。

不为“调整节奏”“重写单镜头”“修复引用”分别创建多个孤立 Skill。

## 7. 分镜 Prompt 的固定质量契约

S1 已把以下规则写入生成和调整 Prompt，作为模型输出前的内部检查；S2 再把其中高确定性的项目变成后端固定校验和一次定向修复：

| 维度 | 固定要求 |
| --- | --- |
| 忠实性 | 不新增结构和正文中不存在的事件、人物、道具结论或对白事实 |
| 覆盖 | 每个 beat 至少被一个 Shot 承接；每个 Shot 必须引用一个有效 beat 和 scene |
| 单镜头可画性 | 一个 Shot 聚焦一个可以被单帧表达的主要瞬间，不把连续多动作塞成一句 |
| 连续性 | 人物、道具、空间、行动结果和视线方向前后可衔接 |
| 叙事功能 | 建立、动作、反应、细节、对话和转场根据剧情功能使用，不机械平均 |
| 漫画语法 | 保证阅读顺序、信息揭示顺序、对白承载量和强弱画格节奏 |
| 视觉变化 | 连续镜头避免无意义地重复相同景别、机位、构图和动作描述 |
| 重点强调 | 关键选择、情绪峰值、线索揭示和结尾钩子获得合适的反应或细节镜头 |
| 双表达一致 | comic 和 motion 描述同一剧情瞬间；运动字段可增加时间表达，但不能改变事实 |
| 下游边界 | 不直接写最终图片 Prompt，不擅自生成图片、声音、字幕、排版或视频 |

## 8. 用户纠偏后的当前推进顺序

S1 完成后，用户明确纠正了原先“立刻进入 S2 分镜固定校验”的顺序：当前更需要继续 2026-07-09 外部借鉴方案里的 P23～P26，并由真实下游需要反推 P06。正式顺序调整为：

```text
P23 角色参考图 + P24 场景参考图
→ P25 候选图真实 provider Prompt
→ P26 页面预览 Prompt
→ 反推 P06 分镜画面事实与 promptDraft 边界
→ 固定测试与 fake-provider 页面闭环
```

原因不是分镜质量门不重要，而是如果候选图真实输入、参考图约束和页面预览尚未同源，先继续给分镜增加抽象规则仍无法证明最终图片质量。

### D1：角色与场景参考图 Prompt（已完成）

- 角色 preview 固定为单角色身份种子：脸型、发型轮廓、年龄、体型、服装结构、颜色和固定配饰必须清楚。
- 角色 final 固定为同一角色、同一服装、同一比例的四视图，明确前半身、前全身、侧全身、后全身顺序。
- 场景参考图固定为可复用环境资产：无人、无文字、无动作主体，包含前中后景、透视、入口出口、稳定地标、时间天气和光线方向。
- 不复制外部完整模板，不写艺术家名、第三方 IP 或 provider 私有参数。

### D2：候选图实际 Prompt 与页面预览（已完成）

- `buildCandidatePromptContent` 是普通/file、DB 持久任务和页面预览共同使用的领域构造器。
- Prompt 固定组织为主体静态瞬间、动作情绪、构图焦点、景别机位、角色身份、环境光线和漫画画风。
- 输出只能是一张干净漫画底图、一个场景、一个静态瞬间和一个主要构图；不得包含文字、气泡、分格、整页漫画、拼贴或角色设定表。
- DB 任务创建时冻结 `providerType/providerProfileId/providerPrompt/negativePromptDelivery`；执行前若当前 provider 已变化则停止，不把另一种 profile 的 Prompt 静默发送出去。
- 页面展示服务端 `positivePrompt`；当前 OpenAI、Doubao、Grok 公共网关均只收单个 Prompt，且领域正向规格已包含自然语言禁令，因此不再由前端或 worker 固定追加 `Avoid:`。

### D3：反推 P06 分镜 Prompt（已完成）

- 分镜根据 beat 功能选择建立、动作、反应、细节或转场镜头，不机械套用视频平均切镜或固定 16:9 逻辑。
- `composition` 同时表达主体、视觉动线、必要留白和气泡安全区，但候选图本身仍禁止生成气泡与文字。
- `promptDraft` 只压缩主体身份、静态瞬间、环境、光线、情绪和构图重点，不包含对白原文、字幕、整页布局、模型名、艺术家名或 provider 参数。
- 页面和 `StoryboardShot` 字段保持不变。

### D4：固定验证（已完成）

- 固定单元样例覆盖角色 preview/final、场景参考、多人/单人/无角色候选图和三个 provider profile。
- DB 集成测试证明持久任务冻结统一规格和 provider profile。
- 新建隔离项目的 Chromium 路径证明假 provider 收到 3 次图片请求，页面可展开查看同源 Prompt；运行截图保存在任务 evidence 中。

## 9. 原 S2/S3 的保留位置

### S1：分镜生成契约与引用映射（已完成）

- 修正 `over_shoulder` 枚举。
- 冻结 AI 输出与 DTO / 数据库的引用边界。
- 完善首次生成 Prompt。
- 增加待确认草稿调整动作的意图和 Prompt 契约。
- DB 模式接入正式 Storyboard Working Copy：后台分配稳定 Shot ID、映射 Project Character ID，并使用版本服务保存和确认。
- 分镜对白/动作只读取剧情结构绑定的正式 ScriptVersion；存在未发布正文修改时拒绝生成。

### S2：分镜固定校验与一次修复（保留为后续）

- 增加覆盖、引用、顺序、必填、空泛重复和 comic/motion 一致性校验。
- 一次定向修复。
- 不再用默认值掩盖生产输出错误；旧数据读取仍保留兼容。

### S3：分镜测试与真实模型验收（保留为后续）

- 固定正例、缺 beat、非法引用、重复镜头、错误枚举、空对白/旁白等触发用例。
- 分别使用 AI 创作路线和已有剧本导入路线形成的 StoryVersion 做真实模型验证。
- 两种来源使用同一个分镜 Prompt，验证汇合后的行为一致。

### S4：真实图片评测（需要单独授权）

- 使用固定镜头集评测角色一致性、场景一致性、构图、文本污染和漫画风格。
- 按 OpenAI、Doubao、Grok 分别记录模型、尺寸、profile、输入参考图和结果，不把不同模型混成一个总分。
- 真实 provider 会消耗凭据或费用，只能在用户再次明确授权后执行；本轮 fake-provider 通过不等于真实图片艺术质量已经验收。

### 暂不新增的 Prompt

- 出图准备首先是确定性检查和用户放行，不需要创作型 Prompt。
- 排版导出首先是规则和编辑器问题，不优先用 LLM Prompt 解决。
- 素材包是确定性收集、校验和导出，不新增生成 Prompt。

## 10. 下一步施工范围

当前 P06/P23～P26 的生产 Prompt、provider 边界和页面预览已经收口。下一步有两个独立方向，不能混成一项：

1. 不调用付费图片模型时，继续 S2：只实现可确定的分镜固定校验与一次定向修复。
2. 用户明确授权真实图片调用时，执行 S4：在隔离新项目中用固定镜头集做 OpenAI/Doubao/Grok 分模型评测，再按真实图片缺陷调整 profile。

两者都不改变当前页面展示字段和用户确认流程。
