## 1. 复核结论

`全功能竞品对照-终版.html` 的大方向有价值：用“漫画垂直平台 / 生图平台 / 故事板视频平台 / 开源工作流”分组，并把 AI漫游定位为章节级生产工作台，而不是单点生图工具。

但当前版本不能直接作为产品排期依据，需做一次较大修订。问题集中在四类：

1. **AI漫游现状过期**：页面列为 P0 缺口的 prompt 预览、候选批次、分镜缩略图、拖拽重排、批量生成，已于 2026-07-09 落地。
2. **个别竞品事实错误**：AI Comic Factory 当前源码支持单格 Redraw、单格 Prompt 编辑、可编辑 Caption/气泡以及浏览器打印 PDF，与页面中的“不能单格重画 / prompt 不可编辑 / 只能改 caption”不符。
3. **推断写成事实**：`独家`、`最强`、`最优解`、`所有主流产品`、`整镜重画覆盖 80%` 等没有对应的比较标准、用户数据或逐条证据。
4. **优先级与项目事实源冲突**：现有项目事实源把基础轻漫剧列为 P0.5、局部重生成列为 P1；本页把两者都降到 P2，但没有作为产品决策变更留痕。

结论分级：**核心方向可保留，能力矩阵和排期结论需重写。**

## 4. 竞品能力重新校准

### 4.1 Dashtoon

官方 2024 Studio 发布说明可确认：Story Mode 会把故事转成逐格 screenplay；每格可编辑；编辑器有无限画布、预设 frame、text-to-image、storyboard-to-comic、inpainting、image-to-image、speech bubbles。官网同时提供发布和变现入口。

可以保留的判断：漫画垂直编辑与发布闭环较完整。

需要降级的判断：未找到足以证明其 `PDF 导出`、`候选历史强弱` 或“全章批量生成领先”的公开证据，应写“待实测”。

### 4.2 LlamaGen

官方发布记录可确认：

- 单 panel redraw（2024-03）。
- PDF 导出（2024-03）。
- Comic History 与批量重画（2025-09）。
- Version History / Generation History，可恢复旧版本和复用旧资产（官方帮助与官方博客）。
- Storyboard 可导出 PDF、screenplay、Word、shotlist Excel 和 MP4（2026-01）。

原页面把它作为“候选迭代参考”是合理的，但“最优解/最成熟”仍是主观排名，应改为“已公开覆盖较完整”。

### 4.3 Anifusion

官方当前页面可确认：漫画/漫画页生成、专业 layouts/templates、可编辑气泡和文字层、无限画布、inpaint、character sheet、PNG/PDF 导出、图生视频。

原页面的大部分功能点成立，但 `manga 最强`、`漫画页编辑最强` 没有统一样本和实测评分，应该删除排名，只保留能力事实。

### 4.4 AI Comic Factory

本次直接复核官方仓库源码（主分支最新提交日期 2025-10-30）：

- `src/app/interface/panel/index.tsx`：单格 `Redraw`、单格 `Edit Prompt`。
- `src/app/interface/panel/bubble/index.tsx`：Caption 为可编辑覆盖层。
- `src/app/interface/share/index.tsx`：通过浏览器 Print to PDF 导出。
- `src/app/layouts/index.tsx`：包含多种页面布局。

因此它不应再被写成“不可单格重画的反面教材”。更准确的短板是：项目/章节生产状态、正式素材追溯、候选版本管理和专业排版深度有限。

### 4.5 Midjourney / Niji

官方文档可确认：默认一组四图、reroll/rerun、图片参考与权重、Editor mask/inpainting、编辑结果历史。它适合作为“单图生成和局部编辑交互”的参考，不适合放进漫画章节业务矩阵后直接比较项目管理、preflight 或 manifest。

### 4.6 Katalist / LTX / Runway / ComfyUI

- Katalist：官方页面确认 script-to-storyboard、自动拆镜、角色一致性、镜头细节控制。
- LTX：官方页面确认从 script 生成 scenes/storyboards，提供 Storyboards、Dynamic Storyboard、Timeline/Video Editor 和一致性 Elements。
- Runway：官方文档确认 Gen-4 References 可用单张参考图保持角色、物体和场景一致性。
- ComfyUI：官方 App Mode 把 workflow 的输入/输出包装成简化应用界面；它是底层工作流参考，不是漫画生产直接竞品。

这些产品应作为局部能力参考，不应和漫画垂直平台共用一套“领先/强/中/弱”总分。

## 6. 建议的新优先级

### 立即修正：事实与状态闭环

1. 更新竞品页面，把已经完成的 5 项 P0 从“缺口”移到“已实现”。
2. 为候选 `selected/rejected/superseded` 明确用户动作、状态转换和持久化 API；不能只显示颜色。
3. 做一次真实用户路径复核：多批重画、prompt 预览、拖拽重排、批量生成、锁定、排版、素材包。

### 下一阶段：先定义交付渠道，再做成稿

1. 明确第一交付目标：竖滑条漫、横版页漫、四格、印刷 PDF，不能用一个“PDF 刚需”覆盖所有渠道。
2. 基础气泡采用可序列化文字层：dialogue/caption、位置、尺寸、样式、tail、读序；先做人工可编辑，不承诺智能排布。
3. 基础多镜排版：优先覆盖项目选定的首个漫画格式；线上发布优先长图/PNG/ZIP，印刷/审阅场景再补 PDF。
4. prompt 编辑必须形成新生成批次并保存 prompt 版本，避免只改界面、不保留生成依据。

### 条件式后置：局部修图与视频

- inpaint 的真实前置是 provider 是否支持 edit/mask、遮罩编辑器和结果追溯；不必先建设无限画布。是否进入近期排期，应由候选重画的真实失败类型决定。
- 基础轻漫剧在现有产品事实源中是 P0.5，不应由竞品报告静默改成 P2。若确实决定降级，需要同步更新产品路线和决策记录。
- `ComfyUI 式专家模式` 暂无明确用户需求，不建议默认进入 P2 路线，仅保留架构兼容思路。
