# G3-D2 与 M6 推进路线

## 1. 当前结论

- M5-A0～A3 的 capability registry、协调备份、sealed restore 与临时重启/API smoke 已有实现。
- M5 的原验收记录把 7 个集成测试扩写成了完整 BAK/RST 故障矩阵；独立复核又发现备份一致性窗口、恢复账本身份、release identity、secret 扫描和补偿清理仍有实现缺口。因此 M5 当前状态改为 `hardening_required`，先执行 M5-A4。
- D2 仍未满足：required capability 只有 task 全绿，Settings/SecretStore、final importer 和多组公开 DB 写路径仍阻塞。
- M6 继续为 `prerequisite_blocked`。没有 D2 全绿和用户对真实停写的再次授权，不得执行 `pre-cutover` 成功路径或 `db:activate --execute`。

## 2. 唯一顺序

```text
M5-A4 备份恢复验收收口
  -> D2-A0 操作级 capability 盘点
    -> D2-A1 Settings + SecretStore
      -> D2-A2 Project/Chapter/Script 公开写闭环
        -> D2-A3 Story/Storyboard/Preflight + Character/Scene/Asset/Lock
          -> D2-A4 Layout/Export
            -> D2-A5 Dialogue runtime
              -> D2-A6 Project delete + Outbox
                -> D2-A7 full final importer 与 ready_for_activation coordinator
                  -> D2-A8 双 fresh/replay/公开 DTO/secret 证据
                    -> D3 用户授权与 pre-cutover rehearsal
                      -> M6 C0～C7
```

一次只交付一个切片。上游未复核、未提交时，不领取下游。

| 切片 | 主要产出 | 退出门 |
| --- | --- | --- |

| D2-A1 | DB settings metadata、SecretStore adapter、fake store、credential redactor、明文移除/回滚契约 | SEC-01～11 适用项通过；DB/settings/report/log/workspace sentinel=0；无 SecretStore 时不回退明文 JSON |

## 4. M6 边界

M6 只负责已经满足 D2 后的切换编排、dry-run/execute activate 和回滚演练，不再夹带补业务 Repository、SecretStore 或 importer 的工作。

```text
C0 bridge release/file mode + 全门禁 + 用户再次授权
C1 同进程 drain/close/runtime bundle
C2 final snapshot + pre-cutover restore rehearsal
C3 fresh DB + SecretStore 预暂存
C4 final import/verify + 明文清除 + ready_for_activation
C5 DB maintenance read/API/rollback smoke
C6 metadata-only archive，Asset 原路径保留
C7 db:activate execute + reopen DB writes
```

## 5. 授权边界

- 可以在测试临时根实现和验证 M5-A4、D2 各切片及 `db:activate --dry-run`。
- 不得访问默认/真实 workspace、真实数据库或真实系统 SecretStore。
- 不得运行真实 `final`、`pre-cutover`、metadata archive 或 `db:activate --execute`。
- 用户当前“继续开发”的授权不等于 C0 的真实停写授权；C0 前必须再次明确询问。
