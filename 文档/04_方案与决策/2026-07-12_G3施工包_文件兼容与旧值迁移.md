# G3 施工包：file 兼容与旧值迁移

## 1. 目标与边界

当前默认 persistence mode 仍是 `file`，完整 G1 maintenance importer 尚未实现。G3-core 必须同时做到：

1. 新请求、新项目、新 Preflight、新 Task 只产生 canonical 两值。
2. 旧 file 项目不能因 Shared 枚举翻转而静默消失或被默认成 vertical。
3. G3-core 不复制一套完整 importer、MigrationRun、备份恢复或 DB-only activate。
4. 旧 Project metadata、历史 Preflight/Layout/Task 不因普通读取或无关编辑被全局改写。

因此本文冻结一个窄的 **file read compatibility boundary**。它不是 runtime 请求别名，也不是 importer。

## 2. 三类入口必须分离

| 入口 | 函数/模块 | 接受值 | 是否写入 |
| --- | --- | --- | --- |
| HTTP/DB/new artifact | `parseCanonicalComicFormat` | `vertical_scroll/paged_comic` | canonical only |
| 旧 `project.json` 读取 | `readLegacyProjectComicFormatV1` | canonical、`page_horizontal`、歧义值 | 只读分类 |
| G1 maintenance importer | `mapLegacyComicFormatForImportV1` | 任意 legacy snapshot 值 + decisions | 未来写 DB |

禁止把三者合并成 `normalizeComicFormat(value)`；禁止让 Controller 调用 file reader；禁止让 file reader创建 MigrationIssue。

## 3. tagged read contract

新增：

```text
apps/server/src/projects/legacy-project-comic-format.ts
apps/server/src/projects/legacy-project-comic-format.spec.ts
```

固定返回类型：

```ts
export const G3_FILE_COMIC_FORMAT_READ_POLICY_VERSION =
  "g3-file-comic-format-read-v1" as const;

export type LegacyComicFormatSafeValueKind =
  | "string"
  | "missing"
  | "number"
  | "boolean"
  | "array"
  | "object";

export type LegacyProjectComicFormatReadResult =
  | {
      status: "canonical";
      runtimeValue: ComicFormat;
      persistedValue: ComicFormat;
      policyVersion: typeof G3_FILE_COMIC_FORMAT_READ_POLICY_VERSION;
    }
  | {
      status: "auto_mapped_read_only";
      runtimeValue: "paged_comic";
      persistedValue: "page_horizontal";
      mappedFrom: "page_horizontal";
      policyVersion: typeof G3_FILE_COMIC_FORMAT_READ_POLICY_VERSION;
    }
  | {
      status: "decision_required";
      reason: "FOUR_PANEL" | "MISSING" | "INVALID";
      safeValueKind: LegacyComicFormatSafeValueKind;
      policyVersion: typeof G3_FILE_COMIC_FORMAT_READ_POLICY_VERSION;
    };

export function readLegacyProjectComicFormatV1(
  value: unknown,
): LegacyProjectComicFormatReadResult;
```

`safeValueKind` 只用于诊断，不保存完整非法对象或用户内容。

## 4. 映射矩阵

| `project.json.comicFormat` | 返回 | runtime | 原文件 |
| --- | --- | --- | --- |
| `vertical_scroll` | `canonical` | vertical | 保持原值 |
| `paged_comic` | `canonical` | paged | 保持原值 |
| `page_horizontal` | `auto_mapped_read_only` | paged | 保持 alias |
| `four_panel` | `decision_required/FOUR_PANEL` | 不加载 | 不改 |
| 缺失/null/空/纯空格 | `decision_required/MISSING` | 不加载 | 不改 |
| 其他字符串/类型 | `decision_required/INVALID` | 不加载 | 不改 |

`page_horizontal` 是唯一无歧义 alias。四格不能自动映射为分页漫画；LayoutPreset 意图尚无正式 G5 落点。

## 5. LocalProject 内部 provenance

修改：

```text
apps/server/src/projects/local-types.ts
```

增加仅 Server 内部可见字段：

```ts
export interface LocalProjectPersistenceCompatibility {
  comicFormatSource:
    | { kind: "canonical" }
    | {
        kind: "legacy_alias";
        rawValue: "page_horizontal";
        policyVersion: "g3-file-comic-format-read-v1";
      };
}

export interface LocalProject {
  // existing fields...
  persistenceCompatibility?: LocalProjectPersistenceCompatibility;
}
```

规则：

- 该字段不进入 Shared DTO、API、DB、SourceSnapshot、Prompt、Task、Layout 或用户界面。
- DB mode Project 不设置该字段。
- 新 file 项目设置 `canonical` 或省略，`project.json` 写 canonical。
- 旧 `page_horizontal` 项目设置 `legacy_alias`，runtime 的 `project.comicFormat` 为 `paged_comic`。
- 所有对象 spread/update 必须保留该字段；不能因更新章节而丢失 provenance。

## 6. file serializer 不自动迁移

修改：

```text
apps/server/src/projects/project-repository.service.ts
apps/server/src/projects/project-store.service.ts
```

写 `project.json` 时使用：

```ts
function persistedProjectComicFormat(project: LocalProject):
  | ComicFormat
  | "page_horizontal" {
  return project.persistenceCompatibility?.comicFormatSource.kind === "legacy_alias"
    ? project.persistenceCompatibility.comicFormatSource.rawValue
    : project.comicFormat;
}
```

含义：

- 旧 `page_horizontal` 项目在内存/API/新下游中表现为 `paged_comic`。
- 保存剧本、章节或其他无关内容时，`project.json` 继续保留原 alias。
- G3-core 不借普通写入静默迁移文件，也不丢失 importer 的 `mappedFrom` 证据。
- 只有未来 G3-M/G1 importer 才清除 provenance 并写 canonical DB。

不得把 `persistenceCompatibility` 整体序列化到 `project.json`；原始 alias 本身就是当前迁移输入证据。

## 7. 加载失败语义

当前加载循环会 catch 任意错误并 warning 后跳过单个项目。G3 必须区分：

```ts
export class LegacyComicFormatDecisionRequiredError extends Error {
  readonly code = "LEGACY_COMIC_FORMAT_DECISION_REQUIRED";
  readonly projectId: string;
  readonly reason: "FOUR_PANEL" | "MISSING" | "INVALID";
  readonly safeValueKind: LegacyComicFormatSafeValueKind;
}
```

处理规则：

1. 扫描目录时收集所有该类错误，只记录 projectId/reason/safeValueKind。
2. 扫描结束后，如果集合非空，`ensureLoaded/listProjects` 整体 fail-closed。
3. 不把有问题项目默默从项目库隐藏，也不加载为 vertical。
4. 不输出物理 workspace 根、完整 metadata、原始非法对象或用户内容。
5. 其他文件损坏仍沿用现有分类，但完成记录必须说明是否仍会 skip；G3 只强制改变 comicFormat decision error。

API 映射：

```text
409 LEGACY_COMIC_FORMAT_DECISION_REQUIRED
details = {
  issueCount: number,
  projects: Array<{ projectId, reason, safeValueKind }>
}
```

`projects` 最多 100 条；更多时只返回 count，避免超大响应。

## 8. 只读 audit 命令

G3-core 增加一个直接、只读的 inventory 命令，不建设 review 流水线：

```text
apps/server/src/projects/g3-legacy-comic-format-audit.cli.ts
apps/server/src/projects/g3-legacy-comic-format-audit.spec.ts
```

package script：

```json
{
  "g3:comic-format:audit": "tsx src/projects/g3-legacy-comic-format-audit.cli.ts"
}
```

调用必须显式提供根：

```bash
corepack pnpm --filter @airoaming/server g3:comic-format:audit -- --workspace-root /absolute/path --format json
```

命令约束：

- 没有 `--workspace-root` 立即失败，不读取默认真实 workspace。
- 只读 `projects/*/project.json`；不读取剧本、图片、task body 或 key。
- 不创建文件、不改 mtime、不 chmod、不连接数据库、不调用网络。
- stdout 只输出 JSON summary；stderr 输出稳定错误码。
- 退出码：`0` 无 decision-required；`2` 存在 ambiguity；`1` 参数/IO/解析失败。
- 不输出项目名称和完整内容，只输出 projectId、分类和计数。

固定输出：

```json
{
  "schemaVersion": 1,
  "policyVersion": "g3-file-comic-format-read-v1",
  "counts": {
    "canonical": 0,
    "autoMappedReadOnly": 0,
    "decisionRequired": 0
  },
  "issues": []
}
```

该 JSON 不是 MigrationRun/MigrationIssue，也不能作为 final import 报告。它只决定真实 workspace 是否允许启用 G3-core。

## 9. 历史 artifact 处理

### 9.1 Preflight

- 新 Preflight 只写 canonical。
- 旧 file preflight 的 `page_horizontal` 可在明确 `legacy-preflight-read-v1` adapter 中显示为 paged，但不得覆盖旧文件。
- `four_panel/缺失/非法` 标记 unresolved/stale；不能伪造新的 confirmed PreflightRevision。

### 9.2 Layout

- 旧 `LayoutPage.format` 继续保留 `vertical_comic/page_horizontal/four_panel`。
- 只允许 `toLegacyLayoutPageFormat()` 从 canonical 生成当前旧布局骨架。
- 历史 layout JSON 不做字符串替换，不修改 digest。

### 9.3 GenerationTask

- 旧 input/output 原样只读，不反序列化成新 command 重放。
- 新 task input 必须 canonical，并保存 `sizePolicyVersion`。
- 旧 task 若缺 policy 视为 V1 historical，不用当前代码补推字段后执行。

## 10. 与 G1 importer 的交接

未来 G3-M/G1 importer 读取原始 file metadata，而不是读取 G3 runtime 投影：

| file reader 结果 | importer 行为 |
| --- | --- |
| canonical | 直接插入 canonical，无 issue |
| `page_horizontal` | 插入 paged，报告保留 mappedFrom |
| `four_panel` | 创建 blocker，要求 canonical + layoutPresetIntent 决议 |
| missing/invalid | 创建 blocker，要求 canonical 决议 |

G3-core audit summary 不能替代 importer source manifest、decisionsDigest、MigrationRun 或协调备份。

## 11. 测试矩阵

### 11.1 纯函数

```text
FILE-001 canonical vertical
FILE-002 canonical paged
FILE-003 page_horizontal -> auto_mapped_read_only paged
FILE-004 four_panel -> decision_required/FOUR_PANEL
FILE-005 missing/null/empty -> decision_required/MISSING
FILE-006 arbitrary string/object/array -> decision_required/INVALID + safeValueKind
FILE-007 mapper 不接收 trim 后的 alias
```

### 11.2 Repository fixture

```text
FILE-010 新 canonical 项目写回 canonical
FILE-011 旧 page_horizontal 加载后 API/runtime 为 paged
FILE-012 保存无关章节后 project.json 仍是 page_horizontal
FILE-013 provenance 不进入 API/DB/task/source snapshot
FILE-014 ambiguity 使 list fail-closed，不从列表静默消失
FILE-015 错误日志不含物理根和 metadata body
FILE-016 进程 reopen 后行为一致
```

### 11.3 Audit CLI

```text
AUD-001 缺 root 参数失败且不访问默认 workspace
AUD-002 临时 fixture 分类/计数/退出码精确
AUD-003 运行前后文件内容与 mtime 不变
AUD-004 输出不含项目名称、正文、路径或 key
AUD-005 issues >100 时截断明细但保留总数
```

## 12. 发布与完成判定

`G3-B2 completed`：

- tagged reader、internal provenance、serializer、fail-closed 和 audit CLI 测试通过。
- 新 runtime 输出 canonical，旧 page alias 只存在 file legacy allowlist。
- ambiguous fixture 不默认、不隐藏、不改文件。

真实 workspace 发布还要求 audit `decisionRequired=0`。若不为 0，状态必须是 `release_blocked`，等待 G3-M；不得让 Luna 增加临时默认值“把测试跑绿”。
