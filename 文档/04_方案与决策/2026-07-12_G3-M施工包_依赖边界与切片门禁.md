# G3-M 施工包：依赖边界与切片门禁

## 1. 文档定位

本文是 G3 剩余功能的唯一施工入口。G3-M 不是一个独立的漫画版式 mapper，而是：

```text
G1 maintenance/snapshot/import/backup/cutover runtime
  + G3 comic-format decision plugin
  + 真实 workspace rollout evidence
```

Luna 不得把本文交付压成一个任务，也不得在缺少 G1 前置时直接实现或运行 production activate。

| verifier/shadow replay | implemented，M4 待签字 | 来源证据注册表、integrity/FK/ledger/API/Asset/DB-only/pending Dialogue、双 fresh 与 replay 证据已具备 |

## 3. 交付名称与允许声明

| 名称 | 含义 | 当前 |
| --- | --- | --- |
| G3-M foundation | M0～M4 在临时 workspace/SQLite 完成 | implementation_evidence_ready，M4_signoff_pending |
| G3-M rollout tooling | M5 备份恢复与激活工具完成，仍未用于真实数据 | prerequisite_blocked |
| G3 production-ready | 全量 DB capability、SecretStore、final import、真实切换与复核均通过 | release_blocked |

只完成 mapper 不得写 G3-M completed；只完成临时 final run 不得写 production-ready。

## 4. 强制前置门

### 4.1 开发门 D0

- 当前工作树有明确 commit，任务书写出 commit SHA。
- G3-core typecheck/server tests/G1 三项 check 全绿。
- 所有测试使用临时 workspace、临时 dataRoot、临时 DB 和 fake key。
- 不访问默认真实 workspace。

### 4.2 Shadow 门 D1

开始 M3 前必须：M0 maintenance、M1 snapshot、M2 decision codec 全绿；snapshot sourceManifestDigest 与 decisions artifact 绑定。

### 4.3 Final-ready 门 D2

允许在临时根执行 final run 前必须：

- 全量 importer 覆盖 G1 导入顺序，不只是 Project/comicFormat。
- DB capability registry 中 required 项全部 implemented。
- SecretStore、CredentialRedactor、runtime bundle 已实现。
- 两轮 fresh shadow import、幂等重跑与公开 DTO 对照通过。

### 4.4 Activate 门 D3

运行 activate CLI 前还必须：

- 用户对本次真实停写再次明确授权。
- 协调 backup/restore 演练通过。
- final MigrationRun=succeeded、open blocker=0。
- PersistenceState=ready_for_activation 且身份与 final run/effective manifest 完全一致。
- DB maintenance smoke 通过，firstBusinessWriteAt 仍为 null。
- 旧 metadata 已按 G1 C6 规则封存，Secret 扫描为 0。

当前 D2 的临时实现与双 fresh 证据已具备，但正式验收签字尚未完成；D3 仍未满足。Settings/SecretStore、backup、final importer 与用户授权切换不能被 M4 证据替代。

## 5. 施工切片

| 切片 | 目标 | 主要输出 | 可否现在领取 |
| --- | --- | --- | --- |
| G3-M0 | maintenance gate 与 participant/runtime bundle 骨架 | MaintenanceModule、同进程控制、活动计数、503 | 是 |
| G3-M1 | immutable snapshot 与 manifest | snapshot CLI、redactor、pre/post/source/snapshot digest | 是，依赖 M0 closed fixture |
| G3-M2 | 版式 mapper、decision artifact 与 MigrationIssue codec | 决议文件、JCS digest、issue/report codec | 是，依赖 M1 |
| G3-M3 | importer run/账本与 comic-format plugin | audit/shadow/final runner、确定性 sourceKey/ID | 是，但全量 importer 需分子切片 |
| G3-M4 | verifier 与 shadow/replay | integrity/FK/ledger/API/asset/source 对照 | 依赖 M3 |
| G3-M5 | offline coordinated backup/restore | app-backup/app-restore、manifest、空根恢复 | 前置不全，只能临时实现 |
| G3-M6 | final cutover/activate/rollback | cutover coordinator、activate CLI、Runtime Review | 阻塞，D2/D3 通过后领取 |

## 6. 依赖图

```text
M0 maintenance
  -> M1 snapshot/runtime bundle
    -> M2 decision artifact
      -> M3 importer
        -> M4 shadow verifier
          -> D2 full DB/SecretStore gate
            -> M5 backup/restore rehearsal
              -> D3 user-authorized M6 cutover/activate
```

M0～M4 可在当前波次推进；M6 不得通过补默认值、跳过 SecretStore 或只导入 Project 来绕过。

## 8. Stop condition

遇到任一条件立即停止当前切片并记录 blocker：

- 需要读取或写入默认真实 workspace/正式 DB。
- 需要给 four_panel、缺失或非法值自动选择 canonical。
- snapshot pre/post manifest 不一致或发现 symlink/越界。
- decision sourceManifestDigest、issueKey 或 sourceDigest 不匹配。
- DB capability registry 仍有 required=unsupported 却准备 activate。
- final run 有 open blocker，或 verification identity 与当前 release 不同。
- 备份未完成恢复演练、Secret 扫描非零、firstBusinessWriteAt 已非空却尝试 file-only。

```text

输入 fixture：<临时绝对路径>
最小测试：<精确命令>
退出证据：<测试、report、残留 blocker>

```

禁止给 Luna 的任务描述：按照 G3 剩余文档全部做完、缺什么自己补、直接切到 DB-only。

## 10. 完成判定

G3-M foundation：M0～M4 的实现和临时证据齐全；只有完成 M4 正式验收签字后，才能将状态写为 `completed`。当前状态为 `implementation_evidence_ready`，不得写成 production-ready。

G3-M completed：M5/M6 工具、回滚和全部 deferred 用例通过。

G3 production-ready：另加真实 workspace audit=0、用户授权切换、Runtime/User Review 与观察期证据。三者不得混写。
