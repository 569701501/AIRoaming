# G3-M 施工包：依赖边界与切片门禁

## 1. 文档定位

本文保留 G3-M 的依赖和安全门禁；当前唯一连续施工入口已更新为 `文档/05_执行与记录/任务记录/2026-07-13_D2至M6连续交付总目标/handoff.md`。G3-M 不是一个独立的漫画版式 mapper，而是：

```text
G1 maintenance/snapshot/import/backup/cutover runtime
  + G3 comic-format decision plugin
  + 真实 workspace rollout evidence
```

Luna 可以领取一个连续总目标，但必须在内部按切片顺序自测、复核、提交后续跑；不得把全部改动压成一个提交，也不得在缺少 G1/D2 前置时运行 production activate。

## 4. 强制前置门

### 4.1 开发门 D0

- 当前工作树有明确 commit，任务书写出 commit SHA。
- G3-core typecheck/server tests/G1 三项 check 全绿。
- 所有测试使用临时 workspace、临时 dataRoot、临时 DB 和 fake key。
- 不访问默认真实 workspace。

### 4.2 Shadow 门 D1

开始 M3 前必须：M0 maintenance、M1 snapshot、M2 decision codec 全绿；snapshot sourceManifestDigest 与 decisions artifact 绑定。

### 4.3 Final-ready 门 D2

允许在临时根执行 final run 前必须：

- 全量 importer 覆盖 G1 导入顺序，不只是 Project/comicFormat。
- DB capability registry 中 required 项全部 implemented。
- SecretStore、CredentialRedactor、runtime bundle 已实现。
- 两轮 fresh shadow import、幂等重跑与公开 DTO 对照通过。

### 4.4 Activate 门 D3

运行 activate CLI 前还必须：

- 用户对本次真实停写再次明确授权。
- 协调 backup/restore 演练通过。
- final MigrationRun=succeeded、open blocker=0。
- PersistenceState=ready_for_activation 且身份与 final run/effective manifest 完全一致。
- DB maintenance smoke 通过，firstBusinessWriteAt 仍为 null。
- 旧 metadata 已按 G1 C6 规则封存，Secret 扫描为 0。

当前 M4 临时实现、双 fresh 证据与正式签字及 M5-A4 均已完成。D2-A1 Settings/SecretStore 已完成，但其余 6 个 required capability、final importer 和综合证据仍未满足；D3 也未满足。不能借 M5 completed 放行真实 pre-cutover 或 activate。

## 6. 依赖图

## 8. Stop condition

遇到任一条件立即停止当前切片并记录 blocker：

- 需要读取或写入默认真实 workspace/正式 DB。
- 需要给 four_panel、缺失或非法值自动选择 canonical。
- snapshot pre/post manifest 不一致或发现 symlink/越界。
- decision sourceManifestDigest、issueKey 或 sourceDigest 不匹配。
- DB capability registry 仍有 required=unsupported 却准备 activate。
- final run 有 open blocker，或 verification identity 与当前 release 不同。
- 备份未完成恢复演练、Secret 扫描非零、firstBusinessWriteAt 已非空却尝试 file-only。

## 9. Luna 连续目标与内部切片

Luna 领取 `2026-07-13_D2至M6连续交付总目标/handoff.md`。总目标已经给出每个内部切片的范围、capability 里程碑、测试、提交和真实授权边界。

连续执行不改变以下规则：

- 内部一次只执行一个切片。
- 上游测试、复核和提交不通过，不得越级。
- 每个 capability 只能由公开路径证据变绿。
- 不访问真实 workspace、DB 或 SecretStore。
- 开发终点先停在 `ready_for_real_cutover_authorization`。

## 10. 完成判定

G3-M foundation：M0～M4 的实现、临时证据与正式签字齐全，当前状态为 `completed`；仍不得写成 production-ready。

G3-M development completed：M5-A4、D2、M6 工具、隔离回滚和全部 deferred 用例通过；真实切换未授权时状态为 `ready_for_real_cutover_authorization`。

G3 production-ready：另加真实 workspace audit=0、用户授权切换、真实 C0～C7、Runtime/User Review 与观察期证据。三者不得混写。
