## 1. 背景与问题

AI漫游的项目工作区已经收口为：

```text
左侧公共对话框
  -> 当前步骤提示词
  -> 用户上传或讨论剧本/分镜/素材
  -> AI 返回建议、总结、改写或触发受控业务工具
右侧当前步骤文档或工作面板
  -> 用户编辑、AI 受控写入、保存、锁定或生成任务
```

当前文档已经明确：

- 对话框组件公共复用。
- 原始对话记录按 `projectId + stepKey` 隔离；章节工作流接入后，剧本等章节内步骤需要进一步按 `chapterId` 隔离。
- 跨步骤只共享用户已确认事实、保存文档和锁定产物。
- AI 不直接操作本地物理路径；剧本阶段可以通过 AI漫游受控工具/API 写入章节草稿。

现在用户已决定第一阶段采用 OpenCode，而不是 `pi-mono`，作为项目对话框背后的 AI Runtime。

本文档用于记录 OpenCode 从 AuroraPlatformWeb 到 AI漫游的移植边界、阶段、数据协议、风险和验收口径。

截至 2026-05-27，AI漫游已经完成剧本步骤的 OpenCode 对话最小闭环和流式输出：后端可启动或连接 `opencode serve`，创建 OpenCode session，发送剧本阶段 prompt，将 OpenCode `message.part.delta` 转换为 AI漫游 `dialogue.message.delta`，并把最终 assistant 文本保存为 AI漫游自己的对话消息；前端 store 可读取非敏感模型列表，发送消息时可透传 provider/model。当前已接入用户提供剧本整理第一版：`.txt/.md` 文本附件或输入框长文本可触发 `import_script_to_chapters`，写入章节并通过 `dialogue.tool_result.created` 刷新前端。停止生成、模型添加 UI、variant、灵感种子生成和章节内 AI 受控编辑仍未完成。

## 2. 目标与非目标

### 2.1 目标

- 采用 OpenCode 作为 AI漫游第一阶段项目对话框的 AI Runtime。
- 支持项目内对话消息发送、流式返回、停止生成和错误恢复。
- 支持模型添加、模型选择和模型变体选择。
- 支持按 6 个项目步骤注入不同系统提示词和上下文。
- 保持 AI漫游自己的 `ConversationThread`、`ConversationMessage`、`ProjectContextFact` 作为业务事实源。
- 从 AuroraPlatformWeb 迁移可复用的 OpenCode 配置、事件桥、模型选择和 provider adapter 思路。

### 2.2 非目标

- 不迁移 Aurora 的完整 Docker sandbox 体系。
- 不让 OpenCode 直接修改本地物理文件或业务数据库；剧本阶段写入必须通过 AI漫游受控工具/API。
- 不迁移 Aurora 的 Phaser 工具、浏览器预览运行时、远程控制、微信通道。
- 不迁移团队、计费 ledger、复杂权限和商业化能力。
- 不把 OpenCode 的原始 session tree 作为 AI漫游的业务会话事实源。
- 不把 OpenCode 原始事件直接暴露给前端组件。

## 3. 术语收口

| 术语 | 定义 | 说明 |
| --- | --- | --- |
| OpenCode 对话运行时 | AI漫游后端启动或连接的 OpenCode headless server | 负责模型调用、流式输出和运行时事件 |
| AI漫游对话线程 | `ConversationThread(projectId + stepKey + optional chapterId)` | 业务事实源，按项目步骤隔离；章节内步骤优先带 `chapterId` |
| OpenCode Session | OpenCode 内部 session | 运行时状态，不是业务事实源 |
| 对话运行时映射 | AI漫游线程到 OpenCode Session 的映射 | 用于恢复和路由，不向用户暴露 |
| 模型选择 | `providerId + modelId + variant` | 由 AI漫游 UI 选择，后端转换给 OpenCode |
| 受控业务工具 | AI 通过 AI漫游后端调用的读取、导入、生成、写章节草稿等能力 | 不能暴露本地物理路径，必须校验项目和章节 |
| AI 写入记录 | AI 通过受控工具修改章节草稿或产物后留下的来源记录 | 用于追溯 `threadId/messageId/toolCallId` |

## 5. 方案概览

一句话方案：

```text
AI漫游第一阶段迁移 OpenCode 作为项目对话框 AI Runtime；
AI漫游仍保留自己的项目、步骤、对话、上下文和应用动作模型；
OpenCode 只负责运行时调用、流式输出和模型接入。
```

核心取舍：

| 取舍 | 当前选择 | 原因 |
| --- | --- | --- |
| Runtime | OpenCode | 用户已明确选择；Aurora 有可参考实现；官方有 server/SDK |
| 运行方式 | 本地 NestJS 管理 OpenCode headless server | 符合 Web 工作台 + 本地服务形态 |
| 会话事实源 | AI漫游 `ConversationThread` | 避免被 OpenCode session tree 绑死 |
| 模型配置 | AI漫游维护选择，OpenCode 执行 | 支持产品 UI 和后续 provider 管理 |
| 工具权限 | 不暴露本地物理路径和命令执行；按业务工具开放读写 | 剧本阶段可写章节草稿，但必须经过 AI漫游 API |
| Docker sandbox | 不迁移 | AI漫游当前不运行用户代码，不需要重基础设施 |

## 6. 目标架构

```text
Web 项目工作区
  -> ProjectDialoguePanel
    -> 选择模型 / 发送消息 / 停止 / 触发受控业务工具
  -> Dialogue API
    -> ConversationThreadService
    -> DialogueContextBuilder
    -> OpenCodeRuntimeService
    -> DialogueEventNormalizer
  -> OpenCode headless server
    -> Provider / Model
```

OpenCode 运行时与 AI漫游业务事实的关系：

```text
ConversationThread
  -> DialogueRuntimeSession(runtime = opencode, externalSessionId)
  -> OpenCode Session

ConversationMessage
  <- DialogueEventNormalizer
  <- OpenCode message.updated / message.part.updated / session.idle
```

## 7. 数据与协议设计

### 7.1 新增运行时映射建议

不建议把 OpenCode 字段直接塞满 `ConversationThread`。建议单独建运行时映射：

```json
{
  "id": "runtime_session_001",
  "threadId": "thread_001",
  "projectId": "project_001",
  "stepKey": "story",
  "runtime": "opencode",
  "externalSessionId": "oc_session_001",
  "status": "active",
  "providerId": "aurora",
  "modelId": "gpt-5.5",
  "variant": "medium",
  "createdAt": "2026-05-25T00:00:00.000Z",
  "updatedAt": "2026-05-25T00:00:00.000Z"
}
```

建议命名：

```text
DialogueRuntimeSession
```

它的职责是运行时路由，不承载业务聊天内容。

### 7.2 对话发送接口建议

```text
POST /api/projects/{projectId}/dialogue/threads/{stepKey}/messages
```

请求：

```json
{
  "content": "帮我看一下这一段剧本节奏有没有问题",
  "model": {
    "providerId": "aurora",
    "modelId": "gpt-5.5",
    "variant": "medium"
  },
  "attachments": [
    {
      "assetId": "asset_script_001",
      "kind": "text"
    }
  ]
}
```

响应：

```json
{
  "accepted": true,
  "threadId": "thread_001",
  "messageId": "msg_user_001",
  "runtimeSessionId": "runtime_session_001"
}
```

### 7.3 对话事件接口建议

```text
GET /api/projects/{projectId}/dialogue/threads/{stepKey}/events
```

前端只消费 AI漫游标准事件：

| 事件 | 说明 |
| --- | --- |
| `dialogue.message.created` | 用户或 assistant 消息已创建 |
| `dialogue.message.delta` | assistant 文本增量 |
| `dialogue.message.completed` | assistant 消息完成 |
| `dialogue.status` | 当前线程运行状态 |
| `dialogue.tool_result.created` | 受控业务工具产生结果，例如章节草稿更新 |
| `dialogue.usage.updated` | provider/model/token 用量更新 |
| `dialogue.error` | 运行时错误 |

不把 OpenCode 原始事件名作为前端契约。

### 7.4 模型配置接口建议

```text
GET /api/ai-runtime/models
POST /api/ai-runtime/providers
PATCH /api/ai-runtime/providers/{providerId}
```

MVP 可以先用本地配置文件或环境变量，不立即做完整凭证管理 UI。但前端对话框需要能读取：

```json
{
  "defaultModel": {
    "providerId": "aurora",
    "modelId": "gpt-5.5",
    "variant": "medium"
  },
  "providers": [
    {
      "providerId": "aurora",
      "displayName": "OpenAI Compatible",
      "baseUrlEditable": true,
      "models": [
        {
          "modelId": "gpt-5.5",
          "displayName": "gpt-5.5",
          "variants": ["low", "medium", "high"]
        }
      ]
    }
  ]
}
```

## 8. OpenCode 配置策略

### 8.1 配置来源

AI漫游采用独立的 OpenCode AI 资产目录：

```text
apps/server/opencodeAI/
  opencode.json
  AGENTS.md.tpl
  agents/
    airoaming__script-collaboration-agent.md
  skills/
    script-import-normalize/
      SKILL.md
  tools/
```

命名沿用 AuroraPlatformWeb 的 `opencodeAI` 目录习惯，便于后续按 `agents / skills / tools` 扩展；但内容必须是 AI漫游自己的资产，不直接复制 Aurora 的业务提示词和工具。

原因：

- Aurora 的 agents/tools/skills 绑定游戏、Phaser、沙盒和闭环工作流。
- AI漫游需要漫画创作提示词、剧本编辑提示词和生成任务动作。
- 直接复制会导致后续 AI 误用 Aurora 业务术语。

截至 2026-05-27，源码目录已先落地 `script-import-normalize` skill 和剧本协作 agent；运行时尚未接入完整模板复制和 OpenCode tool bridge。

### 8.2 权限原则

第一阶段 OpenCode agent 必须遵守：

```text
允许：
  - 读取由后端注入的上下文
  - 输出建议、总结、改写、结构化草稿
  - 通过 AI漫游受控工具/API 读取或更新当前章节草稿
  - 通过 AI漫游受控工具/API 导入剧本、生成章节或生成灵感种子
  - 请求创建 AI漫游标准生成任务

禁止：
  - 直接写本地物理项目文件
  - 直接执行 bash
  - 直接编辑数据库
  - 直接修改 workspace 产物路径
  - 绕过 AI漫游后端工具/API 校验
```

OpenCode 配置应尽量使用受限 agent 或等价权限规则。若 OpenCode 权限无法完全限制，应由 AI漫游后端不向 OpenCode 暴露可写路径，只暴露业务级工具，例如读取当前章节、导入剧本、更新当前章节草稿。

### 8.3 模型策略

MVP 初始模型建议：

| providerId | 用途 | 说明 |
| --- | --- | --- |
| `aurora` | 默认对话 | 可复用 Aurora 的 OpenAI-compatible 配置思路 |
| `kimi` | 中文长文本备选 | 可复用 Aurora 的 Kimi provider 思路 |
| `custom` | 后续自定义 provider | 用户需要添加模型时扩展 |

模型切换位置：

- 项目对话框顶部显示当前模型。
- 用户可切换 `provider/model/variant`。
- 每条用户消息记录当次模型选择，避免后续复盘不清楚。

## 9. 上下文注入策略

OpenCode 不直接读取所有项目文件。AI漫游后端负责组装上下文：

```text
当前步骤系统提示词
  -> 项目级已确认事实
  -> 当前步骤主文档或产物
  -> 当前步骤对话摘要或最近消息
  -> 用户本轮输入
```

步骤提示词：

| stepKey | 提示词重点 |
| --- | --- |
| `story` | 剧本理解、节奏、角色动机、改写建议 |
| `structure` | 剧情结构、节拍、人物关系、冲突推进 |
| `storyboard` | 分镜拆分、镜头、构图、台词节奏 |
| `candidates` | 候选图评估、提示词优化、重生成建议 |
| `layout` | 页面节奏、格子布局、阅读流 |
| `assets` | 素材整理、归档说明、复用建议 |

## 10. 受控工具与 AI 写入协议

剧本阶段不再以“assistant 输出 -> 用户点插入/追加”为主闭环。AI 可以通过 AI漫游受控工具/API 更新章节草稿，但工具结果必须转成 AI漫游业务事件和写入记录：

```json
{
  "messageId": "msg_assistant_001",
  "toolResults": [
    {
      "id": "tool_result_001",
      "tool": "update_chapter_draft",
      "target": {
        "stepKey": "project_story",
        "chapterId": "chapter_001",
        "field": "sourceText"
      },
      "summary": "改写开场冲突并补充主角动机",
      "revisionId": "script_revision_001"
    }
  ]
}
```

剧本阶段工具类型：

| 类型 | 说明 |
| --- | --- |
| `read_current_chapter` | 读取当前章节正文和状态 |
| `read_chapter_list` | 读取章节列表 |
| `import_script_to_chapters` | 把上传或粘贴的完整剧本整理并写入章节 |
| `generate_inspiration_seeds` | 生成灵感种子供用户选择 |
| `generate_script_from_seed` | 根据用户确认的种子生成章节剧本 |
| `update_chapter_draft` | 更新当前章节草稿全文 |
| `create_generation_task` | 创建结构化、分镜或图片生成任务 |
| `save_as_context_fact` | 保存为项目级已确认事实 |

- OpenCode 对话框不再只是聊天，而是可以通过 AI漫游标准动作推进 6 步流程。

## 12. 风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| OpenCode 被误用为本地文件编辑 agent | 可能绕过项目契约 | 禁止暴露本地物理路径和命令执行；所有写入必须走 AI漫游受控工具/API |
| 直接复制 Aurora 复杂链路 | 引入沙盒、权限、计费和子会话复杂度 | 只迁移对话运行时最小闭环 |
| OpenCode 原始事件污染前端 | 前端强依赖第三方事件结构 | 后端统一转换为 `dialogue.*` 事件 |
| 模型配置散落 | 后续添加模型困难 | 后端集中维护 provider/model/variant |
| 会话恢复过早复杂化 | 增加上下文污染和状态 bug | MVP 每个步骤只保留一条主线程，先不做复杂 session tree |
| 运行时不可用 | 对话框无法使用 | 保留 mock provider 或降级提示，不影响右侧文档手动编辑 |

回滚策略：

- 如果 OpenCode PoC 不稳定，保留 AI漫游 `ConversationThread` 和标准对话 API，不删除业务模型。
- 将 `OpenCodeRuntimeService` 替换为 mock 或 direct provider adapter 时，不影响前端对话框和业务数据结构。

## 13. 验收标准

- [x] 新 AI 读取入口文档时不会误判为“不接 OpenCode”。

## 14. 待确认问题

### 14.1 OpenCode 第一阶段是否完全禁用本地文件写入和 bash？

建议答案：

```text
是，禁用本地物理文件写入和 bash；但允许通过 AI漫游受控工具/API 写章节草稿。
```

原因：

- AI漫游的产品原则是人工可控。
- 剧本阶段需要 AI 整理、生成和编辑章节草稿，但写入必须能追溯到项目、章节和工具调用。
- 直接开放本地路径写文件会绕过章节契约、版本记录和来源追溯。

### 14.2 第一版是否只接剧本步骤真实对话？

建议答案：

```text
是。
```

原因：

- 剧本步骤是对话框价值最明显的入口。
- 其他步骤依赖结构化剧情、分镜、候选图和排版数据，过早接入容易做成空功能。
- 公共对话框组件和运行时先稳定，再逐步扩展到 6 步。
