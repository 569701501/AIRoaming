# G3-M 施工包：导入器、决议与迁移账本

## 1. 边界

Importer 只读取 sealed snapshot，不读取 G3 file runtime 的内存投影，也不反写活动 workspace。comic-format 只是全量 G1 importer 的一个 plugin；final import 不允许只插 Project 后激活。

## 2. 唯一版式 mapper

文件：apps/server/src/migration/comic-format-migration.plugin.ts。

| 原始值 | mappingKind | target | issue code | intent |
| --- | --- | --- | --- | --- |
| vertical_scroll | canonical | vertical_scroll | 无 | null |
| paged_comic | canonical | paged_comic | 无 | null |
| page_horizontal | auto_mapped | paged_comic | 无 | null |
| four_panel | decision_required | null | COMIC_FORMAT_FOUR_PANEL_REQUIRES_CONTAINER | four_panel |
| undefined/null/空串 | decision_required | null | COMIC_FORMAT_MISSING | null |
| 其他字符串/类型 | decision_required | null | COMIC_FORMAT_INVALID_LEGACY_VALUE | null |

不 trim、不 lowercase、不 fallback。旧文档中的 COMIC_FORMAT_CONFIRMATION_REQUIRED、FORMAT_CONFIRMATION_REQUIRED 视为泛化描述，不作为新 issue code；验收 IMP-07 应改断言具体 code。

Runtime 的 readLegacyProjectComicFormatV1 不能被 importer 调用或搬走；两者测试分别证明边界。

## 3. issue identity 与 payload

issueKey 固定为 project:{projectId}:comic-format，同一 run 唯一。

detailJson schemaVersion=1，必须包含：projectId、sourceStorageKey、originalValueKind、originalValuePreview、sourceDigest、layoutPresetIntent、allowedComicFormats。

originalValuePreview 只允许安全截断字符串或类型名，不保存任意对象序列化结果。storageKey 使用虚拟相对路径。

resolutionJson：

```json
{
  "decisionSchemaVersion": 1,
  "action": "set_comic_format",
  "chosenComicFormat": "paged_comic",
  "layoutPresetIntent": "four_panel"
}
```

chosenComicFormat 只能是 vertical_scroll/paged_comic；layoutPresetIntent 只能 four_panel/null，且只有原值 four_panel 可为 four_panel。

## 4. 决议 artifact

### 4.1 文件格式

```json
{
  "schemaVersion": 1,
  "kind": "airoaming_migration_decisions_v1",
  "sourceManifestDigest": "sha256:...",
  "entries": [
    {
      "issueKey": "project:p1:comic-format",
      "sourceKey": "workspace-v1:p1:Project:p1",
      "sourceDigest": "sha256:...",
      "action": "set_comic_format",
      "chosenComicFormat": "paged_comic",
      "layoutPresetIntent": "four_panel"
    }
  ],
  "decisionsDigest": "sha256:..."
}
```

entries 按 issueKey 升序且不得重复。decisionsDigest 使用 packages/shared 的 digestCanonicalJson，对排除 decisionsDigest 字段后的完整对象计算。

即使没有人工决议，final run 也使用 entries=[] 的决议 artifact 和非空 decisionsDigest，满足数据库 final 约束。

### 4.2 接受规则

- artifact sourceManifestDigest 必须与 sealed snapshot 和新 MigrationRun 一致。
- issueKey/sourceKey/sourceDigest 必须与当前 audit 发现完全一致。
- 不接受多余 entry、未知 action、未知字段、旧 snapshot 决议或 duplicate。
- 决议改变必须生成新 artifact 和新 run；不更新 terminal run 的旧 issue。
- 人工编辑完成后由 decision check CLI 校验并规范化输出；Importer 只读已校验 artifact。

## 5. MigrationRun 状态

```text
INSERT running（冻结 kind/importerVersion/sourceManifestDigest/decisionsDigest）
  -> blocked  有未决 blocker，finishedAt 同次写入
  -> failed   I/O/codec/DB/verification 错误，errorCode+finishedAt
  -> succeeded 仅 shadow 或满足完整 verification 的 final
```

audit run 发现歧义时写 open issue 后 blocked。新 shadow/final run 读取决议，在该新 run 内写同 issueKey 的 resolved issue；不修改旧 run。

final→succeeded 前必须填写 snapshotManifestDigest、decisionsDigest、reportDigest、counts、verification，并满足现有 trigger 的 integrity/FK/ledger/source/effective/openBlocker 条件。

## 6. 导入顺序与事务

沿用 G1 顺序：MigrationRun/decisions → Project/Chapter → Script/Outline → Story → Storyboard/Shot → Preflight → legacy Task → Asset/Visual → Candidate/Lock → Layout/Export → Dialogue/pending → Provider metadata → read model → verify。

comic-format plugin 在 Project INSERT 前运行：canonical/auto_mapped 直接得到 target；decision_required 必须先匹配 resolution，否则本项目不插入。

生产 shadow/final 的目标数据库必须是 fresh migration tree。每个 Project subtree 使用单事务；任何子实体失败则该项目事务回滚，run 最终 failed/blocked，目标库不得承接业务。正式切换失败时丢弃目标库，不尝试在部分 final 库上继续。

服务级测试必须额外覆盖同一 DB 重放：相同 sourceKey+digest 不新增；不同 digest 建 conflict issue，不覆盖旧实体。

## 7. ImportedEntitySource

sourceKey 固定：workspace-v1:{projectId}:{entityType}:{legacyId-or-relative-key}。

- 目标 entity ID 由 entityType+sourceKey 的稳定摘要生成，不用 random/time/import order。
- sourceDigest 从原始 source evidence 得到，payloadDigest 从规范化导入 payload 得到。
- 首次记录 firstRunId；更强证据只允许 reference_only→partial→complete，并更新 lastRunId。
- 同 sourceKey 不同 sourceDigest 是 blocker；禁止 upsert 覆盖 identity。

## 8. 报告

每项目至少记录 projectId、sourceStorageKey、sourceDigest、originalComicFormat 安全预览、mappingKind、targetComicFormat、layoutPresetIntent、issueKey、resolutionStatus、importStatus。

汇总至少含 projectCount、canonicalCount、autoMappedCount、decisionRequiredCount、unresolvedBlockerCount、importedCount、entityCounts、warningCount。

reportDigest 对去除 runId/时间/绝对根后的 canonical report 计算；两个 fresh DB 对同 snapshot+decisions 必须一致。

## 9. CLI

```text
db-audit
  --snapshot <sealed-dir>
  --database-url <explicit temp sqlite url>
  --report <output>

migration-decisions check
  --snapshot <sealed-dir>
  --input <decisions.json>
  --output <normalized-decisions.json>

db-import
  --kind shadow|final
  --snapshot <sealed-dir>
  --decisions <normalized-decisions.json>
  --database-url <explicit fresh sqlite url>
  --report <output>

db-verify
  --snapshot <sealed-dir>
  --decisions <normalized-decisions.json>
  --import-report <slice-report.json>
  --database-url <explicit sqlite url>
  --run-id <id>
  --report <output>
  --workspace-root <repo-root>
  --format json
```

所有路径和 database-url 必须显式传入。final CLI 拒绝非 fresh 目标、open blocker、snapshot/decision digest mismatch 和 capability gate 非零。

## 10. 稳定错误

| code | 含义 |
| --- | --- |
| MIGRATION_SNAPSHOT_NOT_SEALED | 输入不是 sealed snapshot |
| MIGRATION_SOURCE_DIGEST_MISMATCH | snapshot/run/decision source identity 不同 |
| MIGRATION_DECISION_INVALID | 决议 schema/action/value 非法 |
| MIGRATION_DECISION_STALE | issueKey/sourceKey/sourceDigest 不匹配 |
| MIGRATION_DECISION_REQUIRED | 存在 open blocker |
| MIGRATION_SOURCE_CONFLICT | 相同 sourceKey 出现不同 digest |
| MIGRATION_TARGET_NOT_FRESH | 正式目标不是 fresh tree |
| MIGRATION_CAPABILITY_BLOCKED | DB required capability 未完成 |
| MIGRATION_VERIFICATION_FAILED | integrity/FK/ledger/count/pointer 任一失败 |
