# 智能成稿与编辑器一体化开发方案

## 1. 本方案的结果

本方案升级现有第 6 步，不新增制作阶段，不重做 renderer，不另建一套简易排版器。

用户目标路径固定为：

```text
候选图全部定稿
  -> 打开“漫画成稿”
  -> 系统零配置生成完整可编辑成稿
  -> 用户直接阅读并修正少量例外
  -> 可按整章/场景/页面/段落/选区局部智能优化
  -> 阅读预览
  -> 一次预览并导出
```

智能成稿首版必须自动完成：

- 画格分组、页面或条漫段落。
- 画格尺寸、位置、间距、重点和阅读顺序。
- 每个定稿镜头的放置和非破坏裁切。
- 全部对白、旁白、气泡类型、位置、尾巴和断行。
- 字号、行高、边框、留白和基础全章样式。
- 漏镜头、漏对白、文字溢出、主体遮挡和来源问题检查。

编辑器继续完整存在，但产品心智从“用户从零排版”改为“系统先完成大部分，用户修正少量例外”。

## 2. 背景与问题

### 2.1 当前已经具备的能力

现有代码已经完成：

- `LayoutDocumentV1`、页漫/条漫 Profile、7 种低层模板。
- PanelFrame、FreeImage、非破坏 crop/zoom/offset/rotate/flip。
- 横排/竖排受控富文本、普通/思考/喊叫/旁白四类气泡和单尾巴。
- Konva 交互层、DOM 文字编辑、Undo/Redo、多选、图层和阅读顺序。
- DB-only Working Copy、自动保存、CAS 冲突恢复。
- 来源替换、LayoutRevision、历史、preflight、固定 RenderScene。
- PNG/PDF/条漫切片/长图 publication、手机只读和 AI pending 命令。

### 2.2 当前体验为什么仍难用

- 初始布局只是固定一镜一段或四镜一页，不理解场景、beat、节奏和对白。
- 对白、旁白和气泡不会自动进入成稿，用户需要从空画布补内容。
- 页面同时暴露保存草稿、保存版本、预检、出版、历史、来源和对象属性，用户不知道主路径。
- 当前“AI 建议”只是命令能力示例，没有真实排版价值。
- 用户进入前还要理解 Profile、模板和底层系统状态，违背低学习成本目标。

## 3. 用户与成功标准

### 3.1 目标用户

- 希望快速把当前章节定稿图变成可发布漫画的创作者。
- 能判断漫画是否好读，但不一定熟悉专业排版软件。
- 需要保留手调能力，不接受一次性扁平 AI 输出。

### 3.2 成功指标

| 指标 | 首版目标 |
| --- | ---: |
| 首次配置项 | 0 |
| active Shot 自动放置覆盖率 | 100% |
| 正式对白/旁白自动放置覆盖率 | 100% |
| 智能阶段静默改写台词 | 0 |
| 应用前文字溢出 | 0 |
| 普通固定样例画格/裁切直接可用率 | ≥ 80% |
| 自动绑定气泡无需改类型/移动/缩放率 | ≥ 80% |
| 人工修改被局部智能操作覆盖 | 0 |
| 编辑预览与正式导出可见差异 | 延续现有 G5 golden 门槛 |

两项“≥80%”必须由固定条漫/页漫语料和人工评分分别得出，不能用单个演示项目自评，也不能用镜头 100% 放置替代版面质量。

## 4. 目标与非目标

### 4.1 目标

- 一次打开即可得到完整、可读、可继续编辑的漫画初稿。
- 自动排版能反映场景、镜头作用、节奏和对白密度。
- 对白和气泡从正式分镜自动生成，不要求用户重新输入。
- 编辑器常用操作直接可见，复杂系统状态渐进展开。
- 智能能力在首次之后仍可按局部范围使用，并保护手调结果。
- 导出只保留用户能理解的一条主路径。

### 4.2 非目标

- 不做绘画、滤镜、像素修图、inpaint、复杂蒙版和节点工作流。
- 不做印刷出血、跨页大图、任意画格轮廓、多尾气泡或专业字体排印全集。
- 不自动重新创作对白，不把成稿步骤变成剧情编辑器。
- 不改变项目创建时锁定的 `vertical_scroll/paged_comic`。
- 不重写 G5 的 Working Copy、Revision、renderer、publication 和历史产物。
- 不把 G6 素材包或 ZIP 合并进本轮。

## 6. 用户主路径

### 6.1 前置不完整

如果仍有镜头未定稿，不打开空编辑器。页面只显示：

```text
还差 2 个镜头定稿，完成后即可自动生成漫画成稿。
[返回候选图工作台]
```

可以查看缺少的镜头，但不显示 Profile、空画布或内部错误码。

### 6.2 首次进入

前置完整且不存在 Working Copy 时自动开始，不要求用户再点“生成排版”：

```text
正在生成漫画成稿
✓ 整理 11 个镜头
✓ 放置 8 条对白与 2 条旁白
• 正在选择更合适的版式
```

完成后直接进入编辑器，并显示一次轻量结果摘要：

```text
智能成稿已完成
11 个镜头 · 8 条对白 · 2 条旁白
1 处建议确认
```

摘要不使用 modal 阻塞编辑；几秒后可收起，问题可从右上角重新打开。

### 6.3 再次进入

存在 Working Copy 时直接恢复上次编辑位置和缩放，不重新生成、不询问模板，也不覆盖手调内容。

如果存在未应用的智能预览，显示“上次的新排法仍待确认”，用户可继续对比、应用或放弃。

### 6.4 日常编辑

用户可以：

- 拖动画格边缘调整大小。
- 拖动图片或双击进入裁切。
- 拖动气泡和尾巴。
- 双击对白直接编辑文字。
- 从左侧拖动镜头改变位置或把未放镜头放回画布。
- 使用撤销/重做恢复操作。

第一次编辑不弹教学向导。仅在首次选中对象时显示一次不超过 3 条的非阻塞提示。

### 6.5 局部智能优化

根据当前选择只显示明确动作：

| 选择 | 动作 |
| --- | --- |
| 未选择 | `整章换一种排法`、`整理全章气泡` |
| 场景/页面/条漫段落 | `重新排这一段`、`更紧凑`、`更舒展`、`强化重点镜头` |
| 画格 | `换一个画格比例`、`重新聚焦人物` |
| 多个画格 | `整理选中画格`、`统一间距` |
| 气泡 | `避让人物`、`重新指向说话者`、`整理断行` |

不使用含义模糊的“AI 建议”按钮。

智能结果进入对比状态：原稿保持不变，新稿以叠层/并排预览显示。用户选择“应用新排法”后才产生一个可撤销批次。

### 6.6 阅读预览

- 条漫：使用手机宽度模拟连续滚动，标记实际切片边界但不遮挡内容。
- 页漫：逐页/缩略页阅读，按项目阅读方向翻页。
- 问题卡点击后退出预览并定位到对应画格或气泡。
- 预览读取当前自动保存的 Working Copy，不创建正式 Revision。

### 6.7 预览并导出

顶部唯一主动作使用“预览并导出”：

```text
保存当前编辑
  -> 成稿检查
  -> 如内容变化则创建不可变 LayoutRevision
  -> 选择默认出版 Profile
  -> 创建 layout_publication
  -> 显示进度与下载结果
```

普通用户不需要分别操作“立即保存 / 保存版本 / 正式出版”。历史抽屉仍可以显式创建检查点或查看旧版本。

导出选择默认收敛：

- 条漫：默认导出切片，能力允许时同时生成长图；更多设置折叠。
- 页漫：默认导出 PNG 页面；PDF 是同一弹窗内的一个清晰选项。

## 7. 工作台信息架构

```text
┌ 漫画成稿｜已自动保存｜撤销｜重做｜编辑/阅读预览｜预览并导出 ┐
├────────────┬──────────────────────────┬──────────────┤
│ 场景/页/段  │                          │ 当前对象      │
│ 镜头顺序    │       正式可编辑画布       │ 常用属性      │
│ 未放置镜头  │                          │ 局部智能动作  │
├────────────┴──────────────────────────┴──────────────┤
│ 问题、来源更新、历史、图层：按需抽屉，不常驻挤压画布       │
└────────────────────────────────────────────────────┘
```

### 7.1 顶部栏

固定保留：

- 返回项目。
- 当前章节与“漫画成稿”。
- 自动保存状态。
- 撤销、重做。
- 编辑/阅读预览切换。
- `预览并导出` 主按钮。

按需出现：

- `新排法待确认`。
- `有镜头定稿已更新`。
- `成稿有 1 个问题`。

默认隐藏：

- Working Copy、LayoutRevision、publication、digest、内部任务 ID。
- 立即保存、保存版本、当前正式、正式出版等并列动作。

### 7.2 左侧结构栏

条漫：

- 按场景折叠。
- 每个场景下显示条漫段落和镜头缩略图。
- 显示对白数量、是否放置和问题标记。

页漫：

- 页面缩略图列表。
- 页面内镜头顺序。
- 场景和 beat 分隔提示。

底部统一保留“未放置镜头”。自动初稿正常情况下应为 0；用户删除画格或来源更新异常时才出现。

### 7.3 中央画布

- 默认选择工具，不要求用户理解工具模式。
- 单击选中，双击进入文字或裁切编辑。
- 条漫按连续阅读展示，但内部仍保留 section 作为性能、保存和切片边界。
- 页漫显示单页主画布，可切换缩略总览。
- 画格、气泡和文字的安全区问题直接在对象边缘提示，不常驻大面板。

### 7.4 右侧上下文面板

未选择：

- 全章基础样式。
- 智能整理动作。
- 成稿问题摘要。

选择画格：

- 画格尺寸/边框。
- 图片裁切与聚焦。
- 更换布局、锁定。

选择文字/气泡：

- 文字内容、字号和方向。
- 气泡类型、位置、尾巴和说话者。
- 智能避让与断行。

精确坐标、完整图层、历史版本和来源详情放入“更多”，不是主面板首屏。

## 8. 智能成稿详细规则

### 8.1 叙事分组

使用已有字段：

- `sceneId`：场景边界。
- `beatId`：剧情事件归组。
- `motion.frameType`：环境/对白/动作/反应/细节/转场。
- `comic.panelRhythm`：慢/正常/快/冲击/转场。
- `shotType/cameraAngle`：画格比例与视觉强度。
- `characterIds`：气泡说话者与主体避让。

规则不允许跨场景随意拼页；连续对白、动作—反应和铺垫—冲击应保持为完整叙事组。

### 8.2 对白与旁白

- 优先读取带人物的 `motion.voiceLines[]`。
- `comic.dialogue` 只作兼容回退并去重。
- `comic.caption` 生成旁白框。
- 保留原文字、人物和顺序；只允许断行与样式变化。
- 普通/思考/喊叫/旁白按结构和 voiceStyle 判断。
- 未识别说话者仍生成无尾巴气泡，并进入轻量确认列表。
- 每条来源文本用稳定 dialogue item ID 绑定到唯一气泡；用户改文保留 binding 并保护 text，用户确认删除/隐藏时留下 `user_suppressed` 记录，后续智能调整不得偷偷补回。

### 8.3 图片与裁切

- 根据图片宽高、景别和主体区域选择画格比例。
- 优先保留所有必需人物和高置信度脸部。
- 视觉分析不可靠时使用保守裁切，不激进放大。
- 气泡优先进入文字安全区；条漫可使用画格之间留白。

### 8.4 多方案与评分

每个叙事组至少生成 3 种候选，比较：

- 文字是否可读。
- 主体是否被裁切或遮挡。
- 重点镜头是否足够突出。
- 对话阅读顺序是否自然。
- 留白和密度是否符合节奏。
- 是否触碰人工保护。

所有候选先通过镜头/对白完整、文字不溢出、来源 current 等硬门，再从有效候选中稳定选择最高分。

### 8.5 自动修复

发现问题时系统自动尝试：

1. 调整气泡尺寸和位置。
2. 调整断行，不降低到最小可读字号以下。
3. 改画格比例或条漫段落高度。
4. 换同组模板。
5. 页漫重新分页或条漫增加留白段。

仍无法解决才交给用户，不把明显溢出或漏对白结果标记为“已完成”。

## 9. 人工编辑保护

### 9.1 自动保护

用户做过的具体修改只保护对应字段：

- 改裁切：保护 crop，允许系统调整画格。
- 改对白：保护 text，允许系统移动气泡。
- 移动气泡：保护 geometry，允许用户主动整理断行。
- 改样式：保护 style。
- 调尾巴：保护 tail。

不能把任何一次小修改都自动变成整个元素完全锁定。

### 9.2 显式锁定

用户点击“锁定”后，智能功能不能调整该对象的内容、位置、样式、裁切或来源。解除锁定由用户明确操作。

### 9.3 允许再次智能调整

用户可以选择对象并点击“允许智能调整”，清除指定保护。系统不得在后台自行清除。

### 9.4 预览和撤销

- 首次没有 Working Copy 时可以自动应用，因为不存在用户内容。
- 其他所有智能结果必须先预览。
- 应用后是一个完整 Undo 批次，不把几十个微调分散进撤销历史。

### 9.5 删除对白不是普通图层删除

- 删除或隐藏自动绑定的对白/旁白前，系统提示“后续智能排版也会保留省略”。
- 用户确认后保存 `user_suppressed`，不再把该行计为未解释遗漏。
- 用户可从问题/对白列表执行“恢复原对白”；普通新增或复制气泡不自动冒充正式对白绑定。
- 导出前把人工改文和人工省略列为可定位 warning，未绑定遗漏、重复绑定和悬空绑定继续阻断。

## 10. 来源更新、历史与版本

### 10.1 定稿图更新

页面显示：

```text
3 个镜头有新定稿图
[查看] [更新到成稿]
```

批量更新默认保留归一化 crop、画格、对白和气泡。新图主体位置变化导致裁切不安全时，先生成替换预览；旧 LayoutRevision 和旧 publication 永不覆盖。

### 10.2 自动保存

- 所有编辑持续保存 Working Copy。
- 顶部只显示“保存中 / 已自动保存 / 保存冲突”。
- 离开页面先 flush，不自动创建正式 Revision。

### 10.3 历史

历史放入抽屉，显示用户能理解的时间、原因和导出缩略图：

- 自动导出前版本。
- 用户创建的检查点。
- 从历史恢复形成的新 Working Copy。

默认不展示 revision ID、digest 或 binding set。

## 11. 数据、任务与 API 概览

详细字段以 `文档/02_架构与契约/2026-07-22_智能成稿规划与编辑保护契约.md` 为准。

本轮新增：

- `LayoutDocumentV2.automation`：规划来源和字段级 protection。
- `layout_compose`：只生成成稿计划的持久章节任务。
- `LayoutCompositionService/Worker`：来源密封、规划、评分和 apply。
- 初次整章 plan 输出完整 V2 文档；reflow 输出 EditorCommandBatch。

继续复用：

- LayoutWorkingCopy 表与 CAS。
- PendingDialogueArtifact 承载待应用命令。
- LayoutRevision/LayoutSourceBinding。
- layout preflight、renderer、publication、Asset 和 manifest。

成稿文档、保护、对白绑定和任务计划不新增关系模型，继续由现有 Working Copy/Revision/Task/Pending 承载。M4 实施时确认“任务成功”和“建议已经应用”必须有独立 exactly-once 证据，而 `GenerationTask.observedEvidenceJson` 受 legacy import 约束且终态任务不可回写，因此已按原停止线新增 ADR-0020，并增加窄、不可变、每任务至多一条的 `LayoutCompositionApplication`。它只记录实际 WC/Pending 目标和摘要，不保存第二份漫画内容。

## 12. 前端组件拆分建议

当前 `LayoutExportWorkspace.vue` 体积和职责过大。本轮按用户路径拆分，不按视觉区域机械搬代码：

| 组件/模块 | 职责 |
| --- | --- |
| `LayoutManuscriptWorkspace.vue` | 页面状态编排和顶部主路径 |
| `LayoutCompositionGate.vue` | 前置不足、首次任务、失败与恢复 |

## 14. 分阶段开发

### M0：固定样例与现状基线

交付：

- 竖向条漫与分页漫画各不少于 4 组固定章节。
- 覆盖单人独白、双人对话、多人对话、长对白、动作高潮、安静转场、无对白和来源更新。
- 保存现有固定布局、页面截图、人工调整数量和 renderer 输出作为红灯基线。

退出标准：

- 每个样例都有正式 Storyboard、CandidateLockSet、真实尺寸图片和受控字体。
- 评分表和人工复核方法固定，不能开发后再挑有利样例。

### M1：LayoutDocumentV2 与编辑保护

实施状态：`complete`（2026-07-22）。实现位于 `packages/shared/src/layout/automation.ts` 与 `commands-v2.ts`，合同证据见任务目录 `evidence/m1-contract/`；尚未接 Server 持久化、`layout_compose` 或 Web。

交付：

- V1/V2 codec、无损升级与降级。
- automation/dialogue binding/protection contract。
- Command actor 和字段保护映射。
- smart 结果触碰保护时的拒绝与测试。

退出标准：

- `V1 -> V2 -> V1` 可见文档等价；V1 Working Copy 的既有对象默认 `explicit_preserve`，历史 Revision 不改写。
- 人工修改 crop/text/geometry/style/tail 后，测试证明 smart batch 只改未保护字段。
- dialogue binding 的用户改文、删除/隐藏 tombstone、恢复和复制规则通过合同测试。
- 现有 G5 renderer golden 不变。

### M2：对白、叙事分组和规则模式智能初稿

实施状态：`complete`（2026-07-22）。实现位于 `packages/shared/src/layout/dialogue.ts`、`narrative.ts`、`rule-composer.ts`；真实 renderer、manifest 和视觉复核见任务目录 `evidence/m2-rule-composition/`。本状态只关闭内容完整、忠实、确定性和规则 fallback 可渲染，不提前关闭 M3 的 80% 视觉质量门。

交付：

- 对白归一化、稳定 lineId、去重和覆盖账本。
- lineId 与气泡元素的持久 binding，以及 `placed/user_suppressed` 状态。
- scene/beat/frameType/panelRhythm 分组。
- 条漫可变段落、页漫 3～6 格规划。
- 自动气泡、旁白、断行、阅读顺序和规则 fallback 裁切。

退出标准：

- 固定语料镜头/对白/旁白 100% 覆盖，无静默改写和文字溢出。
- 不依赖外部视觉 Provider 也能生成可读基础成稿。

### M3：视觉分析、多候选评分与自动修复

交付：

- 严格视觉区域 adapter 和置信度策略。
- 主体/人脸保护、文字安全区和尾巴定位。
- 每组多候选、硬门、100 分软分、稳定 tie-break。
- 最多 4 轮有限自动修复。

退出标准：

- 同输入同策略输出相同 plan digest。
- Provider 非法输出、超时和低置信度都安全降级。
- 固定语料普通章节的画格/裁切直接可用率和自动绑定气泡直接可用率均达到 ≥80%，未达到则不得进入默认 on。

### M4：持久 layout_compose 任务与首次应用

交付：

- Shared task type/policy/source/output codec。
- Server create/status/apply API、idempotency、重启恢复和来源二次校验。
- 无 Working Copy 的首次自动创建；有 Working Copy 只生成 preview。

退出标准：

- 刷新、丢响应、服务重启和重复点击不重复创建或覆盖 Working Copy。
- 任务期间 Storyboard/定稿图变化时结果过期，不写 current。

### M5：统一漫画成稿工作台

实施状态（2026-07-23）：`complete`。条漫和页漫零配置浏览器路径、已有稿恢复、V2 同一编辑器手调、整章左右对比、保留/应用/一次 Undo 已通过；当前仍使用规则 fallback，不把本阶段写成真实视觉 Provider 已完成。

交付：

- 首次 CompositionGate。
- 顶部单主路径、左侧结构栏、中央画布、右侧上下文面板。
- 编辑/阅读预览切换、问题定位和简化文案。
- 原有完整编辑能力迁入新壳，不建立第二个轻量编辑器。

退出标准：

- 首次用户不接触 Profile、模板或系统术语。
- 直接修改画格、裁切、对白和气泡的真实浏览器路径通过。
- 长条章节编辑性能达到现有 G5 门槛，无明显回退。

### M6：局部智能预览与人工保护闭环

实施状态（2026-07-23）：`complete`。真实图片附件、严格视觉分析 adapter、逐镜头规则回退与历史分析复用已接入持久成稿任务；同一工作台已开放选中内容、当前页/段和当前场景调整，全部继续走原稿/新稿预览、保留/应用和一次 Undo。手调字段和显式锁定逐字段跳过；用户可对选中对象显式“允许智能再次调整”。本轮只使用本地假结构化服务验证 provider 通道，没有发起付费外部视觉调用，因此不把具体视觉模型的审美质量写成已验收。

交付：

- 整章、场景、页面/段落、选区动作。
- PendingEditorCommandSet 原稿/新稿对比。
- 应用/放弃、单批 Undo、允许智能调整和显式锁定。

退出标准：

- 所有非首次智能变更先预览。
- 受保护和锁定字段 0 覆盖。
- base/source 变化导致预览过期并可重新生成。

### M7：来源更新、阅读检查与一键出版

交付：

- 用户可理解的来源更新 banner 和保留 crop 的替换预览。
- 条漫手机滚动、页漫逐页预览和问题定位。
- “预览并导出”编排 autosave、preflight、Revision 和 publication。
- 历史、图层、来源详情移入按需抽屉。

退出标准：

- 用户不需要理解“Working Copy / LayoutRevision / publication”。
- 导出失败可恢复，不生成半成品 current。
- 编辑预览、阅读预览和下载产物一致。

### M8：切换、回归和真实用户签收

交付：

- feature gate `off -> shadow -> on`。
- 旧 V1 Working Copy/Revision 兼容、现有用户显式智能升级预览。
- 全量 Shared/Server/Web/renderer/E2E 回归。
- 条漫与页漫真实项目 Runtime/User Review、截图和导出证据。

退出标准：

- 验收清单所有 P0/P1 用例为 passed 或获批 not_applicable。
- 无未解释 failed/blocked/not_run。
- 现有 G5 出版和历史导出没有回归。

## 17. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 分镜对白结构不完整 | 气泡说话者错误 | voiceLines 优先、comic fallback、稳定去重、无尾巴保守结果；后续再评估上游显式 lineKind |
| 视觉分析不稳定或成本高 | 首次慢或遮挡错误 | 规则模式必备、分析缓存绑定 Asset digest、置信度门槛、shadow 评测 |
| 多候选搜索过慢 | 首次等待和本地资源压力 | NarrativeGroup、beam 上限、有限修复和全局并发 1 |
| V2 破坏 renderer | 正式导出回归 | 不增加可见元素、V1/V2 golden、降级器、feature gate |
| 人工保护过强 | 智能功能看似无效 | 字段级 protection、明确“允许智能调整”，不把小改自动全锁 |
| 人工保护过弱 | 覆盖用户工作 | apply 前硬门、预览、单批 Undo 和锁定 |
| 大组件继续膨胀 | 后续难维护 | composition/editor/publication 状态分层，按业务职责拆组件与 service |

## 18. 完成定义

以下全部满足后，才能把新版“漫画成稿”标记为完成：

1. 用户不配置模板、尺寸或气泡即可得到完整成稿。
2. 全部镜头、对白和旁白自动进入正式可编辑对象。
3. 固定语料达到内容 100% 覆盖、文字 0 溢出、画格/裁切与自动绑定气泡两项直接可用率均 ≥80%。
4. 编辑器可以直接改画格、裁切、对白、气泡、顺序和样式。
5. 局部智能调整保护人工修改、尊重锁定、先预览并可撤销。
6. 来源变化、并发、刷新、重启和失败不会静默覆盖当前内容。
7. 一次“预览并导出”产生真实 current publication；旧版本和旧导出保留。
8. 真实条漫与页漫 Runtime/User Review 通过，并有截图、任务、Revision 和产物证据。
