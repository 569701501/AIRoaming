## 1. 背景

> 关联：本文档定义角色库"作为常驻资产 + 硬门槛后移到出图准备"的总体定位。角色版本区间模型、档案与三视图的建立时机、剧情结构页角色区域交互（新角色定稿状态机 + 老角色带入 + 新版本）等细化决策，见 `ADR-0004_角色版本与定稿时机方案.md`。

原口径把 `项目角色库` 放在剧本和剧情结构之间，并要求主角和常驻角色完成视觉定稿后才能进入剧情结构。

用户视角复盘后发现：

- 剧情结构是写作和制作结构，不依赖角色图全部定稿。
- 角色图生成可能慢、失败或需要多次挑选，如果放在剧情结构前，会打断创作节奏。
- 如果完全隐藏角色库，用户又会缺少“角色一致性是否已经处理好”的安全感。
- 候选图生成才真正依赖稳定角色参考图。

## 2. 决策

顶部主流程调整为：

```text
剧本 -> 剧情结构 -> 分镜工作台 -> 出图准备 -> 候选图工作台 -> 排版导出 -> 素材包
```

`项目角色库` 调整为项目级常驻资产入口，不再作为顶部主流程步骤。

角色视觉定稿的硬门槛后移到 `出图准备`：

- 不阻塞剧情结构。
- 不阻塞分镜生成。
- 阻塞候选图生成。

## 3. 角色库职责

项目角色库负责保存：

- 主角 `lead`
- 常驻角色 `recurring`
- 本章重要角色 `chapter`
- 临时/背景角色 `extra`
- 角色描述、角色层级、预览图、定稿图、视觉版本和锁定状态

角色库中的 `角色名` 是项目内身份标识，不是图片生成弹窗里的可编辑字段。普通用户在角色图卡片里看到角色名，但不能在图片生成弹窗中改名；如果 AI 识别错了角色身份，应走底层合并、重新入库或高级维护，而不是在生图弹窗里临时改名。

普通角色图流程只允许用户修改用于 AI 生图的形象描述 / prompt，并重新生成或应用当前图片。左侧 AI 对话负责生成、解释、合并建议和批量调整，但用户可见主路径不应把角色名、层级和角色归属混进图片生成弹窗。

角色定稿图一旦被候选图使用，不允许覆盖旧图；后续改变形象应创建新视觉版本，只影响新生成内容。

## 4. 新角色增量机制

剧情结构和分镜阶段自动发现本章角色，并与项目角色库匹配。

匹配不到的角色进入待处理列表，底层仍支持四种归类动作：

| 动作 | 含义 |
| --- | --- |
| 加入角色库 | 作为新的项目角色保存 |
| 合并到已有角色 | 说明 AI 识别的是同一角色或别名 |
| 标记临时 | 本章路人、功能性人物或背景人物 |
| 忽略 | AI 误判，不进入后续检查 |

> 2026-06-21 调整：出图准备页不再就地展示这四种动作。改为**源头约束**——分镜生成时 AI 必须只用 `structure.characters` 已有角色名，未识别应几乎不发生；偶发未识别时出图准备只提示"回分镜修正或重新生成分镜"。四种动作的前端 UI 已移除，后端 `resolveImagePreflightCharacter` 接口暂留待清理。

## 5. 出图准备职责

出图准备是章节级检查点。

它读取：

- 当前章节正式 `storyboard.json` / `Shot[]`
- 项目角色库 `Character[]`
- 角色参考图 `Asset(reference image)`
- 后续场景和风格参考

它检查：

- 每个镜头出镜角色是否已绑定项目角色或明确为临时/背景角色。
- 待处理新角色是否已经处理。
- 主角、常驻角色和当前章重要出镜角色是否具备可用参考图。
- 场景、画风和漫画形式是否足够生成候选图。

确认通过后，才允许进入候选图工作台。

## 6. 角色图卡片与图片生成弹窗

2026-06-06 追加交互口径：

- 右侧内容区可以在剧情结构或出图准备中展示“本章角色图列表”。
- 列表只展示当前章节相关角色：主角、常驻角色、本章结构/分镜中出现的重要角色和当前阻塞角色；全量项目角色库通过“查看全部角色”进入。
- 用户确认剧情结构时，系统按角色名匹配项目角色库；已有角色复用已有角色档案和角色图，不重复创建、不重复生成；新角色自动写入项目角色库，并自动排队生成第一张角色图。
- 角色图卡片默认展示图片和只读角色名。
- 鼠标悬停卡片时显示编辑和删除图标。
- 点击编辑打开“角色图片生成弹窗”，不是“角色档案编辑弹窗”。
- 弹窗中角色名只读，不能修改。
- 弹窗中的“描述”是给 AI 生图用的形象描述 / prompt，不是角色身份名称。
- 用户修改描述后可以重新生成图片；普通 UI 中重新生成表现为直接替换当前卡片图。
- 普通卡片不展示 `确认预览`、`重新生成预览` 这类中间状态按钮；无图时显示 `生成角色图`，需要定稿时显示 `生成定稿`，定稿图确认使用时显示 `锁定定稿`。
- 当用户触发 `生成定稿` 时，系统内部自动使用当前第一张角色图作为参考，不要求用户先点击“确认预览”。
- 底层仍可为了素材追溯创建新的 `Asset` 或视觉版本，但不在普通 UI 中展示图片版本选择器。
- 点击删除只删除当前图片版本或当前卡片展示图，不删除项目级 `Character` 角色条目。
- 删除当前图片必须二次确认。
- 如果角色定稿图已经被漫画候选图使用，不能覆盖旧参考图；后续换形象必须走新视觉版本并只影响新生成内容。

## 7. 取舍

优点：

- 用户可以先推进写作和分镜，不被图片生成拖住。
- 角色一致性在真正出图前被强制检查，不会遗漏。
- 项目角色库保持长期资产属性，适合跨章节复用。
- 后续章节出现新角色时，有明确的增量入库和合并路径。

代价：

- 需要新增 `出图准备` 页面和状态。
- 已完成一次主流程迁移：`project_characters` 从顶部主流程移出，新增 `image_preflight`。
- 候选图生成前需要多一层检查逻辑。

## 8. 实现状态

2026-06-02 已完成首轮迁移：

- `PROJECT_WORKFLOW_STEP_KEYS` 已调整为 `project_story -> story_structure -> storyboard -> image_preflight -> image_candidates -> layout_export -> asset_package`。
- `/projects/:projectId/characters` 保留为项目级资产入口，不再显示在顶部主流程序号中。
- `/projects/:projectId/preflight` 已新增为出图准备路由。
- `resolveWorkflowCurrentStepKey` 不再用角色库完成状态阻塞 `story_structure`。
- `storyboard_done` 后会先进入 `image_preflight`；用户确认出图准备后，系统写入 `chapters/{chapterSlug}/preflight.json`。
- `workflow` 只有在 `preflight.json` 与当前正式 `storyboard.json` 的 `storyboardId/updatedAt` 匹配，且当前派生检查仍通过时，才推进到 `image_candidates`。
- `POST /api/tasks` 创建 `shot_prompt_generate` / `image_generate` 前会校验本章出图准备确认，创建成功的任务 input 会写入 `imagePreflightId`、`sourceStoryboardId` 等追溯字段。
- 出图准备对未识别出镜角色不再就地处理（2026-06-21：前端"加入/合并/临时/忽略"4 动作 UI 移除，改源头约束，见下方 2026-06-21 更新）。后端 `resolveImagePreflightCharacter` 接口暂留。
- 出图准备已补齐轻量场景和画风检查：镜头 `sceneId` 必须匹配本章剧情结构场景卡；确认记录写入 `sceneChecks` 和 `styleCheck`，自定义画风先作为 warning，不阻塞候选图。
- 项目页顶栏新增“角色库”入口，用户可随时进入项目角色库。

2026-06-06 发现的实现缺口：

- `StoryStructureWorkspace.vue` 当前只有本章文字角色卡，还没有内嵌“本章角色图列表”。
- `ProjectCharactersWorkspace.vue` 当前更像完整角色库页面，不是 Seko 式轻量图卡列表和图片生成弹窗。
- ~~出图准备页当前仍显式展示加入角色库、合并、标记临时、忽略等底层动作~~ → 2026-06-21 已收敛：前端 UI 移除，改源头约束分镜角色名。
- 角色图重新生成在用户界面上应直接替换当前卡片图；底层资产版本追溯与 UI 版本选择要明确区分。

2026-06-21 更新（出图准备重构为"出门检查单"）：

- 出图准备页重构：砍掉 metrics 数字仪表盘、重复 hero、next-card 引导卡、未识别角色 4 动作区、本章角色图列表、场景画风面板、镜头角色绑定面板；改为"就绪度一句话 + 全项检查清单（✓已完成 / ⚠未完成+提醒+入口）+ 主按钮"。
- 定位收窄：出图准备不再当"第二个角色库"，角色图生成/定稿彻底还给剧情结构页；出图准备只做检查+放行候选图。
- 源头约束：`buildStoryboardPrompt` 加硬约束，`characterIds` 必须从 `structure.characters` 的 name 选，消除未识别出镜。
- 修复 `isFinalized` 误判：改为判断 `primaryReferenceAssetId` 是否真锁定到 `final_reference`（与 `hasFinalReference` 一致），解决"有定稿图但 `fully-locked` 模式隐藏锁定按钮"的死锁。
- 前端 `isRequiredReferenceCharacter` 补 `minor`（与后端一致）。
- 死链清理：`ProjectWorkbenchView` + `AppShell` 的 `resolveCharacter` 绑定/emit/函数/import 已删；`stores`/`api`/后端接口暂留。

2026-07-19 更新（素材要求前置，见 ADR-0018）：

- 出图准备继续保持纯检查：缺项阻断，但不生成、不修复、不自动补图。
- 素材要求在剧情结构确认时按 `level + entityType` 固定；`appearanceCount` 仅展示，不再让角色在确认分镜后突然升级为定稿要求。
- `human + lead/recurring/chapter` 要求定稿组合图；`human + minor/extra`、`creature`、`group` 只要求单张参考；`voice` 不要求图片。
- 分镜只能引用当前确认剧情结构主体；同一 group 的保守文字别名共用一份素材身份。

后续可继续增强：

- 场景参考图、风格板和项目级画风提示词片段的资产化管理。
