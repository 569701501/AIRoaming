哪些提示词值得去 GitHub 借鉴

结论先说：最适合借鉴的是“生图类提示词模板”和“角色一致性模板”；剧情结构、分镜、剧本写作可以借鉴方法论；项目事实源、工具调用边界和写入协议不要照搬外部提示词。

最高优先级P23-P26

总判断

外部提示词不是拿来整体复制的，更适合拆成“提示词部件”：主体、动作、构图、镜头、光线、风格、角色一致性、负面约束、输出格式、验收规则。

可以直接借鉴结构

图片生成、角色定稿、场景参考

这类提示词在 Stable Diffusion、ComfyUI、Fooocus 风格库、漫画生图项目里沉淀很多。我们可以借鉴它们的分层结构和负面提示词，但不要整段复制。

只能借鉴方法

灵感、故事结构、章节写作、分镜

外部写作提示词能提供故事钩子、因果推进、角色弧光、场景诊断等框架；但 AI漫游有自己的章节流水线和 JSON 契约，必须二次改造。

不建议外部照搬

事实源、写入边界、工具描述

这些提示词本质是项目安全协议和本地工具协议。外部通用 agent prompt 可能破坏受控写入、章节作用域和素材追溯。

提示词资产借鉴矩阵

基于当前盘点出的 P01-P27，按“能不能从外部热门 prompt 直接吸收结构”重新分级。

资产 当前用途 借鉴等级 可借鉴什么 不该借鉴什么 推荐来源方向
P25 / P26 候选图最终 provider prompt 与前端 prompt 预览 最高：直接借鉴结构 借鉴生图 prompt 的分层：主体、动作、镜头景别、构图、漫画画格、光线、情绪、角色一致性、风格 preset、negative prompt。 不要直接复制某个模型或某个画师风格整段词；不要把第三方版权角色、IP、艺术家名作为默认模板。 Stable Diffusion prompt 集、ComfyUI style preset、Fooocus/SDXL 风格库、漫画 panel prompt。
P23 角色参考图、预览图、定稿四视图 最高：直接借鉴结构 借鉴 character reference sheet / turnaround sheet 写法：正面、侧面、背面、表情、服装细节、色板、白底、同一角色一致性。 不要照搬偏 3D、真人、儿童化、特定 IP 的模板；AI漫游默认应保持漫画/条漫角色设定图。 角色设定图 prompt、character consistency、turnaround reference sheet。
P24 场景参考图 prompt 高：直接借鉴结构 借鉴环境场景 prompt 的空间层级：地点、时代、时间、天气、镜头、焦点、透视、光线、氛围、可复用背景资产。 不要只堆“高质量、细节丰富”；不要把场景做成不可用于漫画分镜的概念图。 environment concept art prompt、background prompt、manga/comic scene prompt。
P06 分镜 JSON prompt 高：借鉴漫画镜头语言 借鉴 storyboard、comic panel、cinematic shot 的质量标准：景别、视角、动作连续性、阅读顺序、对白气泡位置、节奏变化。 不要照搬视频 storyboard 的 16:9 镜头逻辑；漫画分镜要保留画格、条漫阅读和气泡排版语义。 storyboard 工具、漫画面板 prompt、视频 prompt 的 shot grammar。
P05 剧情结构 JSON prompt 中高：借鉴故事工程方法 借鉴 Story Spine、Hero's Journey、因果推进、角色目标/阻碍/转折等结构诊断维度。 不要让外部三幕剧模板覆盖章节级结构卡；不要把剧情结构直接变成最终读者正文。 story generation、writers room、story beat design。
P07 / P19 灵感种子 prompt / skill 中：借鉴开篇钩子 借鉴爆款开篇、冲突设问、角色欲望、反转承诺、视觉钩子等维度，让 3 个方向差异更大。 不要复制外部故事创意；不要生成无法落到漫画画面的抽象主题。 creative writing prompts、story ideation prompts、短剧/漫画 hook 模板。
P08-P10 / P20-P21 大纲和章节生成 prompt / skill 中：借鉴方法，不借鉴格式 借鉴“从 premise 到 outline 到 chapter”的多阶段拆解、角色弧光、冲突升级、场景目的。 不要改掉项目固定大纲和章节格式；不要让章节正文提前输出分镜、镜头编号或图片 prompt。 story writing agents、novel writing workflow、prompt chaining。
P12 / P22 章节改写 prompt / skill 中低：借鉴编辑诊断 借鉴改写评估项：节奏、对白自然度、冲突密度、人物动机、视觉可画性、章节结尾钩子。 不要让编辑 prompt 只输出建议或 diff；项目仍需要完整章节 Markdown。 writing editor prompts、revision prompts。
P13-P15 剧本大纲/章节格式和禁止输出约束 保留自有 可以参考外部“格式约束写法”，比如明确输出边界、禁止项、示例不要复用。 不要照搬外部格式；这些约束是 AI漫游流水线事实源的一部分。 Prompt Engineering Guide 的结构化输出原则。
P01-P04 通用上下文与阶段边界契约 不宜借鉴内容 只能借鉴“指令层级清晰、事实源优先、动作边界明确”的写法。 不要套外部 assistant persona；它们容易破坏项目阶段、章节作用域和受控写入边界。 通用 prompt engineering 方法，不直接拿模板。
P16-P18 / P27 OpenCode AGENTS、agent、导入 skill、工具描述 不宜借鉴内容 可以借鉴 prompt 测试、红队、tool description 评估方法。 不要直接用外部 agent prompt；工具名、回调、写入边界、素材路径都是项目私有协议。 promptfoo、agent eval、tool calling best practices。

外部来源怎么用

这些来源不是让我们复制文本，而是帮助拆解成熟提示词的“部件”和“验收标准”。

f/prompts.chat

大型通用 prompt 集合，适合观察角色设定、任务说明、输出口径的组织方式。它更适合启发 P07/P12 这类文本创作 prompt，不适合直接进项目协议。

通用 prompt 结构

dair-ai/Prompt-Engineering-Guide

适合借鉴提示词工程方法：任务分解、结构化输出、示例、约束顺序、评估。它不是漫画 prompt 库，但适合规范 P01-P15 的写法。

提示词工程方法

Stable Diffusion prompt collection

适合拆解图像 prompt 的风格词、质量词和 negative prompt 组合。对 P23-P26 有直接参考价值，但 GPL 仓库文本不要整段搬进代码。

生图 prompt 结构

ComfyUI style preset

适合学习“风格 preset = prompt 模板 + negative_prompt”的组织方式。AI漫游后续可以做自己的漫画风格库，而不是把风格散落在每个任务里。

风格预设库

automatic-comic-book

项目不大，但方向贴近漫画：角色一致性依赖可识别特征和负面提示词。这个观点对 P23 角色定稿和 P25 候选图都重要。

角色一致性

manga-editor-desu

更偏漫画页面制作和 WebUI 扩展，不是 prompt 库。适合参考漫画创作工具流程，尤其是从生图到面板编辑的产品形态。

漫画工具流程

writers-room-story-engine

适合借鉴故事工作流：故事地基、世界观压力、场景写作、修订诊断。可用于加强 P05/P07/P20/P21 的创作质量评价维度。

故事方法论

promptfoo

不是拿来抄 prompt，而是给提示词做回归测试、模型对比、红队测试。后续替换 P23-P26 前，应该先准备一组固定漫画样例做对比。

提示词评测

建议的下一步

先不要全项目大改。最小可控做法是先优化候选图和角色图，再反推分镜 prompt。

第一批只动 P23-P26：建立 AI漫游自己的漫画生图 prompt 模板，统一后端实际 provider prompt 与前端预览 prompt，并保留用户可编辑入口。
  • 1. 建 Prompt 部件库把风格、构图、角色一致性、负面提示词拆成可组合片段，避免每个服务硬编码一段长 prompt。
  • 2. 统一候选图拼装P25 后端实际出图必须复用 P26 前端预览的同一套纯函数或同构逻辑。
  • 3. 引入角色一致性模板P23 增加正面/侧面/背面、服装细节、色板、表情、白底和同一角色一致性约束。
  • 4. 补漫画 negative prompt按漫画生成常见问题分层：真人感、低清、畸形、文字水印、多角色错位、气泡文字异常。
  • 5. 做样例对照页每次优化提示词，用同一批 shot、character、scene 样例生成对比，避免凭感觉改。
  • 6. 再升级 P06 分镜当图片 prompt 稳了，再让分镜输出更适合生图的 promptDraft 和漫画画格字段。
