# G2 施工包：API、DTO、兼容与幂等契约

## 1. 通用规则

- 所有响应继续使用 `ApiEnvelope<T>` / `ApiErrorEnvelope`。
- 所有 G2 mutation 都携带 expected ID/digest/rowVersion；不接受客户端提交 freshness/current 状态。
- 所有文档 PATCH 是**完整 strict document replace**，不是 JSON Patch，也不是任意 partial object。
- 409 后客户端必须重新 GET `production-state` 和对应 working copy；不得自动覆盖。
- `projectId/chapterId/versionId/shotId` 必须做同 scope 验证。
- 时间为 UTC ISO 8601；digest 为 `sha256:<64 lowercase hex>`。

基础路径：

```text
/api/projects/{projectId}/chapters/{chapterId}
```

## 2. Capability

`WorkbenchSnapshot` 增加：

```ts
interface VersioningCapability {
  mode: "legacy_file" | "g2_db";
  schemaVersion: 2;
  supports: {
    scriptWorkingCopy: boolean;
    storyWorkingCopy: boolean;
    storyboardWorkingCopy: boolean;
    preflightRevision: boolean;
    persistentTaskRuntime: boolean;
    importer: boolean;
  };
}
```

能力必须来自服务端真实 runtime，不按表是否存在推断。`persistentTaskRuntime/importer` 在接线前固定 `false`。

所有 G2 新 mutation 路径在 `mode='legacy_file'` 时返回 `409 G2_DB_MODE_REQUIRED`；Capability 的作用是避免正常 UI 发出这类请求，不是替代服务端保护。

## 3. 公共 DTO

### 3.1 Version summary

```ts
interface VersionSummary {
  id: string;
  version: number;
  lifecycle: "pending_confirmation" | "confirmed" | "archived";
  schemaVersion: number;
  documentDigest: string;
  sourceId: string | null;
  sourceDigest: string | null;
  sourcePolicyVersion: string | null;
  origin: "user_edit" | "ai_generate" | "import" | "legacy_import";
  rowVersion: number | null;
  freshness: "current" | "stale" | "historical" | "pending";
  reasonCodes: FreshnessReasonCode[];
  createdAt: string;
  confirmedAt: string | null;
  archivedAt: string | null;
}
```

Script/Preflight 无 mutable pending row 时 `rowVersion=null`；其 history adapter 可使用同一 summary。

### 3.2 Mutation result

```ts
interface VersionMutationResult<T> {
  value: T;
  productionState: ChapterProductionState;
  chapterRowVersion: number;
  replayed: boolean;
}
```

`replayed=true` 只表示服务端从已提交状态识别出同一目标已经达成，不表示请求再次执行了写入。

### 3.3 History page

```ts
interface VersionHistoryPage<T> {
  items: T[];
  nextBeforeVersion: number | null;
}
```

查询参数：

```text
limit: default 20, min 1, max 100
beforeVersion: optional positive integer, exclusive
```

固定排序 `version DESC`；禁止 offset pagination。

## 5. Script Working Copy

### 5.1 读取

```text
GET .../script/working-copy
```

```ts
interface ScriptWorkingCopyDto {
  sourceText: string;
  title: string;
  summary: string | null;
  digest: string;
  state: "empty" | "clean" | "dirty";
  currentVersion: VersionSummary | null;
  chapterRowVersion: number;
}
```

### 5.2 保存/AI 采用

```text
PATCH .../script/working-copy
```

```ts
interface UpdateScriptWorkingCopyRequest {
  sourceText: string;
  title?: string;
  summary?: string | null;
  expectedChapterRowVersion: number;
}
```

响应 `VersionMutationResult<ScriptWorkingCopyDto>`。

状态重放：如果当前 `chapterRowVersion=expected+1` 且规范化后的 text/title/summary/digest 与请求完全相等，返回现状并令 `replayed=true`；否则旧 rowVersion 返回 `409 CHAPTER_VERSION_CONFLICT`。

### 5.3 清空 Working Copy

```text
DELETE .../script/working-copy
```

```ts
interface ClearScriptWorkingCopyRequest {
  expectedWorkingDigest: string;
  expectedChapterRowVersion: number;
}
```

- 无 current：结果 `state=empty`。
- 有 current：正文置空、digest 为空文本摘要、`state=dirty`；不删除 current/history/downstream。
- 已处于目标状态时按 expected digest/rowVersion 识别重放。

### 5.4 还原

```text
POST .../script/working-copy/revert
```

```ts
interface RevertScriptWorkingCopyRequest {
  expectedCurrentScriptVersionId: string;
  expectedWorkingDigest: string;
  expectedChapterRowVersion: number;
}
```

还原到 current Script，返回 clean。没有 current 返回 `409 SCRIPT_VERSION_MISSING`。若已 clean 且 current ID/digest 相等，返回 `replayed=true`。

### 5.5 发布

```text
POST .../script/publish
```

```ts
interface PublishScriptRequest {
  expectedCurrentScriptVersionId: string | null;
  expectedWorkingDigest: string;
  expectedChapterRowVersion: number;
  createNextChapter: boolean;
  nextChapterTitle?: string;
}
```

```ts
interface PublishScriptResponse {
  scriptVersion: VersionSummary;
  workingCopy: ScriptWorkingCopyDto;
  activeChapterId: string;
  createdNextChapter: boolean;
  productionState: ChapterProductionState;
  replayed: boolean;
}
```

空正文返回 `400 SCRIPT_WORKING_EMPTY`。丢响应重放：若 current Script 的 sourceDigest 等于 expectedWorkingDigest、Working Copy clean 且未出现更新的 working rowVersion，返回该 current，`replayed=true`；不得创建第二个版本或第二个下一章。

`createNextChapter=true` 的幂等由 `(project_id, order/slug)` unique 和 committed active chapter 共同识别；重放不能再创建下一章。

### 5.6 AI 待采用稿

`ChapterScriptPending` 是 AI 提议缓冲，不是正式 ScriptVersion，也不等于 Chapter Working Copy。

```text
GET    .../script/pending-suggestion
POST   .../script/pending-suggestion/adopt
DELETE .../script/pending-suggestion
```

```ts
interface ScriptPendingSuggestionDto {
  id: string;
  sourceText: string;
  digest: string;
  operation: string;
  rowVersion: number;
  createdAt: string;
  updatedAt: string;
}

interface AdoptScriptPendingSuggestionRequest {
  pendingId: string;
  expectedPendingRowVersion: number;
  expectedPendingDigest: string;
  expectedChapterRowVersion: number;
}

interface DiscardScriptPendingSuggestionRequest {
  pendingId: string;
  expectedPendingRowVersion: number;
}
```

adopt：校验后把 pending 文本写入 Working Copy、删除 pending、Chapter rowVersion+1；不创建 ScriptVersion。若 pending 已消失且 Working Copy digest 等于该请求目标 digest，返回重放成功。discard：只删除 pending；已不存在时幂等返回。存在 pending suggestion 时所有新下游任务和 Story/Board/Preflight confirm 都返回 `409 UPSTREAM_WORK_NOT_CONFIRMED`。

## 6. Story Working Copy

### 6.1 读取

```text

```

返回：

```ts
interface StoryWorkingCopyDto {
  pending: VersionSummary | null;
  current: VersionSummary | null;
  document: StoryDocumentV2 | null;
  basedOnCurrentVersionId: string | null;
  sourceScriptVersionId: string | null;
  rowVersion: number | null;
  productionState: ChapterProductionState;
}
```

### 6.2 创建

```text
POST .../story-structure/working-copy
```

```ts
interface CreateStoryWorkingCopyRequest {
  mode: "clone_current" | "empty";
  expectedCurrentVersionId: string | null;
  expectedSourceScriptVersionId: string;
  expectedChapterRowVersion: number;
}
```

- 已有 active pending 且 current/source/mode 目标一致：幂等返回，`replayed=true`。
- 已有不兼容 pending：`409 ACTIVE_PENDING_EXISTS`，不覆盖。
- `empty` 创建合法 V2 空壳，但 confirm 前必须通过完整 strict codec。

### 6.3 更新

```text
PATCH .../story-structure/working-copy
```

```ts
interface UpdateStoryWorkingCopyRequest {
  pendingVersionId: string;
  document: StoryDocumentV2;
  expectedPendingRowVersion: number;
  expectedChapterRowVersion: number;
}
```

完整替换。角色 token 解析为 Character.id 后再计算 digest。若当前 pending rowVersion=`expected+1` 且 documentDigest 等于请求规范化 digest，识别为重放；否则冲突。

### 6.4 丢弃

```text
DELETE .../story-structure/working-copy
```

```ts
interface DiscardStoryWorkingCopyRequest {
  pendingVersionId: string;
  expectedPendingRowVersion: number;
  expectedChapterRowVersion: number;
}
```

pending→archived 并清 pointer。若 pointer 已空且该 version 已 archived，返回重放成功。

### 6.5 确认

```text
POST .../story-structure/working-copy/confirm
```

```ts
interface ConfirmStoryWorkingCopyRequest {
  pendingVersionId: string;
  expectedPendingDocumentDigest: string;
  expectedPendingRowVersion: number;
  expectedCurrentVersionId: string | null;
  expectedSourceScriptVersionId: string;
  expectedSourceDigest: string;
  expectedChapterRowVersion: number;
}
```

响应 `VersionMutationResult<{ current: VersionSummary; document: StoryDocumentV2 }>`。

丢响应重放：pending pointer 已空、`currentStoryVersionId=pendingVersionId`、document/source digest 与请求相等时返回成功。新 current 不得重复 formalize。

## 7. Storyboard Working Copy

路径与 Story 完全展开如下，不再使用“同构”代替契约：

```text
GET    .../storyboard/working-copy
POST   .../storyboard/working-copy
PATCH  .../storyboard/working-copy
DELETE .../storyboard/working-copy
POST   .../storyboard/working-copy/confirm
POST   .../storyboard/working-copy/shots
```

### 7.1 DTO

```ts
interface StoryboardWorkingCopyDto {
  pending: VersionSummary | null;
  current: VersionSummary | null;
  document: StoryboardDocumentV2 | null;
  basedOnCurrentVersionId: string | null;
  sourceStoryVersionId: string | null;
  rowVersion: number | null;
  productionState: ChapterProductionState;
}

interface CreateStoryboardWorkingCopyRequest {
  mode: "clone_current" | "empty";
  expectedCurrentVersionId: string | null;
  expectedSourceStoryVersionId: string;
  expectedChapterRowVersion: number;
}

interface UpdateStoryboardWorkingCopyRequest {
  pendingVersionId: string;
  document: StoryboardDocumentV2;
  expectedPendingRowVersion: number;
  expectedChapterRowVersion: number;
}

interface DiscardStoryboardWorkingCopyRequest {
  pendingVersionId: string;
  expectedPendingRowVersion: number;
  expectedChapterRowVersion: number;
}

interface ConfirmStoryboardWorkingCopyRequest {
  pendingVersionId: string;
  expectedPendingDocumentDigest: string;
  expectedPendingRowVersion: number;
  expectedCurrentVersionId: string | null;
  expectedSourceStoryVersionId: string;
  expectedSourceDigest: string;
  expectedChapterRowVersion: number;
}
```

创建、更新、丢弃、确认的 state-based replay 与 Story 相同。

### 7.2 创建 Stable Shot

```ts
interface CreatePendingShotRequest {
  pendingVersionId: string;
  requestId: string; // UUID v4，由客户端每次“新增镜头”动作生成并在重试中复用
  afterShotId: string | null;
  expectedPendingRowVersion: number;
  expectedChapterRowVersion: number;
  initial: Omit<StoryboardShotV2, "id" | "order">;
}
```

```ts
interface CreatePendingShotResponse {
  shotId: string;
  workingCopy: StoryboardWorkingCopyDto;
  replayed: boolean;
}
```

服务端 ID 算法：

```text
material = "g2-shot-v1\0" + projectId + "\0" + chapterId + "\0" + pendingVersionId + "\0" + requestId
shotId = "shot_" + lowerHex(sha256(utf8(material))).slice(0, 32)
```

- 同 requestId 重放得到同 ID；若同 ID 已在同一 pending document，返回当前文档。
- ID 已 retired 返回 `409 SHOT_ID_RETIRED`。
- 全量 PATCH 只接受：当前 Board 已知 Shot，或由本 pending 的 create-shot 命令建立且 scope 一致的 Shot。
- 客户端自行构造未知 ID 返回 `400 SHOT_ID_UNKNOWN`。
- 从 pending 删除、且从未进入任何 confirmed Board 的 Shot 可立即 retire；从 current Board 删除的 Shot只在新 Board confirm 时 retire。

### 9.2 Detail

```ts
interface VersionDetail<TDocument> {
  summary: VersionSummary;
  document: TDocument;
  source: SourceSnapshotV1 | null;
  isCurrent: boolean;
  isActivePending: boolean;
}
```

History detail 永远只读。copy-to-working-copy 请求携带 expected current/active pending/chapter rowVersion；已有 active pending 时不覆盖。Preflight 不提供 copy：它必须用当前 live source 重新 preview/confirm。

请求 DTO：

```ts
interface CopyScriptVersionToWorkingCopyRequest {
  expectedCurrentVersionId: string | null;
  expectedWorkingDigest: string;
  expectedChapterRowVersion: number;
}

interface CopyFormalVersionToWorkingCopyRequest {
  expectedCurrentVersionId: string | null;
  expectedActivePendingVersionId: null;
  expectedChapterRowVersion: number;
}
```

Script copy 只替换 Chapter Working Copy，不切 current。Story/Board copy 创建一个新 version number 的 pending，source 绑定复制时的当前上游，而不是沿用历史 source；历史 document 先通过当前 V2 codec 和 scope resolution，无法解析返回 `422 SOURCE_UNRESOLVED`。不得把历史 version 本身重新设为 current。

## 11. 旧路径兼容

### 11.1 读路径

旧 GET 路径可保留并投影 current/pending，但新增消费者必须用新 DTO；旧响应标记 deprecated。

### 11.2 写路径

| 旧路径 | file mode | g2_db mode |
| --- | --- | --- |
| `PATCH .../draft` | 保持旧行为 | `409 LEGACY_WRITE_ROUTE_DISABLED`，replacement=`.../script/working-copy` |
| `POST .../complete` | 保持旧行为 | `409 LEGACY_WRITE_ROUTE_DISABLED`，replacement=`.../script/publish` |
| `POST/DELETE .../source-pending` | 保持旧行为 | 禁止，指向 `.../script/pending-suggestion/*` |
| `POST/PATCH .../story-structure` | 保持旧行为 | 禁止，指向 Story Working Copy 路径 |
| `PATCH .../storyboard/pending`、旧 confirm/update | 保持旧行为 | 禁止，指向 Board Working Copy 路径 |
| 旧 preflight confirm | 保持旧行为 | 禁止，指向 V2 preview/confirm |

选择 fail-closed，不在 DB mode 为缺少 expected 字段的旧请求偷偷读取最新值后写入。Web 与 Server 的新路由必须同一发布单元切换。

## 13. 幂等总表

| 命令 | 首次提交证据 | 丢响应后的成功识别 |
| --- | --- | --- |
| Script PATCH | Chapter rowVersion+1 + requested digest | rowVersion=expected+1 且规范化字段完全相等 |
| Script clear/revert | working state/digest + rowVersion | 目标状态已达成且 current/expected 相等 |
| Script publish | 新 Script current + clean working | current.sourceDigest=expectedWorkingDigest，且 next chapter 已存在时复用 |
| Script pending adopt/discard | pending 删除 + working digest/无 pending | 目标 working 已达成或 pending 已不存在 |
| create pending | active pending pointer | pending 的 current/source/mode 目标相等 |
| update pending | pending rowVersion+1 + documentDigest | rowVersion=expected+1 且 digest 相等 |
| discard pending | archived row + pointer null | 同 version archived 且 pointer null |
| confirm pending | current pointer=pending ID | current ID/document/source digest 全相等 |
| create Shot | 确定性 shotId + pending doc | 同 requestId 派生 ID 已在同 pending |
| Preflight confirm | current revision source/document digest | 当前 revision 与请求快照完全相等 |
| task create | G1 idempotencyKey unique | 返回既有 task，不重算 mutable pointer |
| task complete | claimToken + target CAS + task terminal | terminal task 只读返回；不得再次写 target |

## 14. 安全上限

- Script sourceText：UTF-8 最大 2 MiB。
- Story/Storyboard/Preflight request body：最大 4 MiB。
- Story scenes/beats 各最大 500；Storyboard shots 最大 2000；单 shot characters 最大 64。
- History limit 最大 100。
- unknown field 一律拒绝；不得默默 strip 后成功。
