# G1 TaskPolicy 与 Outbox Handler 实施注册表

## 1. 权威边界

本文冻结 `TaskPolicyRegistryV1` 与 `OutboxHandlerRegistryV1`。两份注册表是 G1 M0-A machine manifest 的组成部分；`GenerationTask.type` 或 `OutboxEvent.eventType` 即使是 controlled-open string，也必须先在对应有效阶段注册，才允许创建 runtime 行或 claim。

优先级：

```text
生成任务协议与已采纳 G1～G5 业务契约
  -> 本注册表
    -> G1 machine manifest
      -> runtime registry / codec / worker / SQL guard / tests
```

本文件仍为 `in_progress`，直到 Pass 2 machine manifest 与两名 Scrutiny Review 签收。它不授权真实任务、真实文件、真实 SecretStore 或正式切换。

## 2. 通用执行语义

### 2.1 Codec 与严格解析

- 所有 codec 都拒绝未知字段、缺失必填字段、错误 nullability、非 I-JSON、绝对路径、credential/key/token/cookie 字段和未登记 schemaVersion。
- input/output/payload 在入库前 strict parse → normalize → RFC 8785 JCS → SHA-256；数据库保存 sibling schemaVersion/digest。
- `target.type` 只取 Shared 的 8 值；`GenerationTaskSource.sourceType` 只取 G1 source registry。两者不得互换。
- `maxAttempts` 表示总 attempt 数，不是“首次 + 重试次数”。因此 V1 的 `maxAttempts=3` 只有两次 retry delay，精确 `backoffSeconds=[5,30]`；`maxAttempts=2` 只有 `[5]`。最后一次 attempt 失败直接终态，不登记永远不会消费的 `120`。

### 2.2 Task 共用 claim/finalize

所有 enabled runtime policy 共用 G1 Schema 实施契约 10.1～10.4：

1. 先在同一事务确认 owner Project active；再把 unsealed Task、Sources 和 `input.sourceProjection` 同事务创建并 seal；policy/codec/target/source 任一不完整或 Project 已 deleting 即拒绝创建。
2. claim 由 Task 条件 UPDATE 原子建立 Attempt 与最低空闲 Slot；claimToken、owner、heartbeat、expiry 三表一致。
3. heartbeat、结果预写和 finish 都核对当前 claimToken；Attempt finish 是 Task 终结/重试和 Slot 释放的唯一入口。
4. queued/retrying 可直接取消；running 先写 cancelRequestedAt，worker 确认或 recovery 后才终态 cancelled。
5. terminal 不重开；用户重试创建新 runtime task。迟到 worker 只能登记脱敏诊断，不能写 current。
6. `idempotencyKey` 只在 Task 创建事务中由已冻结的 GenerationTask 标量字段和 strict `inputJson` 字段计算一次，随 Task 持久化；replay 直接使用已存 key，不重读 Chapter current/pending pointer 或其他可变业务行重算。

`replayPolicy` 值固定：

| 值 | lease 过期处理 |
| --- | --- |
| `deterministic_replay` | 先核验既有 staged/ready 产物和唯一约束，再以新 Attempt 重放 |
| `live_retry_only` | 仅当前 claim 明确收到 pre-submit、timeout/rate-limit 等 policy allowlist 错误时有限重试；未知中断 `WORKER_INTERRUPTED + needsReview` |
| `manual_review` | 不自动再次调用外部 provider；终态 failed/needsReview |

### 2.3 Registry 穷尽性

Shared `GENERATION_TASK_TYPES` 的 10 个值必须与本表逐项相等。`availability=reserved_*` 仍必须有完整 codec/target/source/idempotency/replay 契约，但 runtime create 固定返回 `TASK_POLICY_NOT_ENABLED`；对应阶段 overlay 启用前不得因“已有枚举”绕过。

## 4. OutboxHandlerRegistryV1

### 4.1 共用 claim/fencing

- 所有 intent 与所属领域状态在同一 DB 事务插入，INSERT 固定 pending/attempt=0/maxAttempts=3。
- claim 固定 lease=60 秒、heartbeat=15 秒；pending→processing 恰好 attempt+1并写 UUID v4 token。
- 外部动作不在 DB 事务内；完成/retry/fail 的 UPDATE 必须 `status=processing AND leaseToken=<claimToken>`。
- 过期 recovery 先以 OLD token CAS 回 pending，并按 `[5,30]` 秒安排 availableAt；随后新 claim 增 attempt。到第 3 次只能 processed 或 failed。
- replay 前必须执行 handler 的 postcondition probe；已经满足完成条件时不得重复破坏性副作用，直接进入 fenced completion。
- payload codec strict、拒绝 unknown、绝对路径和 secret 字段；payloadDigest/idempotencyKey 从 normalized payload 计算，intent 字段永久不可变。

### 4.3 Payload nullability 与 unknown-field 规则

- `asset.promote/delete` 的 `chapterId` 是唯一 nullable owner 字段；其他列非空。
- `expectedSha256/sha256` 必须是完整 `sha256:*`；`bytes` 为正整数。
- storageKey 全部是 `/` 分隔的相对受控 key；codec 和 canonical path guard 双重验证。
- `oldSecretRef` 必须符合 `airoaming:image:v1:<uuid-v4>`；`expectedFingerprint` 是完整 sha256。payload 的 key 名和值都执行 credential sentinel 扫描。
- 五个 codec 的允许 key 集精确等于表中对象字段；unknown key、重复键、缺字段、显式 `undefined`、额外 null 一律拒绝。

## 5. 与 SQL 状态机的关系

本注册表不允许 handler 绕过 G1 Schema trigger：

- Outbox pending/processing/processed/failed 状态、attempt、lease 和 terminal 不可变以数据库为最后防线。
- handler registry 负责 SQL 无法证明的 payload 语义、外部 postcondition、canonical path/SecretStore 与幂等检查。
- `processed` 只表示该 event 的外部 postcondition 已验证；它不自动删除 Asset/Project/CredentialMetadata。后续领域事务仍需自己的 FK、purge 或 clear guard。
- machine manifest 必须同时包含本表结构化 registry、Outbox trigger 的 timing/event/WHEN/body 和五类 payload golden/unknown-field 用例。

## 6. 退出条件

1. Shared 10 类 task 与 TaskPolicy registry 精确相等；缺项/多项/重复项失败。
2. enabled/reserved create gate、codec、source seal、target 与 stage overlay 均有机械测试。
3. 五类 Outbox event 与 handler registry 精确相等；未知 event 不可 claim。
4. 每类 handler 至少有“首次成功、响应丢失重放、lease 过期接管、第三次失败、payload unknown/secret/path 负例”。
5. Task/Outbox registry 已进入 G1 machine manifest canonical hash，并通过两名只读审查。
