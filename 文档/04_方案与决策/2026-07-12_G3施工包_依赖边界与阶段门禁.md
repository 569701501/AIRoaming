# G3 施工包：依赖边界与阶段门禁

## 1. 文档定位

本文冻结 G3 在 2026-07-12 当前仓库上的真实前置、阶段顺序、允许改动面、阻塞条件与完成名称。Luna 开工前先读本文；不能因为 G1 Schema 已存在 `Project.comicFormat` 和 `MigrationIssue`，就把 maintenance importer、备份恢复或 DB-only 切换当作已实现。

优先级：

```text
ADR-0009 产品决策
  -> 本施工包五份资料
    -> G3 主方案与契约字典
      -> 当前代码实现
```

若旧 G3 文档把 importer/DB-only 写成已完成前提，以本文的阶段门禁为准；产品两值与创建后不可变的决策不变。

## 2. 状态词

| 状态 | 含义 |
| --- | --- |
| `ready` | 当前代码已有，可直接依赖且必须复用 |
| `slice_owned` | 当前 G3-core 切片负责实现，退出时必须完成 |
| `integration_blocked` | 可开发接口或纯逻辑，但相关集成证据当前不能宣称通过 |
| `release_blocked` | 不阻止临时库/临时 workspace 开发，阻止真实 workspace 发布 |
| `deferred` | 不属于 G3-core，禁止顺手实现 |

## 3. 交付名称

G3 不再用一个“全部完成”名称掩盖 importer 缺口：

| 名称 | 范围 | 当前可否施工 |
| --- | --- | --- |
| `G3-core` | Shared 两值、0010、Create/PATCH 保护、file 兼容读取、现有弹窗、只读展示、G2 下游适配 | 可以 |
| `G3-M` | G1 maintenance importer 中的 MigrationIssue、人工决议、备份恢复、final import、DB-only activate | `integration_blocked` |
| `G3 production-ready` | G3-core + G3-M + 真实 workspace dry-run/用户复核 | `release_blocked` |

完成记录必须写 `G3-core completed` 或具体切片名；在 G3-M 未完成前不得写“G3 全部完成”或“已完成生产切换”。

## 4. 当前基线

### 4.1 已存在且必须复用

| 能力 | 状态 | G3 使用方式 |
| --- | --- | --- |
| 现有项目库、创建按钮、`CreateProjectModal.vue`、成功导航 | `ready` | 只扩展同一表单和同一路由 |
| Shared/Server/Web 三包与 G0 Vitest/Playwright harness | `ready` | 扩展现有测试，不建第二套 runner |
| Prisma 6.19.3、Project 两值 CHECK、0001～0009 migration tree | `ready` | 只追加固定 0010，不改 0008/0009 |
| DB mode Project + 默认 Chapter 同事务创建 | `ready` | 删除旧 alias 双向转换后复用 |
| G2 Preflight V2、SourceSnapshot、persistent task runtime | `ready` | G3 必须更新真实消费点，不复制任务链 |
| file mode workspace 项目读写 | `ready` | 只在 repository 边界增加显式 legacy read adapter |
| `ApiEnvelope/ApiErrorEnvelope` Shared 类型 | `ready` | G3 错误返回稳定 envelope；Web 保留 code/details |

### 4.2 尚未实现

| 能力 | 状态 | 对 G3 的影响 |
| --- | --- | --- |
| G1 maintenance importer/decision runner | 未实现 | G3-M 阻塞；G3-core 不复制 importer |
| 协调备份/恢复与 DB-only activate | 未实现 | 真实发布阻塞，不阻止临时根开发 |
| 通用 DB Project metadata PATCH | 未实现 | G3 不扩容；只保证带 comicFormat 的请求先 409 |
| file legacy ambiguity 的用户决议 UI | 未实现 | `four_panel/缺失/非法` fail-closed，rollout inventory 必须为 0 |
| G5 PageProfile/LayoutPreset | 未实现 | G3 只保留版本化尺寸与 legacy layout adapter |

## 5. 冻结裁决

### 5.1 Runtime 与 file compatibility 分层

- HTTP Create、DB Project、新 Preflight、新 Task、API output 只允许 canonical 两值。
- file repository 可以读取 canonical 与 `page_horizontal`；后者只在内存映射为 `paged_comic`，原文件保持不变。
- `four_panel/缺失/非法` 不猜测，不默认 vertical；必须形成稳定 decision-required 错误。
- file adapter 与 G1 importer mapper 是两个名字、两个模块、两个用途，禁止共用含糊的 `normalizeComicFormat`。

### 5.2 数据库追加 0010

- migration 名固定 `0010_g3_comic_format_immutable`。
- 只新增 `trg_g3_projects_comic_format_immutable`。
- G3-core 激活后，`PrismaService` 精确校验 0001～0010 的 artifact 与 ledger。
- 不修改 G1 manifest 的 44/556/195/194 基线计数；G3 trigger 由独立 overlay contract 验证。

### 5.3 DB PATCH 不扩容

- PATCH body 自有属性含 `comicFormat`：file/db 均 `409 COMIC_FORMAT_IMMUTABLE`。
- PATCH 不含该字段：file 保持旧行为；db 保持既有 unsupported 行为。
- G3 不新增通用 Project metadata repository，仅为未来底层误写提供 trigger。

### 5.4 图片尺寸版本分词

- 图片尺寸版本只叫 `sizePolicyVersion`。
- G2 来源投影仍叫 `policyVersion`，固定 `g2-task-source-v1`。
- 两者不可互换，也不可只保留一个模糊 `policyVersion` 字段。

## 7. 顺序与并行边界

允许并行：

- `G3-A0` 与 `G3-A1`。
- `G3-C0` 的静态表单开发与 `G3-B1/B2`，前提是 A0/B0 DTO 和错误码已冻结。
- DB contract tests 与 file compatibility unit tests。

必须串行：

```text
G3-A0
  -> G3-B0
    -> G3-B1 / G3-B2
      -> G3-C0 / G3-C1 / G3-D0
        -> G3-E0

G3-A1 -> G3-B1 -> G3-E0
```

理由：枚举翻转会同时影响三包 exhaustive 分支；不允许在主分支长期留下“Shared 已两值、Server/Web 仍三值”的不可编译状态。A0 合并单元必须包含所有编译修复，或使用一条原子提交完成。

## 8. 开发门与发布门

### 8.1 Luna 本地开发门

满足以下条件即可施工 G3-core：

1. 使用临时 workspace、临时 SQLite 和假 provider；不读取真实项目。
2. fresh deploy 0001～0010；不得在应用启动时自动 migrate。
3. file legacy 测试只使用 fixture 根。
4. 每个切片只改施工包列出的文件并执行最小测试。
5. 发现真实代码与文档不一致时停在当前切片，更新 findings，不自行扩大范围。

### 8.2 真实 workspace 发布门

同时满足以下条件前，G3-core 不能对真实 workspace 宣称 production-ready：

- 只读 `g3:comic-format:audit` 对目标 workspace 返回 `decisionRequired=0`。
- 0001～0010 在脱敏数据库副本 fresh/replay 均通过。
- 旧构建回滚策略确认理解 `paged_comic`，不存在静默回退版本。
- G3-core Runtime/User Review 通过。
- 若存在四格、缺失或非法旧值，必须等待 G3-M/G1 importer 决议；不能手改或默认 vertical。

## 9. Stop condition

出现任一情况立即停止当前切片并记录：

- 需要修改 0008/0009 已应用 SQL 才能继续。
- 需要新业务表、新 Project 字段或第 45 个模型。
- 需要默认把 `four_panel/缺失/非法` 变成任一 canonical 值。
- 需要运行时改写旧 task/layout digest。
- 需要让 Web 自行推断 canonical 或错误码。
- 需要为通过 G3 测试实现完整 importer、备份恢复、Outbox 或 G5 LayoutDocument。
- 测试命令会访问真实 workspace、真实数据库或真实 key。

## 10. Luna 单切片任务书格式

每次只交一个切片，任务书必须包含：

```text
目标切片：G3-xx
当前 commit：<sha>
必读资料：五份 G3 施工包 + 对应主方案章节
允许修改文件：精确列表
明确禁止：相邻切片/G3-M/G5
最小测试：精确命令
退出证据：文件、测试结果、残留 blocker
```

禁止使用：

```text
按照 G3 文档全部做完。
缺什么自己补什么。
把所有旧数据自动兼容掉。
```

## 11. 完成判定

`G3-core completed` 必须满足：

- A0～E0 全部通过。
- 新 runtime/API/DB/新 task 只有 canonical 值。
- file alias 仅出现在明确 legacy allowlist，ambiguity 不静默。
- 0010 artifact、inspection、ledger、startup guard 全通过。
- 两种版式从现有弹窗创建、重启保持、只读展示正确。
- Scrutiny Review 与临时环境 Runtime/User Review 通过。

`G3 production-ready` 还必须满足 G3-M 和真实 workspace 发布门；不能用 G3-core 的绿色测试替代。
