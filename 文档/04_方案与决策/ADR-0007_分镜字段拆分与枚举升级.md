## 1. 状态

已采纳。

## 2. 背景

分镜 `StoryboardShot` 原有的 `comic` 和 `motion` 字段存在三类问题（详见 `文档/05_执行与记录/任务记录/2026-06-21_分镜字段完整性调研/findings.md`）：

### 2.1 信息揉合（没拆干净）

- `comic.composition` 和 `motion.compositionDesign` 把**景别**（中景/特写）、**机位角度**（平视/俯仰）、**构图**（人物位置）三个独立维度揉在一段自由文本里。AI 要自己拆解，抓不准；下游出图/视频也无法分别控制。
- `motion.durationHint`（"2.5s"）是字符串，数值和展示混在一起，程序算不了时间线。
- `motion.voiceRole` + `motion.line` 只能记**一个人的一句**台词，无法表达一个镜头里多人对话；且用名字不用 characterId，与 ADR-0006 的 projectCharacterId 思路冲突。

### 2.2 自由文本不稳定

`comic.panelRhythm`、`motion.cameraMovement`、`motion.frameType` 三个字段语义本质是固定选项，却用自由文本存储。AI 每次写法不同（"慢节奏"/"慢节奏留白"/"缓慢"），下游无法稳定识别、统计、筛选。

### 2.3 镜头语言维度缺失

业界分镜标准（影视 shot list、webtoon、motion comic）普遍把景别、机位角度作为独立维度。项目原结构没有这两个独立字段。

## 3. 决策

### 3.1 景别和机位提到共同核心层

新增 `shotType`（景别）和 `cameraAngle`（机位角度）到 `StoryboardShot` 顶层，comic 和 motion **共用一份**。

理由：M1 当前使用一个 `Shot` 同时承载一个漫画画格表达和一个基础漫剧镜头表达，景别和机位作为共享骨架的兼容字段只存一份。这样可以在尚未落地独立漫剧生产链时控制字段和页面复杂度。未来若打破一一对应（一格拆多镜头、多个画格合成一镜或两轨需要不同景别/机位），再让两条轨道分别拥有镜头序列和镜头语言字段。

#### 2026-07-16 语义澄清

M1 的共同 `Shot` 只是存储和页面兼容方案，不代表漫画分镜与漫剧分镜存在主从关系：

- 漫画分镜独立设计静态决定性瞬间、画格构图、阅读顺序、气泡/旁白和格间节奏。
- 漫剧分镜独立设计时间过程、人物表演、镜头运动、时长、配音和动态镜头衔接。
- 两者只共享正式剧情事实并且不得互相矛盾；漫剧不是漫画画格的“动态投影”。
- 当前共用 `shotType`、`cameraAngle` 和数量是 M1 已知限制，不应写成长期领域规则。

### 3.2 三个自由文本字段升枚举

| 字段 | 枚举值 |
| --- | --- |
| `comic.panelRhythm` | slow / normal / fast / impact / transition |
| `motion.cameraMovement` | static / push_in / pull_out / pan_left / pan_right / tilt_up / tilt_down / track_left / track_right / slow_zoom / handheld / none |
| `motion.frameType` | atmosphere / dialogue / action / reaction / detail / transition |

枚举值参考业界标准（StudioBinder、Boords、Clip Studio 等）并精简到 AI 漫画/漫剧生产够用。

### 3.3 durationMs 拆出，voiceLines 替换

- `motion.durationMs: number`（毫秒，给程序算时间线）+ 保留 `motion.durationHint: string`（展示文本）。
- 删除 `motion.voiceRole` + `motion.line`，新增 `motion.voiceLines: StoryboardShotVoiceLine[]`。每条含 `characterId`（与 ADR-0006 对齐）/ `name` / `line` / `voiceStyle`，支持一个镜头多人对话。

### 3.4 枚举兜底逻辑抽到 shared 包

新增 `packages/shared/src/storyboard-normalize.ts`，导出枚举校验 + 默认值兜底函数。两份 normalize（`projects.service.ts` 严格版、`dialogue.service.ts` 宽松版）共用，杜绝 schema 漂移。枚举定义和兜底规则只在一处维护。

### 3.5 兼容策略：normalize 读时兜底，不写迁移脚本

旧 `storyboard.json`（无新字段 / 自由文本 / 旧 voiceRole+line）重读时由 normalize 兜底：

| 情况 | 兜底 |
| --- | --- |
| shotType/cameraAngle 缺失或非法 | 默认 medium / eye_level |
| panelRhythm/cameraMovement/frameType 不在枚举 | 默认 normal / static / atmosphere |
| durationMs 缺失 | 从 durationHint 解析，失败默认 2500 |
| 旧 voiceRole+line | 自动转成 `[{characterId:null, name:voiceRole, line, voiceStyle:""}]` |

当前 workspace 只有 pending 数据，无正式 storyboard.json，重生成即新格式，无需迁移脚本。

### 3.6 前端：修复编译错误，UI 布局不动

前端本次不重构 UI，但必须能编译。3 处旧字段引用最小修复：
- `StoryboardWorkspace.vue`：voiceRole/line 两行编辑框改为只读展示 voiceLines 第一条（布局不变，编辑能力暂失）。
- `ProjectDialoguePanel.vue`：本地类型声明改为导入真实 `StoryboardJson`。
- `createEmptyShot` 新增模板改为新结构（枚举默认值与后端一致）。

完整 UI 重构（shotType/cameraAngle 下拉、voiceLines 列表编辑器、枚举改下拉选择）单独立项，不在本次范围。

## 4. 被否决的备选

### 4.1 否决：GPT 清单全盘照收

GPT 给的字段清单把 comic 扩到 17 个、motion 扩到 21 个（含 panelShape/characterPlacement/backgroundRole/textPlacement/emptySpaceHint/sfx/continuityHint/forbid × 2 + motion 的 8 个特效字段）。否决原因：严重过度设计，下游还没接上，塞进去全是死字段；且 GPT 不知道项目已有共同核心，另造 `shotBasis` 制造概念冲突。只采纳其中"该拆该升"的核心子集。

### 4.2 否决：shotType/cameraAngle 在 comic 和 motion 各存一份

GPT 清单在 comic 和 motion 各放一份 shotType/cameraAngle。否决原因：M1 页面和存储仍采用共享 Shot 骨架，在真实漫剧生产尚未验证需要独立序列前，各存一份会增加未被消费的字段和一致性处理成本。共同核心层是当前兼容取舍，不表示两种媒介长期必然使用相同镜头语言。

### 4.3 否决：保留 voiceRole/line 与 voiceLines 并存

否决原因：两套并行会让"台词真相源"分裂，未来还要再清。一次性替换干净，旧数据靠 normalize 兜底。

### 4.4 否决：写一次性迁移脚本

否决原因：当前无正式 storyboard.json 数据（只有 pending），重生成即新格式。normalize 兜底已足够，写脚本增加风险无收益。

### 4.5 否决：前端一并做 UI 重构

否决原因：本次范围聚焦字段结构。UI 重构（下拉组件、列表编辑器）工作量等于后端，且枚举值刚定，先让数据跑起来验证枚举是否够用，再投入 UI。用户已选"UI 布局不动"。

## 5. 已知限制

- **前端展示已落地（2026-06-21）**：枚举字段（shotType/cameraAngle/panelRhythm/cameraMovement/frameType）已改为中文下拉；durationMs 用数字输入；voiceLines 改为只读列表展示。详见 `文档/05_执行与记录/功能完成记录/2026-06-21_分镜字段前端展示.md`。
- **voiceLines 仍只读**：本次只展示不编辑，用户不能在前端增删改配音台词。如需编辑能力，后续做列表编辑器。
- **旧自由文本语义丢失**：旧数据 panelRhythm="慢节奏留白" 不在枚举内，normalize 归为 normal，原语义丢失（测试数据，已确认接受）。
- **下游仍未消费**：shot_prompt_generate / layout_export / tts / video 的消费逻辑未落地，本次只改字段结构 + normalize + prompt。字段是否"够用"的最终验证依赖下游实现。
- **M1 双轨表达仍共享镜头骨架**：`comic` 和 `motion` 内容字段已分开，但镜头数量、order、beat/scene/character、shotType 和 cameraAngle 仍共用。Prompt 必须分别生成漫画与漫剧表达，不能把 motion 降级为 comic 的附属说明；若真实漫剧链路证明需要独立拆镜，应升级数据契约而不是继续强行一一对应。

## 7. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 两份 normalize 漂移 | 枚举兜底抽到 shared 包，两份共用 |
| 旧自由文本丢失语义 | 已确认接受（测试数据） |
| 前端编辑能力缺失 | 已记录为已知限制，UI 重构单独立项 |
| 枚举值不够用 | 枚举是开放扩展的，发现不够可补值；兜底逻辑用 include 判断，补值无需改 normalize |
| AI 不遵守枚举约束 | prompt 已列全枚举清单 + normalize 兜底双重保险 |

回滚：删除新增字段与枚举类型，normalize 恢复旧逻辑，前端恢复旧字段引用。已落盘的 storyboard.json 多出的字段会被旧 normalize 忽略，不影响读取。
