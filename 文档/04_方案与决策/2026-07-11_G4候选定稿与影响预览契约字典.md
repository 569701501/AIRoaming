# G4 候选定稿与影响预览契约字典

## 1. 用途与优先级

本文是 G4 实施时可直接用于 Shared types、runtime parser、Service、SQLite migration、fixture 和测试的精确契约。

优先级：

```text
ADR-0010 产品/架构决策
  -> 本契约字典
    -> G4 主方案
      -> 代码、Schema、测试与 UI
```

本文对 G1 进行两项字段级细化，不新增领域模型：

1. `CandidateLockRevision.previousRevisionId` 增加非空唯一和线性链约束。
2. `ExportRevision.applicability` 实施时命名为 `completionApplicability`，明确它是完成登记时的不可变结论；当前 freshness 仍查询派生。

## 2. 术语字典

| 用户语言 | 代码名 | 精确含义 |
| --- | --- | --- |
| 候选图 | `Candidate` | 一次生成任务的一张不可覆盖结果 |
| 收藏 | `favoriteAt` | 非权威挑选偏好，可多选 |
| 废弃 | `Candidate.status=rejected` | 不再作为新定稿目标，不删图/历史 |
| 当前定稿 | `CurrentCandidateDecision(finalized)` | Shot 当前修订指向的 Candidate |
| 定稿此图 | `action=lock` | unset/cleared 状态下建立新定稿 |
| 更换为定稿图 | `action=replace` | finalized 状态下选另一 Candidate |
| 取消定稿 | `action=clear` | 保留事件，当前无下游候选 |
| 来源已更新 | `BindingSourceResolution=stale` | 布局仍引用可识别的旧定稿修订 |
| 来源无法确认 | `BindingSourceResolution=unresolved` | 关系缺失/断裂，不得猜测 |
| 影响预览 | `CandidateLockImpactPreview` | 提交前查询当前会新变 stale 的下游引用 |
| 历史导出 | historical ExportRevision | 文件仍可查看/下载，但不代表当前定稿 |

禁止同义混用：

- “收藏”不叫 selected。
- “当前定稿”不叫 Candidate.locked status。
- `lockedCandidateId` 不是新模型的可写字段。
- historical 表示版本位置/任务适用性，stale 表示来源已变，两者不是同一轴。

### 4.1 Candidate

不可变字段：Project/Chapter/Shot/Task/Asset 归属、index、prompt/generation spec 和生成产物。允许变更：status、favoriteAt、label/notes/score、updatedAt。

### 4.2 CandidateLockRevision

```ts
interface CandidateLockRevisionRecord {
  id: string;
  projectId: string;
  chapterId: string;
  shotId: string;
  revision: number;
  action: CandidateLockAction;
  candidateId: string | null;
  previousRevisionId: string | null;
  origin: CandidateLockOrigin;
  reason: string | null;
  decidedAt: string | null;
  recordedAt: string;
}

export type CandidateLockRevisionDto = CandidateLockRevisionRecord;
```

数据库约束：

| 约束 | 要求 |
| --- | --- |
| PK | `id` |
| unique | `(shotId, revision)` |
| unique | `previousRevisionId` 非空时全表唯一 |
| index | `(projectId, chapterId, shotId, revision DESC)` |
| index | `candidateId` |
| scope | candidate/previous/current 必须属于同 Project/Chapter/Shot |
| current parent | runtime 插入时 previous 必须等于 Shot 插入前的 current；首次 lock 要求 Shot current 为空 |
| nullability | lock/replace 的 candidateId 非空；clear 的 candidateId 为空 |
| time | runtime 的 decidedAt 非空；legacy_import 可空；recordedAt 始终非空 |
| immutable | INSERT 后 UPDATE/DELETE 由 trigger 拒绝 |

链规则：

```text
previous=null
  -> revision=1
  -> action=lock
  -> Shot.currentCandidateLockRevisionId=null

previous.action=clear
  -> revision=previous.revision+1
  -> action=lock
  -> previous.id == Shot.currentCandidateLockRevisionId

previous.action in (lock, replace)
  -> revision=previous.revision+1
  -> action in (replace, clear)
  -> previous.id == Shot.currentCandidateLockRevisionId

action=replace
  -> candidateId != previous.candidateId
```

runtime 的合法性先由 Service 给出可读错误，SQLite trigger 只作防线，不把 trigger 原始文本直接回给用户。

### 4.3 Shot 当前指针

```ts
interface ShotCandidateDecisionFields {
  currentCandidateLockRevisionId: string | null;
}
```

- 指针必须指向同 Shot 修订。
- 指向 clear 是合法状态，不能自动置 null。
- 修订插入与指针切换同事务。
- 旧 `lockedCandidateId` 若在迁移过渡 DTO 中短暂存在，只能从当前修订派生，不接受写入。G4 退出前正式 DTO 删除它。

## 5. 意图与状态机

### 5.1 HTTP 意图类型

```ts
export type CandidateLockIntent =
  | {
      action: "lock" | "replace";
      candidateId: string;
    }
  | {
      action: "clear";
      candidateId?: never;
    };
```

JSON 规则：

- lock/replace 必须有非空 candidateId。
- clear 必须省略 candidateId；显式 `null`、空字符或任意值均拒绝。
- 进入 digest 前，clear 的 `targetCandidateId` 规范化为 null。
- ID 不 trim 成另一个值；空/纯空白拒绝，前后有空白也视为非法 ID。

### 5.2 纯函数状态机

```ts
interface CandidateLockTransition {
  kind: "create" | "no_op";
  action: CandidateLockAction;
  candidateId: string | null;
}

function resolveCandidateLockTransition(
  current: CurrentCandidateDecision,
  intent: CandidateLockIntent,
): CandidateLockTransition;
```

| current.state | intent | 结果 |
| --- | --- | --- |
| unset | lock(A) | create lock(A) |
| unset | replace/clear | ACTION_INVALID |
| finalized(A) | replace(B) | create replace(B) |
| finalized(A) | replace(A) | no_op |
| finalized | clear | create clear |
| finalized | lock | ACTION_INVALID（精确 replay 在此函数前识别） |
| cleared | lock(A) | create lock(A) |
| cleared | clear | no_op |
| cleared | replace | ACTION_INVALID |

## 7. Lock set 契约

### 7.1 响应

```ts
export interface CandidateLockSetEntry {
  shotId: string;
  candidateLockRevisionId: string;
  candidateId: string;
}

export interface CandidateLockSetSummary {
  schemaVersion: 1;
  projectId: string;
  chapterId: string;
  storyboardVersionId: string;
  state: CandidateLockSetState;
  sourceApplicability: TaskApplicability;
  entries: CandidateLockSetEntry[];
  missingShotIds: string[];
  clearedShotIds: string[];
  unresolvedShotIds: string[];
  digest: string | null;
}
```

- `entries` 只包含可完整解析的 finalized Shot。
- 所有 ID 数组字典序且不重复。
- `state=complete` 时三个异常数组都为空，digest 非空。
- `incomplete` 仅表示 unset/clear；任何断链升级为 unresolved。
- `sourceApplicability` 与结构 state 正交；只对 complete lock set 聚合，incomplete/unresolved 时为 null。上游更新后可出现 `state=complete + sourceApplicability=historical`。legacy 直接定稿证据可形成结构 complete，但来源不可证明时为 `legacy_unresolved`。
- 新正式 LayoutRevision 的门禁是 `state=complete && sourceApplicability=current`。

### 7.2 Digest input

Candidate ID 只用于响应/完整性核对，不进入 digest：

```ts
interface CandidateLockSetDigestEntryV1 {
  shotId: string;
  candidateLockRevisionId: string;
}
```

算法：

```text
entries = active shots 的 finalized 条目
assert state == complete
sort entries by shotId ASC (Unicode code point order)
bytes = UTF-8(RFC8785_JCS(entries))
digest = "sha256:" + lowercaseHex(SHA-256(bytes))
```

不包含 `schemaVersion`、project/chapter/storyboard ID、Candidate ID、order 或时间；作用域通过持有该 digest 的 Layout/Task 字段另行约束。

## 9. Commit 契约

### 9.1 Request

```ts
export type CommitCandidateLockRequest = CandidateLockIntent & {
  expectedCurrentRevisionId: string | null;
  impactDigest: string;
  reason?: string;
};
```

上述 TypeScript 的交叉仅表意；实际 Shared 实现应保持 lock/replace/clear 的 discriminated union，不让 clear 意外接受 candidateId。

replace：

```json
{
  "action": "replace",
  "candidateId": "candidate_B",
  "expectedCurrentRevisionId": "lockrev_001",
  "impactDigest": "sha256:<64-lowercase-hex>",
  "reason": "选择了构图更稳定的候选"
}
```

首次 lock：

```json
{
  "action": "lock",
  "candidateId": "candidate_A",
  "expectedCurrentRevisionId": null,
  "impactDigest": "sha256:<64-lowercase-hex>"
}
```

clear：

```json
{
  "action": "clear",
  "expectedCurrentRevisionId": "lockrev_002",
  "impactDigest": "sha256:<64-lowercase-hex>"
}
```

`expectedCurrentRevisionId` 属性必须存在；首次 lock 使用 null。省略字段不等于 null，返回 `EXPECTED_CURRENT_REVISION_REQUIRED`。

### 9.2 Response

```ts
export interface CandidateLockCommitResponse {
  schemaVersion: 1;
  result: CandidateLockCommitResult;
  revision: CandidateLockRevisionDto;
  currentDecision: CurrentCandidateDecision;
  shot: WorkbenchShotV2;
  candidatesForShot: WorkbenchCandidateV2[];
  candidateLockSet: CandidateLockSetSummary;
  productionState: ChapterProductionState;
  committedImpact: CandidateLockImpactDetails;
}
```

- `created`：revision 是新行。
- `replayed`：revision 是已存在且精确匹配的行。
- `no_op`：revision 是当前修订；unset 下不存在合法 no-op，因此响应 revision 始终非空。
- 响应内的 workflow/shot/candidates 必须在事务提交后从 Server 重新查询，不复用请求前的内存对象。

### 9.3 Replay predicate

```ts
function isExactCandidateLockReplay(
  current: CandidateLockRevisionRecord | null,
  request: CommitCandidateLockRequest,
): boolean {
  if (!current) return false;
  return current.previousRevisionId === request.expectedCurrentRevisionId
    && current.action === request.action
    && current.candidateId === normalizeTargetCandidateId(request);
}
```

识别顺序必须在 expected conflict 之前。精确 replay 不重算/比较旧 impactDigest；因为权威修订已证明同一意图成功。

### 9.4 No-op

```text
current=finalized(A) + replace(A) + expected=current.id -> no_op
current=cleared + clear + expected=current.id          -> no_op
```

no-op 不插入修订、不更新 Shot/Chapter、不更新 updatedAt、不取消任务。

## 10. 影响分析查询

### 10.1 Working Copy

Projector 输出：

```ts
interface WorkingCopyCandidateBindingProjection {
  workingCopyId: string;
  documentDigest: string;
  elementId: string;
  shotId: string | null;
  candidateId: string | null;
  sourceCandidateLockRevisionId: string | null;
  resolution: BindingSourceResolution;
}
```

只有 `shotId=request.shotId` 且 `sourceCandidateLockRevisionId=expectedCurrentRevisionId` 的元素进 `affectedWorkingCopyElements`。已 stale/unresolved 只进展示数量。

### 10.2 Formal Layout

索引建议：

```text
LayoutSourceBinding(shotId, candidateLockRevisionId, layoutRevisionId)
ExportRevision(layoutRevisionId, status)
```

查询只匹配 `candidateLockRevisionId=expectedCurrentRevisionId`。正式布局的一个 element 可有多个 role binding；impact 对 `(layoutRevisionId, elementId)` 去重，不因 role 数重复计数。

### 10.3 Export

`affectedExportRevisionIds` 包含所有指向受影响 LayoutRevision 的 ExportRevision，包括既有 current pointer 所指和历史行。任何行都不被改写。

### 10.4 Active Task

active status 精确为：

```text
queued | running | retrying
```

当 GenerationTaskSource 满足任一条件时进入影响集：

- `sourceType=candidate_lock_revision && sourceId=expectedCurrentRevisionId`
- `sourceType=lock_set && sourceDigest=currentCompleteLockSetDigest`
- `sourceType=layout_revision && sourceId in affectedLayoutRevisionIds`
- `sourceType=export_revision && sourceId in affectedExportRevisionIds`

`image_generate` 不因它的 target Shot 相同而被纳入；它依赖 Preflight，不依赖 lock。

## 11. 收藏与废弃 API

### 11.1 Favorite

```text
PUT    /api/projects/{projectId}/chapters/{chapterId}/candidates/{candidateId}/favorite
DELETE /api/projects/{projectId}/chapters/{chapterId}/candidates/{candidateId}/favorite
```

- PUT 已收藏、DELETE 已取消都幂等。
- 响应 `{candidate: WorkbenchCandidateV2}`。
- 不创建 CandidateLockRevision，不更新 Shot/Chapter/Layout/Export/Task。
- 收藏时间由 Server 生成，客户端不传 timestamp。

### 11.2 Rejection

```text
PUT    /api/projects/{projectId}/chapters/{chapterId}/candidates/{candidateId}/rejection
DELETE /api/projects/{projectId}/chapters/{chapterId}/candidates/{candidateId}/rejection
```

- PUT：`generated -> rejected`，同事务清 `favoriteAt`。
- DELETE：`rejected -> generated`，不恢复 favoriteAt。
- 当前定稿 Candidate 的 PUT 返回 409 `CANDIDATE_IS_CURRENT_FINAL`。
- `superseded` 的 PUT/DELETE 返回 409 `CANDIDATE_STATUS_TRANSITION_INVALID`。
- 已经被历史 lock/layout/export 引用的非当前 Candidate 可以 rejected；Asset 和历史引用不删除。

```ts
  | "SOURCE_LOCK_CHANGED"
  | "LOCK_SET_DIGEST_MISMATCH";
```

## 16. 事务伪代码

```ts
async function commitCandidateLock(
  scope: { projectId: string; chapterId: string; shotId: string },
  raw: unknown,
): Promise<CandidateLockCommitResponse> {
  const request = parseCommitCandidateLockRequest(raw);

  const outcome = await db.writeTransaction(async (tx) => {
    const context = await repository.readDecisionContext(tx, scope);

    if (isExactCandidateLockReplay(context.currentRevision, request)) {
      return { kind: "replayed", revision: context.currentRevision };
    }

    assertExpectedRevision(context.currentRevision, request.expectedCurrentRevisionId);
    const transition = resolveCandidateLockTransition(context.currentDecision, request);

    if (transition.kind === "no_op") {
      return { kind: "no_op", revision: context.currentRevision };
    }

    await newWorkGate.assertCandidateDecisionAllowed(tx, context);
    await candidatePolicy.assertLockable(tx, scope, transition.candidateId);

    const impact = await impactAnalyzer.analyze(tx, context, transition);
    assertImpactDigest(impact, request.impactDigest);

    const revision = await repository.insertNextRevision(tx, {
      ...scope,
      transition,
      previousRevisionId: context.currentRevision?.id ?? null,
      previousRevision: context.currentRevision?.revision ?? 0,
      reason: normalizeReason(request.reason),
    });

    const changed = await repository.compareAndSetCurrentRevision(
      tx,
      scope.shotId,
      request.expectedCurrentRevisionId,
      revision.id,
    );
    if (!changed) throw new RevisionConflict();

    return { kind: "created", revision, impact };
  });

  if (outcome.kind === "created") {
    void taskCancellation.requestAffected(outcome.impact.activeTaskIds);
  }
  return queryAuthoritativeCommitResponse(scope, outcome);
}
```

`no_op` 在当前 expected 匹配时可直接返回；它没有“本次会发生的影响”。`replayed` 必须在 expected conflict 前判定。

## 17. 迁移字典

### 17.1 Candidate/Shot

| 输入证据 | 目标 | issue |
| --- | --- | --- |
| Shot.lockedCandidateId 指同 Shot Candidate + ready Asset | legacy v1 lock + Shot current | info |
| lockedCandidateId 指向不存在 Candidate | 不建 revision | blocker `LOCKED_CANDIDATE_MISSING` |
| Candidate 属其他 Shot/Chapter/Project | 不建 revision | blocker `LOCKED_CANDIDATE_SCOPE_MISMATCH` |
| Candidate Asset 缺失/不可读 | 不建 revision | blocker `LOCKED_CANDIDATE_ASSET_UNRESOLVED` |
| 只有一个 Candidate.status=locked，Shot 无指针 | 转 generated，不猜 current | warning `LOCK_STATUS_WITHOUT_SHOT_EVIDENCE` |
| 多个 status=locked，Shot 无/有冲突指针 | 按 Shot 直接证据或不建 | blocker/warning 明细 |
| status=selected | 转 generated + favoriteAt | info/warning（时间推定） |
| status=rejected/superseded | 保持合法目标状态 | none |

legacy revision：

```text
revision=1
action=lock
candidateId=Shot.lockedCandidateId
previousRevisionId=null
origin=legacy_import
reason=null
decidedAt=null（除非有直接决策时间）
recordedAt=import record time
```

幂等 sourceKey 建议：

```text
candidate-lock-revision:{legacyProjectSourceKey}:{legacyChapterSourceKey}:{shotId}:v1
```

通过 G1 `ImportedEntitySource.sourceKey` 防重；digest 相同重跑 no-op，不同进 `SOURCE_MUTATED_AFTER_IMPORT`，不覆盖已导入修订。

### 17.2 Layout

| 输入 | 目标 |
| --- | --- |
| placement candidateId == 该 Shot legacy v1.candidateId | binding.candidateLockRevisionId=v1 |
| candidateId 不同 | candidate/asset 引用保留，lock revision 为 null，unresolved |
| 缺 candidateId/shotId | unresolved |
| 旧 placement 无 ID | codec 稳定生成 `legacy:{pageId}:{order}` |

不为一张历史 layout 反推并创建新的假 CandidateLockRevision。

### 17.3 Export

- 可证明 layout + lock set：建 legacy ExportRevision，`completionApplicability=historical` 或按切换时 current 决议。
- 只有文件无法证明 layout/source：`completionApplicability=legacy_unresolved`，保留 Asset，不设 currentExportRevisionId。
- 不用文件 mtime 猜测“最新 current”。

```ts
// 禁止：从 Candidate 状态猜当前定稿
```
