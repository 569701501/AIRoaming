# 模型管理功能设计方案

## 1. 背景与问题

- 对话模型和图片生成模型都可能配置多个，用户希望"选中哪个就使用哪个"，且随时可切换。
- 当前设置页：对话只有单一 AI 密钥槽位（服务商下拉+一个模型框），图片生成是 4 个写死的槽位。
- 对话面板无模型选择器；前端 `selectedDialogueModel` 只在启动时取一次默认，之后不可改 → "选 a 后想换 b 没办法"。

## 2. 目标与非目标

### 目标

1. 设置页新增独立 tab「模型管理」。
2. 用户可自己添加模型（对话/图片两类，分两个区块管理）。
3. 添加后出现对应模型列表：卡片有名字、有删除按钮；点击某行即选中。
4. 选中状态持久化；删除被选中项被禁止（先选别的再删）。
5. 首次进入预置常用模型。

### 非目标（本期）

- 不替换现有「AI 密钥」「图片生成」tab 的功能。
- 不做运行时衔接（选中模型如何接入对话/图片生成、持久化粒度）——待用户后续确认。
- 不做 OpenCode 原生 provider 管理（增删 provider 配置）。

## 3. 产品设计

### 3.1 入口与布局

```text
设置页 tab: [AI 密钥] [图片生成] [模型管理(新)] [外观设置]
                                        │
模型管理页:
┌─ 对话模型 ─────────────────────────────┐
│ [ + 添加对话模型 ]                     │
│ ┌────────────────────────────────────┐ │
│ │ ● GPT 对话          gpt/gpt-5.5   │ │ ← 选中高亮(圆点)
│ │   Kimi 对话        kimi/kimi-k2   [删除]
│ │   DeepSeek 对话 deepseek/deepseek-chat [删除]
│ └────────────────────────────────────┘ │
└────────────────────────────────────────┘
┌─ 图片生成模型 ─────────────────────────┐
│ [ + 添加图片模型 ]                     │
│ ┌────────────────────────────────────┐ │
│ │ ● OpenAI 图片    gpt-image-2       │ │
│ │   Grok 图片      grok-imagine       [删除]
│ │   Runware 图片   runware:100@1      [删除]
│ └────────────────────────────────────┘ │
└────────────────────────────────────────┘
```

- 点击某行 → 高亮选中（该区块内唯一）。
- 删除按钮对被选中行禁用（不可删除当前选中）。
- 每个区块下方可加"添加模型"内联表单（展开式）：
  - 显示名称（必填）
  - 服务商 providerId（必填）
  - 模型 modelId（必填）
  - Base URL（可选，留空走服务商默认/OpenCode 内置）
  - API Key（可选，留空则不配置凭证）
  - 保存/取消

### 3.2 预置模型（首次进入列表为空时初始化）

| 显示名 | kind | providerId | modelId | 默认 Base URL |
| --- | --- | --- | --- | --- |
| GPT 对话 | text | gpt | gpt-5.5 | 空（OpenCode 内置） |
| Kimi 对话 | text | kimi | kimi-k2 | 空 |
| DeepSeek 对话 | text | deepseek | deepseek-chat | 空 |
| OpenAI 图片 | image | openai_image | gpt-image-2 | 空 |
| Grok 图片 | image | grok_image | grok-imagine-image-quality | https://api.x.ai/v1 |
| Runware 图片 | image | runware_image | runware:100@1 | https://api.runware.ai/v1 |

- 默认选中：对话区 = GPT 对话；图片区 = OpenAI 图片。
- 预置项不带 API Key（用户自行填写或后续运行时衔接再配）。

## 4. 数据模型与契约

### 4.1 共享契约（packages/shared/src/dto.ts）

```ts
export type ManagedModelKind = "text" | "image";

export interface ManagedModelItem {
  id: string;                    // 稳定唯一 ID(服务端生成,如 model_xxx)
  kind: ManagedModelKind;
  displayName: string;
  providerId: string;
  modelId: string;
  baseUrl: string | null;
  configured: boolean;           // 是否有凭证
  keyFingerprint: string | null;
  active: boolean;               // 是否当前选中(该 kind 内唯一)
  createdAt: string;
  updatedAt: string;
}

// AppSettings 扩展:
//   models: ManagedModelItem[]
```

### 4.2 服务端存储

```ts
interface StoredManagedModel {
  id: string;
  kind: "text" | "image";
  displayName: string;
  providerId: string;
  modelId: string;
  baseUrl: string | null;
  secretRef: string | null;
  keyFingerprint: string | null;
  createdAt: string;
  updatedAt: string;
}

interface StoredAppSettings {
  version: 2;                    // 1 → 2(兼容读取旧文件)
  // 以下为既有字段,保持不变,继续承担当前运行时职责:
  aiKey: StoredAIKeySettings;
  openaiImageProvider / doubaoImageProvider / grokImageProvider / runwareImageProvider;
  activeImageProvider: ImageProviderType;
  appearance: AppAppearanceSettings;
  updatedAt: string;
  // 新增:
  models: StoredManagedModel[];          // 模型管理列表
  activeTextModelId: string | null;      // 对话区选中模型 id
  activeImageModelId: string | null;     // 图片区选中模型 id
}
```

- 兼容：旧 `version: 1` 设置文件读取时，补 `models=[]` 并触发预置初始化。
- 数据库模式（providerConfig 表）：每个 ManagedModel 映射一行 providerConfig（`runtimeKind=text|image`、`providerId` 唯一）；active 指针写入 `appPreference.defaultTextProviderId`（text）与 `appPreference.activeImageProviderId`（image）。**注意**：现 DB 行有 providerId 唯一约束，若用户添加与既有 providerConfig 行同 providerId 的模型会冲突 → 本期新增模型使用独立内部 id 映射，providerId 冲突时复用/更新既有行，避免唯一键冲突。

### 4.3 API（扩展 settings 模块）

```text
GET    /api/settings                      # 已有,响应扩展 models 字段
POST   /api/settings/models               # 添加 {kind, displayName, providerId, modelId, baseUrl?, apiKey?}
PATCH  /api/settings/models/:id           # 编辑(本期可选实现)
DELETE /api/settings/models/:id           # 删除(禁止删除 active;文本/图片各至少保留一项?)
PUT    /api/settings/models/:id/activate  # 选中:更新对应 kind 的 active 指针
```

- 校验：displayName/providerId/modelId 必填、长度/格式与现有 normalize 一致；kind 枚举。
- 凭证：apiKey 走 SecretStore（复用 image 凭证模式 `credentialIdForManagedModel(kind,id)`）。
- 删除 active → 400 `MANAGED_MODEL_ACTIVE_DELETE_FORBIDDEN`。

## 5. 预置与迁移

- 文件模式：读取设置时若 `models` 不存在或为空 → 写入预置 6 项 + active 指针。
- DB 模式：初始化时向 providerConfig 写入预置行（幂等 upsert）；已存在旧行（openai_image 等）时复用并补 displayName。
- 现有 activeImageProvider 与新 activeImageModelId 暂保持并行（现有运行时继续读旧字段，本期不改运行时）。

## 6. 运行时衔接（已实现，2026-08-05）

### 对话

- 对话运行时默认模型 = 模型管理选中的 text 模型（`getRuntimeAIKeySettings` 跟随 `activeTextModelId`），无选中时回退 aiKey。
- 选中模型凭证解析优先级：模型自带 SecretStore 凭证（文件模式）→ 同 providerId 复用 aiKey 凭证 → null（走 OpenCode 原生 provider 自带 auth）。
- 对话面板 header 模型选择器：列表 = 模型管理 text 模型，切换即 `activate`（持久化）+ 更新前端 `selectedDialogueModel`，后续消息立即生效；消息气泡显示所用 modelId。
- 「AI 密钥」tab 保存时 `syncActiveTextModelWithAIKey` 同步选中/镜像对应模型，新旧入口语义一致。
- v1 设置文件升级时，若 aiKey 已配置凭证且 provider 不在预置中，自动镜像一条同源模型并设为默认选中（保证默认对话行为不变）。

### 图片生成

- 图片运行时默认模型 = 模型管理选中的 image 模型（`getRuntimeImageProviderSettings` 跟随 `activeImageModelId`），无选中时回退固定槽位。
- 协议分支由 providerId 推断：含 doubao/grok/runware 关键字 → 对应协议，否则 OpenAI 兼容。
- 凭证解析优先级：模型自带 SecretStore 凭证（文件模式）→ 同 providerId 固定槽位复用（DB 模式共享行）→ null（生成时报 IMAGE_PROVIDER_NOT_CONFIGURED）。
- 候选图工作区工具栏图片模型快捷切换；「图片生成」tab 切换 activeImageProvider 时 `syncActiveImageModelWithProvider` 同步选中/镜像/字段。

### 已知限制

- DB 模式模型凭证不可用、active 指针不持久化（重启回默认）、固定槽位模型不可在模型管理删除，见 §7。

## 7. 风险与回滚

- 新增字段为纯增量，旧设置文件/DB 兼容读取；回滚只需前端移除 tab 与接口停用。
- DB providerId 唯一约束与新模型冲突：采用复用/更新策略，不新增迁移。
- 对话运行时已跟随 activeTextModelId：切换无凭证模型后调用可能失败（选择器有"无密钥"标记，错误透传）；带 baseUrl 的跨 provider 切换会重启 OpenCode serve（数秒，既有行为）。
- DB 模式模型凭证不可用（`MANAGED_MODEL_SECRET_UNSUPPORTED_IN_DB`）；DB active 指针不持久化（重启回默认）。

## 8. 验收标准

1. 设置页出现「模型管理」tab，两个区块各自列表展示预置项。
2. 添加模型（各字段组合）后出现在对应列表，格式校验错误有提示。
3. 点击行选中高亮；刷新后选中保持。
4. 删除非选中模型成功；删除选中模型被禁止并提示。
5. API 校验（缺字段/超长/非法 kind）返回明确错误。
6. 旧版设置文件升级后正常读取并出现预置列表（兼容性验证）。
7. shared/server/web typecheck 与现有测试全绿。
