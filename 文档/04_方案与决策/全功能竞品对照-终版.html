1核心判断（综合两版 + 深挖）

✅ 守住：章节级漫画生产操作系统

AI漫游 不是单点生图工具，而是"项目→章节→结构→分镜→出图准备→候选→排版→素材包"的完整可追溯生产链路。这个定位在所有竞品里没有直接对手——海外专业工具是英文/偏 webtoon，国内工具是动态漫剧，通用生图工具没有漫画章节流水线。

护城河 = 章节流水线 + 正式分镜契约 + 出图门禁 + 角色定稿追溯 + 候选锁定 + manifest 归档
不要降级 × 别变成"生成几张漫画图"的单点工具 × 别抄 ComfyUI 节点编辑器

⚠️ 补齐：候选迭代 × 漫画成稿 × 交付

当前最大矛盾：流程骨架完整，但离"能交付一章可阅读的漫画"还差三块——候选图的反复迭代体验弱、没有对白气泡、排版只是占位。这三块决定了用户能不能真正"用 AI漫游 产出作品"，而不是停留在 demo。

补齐重点 = 候选重画(prompt透明+单镜重画+历史) + 气泡文字层 + 排版成稿(PDF)
关键技术发现 气泡是"前端文字图层"不是"AI生成"——所有主流产品都把它做成可编辑覆盖层，难度远低于想象

3本轮深挖的 4 个关键发现（影响优先级判断）

1

气泡是"前端文字图层"，不是"AI生成"——难度被高估了

所有主流产品（Anifusion/Dashtoon/LlamaGen）都不让 AI 直接画文字进图（会出乱码），而是把气泡做成可编辑覆盖层/文字图层，叠加在生成的画面上。这意味着对白气泡功能的本质是"前端图层编辑器 + 从分镜的 comic.dialogue 读取台词自动填充"，不需要调 AI 模型。实现难度远低于"AI 写对白"。

→ 气泡优先级可上调：它是前端工程，不依赖图片模型，ROI 高
2

LlamaGen 的"版本历史自动保存"是候选迭代的最优解

深挖发现 LlamaGen 每次 redraw/edit 都自动保存旧版本到 Version History，右侧可随时回溯拖拽复用——这正是 AI漫游 候选图缺的"生成历史"。AI漫游 后端其实已定义了 5 态（generated/selected/locked/rejected/superseded），差的只是前端把这 5 态用起来 + 展示历史批次。不需要新数据模型，是纯 UI 补齐。

→ 候选重画不是"补能力"，是"补 UI + 明确语义（重画=新批次，旧批保留备选）"
3

局部修图 inpaint 技术重，应往后挪

GPT 报告把 inpaint 放 P1，但深挖确认它需要：mask 编辑器 + inpainting 模型调用 + 局部与角色一致性的冲突处理。Dashtoon/ComfyUI 能做好是因为它们有完整画布引擎。AI漫游 当前是"镜头卡列表"形态，没有画布基础，做 inpaint 要先建画布。这是 P2 以后的能力，当前阶段用"整镜重画"覆盖 80% 场景更划算。

→ inpaint 从 P1 降到 P2；P1 用"锁定图后重新生成"替代局部修图
4

分镜工作台的"预览/重排"比想象更紧急

分镜是候选图的直接上游，分镜不能缩略预览、不能拖拽重排，用户在"盲生候选图"。Katalist/LTX 的视觉故事板之所以体验好，就是分镜阶段就能看到画面节奏。AI漫游 的分镜还是纯文本卡。这直接影响候选图质量，应纳入近期优化，不能只当 P1。

→ 分镜缩略预览 + 拖拽重排，应与候选重画同期推进

5终版优先级（修正两版后）

原则：先补"能不能交付一章可阅读漫画"，再补"做得更好"，最后补"进阶能力"。inpaint 下调（GPT 放太早），气泡上调（难度被高估），分镜预览提前。

P0：候选迭代 + 分镜预览

目标：让"出图"这步体验顺畅
  • 单格重画做成一等操作明确语义：重画=新批次，旧批保留备选（对标 LlamaGen）
  • 候选版本历史/批次展示后端已有5态，纯前端补齐，展示多组候选 + 备选/废弃
  • prompt 可见（先不可编辑）出图不满意时让用户知道 AI 怎么理解的
  • 分镜缩略预览 + 拖拽重排分镜是候选直接上游，盲生候选图质量差
  • 批量生成未锁镜头15镜逐个点太累，对标 Dashtoon/LlamaGen

P1：漫画成稿交付

目标：让"能交付一章可阅读漫画"
  • 对白气泡（文字图层编辑器）前端工程，从 comic.dialogue 读台词填充，不需AI模型。ROI最高
  • 多镜排版（替代一镜一页）对标 Anifusion/Dashtoon，基础分格模板
  • PDF 导出连载交付刚需，对标 Comic Factory/LlamaGen
  • prompt 可编辑P0 可见后的进阶，让用户微调
  • 角色 sheet/表情变体角色库增强，对标 Anifusion

P2：进阶与生态

目标：锦上添花 + 延展
  • 局部修图 inpaint需画布引擎+mask编辑，技术重。用整镜重画先覆盖80%
  • 分享链接/读者反馈对标 Canva/Dashtoon 发布
  • 视频/漫剧导出(MP4)motion字段已留，接 Runway/即梦类能力
  • 团队协作对标 LlamaGen Enterprise
  • ComfyUI式专家模式不进默认主线，作为高级选项

6结论

一句话：骨架完整、护城河清晰，但"画完一张图"到"交付一章漫画"之间，缺了对白气泡和成稿排版——这两块才是用户能不能真正产出作品的关键。

近期（P0）：让出图顺。单格重画 + 候选历史 + prompt可见 + 分镜预览 + 批量生成。候选这块"补 UI"为主，后端 5 态数据模型已就位。

中期（P1）：让能交付。气泡（前端图层，非AI生成，ROI高）+ 多镜排版 + PDF。这是从 demo 走向"能产出作品"的分水岭。

远期（P2）：让更好。局部修图（需画布引擎，技术重，后置）/ 发布 / 视频漫剧 / 协作。inpaint 用"整镜重画"先顶 80% 场景。
