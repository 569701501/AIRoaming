# ADR-0011 高自由成稿编辑器首版边界

## 1. 状态

已采纳，尚未实现。

## 2. 背景

当前 `LayoutExportWorkspace` 只有章节选择、生成排版、导出 PNG 序列和卡片预览；服务端近似按一镜一页建立 placement，导出时复制候选原图。系统还不能表达多格、裁切、重叠、文字、气泡或确定性合成。

用户已为 D4 选择高自由文字/气泡，为 D5 选择高自由画布，同时要求首版只实现基础、主要、能形成真实漫画成品的能力。

专业漫画工具、AI 漫画工作台和轻量设计编辑器的共同模式是：模板先行、画格作为裁切容器、图像非破坏裁切、文字/气泡可编辑、对象属性随选中变化，以及导出前预检。

## 3. 决策

### 3.1 产品定位

成稿编辑器使用“有限正式成稿容器 + 高自由对象编排”：

- 容器由 ADR-0009 确定的 `vertical_scroll/paged_comic` 决定。
- 画格、图片、文字和气泡是正式可编辑对象。
- 不把成稿步骤定义为无限白板、绘画软件、Photoshop 或通用矢量编辑器。

### 3.2 已确认的首版边界

| 决策 | 选择 | 已采纳边界 |
| --- | --- | --- |
| D45-1 画格 | A | 矩形/圆角矩形轮廓；允许自由移动、缩放、旋转、重叠和层级调整 |
| D45-2 文字 | C | `horizontal-tb/vertical-rl` + 同文字框字符范围富文本 |
| D45-3 气泡 | A | `speech/thought/shout/caption` 四类预设 + 单可调尾巴；整体可自由变换 |
| D45-4 分组 | A | 临时多选和批量命令；不把一般 Group 写入正式文档 |
| D45-5 移动端 | A | 桌面完整编辑；手机只读预览和预检查看 |
| D45-6 AI 助手 | A | 成稿编辑默认收起 AI 助手；保留可展开抽屉与该步骤独立对话上下文 |

### 3.3 编辑文档与版本

- 正式事实源使用规范化 `LayoutDocument`，核心对象为 `LayoutCanvas/PanelFrame/ImageElement/TextElement/BalloonElement`。
- 模板只生成同一套 LayoutElement，不建立“模板排版”与“自由排版”两套数据。
- 图像使用非破坏 crop/scale/offset/rotation，候选原图不被改写。
- 图像对象保存 `sourceCandidateLockRevisionId`，遵守 ADR-0010 的 stale、旧布局和旧导出保留规则。
- 自动保存更新 Layout Working Copy；只有不可变 LayoutRevision 可被正式导出或下游任务引用。

### 3.4 富文本与气泡

- `TextElement` 与气泡内文字共用 `RichTextDocument -> paragraphs[] -> runs[]`。
- `writingMode` 是文字对象属性，与项目级漫画版式无关。
- 富文本必须支持中日文 IME、字符选区、粘贴清洗、范围级 Undo/Redo、竖排常用标点/混合字符和受控 FontAsset。
- 缩放文本框或气泡时重新排版，不默认按比例改字号。

### 3.5 交互与 AI 权限

- 一般多选使用会话级 `SelectionSet`，批量结果分别写回各元素；气泡内部和画格—图片所属仍是持久领域关系。
- 手机不调用编辑、Working Copy 写入、LayoutRevision 创建或导出确认 API。
- AI 建议先形成 `PendingEditorCommandSet`，包含来源 digest、影响摘要和可预览差异；用户确认后才转为可撤销 Editor Command。
- AI 不能自动保存正式修订、确认导出、覆盖历史或跳过来源 stale 检查。

### 3.6 确定性渲染是 V1 退出标准

- 前端预览与正式渲染器使用同一 LayoutDocument、字体资产、换行和裁切语义。
- 真正的 PNG 合成是 V1 退出标准；DOM 截图或复制候选原图不算完成。
- 导出前至少检查来源 stale/unresolved、缺图、缺字体、文字溢出、低分辨率、画布外对象和未保存修改。

## 4. 不进入 V1

- 任意多边形/贝塞尔画格、气泡轮廓节点、多尾巴、连接/合并气泡。
- 通用持久 Group、嵌套 Group、组级裁切/蒙版。
- 手机/平板完整编辑。
- `ruby`/注音、路径文字、透视/弧形变形和逐字自由位置/旋转。
- 画笔、橡皮、像素级修图、滤镜、混合模式、画布内 inpaint、节点工作流、视频时间线和多人实时协作。

## 5. 被否决的备选

### 5.1 否决：只做结构化轻画布

不满足用户已确认的高自由对象编排、横竖排富文本和独立图像叠加需求。

### 5.2 否决：首版即做通用无限白板/绘画软件

会将平移缩放容器误当产品身份，挤压漫画成稿、版本、预检和真实导出。

### 5.3 否决：前端拖拽 + 截图导出

无法保证字体、横竖排富文本、裁切和层级在服务端重现，也无法形成可追溯正式产物。

### 5.4 否决：AI 直接修改并自动导出

会绕过用户确认、Editor Command 撤销、D3 来源检查和不可变修订，与现有分阶段用户确认机制冲突。

## 6. 影响与后果

- D45-2=C 使富文本成为 E0/E3 中的高风险技术原型，不能使用普通 textarea 代替。
- 需要受控 FontAsset、中日文 IME/竖排样例和浏览器/服务端黄金渲染对照。
- 需要新的 LayoutDocument schema、Working Copy、LayoutRevision、预检、真实合成器和渠道导出垂直切片。
- 成稿步骤的现有左侧固定对话框需改为默认收起抽屉，但其他步骤的对话信息架构不随之改变。
- 实现顺序必须从 E0 技术原型开始，不允许先在正式页面堆积无可追溯结构的拖拽状态。

## 7. 验证标准

- 同一 LayoutDocument 在浏览器预览与服务端 PNG 渲染中的画格、裁切、字体、横竖排、富文本和气泡位置一致。
- 候选 A 进入画布后更换为 B，旧布局不被改写，相关图像对象显示 stale 并可生成新 LayoutRevision。
- 字符范围样式、中日文 IME、竖排标点/混合字符、粘贴清洗和范围级撤销有自动化与黄金渲染样例。
- 多选批量变换可一步撤销，取消选中后不保留一般 Group。
- 手机只读预览不会调用任何画布写入或正式修订 API，且与桌面预览展示同一渲染结果。
- AI 建议在应用前必须可预览/放弃，来源 digest 变更后旧建议不可直接应用，AI 不能自动导出。
- 真正 PNG 合成、条漫切片/页漫序列和导出前预检有可重复验证的样例与 manifest。

## 8. 后续

- 按 E0–E6 编写详细开发文档，但要先完成全项目剩余关键决策与 D7 数据库迁移方案。
- E0 使用可丢弃原型比较画布内核与服务端渲染路线；技术原型完成前不在 ADR 中锁定 Konva、Fabric、SVG 或其他库。
