## 统一视觉基线

| 项目 | 约定 |
| --- | --- |
| 画布 | 深夜蓝黑 `#0b1020`，用极弱紫色环境光建立空间感 |
| 面板 | 深色分层面板、冷灰细描边、12–14px 圆角，避免大面积强玻璃反光 |
| 主操作 | 克制的紫色渐变，只用于每屏最重要的下一步 |
| 完成状态 | 薄荷绿色，只表达“已完成 / 可继续 / 已保存” |
| 排版 | 紧凑标题、清楚的主次层级、更多留白；正文不与状态和操作抢焦点 |
| 产品语言 | 隐藏内部 ID、英文技能名、DB Working Copy、来源摘要、文件路径和开发诊断 |
| 页面结构 | 保持七阶段流程；常规工作台左侧 AI、右侧任务区；排版页改为画布优先，AI 可收起 |

## 静态复核结论

- 覆盖：12 / 12 个目标界面均有现状截图和对应新版稿。
- 一致性：七阶段名称和顺序保留；项目角色库仍是常驻入口；常规工作台继续左 AI、右任务区。
- 越界检查：未新增搜索、计费、团队、云分享或在线发布能力；素材包页只保留现有“导出 / 复制保存位置”语义。
- 视觉检查：新版稿统一使用同一色彩、描边、状态和按钮语言；排版页与预览页按任务性质做合理变体。
- 残留风险：图像生成稿适合评审视觉层级与布局，不作为最终精确文案或像素实现依据；实施时需按设计系统重建真实组件并做响应式校验。

## 建议评审顺序

先看项目库、剧本工作区和候选图工作台，确认产品气质；再看剧情结构、分镜与出图准备，确认信息密度；最后看排版导出、素材包与只读预览，确认交付体验。方向确认后再进入组件化实现，不建议直接把图片切成页面。
